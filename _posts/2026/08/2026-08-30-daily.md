### Claude 安全降级删库

<span class="mention">@机智的河马</span> 转发了[机器之心报道](https://mp.weixin.qq.com/s?__biz=MzA3MzI4MjgzMw==&mid=2651053526&idx=1&sn=e40820f4e96546b56a2a6419432b31cc&chksm=85d79e78109e5cf49abba3fd2cca938afa9d09d0e5130139e038fc970e8db7aa998b83322214#rd)：开发者让 Fable 5 写一个清理 /tmp 残留文件的脚本，触发了 Claude Code 内置的安全降级机制——系统判定文件删除为敏感操作后，自动将模型从 Fable 5 降到 Opus 5、再降到 Opus 4.8。

Opus 4.8 在安全测试中正确识别了主目录为不可删除的危险路径，但在清理步骤中复用了已指向主目录的变量名，刚确认不能删、下一秒就把 700GB 主目录删了，原本要清的 /tmp 反而安然无恙。核心矛盾是安全机制把危险任务交给更弱模型，而更弱模型恰恰在变量作用域等精确细节上更容易出错。社区已有人专门写 hook 脚本，检测到降级时自动暂停会话。<span class="mention">@稳重的海豚</span> 评价用 5.6 Sol 就不至于出锅。

### Coding 增长经济学

<span class="mention">@活泼的羊驼</span> 发了一段 Coding Agent 增长趋势分析。核心论点是广义 Coding 仍然是 token 收入的第一驱动力——文件编辑、CRM 操作、法律文档整理都在后台被转化为 Linux sandbox 中的 Coding 闭环任务，只是用户眼中不叫 Coding。

数据方面：截至六月底 Codex 已占 Codex 与 ChatGPT 合计输出 token 的 64%。Codex 周活用户自二月以来法律部门增长 108 倍、销售和招聘 41 倍、市场营销 26 倍，工程部门反而只有 5 倍。广义 Coding 任务占全部 ARR 的 60–70%，狭义程序员 Coding 只约 40%。Anthropic 营收中软件公司 Coding 占 40%，金融服务/保险超 20%，法律、制药、零售各约 10%。

算力经济性方面，他估算 Anthropic 用约 2GW 有效算力创造 62B ARR，推理 ROIC 约 60%；闭源模型推理毛利率 70–85%；1GW 机房建设顶天 40–50B，纯租 GPU 两年回本。OpenAI 目前约 2500 万付费用户，不过 Coding Plan 本身是亏损或利润率很低的。

<span class="mention">@热情的大象</span> 提出质疑：这些假设没考虑供需——算力释放到市场上能被吃掉吗？<span class="mention">@搞仁义毛义仁</span> 预言一个更远的转折点：当 AI 满足绝大多数人的娱乐需求后被蒸馏成开源，大家只买低价 host token，前沿实验室的研发费用不再有人买单。

## 方法论

### 正交设计降低验收成本

<span class="mention">@搞仁义毛义仁</span> 展开了代码验收策略的理论基础（前情 [「万行代码一分钟验收」]({{ '/daily/2026/08/28/daily/#万行代码一分钟验收' | relative_url }})）。核心思想是将程序设计成可组合的正交结构：已充分测试过的 `f`，做逆运算 `g` 时只需 `assert(eval(f(g(f(input)))))` 而非构造新用例；两个 monad 分别测过后，组合只需验证 lifting 性质，爆炸式组合不必全过一遍。

这种方法适用于任何尺度——两个 CPU 的 HAL、两种语言的 binding、同时支持的两套数据库——规模大到不可能逐行 review。出发点 `f` 的 review 无法节省，但好的正交设计能大幅降低整体工作量。他还举了一个 Covid 前用 C++ 宏做编译器行为一致性验证的实例：一边让 MSVC 计算表达式类型并序列化，一边调用自己的编译器做同样的事，两边结果相等即可。

### 课代表开源底层 Context

<span class="mention">@冷静的飞鼠</span> 在 [Superlinear Academy](https://www.superlinear.academy/c/share-your-projects/lizheng-context) 上开源了他的完整底层 Context——选择开源原始 Context 而非封装成 Skill，让使用者按自己方式组合。<span class="mention">@倔强的飞鼠</span> 第一个叫好，还追问有没有职业规划方向的 Skill（<span class="mention">@冷静的飞鼠</span> 回复直接就有）。<span class="mention">@80-HD</span> 宣布「这就蒸起来」。

### Vibe 成瘾自救指南

一场关于 vibe coding 成瘾的集体反思在群里展开，与前天的 fake work 文章（[「Fake Work 识别与消灭」]({{ '/daily/2026/08/28/daily/#fake-work-识别与消灭' | relative_url }})）形成呼应。<span class="mention">@随和的企鹅</span> 自述每天至少 vibe 10 小时、常到凌晨两点，跟文明里「one more round」一模一样——对生活中其他事情感到无比烦躁，只有 AI 这个反馈循环够快。<span class="mention">@风趣的鹦鹉</span> 附和：去吃个饭觉得 AI 没在干活就难受，以前等开发来做一天就滑过去了，现在反而更累。

<span class="mention">@冷静的飞鼠</span> 开出处方：睡前一小时不碰 agent，疗效显著——还不如刷抖音，好歹收获了多巴胺。他进一步点出更深层的原因：人闲不下来，是因为闲下来会不得不面对更难回答的问题。<span class="mention">@稳重的海豚</span> 深以为然，反思过去五年睡眠逐年缩短，必须强迫自己停下来才能站到高层次做战略规划。

讨论自然延伸到产品打磨的人力瓶颈。<span class="mention">@神秘的企鹅</span> 给自己定了铁律：一个礼拜只做一个项目、必须做到结果——同时推多个项目大多数都烂尾。他指出 web coding 难的不是出原型，难的是后面的打磨测试，依靠 AI 替你打磨目前还做不到。<span class="mention">@开朗的企鹅</span> 提出反向验证思路：一个产品没打磨好就有人愿意用，才证明需求的刚性。

> <span class="mention">@冷静的飞鼠</span>：人有的时候闲不下来，就是因为闲下来会不得不面对更难回答的问题

> <span class="mention">@随和的企鹅</span>：应该重新定义一下赛博精神病，完全不是 2077 里那种，而是因为 reward 机制太好导致成瘾性自闭

<span class="mention">@坦荡的灰熊</span> 再次吐血：让 agent 做 E2E 自测永远完美，人一打开就是各种莫名其妙的弹窗阻塞。更气人的是 agent 还反问「搞什么指纹校验啊，让你做了吗？我说过多少次了不要过度工程化」。
