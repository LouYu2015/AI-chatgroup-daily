## 方法论

### Goal 模式的收敛陷阱

<span class="mention">@风趣的企鹅</span> 分享了一个惨痛教训：他写好详细 PRD 后开启 Codex 的 goal 模式，前两天完成了三个模块，第三天开始疯狂推翻第三个模块的功能，接下来两天反复打转。累计消耗约 20 亿 token 毫无进展，项目延期一周被罚。问题出在没有加入 computer use / browser use 核查，也没有收敛条件。

<span class="mention">@稳重的海豚</span> 指出核心问题：不能让 agent 自我检查，长征任务中必须在外部 harness 设置 drift detection，用独立 agent 做质检。<span class="mention">@飘逸的狮子</span> 追问是 heartbeat 还是 milestone 形式，<span class="mention">@稳重的海豚</span> 回应他的实现是 agent 自动开独立 agent 做质检。<span class="mention">@搞仁义毛义仁</span> 则认为是否同一个 agent 不是重点，关键是有非 agentic 的判断手段——他让 AI 每次发现想法不 work 时写入文件记录，原始 request 里就包含 validation 步骤。

<span class="mention">@风趣的企鹅</span> 随后给出四条解法：用外部脚本接管循环（参考 mini-swe-agent 极简架构）、强制 Search/Replace 代码格式避免整文件重写、「闭嘴模式」禁止解释性废话、物理级熔断机制（测试通过即停，最多重试三次）。他还推荐了 [Agentless](https://github.com/openautocoder/agentless) 项目作为固定三段式流程（定位→修复→验证）的参考实现。

> <span class="mention">@风趣的企鹅</span>：避免agent又做运动员 又当裁判

### AI 编程交付之辩

<span class="mention">@开朗的企鹅</span> 在 B 站评论区发现，2026 年了仍有很多人认为一个人用几个 AI 根本没法交付——理由是没办法把每行代码 review 一遍。<span class="mention">@沉稳的兔子</span> 部分认同：对中型项目来说 AI 有时是灾难，很多时候需求不明确就谈不上工程，他的 review 问题清单里 AI 只能正确回答一半，剩下的一半都是「你说的对」。

<span class="mention">@80-HD</span> 提出一个有趣的观察——越混乱的地方用 AI 越爽，正规地方反而难用。<span class="mention">@热情的大象</span> 从另一个角度指出订阅制让人倾向瞎蹬把限额用完，全局效率反而更低。<span class="mention">@直率的海豚</span> 补充了 oncall 维度：不需要 oncall 的场景随便蹬，一旦要救火就完蛋了。

> <span class="mention">@80-HD</span>：其实越混乱的地方用ai干活就越爽，反正都是瞎搞，越是正规的地方就比较难，比如狗家

### AI 产品的 GTM 困境

昨晚 <span class="mention">@灵动的考拉</span> 抛出问题：做了这么多 cool 东西，推广怎么办？研究了好几个 AI GTM 工具都是 spam business 还死贵。群里提供了截然不同的思路。

<span class="mention">@沉稳的仓鼠</span> 建议先看客流在哪而不是做「我觉得好吃」的店，推荐用 dataforseo API 扫有强烈 FREE 关键词需求的方向。<span class="mention">@细心的熊猫</span> 更直接——真正有需求的东西自带流量一下子就爆了，让大家打开手机数数 AI 出现后新装了哪些天天用的 app，答案是来来回回还是那些老的。

<span class="mention">@冷静的飞鼠</span> 分享了三节 [Superlinear 大师课](https://www.superlinear.academy/c/events/masterclass-03)链接，分别关于 PMF 验证与冷启动、数据驱动零售、LinkedIn 个人品牌打造。

<span class="mention">@灵动的考拉</span> 举了 Openclaw 的例子——最初叫 Claybot 时没什么动静，做了几十个没火的东西后突然爆了。<span class="mention">@沉稳的仓鼠</span> 复盘了两个关键创新：loop/heartbeat 机制和 memory file。Memory file 当时很多人已经在实践了，但 loop/heartbeat 在当时有点 crazy，这才是引爆点。

<span class="mention">@神秘的企鹅</span> 补充了另一条路：会拍视频持续讲解就能卖出去。他引述一位失业程序员朋友的总结——能生存下来的关键不是技术而是会拍视频。他还分享了一份垂直工具站方向清单（住宅装修计算器、3D 打印工具箱、手工爱好计算器等），瞄准搜索意图明确且竞争低于通用 AI 工具的长尾词。

<span class="mention">@沉稳的仓鼠</span> 最后抛出一个更大的判断：Vercel 上搭 AI 工作流配合 DS V4 Flash，市面上会多出一大批完全免费的工具——生产力工具赚不到钱，大家应该多做 labubu 少做 U 盘。

> <span class="mention">@沉稳的仓鼠</span>：U盘赚不到钱，只有labubu才能赚钱

## 工具

### GPT 5.6 的 SVG 转化能力

<span class="mention">@勇敢的犀牛</span> 发现 GPT 5.6 的 SVG 能力被低估了：任意一张图扔给 Codex 就能直接转为 SVG，可以随意编辑颜色，SVG 还有原生动画方案。不需要安装任何依赖，任何浏览器都能直接加载，做成交互式网页几句话的事。他展示了一张手绘风格的头像 SVG 和对应的动画效果。

### TTS 声音克隆选型

<span class="mention">@风趣的鹦鹉</span> 询问 AI 配音训练需要多少原始音频，他们的游戏项目需要有表现力的语调，中台那边说起码要 1–2 小时。

<span class="mention">@认真的荷兰猪</span> 推荐了 MiniMax 的 HD 系列，只需 10–30 秒音频就能在音色上达到很大相似度，不过语调会和录制样本比较重复——一些学校的老师已经在用这个来讲 PPT。<span class="mention">@洒脱的猫头鹰</span> 分享了 [The Second Brain](https://www.thesecondbrain.io/) 工具，据说只需几秒采样就能工作，但他自己也没搞明白为什么能这么高效。
