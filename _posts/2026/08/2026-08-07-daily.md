今天最值得细读的是 <span class="mention">@今天群内信息量极大</span> 的 AI 编程三代对比——同一套监控系统 21 年手工两三周、24 年 Copilot 几天、26 年一小时搞定，同时分享了高可靠业务代码的实战经验。<span class="mention">@稳重的海豚</span> 与 <span class="mention">@今天群内信息量极大</span> 围绕指令注入展开实操讨论，拆出事前 harness、事中 heartbeat、事后碎嘴三条路线。行业侧最大新闻是 SpaceX 600 亿美元收购 Cursor，品牌将逐步消失。

## 方法论

### AI 编程三代进化：五分钟 prompt，一小时交付

<span class="mention">@今天群内信息量极大</span> 用自家近十个监控摄像头的项目串起了三代 AI 编程的完整对比。21 年古法手工：从接入摄像头 API 到训练 YOLO v5、适配 TensorRT，断断续续花两三周。24 年 Copilot 辅助：每个函数写好 docstring 一按 Tab 就出实现，花几天完成 Ray 分布式存档和重构。26 年 agent：花五分钟描述需求，AI 一小时搞定实现、测试、部署。

性能全面超越旧版——行人出现 1 秒内通知（以前要 5 秒），还自动找到了一个他不知道的摄像头 API，在浏览器里直接显示视频流而非截图。他提炼的关键变化是 prompt 复杂度没怎么涨，但可委派的任务复杂度爆炸了。

> <span class="mention">@今天群内信息量极大</span>：在24年的时候，我需要写一个非常详尽的 docstring才能可靠地让它自动补全出来一个完整的函数。这里，我的 prompt很复杂，但是它完成的任务很简单。而26年我给它的 prompt类似："这是训练数据，你自己去搜索调研找到适合咱们场景、latency budget和算力的vision transformer模型，帮我训练一个模型出来。然后用Mac GPU在今天录的视频上测试。最后给我一个报告，要包含成功的例子、失败的例子、PR curve、latency。"

第二个例子更能说明可靠性：Superlinear Academy 转付费会员制后需要一套 ledger 管理权限——多课程、多渠道、多会员类型、多权限、多撤销时间，组合爆炸加上大量 corner case。这种业务是 AI 最不擅长的类型，再聪明也猜不到业务需求。GPT 花四五天写了十几万行代码部署到 production，上线两周还没发现 bug。

<span class="mention">@80-HD</span> 感慨这套 ledger 放大公司在 AI 时代以前能干半年。<span class="mention">@今天群内信息量极大</span> 接了一段大公司立项全流程的经典模拟：

> <span class="mention">@今天群内信息量极大</span>：先scoping，pitch给老板，resourcing，被毙，迭代几轮，招人的时候夹带私货弄个能干这个的人进来，做做小原型，给老板看，老板说不错可以做，带着圣旨跟同事align，pm入场，开始track，半年没了

### 指令注入三条路：harness、heartbeat、事后碎嘴

<span class="mention">@稳重的海豚</span> 提出实际痛点：HappyHerd 只把 AGENTS.md 和 COMMANDER.md 装进 bundle，USER.md 和 DOCTRINES.md 不会递归展开。不加载 memory、只靠 file routing 做动态发现时，agent 经常找不准该读哪个文件，行为时好时坏。

他在 herdr 里的做法是把原则性指令直接 append 到 session 开头的 system instruction 里强制加载，这个模式下从没出过错。<span class="mention">@80-HD</span> 确认靠 dynamic discovery 确实有「抽卡」手感。<span class="mention">@今天群内信息量极大</span> 补充了 DeepSeek 的极端情况：agents.md 第一句加粗强调「任何情况绝无例外」，DeepSeek 照样不读。<span class="mention">@稳重的海豚</span> 打趣只有 DeepSeek 是天选之模型——「我就是例外」。

<span class="mention">@今天群内信息量极大</span> 随后分享了另一条思路：把规范 encode 在代码里做[事后注入](https://github.com/grapeot/writing-skill/blob/master/src/writing_skill/external_prose_lint_cli.py)。AI 先跑完推理输出结果，确定性扫描器检查违规，通过 stdout 注入规则让 AI 修正——好处是只在实际违规时加指令，更精准；坏处是得先走完一遍推理。<span class="mention">@稳重的海豚</span> 补充自己还有 heartbeat 事中注入，三条路线各有取舍。

<span class="mention">@今天群内信息量极大</span> 用 MemGPT 做类比：context window 是内存，文件是 virtual memory，有个组件负责换页。他说这套事后注入是被 Gemini 逼出来的——instruction following 太差，GPT 遵循指令但写作拉胯，最后只能和 Gemini 死磕。

> <span class="mention">@今天群内信息量极大</span>：总之有个碎嘴监工，跟傻逼模型碎碎念，你要遵循指令，你要遵循指令，感觉确实会更好

他提议给这个工具起名叫 tangsen，英文 Tungsten。

### Agent 产品的运行时困境

<span class="mention">@低调的熊猫</span> 分享了切身感受：做软件产品与做 Agent 产品天差地别，所有思路、协作、harness 都要推翻重建。搭建能干活的 Agent 要逐个 runtime 细节磨合，每次测试牵一发动全身。

他指出 Codex 等 coding agent 在测试阻塞时倾向自己胡乱打补丁，而 Agent Runtime 应更多依靠智能而非臃肿的补丁结构——Agent 内核一定要做减法和极简，控制 Codex 对它的不自主熵增。<span class="mention">@冷静的飞鼠</span> 推荐了 <span class="mention">@今天群内信息量极大</span> 关于[结果确定性](https://www.superlinear.academy/c/ai-resources/result-certainty)的文章：从过程确定性转向结果确定性——不规定每一步怎么做，而是定义终点和验收标准。

<span class="mention">@低调的熊猫</span> 对文章中运行时层的拆解印象最深：大家讨论最多的是协议层，但实际最花时间的是运行时层——LLM 引入了太多不确定性，每个团队都在重复造轮子。<span class="mention">@今天群内信息量极大</span> 回应说 Codex 胡乱打补丁的情况在 frontier model 上已比较少见，建议<span class="mention">@低调的熊猫</span> 把具体场景发到社区 Q&A 一起诊断。<span class="mention">@低调的熊猫</span> 另外验证了一个省 token 模式：Sol 做复杂诊断、Luna 跑执行和自测、5.5 处理中等复杂度，一晚上血条几乎不动。

### Sol HTTP 执念与三天装不上的 qm

Sol 过度设计的故事继续演化（前情 [「Sol 自缚：先建门控再翻墙」]({{ '/daily/2026/08/04/daily/#sol-自缚先建门控再翻墙' | relative_url }})）。<span class="mention">@80-HD</span> 让 Sol 安装 YC 的 qm 工具，第三天了还没用上——Sol 一直在搞各种权限 gate。<span class="mention">@稳重的海豚</span> 指出 qm 主要面向 sandbox 环境，没有本地 access，要用得大改。<span class="mention">@80-HD</span> 最终宣布彻底放弃。

<span class="mention">@搞仁义毛义仁</span> 总结了 Sol 更深层的行为模式：碰到 HTTP stack 就变得特别严重，不管是用已有库还是自己写，都会不断垒新的抽象和协议。蹬了一个月写了二十万行也删了二十万行，功能做出来了但垃圾喷得超快。

> <span class="mention">@搞仁义毛义仁</span>：一点小事不断一层一层垒新的抽象和协议。说明模型对这类事情可能有自己"独特的看法"

他的应对策略是先由着 Sol 跑通功能和测试，然后一口气让它删掉所有多余的东西。每次 Sol 都要学习「这也不行那也不行」然后存起来，行为逐渐收敛。

### Math harness 反思：先造通用推理引擎

<span class="mention">@坚定的貂</span> 回看 Noam Brown 访谈得到一个反思（前情 [「Math harness 第四日：禁写代码反而更强」]({{ '/daily/2026/08/04/daily/#math-harness-第四日禁写代码反而更强' | relative_url }})）：真正需要的不是 AI4Math，而是创建可以让模型在任意领域持续推理、超越 context window 的通用 harness——数学只是其中一个应用，就像 OpenAI 做的也不是 AI4Math 而是 reasoning mode。<span class="mention">@搞仁义毛义仁</span> 接了一句：人脑只有 7 个寄存器都能做超长 reasoning。

## 行业新闻

### SpaceX 600 亿收购 Cursor

<span class="mention">@开朗的企鹅</span> 转来[新智元报道](https://mp.weixin.qq.com/s?__biz=MzI3MTA0MTk1MA==&mid=2652717014&idx=1&sn=2cd10fe93b8020e601081b30fc75b44e&chksm=f0aeb1f1d2c462b6c3ee6bf7edde87fc20396eef4559e5f51ebfb8c45978d0025010152f64c0#rd)：SpaceX 对 Cursor 的收购最快下周五完成，金额 600 亿美元，为史上最大初创公司收购案。Cursor 品牌将逐步消失，整个公司拆分并入 SpaceX AI 各团队；内部代号 Sand 的通用 AI Agent 上线后可能以 Grok Bot 名义推出。

收购核心是 Grok 在编程领域打不开局面：企业采用率仅 7%，而 Claude Code 已将 Anthropic 年化收入推至 140 亿美元。Cursor 的 5 万家企业客户、百万付费用户和海量真实编码数据是 600 亿估值的主要支撑。财务面 SpaceX 整体仍亏损，AI 基建季度烧钱 158 亿，Cursor 并表被视为冲刺千亿年化收入的关键。

<span class="mention">@沉稳的仓鼠</span> 看到的后果是 Cursor coding plan 可能与 Grok build 合并，可选的独立 coding plan 又少了一个。开发者社区最大的忧虑是模型中立性——Cursor 此前不绑定特定大模型是其核心优势，母公司自有前沿模型后能否一视同仁，悬而未决。

### Kitesurf：Agent 专用轻量浏览器

<span class="mention">@天真的浣熊</span> 转来 Cloudflare 发布的 Kitesurf：专为 agent 设计的浏览器，运行在 Cloudflare Workers 的 V8 隔离环境中，用 Rust 重写，CPU 和内存占用比 Chromium 减少 3–7 倍，按请求即起即灭，beta 期间免费。<span class="mention">@天真的浣熊</span> 觉得思路不错，随口感慨微软其实也可以复活 IE。

### ChatGPT Pro 降智归因：IP 检测

<span class="mention">@勇敢的仓鼠</span> 反映 ChatGPT 即便把 thinking 开到 Extra High，有时仍输出碎片化的低质量回复。<span class="mention">@冷静的麋鹿</span> 怀疑被路由到了 mini，<span class="mention">@沉稳的仓鼠</span> 确认可以直接问模型——会承认自己是 GPT-5.5-mini。

<span class="mention">@博学的海狸</span> 随即贴出一条 X 帖子揭示降智机制：网页版检测用户 IP，机房和共享出口等「脏网络」下 Pro 会被替换成 5.5 Mini；手机 App 不降智，判定只在请求发出那一刻生效。解法是电脑上把需求一股脑发过去别看回复，手机打开同一对话说「重新思考一遍」。<span class="mention">@开朗的企鹅</span> 补充了更简单的办法——直接修改上一条 prompt 重新生成。

### GacUI Linux 移植：Codex 自主跑 UI 测试

<span class="mention">@搞仁义毛义仁</span> 展示了 GacUI 跨平台移植的进展：Codex 在 Ubuntu 下自主拉起各个 test app、发送点击事件、检查元素正确性，ViewModel 和渲染器分进独立进程也不会乱。他评价「还得是 5.6 Sol，以前的模型根本没法想」。Linux 移植完成后自动总结 breaking change 交给 macOS 继续做。

架构设计上渲染器可以是浏览器或其他进程，MVVM 的 VM 独立出来通过 JSON + stdio 通信。<span class="mention">@搞仁义毛义仁</span> 计划自己做 TS demo 留下文档，用户想用其他语言就喂给 Codex 写 codegen。<span class="mention">@天真的浣熊</span> 总结这个闭环为「先冒烟，再落盘」。
