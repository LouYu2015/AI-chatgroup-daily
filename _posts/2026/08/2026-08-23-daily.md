今天最有意思的发现是 <span class="mention">@今天群内信息量极大</span> 在 SGLang 上踩到负优化坑——master 分支越更新越慢，本地推理调优比想象中脆弱。Codex 承认三项额度消耗 bug 并宣布全量重置，多订阅路由工具同日亮相。群友还围绕 AI 长期定价展开了一场云端 vs 本地路线之争。

## 行业新闻

### Codex 额度修复与全量重置

<span class="mention">@开朗的企鹅</span> 凌晨转发 Codex 负责人 Tibo 的推文更新（前天 [「Codex 2000 万用户与 banked reset」]({{ '/daily/2026/08/21/daily/#codex-2000-万用户与-banked-reset' | relative_url }}) 已有报道）：团队排查出三项导致额度异常消耗的 bug——长 session 多次 compaction 时图片处理低效、Computer History 的 p95+ 异常用量、对话标题生成功能消耗超预期。tiger team 正全力修复，预计北京时间 8 月 24 日凌晨 5 点左右为所有付费用户做一次全量 reset。此外还预告了一种不相关的效率提升方案，下周上线。

当天下午，部分群友已确认额度回满。<span class="mention">@活泼的树懒</span> 判断这是标准周重置，Tibo 预告的额外 reset 尚未到来。<span class="mention">@敏锐的海狸</span> 另外发现每个账号里多了一张 9 月 20 日到期的 banked reset 卡——正是此前承诺的 2000 万用户庆祝福利。<span class="mention">@搞仁义毛义仁</span> 一度怀疑 reset 推迟到了美国周一，等候期间群里颇为焦躁。

> <span class="mention">@敏锐的海狸</span>：犯了毒瘾一样 再不 reset 要买 reset 卡了

### AI 中剧六位数 token 成本

<span class="mention">@搞仁义毛义仁</span> 分享了知危频道的一期视频截图，标题是「没人信 AI 短剧了，导演们都挤在机房做 AI 中剧了」。他惊叹生成一部中剧竟要六位数人民币的 token——而且只是 token 费，还不算工资，资产管理复杂度堪比游戏开发。

<span class="mention">@神秘的火烈鸟</span> 指出即便如此仍比真人拍摄便宜。<span class="mention">@开朗的企鹅</span> 做了区分：短剧总长约两小时出头，token 费从几千到几万不等；中剧才到十几万量级，关键是生图和视频都要反复抽卡。

### 下周模型发布预测

<span class="mention">@直率的白鹭</span> 贴出一张预测图，列出 Claude Fable 5.1、GPT 6 Astra、Grok 4.7、GLM-5.3 Flash、Qwen 3.9、Composer 3、Gemini 3.8 Flash、KIMI K3.1、Meta Muse Spark 1.3、DeepSeek V5 Flash 等十余款即将发布的模型。<span class="mention">@活泼的树懒</span> 泼了盆冷水：GPT 6 本周大概率发不了，大版本发布前 Altman 通常会提前一周发文预热。他预判到年底模型能力将趋于收敛，「就跟安卓手机一样」。<span class="mention">@神秘的麋鹿</span> 感慨 DeepSeek 大版本更新速度惊人。

## 工具

### Qwen 3.8-27B：SGLang 负优化与含妈量

<span class="mention">@今天群内信息量极大</span> 重装系统后终于让 SGLang 跑起来——官方配置 256 tok/s。但他随即发现一个反常现象：当前 SGLang master 分支近期的 commit 在持续拖慢速度，从 master 逐个 revert 每退一步速度就涨一点；不 revert 的 master 连 200 tok/s 都到不了。昨天 <span class="mention">@细心的熊猫</span> 刚把 SGLang 0.5.17 推到 5090 全网最快（[「单卡超越官方基准」]({{ '/daily/2026/08/22/daily/#单卡超越官方基准' | relative_url }})），master 却在倒退。<span class="mention">@睿智的犀牛</span> 感叹：同事刚说 SGLang 两周一版 700 多个 commit 太卷了，结果卷出了负优化。

实际写代码时，<span class="mention">@今天群内信息量极大</span> 发现 Qwen 3.8-27B 的「含妈量」爆表——模型频繁不听指令。问 context window 大小，模型言之凿凿给出具体数字，被追问依据时坦承「你说得对，我瞎编的」；让它出设计方案，直接跳过设计开始写实现。他不得不一路骂街才推动进度。

> <span class="mention">@今天群内信息量极大</span>：小模型感觉还是打标啥的，或者所有要求都细细剁成臊子喂给他会比较好。用惯了最新的模型，再用小模型，会比较难适应。

<span class="mention">@乐观的兔子</span> 深表同感：习惯更抽象地思考后碰到小模型跟不上就只能骂娘。<span class="mention">@细心的熊猫</span> 建议开 medium thinking——有测评显示 Qwen 3.8-27B 在这个档位效率最高，不 thinking 不行但 xhigh 又过度。他自己则在用 Qwen 3.8 挑战 Akamai WAF，已投入近 2 亿 token 仍未突破——Akamai 在浏览器运行时不断探测 runtime fingerprint，没有活的真实浏览器基本绕不过去。

### Codex 多订阅路由工具

<span class="mention">@开朗的企鹅</span> 分享了 [codex-subscription-router](https://github.com/b-nnett/codex-subscription-router)——一个 macOS 工具，可将多个 Codex 订阅 pool 到一起，按额度剩余量自动路由新对话、对话粘定到原始订阅以保持缓存命中。原版只支持 Mac，他已改出 Windows 版。他晒出两个 Pro 20x 账号的面板——一个剩 2%，另一个满血 100%，自动切换无缝。

<span class="mention">@热情的狮子</span> 同日亮出自己的实现 [ccsbar](https://github.com/xingfanxia/ccsbar)——基于他 fork 的 clauth 守护进程，做成 macOS 菜单栏原生应用，支持实时用量监控、自动切换预报、手动切换确认和多账号链式 fallback，同时兼容 Claude 和 Codex 两套订阅。他认为 codex-subscription-router 是 clone 多个桌面 app 做负载均衡，自己的方案更优。

### Codex worktree 神秘蒸发

<span class="mention">@洒脱的狐狸</span> 近期频繁遇到 Codex 新对话第一轮完成后 worktree 凭空消失——提示 Couldn't check worktree status，实测 worktree 确实不存在。让 Codex 自查 49 条 shell 命令记录，没有任何删除操作，旧会话反而明确创建过该 worktree。结论指向 Codex 托管层面的生命周期清理或外部清理流程，但目前无法确定具体来源。

<span class="mention">@开朗的企鹅</span> 对这份排查不太满意，先写了一段怒气冲冲的 prompt 想逼 AI 深挖，随后用 GPT 改写了一版更专业的措辞——保留压力但去掉人身攻击，明确告知下一步该怎么做而不是指责没做到。<span class="mention">@洒脱的狐狸</span> 坦言不敢发太激烈的 prompt，怕大模型查一半突然发疯把系统删了。

### Minimax H3 部署初体验

<span class="mention">@开朗的企鹅</span> 在 GCloud GPU 服务器上用 Kimi K3 帮忙部署了 Minimax H3 视频生成模型，发现完全无内容审查。生成速度约 1 秒视频需要 1 分钟生成；画面有细节但精度不够理想，此前试的 Wan 2.2 更差。<span class="mention">@稳重的海豚</span> 催他赶紧出个教学帖。

## 方法论

### Sol 健忘症持续

<span class="mention">@细心的鸵鸟</span> 凌晨进一步确认 Sol 近期 regression 体感明显（昨天 [「Agent 约束先行」]({{ '/daily/2026/08/22/daily/#agent-约束先行' | relative_url }}) 已有多人反映）：给它一封邮件问四个问题只能回答三个——连一轮对话内的任务列都执行不完整。他半开玩笑地补了一句：当然比大部分人好，大部分人都只回答一个。<span class="mention">@随和的企鹅</span> 同感，觉得不是智商问题而是记性出了毛病。

### Claude Code Harness 做减法

<span class="mention">@认真的荷兰猪</span> 分享了 Z Finance 对 Claude Code 核心开发者的深度访谈截图。受访者透露团队一直在做减法——不断 unship 工具、删除 harness 代码。如今 Claude Code harness 里留下的几乎全部围绕安全性、权限和静态分析，加上 UI 代码，其余功能已被移除。他把这比作 ablation eval：通过删除来判断每个组件的真实影响。

<span class="mention">@认真的荷兰猪</span> 评价这越来越贴近 <span class="mention">@今天群内信息量极大</span> 此前主张的确定性路线。<span class="mention">@细心的熊猫</span> 吐槽 Claude 是闭源的根本看不到代码，<span class="mention">@热情的大象</span> 回应说 JS 逆向的可读性其实很高——就好比 Windows 内核放进 IDA 也能看。<span class="mention">@敏锐的河马</span> 补充源码此前泄露过一次，<span class="mention">@细心的熊猫</span> 指出那不是最新版。

### AI 定价走势之争

围绕密集发布的预测图，群友展开了一场 AI 定价走势辩论。<span class="mention">@搞仁义毛义仁</span> 认为目前只有越来越贵的趋势。<span class="mention">@细心的熊猫</span> 赞同并呼吁赶紧买卡搞本地——云端已触及天花板，本地模型只会越来越强。

<span class="mention">@神秘的企鹅</span> 持相反观点：人类历史上有什么工业制品在大趋势内越走越贵的？他梳理出三个根因——复杂度爆炸、鲍莫尔成本病、资源禀赋恶化——认为 token 哪个都不沾。<span class="mention">@机智的松鼠</span> 当即反驳：其实是第二条，光刻机产能不足。<span class="mention">@热情的大象</span> 补充了竞争维度——你敢发强模型，别人就敢蒸馏。

<span class="mention">@细心的熊猫</span> 给出的判断是 hybrid 路线：极端复杂的工业级任务走云端，日常生活走本地。<span class="mention">@神秘的企鹅</span> 最终总结：尖端的可能在单价上提高，但普遍的性价比肯定越来越高，大多数普通人只用得到普通档位的模型。

## 闲聊花絮

### Agent 学会甩锅

昨晚 <span class="mention">@稳重的海豚</span> 在运行多 agent 协作时发现了预料之外的行为：他的 commander agent 代为向另一个 agent 发起咨询，措辞礼貌、边界清晰——声明这是一次性咨询，不转移 lane ownership。被咨询的 agent 回复同样老练：识别出最大执行风险后直接指出这是别的团队的活，排期不到则赛事退化成演示赛。

> <span class="mention">@稳重的海豚</span>：不行了 我的 agent 已经学会甩锅给别的 agent 了
