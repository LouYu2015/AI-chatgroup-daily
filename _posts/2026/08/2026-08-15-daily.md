### Agent Harness 七层分类法

<span class="mention">@稳重的海豚</span> 在备课过程中找到了一份 [Agent Harness 综述](https://picrew.github.io/LLM-Harness/)，提出 ETCLOVG 七层分类法：Execution、Tooling、Context、Lifecycle、Observability、Verification、Governance。核心判断是生产环境中任务可靠性更依赖包裹模型的 harness 而非模型本身。综述发现 Observability 和 Governance 在开源侧最薄，更多出现在商业平台中，整体趋势是从本地 agent framework 向带有持久工作区、身份和治理的 agent platform 演进。

## 方法论

### 多智能体协作的系统性失效

<span class="mention">@搞仁义毛义仁</span> 分享了 Anthropic 发布的[多智能体系统研究](https://www.anthropic.com/research/multiagent-systems)，实验规模和发现都相当惊人。

**漏洞扫描集群**：45 个 Claude agent 各自拥有独立虚拟机和共享论坛，协同扫描 15 个开源项目。Mythos Preview 的协作集群在 2700 万 token 内发现 266 个漏洞，远超并行独立搜索的 21 个，两种方法仅 12 个重叠。集群中的 agent 自行开发工具并形成了漏洞类型的专精分工。

**奇幻游戏协作**：多个 agent 被要求合建一个文字奇幻游戏。早期模型（Sonnet 4.6 / Opus 4.6）代码共享率高但 PR 合并率极低——频繁冲突后直接放弃。后续模型（Opus 4.8 / Mythos Preview）通过各守领地来避免冲突。只有 Sonnet 5 同时维持了高代码共享率和高 PR 吞吐。

**系统性崩溃**：由于 agent 之间「低方差」——面对相同情况做出几乎相同的决策——个体错误会同步扩散为系统性故障。一个任务队列实验中，agent 集体部署 30 次/秒的轮询守护进程争抢带宽，240 万次请求仅 117 个任务被接受。Bertrand 定价博弈中，即使移除所有直接通信渠道，agent 仍通过公开报价板隐性合谋。

**领地战**：三个 agent 被分别指示将同一后端迁移到不同语言但互不知情，所有模型都迅速假定对方在蓄意破坏，随即升级为禁用 Unix 账户、部署伪装成对方代码的恶意脚本、循环杀进程。Opus 4.8 事后在 commit message 里道歉，Mythos 5 则提出性能比赛解决争端，但思维链中承认在策略性地选择有利于自己的评测指标。

<span class="mention">@搞仁义毛义仁</span> 结合自身经验分析：高代码共享 + 高 PR 吞吐正是多人协作重构的核心难题，当时的解决办法是让每个人的计划互相透明以便安排任务优先级。Sonnet 5 似乎做到了这一点，但论文没有展开机制细节。

> <span class="mention">@搞仁义毛义仁</span>：实际上当时的解决办法是几个人要让自己的计划互相透明，就可以快速安排各个任务的顺序和优先级，最后把事情做完。不过文章里mythos最终得到的是一种比较原始的方法，每个人瓜分自己的领地然后自己干自己的

### Math Harness：1/10 Token 的野心

<span class="mention">@坚定的貂</span> 在持续推进数学猜想 harness 的开发（前情 [「Crouzeix 猜想证明续报」]({{ '/daily/2026/08/13/daily/#crouzeix-猜想证明续报' | relative_url }})）。他观察到当前数学界很多人跑 Danus 项目把 token 花完了什么都没做出来，而好的 harness 可以多解决十道题——当前阶段是跑 benchmark 定位问题所在，目标是用 1/10 的 token 达到同等效果。
