### DINOv3 分类器 skill

<span class="mention">@今天群内信息量极大</span> 把前几天 ESP32 车库门项目（前情 [「10 小时攻关，30 分钟 dev time」]({{ '/daily/2026/08/02/daily/#10-小时攻关30-分钟-dev-time' | relative_url }})）的全流程打包成了 [DINOv3 Classifier Skill](https://skills.superlinear.academy/?skill=dinov3-classifier-skill)：从 AI 自主标注、正负例迭代挖掘、模型训练调参，到蒸馏量化、固件开发、嵌入式部署——整条流水线由 AI 主导，用户基本不用动手。适用场景包括监控判断猫有没有上沙发、天有没有下雨、车库门有没有关等。

性能数据跨越四个数量级：22M 参数 DINOv3 + Linear Probe 在 M3 Ultra 上 102fps；蒸馏到 8.4M CNN 后精度不变，Mac CPU 356fps、Apple ANE 2170fps；量化部署到香橙派也有 370fps；进一步蒸馏到 0.9M 参数后，20 元单片机仍有 4.2fps，精度依然不变。

## 方法论

### 高扇入场景的 Pre-Agent 过滤

昨晚 <span class="mention">@今天群内信息量极大</span> 发布了[《高扇入场景下的 Agent 控本：在 Agent 看到输入之前》](https://yage.ai/share/pre-agent-fan-in-filter-cost-20260806.html)。核心观点是：在 AIOps 等高告警量场景下，决定什么值得让 Agent 启动调查，比把单次 Agent 调用调便宜更重要。

文章拆解了 Datadog 的 AI Security Detection Pipeline：Mambark 约 96.9M 参数的 Mamba 模型，每天从约 100 亿条安全事件中选出约 10,000 条候选再交给大模型 Agent 调查。它不是做通用文本分类，而是把日志流视为系统状态序列，用 next-event prediction 的困惑度捕捉异常——实际事件偏离常态时自动标为高异常度，不需要人类提问。

> <span class="mention">@今天群内信息量极大</span>：Datadog这个思路挺有意思的，他训练了一个基于mamba的LM去做anomaly detection，每个token是event的元数据，不是自然语言的token，用它做next token prediction。如果实际看见的token和predict出来的token不一样的话，就说明这是个anomaly

文章也给出按事件量级选择策略的建议：量低时直接调大模型批量摘要最简单；量中等且每条候选都会触发多步调查时做廉价 triage；量极高且 cheap API pass 本身成为主要成本时才上专用小模型过滤层。

### Semantic layer 先行：离线编撰反论

<span class="mention">@80-HD</span> 读完昨天 [「离线编撰优于实时 RAG」]({{ '/daily/2026/08/04/daily/#离线编撰优于实时-rag' | relative_url }}) 后给出反方意见：活做得漂亮但方向不对——应该在 ETL/ingestion 阶段就把 semantics 和 metadata 存好，而非事后烧 token 来补。

> <span class="mention">@80-HD</span>：让每个table在ETL/ingestion的时候就把semantics/metadata都存好，比后面烧token来找补的效果和开销都好太多。semantic layer做好了再配个老鸭汤，就是个很漂亮也简洁的方案

他推荐 dbt 和 sqlmesh（两者已合并）作为成熟轮子，认为用编译器技术分析 SQL 比分析 C++ 简单得多。
