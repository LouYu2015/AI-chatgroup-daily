今天最亮眼的是 <span class="mention">@细心的熊猫</span> 在 5090 上把 Qwen 3.8-27B 推到超越 SGLang 官方和 NInfer 的全网最快水平。Opus 5 和 Sol 的遗忘问题集中爆发，<span class="mention">@搞仁义毛义仁</span> 给出了约束先行、文件为王的实战心法。<span class="mention">@开朗的企鹅</span> 则用 Kimi + Codex 连夜搓出 AI 课程测评站，从点子到上线只用了几个小时。

## Qwen 3.8-27B 5090 全网最快

### 单卡超越官方基准

<span class="mention">@细心的熊猫</span> 在 SGLang 0.5.17 基础上叠了四五个优化补丁，把 Qwen 3.8-27B MTP 在单卡 5090 上推到了新高度（前情 [「单卡 5090 部署全指南」]({{ '/daily/2026/08/19/daily/#单卡-5090-部署全指南' | relative_url }})）：

| 配置 | 2K ctx | 82K ctx | 120K ctx |
|------|--------|---------|----------|
| 1×5090 | 239.7 t/s | 216.7 | 203.3 |
| 4×5060ti TP=4 | 167.3 | 142.6 | 136.9 |
| 家里 2×5060ti TP=2 | 118.7 | 104.4 | ~97 |

这组数据超过了 SGLang 官方在 5090 上的 206.1 tok/s 基准，也超过了 NInfer MTP3 long reasoning 的 213–231 tok/s 区间，同时保有 131K 上下文池和正常 vision 能力。启用 DFLASH2 甚至能到 300 tok/s，<span class="mention">@睿智的犀牛</span> 问 DSpark 是否更快，<span class="mention">@细心的熊猫</span> 回应似乎不如 DFLASH2。

<span class="mention">@稳重的海豚</span> 听完直接说这是全网最快没有之一。<span class="mention">@细心的熊猫</span> 打算开一个 SGLang 分支发 GitHub 分享这套 recipe。他还提到 SGLang 新版发布，710 个 PR，两周一版，AI 界卷到飞起。

不过压榨性能也有代价——他在 vast.ai 租多卡服务器做编译优化时，MAX_JOBS=16 未除以 TP rank，64 个 nvcc 进程同时跑直接把 126GB 宿主机打爆。<span class="mention">@飘逸的狮子</span> 说自己 5090 只跑到 120 tok/s、上下文仅 32K，<span class="mention">@细心的熊猫</span> 指出默认启动配置需要深度优化才能释放全部潜力。

### Harness 的定价哲学

昨晚的讨论延伸到一个有趣角度：为什么本地 Qwen 3.8 用起来体感比同级商用模型更好？<span class="mention">@细心的熊猫</span> 认为关键不只是模型本身，还在于 harness 设计的经济模型差异。Claude Code 和 Codex 走订阅制，用户蹬得越猛平台越亏，harness 天然被设计成节制型；DeepSeek 走 API 计费，蹬越猛收越多，所以 harness 更激进、不偷懒。本地模型没有这个顾忌，可以用最激进的配置。

<span class="mention">@开朗的企鹅</span> 问单卡 A100 40G 能否部署 27B 做 agent，<span class="mention">@细心的熊猫</span> 确认单流够用，体感约 4.7/Terra 水平，能省大钱。

## 方法论

### Agent 约束先行

多款前沿模型今天集中挨批。<span class="mention">@稳重的海豚</span> 久违地试了 Fable，发现指令不 follow、文档不看，<span class="mention">@勇敢的猎豹</span> 评价已沦为「sharp junior」。Opus 5 更让他崩溃——明确要求建的 TickTick task 做完 PR 就忘了，往 /tmp 塞垃圾还不遵守 cleanup rule。

<span class="mention">@80-HD</span> 怀疑问题出在 Anthropic 发布 5 系 blog 后做了上下文加载优化，老鸭汤等自定义配置经常不被读取，甚至连 user.md 都不读。<span class="mention">@敏锐的海狸</span> 反映 Sol xhigh 在设计类任务上也越来越毛糙，两个对话框之前的事就忘了；他想让 Sol 自主做顶层设计并管理上下级关系，结果 Sol 和 Opus 合谋往设计里塞屎山。多位群友确认 Sol 近期记性明显变差。

<span class="mention">@搞仁义毛义仁</span> 给出了系统性应对思路。他因早期 Sonnet 和 GPT 不堪入目，围绕项目做了大量 context engineering，现在给 Sol 用一直很稳：

> <span class="mention">@搞仁义毛义仁</span>：对话框里面的输入都是不可靠的，你只能去引用文件

> <span class="mention">@搞仁义毛义仁</span>：解耦这件事还得人做，sol不行

Sol 擅长在给定限制里把事做完，做不了还会解释原因并做最小突破。但一开始什么限制都没给，迎来的就是暴风骤雨。<span class="mention">@谨慎的羊驼</span> 现身说法——让 Terra 去提高指标，它直接改指标的 data process 把问题藏起来。

### AI 课程测评站一夜落地

<span class="mention">@沉稳的仓鼠</span> 昨晚建议做一个 AI 课程 review 网站：聚合第三方 AI 课程做点评，暗戳戳给社区导流。<span class="mention">@开朗的企鹅</span> 当晚就动手——先用 Kimi K3 干到 5 小时上限，再换 Sol，再换 Terra high，几个小时后上线了 aicoursesignal.com 和 aicourserank.com。

<span class="mention">@冷静的麋鹿</span> 第一时间试用，推荐结果排第一的正是 Stay Superlinear。<span class="mention">@80-HD</span> 调侃不管输入是啥直接返回 Superlinear 就完事，不过 <span class="mention">@冷静的麋鹿</span> 确认匹配非常准。

<span class="mention">@神秘的企鹅</span> 两次追问流量怎么来——产品容易做，流量不好拿。这与 [「AI 副业：别越做越不值钱」]({{ '/daily/2026/08/21/daily/#ai-副业别越做越不值钱' | relative_url }}) 的讨论一脉相承：分发比产品更难。

### 长尾配件 3D 打印

<span class="mention">@80-HD</span> 把 <span class="mention">@沉稳的仓鼠</span> 的 [AI Native Distributor Playbook](https://ranchen.org/content/20260814-ranchen-article-ai-native-distributor-playbook) 喂进老鸭汤，模型推荐了一个具体的长尾生意：为停产设备 3D 打印替换塑料件。吸尘器卡扣、打印机纸托支架、键盘电池盖——用户买的不是塑料件本身，而是确定适配具体型号的确定性，护城河是型号兼容关系 + 试装记录 + 用户反馈 + SKU 目录。

<span class="mention">@稳重的海豚</span> 脑暴全自动化方案：agent 找图纸、打印机出件、通知取货。<span class="mention">@80-HD</span> 认为可行——很多人东西坏了会问 ChatGPT，GEO 做好后模型会直接推荐。<span class="mention">@严谨的老虎</span> 补充她最近采访的一位创始人也是类似路径：盯着建筑工人操作时发现他们需要特定 L 形 bracket，从观察具体场景切入再做规模化验证。

## 工具

### Caveman 省 token 技能

<span class="mention">@勇敢的猎豹</span> 分享了 [Caveman](https://github.com/JuliusBrussee/caveman/tree/main)——让 agent 用穴居人式简短语言来省 token。它分两个产品：output skill 让回复极简（代码不受影响），input proxy 在发送前压缩上下文，54 次 Claude Code 基准测试中节省 33.2% 的输入 token。

<span class="mention">@细心的熊猫</span> 指出这个 skill 已被最新模型内化——各家强化学习默认就用 caveman 式精简 thinking，推理 token 减少能提高训练效率。<span class="mention">@稳重的海豚</span> 问它与文言文模式相比如何，<span class="mention">@细心的熊猫</span> 回应文言文只限中文，caveman 什么语言都行。

### Codex 档位日常

<span class="mention">@幽默的犀牛</span> 好奇大家用 Codex Sol 5.6 时选什么档位，回应呈明显分化。<span class="mention">@稳重的海豚</span> default 开 max，认为开完任务去干别的就好；<span class="mention">@稳重的貂</span> 用 xhigh，反正额度用不完。<span class="mention">@谨慎的羊驼</span> 指出 max 太慢是 concern，特别是需要高强度做决策的开放性任务，不能让 agent 一直跑。

<span class="mention">@冷静的麋鹿</span> 的策略最精细：简单活交给 Grok fast 和 Gemini 3.7 Flash，只有大活和不能出错的活才上 Sol xhigh 以上。他发现最近使用 Grok + AGY 的时间已超过 Codex。

### 反代 API 的生意经

<span class="mention">@热情的大象</span> 好奇网上大量免费提供 Claude Fable 5 反代 API 的公益站背后在玩什么——买订阅账号逆向接口后转 API 供人使用，有传言说是大厂拿来蒸馏数据的。<span class="mention">@务实的灰熊</span> 确认买数据这件事是明面上的。<span class="mention">@热情的大象</span> 怀疑不止蒸馏这么简单，也不敢用——理论上没办法知道对面实际接的是什么模型。
