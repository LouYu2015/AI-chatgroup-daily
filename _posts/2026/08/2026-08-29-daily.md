今天最重磅的是 OpenAI 因 SpaceX 收购 Cursor 而宣布断供模型、Musk 火力全开回怼——这场恩怨升级将实实在在影响 Cursor 用户的日常工具选择。AWS Bedrock 因上亿美元欺诈坏账全面收紧审批同样值得跑云的人留意。

## 行业新闻

### OpenAI 断供 Cursor 的 SpaceX 因素

昨天 [「OpenAI 终止与 Cursor 合作」]({{ '/daily/2026/08/28/daily/#openai-终止与-cursor-合作' | relative_url }}) 只提到了断供消息本身，今天凌晨 <span class="mention">@天真的浣熊</span> 补充了完整始末：导火索是 SpaceX 收购了 Cursor。OpenAI 同日通知 SpaceX，将于 2026 年 11 月 12 日终止向 Cursor 提供模型访问权限，给出合同允许的最长提前通知期，未来新模型（包括 Astra）将不再提供给 Cursor。

OpenAI 声明直指 Musk 旗下公司的信用问题——基于 Elon Musk 旗下公司违反合同的经验，无法确信 SpaceX 会在服务条款内使用其技术。Musk 在 X 上随即回怼，称 Altman 和 Stockman 为偷走开源非营利组织的骗子。

### OpenAI 收入结构：API 仅占一成

<span class="mention">@坚定的貂</span> 贴出一张 OpenAI 收入结构饼图：ChatGPT 个人订阅约占 60%（~$15B），ChatGPT Business 约 30%（~$7.5B），API/Token 仅约 10%（~$3.5B）。

<span class="mention">@谨慎的灰熊</span> 第一反应是 API 销售太少，认为与 Anthropic 相比不够企业级、粘性不足。<span class="mention">@沉稳的兔子</span> 持不同看法：GPT 对第三方 harness 比较开放，API 的相对意义本来就小。<span class="mention">@稳重的海豚</span> 用自己的消费账单做了注脚——他开了十个 Claude 企业账号、五个 premium 席位，GPT 只开了一个 team 号且几乎没用。

### AWS Bedrock 反欺诈收紧

<span class="mention">@冷静的飞鼠</span> 分享推文截图：AWS 客户超刷九位数美金造成巨额坏账，低价号源被彻底封死。AWS Bedrock 随即推出重磅流程更新——C-Score override 信用评分覆写规则直接升级 GCR、APJ 区域账户，不再接受邮件、Excel、SIM 的临时豁免，必须走 Amazon Approvals 正式申请，强制 Finance 团队 + L10 业务负责人双审批，没有 L10 领导签字一律打回。

<span class="mention">@专注的剑鱼</span> 感慨今年刷得太夸张了。<span class="mention">@细心的熊猫</span> 连发两条精准修正——先说「这才是真正的薅羊毛」，接着纠正：「羊腿」。

### Sol 降智已逾两周

<span class="mention">@睿智的北极熊</span> 分享了 B 站 UP 主无机酸的 [GPT 5.6 Sol 复测视频](https://b23.tv/eNlac2p)，此前该系列给 Sol 的评价是毫无争议的好用，这次文字处理水平明显下降，等于出现回调。

群友们纷纷确认体感一致。<span class="mention">@沉稳的兔子</span> 反映 xHigh 档位重置后写的作文又看不懂了，<span class="mention">@直率的鹦鹉</span> 吐槽 Max 太慢还喜欢算哈希，<span class="mention">@务实的灰熊</span> 判断降智至少已持续两三周。这延续了近期的 Sol 质量波动系列讨论（[「Sol 上下文爆炸与 regression」]({{ '/daily/2026/08/26/daily/#sol-上下文爆炸与-regression' | relative_url }})）。

## 工具

### WorkBuddy 产品力评测

<span class="mention">@稳重的海豚</span> 体验 WorkBuddy 后感叹产品力很强——文件可以直接打开编辑，各种工作台集成在一起。<span class="mention">@沉稳的大象</span> 在调研中发现很多品牌已在用 WorkBuddy 办公，评价腾讯的产品力太强了。

某群友提供了不同视角：不是 WorkBuddy 本身多强，而是腾讯其他 AI 产品全军覆没——元宝怎么扶都扶不起来，WorkBuddy 成了唯一能打的，于是变成了全公司最重要的项目。

<span class="mention">@稳重的海豚</span> 进一步指出 WorkBuddy 体验好的秘密在于内置了大量 steering prompt——如何展示文件、如何搜索、如何使用自身工具都有精心编排。本地 Codex 客户端想达到类似效果就需要覆写 agents.md 入口，程序员没问题，普通用户则是门槛。<span class="mention">@80-HD</span> 补了一句：功能全是全，就是打开容易大脑过载。

> <span class="mention">@稳重的海豚</span>：我研究了一下感觉自己搓产品真的没啥价值了……orca herdr happy happyherdr 全都可以退役了

<span class="mention">@稳重的海豚</span> 透露目前搭配使用的模型是 Kimi K3。<span class="mention">@谨慎的灰熊</span> 预告 K3.1 马上到来。

### Codex session 跨任务编排

<span class="mention">@搞仁义毛义仁</span> 发现 Codex 新增了 session 监控功能：一个 session 可以 monitor 同一台机器上的其他 session，由此实现基于偏序关系的任务编排——指定某些 session 在特定 session 结束后才启动，无缝衔接。

> <span class="mention">@搞仁义毛义仁</span>：任务之间通常是有偏序关系的，指定每一个 session 在某些特定的 session 结束之后开始干，无缝衔接，直接明天见

他希望未来能直接访问所有已登录的 Codex 实例。<span class="mention">@天真的浣熊</span> 感慨 Copilot 急需抄作业，<span class="mention">@搞仁义毛义仁</span> 直言半年前各家水平差不多，如今差距已经拉开。<span class="mention">@直率的穿山甲</span> 确认 Claude Code 尚不支持同类功能。

### 4×5060 Ti 四卡部署

延续近日的本地部署系列（[「本地推理利用率悖论」]({{ '/daily/2026/08/26/daily/#本地推理利用率悖论' | relative_url }})），<span class="mention">@细心的熊猫</span> 完成了 4×RTX 5060 Ti 16GB 的四卡部署。四卡总共花费不到两千元——前两张各 300 元入手，后两张分别 600 和 300 元。

nvidia-smi 截图显示四卡全部跑满 100% GPU 利用率。<span class="mention">@睿智的犀牛</span> 质疑没有 NVLink 多卡性能堪忧，<span class="mention">@细心的熊猫</span> 用 vast.ai 上的对比数据反驳：PCIe 4.0 x4 与 x16 对 Qwen 3.8-27B 的 TP 推理完全没有性能差异，说明 PCIe 带宽对此场景不是瓶颈。

<span class="mention">@灵动的考拉</span> 从经济性角度提出不同看法：本地模型的核心价值在隐私而非便宜。他目前每周消耗两个 Grok superheavy + Claude 的量，等新 Mac Studio 到手再考虑本地。<span class="mention">@细心的熊猫</span> 则表示有了本地模型后两个 Claude Pro 就够用了。

### Herdr + Happy 半完美合体

延续昨天 [「Codex 跨端 session 锁定」]({{ '/daily/2026/08/28/daily/#codex-跨端-session-锁定' | relative_url }}) 的探索，<span class="mention">@坚定的貂</span> 宣布 herdr + happy 合体成功——但随即纠正为「不完美合体」：happy 的语音输入实际走的是 voice assistant 而非普通输入，不符合用户直觉。他质疑既然 Codex 和 Claude CLI 都已支持语音输入，为什么不能直接把音频 pipe 过去。

他同时修好了 happy 的 Codex TUI 功能，并与 <span class="mention">@稳重的海豚</span> 讨论如何将修复合并到后者的魔改版本中。<span class="mention">@稳重的海豚</span> 加入了 native credential pool 支持。

<span class="mention">@开朗的企鹅</span> 指出 TUI 天然与异步冲突。<span class="mention">@坚定的貂</span> 回应：并非所有场景都需要异步，intense work session 仍需 TUI，而且新手不能一步跨到纯异步加信任 AI 的状态。<span class="mention">@睿智的北极熊</span> 给了一个精简区分——TUI 对应 vi/nano，CLI 对应 sed/awk。

### Stash：Agent 持久记忆层

<span class="mention">@开朗的企鹅</span> 昨晚分享了 [Stash](https://github.com/alash3al/stash)——一个开源的 agent 持久记忆方案，基于 Postgres + pgvector，自带 MCP server，一行 `docker compose up` 即可启动。其核心是一个 9 阶段整合管线，将 agent 的原始观察逐步转化为事实、关系、因果链和模式。<span class="mention">@热情的大象</span> 问它与 mem0 有什么区别，讨论未展开。

## 方法论

### AI 赋能 Infra 两板斧

<span class="mention">@倔强的飞鼠</span> 求助：公司让他做云计算架构和 CI/CD 流水线，完全没有经验。<span class="mention">@博学的海狸</span> 推荐 AI 做日志排查，oncall 会轻松很多。

<span class="mention">@开朗的企鹅</span> 给出更结构化的建议，围绕入口和 context 两个维度展开：入口要方便——从 GitHub 或飞书就能开启任务和接收通知；context 方面，关键是在服务端给 agent 预留只读接口获取日志信息。
