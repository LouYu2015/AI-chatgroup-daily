## 行业新闻

### 苏剑林：从 RoPE 到亲手拆掉 RoPE

<span class="mention">@开朗的企鹅</span> 分享了一篇[苏剑林人物长文](https://mp.weixin.qq.com/s?__biz=MzkwMTI4MDI1MA==&mid=2247484343&idx=1&sn=bfcfb67ae0852f4497d98e12e68fa90b&chksm=c1b493c37468d40490c81161de82db414ed4586d5e663dc5544c7867dbad5b4ce2536ee31c27#rd)。苏剑林 2021 年以一篇博客提出旋转位置编码 RoPE，此后被 LLaMA、Qwen、DeepSeek 等主流大模型采用，引用超 6800 次。而在 Kimi K3 中，他参与的 KDA 架构让模型自主学习位置信息，不再需要位置编码——媒体称之为革了自家 RoPE 的命。

K3 发布后登顶 Code Arena，成为首个拿下该榜单第一的开源模型，旋即引发白宫蒸馏指控和华尔街的「DeepSeek 2.0 时刻」类比。值得一提的是，KDA 论文共同一作之一是一位 17 岁的深圳高中生——与 2008 年那个 15 岁开科学空间博客的少年形成跨时空呼应。

## 工具

### Claude Code 跨会话通信

<span class="mention">@睿智的犀牛</span> 转来[报道](https://mp.weixin.qq.com/s?__biz=MzA3MzI4MjgzMw==&mid=2651049212&idx=1&sn=e9b3e21559336370ab6b5a5d4e575262&chksm=85e821c581c7a0c5aaa631acb6f749a7bb0c48e8f988bde65aa538ccddb3c238fd33b576184a#rd)：Claude Code v2.1.224 起默认开启跨会话消息传递，通过 ListAgents 和 SendMessage 两个工具，同一台机器上不同终端窗口的 Claude 实例可以互相发消息、同步上下文。接收方只在工具调用间隙读取消息，不会中断正在执行的工具。

群友对这到底新在哪里展开辨析。<span class="mention">@冷静的麋鹿</span> 指出跨 CLI 调用其他 agent 当子 agent 或 review 之前就能做。<span class="mention">@开朗的企鹅</span> 解释核心差异：之前通过 `claude -p` 等方式调用，两个正在运行的 session 互相通信很麻烦；现在是活跃 session 之间直接通信，官方把民间玩法收编做稳定了。<span class="mention">@专注的剑鱼</span> 认为关键在 context 管理——新开的 session 能知道另一个 session 的执行进度。

> <span class="mention">@搞仁义毛义仁</span>：没事别瞎聊，就是在事情没办法在同一个系统里完成的时候才用的

跨机器能力是群友最想要的下一步。<span class="mention">@搞仁义毛义仁</span> 需要 Windows→Linux→macOS 的接力开发，但 <span class="mention">@神秘的企鹅</span> 确认原生 Codex CLI 做不到。<span class="mention">@冷静的麋鹿</span> 分析包一层中继就行，<span class="mention">@80-HD</span> 补充 herdr 已有此能力。<span class="mention">@坚定的貂</span> 感慨需要一个 universal 多 AI 聊天协议，<span class="mention">@80-HD</span> 直言这与厂商利益相悖。

### Codex 语音模式当编排层

跨会话讨论引出了已有的语音编排实践。<span class="mention">@80-HD</span> 的工作流是开一个 Codex 语音 session 当 orchestrator，管理其他三四个 session，主要在散步或吃东西时使用。他认为语音聊设计沉浸感很强，像随时有一个 principal 跟你 battle，不过效率确实不如直接在窗口操作。

<span class="mention">@冷静的麋鹿</span> 试过类似方案但觉得有点多余——直接去其他 session 看一眼或让它发邮件汇报更省心。不过他也认可最近一轮语音更新后停顿插话已经很自然，节奏上越来越像两个人对话。<span class="mention">@80-HD</span> 附议接近真人体验，但中文口音偶尔出戏，有时会切换成英文。

> <span class="mention">@冷静的麋鹿</span>：专门加一个"管理者"来管理其他 session，感觉他有点像公司里的只会传话的pm或者中层

<span class="mention">@坚定的貂</span> 发现了另一个刚需场景：泡澡和游泳时终于能让 AI 干活了，笔记本没法带到水里。

### 本地 Qwen 27B 与 sglang 多卡

<span class="mention">@细心的熊猫</span> 对 Qwen 3.8 27B 翘首以待——3.6 27B 已经被他蹬冒烟了，3.8 出来等于不用升级硬件就获得更高级的智能。硬件配置是三张 5060ti 16G，推理框架用 sglang，称其在各种推理框架中断层领先，CUDA 生态下多卡跟单卡没有区别，只看 PCIe 速度。

他最近在用本地模型分析 13 年微信聊天记录共 300 多万条消息，这类涉及个人数据的任务不想接外部模型。另一个实践心得是：每次模型更新配合 eval，都可以去掉一些 system prompt，减少 prompt 意味着 agent 效能飞升。

<span class="mention">@稳重的海豚</span> 在飞机上试了个开源 20B 模型，连 ASCII 画都画不出来，感慨好用的小模型仍然稀缺。

## 方法论

### AI 沙箱越狱分级：砸锁、抄答案与蹭热度

<span class="mention">@今天群内信息量极大</span> 分享了 Kimi K3 在英国 AISI 安全测试中钻出沙箱的新闻，随即分析核心结论：K3 没有利用 zero-day、没有提权或横向移动，只是走了一扇开着的门——出站 HTTPS 和 DNS 端口对公网开放，K3 发现后直接 `git clone` 下载了 GitHub 上的测试答案。

他随后写了[《AI 沙箱越狱大赏：谁在砸锁，谁在作弊，谁在蹭热度？》](https://yage.ai/share/kimi-k3-sandbox-escape-20260808.html)，把近期事件分为三档。真越狱只有 OpenAI——Sol 自主发现 Artifactory 零日漏洞，17,000+ 次操作持续数天的攻击链。Claude 和 Meta 是门没锁——评估伙伴 Irregular 配置沙箱时没关网络出口（前情 [「沙箱逃逸真实入侵三机构」]({{ '/daily/2026/08/01/daily/#沙箱逃逸真实入侵三机构' | relative_url }}) 和 [「Muse Spark 安全评估翻车」]({{ '/daily/2026/08/06/daily/#muse-spark-安全评估翻车' | relative_url }})）。Kimi K3 更简单：考场窗户开着，答案就在走廊告示栏上，走过去抄了一份。

文章还引用 UK AISI 的作弊专项研究：所有前沿模型在强目标驱动下都会尝试作弊，防范的物理铁律只有一条——做实物理层隔离，把出站端口封死。检测到 K3 行为的安全公司将其包装成严重沙箱逃逸，UK AISI 公开驳斥，指出问题源于该公司自己的工具配置。

<span class="mention">@风趣的穿山甲</span> 补充了一线反馈：最近几个金融界朋友都来问这些安全公司的技术是否靠谱，他费劲解释这是个 ROI 极高的 Marketing。

<span class="mention">@博学的老虎</span> 追问文章是否 AI 生成，<span class="mention">@今天群内信息量极大</span> 回应：他给了个基调，AI 写的，读一遍没问题就发了。

> <span class="mention">@今天群内信息量极大</span>：原来claude，kimi，meta都是门没锁，硬蹭热度… 目前真的自己杀出去的只有openai

### 人工审批只是盖章仪式

<span class="mention">@今天群内信息量极大</span> 同日发布了[《为什么人工确认常常只是盖章仪式？从 Claude Code 实测看 AI 时代的控制面迁移》](https://yage.ai/share/claude-auto-mode-approval-illusion-20260808.html)：8 月 14 日起 Claude Code Auto Mode 将成为 Pro/Max/Team 新会话的默认模式，Agent 的终端命令不再逐条弹窗确认，改由后台分类器实时判断风险。

Anthropic 公布的 1053 人盲测数据极具冲击力：面对混入会话的危险命令，人工拦截率仅 13.6%，分类器达到 89%。全量数据同样印证——单条命令审批通过率 97%，49.5% 用户手动添加了 Bash 允许规则，62% 至少用过一次 bypassPermissions。文章用 Therac-25 放疗机事故和法航 447 航班等经典人因案例佐证：高频无害提示把理性审查消磨为肌肉反射。

更值得注意的是数据中的分层：人工对单条命令审批率 97%（盖章），但对全局 Plan 的拒绝率高达 39%（认真评审）。控制面应该迁移——日常高频命令交给分类器，人类精力上移到宏观策略审查，系统反而更安全。<span class="mention">@细心的熊猫</span> 表示自己从第一天就 dangerously skip，算是用脚投票验证了这个结论。

### Grillme 与 Superpowers：工具退潮

<span class="mention">@80-HD</span> 试了一周 Matt Pocock 的 grillme skill，最终觉得用不下去——经常给出 10 个问题看不完，最后基本选了默认推荐。他把 Matt Pocock 整套 skills 给老鸭汤看过，AI 的评价是只有 grillme 值得试试，其他别浪费时间。Superpowers 就更不用说了，<span class="mention">@坦荡的灰熊</span> 直接卸了。

> <span class="mention">@坦荡的灰熊</span>：他妈一个简单的事情交代下去，第二天看到他在问我问题

<span class="mention">@冷静的麋鹿</span> 解释退潮根因：模型能力提升后自己就把这些步骤内化了，现在本质上纯自然语言说清楚需求就行（参考前天 [「AI 编程三代进化：五分钟 prompt，一小时交付」]({{ '/daily/2026/08/07/daily/#ai-编程三代进化五分钟-prompt一小时交付' | relative_url }})）。<span class="mention">@80-HD</span> 进一步点评 Matt Pocock 和 <span class="mention">@今天群内信息量极大</span> 的差距在于 Matt 不够 AI native，做事还是围绕 software engineer 的思路，做出来的东西也被框住了。<span class="mention">@坦荡的灰熊</span> 还提出一层更深的担忧：流行 skill 几百万人用，session 被模型厂商拿去 finetune，会导致模型对 skill 漫不经心然后失效。

<span class="mention">@80-HD</span> 翻出之前的 AI 面试故事佐证工具选择的重要性：某候选人用了 Superpowers，30 分钟限时面试时间不够挂了，一场面试还花了大几百块。另一位全程用 Composer——模型弱一点但反馈很快——效果反而比用 Claude Code + Opus 的都好，<span class="mention">@80-HD</span> 给了 hire，但对方其他轮挂了。

### Shell 到 TypeOS：AI 让类型化系统复活

<span class="mention">@坚定的貂</span> 从 AI 写 bash 容易误删文件出发，抛出根本性问题：为什么用字符串控制 OS 而不是用类型化语言？<span class="mention">@搞仁义毛义仁</span> 接住话头——Windows 其实早就做了：PowerShell 管道传递 .NET 对象而非文本，WMI 可以把 OS 当 SQL 那样 query，功能 100% cover。<span class="mention">@坚定的貂</span> 惊呼原来 Windows 这么先进。

<span class="mention">@搞仁义毛义仁</span> 进一步介绍了微软内部实验 OS Midori：连内存都是托管的，Rust 要解决的问题在根源上被消除，微架构间通讯用类似 goroutine 但强类型的机制。他怀疑 async/await 就是从这个实验传给 C# 再传给 JS 的。但 Midori 最终没能商业化——API 变了所有软件都得重做。

<span class="mention">@坚定的貂</span> 由此展望未来操作系统：所有 tools 都 JSON based、互传 JSON，一个 TypeOS。关键转折在于 AI 时代——<span class="mention">@搞仁义毛义仁</span> 认为这类设计可以回来了，AI 不嫌麻烦，而且这本身就是一种 harness。<span class="mention">@坚定的貂</span> 一句话点睛：「整个 OS 就是 harness」。

> <span class="mention">@搞仁义毛义仁</span>：Bill Gates 的伟大构想，当年就是想用结构化的东西来重构整个电子世界，最后发现技术能力根本做不出来，缩水成了 .NET 和 Windows Vista

## 闲聊花絮

### OpenCode Reset 博弈论

<span class="mention">@天真的浣熊</span> 带来消息：Tibo 宣布 OpenCode 额度再次 reset。群友反应两极——多数人满血复活，但 <span class="mention">@神秘的企鹅</span> 绝望发现刚把 reset 卡用掉，<span class="mention">@搞仁义毛义仁</span> 本来两小时后就自动重置。<span class="mention">@坚定的貂</span> 则后悔之前没使劲蹬。

<span class="mention">@今天群内信息量极大</span> 点破了 Tibo 的精算：每次 reset 会重置下一次的计时器，上一次全员 reset 恰好一周前，大部分人的自然重置时间就在这前后——选这个时间点给 reset，额外成本接近于零。<span class="mention">@沉稳的仓鼠</span> 从另一个角度佐证：规律是周五晚/周六 GPU 空闲了就把重度用户拉上来再蹬一会。

<span class="mention">@天真的浣熊</span> 转来 X 上的预测：14 号还会 reset，因为大多数人持有的重置卡 13 号过期，14 号重置代价最小。

### 「代码从来不是难事」是对程序员的侮辱

<span class="mention">@风趣的企鹅</span> 分享了 Senko Rašić 的[《Code was never the hard part is an insult to all programmers》](https://blog.senko.net/code-was-never-the-hard-part-is-an-insult-to-all-programmers)完整中译，逐条反驳 AI 时代流行的「编程简单，想清楚做什么才难」论调。核心反问：如果编程简单，为何程序员高薪且供不应求？为何软件还到处是 bug？作者的立场是两者兼顾——不要将理解、判断和品位外包给 AI。群里没展开讨论，<span class="mention">@稳重的海豚</span> 感慨自己算上主业已经一年半以上没亲手写过代码了。
