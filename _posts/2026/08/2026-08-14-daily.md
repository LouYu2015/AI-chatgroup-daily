今天的绝对主角是 Qwen 3.8-27B 开源——<span class="mention">@细心的熊猫</span> 在双 5060ti 上完成量化选型和全流程跑分，<span class="mention">@今天群内信息量极大</span> 在 Mac 上跑到烤腿。GLM 5.3 同日亮相，<span class="mention">@沉稳的仓鼠</span> 感叹各领风骚一百小时。方法论最值得读的是<span class="mention">@冷静的飞鼠</span> 的 show the diff 传播方法论，以及<span class="mention">@今天群内信息量极大</span> 用定时 AI 巡检发现台风改签航班的实战故事。

## Qwen 3.8-27B 首日实测

### 开源上线与量化竞速

<span class="mention">@细心的熊猫</span> 贴出倒计时后不到一小时，<span class="mention">@专注的剑鱼</span> 转发了[官方公告](https://mp.weixin.qq.com/s?__biz=Mzk0ODg4NDI5NA==&mid=2247489926&idx=1&sn=238ec7e08757d0503e80fd9a13ec6bdb&chksm=c240630c44a4de7e7836090e4027217ecb0e311dfb270252bdcd5ac730739caf503cb494540a#rd)：Qwen 3.8-27B 为原生多模态稠密模型，Gated DeltaNet + Gated Attention 混合布局（64 层），262K 原生上下文可扩至 1M token，Apache 2.0 许可。此前群里呼声最高的就是 27B 版本（前情 [「Qwen 3.8 开源」]({{ '/daily/2026/08/12/daily/#qwen-38-开源' | relative_url }})），今天如约而至。

<span class="mention">@细心的熊猫</span> 算了一笔账：Opus 4.6 今年 2 月发布时还是 T 级参数，六个月后同等智能所需 VRAM 下降约 100 倍。<span class="mention">@今天群内信息量极大</span> 赶在航班前下载了 MLX 版准备断网测试，<span class="mention">@神秘的麋鹿</span> 也同步开拉 LM Studio 的 MLX 6bit。

量化版几乎同步涌出但质量天差地别。<span class="mention">@细心的熊猫</span> 在双 5060ti 上逐一试过，结论是 [unsloth NVFP4](https://huggingface.co/unsloth/Qwen3.8-27B-NVFP4) 表现很差，后出的 [RadixArk NVFP4](https://huggingface.co/RadixArk/Qwen3.8-27B-NVFP4) 好很多。根本原因在于 unsloth 用 compressed-tensors 框架走了不同 GEMM 路径，GDN 层（占 48/64 层）保留 bf16 不量化；RadixArk 忠实复刻 nvidia 官方 modelopt 配方（W4A4 激活也压到 FP4），与现有 prod 部署一致。

### 跑分实录

<span class="mention">@细心的熊猫</span> 用自建 BFCL-150 tool calling 测试集在双 5060ti 上跑了多组对比。Qwen 3.8（unsloth W4A4）不开 thinking 时总分 80.67，比 Qwen 3.6 的 90.67 低 10 分，parallel 和 irrelevance 类别退步明显。开 thinking（xhigh）也只回到 82。<span class="mention">@80-HD</span> 一度惊呼「反向升级」。

不过后续测试逐步逆转印象。reasoning_effort 档位对答案质量影响巨大：xhigh 模式思考 token 最多（1619），总 token 反而比 medium 少（2125 vs 2188），因为想清楚后给出极简答案——一道组合数学题只有 xhigh 直接给出正确结果，其余三档都在写长篇 markdown。

换到 RadixArk 量化版后体验进一步改善。<span class="mention">@细心的熊猫</span> 用 Claude 编排 Qwen 3.8 跑自建 agent eval，标注准确率从 10/11 升至 11/11。最终他将模型接入 Codex 使用，评价极高。

> <span class="mention">@细心的熊猫</span>：qwen3.8 27b牛逼炸了，接入了codex，用起来丝滑的狠

### 本地部署：Mac 与 5090

<span class="mention">@今天群内信息量极大</span> 在 MacBook M5 Max 上的体验则是另一极端。4bit MLX 量化 decode 约 22 tok/s 本身尚可忍受，但 Qwen 3.8 thinking 极其啰嗦——一个简单问题要长考三分钟——组合起来基本不可用。

> <span class="mention">@今天群内信息量极大</span>：腿都要给烤熟了，一看还在思考

5090 端也不省心。SM120 架构需要打补丁，不打会 seg fault，打了不能用原生 CUDA kernel 只能走 PyTorch，效率大降，当前 decode 仅 4 tok/s。其他用户的 5090 已跑到 prefill 13.5K/s、decode 160/s，说明是配置问题。<span class="mention">@今天群内信息量极大</span> 的合作者正在魔改 PyTorch 逐步排查，<span class="mention">@细心的熊猫</span> 建议用 sglang 官方 Docker 绕过补丁问题。

Mac 与 GPU 在 prefill 上有数量级差距，<span class="mention">@今天群内信息量极大</span> 自嘲经常喷夏利拉半挂。<span class="mention">@细心的熊猫</span> 给出双 5060ti 参考配置：无投机解码 35 tok/s、保留 160K context；开 DSpark 后单流 72 tok/s、context pool 约 93K。

### V4 Pro 首轮工具敏感

<span class="mention">@飘逸的猎豹</span> 转发了一组社区测试截图，揭示 V4 Pro 的一个关键弱点：模型对首轮请求的工具结构极其敏感。官方 Standard/PTC 模式只得 91/92 分，而 Minimal 模式（仅 shell + read 两个工具）反而跑到 99/96。

社区开发者写了一个 [dsh-anchored-standard 插件](https://github.com/xiaobright/dsh-anchored-standard)绕过问题：首轮只给 shell + read 锚定 Minimal 推理轨迹，第一次工具调用后立刻恢复 Standard 全部 25 项工具。Windows 上连跑两次 98/99，证明不是运气且不需牺牲完整工具能力。完整评测数据见 [modeltest 仓库](https://github.com/xiaobright/modeltest)。

含义耐人寻味：V4 Pro 的 RL 训练可能过拟合了 Minimal prompt 格式，首轮给太多工具反而让模型「丢了大脑」。这与发布当天的跑分混乱（前情 [「DeepSeek V4 Pro 发布乱局」]({{ '/daily/2026/08/13/daily/#deepseek-v4-pro-发布乱局' | relative_url }})）互为印证。<span class="mention">@随和的企鹅</span> 对 workaround 的实际价值持保留态度。

## 方法论

### Show the diff：高密度内容为何转发无效

<span class="mention">@冷静的飞鼠</span> 发布了一篇[关于内容传播壁垒的文章](https://www.superlinear.academy/c/main/ai-6868ff-719f323a-b5fc-4a94-84b5-9bd497c4e43d)：你手上有好东西推给同事学生，他们看完真诚地觉得说得挺对但没什么用——不是不努力，是察觉不到自己哪里没看懂。转发、倍速、再看一遍全都无效，有效的动作只有一个：show the diff——让对方先拆一段材料，你再拆，然后一起看差值。

<span class="mention">@今天群内信息量极大</span> 评价原始聊天信息量太大，掰开讲得是半小时一节课。<span class="mention">@80-HD</span> 从信息论角度展开：人际交流的本质瓶颈是带宽太低，你要先把想法抽象成语言再抽象成领域语言，对方则要先把自己「鸭化」才能映射回来。

> <span class="mention">@80-HD</span>：鸭哥教课的本质其实就是把脑子里的hashmap交给我，好让我能鸭化

> <span class="mention">@今天群内信息量极大</span>：刷榜是理性选择，无可指摘，我做模型我也刷。但就是觉得蛮搞笑的

### AI 旅行管家

<span class="mention">@今天群内信息量极大</span> 分享了两个 AI 自动化生活案例。一是花 10 块钱给散养的玫瑰加上手机遥控浇水——有 AI 前以为很难会想着雇人做，随口一问发现材料五金店都有、安装极简。二是 AI 在定时巡检中发现一个热带风暴即将升级为台风，会在他着陆后几小时登陆，随即查到航司已发布天气弹性改签政策，建议改签更早航班。

关键工作流是把所有旅行规划写在文件夹里，用定时任务在临近旅途时让 AI 每天甚至每半天全量扫描 context，检查是否有影响行程的新信息——调用的是他们的 OpenCode skill 和 background process manager skill。
