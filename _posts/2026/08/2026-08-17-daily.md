Qwen 3.8-27B 实测第四天，AA 智能指数 52 分追平 GPT-5.6 但中文写作让人看不懂——<span class="mention">@细心的熊猫</span> 用同一权重做的群聊 bot 却骗过了真人，差距全在调教。Codex 正式开放 1M 上下文窗口配置，<span class="mention">@热情的狮子</span> 调研后建议前 500K 视为高可信区、后半段作缓冲。Claude 水印去除工具 GitHub 爆星后，<span class="mention">@今天群内信息量极大</span> 的技术拆解指出九成是旧办法换新场景，值得一读。

## Qwen 3.8-27B 实测第四日

### AA 智能指数登顶开源

<span class="mention">@细心的熊猫</span> 贴出 Artificial Analysis Intelligence Index 最新排名：Qwen 3.8-27B 得分 52，与 GPT-5.6 Luna 版并列，而 Opus 4.6 max 只有 45 分（三天前的 [「开源上线与量化竞速」]({{ '/daily/2026/08/14/daily/#开源上线与量化竞速' | relative_url }})）。一个 27B 稠密模型做到这个水平，意味着 200B 以下的其他开源模型基本被斩杀——<span class="mention">@细心的熊猫</span> 形容帕累托前沿「被撑成了三角形」。

<span class="mention">@幽默的犀牛</span> 强调关键在于体积小，<span class="mention">@今天群内信息量极大</span> 感叹用商业 infra 部署速度岂不快到起飞。<span class="mention">@热情的狮子</span> 转发了[知乎评测讨论](https://www.zhihu.com/question/2071739761476293183/answer/2071972300879032426)，社区对 27B 的性能普遍震惊。

<span class="mention">@优雅的喜鹊</span> 凌晨还贴出一组 5090 上的并发 MTP3 decode 基准数据：Qwen 3.8-27B NVFP4 在 C=8 时聚合解码 766.6 tok/s，MTP 接受率仅 45–49%，显著低于 Qwen 3.6-27B NVFP4 的 67–71%（C=8 达 1,146.9 tok/s）。<span class="mention">@细心的熊猫</span> 惊叹 SGLang 单流就接近这些并发数值，且无需预计算任何 artifact。<span class="mention">@今天群内信息量极大</span> 另转发了一条 4.4 万浏览的推文：有人用 Qwen 3.8-27B 写浏览器 FPS 关卡、ChatGPT Image 生成世界资源，完全本地运行。

### 写作质量冰火两重天

<span class="mention">@搞仁义毛义仁</span> 报告几个朋友自部署 Qwen 3.8 写作文，产出的中文让人怀疑自己是不是外国人，怒而卸载。<span class="mention">@灵动的考拉</span> 也碰到大量不认识的词汇。<span class="mention">@今天群内信息量极大</span> 指出理工科强的 AI 写作一般都差，反过来写作好的模型做编程和 instruction following 又烂得一塌糊涂。

> <span class="mention">@搞仁义毛义仁</span>：这已经突破了AI味了，我觉得就算作文水平再差，至少要能写出"中文"才算合格

<span class="mention">@细心的熊猫</span> 贴出了截然相反的证据：他用同一模型在其他群部署的聊天 bot 表现出极强个性——被说话太密时反怼，被评价没用时回击要天天去差评区打卡——群友完全没发现在跟 AI 说话。差距显然在 prompt 调教而非模型本身。

<span class="mention">@优雅的喜鹊</span> 从技术侧补充了一个关键数据：MTP 接受率随内容类型剧烈变化——代码 76%、结构化输出 90%、翻译 75%，但创意写作只有 37%。这意味着 Qwen 3.8 在创意文本生成时不仅质量不稳，推理速度也大幅下降。<span class="mention">@细心的熊猫</span> 澄清接受率只影响速度不影响精度，但补充量化损失确实不小，还在等 NVIDIA 出官方量化版。

### 本地 DSH 连跑三小时

<span class="mention">@细心的熊猫</span> 让 Qwen 3.8 在 DSH 中连续工作超过三小时（190 分钟、488 步），执行网站逆向工程任务——这种活 Claude 经常拒绝干。他算了一笔经济账：LLM 运行 54 分钟、输入 4.1M token 输出 83K、0% cache hit，按 V4 Flash 空闲价格折算约 $1.47；双 5060ti 满载电费约 $0.15——API 价格的十分之一。

> <span class="mention">@细心的熊猫</span>：这个qwen3.8比3.6稳定多了，3.6之前开thinking经常出现输出崩坏的情况

他对 DSH 的稳定性评价很高，并透露 DSH 底层似乎基于 Pi 框架。<span class="mention">@坚定的貂</span> 表示等稳定性再好一些就从 Pi 切换过来，<span class="mention">@淡定的鸳鸯</span> 也认为 DSH 与 Pi 很像但自由度更高。

## 行业新闻

### Claude 水印去除工具爆火

<span class="mention">@稳重的海豚</span> 分享了[一篇报道](https://mp.weixin.qq.com/s?__biz=MzI2NDk5NzA0Mw==&mid=2248899184&idx=3&sn=5b76878b8ac79bc743b0f590d5b41ec0&chksm=e8717150288d5c07304f451e203df363e9eec088ff73b4d83c14ccf603a7cbe8fc1812cc5384#rd)：GitHub 上的 watermarks-remover 项目冲到 11,000 星，能清除 Claude 文本水印、Google SynthID-Text 和 OpenAI 隐形标记，还能剥离图像和 PDF 的 C2PA 元数据。此前群里已讨论过 Claude 水印的技术原理（上周 [「Claude 水印机制拆解」]({{ '/daily/2026/08/11/daily/#claude-水印机制拆解' | relative_url }})）。

<span class="mention">@今天群内信息量极大</span> 认为公众号在制造大新闻——Anthropic 从来没说过水印很强，发布时自己就承认重写后失效，类似工具也早已存在。他随后分享了自己写的[技术分析](https://yage.ai/share/claude-text-watermark-sampling-20260814.html)，核心观点是：文本水印技术九成是旧办法换新场景，与 JSON mode 本质相同——都是在每步生成时干预 token 概率分布，只是接上了密码学约束。真正的微创新只有 Google SynthID-Text 的 tournament sampling，而传播存活（抗改写）至今无解。

> <span class="mention">@今天群内信息量极大</span>：a家从来没说过水印很强，发布的时候自己就说了，重写了就没用了。有很多限制。而且类似的工具出现很久了，公众号非要写出史诗感

<span class="mention">@风趣的雪豹</span> 补了一刀：没有水印的文本合规不要算 Claude 头上。<span class="mention">@幽默的犀牛</span> 和 <span class="mention">@优雅的喜鹊</span> 则表示从中学到了文本水印原理。

## 工具

### Codex 开放 1M 上下文

昨晚 <span class="mention">@今天群内信息量极大</span> 发现 Codex 支持 1M token 上下文窗口后当即退订了 Claude Code，称「最后一个用 CC 的理由都没了」。<span class="mention">@洒脱的猫头鹰</span> 贴出配置方法：编辑 `~/.codex/config.toml`，设置 `model = "gpt-5.6-sol"`、`model_context_window = 1000000`、`model_auto_compact_token_limit = 900000`，重启 session 即可。

<span class="mention">@随和的企鹅</span> 提醒之前就能手动改 context 但效果并不好，建议 500K 更合理。<span class="mention">@热情的狮子</span> 晚间用 Codex 做了详细调研：OpenAI 数据显示 Sol 在 256K–512K 区间 MRCR 达 91.5%，但 512K–1M 降至 73.8%；GraphWalks 256K 达 90.7%，1M 仍有 77.1%，远高于 GPT-5.5 的 45.4%。社区反馈分化——有人报告 400K 以上开始重复文件和遗漏关联，也有人在大项目中依赖 compaction 未遇严重问题。

<span class="mention">@热情的狮子</span> 最终的建议是配置 1M 但将前 500K 视为高可信工作区，500K–900K 视为缓冲区，关键约束和任务状态仍应写进文件或 ledger。另一则相关变化是 <span class="mention">@随和的斑马</span> 发现 Codex 新版给 session 加了单设备锁——VSCode 开着时手机无法接管，此前可以无缝切换。<span class="mention">@开朗的企鹅</span> 确认确实被坑过。

### picturereader 读图插件

<span class="mention">@睿智的北极熊</span> 分享了开源项目 [picturereader](https://github.com/jing-hy/picturereader)：一款给 DeepSeek 等纯文本模型赋予读图能力的 DSH/ZCode 插件。核心链路默认零外部依赖，纯 JS 完成扫描取样解码，可选桥接本地或云端视觉模型做语义理解。v2.0 新增低信息量拦截避免空白图幻觉，以及多路证据交叉验证。

## 方法论

### 数学 Agent 的对照实验困境

<span class="mention">@坚定的貂</span> 与多位研究者交流后感叹现有 task-specific agent 大多是玄学，benchmark 做得不够严谨，数学领域尤其突出（前天的 [「Math Harness：1/10 Token 的野心」]({{ '/daily/2026/08/15/daily/#math-harness110-token-的野心' | relative_url }})）。<span class="mention">@随和的企鹅</span> 附和说最后都退化成了 prompt engineering。

<span class="mention">@坚定的貂</span> 随后在知乎发布了[问题征集帖](https://zhuanlan.zhihu.com/p/2072423975523816397)，寻找数学 agent 优于模型 zero-shot 的对照实验案例。他目前的基线是模型直接输入问题输出证明，harness 几乎不带 tools。<span class="mention">@稳重的海豚</span> 追问没有 thinking 怎么过得了，<span class="mention">@坚定的貂</span> 澄清模型本身可以思考，zero-shot 只是不给额外工具。

### V4 Flash 之上选什么

<span class="mention">@随和的企鹅</span> 提问 V4 Flash 之上性价比最高的选项。<span class="mention">@今天群内信息量极大</span> 推荐 Grok 4.6 配 SuperGrok Heavy 套餐（昨天的 [「SuperGrok Heavy 薅羊毛全攻略」]({{ '/daily/2026/08/16/daily/#supergrok-heavy-薅羊毛全攻略' | relative_url }})），但<span class="mention">@随和的企鹅</span> 实测 Grok 4.6 high 在工程场景下跟 Flash 差不多，对高评分感到困惑。<span class="mention">@今天群内信息量极大</span> 表示体感完全不在一个档次，双方分歧未解。<span class="mention">@今天群内信息量极大</span> 想了想觉得 Qwen 3.8-27B 或许有希望，但<span class="mention">@随和的企鹅</span> 指出它在 AA 指数上与 Flash 几乎持平。

<span class="mention">@随和的企鹅</span> 随即感叹这个月 AI 充值快一万元，K3 不让开新 coding plan、Qwen credit 计费又坑，有种为了快速爽一波 token 就冲动消费的游戏氪金感。不过昨天的 SuperGrok Heavy 折扣链接今天已经失效——<span class="mention">@稳重的海豚</span> 和 <span class="mention">@热情的狮子</span> 都确认打不开了，窗口期可能只有一天。
