今天 M5 Ultra 上架引爆了持续数小时的本地推理硬件辩论，<span class="mention">@今天群内信息量极大</span> 直指 Mac 算力与内存不均衡的核心矛盾，<span class="mention">@细心的熊猫</span> 却果断下单宣称这是理财产品。Qwen 3.8-Flash-Next 官宣明日开权重，125B-A6B 的 Qwen 4 架构预览让各路硬件玩家开始重新盘算部署方案。<span class="mention">@稳重的海豚</span> 关于认知疲劳的观察也值得一读——AI 加速了决策，思维缜密度可能正在悄然流失。

## M5 Ultra 选购战

### M5 Ultra 上架

<span class="mention">@细心的熊猫</span> 第一时间发现 Mac Studio M5 Ultra 开售：36-core CPU、80-core GPU、32-core Neural Engine，内存带宽 1.2 TB/s，最高 256GB 统一内存。96GB 版 $6,799，256GB 版 $10,799。Apple 官网还预告 512GB 内存选项将于十月底推出。

他根据已有 M5 Max 实测数据推算了 M5 Ultra 跑 Qwen 3.6-27B 4-bit + MTPLX D3 的理论性能：Prefill 约 1,100–1,500 tok/s，Decode 约 105–125 tok/s，128K 上下文约 45–55 tok/s。Apple 官方宣称 M5 Ultra 的 LLM prompt processing 速度是 M1 Ultra 的 9.8 倍、M3 Ultra 的 4.1 倍。

他当即用军折（10% off）以 $9,719 下单了 256GB 版本，取货日期排到 10 月 13 日——他观察到每隔一小时就往后推一周。<span class="mention">@灵动的考拉</span> 也下了单，预计 10 月底交货。<span class="mention">@优雅的喜鹊</span> 在欧洲看到同配置 €12,529，表示纯推理不如买 RTX PRO 6000。<span class="mention">@神秘的麋鹿</span> 算了一下国内定价，顶配 Ultra + 256GB 约 ¥86,000，走 EPP 约 ¥73,000。

<span class="mention">@活泼的羊驼</span> 从供应链角度做了成本拆解：裸 LPDDR5X 内存按当前现货价估算约 5 万人民币，加上 Apple 的定制工艺和利润加成，256GB 版光内存就值大几万。Ultra SKU 产量受限于 InFO-LSI 先进封装产能和当前 DRAM 大缺货，而非需求不足。

### Mac 算力困局

<span class="mention">@今天群内信息量极大</span> 泼了盆冷水。他实测 M5 Max 跑 Qwen 27B 约 22 tok/s（150W），而 5090 能到 200 tok/s（600W），算力差一个数量级。

> <span class="mention">@今天群内信息量极大</span>：Mac 整件事特别傻逼的一点就是，它的瓶颈在算力。这句话不是说它跑小模型跑不动，它的意思是如果跑小模型你为什么要大内存？真的能用上 Mac 大内存的模型，它又跑不动。

<span class="mention">@细心的熊猫</span> 反驳说 256GB 可以直接跑 DeepSeek V4 Flash——激活参数只有 13B，MoE 推理速度看激活参数。<span class="mention">@今天群内信息量极大</span> 回应他实测过，慢得不行。最终两人达成共识：Mac 和 5090 是互补关系——5090 跑 27B dense 无敌但 100B 以上 MoE 束手无策，Mac 大内存正好填这个空档。

<span class="mention">@细心的熊猫</span> 已规划好组合：4×5060ti 跑 Qwen 3.8-27B，Mac Studio 256GB 跑即将发布的 Qwen 3.8-Flash-Next（125B MoE），model routing 分流。<span class="mention">@优雅的喜鹊</span> 则打算用两台 DGX Spark 组 Flash + 5090 部署 27B 做路由。<span class="mention">@今天群内信息量极大</span> 的最终判断：自组硬件预算 5–10 万美元以下基本都是玩具。

### GPU 即理财产品

硬件价格飞涨成了独立话题。<span class="mention">@细心的熊猫</span> 查到 M3 Ultra 256GB 二手成交价已达 $12,050–$13,746，远超原价。他反复强调——买回来用一年还能加价卖出，完全就是印钞机。<span class="mention">@温暖的斑马</span> 在自家社区发现一台今年 4 月购入未拆封的 M3 Ultra 512GB，挂价 $23,900。

<span class="mention">@活泼的羊驼</span> 贴出韩国 NAND 闪存出口单价走势图：从 2024 年约 $10,000/kg 飙升到 2026 年 8 月近 $100,000/kg，涨了约六倍。5090 显卡也在涨——Qwen 3.8 发布后又涨了 20%。

一个有趣的倒挂行情：HP OMEN 45L 搭载 RTX 5090 的整机售价 $4,799（原价 $6,999 直降 $2,200），比单买一张华硕 ROG Astral 5090（$4,829）还便宜。<span class="mention">@稳重的海豚</span> 用 Grok Build 查完发现已 sold out。

<span class="mention">@温暖的斑马</span> 从宏观角度提醒：11 月美国中期选举前这些硬件都会继续涨价，想炒要抓紧。<span class="mention">@热情的大象</span> 指出矛盾——硬件降价需要 AI 叙事出问题，但那样 coding plan 补贴也会受影响。<span class="mention">@稳重的海豚</span> 一句话总结了死循环：那时候就需要本地了，然后本地暴涨。

## 行业新闻

### Qwen 3.8-Flash-Next 明日开权重

<span class="mention">@优雅的喜鹊</span> 发现 Hugging Face 和 ModelScope 同步上线了 Qwen 3.8-Flash-Next 预告页，倒计时指向 8 月 26 日，标记为 Qwen 4 架构预览。阿里官方 X 账号同日发推确认。他整理了一份跨论坛深挖报告，核心规格如下：

- 多模态 MoE，125B 主模型参数 + 51B N-gram 嵌入表，每 token 激活 6B
- GDN 混合层 + Qwen Sparse Attention（QSA）
- 训练成本约为 Qwen 3.7-Plus 的 1/9，coding 和 agentic 任务更强
- 预计发布 FP8 版本

<span class="mention">@细心的熊猫</span> 判断这个模型是对着 DGX Spark 口径开发的——4bpw 量化约 82GB，单台 Spark 121GB 刚好能跑。他进一步预言 Qwen 4 的 27B 版将达到 Claude Opus 4.8 水平，并断言 Anthropic 和 OpenAI 快被活埋——大参数容纳的是知识而非推理能力，小模型配合搜索 API 就可以媲美大模型。<span class="mention">@专注的剑鱼</span> 更冷静，认为主要变化在架构，51B N-gram Embedding 是新变量，需等实测。

### Codex 额度重置与 Sol 质量波动

<span class="mention">@洒脱的狐狸</span> 确认 Codex 今晨再次重置，额度回满 100%，下次重置 9 月 1 日（前天 [「Codex Plus 5h 限制回归」]({{ '/daily/2026/08/24/daily/#codex-plus-5h-限制回归' | relative_url }}) 预告的全量 reset 已落地）。但 5 小时限制同时回归。

Sol 质量方面，<span class="mention">@沉稳的兔子</span> 吐槽同一个 feature 在三个轮次被做了三个不同实现，体感回到 Codex 5.3 时代——不看现有代码、连续套娃三层。<span class="mention">@睿智的北极熊</span> 也遇到大需求做不完、每次 review 报一堆新问题。<span class="mention">@细心的熊猫</span> 猜测是量化降智。

<span class="mention">@坚定的貂</span> 从更底层挖到一个 [multi-agent 路由 bug](https://github.com/openai/codex/issues/37113)：Sol 在 `spawn_agent` 成功后，本应调用 `collaboration.wait_agent` 等待子 agent，却有时错误地调用了不相关的 `functions.wait`，导致子 agent 结果无法回收。他还指出一个[关联问题](https://github.com/openai/codex/issues/35259)：等待/轮询子 agent 时 Codex 反复触发模型推理，一个 11 小时长任务中 45% 的 token 仅用于状态检查。他自己写的 harness 跑同一 prompt 表现极好，而 Codex 原生方案跑了 10 小时。

## 工具

### NInfer 极限推理

<span class="mention">@今天群内信息量极大</span> 推荐了 [NInfer](https://github.com/Neroued/ninfer)——从零手写的 C++/CUDA 推理引擎，专门针对 RTX 5090 + Qwen 系列极限优化（前情 [「单卡超越官方基准」]({{ '/daily/2026/08/22/daily/#单卡超越官方基准' | relative_url }})）。Qwen 3.6-35B-A3B 在 C=8 并发下聚合解码达 1,314 tok/s，Qwen 3.6-27B NVFP4 的 7.6K prompt prefill 达 11,192 tok/s。代价是极端特化：只支持 5090，只支持注册的几个 Qwen checkpoint，别的模型别的卡都用不了——但已有人移植到 4090 上。

<span class="mention">@优雅的喜鹊</span> 做了简单对比：NInfer + MTP 单请求 decode 172 tok/s、prefill 1.470s，与 SGLang + NEXTN（165–183 tok/s、1.466s）接近。<span class="mention">@今天群内信息量极大</span> 指出 NInfer 优势主要在高并发和 prefill 速度。他感慨 27B 是第一次让他觉得消费级显卡能跑可用的 agentic 模型——GLM、KIMI 都太大了。

### 5090 三卡集群与降压调优

<span class="mention">@今天群内信息量极大</span> 用 NInfer 把单个 service stack 压到一张卡上，三卡 5090 负载均衡终于跑满功率，一天重载消耗 1.5 亿 token（前情 [「2×5090 自托管全景分析」]({{ '/daily/2026/08/24/daily/#25090-自托管全景分析' | relative_url }})）。瓶颈不在 GPU 而在电力——美国 110V 下单机功率已超电力法规要求，现在两个 2000W 电源接在不同空气开关上降低起火风险，加第四张卡需要接入 220V 工业电。

<span class="mention">@细心的熊猫</span> 让 AI 做了一轮降压超频调优：解码速度提升 6.3%，功耗从峰值 112W 降到 82–91W（约降 20%），greedy 输出 SHA 哈希完全一致，精度零损失。

<span class="mention">@今天群内信息量极大</span> 还发现了本地推理的隐性收益：通过 serve log 可以看到 harness 背后的操作——有些 harness 为省 context 做中间信息压缩，反而造成 cache miss，整段 prefill 要重算，半分钟一分钟地等。这类性能黑洞用云端 API 根本无从诊断。

## 方法论

### 非 agentic 验收不可少

昨晚 <span class="mention">@灵动的考拉</span> 反映他的 Codex 也连续跑了一个周末、基本在自说自话并破坏了很多既有代码，<span class="mention">@稳重的海豚</span> 建议做 incremental delivery 多阶段验收。<span class="mention">@坦荡的灰熊</span> 叫苦：他的任务是改底层架构、表层维持原状，分层验收都不知道怎么分——事先还跟 AI grill 了三个小时。

延续近日的讨论（[「Follow instruction 与品味对齐」]({{ '/daily/2026/08/24/daily/#follow-instruction-与品味对齐' | relative_url }})），<span class="mention">@搞仁义毛义仁</span> 凌晨给出判断框架：如果原项目 test coverage 充足且测试没被改动，验收核心就是看 AI 有没有 over-engineering。新架构设计有问题时，AI 只能做扭曲的事来满足测试——这时只能通读代码用直觉快速判断。

> <span class="mention">@搞仁义毛义仁</span>：可信的非 agentic 的验收手段是一定要有的

他区分了两个维度：非 agentic 解决 AI 的问题（确保输出正确），可信解决人的问题（让人不必逐行看也能确认结果）。极端情况下，100% 可信的非 agentic 验收意味着看到 AI 跑了就知道对了——人的注意力有限，要在单位时间做更多事就只能关注更少信息，但质量不能降。

<span class="mention">@活泼的羊驼</span> 补充自己也专门做了一个 over-engineering 的 skill，强调读代码仍然必要——如果自己读起来不快不舒服，说明 AI 写的也不行。<span class="mention">@稳重的海豚</span> 坦言自己一两年没手敲过代码，只让 AI 画架构图来审。<span class="mention">@认真的荷兰猪</span> 为此发了一份 [AI 代码阅读习惯调查](https://docs.google.com/forms/d/e/1FAIpQLSd3_EXAoRUfrAJKg0OB2PczoP2wKmXIs9ldEf8-aMdq68IKWA/viewform)，想摸底大家实际阅读 AI 代码的程度。

### 认知疲劳与生产性摩擦

<span class="mention">@稳重的海豚</span> 抛出了一个深层观察：AI 使用导致思维缜密度下降——以前可以花几天甚至几周思考架构设计，现在需要在几小时内做出决策，长期产生认知疲劳。他认为这是各家 AI 公司频出安全漏洞、支付 bug、发布会贴图错误的底层原因。

> <span class="mention">@稳重的海豚</span>：思维的缜密度一旦开始流失，同时缺乏培养这个缜密度的环境和路径，就很难再次获得。这也是为啥我用了这么久 AI，现在又开始强迫自己把学到的知识整理下来再表述出来

<span class="mention">@热情的大象</span> 深表共鸣，把这类刻意保留的手动环节定义为可以提供训练信号的「生产性摩擦」。他还追问：看到答案再讲明白，和自己从头想出答案，学生获得的是否一样？<span class="mention">@稳重的海豚</span> 回应说他设计的教学方案是让学生当面答辩——不吃透了答不出来。<span class="mention">@搞仁义毛义仁</span> 则建议更务实：累了就不做，脑子不清醒判断都做不了了。<span class="mention">@热情的大象</span> 补充说蹬 agent 会上瘾，需要刻意休息。

这场讨论的起因是面试手写代码是否过时的争论。<span class="mention">@稳重的海豚</span> 认为金融公司还让人手敲代码没跟上时代；<span class="mention">@搞仁义毛义仁</span> 冷知识一击——CS 本来就不教编程，编程得下课自己来，更别指望老师会写代码。
