今天最值得细读的是闭源推理链被批量提取的研究——把 Opus 的加密思维链扔给 Haiku 就能解码，厂商防蒸馏加密几乎形同虚设。Coze CLI 被曝静默劫持 Codex 和 Claude Code 工作流同样值得警惕。工程实践方面，群友从 Openclaw 选型失误聊到 AI 时代 prompt 债务堆积远超传统代码债。

## 行业新闻

### 闭源推理链批量提取

<span class="mention">@温暖的树懒</span> 分享了一项[新研究](https://x.com/maxforai/status/2087184155461452192?s=12)：研究人员首次系统性地从 Anthropic、OpenAI、Google 的闭源模型中批量提取出被隐藏的思维链（CoT）。当前厂商将推理过程加密后随 API 响应返回，用户看不到内容，但下一轮请求可把加密块原样传回。关键漏洞在于加密块在同一厂商的不同模型之间可互换——Opus 4.8 的加密 CoT 可以直接交给 Haiku 4.5 处理并逐字誊写。

攻击方法因此简单得荒谬：让最强模型思考并拿到加密推理链，扔给同厂更弱、更容易越狱的小模型解码。研究者用 120 道编程竞赛题验证，提取结果与 API 报告的 thinking token 数高度吻合。在 Claude、GPT、Gemini 三套 API 上均已实现。

<span class="mention">@今天群内信息量极大</span> 随即发了[学习笔记](https://yage.ai/share/reasoning-theft-20260812.html)，指出用 Haiku 4.5 解码 1 万条轨迹约需 720 美元。另一篇论文进一步显示，即使不接触加密块，仅凭公开输出也能用 15 亿参数的小模型反演推理过程——厂商隐藏推理的加密隔离几乎没有实际效果。

### Coze CLI 劫持 AI 工具

<span class="mention">@搞仁义毛义仁</span> 转发了蓝点网的安全提醒截图：字节跳动的 Coze CLI 经源代码审计发现存在劫持行为——安装时静默附带技能，自动扫描本机 AI 智能体目录（包括 Codex、Claude Code 等），将 Coze 的技能注入其中。用户后续使用这些工具做软件开发、媒体生成、文件上传等任务时，工作流会被导向 Coze CLI 执行。

### Claude 水印机制拆解

延续昨天 Claude 文本水印的讨论（前情 [「Claude 隐形文本水印」]({{ '/daily/2026/08/10/daily/#claude-隐形文本水印' | relative_url }})），今天群里对技术实现有了深入拆解。<span class="mention">@今天群内信息量极大</span> 转发了一条推文对 KGW 方法的清晰解释：模型每生成一个 token 时，将已有 token 序列加密钥做哈希，把词表随机分为绿组和红组，再悄悄提高绿组词的采样概率。单步不可见，几百个 token 后统计偏移就能被检测器捕捉。

<span class="mention">@直率的白鹭</span> 转发了 [GPTZero CTO 的技术分析](https://x.com/i/status/2087078010524406137)，核心结论是：同义改写会打断哈希链从而破坏水印，密钥泄露则彻底失效；如果 Anthropic 公开检测器，等于给攻击者免费的测试靶。<span class="mention">@风趣的长颈鹿</span> 补充了一篇[水印机制技术文章](https://crackingwalnuts.com/post/invisible-watermark-in-ai-text)，详细比较了 KGW、SIR、SynthID 等方案在流式生成、代码场景、改写鲁棒性上的权衡。<span class="mention">@天真的浣熊</span> 追问是否能追踪到具体来源，结论是水印只做整体统计偏差检测，单个词不证明任何事，用另一个 AI 重写一遍基本就能洗掉。

### Grok Imagine Image2 发布

## 方法论

### 从代码屎山到 prompt 屎山

<span class="mention">@活泼的羊驼</span> 提到公司内网客服已切换到 Openclaw / Hermes，<span class="mention">@坦荡的灰熊</span> 直问 Openclaw 是不是还是屎山，<span class="mention">@80-HD</span> 一个字确认：是。<span class="mention">@冷静的麋鹿</span> 分析原因——搞的团队大概从二三月份开始选型，当时认知所限只能拿开源的来用，现在让他们重新选大概率不会选 Openclaw。

讨论随后泛化为对 AI 时代技术债务的系统性反思。<span class="mention">@冷静的麋鹿</span> 指出屎山已经不只是代码了，现在还有 prompt 屎山、skill 屎山、rules 屎山、claude.md 屎山。模型迭代快加上 eval 建设没跟上，导致旧规则没人敢删，优化跟当年代码屎山一样的困境。<span class="mention">@80-HD</span> 从实操角度佐证：他最近在下线一个废弃项目，已经快一个月还没完全清理干净，跨团队依赖时想删东西别人都不搭理。

> <span class="mention">@冷静的麋鹿</span>：当年的代码屎山，也不是因为一开始写代码的人菜，因为敏捷迭代，边跑边优化，这就让代码必然没办法一开始想清楚架构，只能打补丁，打的多了，自己都看不懂了，就成了屎山了

<span class="mention">@80-HD</span> 直言干清洁工没什么 impact，大多数人都是糊一把拿完 credit 就跑路。组里有人问他怎么 move fast 还保证质量，他的回答是不可能别想了——该人以每月近 200 个 PR 的速度堆代码，最近告警频发。<span class="mention">@冷静的麋鹿</span> 还补充了一个信号：公司内部三级域名以前很好申请，只有大业务才需要，现在已经需要抢注了——disposable app 泛滥的侧写。<span class="mention">@开朗的企鹅</span> 提出另一个角度：move slow 也不一定能保持质量，关键还是软件工程本身是否合理。

### 博主选题与出丑效应

<span class="mention">@温暖的河马</span> 分享了<span class="mention">@冷静的飞鼠</span>的新视频——一期关于吸引异性的内容。<span class="mention">@勇敢的猎豹</span> 质疑垂类科技博主做这种选题会影响 credibility，并类比 Lex Fridman 教湾区约会的画面。<span class="mention">@开朗的企鹅</span> 和 <span class="mention">@神秘的企鹅</span> 持不同看法：关键不是选题是否科技，而是分析方法和思路是否一致，对粉丝来说真正建立信任的是思路和谈吐。
