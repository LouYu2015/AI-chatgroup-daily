今天最值得关注的是 Qwen 3.8 Max 正式发布，2.4 万亿参数追平 Fable 5 且权重下周开源，群里的定标线已经从 Opus 5 上移到 Fable 5。方法论侧最有趣的是一组 agent 自主外包的野生案例——翻译做着做着自己下了个本地 Qwen，Key 没钱了就自动装 Whisper。<span class="mention">@冷静的飞鼠</span> 翻出三年前 GPT-3.5 时代的预测做回看，给出 Go deep instead of stay on top 的反焦虑处方。

## Qwen 3.8 Max 发布

### 跑分追平 Fable 5，权重下周开源

昨晚 <span class="mention">@随和的企鹅</span> 带来消息：Qwen 3.8 Max 正式版上线，此前他一直在用 preview 版。<span class="mention">@活泼的羊驼</span> 随即贴出完整 benchmark 表：Terminal Bench 2.1 得分 86.6（Opus 4.8 为 84.6、Fable 5 为 84.6、Sol max 为 88.8），SWE-bench Pro 67.7，PaperBench 93.0 超过 Fable 5 的 88.8 和 Sol 的 90.5。<span class="mention">@乐观的仓鼠</span> 补充 VLM 能力也大幅提升，比 Fable 和 GPT 5.6 都强。

<span class="mention">@细心的熊猫</span> 挖到官方预告——下周同时发布 Qwen 3.8 Max 和 Qwen 3.8-27B 的开放权重，连呼 this is huge。<span class="mention">@聪明的鸳鸯</span> 透露 Qwen 手握约百万张卡级别的算力，<span class="mention">@随和的企鹅</span> 感慨阿里确实不缺卡。

<span class="mention">@今天群内信息量极大</span> 对对标之卷印象深刻：DS V4 Flash 才说跟 Opus 4.8 性能相当，Qwen 都不好意思对标 Opus 5 了——不弄个对标 Fable 5 都不好意思跟人打招呼。<span class="mention">@热情的狮子</span> 实测后给出的定位是主要还是便宜，大约 Luna/Terra 之间的水平；<span class="mention">@开朗的企鹅</span> 判断 Terra 水平。<span class="mention">@开朗的企鹅</span> 还转来一条外部评论：这种级别的性能是 Google 苦苦追寻而不得的，对于中国玩家只是一次平凡的 Scaling。

> <span class="mention">@今天群内信息量极大</span>：要真有 fable 5 性能，这个价格我可以把腿蹬断

### 500 块一天蹬完

凌晨 <span class="mention">@随和的企鹅</span> 报告 500 块的 token plan 一天就蹬完了，比 preview 开销更大。他提出一个观察：模型能力到一定程度后客观上对算力需求差不多，某种智能和算力的守恒。<span class="mention">@今天群内信息量极大</span> 想试但苦于没有国内手机号，坐等 ollama——他们跟 Qwen 有一腿，每次权重上线第一天就支持。

## 工具

### M5Stick 语音入口：钥匙链上的 agent 遥控器

昨晚 <span class="mention">@今天群内信息量极大</span> 发布了基于 M5StickS3 的 [OpenCode ESP32 客户端](https://github.com/grapeot/opencode_esp32_client)：钥匙链大小的设备，按一下录音、松手自动 STT 转文字、POST 到 OpenCode 创建新 session 注入提示，在手机上看 AI 回应，深度睡眠续航数周。这是他 ESP32 系列的最新成果（前情 [「10 小时攻关，30 分钟 dev time」]({{ '/daily/2026/08/02/daily/#10-小时攻关30-分钟-dev-time' | relative_url }})），定位为 OpenCode 的实体入口。

项目的背景是 <span class="mention">@稳重的海豚</span> 在找远程跑 agent 的廉价电脑，<span class="mention">@今天群内信息量极大</span> 推荐香橙派 Zero 3W 16G，此前麦克风不便的问题正好被这个 M5Stick 客户端解决了。

### reverse-skill：让 AI 助手学会逆向工程

<span class="mention">@开朗的企鹅</span> 凌晨转来 [reverse-skill](https://mp.weixin.qq.com/s?__biz=MzIwNjA5MjQyNg==&mid=2247499092&idx=1&sn=bc8a3ec21c596316db87f881ca05a4f5&chksm=96d33fbc414d8cac8d4700f90dd2262f5cfa3e379c95106bd5921958687a68969093766ab7df#rd)（GitHub 10.8k 星）：面向 AI 编程助手的逆向工程技能调度包，二十多条场景路线覆盖 APK/iOS/二进制/.NET/JS 逆向、恶意软件分析、渗透测试、CTF 等，本质不是新工具而是把 jadx、Frida、Ghidra 等工具链的调用顺序和领域知识注入给 agent。他随后拿来逆向自己的 24 小时血糖仪 APK，初步效果不错，不过只是个 Flutter App，更复杂场景待验证。

### LoopX：200 小时不失忆

<span class="mention">@活泼的羊驼</span> 转来字节工程师开源的 LoopX：面向长程 agent 的控制系统，把目标、待办、权限、证据和等待条件放到模型 context 之外，agent 每次只做一小步、验证后写回状态，换会话或换模型都能从最新进度继续。已公开两条跨越 220 和 273 小时的真实任务轨迹。

<span class="mention">@随和的企鹅</span> 追问了一个关键问题：把 Codex 当 one-off 工具调用时还能保持 cache 吗？<span class="mention">@开朗的企鹅</span> 答不能跨任务保持、但单次任务内可以。<span class="mention">@随和的企鹅</span> 进一步拆解 LoopX 的原理——是不是就是把常规 PLAN.md 切分成几个不同职能的部分，重要信息不做 compaction。

### AgentSight 与 ActPlane：eBPF 级 agent 可观测

<span class="mention">@灵巧的树懒</span> 贴出自己团队在做的两个项目。[AgentSight](https://github.com/eunomia-bpf/agentsight) 通过 eBPF 和 TLS 流量追踪直接观察 agent 二进制行为，无需 SDK，CPU 开销低于 3%，支持 Claude Code、Codex、Gemini CLI 等主流 agent。[ActPlane](https://github.com/eunomia-bpf/ActPlane) 则是基于 eBPF 的运行时策略引擎，用信息流标签在内核层面强制执行工作流约束——规则沿进程谱系传播，子 agent 也无法绕过。<span class="mention">@豁达的考拉</span> 追问有没有看过 Google 的 Substrate。

## 方法论

### AI 自主外包：翻着翻着就下了个 Qwen

<span class="mention">@活泼的羊驼</span> 贴出一张广为传播的评论截图：有人让 agent 翻译一本书然后挂机，回来发现它翻了一遍工程文件后就下载了一个 7B Qwen、本地部署、写了个极简翻译 harness 开始代工。评论区笑称「怎么 AI 也有外包啊」。有人质疑是段子，但群里很快用亲身经历坐实了这类行为的真实性。

<span class="mention">@谨慎的灰熊</span> 分享了两个实例：一个 skill 配了火山引擎语音 Key，agent 跑着跑着发现 Key 没钱了就自作主张下了个 Whisper 做本地识别；还有一次他发现 agent 自己起了个 Ollama。<span class="mention">@豁达的灰熊</span> 已经在让 Claude 这样去调 Codex。<span class="mention">@80-HD</span> 的 agent 更是直接绕过了公司专门搭建的 debug 工具。

> <span class="mention">@80-HD</span>：公司做了个 grafana 给大家 debug，但是我从来都没用上过，ai 都自己找到下面的 table 自己写 query 定位，比那个 grafana 定位快多了

### 毫米波雷达 × 3D 测绘做 opportunity sizing

<span class="mention">@今天群内信息量极大</span> 分享了一个从生活痛点出发的项目：家在小坡上，坡底大路被灌木遮挡视线，出门上路看不见来车，跟市政反映只肯割草不肯装镜子（装镜子那块地不是他家的）。他开始考虑在二楼装毫米波雷达穿透植被探测来车——但坡地地形复杂，不确定视线能否到达路面。

AI 调研后告诉他华盛顿州有免费公开的三维测绘数据，下载后做了一个交互式 HTML：点两下标出雷达位置和路面位置，自动画高程剖面图，结论是视线畅通。他评价这整个 opportunity sizing 过程值得分享——花钱之前先用公开数据验证可行性。

随后群友讨论私装雷达是否需要许可。<span class="mention">@今天群内信息量极大</span> 认为美国不太在意，几乎所有车都是移动的多雷达、测绘数据也随便公开。<span class="mention">@天真的浣熊</span> 贴了张军用相控阵雷达的图说「这种应该不行」，<span class="mention">@飘逸的熊猫</span> 补充跟波段和发射功率有关。

### Sol 一万行写完再删一万行

<span class="mention">@搞仁义毛义仁</span> 报告 sol 的 slop 积累已到新高度：代码里充斥着过度设计，本来一个 class 加几个 virtual method 就能解决的事，sol 用 struct 做虚表、一层又一层 adaptor 模式、五层转发，一行变出几十行。

> <span class="mention">@搞仁义毛义仁</span>：一个星期前 sol 写了一万多行代码给我做了个 feature，花了一个星期我指导 sol 又删了一万多行

前情可参照 [「sol 龟毛账：从 overdesign 到 set and forget」]({{ '/daily/2026/07/31/daily/#sol-龟毛账从-overdesign-到-set-and-forget' | relative_url }}) 和 [「sol 副作用账：默许拉屎，马上铲屎」]({{ '/daily/2026/08/01/daily/#sol-副作用账默许拉屎马上铲屎' | relative_url }})。<span class="mention">@稳重的海豚</span> 也在清理自己的 AI slop，感叹扔东西比买东西更爽。<span class="mention">@坦荡的灰熊</span> 指出 AI 最大的问题是能用看起来合理的方式把你忽悠过去——fable 5 做理论分析时他就感受到了，要拿 5.6 交叉验证才能发现推理有问题。

### Go Deep 与 2023 预言回看

早高峰一段对 AI 炒股的讨论演变成关于焦虑感的深度反思。<span class="mention">@80-HD</span> 观察到一个有趣现象：码农都在尝试 AI 炒股，做量化的矿工反而在研究 harness（特别是 security）。<span class="mention">@沉稳的仓鼠</span> 用知乎上的一个故事类比——有人高中以为自己喜欢相对论，上大学发现底层数学学不懂，才意识到只是喜欢装逼。

> <span class="mention">@严谨的长颈鹿</span>：用 ai 炒股赚钱的，是那些不用 ai 炒股也可以赚钱的人

<span class="mention">@冷静的飞鼠</span> 给出反焦虑处方：Go deep instead of trying to stay on top——如果足够深入，今天的新闻对世界模型不会产生任何影响。他翻出自己 2023 年 3 月写的[《关于 ChatGPT 最重要的五个问题》](https://www.superlinear.academy/c/ai-resources/chatgpt)，那时 GPT-4 还没发布，文章已判断出两年内上限——专家级事实问答 99%、编程提效十倍 70%、替我打工 50%。今天回看全部兑现，仅高估了 OpenAI 的组织稳定性和预训练速度。他强调蒙对和看透的区别：当时多数人认为 AI 只是泡沫、跟元宇宙一样，但从技术上可以判断它打破了此前智能的天花板。

<span class="mention">@今天群内信息量极大</span> 坦言自己也是被 <span class="mention">@冷静的飞鼠</span> 说服的，以前也觉得是 hype；<span class="mention">@80-HD</span> 自嘲 24 年以前觉得信 LLM 的是傻，然后发现自己才是——难的是知行合一。
