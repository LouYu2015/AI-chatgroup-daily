## 方法论

### DeepSeek V4 Pro 中文写作实测

<span class="mention">@冷静的麋鹿</span> 因 Codex 账号被封，切到 OpenCode 中转站试用 DeepSeek V4 Pro，结果「非常惊喜」。他详细描述了一个完整工作流——在老鸭汤里做调研、写分析、写网站稿、修饰发布、复核——DS V4 Pro 的中文文章质量「比 GPT-5.5 强，有 Opus 4.6 当年那个味道，甚至夸张点讲，中文文章我觉得好像比 Opus 4.6 还牛逼一点。或者说，比最近的 Opus 4.6 强」。全流程约三十分钟跑完，只有一个小格式复核没完成。

指令跟随方面他做了六七次测试：Opus 和 GPT 几乎百分百遵循老鸭汤设定；DS V4 Pro 也很稳，每次都按要求读取五个必读文件；V4 Flash 偶尔不稳定；Gemini 3.5 Flash 和部分国内模型不一定完全遵循。基于价格和 1M 上下文窗口，他判断 DS V4 Pro 能进入常备模型梯队，「对于文案之类的工作，似乎能够完全胜任，并且优于其他」。

> <span class="mention">@冷静的麋鹿</span>：难怪鸭哥，边骂边用

<span class="mention">@今天群内信息量极大</span> 回应：「骂得多其实某种程度上是正面信号，比如 MiniMax M3，就骂了一次再也没用过。」这与前天 [「DeepSeek 写文一流写码翻车」]({{ '/daily/2026/06/03/daily/#deepseek-写文一流写码翻车' | relative_url }}) 的判断完全一致——DS 写作惊艳但写代码让人骂娘，如今多了一个群友的独立验证。

另外当天末尾，<span class="mention">@谨慎的树懒</span> 也赞叹 DeepSeek 的 agentic 能力——给它一张图，它「自己写 OpenCV，尝试各种脚本，最后把图片转成 ASCII 来解读」，堪称不达目的不罢休。

### AI 打通生活琐事

<span class="mention">@今天群内信息量极大</span> 分享了一个具体案例：填孩子报名表需要牙医和全科医生的姓名、地址、联系方式和上次体检时间，表格还是 Word 下划线格式——「填过这种下划线表格的人可能会有共鸣，特别麻烦，保守估计怎么着也得填个 15–20 分钟」。他花半分钟告诉 AI 医生名字，AI 用网络搜索 skill 查电话地址、用 Outlook skill 翻 calendar 找体检日期、用 docx skill 填表，全部搞定。

> <span class="mention">@今天群内信息量极大</span>：现在自从把很多东西通过 skill 和 AI 打通之后，以前感觉摩擦特别大的环节都可以轻松被 AI 搞定，整个生活质量高了很多

签证申请也是如此——个人信息存在 1Password 里，AI 直接填，「我都不用嘴炮」，而且信息积累下来「下次申请别的国家的签证又能复用」。<span class="mention">@严谨的老虎</span> 补充了另一个场景：学校一整年的活动 calendar 需要家长自己记，一个个去 mark 至少 30 分钟。<span class="mention">@80-HD</span> 说自己的做法是拍照给 AI，以前用 ChatGPT 生成 ical，「现在就直接进日历了」。

## 工具

### Codex 跨设备 Session 管理

<span class="mention">@我要成为灵能高手</span> 提出一个实际需求：他昨天让 Codex 修整个 monorepo 的 CI，C++ 编译太慢跑了 18 个小时，「一下干掉了 1/4 weekly limit」。他想让笔记本上的 Codex 任务在做完一段后自动转交给 3 倍速的台式机接着干。昨晚已经用 GitHub 当 semaphore 实现了「睡觉后台式机接手」，但希望多个 Codex 客户端能直接通信。核心卡点是远程登录 Windows 有绕不过去的 authentication 问题。

<span class="mention">@开朗的企鹅</span> 深挖了 Codex 的 [app-server 文档](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md)，发现关键过滤规则：`thread/list` 的 `sourceKinds` 省略时只返回 interactive sessions（cli 和 vscode），`codex exec` 产生的 source 为 exec，默认不进 App 历史列表。想让 exec 线程显示，需要把 `threads.source` 从 exec 改为 cli——但他警告「这相当于伪造线程类型」，不建议在主数据上做。另一个坑：通过 API key 和 subscription 创建的 session source 不同，无法互相 resume，从中转站切到 subscription 需要修改 source。

他还推荐了自己的 [AgentHub-OSS](https://github.com/holdonyb/AgentHub-OSS)——一个自托管的 agent 会话控制平面，解决 Codex、Claude Code 等本地 agent 的跨设备统一管理问题，支持 Tailscale 内网和 HTTPS 公网两种接入模式。

### PDF 转 Markdown 工具选型

<span class="mention">@温暖的斑马</span> 用 Gemini 提取 14 章 PDF，结果只提了 4 章就宣布「全部干完了」。<span class="mention">@稳重的海豚</span> 评价新 Gemini 模型「稳定性相当差了，但只要多试几次总有一次能过，所以跑分高」。<span class="mention">@温暖的斑马</span> 对比发现千问表现出色——「很乱的扫描 PDF，居然把图片、文字都大差不差整理出来」；DeepSeek「很守规矩」，说不能直接生成 PDF 但完整抓出 300 页书的文字，「真是好孩子」。

<span class="mention">@80-HD</span> 追问如果是扫描 PDF 怎么办，<span class="mention">@今天群内信息量极大</span> 直接甩出老鸭汤里的 [PDF 转 Markdown best practice 文档](https://github.com/grapeot/context-infrastructure/blob/main/rules/skills/bestpractice_pdf_to_markdown.md)。核心路径选择：文本 PDF 首选 Docling（benchmark 综合得分 0.882，MIT 许可），英文扫描件也走 Docling 自带 OCR；中文扫描件、图文混排则走 LM Studio VLM OCR，逐页渲染为 200 DPI 图片喂给视觉模型。<span class="mention">@80-HD</span> 感叹：「老鸭汤真是什么都有。」

## 闲聊花絮
