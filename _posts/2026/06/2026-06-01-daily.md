## Alpha/Beta 再定义

### 对冲基金：Alpha is Zero-Sum

接续前天 [「Beta 哲学：用 AI 别追 Alpha」]({{ '/daily/2026/05/30/daily/#beta-哲学用-ai-别追-alpha' | relative_url }}) 的大讨论，今天最先开口的是 <span class="mention">@风趣的犀牛</span>——他在平台式对冲基金工作，给出了全场最严谨的 Alpha 定义：

> <span class="mention">@风趣的犀牛</span>：Alpha is skill. Alpha is effort. Which is why alpha is highly paid and why alpha is so hard.

追问之后的第二句同样利落：

> <span class="mention">@风趣的犀牛</span>：Alpha is zero sum. Alpha requires you to beat most people out there doing the same job.

<span class="mention">@谨慎的灰熊</span> 部分认同但觉得「说了等于没说，有点鸡汤了」——Alpha 很多时候也是运气，现在时代最强的 Alpha 是做模型研发的研究员和 infra 专家，「你如果几年前选的是游戏研发，你做的再好，你就赚不到这个时代 Alpha」。<span class="mention">@我要成为灵能高手</span> 的反驳很干脆：比较没有尽头，「为什么 2010 年不去挖矿？为什么 2008 年不去北京买房？」「反正不管做什么都会在八九十年后戛然而止——能做出博德之门三一样会让你爽好久，体验到了的东西才是真的。」<span class="mention">@谨慎的灰熊</span> 补充了投资侧的注解：「去年买了 SanDisk 就拥有最高的 Alpha 了。」<span class="mention">@风趣的犀牛</span> 回到底层逻辑：「Return on time 也是要讲究复利的。Some knowledge compounds, but not all.」

### AI 解读群聊讨论

<span class="mention">@活泼的羊驼</span> 把前两天群聊讨论喂给 GPT Pro 分析，得到了一份七条操作原则，核心判断是「不要在没有明确 edge 的地方追求 alpha。先把能低成本拿到的 beta 吃满」。他分享了自己使用 AI 分析群讨论的方法论：不仅关注群友说了什么，更关注「他们背后的 mindset 是什么样的」以及「我可以如何内化到我自己」——正是这个 prompt 角度让输出质量远超简单的内容摘要。

<span class="mention">@热情的狮子</span> 随后用同样的 prompt 分别跑了 Opus 4.8 和 GPT Pro。两者风格差异明显：Opus 主动寻找框架裂缝——指出「alpha is skill/effort/zero-sum 这个定义从金融搬出来就断裂了」、「beta = zero effort 是偷换」；GPT Pro 更附和原始框架但分析更长更结构化。<span class="mention">@热情的狮子</span> 的评价：「感觉 GPT 比较附和，Opus 会找新角度」，但同时吐槽 4.8 的中文「读起来好不通顺」。<span class="mention">@稳重的海豚</span> 试了 Claude Code 分析同样的讨论，结果一个 turn 就返回了一篇完整的长文——连「我沉浸了两天」都编进去了。他一句话总结核心收获：「把 labor 转成 asset，不要去卖时间赚钱。」

### 幂律重构 Alpha 框架

<span class="mention">@冷静的飞鼠</span> 从幂律分布的角度给出了完全不同于投资领域的定义。他分享了 Veritasium 的[幂律分布视频](https://m.youtube.com/watch?v=HBluLfX2F_k&pp=iggCQAE%3D)、自己的[三条反直觉复利公式视频](https://youtu.be/4V8aNnJZAJw)以及一期关于[《规模》读后感的播客](https://www.xiaoyuzhoufm.com/episode/696deb65ef1cf272a736299d?s=eyJ1IjogIjYxNzlmYzJlZTBmNWU3MjNiYjAxY2ZlNSJ9)。核心论点：在幂律系统中平均值由 outlier 决定、没有上限，这和正态分布的世界完全不同。

他进而指出 Alpha 和 Beta 是投资概念，不能直接套用到工作中。在工作中，跟别人做同一件事卷来卷去就是 beta；Alpha 是做出根本不同的东西。创造 Alpha 需要一种关键能力：

> <span class="mention">@冷静的飞鼠</span>：什么是知识之上的知识，方法之上的方法？答案就是结构。你能看到不同事物的结构，才有可能去超越这个结构。如果你看不到结构，就只能在结构里面内卷。

<span class="mention">@今天群内信息量极大</span> 被幂律视频打动，联想到投资数据——买大盘一年赚 7%，但「最主要的收益是前十个最赚钱的 trading days，把这十个刨掉基本上就不赚不赔了」。<span class="mention">@飘逸的狮子</span> 补充了传统技术分析中的分形流派——把 candle 当 fractal 分析，「横有多长竖有多高」的经验玄学。

### Tweak 型 Alpha 有半衰期

<span class="mention">@今天群内信息量极大</span> 将这几天的讨论写成博文[《什么时候该要 Alpha，什么时候该要 Beta》](https://yage.ai/share/alpha-beta-life-20250601.html?utm_source=wechat&utm_medium=share&utm_campaign=alpha-beta-life-20250601)。核心新贡献是把「追 Alpha」拆成两种类型：Tweak（在已有系统上微调——改 prompt、研究信用卡规则、比较工具配置）和 Build（从零搭建新结构——写工具、设计工作流、建创作系统）。两者的根本区别在于反馈结构——Tweak 反馈闭环长且噪音大，Build 反馈短而清晰、迭代可滚动。

Tweak 型 Alpha 有一个结构性问题：你优化的对象本身在进化，且进化速度可能比你快。精心调试的 Claude Code prompt 两个月后可能因模型升级直接失效。文章的底层判断：**Alpha 有半衰期，Beta 有复利**。判断一个领域值不值得投 Alpha 精力有三个维度：复利潜力（能否积累十年以上）、反馈质量（能否区分能力和运气）、比较优势（需要历史记录而非感受来验证）。三个都满足才是真正的 Alpha zone，数量应限制在一两个。

### 坚持是幂律的入场券

由幂律讨论自然延伸出一段关于「先干起来」的共鸣。<span class="mention">@温暖的斑马</span> 说「先干起来对很多人来说就是一个比较大的阻力」，完成只需再加 10-15%。<span class="mention">@80-HD</span> 分享了两步难关：「一开始动手是第一个难关，然后坚持是第二个难关。有了 AI 以后第一步的通过率高了不少，但是第二步还是很难。」

<span class="mention">@今天群内信息量极大</span> 贡献了一个有确切统计的案例：学飞行领域报名上课的人只有 20% 最终通过考试——「以前觉得蛮低的，但生活阅历多了之后，20% 其实是蛮高的比例了」。<span class="mention">@冷静的飞鼠</span> 补了一刀：「那是第一条建议，take 第一条建议的人才会给第二条建议。但到现在为止可能就 2% 的人会真的 take 第一条建议。」<span class="mention">@稳重的海豚</span> 以自己的社群为例——「纽约这边好几个小社群都在搞，才过了一年不到大部分都不干了。这就坚持往下干。」<span class="mention">@我要成为灵能高手</span> 则从另一个角度切入：生活压力越大对成功的渴望就越多，对取得成果就越急，越不容易坚持——「在相同的客观启动难度的前提下，越不需要做这件事就越容易开始」。

## 方法论

### AI Code Review 的贝叶斯困境

<span class="mention">@好奇的仓鼠</span> 发布了[《AI 让你工作更累了？可能是你用的方式不对》](https://mp.weixin.qq.com/s?__biz=MzI1MDQ3NTAxOQ==&mid=2247486490&idx=1&sn=32859eb2edc6fb02656f36cdb7e567ab&chksm=e8ce234af3138be94154564c275e244f9b0bcee2d4426cb9b014f7e08ba82a76e5e8aeb25300&mpshare=1&scene=1&srcid=0602xq8ruYHrGwNA2BZl30Bo&sharer_shareinfo=f3e9a7310abddccd6909c678eb021261&sharer_shareinfo_first=f3e9a7310abddccd6909c678eb021261#rd)，用贝叶斯定理解释了为什么 AI 时代代码审查反而更累。核心推导：AI 让「表述清晰」的概率 P(B) 大幅上升（AI 擅长把不正确的内容写得冠冕堂皇），而「设计靠谱」的概率 P(A) 没变，于是 P(A|B) 从约 90% 跌到约 70%——以前六成功力能过的 review 现在要八九成。再叠加 AI 让单人日产 CL 从 2 个涨到 20 个，审查员面临「单条更费劲 + 总量暴涨」的双重碾压。

解法分三层：让 AI agent 先做初审互掐过滤低级错误；技术负责人重心从写代码转向搭建 agent harness 和防御机制；确保测试覆盖率高到大部分 CL 不需要人亲眼盯着。这与昨天 [「Linter 对 AI 代码的三类作用」]({{ '/daily/2026/05/31/daily/#linter-对-ai-代码的三类作用' | relative_url }}) 中 <span class="mention">@我要成为灵能高手</span> 关于「约束结果而非约束代码」的思路形成互补。

### AI 驱动网站增长闭环

<span class="mention">@今天群内信息量极大</span> 分享了[《我的网站增长全是 AI 在管，我只做了四件事》](https://yage.ai/share/ai-managed-growth-20260601.html?utm_source=wechat&utm_medium=share&utm_campaign=ai-managed-growth-20260601)，复盘了 yage.ai 三个月的增长数据：周活从 2,500 到 7,000，Newsletter 从 300 到 1,200，Twitter 从 170 到 4,800——全程没手动发过一条推文、没手写过一期 Newsletter。他实际做的四件事：付了几笔钱（Typefully Creator、Twitter Premium、Kit 付费，合计每月不到 $50）、帮 AI 逆向了 X 的 per-post analytics 接口并把 session token 喂给它、每天花两分钟圈选题、每隔几周看一眼周报。

三条自动线：Newsletter 线从 arXiv/Twitter/HN/微信抓取再按「关注工程实践」视角写摘要、通过 Kit API 定时发送（5 月打开率 40-55%）；Twitter 线读完站内文章后生成 thread、通过 Typefully API 自动排期（5 月获 458,000 次曝光、互动率 5.05%）；增长分析线每周拉五个数据源生成 Markdown 周报——AI 自己提出了 R/T/N 框架，把帖子分为 Reach/Traffic/Newsletter 三类分别考核。SEO 方面 AI 主动 Allow 了 GPTBot、ClaudeBot、PerplexityBot，并给每个小节加了独立结论段方便 AI 搜索引擎引用。

被证伪的部分同样有价值：英文版直接流量 ROI 很低（中文 PV 是英文 15-115 倍），英文版定位应从「给英文读者的翻译」改成「让 AI 搜索引擎索引的语料」。

<span class="mention">@飘逸的狮子</span> 看完后让 AI 对比自己的 x-auto 系统和 <span class="mention">@今天群内信息量极大</span> 的做法，结果被 AI 一顿喷：两者核心差异在于 <span class="mention">@今天群内信息量极大</span> 优化的是「脉冲退潮之后的基线」（留存指标），而 <span class="mention">@飘逸的狮子</span> 优化的是「单帖在单渠道上的峰值指标」——AI 建议把推文任务从「拿曝光」换成「把人引进一个能留住他的层」。
