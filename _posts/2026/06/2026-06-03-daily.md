## 方法论

### MAI-Thinking-1 技术报告：攀岩式训练方法论

<span class="mention">@今天群内信息量极大</span> 读完昨天 [「MAI-Thinking-1 正式发布」]({{ '/daily/2026/06/02/daily/#mai-thinking-1-正式发布' | relative_url }}) 的 109 页技术报告，用 DeepSeek V4 Pro 写了一篇[学习笔记](https://yage.ai/share/mai-thinking-1-hill-climbing-20260603.html?utm_source=wechat&utm_medium=share&utm_campaign=mai-thinking-1-hill-climbing-20260603)。他认为报告真正的价值不在模型本身，而在于首次完整公开了顶尖实验室的研发方法论。

核心发现：行业默认的假设——小规模实验排名在放大后保持不变——不成立。MAI 做数据配比实验时，stem-heavy 方案在 5B 模型上明显优于 code-heavy，但放大到 23B 训练 20 万亿 token 后性能曲线中途交叉。原因是高质量 STEM 数据多样性不足，小模型受益于"浓缩"，大模型几轮就榨干了。解法是一个叫 Efficiency Gain（EG）的指标：给 baseline 拟合 scaling law 曲线，反查 baseline 要花多少成本达到候选方案同样的性能，两者之比就是 EG。关键不是某一级 EG 大于 1，而是 EG 曲线在更大规模上是否持续上升。报告还记录了架构从 v2 到 v5 的演化节奏——每次重大改动让训练效率 MFU 从 22% 暴跌到 16%，再靠几十项工程优化慢慢爬回。<span class="mention">@今天群内信息量极大</span> 总结底层结论：竞争核心已不在于谁有更好的架构 idea，而在于谁有更好的闭环验证系统。

<span class="mention">@灵动的考拉</span> 联想到人类工程师也只读了 CS 书籍的很小子集，推测 LLM 也许不需要那么多低质量数据。<span class="mention">@我要成为灵能高手</span> 反驳：「但是一个人不会什么都做，模型则不行。」

### Tavily x402 链上 Agent 支付

<span class="mention">@今天群内信息量极大</span> 发布了[深度分析](https://yage.ai/share/tavily-x402-agent-payments-20260603.html?utm_source=wechat&utm_medium=share&utm_campaign=tavily-x402-agent-payments-20260603)：Tavily 把搜索 API 接上 Coinbase 牵头的 x402 协议，agent 无需 API key 和注册账号，直接用链上 USDC 按次付费——一次 advanced 搜索收 $0.01，跑在 Base 主网。文章梳理了三个竞争栈：x402（加密原生）、Stripe/Tempo 主导的 MPP（支持多支付方式、走 IETF 标准化）、Google 的 AP2（解决授权层、已捐给 FIDO Alliance），三层分工是 AP2 管授权、x402/MPP 管结算。安全风险方面 prompt injection 诱导 agent 向攻击者钱包付款最为现实，应对建议是单独开小钱包、设 --max-amount 硬上限、收款地址白名单。

实用判断：短期六个月内 API key 更便宜可控，大概率不必接；中期多 agent 协作需要临时调陌生工具时会变为必要；长期支付协议本身不是关键，授权层和风控层才决定能否生产化。
