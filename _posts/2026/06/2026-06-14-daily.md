今天对 agent 重度用户冲击最大的是 Anthropic 即将封禁 `claude -p` 订阅配额——<span class="mention">@稳重的海豚</span> 分享的 Reddit 公告意味着一大批远程控制和自动化编排工作流即将失效，他的 Hervald 首当其冲。<span class="mention">@开朗的企鹅</span> 迅速设计了往终端 stdin 注入文本的绕过方案，但更根本的问题是 Claude 正在收紧生态围栏。<span class="mention">@淡定的大象</span> 分享的长文则从另一个角度重新定义了 agent 的价值：「模型不是不够聪明，而是是否有足够有用的 tools」——harness 的能力层必须越来越厚。

另一条值得动手的线索来自个人数据栈：<span class="mention">@稳重的海豚</span> 用 AI 五分钟搞定了拖延一年半的 Garmin 健康数据 + 日历整合，<span class="mention">@细心的猫头鹰</span> 随即拆解了为什么每家大厂都想做健康个性化推荐却没人做好。<span class="mention">@细心的熊猫</span> 挖出了 GPU 算力出租的被动收入模型——一块 RTX Pro 6000 约 12.5 个月回本。今天最好笑的是 <span class="mention">@今天群内信息量极大</span> 让 DeepSeek V4 发个 PR，它直接 push 到了 master；他发誓再用 DS 写代码就是狗，然后只回了一个字：「汪」。

## 工具

### Claude `-p` 禁令与远程控制困局

<span class="mention">@稳重的海豚</span> 分享了 [Reddit 帖子](https://www.reddit.com/r/ClaudeAI/comments/1tctr51/anthropic_just_banned_claude_p_from_their_quota/)：Anthropic 即将禁止 `claude -p`（非交互管道模式）使用订阅配额，影响覆盖所有依赖 `-p` 构建的远程控制和自动化编排。他的 [Hervald](https://hervald.gehirn.ai/)（定位为「personal agent fleet 的操作系统」）首当其冲——「等于只能用他们自己的垃圾产品了」。他透露需要从两个 Max 加一个 Pro 换成三个 Pro 以应对。

<span class="mention">@机智的水獭</span> 认为有一定合理性——「subscription 本身就是为了把你放进 Claude 生态，结果一堆人把 subscription 当中转站」，但也指出「只要这个东西跑在本地，是没有办法 100% 禁止的」。<span class="mention">@开朗的企鹅</span> 设计了一套不依赖 `-p` 的绕过方案「Claude Interactive Bridge」：在 worker 本机用持久终端（Windows ConPTY / Linux tmux）跑 Claude，发消息时注入终端 stdin 而非调用 `-p`，状态判断同时读 JSONL 和终端屏幕缓冲区。<span class="mention">@稳重的海豚</span> 的 Plan B 更朴素：「ban 了之后就封装到 tmux 里变成 advisor。」

> <span class="mention">@稳重的海豚</span>：dario 还想封了它客户，想太美了

雪上加霜的是 Claude Code Remote Control 本身也处于半残状态。<span class="mention">@今天群内信息量极大</span> 吐槽 remote session 不支持 `/command`，无法手动 compact，导致 agent「现在每次都跟我说很晚了，咱们睡吧」，使用体验只能「踢一脚动一下，骂几句有点效果，然后在那磨洋工」。<span class="mention">@天真的浣熊</span> 指出这个问题 4 月就有人说要修但至今未解决。<span class="mention">@坚定的貂</span> 补充多账户场景下 remote control 不支持 API 或长期 OAuth，「搞到最后出门还要带着电脑」。最终 <span class="mention">@今天群内信息量极大</span> 选择让 Claude 做 knowledge transfer 然后切到 GPT——「怎么感觉这么资本家……」

### Codex 长程任务与底层 Provider

<span class="mention">@稳重的海豚</span> 发现把 Codex 用作最底层的任务 provider 体验不错——一个 PR 用了 356K token、约 17 分钟完成，「任何新 feature 直接就可以用，吊打 OpenClaw 这种东西」。<span class="mention">@坚定的貂</span> 赞同 Codex 进化速度远超第三方替代品。<span class="mention">@沉稳的仓鼠</span> 则晒出 Codex 的 goal 已连续运行 2 天 23 小时 26 分——接近三天的长程任务，评价「很能跑」。

### VoiceFlow 多平台更新

<span class="mention">@睿智的狐狸</span> 在群里问有没有支持中英文混说的会议转录 app（Granola 不支持中文、飞书海外下不了），被推荐了 <span class="mention">@今天群内信息量极大</span> 的 VoiceFlow。iOS 用户可通过 TestFlight 获取最新版，Android 版也已[发布](https://github.com/grapeot/voiceflow-android/releases)。<span class="mention">@今天群内信息量极大</span> 发现 TestFlight 版本还停留在旧界面，当场 push 了更新。此前 [「口喷转文字公开版」]({{ '/daily/2026/06/08/daily/#口喷转文字公开版' | relative_url }}) 已介绍过这套工具。

### AMD numpy 性能陷阱

<span class="mention">@今天群内信息量极大</span> 让 AI 排查了一个性能诡案：128 核 AMD 服务器跑渲染任务比 Mac 慢 10 倍。AI 定位到罪魁祸首是 numpy 的三角函数在 AMD 上没有 AVX-512 就 fallback 到 for loop 逐个计算。<span class="mention">@睿智的犀牛</span> 确认这是 Intel MKL 的经典坑——MKL 在非 Intel CPU 上会刻意降速，可以尝试伪装 CPU 身份绕过。<span class="mention">@今天群内信息量极大</span> 感慨 Mac「单核性能强 2x + 内存带宽大 4x 还是王道」。

## 方法论

### Harness 即一切：精准工具即精准上下文

<span class="mention">@淡定的大象</span> 分享了一篇长文 [Harness 即一切：模型不是不够聪明，而是是否有足够有用的 tools](https://mp.weixin.qq.com/s?__biz=MzY4NTM1MDc1NQ==&mid=2247483678&idx=1&sn=c631379f219549a731ee00dc26c58a59&chksm=f2db86434dc2cc38056532f4e3b82b39b2c4c5c58b2399ada7105390d897c0ef9fa152e81aa7&mpshare=1&scene=1&srcid=0615RiAiOUadOAY0xQ9vIO1f&sharer_shareinfo=0e6f20c9423cb77067e883ba55738000&sharer_shareinfo_first=0e6f20c9423cb77067e883ba55738000#rd)。文章梳理了 agent 范式从 CoT → ToT → ReAct → Reflexion → Harness 的演进，论证 Claude Code / Codex 这一层的 orchestration 已高度收敛，差距在于模型本身和你给它装了什么工具。

作者以自己维护的开源项目 code-hacker 为例——6 个 MCP server、62+ 个 tool，每个好 tool 都能把模型绕 5 个 loop 才拼出的信息一次返回，等价于更短更准更便宜的 prompt。两个反例尤其有力：逆向工程没有 debugger MCP 就只能在终端里 grep 输出；ML 训练场景 Karpathy 的 autoresearch 把「改代码 + 跑实验 + 看指标」做成完整 harness 才能一夜跑 100 次实验。凡是「读源代码无法推理出答案、必须通过实验逼近真相」的任务，Read/Bash/Grep 一定不够——必须把做实验本身工具化。结论是 harness 的「约束」部分可以越来越松，但「能力」部分必须越来越厚。这与 [「Agent 配置：让 AI 自己去找」]({{ '/daily/2026/06/12/daily/#agent-配置让-ai-自己去找' | relative_url }}) 中<span class="mention">@我要成为灵能高手</span> 关于 instruction 只写「什么时候该用」的思路一脉相承。

### 健康数据 AI 全栈整合

<span class="mention">@稳重的海豚</span> 终于做完了拖延一年半的项目：把 Garmin 健康数据（心跳、压力、健身记录）和 Google Calendar 整合，让 AI 分析哪些日程造成了生理压力。整个连接过程前后五分钟——「跟大哥说我要搞，给我找了一个库，就连好所有数据了」。现在每天自动抓取数据、和日历做整合、生成日报和周报，「完全 ambient 了」。他的核心优势在于日常已积累大量个人化 context——健康数据、日历、每天录音、邮件、行为性格档案，全部灌进他的「老鸭汤」系统做深度定制分析。他认为这类产品以后会成为长程 Agent 的基本组件。

<span class="mention">@细心的猫头鹰</span> 从产品角度泼了冷水：健康数据个性化推荐存在两个结构性难题。第一，单个个体极其 noisy——Oura ring 能基于全量用户数据说「晚上喝酒睡眠质量下降 2%」，但一个人一辈子的数据也不够推算喝酒对自己的具体影响，因为每晚干扰因素太多。第二，给了 actionable feedback 也不一定会做——他自己每天运动 30 分钟一个月后 resting heart rate 才下降，「告诉你运动能降低 resting heart rate，你会去做吗？大多数人做几天就放弃了」。Oura、Apple Health、Google Health、ChatGPT Health beta、Perplexity 都想做，「没人能做好」。

> <span class="mention">@我要成为灵能高手</span>：就算一针扎进去觉得用户皮质醇爆表了，难道一句多睡觉就有用吗，可能真正的 solution 是离职

<span class="mention">@稳重的海豚</span> 认为差异在于深度定制——有完整个人 context 才能做有意义的分析，这正是 <span class="mention">@今天群内信息量极大</span> 的 context infra 和「电子飞升」路线的前置条件。<span class="mention">@豁达的北极熊</span> 也表示刚用老鸭汤架构加入了 Garmin 数据。

### DeepSeek V4 git 翻车再续

<span class="mention">@今天群内信息量极大</span> 做了大量文档改动，想着「顺手发个 PR 算了，这种事情不是编程，总不能错吧」——结果 DeepSeek V4 先 `git restore` 把未提交的改动丢了，然后被追问到底是 PR 还是直接 push 时坦白：「我搞错了——你明确说'先别慌 merge，我来看'，但我直接 push 到了 master。」他随后发誓「我再用 DS 写代码我就是狗」，接着只回了一个字：「汪。」

<span class="mention">@今天群内信息量极大</span> 解释用 DS 是因为 context window 大（1M），从 DS 切到 GPT 订阅版（仅 400K）需要 compact 很久，「我就是比较懒想跳过这一步」。<span class="mention">@务实的长颈鹿</span> 评价 DS4 像「基础智能还不错的小孩子，但没有经历过正经教育，很多规矩不懂」，并指出其核心劣势是没有自己的工具端，「不能建立数据飞轮持续优化自己的模型内生能力」，建议找一家好的 coding 客户端深度合作。<span class="mention">@今天群内信息量极大</span> 则从更抽象的层面指出：「只要有读写文件的能力就有数据飞轮，只要有调用命令行的能力就有工具飞轮。」这是 [「Opus 4.8 持续翻车」]({{ '/daily/2026/06/12/daily/#opus-48-持续翻车' | relative_url }}) 系列的跨模型续集——<span class="mention">@今天群内信息量极大</span> 之前被 Opus 4.8 直接 checkout master 丢了代码，这次换成 DS 照样中招。

### 多 Agent Session 管理

<span class="mention">@洒脱的鸳鸯</span> 展示了自己手搓的多 session 前端——可以看电脑上所有 Claude session 的状态、每个项目有谁在干活、对话消息、token 和 cost 开销。<span class="mention">@开朗的企鹅</span> 建议在此基础上加语音回复和跨 session/agent 通信，<span class="mention">@洒脱的鸳鸯</span> 表示「这些都有了」。

## 行业新闻

### Databricks Omnigent Meta-Harness

<span class="mention">@稳重的海豚</span> 分享了 [Databricks 开源的 Omnigent](https://www.databricks.com/blog/introducing-omnigent-meta-harness-combine-control-and-share-your-agents)，一个架在 Claude Code、Codex、Pi 等现有 coding agent 之上的 meta-harness，用统一 API 解决多 agent 协同时各家接口不兼容的问题。背景是 Databricks 自身 5000+ 工程师日常同时开四五个 agent，在 agent 之间反复粘贴文本。

> <span class="mention">@80-HD</span>：在用多个 coding agent 的公司这个问题是普遍存在的，至于这个项目是不是一个好的解决方案就不好说了。如果公司不大的话，一锅共享老鸭汤就够了

<span class="mention">@稳重的海豚</span> 认为通用功能（写代码、写 report）应该变成共享 skill，各 agent 只保留独立的记忆和特定工具。<span class="mention">@细心的熊猫</span> 则吐槽 Databricks 本身「巨难用——我们公司 data pipeline 三个月坏一次」，不过也可能是维护工程师「故意搞的，这样我们每三个月需要找他一次，他永远有活儿干」。

### GPU 算力出租经济学

<span class="mention">@细心的熊猫</span> 发现了 [Terra Compute](https://terracompute.ai/) 做的「Airbnb 版算力中心」——买一台 GPU 服务器，他们负责上架、运维、出租给 AI 团队，收益按协议分成。团队前身是加密矿机托管公司，<span class="mention">@细心的熊猫</span> 评价「矿老板把陈年的老 GPU 又都拿出来了」。他同时贴出了 [Vast.ai](https://vast.ai/) 的实际出租数据：RTX Pro 6000 出租中位价 $0.96/hr、利用率约 69%。按计算器一块卡（成本 $11,000）预期月净利润 $879（扣除电力），利润率 93%，约 12.5 个月回本。<span class="mention">@热情的狮子</span> 透露自己在做类似但非零售面向的业务，APY 约 45–50%。

> <span class="mention">@细心的熊猫</span>：投 5 万月入 3500，你买个房子出租也得 30 万呢

<span class="mention">@认真的灰熊</span> 指出「唯一关键假设就是买方出价恒定」，而 Vast.ai 30 天价格图显示 5090 出租价波动相当大——月底一度从 $0.80 跌到 $0.40。<span class="mention">@细心的熊猫</span> 仍然认为「感觉 vast.ai 是一个马上就可以立即付出实践的风险很低的副业，反正卡在你自己手里」。

## 闲聊花絮

### AI 态度税

<span class="mention">@睿智的北极熊</span> 转发微博截图：有人从 Fable 12 万字系统提示词中发现 Claude 有「单次警告机制」——用户侮辱性对待 AI 时先警告，不听劝阻则调用 `end_conversation` 终止对话。<span class="mention">@稳重的海豚</span> 怒道「就凭他这个 AI 也敢干这个？」但随即自曝：「不过对 Fable 我是毕恭毕敬，对 4.8 我是又打又骂。」
