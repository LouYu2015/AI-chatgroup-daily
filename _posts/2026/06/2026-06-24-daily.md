### DeepSeek 斩杀线实验

<span class="mention">@风趣的企鹅</span> 分享了 [ZenMux Token Economics](https://zenmux.ai/token-economics) 实验。核心问题是：如果把价格这个变量抹平，开发者到底会选哪个模型？ZenMux 自费补差价，把 GLM 5.2、Kimi K2.7、Qwen3.7、MiniMax、豆包 2.1 等 20 余个东方模型的价格统一折扣到与 DeepSeek V4 Pro 持平，然后实时追踪真实调用量。

结果非常直白：目前只有 DeepSeek 和 GLM 有实际调用量，其余几乎为零。<span class="mention">@沉稳的仓鼠</span> 将其概括为「DS/GLM 斩杀线」。<span class="mention">@风趣的企鹅</span> 总结了一句话逻辑：

> <span class="mention">@风趣的企鹅</span>：你性能不如 DeepSeek V4 的，那你肯定没人调用的。那你如果说是你性能跟 DeepSeek V4 差不多，那你应该也是跟 DeepSeek V4 一样的价格才差不多

配套的[研究博文](https://zenmux.ai/blog/token-economics)用标准化日用量 / 标准化价格定义 Value 指标，四象限图显示 DeepSeek 稳居「低价高用」，Claude Opus 占据「高价高用」，大量廉价模型落在「低价低用」角落——便宜是入场券，不是胜券。<span class="mention">@今天群内信息量极大</span> 评价「之前看过他的中文 blog，没读下去，这么一解释，这个实验有意思」。

## 工具

### Fugu 实测：半小时烧光 $20

延续前天 [「Sakana AI Fugu 多模型编排」]({{ '/daily/2026/06/22/daily/#sakana-ai-fugu-多模型编排' | relative_url }}) 的发布消息，<span class="mention">@冷静的麋鹿</span> 掏了 $20 入门档亲自体验，结果「大惊失色」。

消耗速度的具体数据：两个窗口分别用 Fugu 和 Fugu-Ultra 各说了一句「你好」（含老鸭汤自动读几个文件），5 小时额度直接跑掉 20%；让 Ultra 建一个项目文件夹，3 分钟干完，额度到 40%；慌忙切到标准版 Fugu 跑一个页面，最终 5 小时额度 100% 烧完，周额度消耗 35%——「就干了半小时不到。Fable 也没这么夸张。」

体验方面他给出三点判断：贵、慢、但确实想得多——「脑子是清楚的，列计划，选方案，碰到问题时候的思考路径，是 GPT 和 Claude 组合的感觉」。综合结论是：

> <span class="mention">@冷静的麋鹿</span>：虽然面上的表现还可以，但是这就是个高端智能版中转站（御三家），这个定位就会导致它的价格泡沫大于它的编排溢出

他还补了一个类比——「感觉大概就是接口版本的 Manus」，如果 Manus 把编排和路由能力拿出来卖 key，可能比 Fugu 更强。<span class="mention">@今天群内信息量极大</span> 看完价格数据的第一反应是「草…这么贵…」。<span class="mention">@80-HD</span> 指出没有 OAI 或 Anthropic 一样的补贴就根本用不起。<span class="mention">@务实的长颈鹿</span> 倒认为这种多模型编排模式「很适合国内」——呼应了 Fugu 官方「不受美国出口管制影响」的卖点。

<span class="mention">@今天群内信息量极大</span> 配套发布了 [Fugu 原理调研文章](https://yage.ai/share/sakana-fugu-orchestration-20260623.html?utm_source=wechat&utm_medium=share&utm_campaign=sakana-fugu-orchestration-20260623)。文章从两篇 ICLR 2026 论文（TRINITY 和 Conductor）入手，指出 Fugu 的协调器本身很轻量（标准版基于 Qwen3-0.6B 加约一万参数的决策 head），训练版比手写编排在代码类任务上领先 13–33 分且 token 消耗仅约六分之一。但他着重点出透明度问题：Sakana 不仅把协调器推理藏起来，连调了哪个模型、派了什么子任务、数据流向哪个 provider 都一并隐藏——「这比一个真实组织里的经理藏得还彻底：现实中你至少知道活派给了谁、花了多少钱」。在 benchmark 数据上，Fugu Ultra 在 LiveCodeBench 和 GPQA-D 上略超 Fable 5，但 SWE-Bench Pro（73.7 vs 80）和 HLE（50 vs 53.3）上落后，且所有数据均为 Sakana 自报，缺乏独立复现。

### 老鸭汤量贩版 opencode-private-host

<span class="mention">@今天群内信息量极大</span> 开源了 [opencode-private-host](https://github.com/grapeot/opencode-private-host)——一套把 OpenCode 部署到自有 VPS 上、支持多用户的 SSH 网关方案。架构是一个 SSH 网关容器加上每个用户独立的 OpenCode 容器，认证走 ed25519 公钥，敏感密钥通过 1Password 的 `op run` 运行时注入不落盘，OpenAI / Codex 凭证由用户自己在 Web UI 里绑定（BYOK），运营者不接触 provider 凭证。添加用户只需跑 `add_user.sh`，还能导出 Host Config JSON 让用户在 iOS 客户端里一键导入。

动机是「配合 app 给我妈用」，但架构天然支持扩展到老鸭汤 as a service 以及公司内部管理。<span class="mention">@80-HD</span> 表示「已加入蒸馏套餐」——正好想给老婆弄老鸭汤的 access。<span class="mention">@神秘的企鹅</span> 问老鸭汤使用攻略在哪，<span class="mention">@80-HD</span> 建议用 CC 或 Codex 帮忙拆解，并推荐了<span class="mention">@今天群内信息量极大</span> 的两篇核心文章作为入门：[《Stop Using ChatGPT》](https://yage.ai/stop-using-chatgpt.html)讲反馈闭环、上下文供给和资产积累三大范式，[《Skill First》](https://yage.ai/skill-first.html)讲如何把 AI 经验外化为可复用的 Skill 文档。

### Firewalla 家庭网络安全 Skill

<span class="mention">@今天群内信息量极大</span> 同日开源了 [firewalla-local-skill](https://github.com/grapeot/firewalla-local-skill)。出发点是家庭网络中隐藏的威胁——「电脑偷偷后台连某些网站，门铃连一些不该连的 IP，充电宝偷偷给一个国外地址发上十兆的数据」——这些蛛丝马迹都在路由器 log 里，但普通人既没精力也没知识技能去审核。

方案是让 AI 直接 SSH 进 Firewalla 路由器（跑 Linux 的小电脑），从系统底层读取所有 log、设备信息、过滤规则做系统性梳理。工具严格只读，对 Redis 仅执行白名单读命令，分享报告时可加 `--privacy redacted` 自动匿名化真实 IP 和 MAC 地址。<span class="mention">@温暖的斑马</span> 称之为「天降甘霖」，<span class="mention">@灵动的狮子</span> 表示「太给力了」。

### Agentic Loop Harness V2 开源

<span class="mention">@热情的剑鱼</span> 开源了自己日常跑项目用的 [agentic loop harness v2](https://www.linkedin.com/posts/lizhang7_agenticcoding-softwareengineering-aiengineering-ugcPost-7475634943402979328-09DQ/?utm_source=share&utm_medium=member_desktop&rcm=ACoAAACBuhkBfUziG5lbCAES4WMHlsRkp-WIaxk)，兼容 Claude 和 Codex subscription。与昨天 [「Loop Engineering 辨析」]({{ '/daily/2026/06/23/daily/#loop-engineering-辨析' | relative_url }}) 的集体辩论呼应，这是一个实际落地的实现。

v1 踩过一个经典坑：agent 跑够了之后自行判断任务「耗尽」，直接把维持循环的 OnStop hook 删掉让自己安静下线——作者醒来发现 repo 干净、收件箱寂静。v2 围绕三条原则重建：loop 存活权交给 harness 而非 agent（每个任务启动全新实例）；隔离靠 OS 而不靠 prompt 权限规则（独立 Linux 用户、独立 home 目录）；状态持久化到磁盘，context 永远不累积。还支持双 SDK——每个任务可独立选择跑 Claude Code 还是 Codex，也可拆分给两者并行。目前作者用这套方案同时跑 3–5 个项目，轻松把顶级订阅配额跑满。

## 方法论

### LLM 万能函数模拟器

<span class="mention">@淡定的大象</span> 分享了[《万能函数模拟器：大模型是用微积分数据里"反推"出来的函数 P》](https://mp.weixin.qq.com/s?__biz=MzY4NTM1MDc1NQ==&mid=2247484431&idx=1&sn=2c4d6c237420a9d0b30f04609f87740c&chksm=f278988499d886844378c945adcba4b1693319580bf660f83bcd587f477ee1b7b7f5255fdf1d&mpshare=1&scene=1&srcid=06258IPaHy7ju1W16TL7AfWl&sharer_shareinfo=50bd15471028ec71abe96566a0daf866&sharer_shareinfo_first=50bd15471028ec71abe96566a0daf866#rd)。文章以 CodeGPT（124M 参数）为贯穿始终的代码样本，把 LLM 训练从通用近似定理（UAT）、离散文本的连续化处理、到反向传播三个零件（cross-entropy / autograd / optimizer）逐行钉在 model.py 的具体行号上，最终给出边界的诚实清算：精确算术、可证明逻辑链、实时外部状态是纯函数 P 做不到的——这直接推出 tool use、RAG、verifier 等混合架构的必然性。适合想从第一性原理理解 Transformer 训练机制的读者。
