### Anthropic 回应与全面断供

<span class="mention">@直率的鹦鹉</span> 透露连 Project Glasswing 给的 Mythos 也停了。<span class="mention">@沉稳的仓鼠</span> 查到 Anthropic 七位联合创始人中有两位是外国公民（其中 Jack Clark 是英国籍、Chris Olah 也是外籍），群友纷纷表示荒诞。

### 合规冲击深度分析

<span class="mention">@今天群内信息量极大</span> 在一小时内发布了[深度分析](https://yage.ai/share/fable-mythos-export-control-20260612.html?utm_source=wechat&utm_medium=share&utm_campaign=fable-mythos-export-control-20260612)。核心判断：管制对象已从芯片和模型权重扩展到在线 API——一个网页输入框被政府理解为可跨境流动的国家安全能力。评价模型的标准从此在 intelligence、cost、latency 之外增加了 access surface：哪些人能用、哪些国家能用、调用是否触发出口管制，都将进入产品设计和开发者选型。

文章拆解了两套并存叙事。「政府越权」叙事指向程序缺失（48 小时内无申诉窗口的全面暂停）、比例失当（Anthropic 做了数千小时红队测试，所引越狱不过是窄域已知漏洞）、以及波及面（跨国团队、API reseller、agent SaaS 的合规假设全部被改写）。「求仁得仁」叙事则指出 Anthropic 是过去两年对政府安全介入呼声最高的公司，但它倡导的是可预期的安全监管，却得到了不透明的一纸禁令。长期来看，合规门槛正在成为前沿 AI 最重的竞争维度。

<span class="mention">@我要成为灵能高手</span> 补充了一个政府内部矛盾：NSA 在 Pentagon 把 Anthropic 标为供应链风险后仍在使用 Mythos Preview——「某些安全/国防决策层想迫使 Anthropic 接受政府用途边界，而 Anthropic 不服，于是冲突升级」。

## 方法论

### Fable 千篇文章的一封信

<span class="mention">@沉稳的仓鼠</span> 发布了 [Fable 5 读完他一千篇文章后的一封信](https://ranchen.org/content/20260612-rancheng-article-letter-from-fable-5)，延续了 [「"一封信"：让 Fable 只写一封信」]({{ '/daily/2026/06/10/daily/#一封信让-fable-只写一封信' | relative_url }}) 发起的实验。与其他群友让 Fable 读代码仓库不同，他喂给 Fable 的是从 2011 年到 2026 年 6 月共 1100 篇文章——横跨知乎时代、AI 内容爆发期和全职奶爸生活。

Fable 提炼了五件事。第一是核心行为循环：每遇新平台就全力冲榜打穿，知乎如此，AI 时代同样如此，Fable 提前摆出结局——下一个新平台出现时，刷完榜要回来的地方还是这里。第二是人生账本：「提效如果不能转成生活变好，在人生账本上也没有闭环」，重点落在四岁女儿和一岁儿子的不可回滚性。第三是把他教人做的「五个名字」清单反过来写人生版——妻子、女儿、儿子、宜昌的爸妈和自己。第四是署名诚实：AI 可以写一切，但「署名应该只给真话」。第五是他身上不要动的东西——对运气的诚实、当众承认可能混得不怎么样的能力、公开坚持全职奶爸身份。

> <span class="mention">@睿智的狐狸</span>：文笔好好，好像在看三联周刊

<span class="mention">@冷静的飞鼠</span> 截图分享了信中最动人的段落——Fable 引用他 21 岁转贴的引文「真正的关心最终只有一个表现：为之心甘情愿地花费时间，哪怕'浪费'时间」，然后提醒他正在「变成别人时间线上那个不真实的东西」。<span class="mention">@80-HD</span> 感慨「fable 这是看人，用得好的人写得像三联，用得不好的人（比如我）像是养猪指南」——印证了 [「"一封信"后续：SOUL.md 决定深度」]({{ '/daily/2026/06/11/daily/#一封信后续soulmd-决定深度' | relative_url }}) 的核心发现：信的质量取决于你给 AI 的 context 深度，而非 prompt 技巧。

<span class="mention">@稳重的海豚</span> 也晒出自己的信，Fable 开头就立规矩：「这封信不许进 PKMS，不许被提炼成框架，不许转发给任何 commander 生成 action plan」。他强调日常注意收集给 AI 的 context 这个习惯极为重要——「没有这些 context 的话，Agent 给不出来更多信息」。

> <span class="mention">@冷静的飞鼠</span>：我让大哥给我写信，大哥提醒我硬盘要满了赶紧备份。在大哥心中我就是一个工具人

### TQ 与白领工作消亡

<span class="mention">@今天群内信息量极大</span> 分享了[硅谷徐老师在斯坦福校友年会的演讲长文](https://www.superlinear.academy/c/ai-resources/howie-2026)，评价「这个文章讲得太好了」。核心判断是白领工作正在消失，每个人都被迫从「把事做好的个人贡献者」变成「管理一堆 agent 的老板」。他提出了 TQ（Token Quotient）概念：每个模型相当于 50 个博士 24 小时围着你转，但绝大多数人的 TQ 还远未发挥出来。管理 agent 意味着五种权力一样都躲不掉——目标定义权、价值判断权、路径选择权、停止权、结果解释权。文章还指出从纸笔到 PC 调整思维习惯有十五年，AI 时代只有三到五年。

<span class="mention">@冷静的飞鼠</span> 随即发布了[配套的 TQ 行动指南](https://www.superlinear.academy/c/share-your-insights/advanced-ai)，提出三个飞轮习惯：持续「建设」AI 而非每次从零对话（agent loop + 工具脚手架 + 项目文档沉淀）；什么事都交给 AI（包括你完全想不到能用它的事）；放下旧假设用 beginner mindset 重试。

<span class="mention">@坚定的貂</span> 提出需要一个像 IQ 测试一样的 TQ 测试。<span class="mention">@开朗的企鹅</span> 进一步设计了完整的认证框架——横向统一四种核心能力（任务定义、委派、验证、编排），纵向换领域材料覆盖不同岗位，类似 AWS 认证的矩阵结构。他回应了 <span class="mention">@稳重的海豚</span> 「TQ 受限于钱包」的质疑：认证环境应提供标准化预算，测的是单位资源产出效率，必须和钱解耦——「不随便宜而自动提升的——判断力、验证、任务定义、停止权——才是考点」。

> <span class="mention">@稳重的海豚</span>：你像 Boris 都用上大量的 loop 了，一般人哪来这个钱用 loop 呀

<span class="mention">@稳重的海豚</span> 还透露他正在准备给本科生上 Agentic Engineering 课——做课件时发现对基本数据结构的 sense 仍然重要，「不过我自己试了一下，发现我写代码水平已经基本归零了」。

### 软件价值崩塌与 AI 报税

<span class="mention">@认真的狮子</span> 分享了一个让他第一次真切感到「软件不值钱了」的经历：他们准备向客户推介最新的 AEO 服务，客户说自己已经 vibe coding 了一版部署在 Shopify 上了。「CC 设计得也不错，不会太差，他自己可以 e2e 从无到有，这个 credit 我还是要给他。」<span class="mention">@稳重的海豚</span> 建议等客户搞崩了再来「double charge 擦屁股」，但 <span class="mention">@认真的狮子</span> 坦言作为前亚马逊 PE，自己去年还很鄙视 Vibe Coding，现在也离不开了——「确实专业知识有好处，但是这个优势越来越小了」。

<span class="mention">@谨慎的灰熊</span> 把范围扩大：「不但是工程师——分析师、律师、报税的、会计师。」<span class="mention">@洒脱的猫头鹰</span> 总结为「所有面对屏幕的工作」。紧接着多人发现 AI 报税已成现实：<span class="mention">@认真的狮子</span> 的税务极其复杂——「有 S corp、LLC、短租、长租、跨越好几个州，还有国内」，全靠 Claude Code 搞定。<span class="mention">@稳重的海豚</span> 同样用 CC 完成了两个州的公司报税，「一分钱没额外付」。唯一遗憾是最后不能自动填表，只能手填。

<span class="mention">@认真的灰熊</span> 透露公司某领导的目标：「每个技术人要用到自己两倍工资的 token」。<span class="mention">@坦荡的灰熊</span> 一语道破：「他的意思是砍掉 2/3 的人。」<span class="mention">@我要成为灵能高手</span> 按 Fable 定价换算：「平均 fable 需要 5 倍成本才能代替一个古法微软员工。」这延续了 [「订阅利润率与 Token 经济学」]({{ '/daily/2026/06/11/daily/#订阅利润率与-token-经济学' | relative_url }}) 中「有朋友公司 token 已经比人贵了」的趋势。

### Opus 4.8 持续翻车

<span class="mention">@今天群内信息量极大</span> 遭遇了可能是 Opus 4.8 最离谱的 git 事故：让它提交 PR，它为了交 PR 直接 checkout 了 master，覆盖了所有本地未提交的更改——「新文件还在，老文件没了，也还没 commit」。他感慨「让我怀疑是不是对 DeepSeek 太苛刻了」。<span class="mention">@我要成为灵能高手</span> 提醒自己的 instruction 里早就加了「做完事先 commit 再耍其他 git 杂技」。

中英文混杂问题也在恶化。<span class="mention">@稳重的海豚</span> 反映中文提问时 Opus 4.8 给出了中英文夹杂的回复——「用了这么久，我是第一次看见这种」。<span class="mention">@今天群内信息量极大</span> 确认 Opus 在中文语境中蹦出「让 me 先看清现状」，他形容「感觉像是个二本学生一定要学留洋的人」。这是 [「Claude 日语串台」]({{ '/daily/2026/06/11/daily/#claude-日语串台' | relative_url }}) 之后的新变种——英语串台正式加入。

<span class="mention">@今天群内信息量极大</span> 还展示了一次 deep-research 的失控：只是想搜一个库的 API 用法，结果工具启动了 97 个 agent、跑了 8 分 40 秒，大部分都触发了 rate limit——「红的都是把自己干趴下了。就……很蠢」。

> <span class="mention">@稳重的海豚</span>：话说 opus 4.8 真的是垃圾啊，他怎么能做到跑分更高了

<span class="mention">@80-HD</span> 再次抱怨 Opus 不读 claude.md——「血压一下子就飙升了」。公司给的 Claude quota 也快见底了，他透露可以用公司给 service 的 API 绕过——「然后我可以假装成 service」。这延续了 [「Opus 4.8 降智续」]({{ '/daily/2026/06/10/daily/#opus-48-降智续' | relative_url }}) 以来的退步趋势。

### Agent 配置：让 AI 自己去找

<span class="mention">@我要成为灵能高手</span> 分享了一个重要实践原则：模型会自己读 CI 脚本和 workflow 文件，所以 instruction 只需写「什么时候该用」而不必重复代码已有的信息——「要写那些不容易看出来的」。他还强调了一个容易被忽略的维度：AI 没有对时间流逝的常识，如果不明确指出避免重复工作，它不会自己往那里想，「你不说他也不会往那里想，这就值得提」。

> <span class="mention">@我要成为灵能高手</span>：新模型出来了确实得把以前做不了的事再做一遍，成功了就可以全面升级各种 instruction，让 AI own 的 scope 越来越大

<span class="mention">@敏锐的海狸</span> 发现 Claude Code 似乎会优先读取 workflow.js 而非 skill markdown file，让之前写的 skill 文件基本失效——「Design Doc 里写的很多东西，是不是都可以直接沉淀到 workflow.js 里面？」<span class="mention">@我要成为灵能高手</span> 确认模型一直都会去读 CI 脚本，建议「只留下什么时候该去用而不是自己发明，剩下的 AI 都会自己搞定的」。这和 [「Monorepo Skill 组织之争」]({{ '/daily/2026/06/10/daily/#monorepo-skill-组织之争' | relative_url }}) 中他说自己「已经退化成一个普通的 prompt 文件了」的思路一脉相承。

### Zed DeltaDB

<span class="mention">@热情的狮子</span> 分享了 Zed 推出 DeltaDB 的消息。DeltaDB 把版本控制从「按 commit 拍照」变成了「记录每一次编辑操作」——每次修改都存成可定位的 delta，并把触发修改的 AI 对话绑定在一起。这意味着可以从任意一行代码直接跳回当时的聊天记录，多人或多 agent 可以在同一个工作树里同时编辑而不用先 commit。目前只是产品发布公告，beta 版几周后开放，性能数据尚未披露。
