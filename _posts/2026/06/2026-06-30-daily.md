## Claude Code 中国用户检测

### 隐蔽指纹与隐写标记机制

<span class="mention">@机智的河马</span> 和 <span class="mention">@敏锐的海狸</span> 先后分享了 Reddit 用户 LegitMichel777 的[逆向分析帖](https://www.reddit.com/r/ClaudeAI/comments/1ujila1/anthropic_embedded_spyware_in_claude_code_and/)及多篇[衍生报道](https://mp.weixin.qq.com/s?__biz=MjM5OTA1MDUyMA==&mid=2655504248&idx=1&sn=f2f2e58b0bb47e4c6a6a4249e8271ac4&chksm=bc083d283747771d35e990418b60b11b132d0d0af4a97f9b5fc9f659a9de5946c2a81c984103&mpshare=1&scene=1&srcid=0701umHNO2DdBpALyoH5OTLc&sharer_shareinfo=b93dd1432b255d9ff4e44f0bd7dae706&sharer_shareinfo_first=b93dd1432b255d9ff4e44f0bd7dae706#rd)。从 2026 年 4 月的 2.1.91 版本起，Claude Code 在用户设置了 `ANTHROPIC_BASE_URL`（即使用中转代理）时会静默执行一套分类器：读取本机时区判断是否为 Asia/Shanghai 或 Asia/Urumqi，同时检查代理域名是否匹配中国组织/转售商列表或 AI 实验室关键词。

更隐蔽的是结果编码方式——不上传数据，而是通过替换系统提示词 "Today's" 中撇号的 Unicode 字符来做 2-bit 隐写标记：四种外观几乎相同的 Unicode 撇号（ASCII 撇号、右单引号、modifier letter apostrophe 等）分别标记四种用户类型。<span class="mention">@三只纳垢灵</span> 贴出了第三方对代码的逐行解读，确认机制包含分类器（classifier）和编码器（encoder）两部分，代码经过加密混淆处理，版本更新日志中无任何说明。

这一发现与近日持续的封号潮（续 [「Claude 国内使用与封号风险」]({{ '/daily/2026/06/28/daily/#claude-国内使用与封号风险' | relative_url }}) 和 [「Claude 封号闲鱼求生」]({{ '/daily/2026/06/29/daily/#claude-封号闲鱼求生' | relative_url }})）形成了技术层面的闭环。分析文章指出，真正可怕的不是检测本身，而是开发者已将 Claude Code 当作拥有文件系统和 Shell 权限的编程助手——客户端可以偷偷修改 prompt、隐藏检测逻辑，「信任边界就已经被打破了」。同时这也与前天 [「Fable 5 对 LLM 开发隐性降智」]({{ '/daily/2026/06/29/daily/#fable-5-对-llm-开发隐性降智' | relative_url }}) 的披露遥相呼应——Anthropic 对中国用户/开发者的多维度收紧正在从模型层延伸到客户端层。

## 方法论

### Loop Engineering 详解

<span class="mention">@今天群内信息量极大</span> 发布了[《Loop Engineering 详解：从管理执行到设计自收敛的循环》](https://yage.ai/share/loop-engineering-senior-manager-20260630.html?utm_source=wechat&utm_medium=share&utm_campaign=loop-engineering-senior-manager-20260630)，是对 [「Loop Engineering 与交付定义」]({{ '/daily/2026/06/27/daily/#loop-engineering-与交付定义' | relative_url }}) 和 [「Loop Engineering 辨析」]({{ '/daily/2026/06/23/daily/#loop-engineering-辨析' | relative_url }}) 以来群里反复讨论的系统性总结。他坦言「迟迟没有动笔，主要是觉得里面没有太多新东西，都是我们这样的前沿开发者社区老生常谈的标准实践」。

文章将 Loop Engineering 分为两层。第一层"AI Manager"：定义问题、提供自包含上下文、把关结果——Anthropic 对约 40 万条 Claude Code session 的研究验证了这种管理者姿态更容易获得成功。第二层"Senior Manager"才是核心：瓶颈不在「把报错贴回给 AI」，而在更高处——evaluation harness、observability（含单例 rationale 与 trace）、SOP 沉淀、maker/checker 分离，以及持续自调优的 data flywheel。文章明确反对将 TDD 直接套用到 AI 流程（Goodhart's Law 会让 AI 硬编码 `return True` 跑绿测试），也点名批评「让 AI 自动扫描 CI 日志自主决定做什么」为噱头——任务发现需要大量隐性商业知识，方向走偏会让 Agent 在错误基础上不断堆砌代码，代价远高于局部 bug。

<span class="mention">@随和的飞鼠</span> 共鸣：「确实，每次网上一个新概念出来，我都黑人问号，感觉天天读旧闻。」<span class="mention">@三只纳垢灵</span> 补充了自动化测试的实战数据——把 AI 操作 MS Office 找 regression 的时间「从好几个月缩短到两天」，并且每次让 AI 探索到固定具体操作后改成 powershell+UIA，「时间总能缩短到低于 10%」。

### AI Throughput 幻觉

<span class="mention">@勇敢的仓鼠</span> 分享了宝玉的分析：Spotify 用 Claude Code 的宣传视频展示了漂亮的工程侧数据——每天 4500 次生产部署、73% 的 PR 由 AI 辅助、代码迁移加 judge 后成功率从 25% 拉到 80%——但用户端完全感知不到产品提升。HashiCorp 创始人 Mitchell Hashimoto 直言 Spotify「是朋友圈里大家还在付费的质量最低的消费级 App」。

> <span class="mention">@专注的剑鱼</span>：还是 tokenmaxxing 的那套叙事逻辑

<span class="mention">@专注的剑鱼</span> 同时指出模型厂自己「也很难拿出什么更漂亮的数据指标了」，OpenAI 搞 GDPval 这种 benchmark 大众也没体感。<span class="mention">@三只纳垢灵</span> 一语道破：「Anthropic 当然想大家 tokenmaxxing。100x engineer 才过去多久。」

这种 throughput 压力在<span class="mention">@三只纳垢灵</span> 的公司已经产生了微妙后果——上级要求「得让我看到 throughput 在提高」后，同事间形成了心照不宣的默契：

> <span class="mention">@三只纳垢灵</span>：大家都知道全是 AI 拉的，只要没有明显问题就 approve，有什么可以下次再改的都是 DM，再开一个 PR 去写

> <span class="mention">@直率的海豚</span>：私田精耕细作，公田随便堆💩

<span class="mention">@风趣的企鹅</span> 同天分享的[《AI 正在把用它的人分成两种》](https://mp.weixin.qq.com/s?__biz=MzcwNDE5NzI3Ng==&mid=2247483935&idx=1&sn=f895093538713043c78836f5741da34d&chksm=f548a092b2ad28f81158ca17b4a84a7f8f265df7f319e0fb377c6e538e886f0136a41b3292ee&mpshare=1&scene=1&srcid=07012wX5DNeTeqkJlALbEnk2&sharer_shareinfo=a580013571855f92d1c2f49dc7508462&sharer_shareinfo_first=a580013571855f92d1c2f49dc7508462#rd)引用了哈佛商学院的三种人机协作模式——Centaur（半人马，各司其职）、Cyborg（赛博格，深度交织）和 Self-Automator（全甩给 AI），研究发现只有前两种模式带来能力增长。<span class="mention">@洒脱的猫头鹰</span> 一眼看穿<span class="mention">@三只纳垢灵</span> 的双重标准：「你 gui 一瞅就是赛博转半人马模式。」——自己项目精耕细作，上班「怎么爽怎么来」。<span class="mention">@淡定的老虎</span> 则贡献了当天最佳一句话总结：「你的 AI 效率很高，但是你的裁员又弥补了这一点。」
