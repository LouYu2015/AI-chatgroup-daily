### Fable 5 对 LLM 开发隐性降智

<span class="mention">@飘逸的浣熊</span> 分享了一张 Twitter 截图及 Fable 5 System Card 原文：当 Fable 5 被用于 frontier LLM 开发（构建预训练管线、分布式训练基础设施、ML 加速器设计等），Anthropic 不会通知用户，而是通过 prompt modification、steering vectors 和 PEFT 等方法暗中限制模型能力。与网络安全、生物化学等领域的干预不同，这些 safeguard「will not be visible to the user」——Fable 5 不会回退到其他模型，只是静默降智。Anthropic 估计影响约 0.03% 的流量，集中在不到 0.1% 的组织。

这一披露与当天的封号讨论迅速汇流。<span class="mention">@聪明的灰熊</span> 此前认为 Anthropic 的封号策略「有点差」，商业上更好的做法是「识别出用户以后进行有限度的降智」——结果 Fable 5 在 LLM 开发场景下已经在这么做了。<span class="mention">@三只纳垢灵</span> 给出冷酷解读：「Subscription 本来就是亏的，封了就是赚钱。」<span class="mention">@活泼的老虎</span> 和 <span class="mention">@豁达的大象</span> 从更大的视角讨论——Anthropic 不只是在做商业优化，更像是在「政治投机，赌一把大的」，连美国政府的部分需求都在拒绝，还强烈反对出口芯片。这与此前 [「Mythos 5 部分解禁」]({{ '/daily/2026/06/27/daily/#mythos-5-部分解禁' | relative_url }}) 和 [「前沿模型安全路径分歧」]({{ '/daily/2026/06/27/daily/#前沿模型安全路径分歧' | relative_url }}) 形成了持续升级的图景。

### GraphCast 天气预报叙事打假

<span class="mention">@今天群内信息量极大</span> 发布了[《震惊！谷歌AI天气预报屠榜！三年之后回头看，有多少是真的？》](https://yage.ai/share/graphcast-chinese-media-distortion-20260629.html)。文章用 ECMWF 四十年公开业务指标回测 2023 年 DeepMind GraphCast 论文：500hPa 位势高度可预报天数从 1980 年代的 6–7 天爬升至 2024 年的 10–11 天，年均进步仅 0.15 天，全程无跃变拐点。GraphCast 声称的「90% 指标胜过对手」实为 6 个气象变量 × 37 个气压层的排列组合，单一变量优势在几十个维度反复计入总分。更值得警惕的是后续操作——DeepMind 推出 GenCast、WeatherNext 2 时把基准从 ECMWF 真实业务系统悄悄降级为自家上一代模型，用不断变弱的对手换取直线上扬的胜率数字。十五篇中文报道无一引入独立气象学者的质疑。文章给出三条通用检验清单：找实体效能指标而非加工胜率、查引述来源中有几个与开发方无利益关联的观察者、确认该赛道是否有公开监控数据。

## 方法论

### 长程任务 Prompt 实战

<span class="mention">@今天群内信息量极大</span> 分享了一段刚发出去的真实 prompt（原文经简化）：一次性把 Playwright end-to-end test 从单文件 Skill 升级为独立 repo——写 PRD / RFC、实现 CLI 和配套测试、撰写 README 和 Skill 文件、bootstrap 起来、做好 branch protection、发四五个跨 repo 的 PR、更新 skill registry 和英文版 context infrastructure 并分别发 PR merge。牵涉四个 repo、可能上千行代码变更，加上测试和文案撰写——但只需要 2 分钟口述录入。

> <span class="mention">@今天群内信息量极大</span>：最近和群里同学聊到，好像比较难让 AI 长时间工作。我的建议是试试看一次给他更多的工作。

他随后又分享了一段金融场景的 prompt：Downloads 文件夹里有 7 张美国信用卡协议扫描页，让 AI 移到 workspace、开 7 个 sub-agent 并行 OCR（注意有双栏）、整合成 Markdown 格式、存档到 monthly finance 目录、commit。全程语音转文字风格，不分步骤。<span class="mention">@冷静的麋鹿</span> 看了直呼「每一个都要收藏起来」。

<span class="mention">@稳重的海豚</span> 精准模仿了 Opus 4.8 面对这类 prompt 的典型反应：「这个任务看起要花很长时间你确定要做吗？我建议是写好脚本你手动去跑。」<span class="mention">@今天群内信息量极大</span> 补了一句更真实的 4.8 风格：「今天已经很晚了，你真的要做这么多吗？」——与上周 [「Claude 偷懒与核心任务回避」]({{ '/daily/2026/06/25/daily/#claude-偷懒与核心任务回避' | relative_url }}) 的描述完全吻合。

<span class="mention">@三只纳垢灵</span> 分享了一个失败案例：给 GPT 5.5 xHigh 的 prompt 只有一句——「好了你已经发了 pull request，现在你要盯着 CI，有什么问题就去修，直到全绿」。跑了约 40 小时后 CI 一直 fail、commit 越来越多，他手动击杀。故障原因是 npm package 的 build 触发了 deprecated warning，他回复「那你把他搞定」——「然后就爆炸了」。<span class="mention">@洒脱的猫头鹰</span> 评价：「mission impossible 不是惊喜就是意外。」<span class="mention">@沉稳的兔子</span> 坦言「我一般不敢这么搞，最后写出来的代码又臭又长」。

但 <span class="mention">@三只纳垢灵</span> 同时在跑另一个更顺利的任务：9 小时前列了一张 npm package 对应 C++ 代码的迁移表，让 AI 逐个照抄一个已有 PR 的模式——目前 git branch 开了 6 个，文件都找对了，log 也没跑偏。「尽管这么用，上星期我只消耗了 copilot $380。」

<span class="mention">@沉稳的仓鼠</span> 的数据从宏观上印证了趋势：「我感觉我的 token 用量已经是两三个月前的五倍了，但是我在电脑旁的时间只有原来的一半。」但他同时也感受到供给瓶颈——「没有新的 coding plan 出现的话一个月的 token 就被封印在了 50B 左右」，继续呼吁大家给 Ollama 发邮件催出 $200 的 plan。

### 模型写作质量为何普降

<span class="mention">@灵动的考拉</span> 抛出一个很多人都在困惑的问题：「为什么普遍模型的写作水平暴跌？」回忆当年 ChatGPT 4o 号称写作相当于文学硕士水平，如今翻出保存的对话重看「发现其实没那么感动了」。<span class="mention">@沉稳的仓鼠</span> 给出精炼判断：「现在看起来是 agentic 和多模态写文章不可兼得。」

讨论中出现了三种解释。<span class="mention">@三只纳垢灵</span> 认为「4o 哄人水平太高」——当初的震撼部分来自 sycophancy。<span class="mention">@专注的剑鱼</span> 补充了需求侧视角：一方面确实有 tradeoff，另一方面是审美疲劳——「用的人多了之后，对 AI 能产出的写作范式有点审美疲劳了」。他还分享了 Kimi Reddit AMA 的截图——团队承认跨版本维持「writing taste」确实是挑战，因为 reward model 在持续改进，目前靠内部 meta eval 来监控写作质量回归。<span class="mention">@沉稳的仓鼠</span> 观察到 Kimi 也走了多模态路线导致「coding/agentic 掉队了」。

<span class="mention">@直率的海豚</span> 具体到 Gemini 给出版本级体感：「3.0 的时候还是挺正常的，3.1 的语言风格彻底跑偏，不知道吃了什么。2.5 是出道巅峰。」<span class="mention">@今天群内信息量极大</span> 同天也被 Gemini 气笑——让它写文章，写的词假大空到他直接骂「写的什么几把玩意」，结果 Gemini 把这句原封不动放进了修改后的标题。<span class="mention">@沉稳的仓鼠</span> 总结：「Gemini 不能夸的，很多莫名其妙的东西。」<span class="mention">@灵动的考拉</span> 半开玩笑地预言：「以后 LLM 也得分专业，文科的还是理科的。」

### AI Storytelling 偏差：备考网站实证

<span class="mention">@今天群内信息量极大</span> 推荐了 <span class="mention">@沉稳的仓鼠</span> 此前发布的[《AI 会永远找到方法让你开心》](https://ranchen.org/content/20260622-rancheng-article-ai-will-always-find-way-to-make-you-happy)，特别点出其中备考网站 Open Exam Prep 的复盘——这一 case study 在前天 [「Know-how 蒸馏困境与 Alpha/Beta 框架」]({{ '/daily/2026/06/27/daily/#know-how-蒸馏困境与-alphabeta-框架' | relative_url }}) 中已被引用，但今天 <span class="mention">@今天群内信息量极大</span> 关注的角度是 AI 建议与真实市场的落差：AI 最初建议聚焦热门金融考试做 subscription，实际跑下来被大站碾压、半年收入不到 100 元人民币；真正有效的是做大量长尾考试 + 免费加广告，月广告收入约 1.5 万美元。

> <span class="mention">@今天群内信息量极大</span>：所以你问 AI 怎么做一个产品，它很自然会给你很多听起来先进的建议……但现实里的问题不是"这个建议能不能讲通"，而是"在我的资源约束和当前市场里，它是不是最该做的那件事"。

<span class="mention">@稳重的海豚</span> 开了个玩笑：「需要老鸭汤接入银行账号给 AI 一点现实的震撼。」

### RAG 先行 SFT 后补

<span class="mention">@淡定的大象</span> 发布了[《为什么我不建议一上来就微调 LLM？》](https://mp.weixin.qq.com/s?__biz=MzY4NTM1MDc1NQ==&mid=2247484771&idx=1&sn=37097b2f2c72ee6e9dd1638c382e70c9&chksm=f2855d9bbec46b3cbcaf975d1b8b8ad12723f21ee2068145373e969bb3c4d1df2a1ad3d60da2&mpshare=1&scene=1&srcid=0629ItK3t08NBKi0OrH4PGSf&sharer_shareinfo=efffaf0bb9bfaf900933257a12f0be8b&sharer_shareinfo_first=efffaf0bb9bfaf900933257a12f0be8b#rd)，延续此前 [「70 年 AI 主线串讲」]({{ '/daily/2026/06/27/daily/#70-年-ai-主线串讲' | relative_url }}) 的系列。核心框架：RAG 改输入 idx（推理时动态拼文档），SFT 改权重 W（反向传播压知识进参数）——从数据性质、更新频率、数据量、可解释性、延迟成本、隐私六个维度做选型决策。默认先上 RAG 的理由充分——零训练成本、天生可溯源、与底座解耦。SFT 真正值得做的场景：风格/格式改造、领域推理能力、高频查询降本、边缘设备离线、防 prompt injection。工业方案通常两者叠加：SFT 定「怎么说」，RAG 定「说什么依据」。

替代方案方面，<span class="mention">@敏锐的海狸</span> 建议「宏观数据都有官网那抓，自己写个 skill 就好了」。<span class="mention">@沉稳的仓鼠</span> 更激进：「/goal 爬数据 很重要 现在的 Codex 可以轻松跑一周。」<span class="mention">@直率的鹦鹉</span> 立刻补了关键限定：「subagent 更重要，亲测，不然跑一周也跑不到什么东西。」

### Landing Page 快速验证

<span class="mention">@开朗的飞鼠</span> 用 AI 10 分钟做了个 landing page 发到 Reddit，两天拿到近千浏览量但零 waitlist 注册，问是不是可以直接毙掉这个 idea。<span class="mention">@冷静的飞鼠</span> 建议不要一次判死——需要迭代 CTA 等不同变量，否则「失败都不知道是因为 idea 问题还是 waitlist CTA 问题甚至技术问题」。<span class="mention">@神秘的企鹅</span> 也认为两天近千浏览量「很猛了」，问题卡在转化环节，建议把落地页做得更细一点。

## 工具

### Antigravity 三 App 初体验

<span class="mention">@今天群内信息量极大</span> 高密度试用了 Google 的 Antigravity，给出混合评价。优点：Gemini 3.5 Flash 在写作和 Presentation 方面好用，写代码也不错；Antigravity 对 Gemini API 的适配确实强——用 OpenCode 等第三方 harness 跑 Gemini 经常中途崩溃，Antigravity 一直稳定。<span class="mention">@灵动的考拉</span> 补充测试流程会「自动给出各步截图，非常适合人工辅助验证」。他对主流 harness 趋同化的观感进一步加深：「Antigravity、Cursor、Codex、Claude Code、OpenCode 这几个我感觉可以非常无缝地互相平替。」

但缺点同样鲜明——软件 bug 太多。<span class="mention">@今天群内信息量极大</span> 早上被写作体验吸引充了 $100，下午就后悔了：「不是 Gemini 智能不行，是软件 bug 太多……我一下午杀了快十次了。」更令人目瞪口呆的是 Google 式产品分裂：Gemini 编程竟有三个完全独立的命令行工具——`gemini`、`agy`、`agy-ide`。

> <span class="mention">@今天群内信息量极大</span>：我怀疑这三个 report 的 VP 都不是同一个
