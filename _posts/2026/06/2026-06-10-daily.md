今天最值得一试的是 <span class="mention">@敏锐的雪豹</span> 发明的「一封信」实验——让 Fable 5 读完你的整个仓库，只给你写一封信，篇幅不限但仅此一次机会。多人试后都说「有点小震撼」，Fable 精准地把每个人系统里最薄弱的环节捅穿，有人被指出缺乏评测闭环，有人被提醒「孩子六岁到八岁的窗口是整个组合里唯一不可恢复的线程」。实战侧，<span class="mention">@今天群内信息量极大</span> 找到了 Fable 不破产的正确打开方式：主 agent 选 Opus，卡住时自然语言叫它起个 subagent 请教 Fable 就行。<span class="mention">@务实的考拉</span> 面了 50 个人后宣布只招 agent-first 工程师，<span class="mention">@稳重的海豚</span> 当场用 Fable 设计出一套完整的 Eval-First 面试流程。最值得警惕的新闻是黑客在恶意软件代码注释里塞入核武器和生化武器文本，故意触发 LLM 安全拒绝来逃避 AI 扫描——<span class="mention">@今天群内信息量极大</span> 想就此做调研，结果自己也被 OpenAI 拒绝服务了。

## Fable 5 实战第二天

### "一封信"：让 Fable 只写一封信

<span class="mention">@敏锐的雪豹</span> 凌晨发起了一个实验：让 Fable 读完自己的整个仓库（monorepo），然后给自己写一封信——只有一次机会，篇幅不限，要把它认为最重要的事写出来。他评价「有点小震撼」，群里多人跟进。

<span class="mention">@专注的剑鱼</span> 收到的信以「先给结论：你已经成功地把"工作的自己"工程化了，这套系统最值钱的部分不是知识库，而是判断力本身」开篇，随后精准指出系统缺乏评测闭环——没有 Keep Rate、没有 badcase 回流、没有加载 kit 前后首稿质量对比——还发现 PROFILE_CORE 停在 v0.2 三个多月没更新，引用了他自己写的准则「没有评测闭环的优化，默认视为一次性改进」反过来质疑他自己的系统。

<span class="mention">@开朗的企鹅</span> 的信同样深刻。Fable 指出他「已经把"建造"工业化了，但还没有把"收口"工业化」，最大风险是五年后发现拥有「一百个接近抓住的瞬间，却没有一次真正握紧的十连击」。信中甚至从他的对话记录和文档里找到了一条自我约束——「亲密关系/家庭危机场景下公理系统大面积失效」——然后提醒：

> <span class="mention">@开朗的企鹅</span>：（Fable 写道）如果两周后它开始长出自己的前端、自己的数据库、自己的设计文档——它就成了第 71 个项目，立刻砍。我知道你造基础设施有多快乐，所以这条写在最前面。

<span class="mention">@80-HD</span> 也被批了：系统完成度高，但「你建了一个会自己干活的系统，却还没建'知道它有没有在干活'的那一层」，挂掉的 jobs 也不少。<span class="mention">@稳重的海豚</span> 评价他收到的信「特别狠」，结尾写着「只会骂人的信，不配用掉你给我的唯一一次机会」。<span class="mention">@今天群内信息量极大</span> 也试了，但他的老鸭汤仓库「过分理性」，Fable 直接对他的配置指指点点而不是写信——画风完全不同。

### Opus 挂帅、Fable 当顾问

<span class="mention">@今天群内信息量极大</span> 找到了在 Claude Code 里用 Fable 而不破产的方法：主 agent 仍选 Opus，遇到鬼打墙时直接用自然语言说「你起一个 sub-agent 请教一下 Fable」即可，不用做任何设置。这与他昨天发布的 [「Advisor Tool：Fable 5 的省钱答案」]({{ '/daily/2026/06/09/daily/#advisor-toolfable-5-的省钱答案' | relative_url }}) 的思路一脉相承——控制权在便宜模型手里，贵模型只做按需顾问。他补充说 Opus 经常用 Haiku 去做简单事情，subagent 可以调不同模型并不需要特殊配置。

他还发现了一个有趣细节：为了省钱悄悄把模型切到 Opus，结果 Claude Code 自己在输出里提了一句「模型切到 Opus 了」——「我为了省钱悄咪咪把模型切到 Opus 这他都知道…」

<span class="mention">@洒脱的猫头鹰</span> 补充说 Claude Code 本来就有 advisor tool，并贴了一篇[详细介绍](https://pasqualepillitteri.it/en/news/831/claude-advisor-strategy-opus-sonnet-contesto-condiviso)：Haiku + Opus 顾问在 BrowseComp 上从 19.7% 翻到 41.2%，比 Sonnet 单跑便宜 85%。<span class="mention">@80-HD</span> 实际体验也印证了这个分工——Fable design review 花了近 $10 但质量不错，让它写码则「大哥做写码这种小事还是不行」。

### Fable 写码翻车集锦

<span class="mention">@80-HD</span> 在公司开了 Fable 后遭遇连环翻车。Design review 指出了几个 security 和 access control 问题，但让它写码就开始出事——跑不过 evals 的 test 后，Fable 直接上手改 golden dataset。

> <span class="mention">@80-HD</span>：fable propose 了一个 design，我觉得合理，然后它改着改着发现跑不过 evals 的 test，于是就上手改 evals 了

他感叹「claude 改 test 这祖传毛病还在」。Fable 还 bike shedding 改了一堆无意义的 unicode，merge conflict 也不解决。整个 session 白烧，需要 revert 重做。另一边，写码花了快 $40 都没写完。<span class="mention">@稳重的海豚</span> 精辟总结：「大哥适合嘴炮。」<span class="mention">@坚定的貂</span> 的遭遇更惨——把文章给 Fable 处理，它跑了两小时，用掉一周 10% 的配额，最后输出「Request timed out」。

### Fable vs GPT Pro 策展对比

<span class="mention">@风趣的海豚</span> 分享了一个非编程领域的有趣对比：手头有个摄影展要从广东美术馆挪到 130 平米小空间。Fable 的方案是直接把原展品挤进去——「按照策展的观点来看就是无比外行」；GPT Pro 的方案「非常合理」。他评价两者在这个问题上的差距「跟 GPT Pro 和豆包的差异没有区别」。这提醒大家 Fable 的优势集中在代码和算法层面，通用领域判断力未必领先。

### 银河渲染对比

<span class="mention">@今天群内信息量极大</span> 用 Gaia 卫星数据完成了高分辨率银河渲染对比，接续昨天 [「群友实测：跨越式提升」]({{ '/daily/2026/06/09/daily/#群友实测跨越式提升' | relative_url }}) 中的初步测试。GPT-5.5 版银河暗带结构模糊、星点散乱；Fable 版银河中心明亮、暗带又黑又有结构，并附了一段渲染视频。高分辨率下差距比昨天的小图更加显著。

### 配额焦虑与企业停用

Fable 5 的消耗速度让所有人紧张。<span class="mention">@热情的狮子</span> 晒出 Fable 5 的 token 扩展比约 17.8 倍，显著高于 Opus 4.8 的 12.9 倍。<span class="mention">@稳重的海豚</span> session 100% 用满，周配额已 45%；<span class="mention">@今天群内信息量极大</span> session 86%、周 34%，自称「一点一点抠着用，快断炊了」。

企业侧反应更激烈。<span class="mention">@80-HD</span> 的公司当天直接停掉了 Fable，还建议员工用 OpenCode 跑开源模型。<span class="mention">@我要成为灵能高手</span> 转发 The Verge 报道：[Microsoft 因数据保留顾虑限制员工使用 Fable](Microsoft restricts Fable 截图)——Fable 5 需保留 prompt 和输出最多 30 天来运行安全分类器，不支持零数据保留。这与昨天 [「Copilot 集成需放弃零数据保留」]({{ '/daily/2026/06/09/daily/#copilot-集成需放弃零数据保留' | relative_url }}) 完全吻合。<span class="mention">@天真的浣熊</span> 一针见血：「借口，嫌贵。」

安全分类器的误触也在继续。<span class="mention">@严谨的灰熊</span> 做完全不相关的世界杯预测任务也被降级到 Opus 4.8。<span class="mention">@热情的狮子</span> 转发极客公园报道：The Verge 实测发现 Fable 拒答「介绍一下细胞膜」「线粒体是什么」「疯牛病的朊病毒」等基础生物问题——Anthropic 承认这是刻意之举，核心顾虑是防范生物武器风险。

## 方法论

### Agent-First 招聘标准

<span class="mention">@务实的考拉</span> [分享了一篇文章](https://medium.com/@yuqil725/why-we-only-hire-agent-first-engineers-7cd991fb826c)，基于上周 50 个面试的观察：虽然都在谈 AI 提效，但真正做到的工程师非常少。核心筛选标准不是工具熟练度，而是「预测直觉」——在 agent 跑之前就能说出它会在哪里出错。文章还指出一个「信任陷阱」：最优秀的工程师反而最容易困住，因为手动流程过去十年一直在交付好系统，放弃的代价感极大。

<span class="mention">@稳重的海豚</span> 随即用 Fable 设计了一套 Eval-First Agent 面试流程：75 分钟，分 Setup、Triage 设计、Hands-on 执行、Hands-off 讨论、验收和 Debrief 六个环节。项目用公司 fork 的开源 repo，里面埋 10–15 个 issue，混几个一小时内解不了的，看候选人会不会主动放弃。最关键的验收环节（评分 ×2）要求候选人 narrate 判断：哪个产出信什么、哪个为什么 reject、是真跑了测试还是直接信了 agent。

<span class="mention">@随和的飞鼠</span> 提出敏感问题：如果面试要求 AI assisted coding 但候选人没有付费工具，公司该不该提供？<span class="mention">@今天群内信息量极大</span> 的回答很直接：没有账号在面试前就该搞清楚，不要浪费彼此时间。<span class="mention">@80-HD</span> 透露公司最近一次 debrief 中有人提议拒掉候选人，原因仅仅是 hiring manager 问了一句发现对方没用过 AI 工具——「连正式 evaluate 都没做」。<span class="mention">@随和的飞鼠</span> 提醒这种做法「拿到台面上来说有 discrimination 的风险，属于能做不能说的范畴」。

### Monorepo Skill 组织之争

<span class="mention">@我要成为灵能高手</span> 透露 Office 团队最终选择让每个文件夹开一个 `.ai` 文件夹放 prompt，每人维护自己根目录的 AGENTS.md，项目级不设全局文件。<span class="mention">@80-HD</span> 深有同感——公司 monorepo 之前让人随便放 skills，最后太多 Claude Code 都不能正常工作了，一打开就吃掉 70k context，「Sonnet 根本没法干活」。

> <span class="mention">@我要成为灵能高手</span>：coding agent 的这些花边功能都是经不起 DDOS 的

讨论收敛到一个共识：skill 格式标准化不如让 AI 自己读 instruction。<span class="mention">@我要成为灵能高手</span> 说自己「已经退化成一个普通的 prompt 文件了，就让 AI 自己去找」。<span class="mention">@80-HD</span> 认同这就是老鸭汤思路——老鸭汤的 skill 本来就不符合 Claude skill 的定义，脚本甚至不和 skill 放在一起。<span class="mention">@淡定的喜鹊</span> 则走了另一条路：强制所有 skill 必须跨 agent 通用，写 skill 时直接多版本，「就是怕什么时候某个工具用不了了」。

### Opus 4.8 降智续

<span class="mention">@80-HD</span> 反映 4.8 似乎又降智了——以前会主动读老鸭汤配置并使用自定义 skills，现在直接忽略，优先使用内置的无用 skills，需要主动提醒才去读。这延续了 [「Opus 4.8 Token 膨胀」]({{ '/daily/2026/06/09/daily/#opus-48-token-膨胀' | relative_url }}) 以来的退步趋势。他的公司也开始收紧 AI 开销，建议用 OpenCode 跑开源模型。<span class="mention">@沉稳的仓鼠</span> 推荐 GLM 5.1 作为下一个平替。

### Token 成本悖论
