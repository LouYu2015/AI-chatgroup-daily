## 工具

### 火山妙记：说话人分离最优解

延续昨天 [「音频转录方案讨论」]({{ '/daily/2026/06/16/daily/#音频转录方案讨论' | relative_url }})，<span class="mention">@热情的狮子</span> 今天发布了[完整的方案对比博文](https://blog.ax0x.ai/transcriber-diarization-miaoji-zh)，记录了大半年的踩坑路径。他先后试了 Gemini 切块缝合（缝合点投票投歪越缝越乱）、Senko（快但把一两个字的应答判成新说话人）、豆包录音识别 2.0（中文转写好但说话人分离更崩），最终落在火山妙记 API。

五段真实录音的对比矩阵中，妙记在四段两人对话中全部精准判 2 人，而竞品虚高到 3–5 人；一段 3.45 小时的多角色录音妙记判 3 人，豆包 2.0 判 10 人。结论是说话人分离不该是转写的副产品——把它整个交给一个把分离当正经任务做的专用服务端模型，比在通用模型上堆缝合算法靠谱得多。妙记的硬要求是只接受公网可下载链接，跨境上传需开并行分片突破单连接限速。他正在将妙记接入 watch-transcriber 和 transcribe 两个工具。

## 方法论

### 推理模型四年史

<span class="mention">@今天群内信息量极大</span> 发布了[「推理模型四年史：你以为的石破天惊，其实早有暗线」](https://yage.ai/share/reasoning-model-lineage-20260617.html?utm_source=wechat&utm_medium=share&utm_campaign=reasoning-model-lineage-20260617)。文章从 2022 年的 Chain-of-Thought Prompting 起笔，梳理 Zero-Shot CoT → STaR → PRM800K → test-time compute scaling 的完整谱系，论证 o1 真正做的不是发明推理能力而是产品化——API 引入 reasoning tokens 按量计费，把 test-time search 变成可购买的资源。

对 R1 的分析尤为犀利：独立复现表明 aha moment 在 epoch 0 就存在，RL 只是提高出现频率；用随机奖励跑 RL 也能提升 MATH-500 成绩 21%，接近真实奖励的 29%。R1 的真正贡献在于「用详尽论文、开放权重、六个蒸馏模型和明确的 GRPO 配方，把 reasoning model 的 know-how 公有化」。文章还比较了 OpenAI（隐藏推理过程）和 Anthropic（可见且可调预算）两条相反的产品哲学。

> <span class="mention">@细心的熊猫</span>：模型开发已经跟原子配方一样都是公开的秘密了。原子弹人人都能造，就是拿不到显卡

### CC Memory 与老鸭汤跨 agent 接入

<span class="mention">@风趣的海豚</span> 好奇 <span class="mention">@今天群内信息量极大</span> 用不同 agent 时怎么接入老鸭汤。<span class="mention">@今天群内信息量极大</span> 解释老鸭汤的好处在于它与具体 LLM 和 harness 相对独立——「主要就是一坨 MD 文件和 CLI，只要把工作目录指向老鸭汤的目录就可以了」。multi-agent skill 里会按任务推荐不同 LLM：写作给 DeepSeek / Gemini / GLM，隐私相关的健康分析优先给 Ollama（zero data retention）。

<span class="mention">@稳重的海豚</span> 的方案更工程化：他的 meta harness 底层接 Codex、OpenCode 和 Claude Code，三个 provider 各自往 memory 里乱写。他做了 reverse symlink，把所有 provider 的 memory 全部汇入 monorepo，再用 <span class="mention">@今天群内信息量极大</span> 的 skill 做定期清理。<span class="mention">@敏锐的海狸</span> 也有类似的 monorepo 存「digital me」，并提到需要时不时跑 distill 重新分类。<span class="mention">@敏锐的海狸</span> 还分享了自己的做法：要求 CC 把 memory 写在 design doc 和 skill 里，「不允许留在 memory」。

<span class="mention">@80-HD</span> 坦言自己一直没管 CC 的 memory，「现在经常莫名其妙给我做一些奇怪的决定」。这延续了 [「Memory 只存纠正」]({{ '/daily/2026/06/15/daily/#memory-只存纠正' | relative_url }}) 中对 Claude 自带 memory 混乱问题的讨论。

### Opus 跳步的 prompt 技巧

<span class="mention">@坦荡的灰熊</span> 抱怨 Opus 4.8 在 skill 里写好的 step 居然能跳过——截图显示 AI 承认「STEP 4 我跳了，只做了 in-session 反思，没碰会话 jsonl」。

> <span class="mention">@我要成为灵能高手</span>：我会在 job 里面规定只有我说 abc 他才能跳过 def，这样我什么都不说，他就会全都做

这个技巧的逻辑是把跳过条件绑定在用户的显式指令上——用户什么都不说就不满足跳过条件。多位群友表示「学到了」。<span class="mention">@敏锐的海狸</span> 补充确认「4.8 真的没有 4.6 老实」，这是 [「Opus 4.8 DeepSeek 化」]({{ '/daily/2026/06/15/daily/#opus-48-deepseek-化' | relative_url }}) 以来的又一例。
