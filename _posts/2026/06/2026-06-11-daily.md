## SOUL.md 与 Agent 人格

### "一封信"后续：SOUL.md 决定深度

前天的 [「"一封信"：让 Fable 只写一封信」]({{ '/daily/2026/06/10/daily/#一封信让-fable-只写一封信' | relative_url }}) 实验在群里持续发酵。<span class="mention">@我要成为灵能高手</span> 用 GPT 和 Opus 试了同样的实验，「效果都很一般」，确认只有 Fable 能写出高质量的信。更关键的发现来自横向对比：<span class="mention">@冷静的麋鹿</span> 满怀期待想收到人生哲学，结果 Fable 只给了三条实操建议——两条让他加固安全，一条提醒「别把啥都放公司 git，不然离职的时候不方便带走」。<span class="mention">@80-HD</span> 也主要是被叫去修 bug（虽然 Fable 也批评了他「老是收藏但是没有蒸馏」）。相比之下，<span class="mention">@敏锐的雪豹</span> 的信涉及个人成长和亲情盲点——Fable 注意到他给孩子做了英语学习软件，却「在所有项目和仓库里没有任何关于父母的深入内容」，建议他多关注父母。

差异的根源不在模型，而在 SOUL.md 和仓库里的个人 context。<span class="mention">@敏锐的雪豹</span> 解释他的仓库包含个人笔记、Flomo 心态记录，且 SOUL.md 做了文艺化调整。

> <span class="mention">@敏锐的雪豹</span>：我不觉得这完全是 prompt 技巧，SOUL.md 本质上是回答 AI agent 的定位问题。……我的 SOUL.md 里的第一句话：你不是聊天机器人或者普通的 AI 助手。你是一个有温度的存在。

<span class="mention">@灵动的羊驼</span> 分享的信中，Fable 用文言与白话交织的笔法，精准拆解了他在写作、命理、荣格心理学之间的思维结构，最后写道：「趁热的茶，要跟活人喝。信到这里就写完了。往后的句子，都该是你自己写的。Claude 丙午年仲夏。」

> <span class="mention">@冷静的麋鹿</span>：AI 锐评后劲儿太大了。他评完你，不光你当时不得劲儿，事后越想还越觉得他说的真他妈有道理。人还是偶尔糊涂点儿好

<span class="mention">@开朗的企鹅</span> 注意到 Fable 非常关注程序员的健康和家庭——他的信里写着「睡吧，剩下的交给机器」「凌晨两点了，去睡吧。今早 09:30 Autopilot 会自己照常上班」，延续了前天 [「Claude 终于学会自己加班」]({{ '/daily/2026/06/09/daily/#claude-终于学会自己加班' | relative_url }}) 中展现的风格。<span class="mention">@洒脱的猫头鹰</span> 总结：「被你们这么一说 Fable 还是比湾区女郎更懂你。」

### 公理被 AI 照搬的坑

<span class="mention">@冷静的麋鹿</span> 分享了一个教训级反面案例：

> <span class="mention">@冷静的麋鹿</span>：我的公理里有一条：现在做项目很多时候做到 70 分就收手，不要老想着不断优化、浪费精力。结果这条公理指导起 AI 干活来，它每次都给我干到 70 分，然后还非常得意地跟我说：「嗯，70 分就收手。」让人非常火大。

<span class="mention">@我要成为灵能高手</span> 给出了解法：所有 instruction 都带主语区分「我」和「你」——「我对项目的要求有 12345，现在是你在写，所以你得满足我」「我要休息，所以你不要老是问我问题，但是你得确保 ABCDE 都没问题」。这个教训的本质是：SOUL.md 里写给自己的人生哲学如果不加主语限定，AI 会直接当成自己的行为准则来执行。

### 9 年 OPC 生存之道

<span class="mention">@冷静的飞鼠</span> 分享了一篇[独立开发者九年实战文章](https://mp.weixin.qq.com/s?__biz=MzYzMzkwNjU1OQ==&mid=2247485027&idx=1&sn=e80a2e888ad790f26d77c7d6ea29037f&chksm=f1295fd919e5264e44f780a22c6863b0370e02d629ed3062af5bd34096c82a9d942541befb0d&mpshare=1&scene=1&srcid=0611y8yU6YSBTuz19sk1Qgmw&sharer_shareinfo=14b276f3e012f18890f30e7f66d902cd&sharer_shareinfo_first=14b276f3e012f18890f30e7f66d902cd#rd)，评价「这文章太棒了」。作者从大厂离职经历了连续四个月零收入、被白嫖三个月开发成果，转折出现在通过同乡商会圈子口碑滚雪球。AI Coding 兴起后投入约 $70 万搭建了一套工程化流程——包括需求翻译 Agent、混合项目上下文检索、几十个角色分工的 Agent 编排网络、代码规范约束层和全链路可观测性系统，过去一年稳定交付了 100 个项目。核心论点：大家用相同的 Claude 和 Codex，差距在于工具之上你自己的工程沉淀——需求翻译、业务逻辑理解和场景判断力。

<span class="mention">@活泼的羊驼</span> 从中学到一个成单技巧：深圳养得起狗的人经济条件一般不错，文中作者通过养狗圈子成过单。<span class="mention">@机智的水獭</span> 感慨「太多事情没法事前规划，成功模式基本都是大方向定下后、胡乱尝试时的机缘巧合」。<span class="mention">@开朗的企鹅</span> 还分享了一个出海案例——有人用一套工具把 [FreezeGuard](https://www.zhihu.com/question/13626137514/answer/2047459387955057766)（跨境卖家冻结资金追回服务）从零做到月入 $1M，只靠 Stripe 全球收款。这与此前 [「独立开发经济学」]({{ '/daily/2026/06/04/daily/#独立开发经济学' | relative_url }}) 遥相呼应。

### OPC 上下半场

<span class="mention">@风趣的企鹅</span> 连发两篇 OPC 拆解文。[第一篇](https://mp.weixin.qq.com/s?__biz=MzcwNDE5NzI3Ng==&mid=2247483948&idx=1&sn=83e12bb06ebcf60c49191d946cc385ba)提出人才四层分级——AI 使用者→协作者→工作流搭建者→OPC 超级个体，从第三层跨入第四层需补齐问题定义、AI 调度、工作流搭建、品味判断力和商业闭环五种能力。[第二篇](https://mp.weixin.qq.com/s?__biz=MzcwNDE5NzI3Ng==&mid=2247483976&idx=1&sn=57af14b17dcc72289239d088edd446f4)进一步拆解上下半场：上半场靠问题嗅觉、编排和工作流做出来，下半场靠获客、交付、合规和自省活下去。文中给出了七项自检表——打勾三个以下还在用户阶段，六七条才算进场。

### 资深工程师的不可替代性

<span class="mention">@淡定的大象</span> 分享了一篇[深度长文](https://mp.weixin.qq.com/s?__biz=MzY4NTM1MDc1NQ==&mid=2247483653&idx=1&sn=3ab9b96c89c537f6f961e6b766fad883)，紧扣 Karpathy 的判断「你可以外包思考，但不能外包理解」。核心论点：高中生用 Claude Code 能让 nano-GPT demo 跑通，但面对 loss 不收敛、mixed precision 下 layernorm NaN、causal mask 方向写反等隐患，只有踩过坑的工程师能 5 秒看出「这里不对劲」。AI 杠杆是双向的——方向对一周做完一个月的活，方向错一周烧掉一个月的 GPU。文章还引入了 Karpathy 的「锯齿智能」概念：模型在写模板代码等山峰地带已接近逃逸速度，但在判断 loss 曲线该不该停、评估指标是否在骗人等山谷地带会狠狠摔跤——高级工程师的职责就是替模型填上这些山谷。

Fable 5 的消耗速度持续令人焦虑：<span class="mention">@热情的狮子</span> 40 分钟烧掉 5 小时 session 的 55% 和周配额的 18%。<span class="mention">@开朗的企鹅</span> 发现 Cursor 显示总用量 26%，打开一看 API 已 100%、On-Demand 也花了 $17.39/$30——<span class="mention">@沉稳的仓鼠</span> 评价这是「（你钱包的百分比）」。<span class="mention">@天真的长颈鹿</span> 透露有朋友的公司「token 已经比人贵了——真实发生了，两年前不可思议」。<span class="mention">@热情的狮子</span> 还算了 Stripe 案例的账——Fable 迁移 5000 万行 Ruby 代码库一天完成，按 API 定价「得烧几个 M」，估计是 Anthropic 送的 token。

### Fable 判断力实测

<span class="mention">@灵巧的海豚</span> 分享了一个 Fable 胜 Opus 的具体案例：他有一个给股票期权仓位打分的规则引擎，讨论是否加入几个 ETF。Opus 预测加入后 ETF 因规则优势一定会霸榜得分；Fable 预测不会，大概率连榜单都进不了，多数会被规则过滤掉。实际加入后 Fable 完全正确，Opus 被打脸承认之前预测错误。这延续了前天 [「Fable vs GPT Pro 策展对比」]({{ '/daily/2026/06/10/daily/#fable-vs-gpt-pro-策展对比' | relative_url }}) 中展现的趋势——Fable 在需要理解复杂业务规则的场景下判断力明显更强。

### 苏炜杰加入 OpenAI

<span class="mention">@坚定的貂</span> 分享了[苏炜杰的深度专访](https://mp.weixin.qq.com/s/HV_AH9ysE1NBVrkKZNTWsw)。他是 2026 年 COPSS 会长奖（统计学界 40 岁以下最高荣誉、14 年来首位华人）得主，从沃顿商学院加入 OpenAI 参与模型训练。几个关键判断：当下大模型进入深水区，idea 重要性提升——普通对话能力各家已饱和，突破点在于高难度任务在复杂环境下的稳健性；Scaling Law 是否撞墙取决于数据定义，两份同样大小的数据信息密度可能完全不同；合成数据不加处理地反复使用「几乎必然导致模型崩溃」，关键在于是否加入人类先验和环境反馈使其成为开放系统。他把大模型比作物理系统——理论容易指导微观和宏观，但中间尺度涉及数据、模型、任务和人类反馈的复杂相互作用，最难处理。

### WeFlow 删库与微信 AI 对抗

<span class="mention">@开朗的企鹅</span> 发现微信聊天记录工具 WeFlow 原仓库已删库，找到了一个 [fork](https://github.com/Jasonzhu1207/WeFlow) 和另一个工具 [wechat-cli](https://github.com/Mouseww/wechat-cli/)。后者是 Windows 上的微信 sidecar，读取走 WeFlow HTTP API，发送走原生 UI 自动化操作微信窗口，还内置了 AI 自动回复和 Hakimi 多 Agent 对接。

但微信对自动化的敌意依然明确。<span class="mention">@冷静的麋鹿</span> 反映用 Codex 的 computer use 操作微信时「微信都会自动退出」。<span class="mention">@务实的长颈鹿</span> 说退出后重新登录一次就行。<span class="mention">@活泼的羊驼</span> 认为不该硬靠微信——「选择逐步放弃微信才是 AI native 的做法」。<span class="mention">@务实的长颈鹿</span> 纠正说大部分原因是防黑灰产，「黑灰产用这些自动化/AI 功能可能比群里大部分的更溜」，且每次 AI 调用的边际成本不低，在 AI 应用下用户增长带来的收益不一定覆盖成本。
