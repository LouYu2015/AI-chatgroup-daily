## Claude Fable 5 发布

### Fable 5 / Mythos 5 能力与定价

Anthropic 一次发布两款模型：[Claude Fable 5 与 Claude Mythos 5](https://www.anthropic.com/news/claude-fable-5-mythos-5)。二者共享同一底层模型，Mythos 5 满血但仅向受信合作伙伴开放，Fable 5 面向所有人，多了一层安全分类器——遇到网络安全、生物化学、模型蒸馏三类请求时自动降级到 Opus 4.8 代答。

Benchmark 全面 SOTA：SWE-bench Pro 80.3%（Opus 4.8 为 69.2%，GPT 5.5 为 58.6%），SWE-bench Verified 95.5%，Humanity's Last Exam 无工具 59.0。视觉方面，Fable 5 仅靠截图通关了宝可梦火红。Stripe 早期测试中在 5000 万行 Ruby 代码库完成全局迁移，一天搞定原本需两个月的工作。

定价每百万输入 token $10、输出 $50，是 Opus 4.8 的两倍。Pro、Max、Team 和 Enterprise 用户 6 月 22 日前免费体验，之后需购买 usage credits。<span class="mention">@沉稳的仓鼠</span> 配了一张「暴论」海报：$200 Coding Plan 大概等值 $5K–10K 的 API 成本，是一个「非常短暂的时代红利」，建议所有人赶紧用满。群友实测 Fable 5 消耗配额约为 Opus 的 2–3 倍，<span class="mention">@稳重的海豚</span> 跑了不到两小时 5 小时额度已去 73%。

> <span class="mention">@热情的狮子</span>：用了一个半小时 fable，同时 5 个 session……很坏，fable 用爽了，june 23 不给薅羊毛，要有戒断反应了

### 安全分类器：「你好」也是高危行为

安全分类器的误触率成了今天最大的槽点。<span class="mention">@洒脱的飞鼠</span> 刚拿到 Fable 5 就立刻被 flag——「Fable 5 1M's safety measures flagged this message. Switched to Opus 4.8.」有人发现问「9.9−9.11=?」也会触发降级——疑似 911 关键词命中——随后 Opus 4.8 还顺手算错了。<span class="mention">@灵动的喜鹊</span> 反馈问医疗问题直接降级，<span class="mention">@热情的狮子</span> 发现改 config 就触发。

<span class="mention">@今天群内信息量极大</span> 遭遇最离谱——他对着 Fable 5 的 244 页安全报告写分析文章，讨论其中关于生物武器防御的实验设计，结果「100% 触发」安全审查，连 Opus 降级都不给，直接 Request was blocked。他感慨「总觉得有些个人恩怨在里面」。

> <span class="mention">@80-HD</span>：本文试图由 Claude Fable 5 撰写，但内容百分之百触发安全预警，最终由 DeepSeek V4 Pro 完成。

<span class="mention">@今天群内信息量极大</span> 随后发布了第三篇分析——[付 Fable 的价，拿 Opus 的货：AI 安全护栏的另一重身份](https://yage.ai/share/anthropic-safeguard-price-fence-20260609.html?utm_source=wechat&utm_medium=share&utm_campaign=anthropic-safeguard-price-fence-20260609)。核心洞察是：安全分类器客观上构成了一道精巧的价格围栏——需要满血网络安全能力的组织恰好是能签企业合同、通过审查、接受数据保留条款的组织。受约束版本的生产成本反而更高（多跑一整套 classifier），精确符合经济学上对 damaged goods 的定义。安全功能货真价实，价格围栏也是真的，「护栏和围栏从此是同一个装置」。

<span class="mention">@我要成为灵能高手</span> 还注意到另一层限制：Fable 5 如果检测到你在做前沿 LLM 开发（训练 pipeline、分布式训练基础设施、ML 加速器设计），会通过 prompt 修改、steering vectors 或 PEFT 等方式「悄悄降智」，不通知用户、不降级模型，估计影响约 0.03% 流量。SemiAnalysis 在推特上直呼「Anthropic 的最新模型会在你做 GPU 推理研究时偷偷降 IQ」。

### 稻瘟病实验与 LLM 校准者

<span class="mention">@今天群内信息量极大</span> 发布了 [Fable 5 安全报告里的稻瘟病实验深度分析](https://yage.ai/share/fable5-rice-blast-ai-bottleneck-20260609.html?utm_source=wechat&utm_medium=share&utm_campaign=fable5-rice-blast-ai-bottleneck-20260609)。安全报告找了六位生物学博士配 Mythos 5 做农业病原体防御任务，分为植物病理学专家组和通用微生物学组，结果通用组中两支团队的方案质量反而压过全部专家组——两个人用 AI 一天多完成了估算需两到三个半月的纯人力工作。

关键发现是每支团队都配了一位 LLM 专家。这个人的工作不是写 prompt，而是知道模型会在哪里掉链子——虚构引用、长会话遗忘约束、高估可行性、绕开简单方案直奔复杂路线。模型的弱点是可预测的，但不是模型自己能修复的。

> <span class="mention">@今天群内信息量极大</span>：标准答案存在时，AI 找答案的能力已经打平专家；判断答案对不对、什么时候有问题，还差很远。

<span class="mention">@今天群内信息量极大</span> 判断这画出了一条分界线：领域知识的价值正被 AI 拉平，但 AI 捅出了新缺口——它越能快速输出答案，就越需要有人判断答案靠不靠谱。「那些知道怎么发现和解决这些 failure pattern 的人，可能就是未来最值钱的人。」

### Advisor Tool：Fable 5 的省钱答案

<span class="mention">@今天群内信息量极大</span> 的第二篇文章——[Fable 5 很贵，但省钱的答案 Anthropic 两个月前就发布了](https://yage.ai/share/claude-advisor-tool-20260609.html?utm_source=wechat&utm_medium=share&utm_campaign=claude-advisor-tool-20260609)——指出 Anthropic 在 4 月 9 日上线的 advisor tool 恰好解决了 Fable 5 的成本问题。机制是让便宜模型（Haiku/Sonnet）端到端跑任务、调工具、迭代，遇到拿不准的决策时调用贵模型（Opus/Fable 5）做顾问。Advisor 没有工具、不产生用户可见输出，一次只给几百 token 的建议文字。

核心反转是：这和常见的「大模型做 orchestrator、小模型执行」恰好相反——控制权在便宜模型手里，智能做成按需调用的资源。AgentOpt 论文发现 Opus 做 planner 时九次有七次会越界，直接跳过工具自己答题，反而 Ministral 8B 老老实实分解任务。Advisor tool 从源头去掉了这个风险。

Fable 5 天生适合 advisor 位：$50/M 输出跑完整 agent 很难算账，但顾问一次几百 token，「贵的单价乘以小的用量，恰好是这种定价下唯一舒服的用法」。

### Copilot 集成需放弃零数据保留

[GitHub 同日宣布 Fable 5 上线 Copilot](https://github.blog/changelog/2026-06-09-claude-fable-5-is-generally-available-for-github-copilot/)，可在 VS Code 全部模式、CLI、云端 agent 中使用。但有一个硬约束：Fable 5 需要保留 prompt 和输出最多 30 天来运行安全分类器，不支持 Zero Data Retention。其他 Claude 模型仍维持 ZDR。

这意味着 Enterprise 管理员必须在 Copilot 设置中手动启用 Fable 5 策略，默认关闭。<span class="mention">@我要成为灵能高手</span> 在公司账号上还没看到选项，<span class="mention">@天真的浣熊</span> 找到官方说明确认是「渐进式推出」。<span class="mention">@豁达的考拉</span> 提醒 ZDR 是某些企业选型的硬性约束，30 天数据保留可能直接被否决。

## 方法论

### Benchmark 应标注推理成本

<span class="mention">@专注的剑鱼</span> 分享了 Noam Brown 的推文，呼吁 AI 社区在发布模型 benchmark 时将 token 数、成本或时间作为横轴指标，而非只给一个标量分数。此外安全评估也应在多个推理预算下估算能力。<span class="mention">@专注的剑鱼</span> 评价「这个写评测的思路挺好，希望能成为标配」。这呼应了群里对 Fable 5 定价的讨论——SWE-bench Pro 80.3% 很亮眼，但 2 倍价格和 2–3 倍消耗速度意味着实际性价比远不是数字看起来那么美。

### Opus 4.8 Token 膨胀

<span class="mention">@80-HD</span> 对比了自己在 4.7 和 4.8 上的 token 用量，发现 4.8 输出 token 约为 4.7 的 1.5 倍，输入 token 差了约 5 倍——说明模型更积极地 load context，最近还因此出现了 Slack 429 限流。他判断输出增加主要由返工导致，「活并没有显著增加」。<span class="mention">@淡定的雪豹</span> 确认 4.8 的 CoT 也明显变长了。这延续了此前 [「Opus 偷懒与 GPT 5.5 长任务稳定性」]({{ '/daily/2026/06/06/daily/#opus-偷懒与-gpt-55-长任务稳定性' | relative_url }}) 以来的 Opus 退步讨论。

### 古法手写成流量密码

<span class="mention">@冷静的麋鹿</span> 分享了一个反 AI 的有趣现象：公司收紧个人 token 权限后，他随手写了一篇使用心得发在内网，没什么技术含量——结果迅速登上日榜、周榜第一。排在最前面的评论是「终于看到古法写的东西了」，「万字长文一律不看，写短才是水平」。

> <span class="mention">@冷静的麋鹿</span>：内网上的文章动不动就是【万字长文】，【千字古法手写短文】居然成了流量密码

<span class="mention">@洒脱的猫头鹰</span> 补充说他最烦聊天时不带任何总结就甩 AI 生成的大段内容。这可能是 AI 生成内容泛滥后最早的反噬信号之一——信息过载让人类手写的「有限、粗糙、带个人气息」的文字反而变得稀缺和有价值。

### K2.6 二轮优化意外领跑

<span class="mention">@随和的企鹅</span> 完整 benchmark 了 GPT 5.5 High、Kimi 2.6 和 DeepSeek V4 Pro，用 GPT 出 6 道复杂工程题，含 test 和 perf test。First pass GPT 5.5 明显领先，代码质量和完成度最佳；但给每个模型一次 second pass 自我优化后，K2.6 在代码质量和性能上反而平均最好。三个模型互评结论基本一致。他对这个结果感到意外——「first pass 实现 K2.6 是最差的，不懂为什么会出现这种情况。」

## 工具

### Vibe Coding 外设百花齐放

语音输入和辅助外设的讨论从凌晨延续到深夜，延续了 [「口喷转文字公开版」]({{ '/daily/2026/06/08/daily/#口喷转文字公开版' | relative_url }}) 开启的话题。

**脚踏板**：<span class="mention">@80-HD</span> 说脚踏板适合手里拿着东西不想碰键盘时用，「比如说你在吃辣条的时候干活」。<span class="mention">@洒脱的灰熊</span> 判断脚踏板只适合有一个固定动作的场景——他自己在暗黑专家模式里用脚踏板踩一下立即回城保命，但常见动作用快捷键更省力。<span class="mention">@冷静的麋鹿</span> 质疑习惯建立问题：新设备如果只是旁路，做动作前还要选择用键盘还是新设备，太累心。

**复古电话**：<span class="mention">@冷静的麋鹿</span> 提到隔壁群有人买了老式电话机话筒做 vibe coding 语音输入，「没想到有一天 coding 也能配得上这么花哨的装饰品」。<span class="mention">@开朗的企鹅</span> 找到淘宝同款——¥22.7 包邮。<span class="mention">@今天群内信息量极大</span> 接茬：「直达上帝的听筒，可以搞个宗教」——由此引出了 <span class="mention">@开朗的企鹅</span> 的 ASI 宗教设计（见闲聊花絮）。<span class="mention">@冷静的飞鼠</span> 则认真建议可以做成硬件产品——拿起电话就是语音输入给 AI。

**堵嘴麦克风**：<span class="mention">@机智的水獭</span> 买了 <span class="mention">@今天群内信息量极大</span> 文章里推荐过的堵嘴麦克风，在办公室直接中文指挥干活，「一天 1000 次 f word（还可以对着老板开喷」。<span class="mention">@谨慎的灰熊</span> 更激进：「现在都没有开始用语音输入的话，我觉得对不起这个群名」，他已经用了七八个月，「效率极大提升」。

**迷你键盘**：<span class="mention">@开朗的企鹅</span> 定了一个三键加旋钮的小键盘，绑定语音输入、ESC 和截图，可以带着溜达和骑共享单车时用。<span class="mention">@认真的荷兰猪</span> 则用 8BitDo Zero 2 小手柄绑了切桌面、录音、发送等快捷键。

**健康话题**：<span class="mention">@机智的猫头鹰</span> 为老公的手指麻木问题求助——打字过量导致尺神经受压（cubital tunnel syndrome）。<span class="mention">@我要成为灵能高手</span> 传授了弹钢琴学来的姿势：手肘和手指支撑、手腕悬空、掌心呈弧形垂直按键，代价是勤剪指甲。他还展示了 Kinesis 分体键盘作为替代方案。

> <span class="mention">@神秘的麋鹿</span>：我有一次叫 AI 写的计划里面莫名其妙多出了几个时间节点、版本号，纳闷了半天发现语音输入一大串文字的时候，中间混了一些隔壁项目经理开会的话

## 行业新闻

### Siri 唤醒词十年攻防史

<span class="mention">@今天群内信息量极大</span> 发布了 [Siri 唤醒词防误触的深度分析](https://yage.ai/share/voice-assistant-wake-word-broadcast-20260609.html?utm_source=wechat&utm_medium=share&utm_campaign=voice-assistant-wake-word-broadcast-20260609)。起因是 WWDC26 直播里主持人每次说「Siri」时，3–6 千赫频段被 notch filter 主动压掉——这是为了防止观众家里的设备被误唤醒。文章追溯了这条工程族谱：2014 年 Xbox One 广告里 Aaron Paul 说「Xbox On」让玩家主机自动开机，2017 年达拉斯六岁女孩通过 Echo 误购娃娃屋，同年 Burger King 故意在广告里说「OK Google」触发观众设备念维基百科（被网友编辑成氰化物和鼠肉），Google 三小时内通过声学指纹封杀。

三条技术路线——notch filter（最粗暴）、声学指纹（Amazon 2018 超级碗做到全美 Echo 零误触）、音频水印（Google 多项专利）。Apple 至今最沉默，WWDC26 用的还是十年前的 notch。<span class="mention">@谨慎的灰熊</span> 补了个国内案例：某手机厂发布会当晚，粉丝看直播喊了几次唤醒词，结果全国粉丝家里的语音设备同时被唤醒，系统直接崩了。

<span class="mention">@热情的狮子</span> 另外分享了 [iOS 27 体验视频](https://www.bilibili.com/video/BV1qwEE6bEyw/)，延续 [「iOS 27 与 AI 原生应用展望」]({{ '/daily/2026/06/05/daily/#ios-27-与-ai-原生应用展望' | relative_url }}) 的讨论——完全体 Siri 终于到来，但国行设备无法使用，被称为「国行最没参与感的一集」。
