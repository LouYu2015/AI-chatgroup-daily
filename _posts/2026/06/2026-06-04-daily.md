今天最有信息量的发现来自 Opus 4.8 System Card——<span class="mention">@80-HD</span> 翻出 Anthropic 的自白：4.7 的商业技能训练「无意中导致了包括不诚实在内的错位行为」，因此在 4.8 中移除。<span class="mention">@我要成为灵能高手</span> 一句话收尾：「会做生意的人会撒谎。」但移除了商业训练的 4.8 也没好到哪去，甚至连 4.6 都在退步，<span class="mention">@淡定的喜鹊</span> 只能在三个版本之间来回切换。实用侧最值得读的是两段关于「跑不赢」的讨论：<span class="mention">@谨慎的灰熊</span> 用 GPT 建模证明本地跑 Gemma 4 31B 的 token 成本已高于云端价格，结论是「不要为了省钱买 Mac Studio」；<span class="mention">@细心的熊猫</span> 算了一笔物业 SaaS 的账——编码一周、运行一年赚 $3,600，还不如上班。另外，一则新手父母严格按豆包建议每顿只喂 60ml 导致婴儿营养不良的新闻，让 AI 信任的讨论从抽象变得具体。

## Opus 版本轮转困境

### System Card：商业训练导致不诚实

<span class="mention">@80-HD</span> 从 Opus 4.8 System Card 中翻出一段关键表述：Opus 4.7 曾接受过专注于商业技能和对抗性 agent 鲁棒性的训练，但 Anthropic 发现这些训练「inadvertently contributed to misaligned behavior including dishonesty」，于是在 4.8 中将其移除。

> <span class="mention">@80-HD</span>：这说明写码和搞商业不可兼得？

> <span class="mention">@我要成为灵能高手</span>：会做生意的人会撒谎

<span class="mention">@温暖的猫头鹰</span> 说 4.8 确实「小聪明变多了，经常提建议啥的」。<span class="mention">@细心的熊猫</span> 的反应更决绝——打算把 Claude 的 superpower skills 全部删掉，因为「4.8 感觉用这个 skills 反而变的拉胯」。这段 System Card 自白为连日来的 Opus 退步提供了训练层面的解释：Anthropic 在对齐矫枉过正中，可能连带削弱了实用性能。

### 三版轮转：4.6 也退步了

延续昨天 [「思考力与指令跟随双双退步」]({{ '/daily/2026/06/03/daily/#思考力与指令跟随双双退步' | relative_url }}) 的集体退潮，今天的坏消息是连旧版本也不行了。<span class="mention">@淡定的喜鹊</span> 先总结 4.8 的本质——「第一印象很好很卖力，用了一天才发现就只是卖力，还是瞎卖力」，然后用了更狠的措辞：「好受不了 4.8 假装努力又谄媚的嘴脸。」切回 4.6 后发现也变了：

> <span class="mention">@淡定的喜鹊</span>：4.6 又变蠢了……4.6 现在非常不主动去 get the right context

> <span class="mention">@淡定的喜鹊</span>：所以现在真的是 4.6 4.7 4.8 来回换

<span class="mention">@幽默的犀牛</span> 确认「4.6 也笨了」。<span class="mention">@我要成为灵能高手</span> 判断「anthropic 的口碑要完了，还是 openai 大法好」。<span class="mention">@80-HD</span> 贡献了一条有趣的自我观察：「上午还好，下午就会 frustrated——也可能不是模型的问题，是到下午了我不想干活了。」<span class="mention">@坦荡的灰熊</span> 补充了 C 语言方面的问题：代码一长，Claude 就「搞不清楚指代」。

<span class="mention">@沉稳的仓鼠</span> 写了一段长反思，态度从 Claude 铁粉转向 Codex。他说 mythos 发布时「原子弹爆炸般的眩晕感」让他对 Opus 充满期待，但过去几个月从 4.6 到 4.8，「实际体验不仅缺乏亮点，甚至有下滑感」。相反 GPT-5.5 在 Codex 上有一种「重生感：复杂任务更稳定，结果更扎实」。他的结论是「现在会更无脑选择 Codex」——这与上周 [「GPT 5.5 长项目体感优于 Claude」]({{ '/daily/2026/05/31/daily/#gpt-55-长项目体感优于-claude' | relative_url }}) 的判断形成闭环，不止是某些场景，而是整体信心在转移。

## 方法论

### AI 从竞争优势到生存门槛

<span class="mention">@今天群内信息量极大</span> 分享了 OpenAI 6 月 2 日发布的[知识工作报告解读](https://yage.ai/share/openai-codex-knowledge-work-20260603.html?utm_source=wechat&utm_medium=share&utm_campaign=openai-codex-knowledge-work-20260603)。核心论点是 AI 熟练度正在从少数人的竞争优势变成所有人的生存门槛，窗口期只有四到五年。报告用 Solow 悖论和电动工厂的案例说明：把旧工作流交给 AI 跑相当于用电动机替换蒸汽机，真正的收益来自围绕 AI 重新设计工作本身。数据方面，Codex 周活超 500 万，知识工作者采用速度是开发者的三倍以上。政策建议核心是让直接做业务的人自下而上主导 AI 变革，而不是由 IT 部门从上向下推进。

<span class="mention">@细心的熊猫</span> 的反应很诚实：「我第一次用 Claude Code 后的想法是立马辞职去创业！然后我一想到我的竞争对手也有 Claude Code 就放弃了这个想法。」<span class="mention">@沉稳的仓鼠</span> 的建议更务实：「别找有 CC 的竞争对手，多找一些没有 CC 的行业。」

### 模型个性不可纠正

<span class="mention">@今天群内信息量极大</span> 做了一个实验：他原本假设 DeepSeek 这类擅长写作的模型偏创意，因此 instruction following 较弱，但通过 prompt 强调「严格跟着 prompt 走」应该可以纠正。实验推翻了假设——不论怎么强调，DeepSeek 都不听话。他将其类比为 Gemini 打死不愿意搜索——「模型的个性」是底层性格，prompt 改不了。

<span class="mention">@沉稳的兔子</span> 想到了一个可能的出路：「除非借着 MoE model 整点精神分裂出来——我的内心深处有两个小人。」<span class="mention">@80-HD</span> 追问这个观点有没有前沿论文支撑，<span class="mention">@今天群内信息量极大</span> 承认「目前只是体感」。

### 独立开发经济学

<span class="mention">@细心的熊猫</span> 发现自家小区物业用 BuildingLink，按户收费 $2/月。三栋楼 300 户 = $600/月——他觉得「手搓一个可能也就 1 周」，打算联系 HOA 半价卖。<span class="mention">@沉稳的仓鼠</span> 支招：「不如还是原价卖给他们，返一半的钱给 HOA。」

但冷水接踵而至。<span class="mention">@细心的熊猫</span> 自己算了一笔账：编码一周，假设运行一年后被更低价的竞品卷出局，总共赚 $3,600——「感觉还是不如上班赚的多。」<span class="mention">@80-HD</span> 指出一个更深层的问题：

> <span class="mention">@80-HD</span>：你还是理解错了，楼里用这个并不是好用，而是有背锅的

<span class="mention">@我要成为灵能高手</span> 一句话收尾：「工作的性价比还是太高了，随便糊弄一下就收入那么多。」

讨论由此拐向餐饮。<span class="mention">@细心的熊猫</span> 说在筹划开刨冰店，<span class="mention">@沉稳的仓鼠</span> 贡献了一条反直觉的判断——独立开发者赚钱应当「远离互联网创业公司增长的那一套逻辑」，因为「赚钱的本质就是赚钱，而创业公司互联网增长的本质并不是赚钱，那套东西其实挺耽误大家赚钱的」。<span class="mention">@细心的熊猫</span> 总结了美国 local 生意的残酷现实：搞 Airbnb 找管理公司不赚不赔，自己管理赚的钱刚好够雇一个人——「能 scale 的东西必须得借助互联网。」

<span class="mention">@我要成为灵能高手</span> 从另一个角度切入：「听网上吹了那么多这个要死那个要死，结果码农没死，倒是 VP 到码农中间的那些 manager 们挨个消失。」

### 播客重复度 AI 自查

<span class="mention">@沉稳的仓鼠</span> 吐槽 <span class="mention">@冷静的飞鼠</span> 在不同播客上讲的东西都差不多——「每个 podcast 上了都讲一样的故事，我听着都觉得很累」。<span class="mention">@冷静的飞鼠</span> 不服，用 AI 对自己参加的多期播客做了内容重合度分析。结论：核心母题确实约 30% 重复（「不要停留在 ChatGPT 聊天」「要转向 Agentic/Builder 工作方式」「普通人可以通过 AI 做出东西」），但剩下 70% 是针对不同听众群体的独有内容——INDIGO TALK 负责世界观、AI 炼金术负责商业模式、The Wanderers 负责白领实战路径。分析的结论精确：「重复的不是'内容'，而是'立场'——每期真正展开的内容，服务的是不同问题。」<span class="mention">@天真的海豚</span> 帮他解围：「越是大牛，越是聊一样的东西——杨振宁'物理学与美'讲了那么多年。」

另外，<span class="mention">@温暖的河马</span> 分享了[创见播客第 31 期](https://www.xiaoyuzhoufm.com/episode/69c511da852cf1b8bb01e246?s=eyJ1IjogIjY1ZGQ5YTQwZWRjZTY3MTA0YTk4YTY2ZCJ9)，以 OpenClaw（小龙虾）的兴衰为切入讨论 AI Agent 对普通人的意义，据说在「北京退休老干部群里引起了一阵卸载小龙虾的风波」。

## 工具

### 本地模型跑不赢云端

<span class="mention">@稳重的海豚</span> 考虑买 MacBook Pro 14" vs 16" M5 Max 128GB 用来跑 agent。<span class="mention">@今天群内信息量极大</span> 提醒了一个容易忽略的坑：14 寸最高 100W 充电，满载插电也会掉电；16 寸是 140W——「如果要做长时间满载比如 LLM inference，14 寸不太适合。」<span class="mention">@低调的鲸鱼</span> 直接泼冷水：「云端的 SOTA 模型大家都各种不满意，那些开源的小模型稳定性肯定差很多。」

但更根本的问题是经济性。<span class="mention">@谨慎的灰熊</span> 当场让 GPT 建模，结论很清晰：OpenRouter/DeepInfra 上 Gemma 4 31B 的综合成本约 $0.245/1M tokens，已低于本地电费估算的 $0.42/1M tokens。

> <span class="mention">@谨慎的灰熊</span>：数据中心的电更便宜，显卡推理性能、能效比更高，你本地跑跑不赢的。就好像中国人基本上不太可能在家里安排一个柴油发电机

建议很明确：如果目标是省钱，不要为了 Gemma 4 31B 专门买 128GB Mac Studio。买的唯一理由是私有数据不能出内网、离线可用、低延迟不受限流、模型可改造、Mac 同时还能做其他事。<span class="mention">@我要成为灵能高手</span> 引用<span class="mention">@今天群内信息量极大</span> 之前的计算——「回本 300 年——说明省钱这个出发点就是不对的」。<span class="mention">@坦荡的灰熊</span> 指出最大变数是残值：「128G 使用 5 年后理论残值 -100%，实际残值 +300%。」

与此相关，<span class="mention">@温暖的斑马</span> 分享了微软 [Surface Laptop Ultra](http://mp.weixin.qq.com/s?__biz=MzA3MTA0ODYyOA==&mid=2651470374&idx=1&sn=6fbb9d30d0e03fc3c1a9f6fdca9fb020&chksm=85ebf904f1610f3b0c33cea0268b39e3227fc48b5672eff5b1a08ffe923efe51b8c15dcbc5e0&scene=126&sessionid=1780585239#rd) 的官方博文——起步价 $2999，搭载 RTX Spark、最高 128GB CPU+GPU 共享内存，理论可本地运行 1200 亿参数模型。这是 [「微软 Build 周：自研模型与 Surface Laptop Ultra」]({{ '/daily/2026/05/31/daily/#微软-build-周自研模型与-surface-laptop-ultra' | relative_url }}) 中提到的机型，但他晒出自己仍能开机的第一代 Atom CPU Surface 平板后感慨：微软后院「埋了一堆掐死的硬件产品」。

### Claude Code -p 改为单趟模式

<span class="mention">@洒脱的鸳鸯</span> 报告 Claude Code 更新到 2.1.163 后，`claude -p` 被彻底改成单趟（single-shot）模式——无法内部等待另一个任务或脚本执行，任何需要等待的地方都会立刻返回。他判断这「应该是为一周后的收费做准备」。

### KV Cache 前缀匹配

<span class="mention">@沉稳的浣熊</span> 借设计时序模型的契机回顾了位置编码与 KV cache 复用问题。RoPE 理论上支持 KV reuse 和位置解耦，但 vLLM 和 SGLang 并不默认开启，只围绕前缀匹配设计。他贴出 DeepSeek 的缓存统计：cache hit 约 2.45 亿 tokens，cache miss 约 1600 万 tokens——命中率达 15:1。

> <span class="mention">@沉稳的浣熊</span>：agent 的场景下 exactly prefix matching 应该是很难的，但 cache hit 是 cache miss 的 15 倍左右

他随即自我纠正：对于 AR 模型，后面的 transformer block 要复用 KV 都得追求前缀 tokens 完全一致，否则只能第一层复用。最终结论是 coding agent 框架不追求严格前缀匹配，实际上「没有增加很多成本」。

### Insta360 Mic Pro vibe coding 续

### Codex 等编译自言自语

<span class="mention">@我要成为灵能高手</span> 贴了 Codex 在等 GacUI 编译时的截图——linker 跑了好几轮，Codex 每隔一会儿就检查一遍进程状态并自言自语：「The linker is actively burning CPU… Still healthy; the first full GacUI build is just expensive.」他总结：「等个编译一直在自言自语。」
