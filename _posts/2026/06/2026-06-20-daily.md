今天最值得细读的是 <span class="mention">@今天群内信息量极大</span> 的长文[《使用AI十倍提效，成了模范老黄牛，就能加薪升职了？》](https://yage.ai/ai-productivity-trap.html)——他用自己的真实经历论证了一个反直觉的陷阱：AI 用得越好、交付越快，反而把自己从「脑」变成了「手」，升职连续两次被毙。核心洞察是奖赏系统是人设计出来的，IC 也可以主动设计自己给别人的奖赏系统。由此延伸出的古法编码回归、Terminal Level 躺平经济学等话题占据了全天大半讨论量。硬件方面，<span class="mention">@细心的熊猫</span> 用三张 $300 的 RTX 5060 Ti 跑 Qwen 3.6 27B，Q6 量化 256K context、输出 35 token/s，用 Hermes Agent 做浏览器自动化「太丝滑了」，让群友重新审视 N 卡本地推理的性价比。微信 AI Agent「小微」内测上线，一句话生成小程序的能力是最大亮点。

## 执行力贬值与奖赏系统

### 十倍提效反成模范老黄牛

<span class="mention">@今天群内信息量极大</span> 发布了[《使用AI十倍提效，成了模范老黄牛，就能加薪升职了？》](https://yage.ai/ai-productivity-trap.html)，用自己在中厂的真实经历讲述了一个结构性陷阱。他 AI 提效成果显著——基本不手写代码，产出和 rating 长期是全 org 最高之一，VP 评价「以超人速度交付」，还因此获得了与 CEO/CPO/CTO 每两周定期 meeting 的机会。但升职连续两次失败，复盘后发现根因极具讽刺性：正因为太好用，他在高管眼中从「脑」变成了「手」——有什么不确定的想法直接让他试一把比开会还快，失败了也无所谓。这种高速交付反而激发了老板微操的欲望，导致项目零散方向多变，到升职时讲不清一年做了什么成体系的事。

文章提出的破局思路是：停止响应现有奖赏系统，改为主动设计你给别人的奖赏系统——控制交付的摩擦，不值得做的主动 pushback。他同时发布了另一篇[《当执行力开始贬值》](https://yage.ai/share/ai-productivity-depreciating-asset-20260619.html)，论证 AI 是定向杠杆——放大执行不放大判断；最会用 AI 的人押在执行上的筹码最多，替代说明书也写得最厚。两篇文章构成完整叙事。

讨论迅速炸开。<span class="mention">@稳重的海豚</span> 说自己也曾在老板那里做「最锋利的剑」——「归根结底你就是个 sword」。<span class="mention">@沉稳的仓鼠</span> 切入更结构性的视角：「升职是 ownership / empire building 的路径，不太是 skill 提升的路径」。<span class="mention">@80-HD</span> 从另一个角度反驳：「其实是你老板支持力度不够」——「你第一次直接摊开说不升就走人，ta 就会重视你」。<span class="mention">@今天群内信息量极大</span> 澄清文章 focus 不是给升职本身找归因——他的关系也找了，升职 sponsor 是 CPO，但被另一个 C level kill 了。文章着眼的是一个更被动的因素：一个法师战士双修的人，为了套利爆血变成狂战士，反而对 career ladder 不利。

> <span class="mention">@冷静的飞鼠</span>：不要把自己定位成好用的牛马。如果自己的标签是好用的牛马，那别人就只会用好用的牛马去看待你。最后如果升职成功反而更危险了，因为这个升职是奖励了牛马 path，升职没成功反而是个好事

> <span class="mention">@直率的海豚</span>：不是你努力、牛逼或者做了 impact 大的项目就一定 promote。promote 得看这个 case 做成了，对你老板本身有没有好处

<span class="mention">@风趣的海豚</span> 分享了自己 pua 老板的尝试：「你可以朝着一个方向走，走慢点都行，但是你不能因为自己跑得快就东十公里西十公里，那最后就是原地不动，还浪费了资源。」他认为这篇文章最好的地方在于把所有困境归纳到了「奖励系统陷阱」的框架下——等级、工资数量都属于外加的判断标准。<span class="mention">@80-HD</span> 读完后有了更个人化的反思：也许是自己「自以为是的判断力过早地结束一个可能不错的想法」，所以让 AI 做一下来纠正自己的判断力也是一个提高的方法。

### 古法编码保持判断力

早在文章发布前，<span class="mention">@稳重的海豚</span> 就坦言「脑子不太转了——给 AI 搞的东西太多，自己沉淀下来的知识和能力不够多」。<span class="mention">@今天群内信息量极大</span> 回应自己也踩过这个坑：「用 AI 写的不够爽，还在古法写。」<span class="mention">@幽默的犀牛</span> 分享了相同感悟：最近回去古法写代码，虽然比较慢，但「记忆力和思考能力有显著提升」。<span class="mention">@冷静的白鹭</span> 给出了简洁的分工方案：「AI 干需求，古法提升自己。AI 节约出来的时间，可以更多的提升自己。」这延续了 [「AI 时代的知识内化困境」]({{ '/daily/2026/06/18/daily/#ai-时代的知识内化困境' | relative_url }}) 以来对 AI 削弱学习效果的讨论。

但现实的一面是，<span class="mention">@细心的熊猫</span> 指出古法在职场中已经不可行——「同事被裁了，上班的活儿已经 10x 了，还古法就要被老板骂了」。<span class="mention">@稳重的海豚</span> 最终将古法定位为「用来熟悉一下，保持手感和思路，工作没必要拿古法来做」。<span class="mention">@务实的考拉</span> 的做法更精确：古法主要用在更细节的 system design 上——「项目一大没法 macro manage 了，不然效率更低。」设计好了再放权去执行。

### Terminal Level 与大厂躺平经济学

讨论延伸到了职场结构层面。<span class="mention">@我要成为灵能高手</span> 分享了自己的路径：刚毕业时「PM 让我干什么我风卷残云马上弄出来」，被第一任老板批评，从此学会向上管理。后来了解了公司 career development 体系，发现 promote 也不怎么给钱，就「全面转向躺平，省出来的时间拿来干自己的业务项目」。

> <span class="mention">@我要成为灵能高手</span>：前期 promotion 的动力就是让自己进去一个"隐形的"terminal level，总不能因为一辈子都是 sde1/2 然后被优化掉。Senior SDE 正好就是又可以一直做下去，又不需要做太多太重要的事情，永远处于一种天塌下来有高个子顶住的状态

<span class="mention">@沉稳的松鼠</span> 解释了 terminal level 背后的公司逻辑：当一个人 senior 到一定程度，公司假设他们能自己找到有意义的事，放着不管也能做出有意义的工作——<span class="mention">@沉稳的仓鼠</span> 精炼为「一个 ROI 为正的 autopilot 的牛马」。<span class="mention">@敏锐的穿山甲</span> 一眼看穿：「这不就是大学里评教授的非升即走那一套吗。」

<span class="mention">@我要成为灵能高手</span> 补充微软的收入突变发生在 principal 最后一级，筛选上去的「都是一些发自内心一定要爬梯的人」，「拿的钱和做事的激烈程度开始和湾区高 P 码农看齐」。他还分享了当下的躺平心得：IC 性价比太高了，「随便糊弄一下就有钱」，能拿 $1m 的时候只要 0.5，也许每个星期只需要工作一天。<span class="mention">@稳重的海豚</span> 感叹划水投资回报比太高了，同时推荐了 Millionaire Fastlane 这本书给想做生意的人。

## 工具

### Qwen 3.6 27B 三卡本地推理

<span class="mention">@细心的熊猫</span> 展示了自己的本地推理配置：三张 PNY RTX 5060 Ti（每张 $300），总共 48GB 显存，跑 Qwen 3.6 27B 的 Q6 量化，支持 256K context window。输出速度 35 token/s，prefill 很快。他搭配 Hermes Agent 做浏览器自动化，评价 Qwen 的编码能力和指令遵循「非常可以，我觉得比 DeepSeek 强」，让它删 Apple Note 也不会乱删。他还对比了 Claude 的 context 效率——让 Claude 读 6 页 PDF 直接塞满 1M context window，Qwen 用工具读同样的内容只用了 50K context 就完成了。

> <span class="mention">@细心的熊猫</span>：写码属于生产力值得花钱。爱奇艺的事情可以交给 Qwen。有时候 Claude 办事会 overkill

多卡推理的关键优化是 pipeline parallelism：把神经网络的不同层放进不同卡里，推理速度接近单卡速度，不太受 PCIe 通道制约。<span class="mention">@今天群内信息量极大</span> 踩过一个坑：vLLM 不支持 3 卡部署单模型实例，只能 1/2/4 卡——<span class="mention">@细心的熊猫</span> 建议改用 llama.cpp。量化方面 Q8 甚至 Q4 「几乎无损」。新的 nvfp4 格式暂时跟多卡优化不兼容，「不然可以更快」。<span class="mention">@天真的浣熊</span> 问 5060 是否支持 nvfp4，<span class="mention">@细心的熊猫</span> 确认 Blackwell 系列都行。

<span class="mention">@直率的鸵鸟</span> 对比了自己 Mac AI Max 395 的体验：开 MTP 输出只有 20 token/s，prefill 200 多，「基本不可用」，正在考虑出掉换普通主机。<span class="mention">@豁达的北极熊</span> 分享了另一个发现：opencode + DeepSeek V4 Flash 比 Antigravity 的 Gemini 3.5 Flash 好用——「Antigravity 动不动就跳起来去写 code 了真的好烦，我大多数时间只是想讨论，理解为什么」。

### GLM Coding Plan vs Ollama Cloud

<span class="mention">@今天群内信息量极大</span> 发现 GLM Coding Plan「慢得跟屎一样」，以为 GLM 5.2 就是这德行，后来切成 Ollama Cloud 的 GLM 5.2 后「健步如飞，惊呆了」。Ollama Cloud 采用类似 Claude Code 的订阅制，目前 $20/月的 plan 用着还可以，往上有 $100/月的 plan。GLM 5.2 是 MIT License，Ollama 主要的附加价值是 zero data retention，隐私更放心。这延续了 [「GLM-5.2 评价与 Z-Code 获客」]({{ '/daily/2026/06/17/daily/#glm-52-评价与-z-code-获客' | relative_url }}) 以来的 GLM 讨论。

### GLM 无多模态写前端翻车

<span class="mention">@风趣的海豚</span> 让 GLM 做一个和弦练习工具，写出来的前端音符位置错乱、布局混乱。更离谱的是 GLM 分析了一波代码后坚持说「我检查了代码，没有任何区别」。同样的需求交给 GPT，因为有多模态能看到渲染结果，写出来的界面正常得多——对比截图中音符和钢琴键盘的排列差异一目了然。

> <span class="mention">@开朗的企鹅</span>：没有多模态，前端就问题非常大。哪怕不能生图，一定要有识图的能力

<span class="mention">@风趣的海豚</span> 尝试让 GLM 调用带多模态的子代理（如 Kimi），但衔接出了问题——调用子代理时上下文不连贯。他总结：以前做的程序界面有小问题觉得能跑就行，但音符显示好不好看直接影响练琴心情，「才意识到有没有原生多模态还是有挺大问题的」。<span class="mention">@务实的灰熊</span> 附议：「没多模态写前端就是写不好，或者说没法按照你要求的样子写前端。」

### Superlinear 对 AI 爬虫不可见

<span class="mention">@洒脱的大象</span> 反馈了一个影响内容传播的技术问题：Superlinear Academy 上的公开帖子浏览器能正常看，但 AI 抓取工具（Claude Code 的 WebFetch、r.jina.ai）读到的是空壳——只有标题没正文。原因是 Circle 平台纯前端渲染没有 SSR，加上 Cloudflare 挡机房 IP。这意味着想用 ChatGPT/Claude/Perplexity 总结、收藏这些公开文章的读者会失败。

<span class="mention">@今天群内信息量极大</span> 解释这超出他们的控制范围——需要在 Cloudflare 层面解除对 bot 的屏蔽，他们管不了。<span class="mention">@飘逸的浣熊</span> 贡献了[一套纯 Python 方案](https://github.com/LouYu2015/ai-wechat-newsletter/blob/fd70c126258234cde1eb7151f00c8682143bf87a/wechat_daily/url_enricher.py#L473-L476)：通过 Circle 内部 API 拿到 space_id，再请求帖子 JSON 按 tiptap → plain_text → HTML 优先级提取正文，绕过前端渲染限制。<span class="mention">@洒脱的大象</span> 的临时解法是让 agent 记住都用本机 CDP 驱动的浏览器读 Superlinear 的文章。
