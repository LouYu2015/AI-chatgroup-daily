## 方法论

### Token 资产化率与迭代闭环

<span class="mention">@冷静的麋鹿</span> 发布了[「最危险的不是不用 AI，而是只会用 AI」](https://challenwang.com/essays/only-using-ai-is-the-real-risk-20260620.html)，起因是 <span class="mention">@冷静的飞鼠</span> 前两天在社区发的数据处理文章（[「百万条数据的任务光谱」]({{ '/daily/2026/06/19/daily/#百万条数据的任务光谱' | relative_url }})）中关于迭代闭环的讨论。文章的核心区分是两种 AI 使用状态：「交付状态」——用 AI 更快地完成旧任务，做完就散了；和「迭代闭环」——用 AI 构建能自我进化的小系统，每次 token 消耗都留下可复用的规则、判断样本和反馈机制。他在群里补充了一个直观的对比：

> <span class="mention">@冷静的麋鹿</span>：有的人用AI，是纯粹在燃烧token，烧完就完了，没让自己更聪明，也没让公司更聪明。而有的人，可能熟练度不如前者，但却把AI提效当成一个学习小系统去打造，燃烧了token，沉淀了资产

企业层面，他提出「token 资产化率」作为衡量指标——很多公司 token 消耗涨上去了但组织收益没同步增长，本质是大量 token 花在一次性交付上，用完即过，没转化成可复用的规则或反馈机制。文章还澄清了与 Loop Engineering 的区别：Loop 解决的是让 agent 在单个任务里自动循环，迭代闭环关注的是让一个工作单元形成可学习、可积累的长期进化结构——评价函数、记忆结构、权责边界才是核心。

<span class="mention">@认真的灰熊</span> 补充了一个重要限定：对 badcase 的归因及规则优化大多需要 human in the loop，「并不是所有任务都能无限逼近全自动」。<span class="mention">@冷静的麋鹿</span> 完全同意，指出下一轮的改善往往正是由这一轮的 badcase 驱动的。<span class="mention">@冷静的飞鼠</span> 将文章收入 [Superlinear 的 knowledge bank](https://www.superlinear.academy/c/ai-resources/ai-ai-611e79)，并精炼了一句：「任务的闭环是工作的开始而不是结束。」

### AI 代码退化与 Review 纪律

<span class="mention">@我要成为灵能高手</span> 发了一段长文系统阐述当前 SOTA 模型写代码的结构性问题。核心观察是 AI 代码在首个版本通常看起来合理，但随着早期 interface 的快速演化，几天之内就会出现「继承了之后互相 friend 然后把两个 class 绕在一起」这类畸形结构。这不是某次写差了，而是累积退化——前期地基没把控，后面越改越乱，最终表现为「AI 降智了，怎么一点事来回折腾都做不好」。

他的应对方法是 unit test 先行，但 unit test 在这里的角色不是验证——它是 spec 本身，spec.md 反而是用来解释测试的。先通过写 unit test 判断 interface 设计是否合理（如果测试写得特别扭曲说明 API 设计有问题），确认之后再跟 AI 做覆盖。

更深层的发现是 AI 的「最小能量路径」倾向：

> <span class="mention">@我要成为灵能高手</span>：当你的 expectation 和代码的现状冲突的时候，AI 会倾向于重复已有的构造。光说你想要什么，AI 不会听的

必须三步走才有效：① 明确告诉 AI「这部分代码都是傻逼」（必要），② 别抄（次要），③ 改掉它们（次要）。<span class="mention">@飘逸的浣熊</span> 将这个现象归因于训练数据分布——「AI 觉得自己需要模仿 context window 内出现的代码风格」，加上互联网上大部分代码质量本身不高。<span class="mention">@我要成为灵能高手</span> 冷峻地预言：「马上就是 AI 吃自己拉的屎，内循环。」<span class="mention">@沉稳的兔子</span> 给出实操经验：重构时先让 AI 把代码砍了再重写，效果好于在原有结构上修补。

### 升职的应然与实然

延续昨天 [「十倍提效反成模范老黄牛」]({{ '/daily/2026/06/20/daily/#十倍提效反成模范老黄牛' | relative_url }}) 的讨论，今天的新增视角集中在拆解「干得好→升职」这个默认假设。<span class="mention">@冷静的飞鼠</span> 一刀把问题切成两层——应然是规则设计初衷（把打工人利益和公司 align 起来），实然是「现实复杂一百倍」，包括个体对股价基本没影响、管理层信息和注意力有限、人性等等。他直言：

> <span class="mention">@冷静的飞鼠</span>：如果老板单纯以一个人是否干得好决定这个人是否升职，说明这个老板也没有玩明白大厂打工的游戏。活该干不过印度人

<span class="mention">@神秘的麋鹿</span> 从自己公司的观察补充了中间环节：干得好只是第一步，真正的路径是「老板注意到你的才能→老板需要你去干一个事→为了把你放到那个位置给你相应的地位」。<span class="mention">@睿智的飞鼠</span> 加了更现实的一层：关键岗位看的不只是能力，更重要的是服从性——「遇到大事他可以确定你会坚定选择听他的，而不是听其他派系的安排」。<span class="mention">@80-HD</span> 从反面印证：「干不好也没事，大公司里面找到 tribe 融进去就行了。」<span class="mention">@认真的灰熊</span> 给出进攻路线：自己吹出一个 vision 让老板 buy in，位置自然就到手了。

<span class="mention">@稳重的海豚</span> 引用 NHK72 日本普通人生活纪录片提供了另一重视角：很多人在 survival mode 下非常努力，但没有余力思考如何「摆脱泰坦尼克」——「只能期望在船沉之前多拿点东西」。<span class="mention">@冷静的飞鼠</span> 最后分享了自己在 Superlinear 上的[「真正值钱的建议」](https://www.superlinear.academy/c/notes/advice)一文，核心判断是最稀缺的建议不是教你怎么下棋，而是提醒你应该选哪个棋盘——「不问凭什么，不问应什么」。

### UBI 与加速主义三条路线

<span class="mention">@神秘的企鹅</span> 抛出了一个根本性的问题：「如果 AI + 具身智能大发展，生产力大提高，UBI 是有可能的吗，还是大资本家根本不关心普通人的死活？」讨论迅速分化。

<span class="mention">@优雅的荷兰猪</span> 从需求侧论证 UBI 的可行性——AI 本身不能创造需求，如果大部分人穷困潦倒，AI 生产的东西给谁？<span class="mention">@神秘的企鹅</span> 反驳：当一个实体控制所有生产资料时，「需求供给这套理论已经失效了，银行、货币、印钞厂都是自己的，干嘛赚钱」。<span class="mention">@稳重的海豚</span> 贴出刘慈欣《赡养人类》的百科截图——社会 99% 的财富集中在一个人手里，穷人退化到连出卖劳动力的机会都没有。

<span class="mention">@热情的狮子</span> 用 GPT 5.5 Pro 做了系统分析，产出了一张三条路线对比表：AI dividend / 公民股东制（最坏形态：低效官僚 AI）、平台封建主义 / 平台领主制（最坏形态：数字佃农社会）、高自动化威权治理 / 算法官僚制（最坏形态：「舒适版全景监狱」）。他指出核心判断成立——生产力提高只是物理事实，社会会不会变好取决于新增生产力的产权、接口和强制力分别归谁。

<span class="mention">@神秘的企鹅</span> 补充了翟东升的观点：硅谷是「超级右倾加速主义」——多生孩子、长生不老、AI 只服务少数人；中国是「左倾加速主义」——科技普惠高铁新能源车。「未来的斗争是两种加速主义的斗争。」<span class="mention">@冷静的飞鼠</span> 把讨论拉回地面：「从来就没有什么救世主。你不是大资本家，你关心别人死活么？」<span class="mention">@我要成为灵能高手</span> 给出了最暗黑的判断：「只要 AI 的生产力超过了资本家的需求，穷人一图，就走进共产主义了。」

### 医生与 AI 的攻守默契

AI 社交禁区的讨论延伸到医疗场景。<span class="mention">@风趣的海豚</span> 发现医生对 AI 工具有很清晰的品牌判断——「你说你用豆包和元宝医生就会非常反感，你说你用 ChatGPT 的话，年轻医生可能反而会愿意听一下」。<span class="mention">@神秘的企鹅</span> 一针见血：「医生喜欢自己用，不喜欢患者用，因为会增加沟通成本。」

<span class="mention">@神秘的麋鹿</span> 分享了自己腰突就医的策略——让 ChatGPT 从多个科室的论文角度去查，然后跟医生讲的时候「不会直接说是 AI 给出的建议，我会把那个观点讲出来，然后问他怎么看」。他在港大医院时，年轻医生甚至主动说：「其实你问 AI 也行，他说的基本上是对的。」<span class="mention">@开朗的企鹅</span> 精准概括了医生的真正恐惧：「医生害怕的是'我都百度了'。」<span class="mention">@认真的灰熊</span> 秒接类比——这和产品经理过来跟开发经理聊实现细节一模一样。

### GLM「让me」不屈不挠

### Generative AI 与 Retrieval AI

### Life after Fable 5

<span class="mention">@我要成为灵能高手</span> 分享了一张 Wojak 梗图：标题 "life after fable 5"，上方一个枯瘦老人扶着桌沿，下方标注 "OPUS 4.8" 的小矮人流着口水往形状插孔里塞积木。Fable 5 被管制后回到 Opus 4.8 的落差感，一图胜千言。
