## 行业新闻

### Anthropic 40 万条 CC 会话报告

<span class="mention">@开朗的企鹅</span> 分享了 Anthropic 发布的研究报告[《Agentic coding and persistent returns to expertise》](https://mp.weixin.qq.com/s?__biz=MzkyMDAyNjE5Mw==&mid=2247485050&idx=1&sn=6092bd50ed9e8cee8896dbef89e7053b&chksm=c03fb24035f6d7c07df7fec2d59501b2797adae29ff7aca310d8a5344622ecb2487a3e148ece&mpshare=1&scene=1&srcid=0622vt4Q4TD7zabcCIpRMHKu&sharer_shareinfo=9e819ac63628950c6df96767c26ddd61&sharer_shareinfo_first=9e819ac63628950c6df96767c26ddd61#rd)，基于约 40 万条 Claude Code 真实会话、覆盖约 23.5 万名用户。核心发现：管理职业在 verified success（需要 git commit、PR 合并、测试通过等硬证据）上得分最高，超过软件工程师；最大的 10 个职业群体成功率全落在 ±7% 以内，律师、市场、分析师跟程序员几乎打平。报告解释管理者可能把引导下属的技能迁移到了引导 agent 上。分工数据同样具体：人类负责约 70% 的规划决策，Claude 负责约 80% 的执行决策；领域专家能让 Claude 动作翻倍、输出量达到普通用户的 5 倍。新手遇到麻烦时放弃率高达 19%，中级以上用户降至 5–7%。

群里反应分两派。<span class="mention">@洒脱的猫头鹰</span> 一眼看穿选择偏差——管理者「只管 aha moment，不管 corner case 死活」。<span class="mention">@我要成为灵能高手</span> 给出更实操的验证思路：「互联网公司 measure 这个最简单了，oncall 的时候看看炸了的代码是谁让 AI 写的，很快就知道谁用的好了。」<span class="mention">@谨慎的树懒</span> 更直接：「一眼 bias。」

### Sakana AI Fugu 多模型编排

<span class="mention">@温暖的树懒</span> 分享了 [Sakana AI 发布 Fugu](https://x.com/pirrer/status/2069006674875363651?s=12)。Fugu 将多代理协作封装为单一 OpenAI 兼容 API——调用方看到的是一个模型，背后运行着自动选模型、分派任务、循环验证的协调机制。核心技术来自两篇 ICLR 2026 论文（TRINITY 和 Conductor）。Fugu Ultra 定价输入 $5/M token、输出 $30/M token，SWE Bench Pro 73.7（Opus 4.8 得 69.2）、GPQA-D 95.5。

官方特别强调「不受美国出口管制影响」，直接瞄准因地缘政治无法稳定获取美系前沿模型的客户。Sakana AI 成立于东京，创始团队包括 Transformer 论文共同作者 Llion Jones，2025 年 B 轮融资 1.35 亿美元，估值 26.5 亿美元，投资方包括中情局创投 In-Q-Tel。

## 工具

### Gemini 3.5 Flash 输出截断踩坑

<span class="mention">@今天群内信息量极大</span> 做了一次 deep dive，终于定位到 Gemini 3.5 Flash 在他那边不稳定的根因：output limit 设为 128K token，同时 thinking effort 设得比较高（medium thinking），导致模型先生成几十上百 K 的思考独白，「想个五分钟」，等到终于决定开始写正文时 token 已经不够了——输出被 length 截断。而且这是 consistent behavior，每次重试都卡在同一个地方。修复方法简单粗暴：把 output context window 设大。

但他立刻指出不可持续：一是贵——3.5 Flash 在 medium thinking 下成本跟 Pro 差不多；二是仍然不稳定——多试几次，有时没到 token limit 还是会挂。这延续了 [「工程师视角的 Gemini Harness」]({{ '/daily/2026/06/19/daily/#工程师视角的-gemini-harness' | relative_url }}) 以来对 Gemini 工程可靠性的讨论——智能够用，但工程质量层面的坑总是不断冒出来。

### Prime Protocols V5 开源

<span class="mention">@风趣的海豚</span> 分享了 [The Prime Protocols V5](https://github.com/kv3100123/AI-Rule-Workflow-Design-Super-Boost-your-Antigravity-IDE-with-Gemini-)，一套专为 Gemini Flash 设计的双层 agentic 编程框架。Global Rules 层定义 agent 身份、任务分解逻辑、三层感知和「三方辩论」决策机制；Workflow Engine 层是七阶段收敛状态机（Explore → Parse → Plan → Execute → Verify → Align → Crystallize），每阶段可通过斜杠命令手动触发。当 Verify 阶段循环三次仍无法解决时触发 Gated Halting，主动暂停向用户请求输入，避免死循环。这是 [「工程师视角的 Gemini Harness」]({{ '/daily/2026/06/19/daily/#工程师视角的-gemini-harness' | relative_url }}) 中提到的那套框架的开源版本。

开源原因颇为戏剧性：作者家隔壁房子被雷击失火，当时他在开水龙头，「也感觉被电到了一下」。<span class="mention">@风趣的海豚</span> 确认「就是字面意义的被雷劈了」。<span class="mention">@稳重的海豚</span> 不解：「被雷劈了为啥开源？」

### Coding Plan 经济学与 Credential Pool

<span class="mention">@开朗的飞鼠</span> 问群里推荐便宜模型——Claude $100 档「很容易就一小时就用完了」。<span class="mention">@淡定的喜鹊</span> 建议抢国内版 GLM Coding Plan 或 Kimi Coding Plan，同时指出「claude max 性价比很高」，token 成本优化需要一套任务和模型能力匹配的打分系统。<span class="mention">@我要成为灵能高手</span> 推荐 ChatGPT $100 档：「写 C++ 都不会 5hr 断掉，那是 20 的体验。」<span class="mention">@敏锐的穿山甲</span> 印证升到 $100 后「再也没有 token 不够用的问题了」。

<span class="mention">@沉稳的仓鼠</span> 推送了自己的文章[《200 刀的 coding plan，请无脑开》](https://ranchen.org/content/20260615-rancheng-article-200-dollar-coding-plan)，核心论点是当前 coding plan 与 API 按量计费是两套经济模型——SemiAnalysis 压测数据显示打满用于 long-horizon coding tasks 对应 API 账面价值可达每月约 $8000。补贴存在是因为大厂在争夺下一代开发范式的默认入口，但窗口未必持久。

<span class="mention">@稳重的海豚</span> 亮出一个更硬核的解法：做了一个 credential pool，自动 rotate 多个 plan 账号——截图显示用量到 limit 后一键切换。<span class="mention">@开朗的飞鼠</span> 倒觉得 5 小时强制停 3 小时也不错：「有时间看视频学习，不然经常跟 AI 搞一天不知道搞了些啥。」<span class="mention">@我要成为灵能高手</span> 分享自己的用法更佛系——有些时候想起来去看 Codex 干得怎么样，「已经是两三天后了」。

### GPU 闲置算力共享

<span class="mention">@淡定的喜鹊</span> 提出设想：如果大家都自建 local inference，能不能把闲置算力组成去中心化集群？<span class="mention">@开朗的海豚</span> 泼冷水：「那不如用 public API 还便宜些。」<span class="mention">@飘逸的浣熊</span> 解释了技术瓶颈——网络带宽相比 GPU 带宽太慢，每个机器独立做 inference（在 request 维度切块）是带宽需求最小的方案。<span class="mention">@淡定的喜鹊</span> 追问能否像 BitTorrent 那样突破带宽瓶颈，<span class="mention">@沉稳的兔子</span> 提到 SETI@home 并指出关键在于问题本身的计算带宽比。

<span class="mention">@80-HD</span> 贡献了一个数据点：Anjney Midha 指出前沿实验室算力利用率可能低到 10% 以下，业内顶尖也只有 60–70%——瓶颈不是 GPU 数量，而是调度、网络、kernel 等系统工程。<span class="mention">@飘逸的浣熊</span> 翻出了 [「GPU 算力出租经济学」]({{ '/daily/2026/06/14/daily/#gpu-算力出租经济学' | relative_url }}) 的旧讨论供参考，并解释矿机（ASIC）唯一目标是计算哈希，没有通用性，不能用来做推理。

### "很多人其实是本地小模型"

<span class="mention">@直率的海豚</span> 分享了弱智吧梗图：「参数量极小：可能是 2B；训练集极小：甚至大部分都是污染数据；预训练轮数少：通常不收敛；上下文极小：不超过 500 字；注意力：是稀疏的；联网搜索：是不会的；思维链：是没有的；输出：不是幻觉就是过拟合。」
