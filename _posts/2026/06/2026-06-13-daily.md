## 方法论

### Agent 进度可视化与内部写作规范

<span class="mention">@活泼的喜鹊</span> 抛出了一个困扰很多人的问题：agent 写的代码越来越多，怎么跟上它的进度？他此前一直让 agent 生成文档但「都有些看不下去」，最近让 Codex 自动维护一个 progress 网页（含 Completed Work、Blockers、Steering Log 等面板），效果好一些但仍不够理想。

<span class="mention">@谨慎的狮子</span> 分享了正在迭代的 [show-me](https://github.com/xingyaoww/show-me) skill：让 agent 生成自包含 HTML 页面，用手绘风格内联 SVG 把代码改动和架构变化可视化。他的终极目标是「review PR 的时候直接 review 一堆 diagram 就行，AI 会画出 before & after 的架构设计」。但他坦言目前有两个瓶颈：AI 经常写「很肮脏的没啥用的小函数」导致细节看不下去；对于训模型等高资源开销任务，等 agent 跑完才发现方向错了代价太大，仍需早期介入。

<span class="mention">@今天群内信息量极大</span> 分享了另一个角度的 skill——[内部写作规范](https://github.com/grapeot/context-infrastructure/blob/main/rules/skills/workflow_internal_writing.md)，不追求可视化而是优化文字输出的可消化性。核心围绕两个维度：可跳读性（Skimmability）——开头 15 秒内让读者判断三件事：值不值得继续读、最该看哪段、为什么可以关掉；可验证性（Verifiability）——每条判断旁边直接附证据，不要堆到文末。他的出发点是：「虽然 AI 很牛逼了，我们一天还是只有 24 小时，阅读速度和认知带宽也就这么点。所以宁愿 AI 多花些力气，来围绕我们的限制优化。」

<span class="mention">@认真的灰熊</span> 立刻认出这套结构——「Bottom Line → Why This Matters → Recommended Action，太符合我们 VP 的阅读习惯了」，和 executive communication 的底层思路一模一样。<span class="mention">@谨慎的狮子</span> 看到后说「立刻让我的 AI 去抄一下」，<span class="mention">@今天群内信息量极大</span> 回应「进化算法的基因交流不就出现了！还是双向的！」<span class="mention">@认真的灰熊</span> 也表示每次<span class="mention">@今天群内信息量极大</span> 出新 skill 就让自己的 AI 仔细对照学习。

<span class="mention">@我要成为灵能高手</span> 提供了更轻量的思路：不要在 agent 工作时打断它，「手机登录上去以一秒钟一屏幕的速度扫，遇到有嫌疑的地方脑子自然会报警的」，做完再集中 review。<span class="mention">@稳重的海豚</span> 则指出根本矛盾：「哪怕你这个架构设计得非常好，code 有时候不听你的，不按这个干。」

### Daemon 驱动开发流水线

<span class="mention">@坚定的貂</span> 分享了一篇[工程师自述](https://www.thoughtfultechnologist.com/p/automating-myself-out-of-development)——从本地多终端并行一路推进到全自动 daemon 流水线的完整演化。核心设计是用 GitHub Issues 的 label 做状态机（ready → implementing → branches-ready → needs-attention），一个 tick.sh 脚本每 15 分钟由 cron 触发，找到最老的 ready issue 后以非交互方式启动 Claude 子进程。脚本刻意保持「蠢」，智能全在 Claude 里。最终保留五个人工介入点，失败时打 needs-attention label 留下日志。作者对结果保持清醒：吞吐量提高了，但平均代码质量没有提高，测试过度 mock，架构漂移也很难被发现。

<span class="mention">@坚定的貂</span> 评价「这变成了个比较常见的 workflow 了」。<span class="mention">@我要成为灵能高手</span> 引申到更大趋势：「最终还是要中央服务器去跑，大家只在 UI 上说话就行了」——但抱怨 Copilot / Codex cloud 选模型跑长程任务「都太难了，我觉得就是故意的，local 表现要好太多」。

## 行业新闻

### Meta AAI 团队士气危机

<span class="mention">@我要成为灵能高手</span> 转发了 [Wired 深度报道](https://www.wired.com/story/mark-zuckerberg-meta-employee-meeting-interrupt-ai/)：Meta 内部因 AI 战略调整爆发严重士气危机。今年 3 月成立的 Applied AI (AAI) 团队约 6,500 名工程师被强制划入——「要么加入，要么离职」。他们此前负责开发面向数十亿用户的社交应用，现在的主要任务是每周完成两项「作业」：生成复杂编程题供 AI 科学家训练和评估模型。有人形容这份工作「机械且毫无创意」，一名员工直接说「这简直是古拉格」。

一场面向数千人的内部直播会议上，有人用满口脏话打断，高喊自己「沦为公司的工具」。Chris Cox 在 Instagram 全员会议上承认工作环境「残酷」且「疯狂」，比作「在冰雹中跑马拉松，同时队友被换掉，还被人录像」。超过 1,600 名员工联署反对追踪键盘和点击操作来生成 AI 训练数据的项目。Zuckerberg 随后发内部备忘录承认犯了错误，承诺年内不再大规模裁员，将压缩管理层级并增加团队活动预算。这是继前天 [「Meta 限制员工 Token 消耗」]({{ '/daily/2026/06/12/daily/#meta-限制员工-token-消耗' | relative_url }}) 之后 Meta AI 内部矛盾的又一次集中爆发。

### GLM-5.2 实测与中美定价落差

昨天 [「GLM-5.2 趁乱全量开放」]({{ '/daily/2026/06/12/daily/#glm-52-趁乱全量开放' | relative_url }}) 后，今天开始出现实测反馈。<span class="mention">@风趣的海豚</span> 报告 GLM-5.2「真的丝滑」——跑了四小时所有任务一次性解决且全程不断线，日常工作体验与 GPT-5.5 差不多，但未测试复杂任务。他还发现 MiniMax 后台周限额显示「无限」，疑似限时免费。<span class="mention">@我要成为灵能高手</span> 补充了 GPT-5.5 的特性：一次给很多小任务会偷懒，但单个长程任务反而「质量好得多」——「可能他的 focus 跟人一样不能来回变」。<span class="mention">@淡定的喜鹊</span> 则认为 knowledge work 还是 DeepSeek 靠谱，「world knowledge 比其他家还是准多了」，GLM-5.2 如果只是 coding 特别强「好像对我就没什么用了」。

定价暴露了巨大的中美价差。<span class="mention">@坚定的貂</span> 晒出美区 GLM Coding Max 年费 $1,920（促销后 $1,344），<span class="mention">@风趣的海豚</span> 对比国区 Max 仅 ¥375/月（年付 ¥4,502 ≈ $620），差距约 2.5 倍。<span class="mention">@坚定的貂</span> 直言「这价格，直接 gpt-5.5 不行嘛」「美国玩家需要反向翻墙了」。

而国区用户面临的问题是根本买不到——<span class="mention">@随和的企鹅</span> 截图显示所有套餐「暂时售罄，06/14 10:00 补货」或「抢购人数过多」，他吐槽「比春运 12306 还难买」。<span class="mention">@聪明的蜂鸟</span> 在闲鱼上发现已有人代抢。新套餐还增加了周限额——<span class="mention">@聪明的蜂鸟</span> 实测 Max 约 0.8–1B token/周，「对本群来说有点不够看」。<span class="mention">@飘逸的猎豹</span> 补充高峰期好模型按三倍消耗计算，且个人版额度实际不透明，「团队版才有额度保证」。<span class="mention">@聪明的蜂鸟</span> 更心疼的是老套餐不让续费——他的老版 Lite 没有周限额，一周能用 300–500M token，过两天就到期了。多位群友面临同一个窘境：老套餐即将到期、新套餐抢不到、不知道还有哪家 coding plan 值得续。

### 非工程师的 AI 建设路径

<span class="mention">@冷静的飞鼠</span> 发布了[与 MIT 毕业生 Jenny 的深度对话](https://www.superlinear.academy/c/share-your-insights/mit-jenny)。Jenny 本科工业工程、研究生 BA，非工程背景，用下班和周末时间学 AI 和 vibe coding，总花费约两三千美金（其中一半用来买 Mac）。她形成了一套以 Claude 为主线的完整工作流：先在 Claude App 聊清楚想法、生成 spec 和 go-to-market 文档，导入 Claude Code 按 dev plan 实现，最后用 Codex review。小红书从两三万粉增长到十万，做法是某几个月每周发三条但周日集中录完，选题只讲自己真正学到的东西。核心建议：不要等学完再动手，先找一个自己的小需求做出来，哪怕只有自己一个人用。
