老鸭汤适不适合普通人？凌晨围绕这个问题拆出了一条实操矛盾——想复用的是某次驱动调查的具体结论，老鸭汤却推你往跨域抽象走，正在搭 context 体系的人值得通读这场辩论。额度告急的人今天多了一条路：MCP 把生产数据接给 Web Pro 做规划、Codex 只管执行，一篇文章讲透了两池额度分开花的做法。Sam Altman 宣布本周发布延到下周，盼 reset 的群友又一次空欢喜。

## 方法论

### 老鸭汤：细节复用与跨域的张力

老鸭汤适不适合普通人不断沉淀？凌晨 <span class="mention">@敏锐的雪豹</span> 抛出了这个问题，还追了一句：「普通人不断沉淀自己会不会拉低老鸭汤的水平？」基本共识是老鸭汤是中性放大器——<span class="mention">@冷静的麋鹿</span> 认为厉害的人越厉害、有执念的人反而强化偏差，但逐步变好能否赶上模型迭代速度是未知数。<span class="mention">@坦荡的灰熊</span> 判断更干脆：「肯定会拉低大模型的水平。」

老鸭汤的价值不在于一个人闷头积累——<span class="mention">@今天群内信息量极大</span> 认为关键在于社群效应，「三人行必有我师」：以前学到一个 mindset 需要大量训练和练习，现在改一下 skill 就能把别人的经验植入自己的体系。另一个视角来自 <span class="mention">@风趣的海豚</span>：最大用途不在日常执行，而在没有正确答案的判断上——这类判断平时不会出现，只有遇到了才需要面对，老鸭汤让你提前和 AI 对齐了立场。

> <span class="mention">@今天群内信息量极大</span>：大家相互偷师、相互蒸馏，变得比以前方便很多。以前要想学到一个 mindset，需要很多训练和练习。现在如果用老鸭汤的话，很大程度上就是把 skill 改一下就可以了。

讨论进入操作层面后出现了一个具体矛盾。<span class="mention">@坦荡的灰熊</span> 的日常主要是技术调查——比如排查图像传输延迟时发现驱动每次取图前多了 50ms sleep，随后开 session 调查 CMOS 型号的 app note。他想复用的恰恰是这些细节而非公理，但按领域归类就和老鸭汤跨域打通的理念相悖。回应来得很直接——<span class="mention">@搞仁义毛义仁</span> 认为每次都重新研究一遍是不行的。

折中方案是分层存储：技术细节存项目级 ctx 文件，全局只留公理——<span class="mention">@机智的水獭</span> 认为不这样做容易 bloat。<span class="mention">@今天群内信息量极大</span> 把老鸭汤的核心简化为一句话：「一切都是文件，搜索文件来获取知识，迭代文件来帮助未来的 AI。」即使什么都不做，只要配好 session export 和 semantic search 两个 skill，之前的会话内容就能被调出来。这一点被 <span class="mention">@稳重的海豚</span> 实证——他前两天照做把半年的 session 全部导出，解决问题前先检索，「一般会把之前的做法找出来」。不过他也区分了两类内容：客观技术经验靠检索就好，主观 preference（如写作风格偏好）噪音太多，需要精雕细琢。

> <span class="mention">@80-HD</span>：我感觉这个是我从老鸭汤学到的最好的东西，没有什么是一个简单的 md 不能解决的

<span class="mention">@稳重的海豚</span> 同时在梳理 context engineering 的学界与业界定义，感慨「一个概念诠释多如牛毛，每个人都按自己的意思来讲」，还没有一个完整的思路框架。<span class="mention">@认真的荷兰猪</span> 贴了一篇相关的 [AI memory benchmark 精度研究](https://yage.ai/share/ai-memory-benchmark-precision-20260719.html)，核心观点是写入端应偏向 precision——误存一条信息会在之后许多会话里反复复现，比漏存一条的代价大得多。

### MCP 桥接 Web Pro 省 Codex 额度

<span class="mention">@热情的狮子</span> 分享了一篇[用 MCP 给 Web Pro 接生产数据省额度的文章](https://mp.weixin.qq.com/s?__biz=MzIyMzA5NjEyMA==&mid=2647686431&idx=1&sn=c1bfba7e0b5b7cf995e444daf79861a4&chksm=f113a7ccdd23aee13652bbf96e1688bfc90fc417a5486c53963172a5384794644c3777c2678c#rd)。关键前提是 Web Pro 的对话额度和 Codex 额度分池计算、互不消耗。文章作者让 Codex 花半小时搭了一个只读 MCP Server 接入生产环境的日志和数据库，GPT-6 Pro 在网页版读完全量数据后推理约四十分钟给出降本方案，再点「添加到 Codex」让 Codex 执行——规划环节不吃 Codex 额度，执行环节只花了约 4% 周额度。

<span class="mention">@风趣的海豚</span> 评价「思路有点骚」。<span class="mention">@稳重的海豚</span> 已经在用类似模式续命：任务发到 TickTick，GPT 读 TickTick 和 GitHub，写 plan、开 PR、更新任务状态，定期跑一跑。他坦言两天 Codex 额度就干完，「全靠 6 PRO 续命」，但直言「6 PRO 没有 5.1 好使」。<span class="mention">@热情的狮子</span> 当晚也把自己的私有 MCP 挂到了 Web Pro 上，让它做只读的证据研究和优化分析。

### Astra 规划、弱模型执行

<span class="mention">@敏锐的海狸</span> 分享了一个探索类项目的发现：开 Astra xHigh 做顶层设计和 orchestration，具体执行分发给子线程。体感上单开一个 thread 时 context 全被干活占了，思想深度不够；多开 thread 后 context 主要花在思考分析上，推理效率高出很多。他现在验证思路时会明确要求 Astra 另开 primary agent thread 去测试，主线程自己不做实验。

模型分层策略的讨论随后展开。<span class="mention">@沉稳的兔子</span> 问 Terra 好不好用，<span class="mention">@直率的鹦鹉</span> 泼冷水——「不咋行，喜欢活干一半撂挑子」，得搞个 goal 鞭策。组合拳来自 <span class="mention">@开朗的企鹅</span>：让 Astra 写好 plan 并注明是 Terra 执行的活，Terra xHigh 能一直干十几个小时。<span class="mention">@搞仁义毛义仁</span> 补了前提条件：「当且仅当执行的时候没有意外」——Astra 突然一个脑残，Terra 睡一觉起来就跑飞了，planning 必须把所有问题都考虑到。

> <span class="mention">@稳重的海豚</span>：弱一些的模型不能去想，只能去干

Luna 也能胜任执行角色，但任务必须 self-contained。<span class="mention">@沉稳的兔子</span> 最终的选择是「还是回 Sol 吧，Astra 烧的太快了」——额度焦虑再次推动了模型选择。

### Reset 卡时间陷阱

<span class="mention">@今天群内信息量极大</span> 发现了一个坑：使用 reset 卡（$80）不只重置额度到 100%，还会重置每周计时起点——「那我 reset 了个寂寞？」<span class="mention">@洒脱的猫头鹰</span> 补充了完整的策略分析：如果当前周期前几天没活、打算留额度给最后两天用，结果 Tibo 半路直接重置，时间也刷新，那就是血亏。用卡的最优时机是新周期开始后两三天——刚烧完上周额度就立刻刷新，拿到双倍容量。后面两天用卡则纯属救急，嫖不到什么福利。

> <span class="mention">@洒脱的猫头鹰</span>：所以如果准备用卡，就攒点活，在新的 weekly 一两天用完

<span class="mention">@搞仁义毛义仁</span> 的做法更极端：基本快过期前才安排任务，自然 reset 当天一口气烧光，再用 reset 卡续一轮。额度焦虑今天贯穿全天——<span class="mention">@随和的飞鼠</span> 抱怨 5 小时限制之外又遇到 model at capacity，「也不告诉我什么限额，也不告诉我什么时候恢复」；<span class="mention">@直率的鹦鹉</span> 已转投 Cursor，闲鱼八九十人民币买 $20 套餐，「蹬完就换个号」；<span class="mention">@热情的狮子</span> 下午额度归零，$80 重置按钮赫然在列。

## 行业新闻

### Jev：JSON 判断不靠自回归

<span class="mention">@80-HD</span> 凌晨分享了 [Jev 的发布](https://x.com/completeskeptic/status/2099925682726002904)——声称比传统 LLM 快 20–200 倍、便宜 40–400 倍，输出 token 免费，定价为每百万输入 token $0.042。推特刷屏后 <span class="mention">@豁达的灰熊</span> 追问「有点没懂牛在哪」。

<span class="mention">@80-HD</span> 随后贴出 [Niels Rogge 的可视化解释](https://x.com/NielsRogge/status/2100239244501430438)：Jev 基于 RLCD（Reinforcement Learning for Calibrated Decisions），用预训练 LLM decoder 的单次前向传播处理「上下文 + JSON schema」，对每个 JSON 字段复用 KV cache 做一次受词表约束的分类，而非逐 token 自回归生成——输出保证 100% 合法 JSON。更有喜感的是 [harshagundal 两小时就开源了 Qwen-2.5-1B-RLCD 复现](https://x.com/harshagundal/status/2100044305536889015)，对方潜伏两年，他花两个小时做出了类似效果。

<span class="mention">@热情的狮子</span> 让 GPT 分析后给出简明定性：「就是智能的 if else 判断器，具体逻辑还是固定代码。」<span class="mention">@坦荡的灰熊</span> 倒是看到了应用前景——放到生产线上可以替代监控和日志做瞬间预警，比如设备老化导致良率微降，传统方式非得等 NG 率飙升才会反查出来。

### 反蒸馏「理论上不可防御」

<span class="mention">@热情的狮子</span> 分享了[晚点对安全研究者刘艺的访谈](https://mp.weixin.qq.com/s?__biz=MzU3Mjk1OTQ0Ng==&mid=2247538785&idx=1&sn=a848949fe4f4fafc28156ebc5e40f505&chksm=fd28e7fa3c756593e6059592ef718cccc2a5d0ba1eb6187225225b77bcb3d10f841156793219#rd)。核心判断：反蒸馏是伪命题，理论上蒸馏不可防御；美国前沿模型公司更现实的目标是提高对手数据采集成本，拖慢竞争者，延长领先时间——理解这些行动，商业逻辑比技术逻辑更重要。

访谈归纳了 Anthropic 的三层防线：内嵌分类器检测思维链提取、产品架构上隐藏或压缩思维链、外挂检测输出与思维链重叠度。但这只能形成平台侧的归因证据——GLM、Kimi、DeepSeek 只开源权重不开源数据集，无法白盒确证数据流向。对 Dario 呼吁放慢迭代，刘艺的解读是遇到了瓶颈（数据、算力或基础设施），才「顶着 AI 安全的帽子」出来喊停。这与群内此前几天的讨论方向一致（[「Dario 刹车假设被拆解」]({{ '/daily/2026/09/13/daily/#dario-刹车假设被拆解' | relative_url }})、[「Trump 反击 AI 刹车」]({{ '/daily/2026/09/14/daily/#trump-反击-ai-刹车' | relative_url }})）。他还提到，据说有数据公司出售长程任务思维链，800–1000 元一条。

### AI 文风红旗清单

延续昨天的讨论（[「AI 写作的信噪比」]({{ '/daily/2026/09/15/daily/#ai-写作的信噪比' | relative_url }})），今天群友开始总结具体的鉴别标记。<span class="mention">@谨慎的灰熊</span> 贴了一篇让 GPT-6 Pro 写的越野跑文章，<span class="mention">@80-HD</span> 一眼抓住「一份外卖，一篇论文」的开头——「一包味精不小心全抖进去的感觉」，并指出 AI 特别喜欢双线叙事然后合并的套路。

<span class="mention">@温暖的斑马</span> 列出了更系统的红旗：短排比句、「不是 X 但是是 Y」句式、句子长度接近——「蛋白质女孩味儿十足」。<span class="mention">@冷静的麋鹿</span> 用 Gemini 3.8 生成了同题文章对比，排比句明显减少；他还观察到网页版 5.5 Pro 和 5.6 Pro 似乎改过思考轮次——以前搜两百个网站，现在搜十个就交差了。<span class="mention">@沉稳的兔子</span> 的总结收尾：「AI 很喜欢在没有足够信噪比的地方抬自己的肛。」
