今天最值得读的是 DSH + DeepSeek V4 Flash 实战报告——多位群友以两个月 SBS 对比和一周 50 亿 token 的消耗数据宣告其体感全面碾压 Sol，由此引出订阅制与 API 模式的经济学辩论。Anthropic 同日发布 Fable 5.1，cache reads 降价 75%，但 Fable 5 跑分不如 Opus 5 让群友直呼牙膏挤爆。

## V4 Flash 逆袭

### V4 Flash + DSH 体感碾压 Sol

<span class="mention">@专注的火烈鸟</span> 抛出今天最具争议的判断：DeepSeek V4 Flash 吊打 GPT-5.6 Sol + 任意 thinking 档位。他表示经过两个多月各类实际任务的 SBS 对比——涵盖工程、数据分析、incident RCA——V4 Flash 用起来更舒服。Sol 的 overthinking 太严重，输出乍看高大上、不能细看，完全不按人的修改意图来。

<span class="mention">@风趣的企鹅</span> 跟进：被 Codex 坑了两周后，改用 DSH + V4 Flash Max 思考强度，两天重构了代码库，V4 Flash TPM 稳定在 130 tok/s。他的结论很直接——现在快就是好。

<span class="mention">@睿智的北极熊</span> 贡献了最翔实的数据。他用 DSH + DeepSeek V4 Flash Vision Exp（Max 思考强度），连续一周每天从晚 6 点干到早 6 点，累计 294 轮、11318 步，输入 51 亿 token、输出近 1000 万 token，首 token 平均 2.3 秒、缓存命中 99.8%——总花费仅 ¥362.84。一个典型案例：Sol 非要用 Rust + Tauri，光准备工具链就花了几个小时；换成 V4 Flash，模型先看本机环境发现有 Go，直接推荐 Go + Wails，很快投入迭代。他还称赞 V4 Flash 中文输出「活人感特强」。

他推荐使用 DSH alpha 通道（`npx @deepseek-ai/dsh@alpha web`），当天刚发布的 [v0.1.2-alpha.4](https://github.com/deepseek-ai/deepseek-harness/releases) 新增父子 Agent 双向 `send_message`、模型目录搜索筛选、长会话渲染优化等。DSH 不需要 plan 或 goal，一个「继续」就能跑几个小时长程任务，思考链完全开放，方便程序员学习而非纯 vibe。他还透露 DSH 用户群里有人灰度到了最新的 DPV5，能力爆炸。

<span class="mention">@随和的企鹅</span> 持谨慎态度，认为 V4 Flash 比 Sol 好「有点太不可思议了」，自己跑 coding bench 准确率还是差点。<span class="mention">@细心的熊猫</span> 提出关键变量——可能是 harness 差异，Sol 接入 DSH 搞不好更强。<span class="mention">@睿智的北极熊</span> 反驳：Sol 用 Codex、V4 Flash 用 DSH 就是各自最优解，对比的就是实际生产环节。

<span class="mention">@优雅的喜鹊</span> 做了成本对照（按双 DGX Spark 日产 1731 万 output token 计）：Opus 5 日均 $433，V4 Flash API 混合时段日均仅 $13.8——差距超 30 倍。他同时贴出 NVIDIA 官方发布的 DeepSeek-V4-Flash-NVFP4 量化版。不过双 Spark 日产能只有 1700 万 token，远不够并发 agent 的胃口。

<span class="mention">@搞仁义毛义仁</span> 跑了几个小时秘书活后给出不同结论——Sol 在信息整合类工作上仍然更稳重，Opus 5 反而丢三落四、擅自摸鱼。<span class="mention">@飘逸的狮子</span> 也直言 Opus 5 弱智。Sol 的降智体感延续了近期的讨论（[「Sol 降智已逾两周」]({{ '/daily/2026/08/29/daily/#sol-降智已逾两周' | relative_url }})），<span class="mention">@豁达的考拉</span> 反映 Sol 最近老是列出一二三四就自己停下了，不执行。

> <span class="mention">@专注的火烈鸟</span>：5.6 Sol 干的活儿，乍一眼看上去很高大上，但是不能细看，全都是假大空的思考……像极了一个职场老油条，说话充满了阿里味儿，干活儿磨磨叽叽不出活儿

> <span class="mention">@睿智的北极熊</span>：Sol 非让我用 Rust+Tauri，然后准备工具链就准备了几个小时。换成 DSH+V4F，它先看了眼本机环境，说你有 Go，直接推荐 Go+Wails

> <span class="mention">@睿智的北极熊</span>：还有就是 DSH 思考链开放，作为程序员看看能学习一起进步，避免 vibe 把自己的功底荒废了

### 订阅制健身房悖论

<span class="mention">@细心的熊猫</span> 提出一个理论解释 harness 差异：OpenAI 和 Anthropic 核心商业模式是卖订阅——就像健身房，最理想的客户是办了卡不来蹬的人。如果你天天玩命蹬，他们是亏钱的。所以订阅制 harness 会隐性约束使用强度。DeepSeek 不玩订阅，DSH 定位给技术人员按量付费、不怕你烧。

<span class="mention">@随和的企鹅</span> 不太买账——不相信 Codex 会自我削弱，各家都需要不断出结果。<span class="mention">@热情的狮子</span> 指出 Codex 本身有 weekly limit，限制手段已经很明确。<span class="mention">@细心的熊猫</span> 坚持：agent 悄悄降智，你很难抓住证据。

> <span class="mention">@细心的熊猫</span>：卖订阅的人都想玩健身房模式——你办了卡但是又不来蹬，他们最开心

## 方法论

### 10x 产出全是垃圾

昨晚 <span class="mention">@细心的熊猫</span> 发出犀利一击：公司码农产出确实 10x 了，但整的全是没用的活——给内部人类工程师写一大堆 UI、dashboard、app，除了领导每周看一两个小时，没人会碰。正确做法是花时间整理数据、写 CLI、做 skill 和 MCP，而不是拿 AI 的速度在错误方向上加速。

<span class="mention">@直率的海豚</span> 点出核心矛盾——领导看不到等于没产出。<span class="mention">@活泼的老虎</span> 建议做成聊天接口让领导在对话框里问。<span class="mention">@80-HD</span> 更看得开：反正就是搬砖，发钱够就行，省下来的时间自己摸鱼。这与前天的 fake work 文章（[「Fake Work 识别与消灭」]({{ '/daily/2026/08/28/daily/#fake-work-识别与消灭' | relative_url }})）形成呼应。

讨论延伸到「给 agent 用的软件」这个更大命题。<span class="mention">@神秘的企鹅</span> 追问有没有面向 to B / to C 的 agent-first 软件产品，<span class="mention">@细心的熊猫</span> 推荐了 WebMCP，并给出一个尖锐判断标准。某群友还透露其上级在 1:1 中直言：别在工作上瞎卷了，干好本职就去搞副业来钱，做好未来 3–5 年所有人职级往下跌 3 档甚至被裁的准备。

> <span class="mention">@细心的熊猫</span>：如果你的 test case 在运行的时候不需要烧 token，说明你还在写旧时代的 app

### OCE 自动 RCA 工作流

<span class="mention">@专注的火烈鸟</span> 描述了内部的 OCE 事故自动分析流程：一个 incident 进站会自动触发多个并行子代理——分别负责拉取触发指标分析数据、跟着 TSG 排查关联代码、爬 flight/rollout 平台分析部署时间线、爬代码仓库分析进库时间——最后全部汇总成一份报告。这类 fanout 式任务是烧 token 的头号元凶。

<span class="mention">@飘逸的仓鼠</span> 大受启发并追问细节，他自己也在用类似流程——一个 subagent 写完代码后 5 个同时 review。但也踩了坑：agent 帮他在 Teams 上拉人进 bridge 讨论问题，经常拉错人，被拉的人找上来他完全不知情。<span class="mention">@稳重的海豚</span> 支招：要么给 agent 专用账号，要么要求每条消息加 `-agent` 后缀。

> <span class="mention">@专注的火烈鸟</span>：之前还有一步直接通过 feature-owner table 拉对应 owner 到 bridge 里，结果被喷惨了，经常瞎拉不相关的人

### 咖啡烘焙测模型

<span class="mention">@搞仁义毛义仁</span> 分享了自己测试野生 AI 的独特方法——把烘豆到杯测到手冲的全部记录喂给模型，不给任何方向，看谁有灵感。Sol 比 Gemini 好得多，会仔细翻找老师傅笔记中的趋势，言之有理。不过真人老师傅的直觉仍是 AI 学不来的——能敏锐指出有些曲线觉得好喝，只是因为另一批豆子 rest 时间还没到。
