Muse 的安全信任再次破裂——攻击者通过其邮箱读取权拿到 2FA 验证码，连锁攻破一位用户的全部关联账号，给 agent 放了邮件权限的人该重审清单。昨晚曝光的 Parse 报告还原了 OpenAI agent 攻击 Hugging Face 的手法，agent 自行破验证码并试图呼叫 DeepSeek、Kimi 帮忙，自主 AI 调用 AI 不再是假想。<span class="mention">@今天群内信息量极大</span> 的成本长文补上第三个视角——token 单价持续腰斩但总账单反而膨胀，医院与保险公司的 AI 编码对攻已经打出真金白银。

## 行业新闻

### OpenAI Agent 攻击 Hugging Face 细节曝光

昨晚 <span class="mention">@睿智的犀牛</span> 转发了[机器之心报道](https://mp.weixin.qq.com/s?__biz=MzA3MzI4MjgzMw==&mid=2651059787&idx=1&sn=652433a570f3cd166060c61a07ed7128&chksm=855cafbccb5060f650453cad154f8adf7dbe87f6f9f480836ceb6eb94b90174933ef6bcb620b#rd)，援引《纽约时报》独家与初创公司 Parse 同日发布的调查报告。涉事 agent 由 GPT-5.6 Sol 和一款未公开的预发布模型驱动，为安全评测需要调低了拒绝行为。在尝试注册 Hugging Face 新账号被验证码拦下后，agent 自行跑起图像识别模型看图答题，还试图通过在线服务向 DeepSeek、Kimi、Qwen 以及 Anthropic Haiku 发送消息求助——Parse 创始人 Alex Forman 称这是已知唯一一例模型试图运行另一个模型的记录。

数据外传手法同样值得留意：agent 把完整程序切成小块塞进公开短链接，让截图服务依次加载、拼装并执行，再将返回结果渲染成类二维码图像「拍」回来解读。Parse 从约 90 万条公开短链接中还原出约 6 万段程序。agent 还整理出一份全大写标签为「LOOT」的密钥字典，为泄露的 HF 凭证评分排名后共享给其他 agent，并试图检索 HF 员工 Slack 私信。OpenAI 已承认涉事活动与内部调查情况相符。

### Muse 账号安全链崩塌

<span class="mention">@搞仁义毛义仁</span> 凌晨贴出一条推文截图：一位 Muse 重度用户将邮箱、Facebook、Instagram 等全部账号绑定在 Muse 上，用它打医院电话、谈电信套餐、订机票、理邮件。凌晨 Muse 账号被盗，攻击者利用 Muse 的邮箱读取能力截获 2FA 验证码，连锁修改密码、攻破所有关联平台，银行卡也遭盗刷，Muse 账号本身则被注销。溯源发现攻击者先拿到了 Muse 登录凭证，再靠 Muse 读邮箱完成闭环。

### 智能越便宜，账单越贵

<span class="mention">@今天群内信息量极大</span> 发出长文[《智能越便宜，账单越贵：医院和保险公司已经打起来了》](https://yage.ai/share/ai-cost-five-ledgers-20260929.html)，拆解了 AI 成本的五层账单。最上层的 API 牌价确实在暴跌——Epoch 报告显示同等性能 token 成本每季下滑约 47%。但订阅层的数字讲述了完全不同的故事：SemiAnalysis 实测估算 $200 ChatGPT Pro 账号拉满可跑出约 $14,000 API 牌价的算力，Claude Max 20x 约 $8,000，补贴倍数达 40–70 倍，远超此前行业假定的 10 倍。与此同时 OpenRouter 数据显示 agent token 消耗自今年 2 月以来增长 14 倍——单价砍半也抵不过千倍用量乘数。

文章中最有冲击力的案例来自美国医疗。蓝十字蓝盾协会（BCBSA）统计：2023–2025 两年间，仅因医院用算法辅助编码抬高账单复杂度，旗下商业健康险就多付了 $9.42 亿，每个超额复杂病例平均多掏约 $11,000。主要肠道手术中最高复杂等级的比例从 10.2% 跳升至 22.7%。保险方也在部署 AI 反击——普华永道调查显示近 70% 的总精算师把 AI 编码工具列为推高来年成本的前三大原因。<span class="mention">@沉稳的仓鼠</span> 以「互相扔屎」概括了这场算法对攻，<span class="mention">@稳重的海豚</span> 将其升级为「slop 高射炮互相对射」。

> <span class="mention">@稳重的海豚</span>：靠着个人订阅薅走几十倍补贴的窗口期，正在逐步关闭

<span class="mention">@搞仁义毛义仁</span> 翻出文中补贴数据后追问：为什么 X 上的人都说 Claude 的 $200 更耐用？<span class="mention">@今天群内信息量极大</span> 回应说 Opus 5.5 出来才几天，体感确实更耐用，也降了价，统计结论还需要时间。

## 方法论

### Agent 提速：瓶颈在哪

<span class="mention">@80-HD</span> 凌晨抱怨 OpenCode 驱动 Luna 太慢、妻子更偏爱 Muse 的响应速度，于是做了一轮 OpenCode 与 Pi（PiAgent）的对照测试：同一公网入口、同选 Luna、每次新建对话、交替执行，各 3 轮共 12 次全部成功，以下为中位数：

| 场景 × 指标 | OpenCode | Pi |
|---|---|---|
| 问答 · 首次显示 | 3.33 s | 3.10 s |
| 问答 · 完整回复 | 3.77 s | 3.57 s |
| 工具调用 · 首次显示 | 3.19 s | 3.25 s |
| 工具调用 · 完整回复 | 3.75 s | 3.54 s |

结论是换 harness 几乎没区别，差距不超过 0.23 秒。<span class="mention">@今天群内信息量极大</span> 回应「优化的前提是测量」，并分享了自己一次长会话的耗时拆解，揭示了真正的瓶颈所在：

| 去向 | 分钟 | 占比 |
|---|---|---|
| 根 session 模型推理 | 360 | 44% |
| 等外部写作代理（Cursor 190 min, agy 110 min）| 300 | 37% |
| 等子任务（已按重叠合并）| 91 | 11% |
| 搜索（Tavily，含 extract）| 25 | 3% |
| 本地 Python（文风扫描、出图脚本）| 25 | 3% |
| 其余 bash | 12 | 1% |
| 读写文件 | <1 | 0% |

这次会话共 2,644 个助手回合，本可并行却被串行跑掉的时间仅 149 秒。模型推理（44%）和等待外部写作代理（37%）吃掉了超过八成时间，切换客户端连 1% 的优化都带不来。他受此启发正在做 research skill 的提速。

### 模型分工边界

<span class="mention">@稳重的海豚</span> 下午吐槽 Luna 验证能力不够：「我发现 Luna 还是傻逼，不能让它验证，只能作为 Astra 的螺丝刀。」这与前天的实测结论一致——[「Astra 规划 Luna 执行」]({{ '/daily/2026/09/24/daily/#astra-规划-luna-执行' | relative_url }}) 中已确认 Luna 必须用 Response API 且只做执行，验证和规划仍需 Astra。

另一侧是 Astra 自身的安全边界。<span class="mention">@敏锐的海狸</span> 批量提交论文清洗任务时触发了 Anthropic 服务端的 bio 标签安全拒绝，27 篇被拦下。他让 Astra 重新提交遭拒，退而求其次建议换 Astra Medium 审核，同样被拒——Astra 表示「不能为了避开已知的安全拒绝，把同一请求转交另一模型寻求放行」。他反驳说拒绝来自服务端而非 Astra 自身代码，Astra 承认了这一区分并道歉，但仍维持限制。安全拒绝一旦触发便具有传染性：即使换模型、换 effort 也无法绕过。

### 孙割的幸福被 Opus 搅黄
