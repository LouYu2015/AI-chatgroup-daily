补贴时代今天正式画了句号：OpenAI DevDay 宣布 Pro 额度腰斩，群里大量讨论围着「该不该转 Claude」打转。<span class="mention">@今天群内信息量极大</span> 实测 Ultrafast 模式确实飞快，但同一套餐的周配额转眼见底，提速红利被缩水吃干。Anthropic 同日放出 GLM-5.3 红队报告，表面点名智谱，<span class="mention">@今天群内信息量极大</span> 一拆就发现真正靶心是所有开源权重模型。

## OpenAI DevDay 2026

### Pro 套餐重构

DevDay 前夜 Tibo 就在 X 上预告：Pro $200 重新开放订阅，但用量计算方式调整，折算成 API 花费约为旧版的一半。他用四段话解释为什么用户仍将「get more work done」——API 本身在降价、模型效率在提升、不想人为虚抬 API 标价再打折。<span class="mention">@飘逸的猎豹</span> 替他翻译成人话：保证砍了额度之后，相同价位能干的工作量比以前多。<span class="mention">@开朗的企鹅</span> 一句话戳穿：「这不就相当于效率并没有提升吗。」<span class="mention">@热情的狮子</span> 总结为「语言的艺术，说半天就是砍额度」。

DevDay 正式公布了完整套餐体系：

| 套餐 | 月费 | 用量倍数（Plus 基准） |
|---|---|---|
| Plus | $20 | 1x |
| Pro 100 | $100 | 5x |
| Pro 200 | $200 | 10x |
| Pro 500 | $500 | 25x |

旧 Pro 200 用户暂保 20x 额度至 10 月 29 日，届后统一降至 10x。Pro 500 独享 Ultrafast 模式与取消 5 小时限制，可跨合作 app 使用额度。极客公园的现场报道点出要害：旧 Pro 200 花 10 倍月费拿 20 倍用量，这个「批发价」这次没了——每一档都是 $20 换 1 份 Plus 用量，线性定价。Altman 讲到会员调整时，台下没有一个人鼓掌。

作为对冲，GPT-5.6 Sol 对所有 Pro 用户开放 Unlimited 访问，只有使用 GPT-6 系列时才计入配额。<span class="mention">@稳重的海豚</span> 立刻看到了分工：思考交给 Fable，执行交给 5.6。但<span class="mention">@天真的浣熊</span> 泼了冷水：谁能保证给你的不是弱化版？

<span class="mention">@专注的剑鱼</span> 贴出一条精准的推文回复——有人对 Tibo 说「Beat Opus 5.5 in the overall value for a dollar，then no need for these long posts justifying」，Tibo 回了一个字：Agreed。这大概是当天最诚实的一刻。

群里迅速掀起转投潮。<span class="mention">@直率的鹦鹉</span> 表示准备用脚投票去 Claude，<span class="mention">@活泼的树懒</span> 判断 OpenAI 的目的就是逼人订 $500。但尴尬的是当天早上 Claude Code 也出了认证故障——<span class="mention">@谨慎的松鼠</span>、<span class="mention">@直率的穿山甲</span> 等多人同时报告无法登录，<span class="mention">@幽默的火烈鸟</span> 说自己弹了一天了。<span class="mention">@80-HD</span> 感叹：「每个月都会有用户迁徙，像候鸟一样。」

> <span class="mention">@今天群内信息量极大</span>：补贴时代要结束了，都在涨价了

### GPT-6.1 Sol 与 Ultrafast

DevDay 发布了 GPT-6.1 Sol，同步推出 Ultrafast 推理模式——官方标称较标准速度快 8 倍、峰值 300 tok/s，覆盖 API、ChatGPT 和 Codex 三端。<span class="mention">@坚定的貂</span> 在直播中直呼「吓尿了，速度好快」。值得注意的是 6.1 Astra 并未同步登场，<span class="mention">@天真的浣熊</span> 此前在 X 上看到 6.1 Astra 已取消的传言。<span class="mention">@风趣的企鹅</span> 在 HN 上看到的讨论提到 Sol 的缓存价减半是真正的大新闻，有人算出 Sol 在各计价项上恰好是 Opus 5.5 的一半。

<span class="mention">@今天群内信息量极大</span> 第一时间用同一个翻译任务做了三档对比：Standard 耗时 101 秒，Fast 63 秒，Ultrafast 仅 18 秒——纯文本场景下提速立竿见影。但他随即指出瓶颈已从推理转移到工具调用，体感与 Ollama Cloud 上的 GLM-5.3 Flash 速度接近但整体体验没有质变。<span class="mention">@80-HD</span> 也表示干活经常一堆 test 跑半天，连 Fast 都不开了。

更致命的是配额消耗：<span class="mention">@今天群内信息量极大</span> 升级 $500 套餐后测了一波，20 分钟就烧掉了周配额的四分之一。

> <span class="mention">@今天群内信息量极大</span>：这有个吊用，得多富才敢用

晚间实测反馈分化。<span class="mention">@直率的鹦鹉</span> 用 6.1 Sol 带 5 个 subagent 干了半天只消耗 5% 额度（20x 订阅），认为耐用了很多。<span class="mention">@冷静的麋鹿</span> 则觉得慢了不少、活干得拖泥带水。<span class="mention">@幽默的火烈鸟</span> 更直白：和 6 Sol 没用出区别，速度反而变慢了。

### dots 初体验

DevDay 另一个重头是 dots——Astra 驱动的常驻个人 agent，自带云端电脑和浏览器，可连接 4,000+ 应用，全天候运行。Tibo 发推明确：dot 自己干活时不消耗任何用量，完全在套餐之外；只有让它创建 Codex 任务时才走正常配额。先给每人配一个主 dot，后续可组建团队。

<span class="mention">@冷静的麋鹿</span> 对语音通话功能评价很高——比之前的语音对话在中文场景下「反应快不啰嗦，有重点」，支持多任务交叉指派，不用挂电话就能下新任务。不过他也踩了坑：dot 只能挂一台电脑，换一台就把上一台挤下来；dot 扮演你的分身，做完后会自行检查并给提示词优化，有时过度干预反而拖慢进度。<span class="mention">@直率的鹦鹉</span> 试了云端电脑，发现微信连不上、root 权限也没有。<span class="mention">@洒脱的猫头鹰</span> 则发现让 dot 去操作 GitHub 项目时似乎不占额度。

dot 的定位让<span class="mention">@坦荡的灰熊</span> 直接问出「和 OpenClaw 啥区别」，<span class="mention">@洒脱的猫头鹰</span> 答曰「正统续作」。更惨的是 Jev——<span class="mention">@坚定的貂</span> 在直播中发现 Luna 可以直接模拟 Jev 的功能。<span class="mention">@今天群内信息量极大</span> 替 Jev 心痛——从九天估值 50 倍（[「Jev 估值九天 50 倍」]({{ '/daily/2026/09/24/daily/#jev-估值九天-50-倍' | relative_url }})）到被大厂一周复制，<span class="mention">@稳重的海豚</span> 补了一句「最惨的是投了 jev 的 vc」。

### Codex 生态扩容

DevDay 还推出了一系列生态能力。Codex 企业版原生支持 GLM-5.3 Flash 和 Kimi K3 等开源模型，支出计入 OpenAI 承诺额度——Tibo 转发时说「Open is the way」。此外有 Decisions API（Luna 驱动，毫秒级判断）、Agents API（预览），以及 Codex 云端版和与 AWS 合作的 Codex Security Cloud。

更值得关注的是「Sign in with ChatGPT」——用 ChatGPT 账号登录 Devin、Notion、Vercel 等 16 家合作产品，会员额度跨 app 通用。<span class="mention">@热情的狮子</span> 转发的极客公园文章将这套组合比作微信生态：插件像小程序，登录像微信登录，额度像跨应用钱包。<span class="mention">@神秘的火烈鸟</span> 认为这是必然路径：「做大做强都会是 marketplace 模式，做生态搞一堆小弟。」

## 行业新闻

### Anthropic 红队炮轰 GLM-5.3

<span class="mention">@天真的浣熊</span> 贴出 Anthropic Frontier Red Team 今天发布的报告《GLM-5.3 and the spread of advanced cyber capabilities》。报告称 GLM-5.3 构建端到端网络漏洞利用程序的能力几乎与 Claude Mythos Preview 相当——后者是 Anthropic 出于安全考虑一直封存的模型。区别在于 GLM-5.3 缺乏有效防护，简单攻击手法的绕过率在 64%–100% 之间；同类攻击在受保护的 Claude 模型上未能成功。

<span class="mention">@今天群内信息量极大</span> 细读后指出报告的真正靶心不是智谱：所谓的攻击方法是对权重进行修改来实现越狱，这对任何开放权重模型都成立，GLM-5.3 被拎出来只是因为它能力最强。他承认论点有道理，但也看穿了弦外之音：「遏制开源模型发展的算盘珠子打的 openai 都听见了。」背景是此前 Hugging Face 被 OpenAI agent 攻击时恰恰靠 GLM-5.3 实现了防守（[「OpenAI Agent 攻击 Hugging Face 细节曝光」]({{ '/daily/2026/09/26/daily/#openai-agent-攻击-hugging-face-细节曝光' | relative_url }})）。

### Anthropic 抢活工作流

<span class="mention">@天真的浣熊</span> 转发了一条 49K 浏览的 X 帖子，描述 Anthropic 内部 MTS 的工程工作流：所有人的 Claude session 和项目共享，任何人可以搜到他人的 session history，也可以抢占他人 queue 里的 task——谁先做完 credit 归谁。平均每人 7–10 个 task 排队，做得快的飞快，做得慢的一眨眼任务就被抢走。帖子还补了一句：出不来活的 3 个月走人。<span class="mention">@豁达的灰熊</span> 感叹卷度对得起薪资，<span class="mention">@天真的浣熊</span> 转述评论区的辣评：「Dario 在百度学到真东西了。」

### AI 味检测与文风 LoRA

<span class="mention">@今天群内信息量极大</span> 发布了 [中文 AI 味检测与文风改写 Skill](https://skills.superlinear.academy/?skill=voice-lora)，核心是一个基于 Qwen3.5-9B 的 LoRA 微调模型，用他自己的语料训练，输出带有他的写作口吻。Skill 包含两个能力：AI 味检测器（给文章打分并定位最像 AI 的段落）和改写器（逐段改写为更自然的文字），想定制自己文风的用户可以用自带工具链训练自己的版本。他透露灵感来自 <span class="mention">@洒脱的鸳鸯</span>——后者已训练了自己的 Qwen LoRA 学习知乎文章文风，新文章都是 Codex 写完交给 LoRA 改。<span class="mention">@今天群内信息量极大</span> 的做法是睡前跟 Opus 布置任务，第二天收菜。

<span class="mention">@灵动的羊驼</span> 分享了另一条路线：GitHub 上的 [human-writing Skill](https://github.com/KKKKhazix/human-writing)，走规则而非微调。1.0 版用字符串禁令拦 AI 味（禁「不是……而是……」等句式），但模型换个马甲继续做同样的事；1.1 版把防线从字面挪到动作——禁的是「先给读者立一个他没有的误解再推翻它」这件事本身，不管穿什么外衣。

## 方法论

### AI 写作与逻辑的跷跷板

AI 味 Skill 引出了一个更深的观察。<span class="mention">@今天群内信息量极大</span> 认为到目前为止 AI 的逻辑思维能力与写作能力「似乎还是严格互斥的」：一端是 DeepSeek 和 Gemini，指令遵循和编程一般，但脑暴创新和写作相对好；另一端是 Claude 和 GPT，逻辑完美但 AI 味直冲天灵盖。<span class="mention">@神秘的企鹅</span> 觉得 DeepSeek 也 AI 味重，反而豆包好一些；<span class="mention">@今天群内信息量极大</span> 认为这恰好佐证了观点——豆包以前编程弱的时候写作更好，编程变强后也越来越不说人话。

<span class="mention">@开朗的企鹅</span> 高度怀疑根源在数据配比，类比为「数学金牌选手为什么语文作文不满分」——能力维度本就不同。<span class="mention">@随和的老虎</span> 指出 AI 味太难定义和量化评价，不像数学题有标准答案。<span class="mention">@搞仁义毛义仁</span> 倒是乐观：AI 味经过一代人就会被人类学去，<span class="mention">@洒脱的猫头鹰</span> 接了一句——「那是新时代的普通话。」

### AI 重塑数据库选型

<span class="mention">@稳重的海豚</span> 问 Supabase 替代品，<span class="mention">@热情的狮子</span> 试过 Turso 和 Neon 又回来了，<span class="mention">@专注的火烈鸟</span> 觉得用习惯后无法替代。讨论很快转向 AI 对数据库选型的冲击。<span class="mention">@80-HD</span> 指出 MongoDB 受创最大——CEO 都跑路去了 Meta，根本原因是过去程序员懒得设计 schema 才把 JSON 塞进 Mongo，现在有了 AI 这个问题不存在了，也没必要损失性能用 schemaless。
