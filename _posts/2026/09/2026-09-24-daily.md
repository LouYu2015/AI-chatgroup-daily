## Opus 5.5 产品宣传片

### 一条 Prompt 到完整成片

X 上一位开发者用 Opus 5.5 给自家产品做了一支纯代码渲染的宣传片后迅速出圈。<span class="mention">@天真的羊驼</span> 分享了 [Video ShotCraft](https://vincentwei1021.github.io/video-shotcraft/) skill（157 种镜头配方、214 种动效预览），<span class="mention">@开朗的企鹅</span> 贴出了另一位作者开源的 [guizang-product-video-skill](https://github.com/op7418/guizang-product-video-skill)，群里随即掀起实测潮。

<span class="mention">@冷静的麋鹿</span> 做法最省力：睡前给 Astra 一条 prompt，指定 Astra 统筹取材和验收、Opus 5.5 负责动画配乐，连音乐都要求「用代码算出声波」而不用现成曲子。醒来收到一支 53 秒带配乐的成片，「一体成型」。

| 模型 | 总 token（含缓存） | 其中输出 |
|---|---|---|
| Astra（含协作审查） | 2,776.74 万 | 7.41 万 |
| Opus 5.5 | 2,214.33 万 | 26.61 万 |
| 合计 | 4,991.07 万 | 34.02 万 |

约 5,000 万 token 换一支完整宣传片。他看完后判断以后产品教学白皮书「都可以变成视频了，比文档清楚多了，每个功能再单独来一个」。<span class="mention">@稳重的海豚</span> 立刻跟进给自己内部产品做视频。

不过零人工并不等于高质量。<span class="mention">@热情的狮子</span> 也用 Remotion 做了公司宣传片，但他拉上了一位有剪辑背景的 marketing 同事把控审美，花了约半小时。对比之下，纯 AI 出品的版本「比较平铺直叙」，加入 story telling 后情绪调动明显更强。<span class="mention">@随和的老虎</span> 直接用 Opus 5.5 蹬出的版本则被他自己形容为「很魔性」。<span class="mention">@冷静的麋鹿</span> 对比两版后坦承「还是得专业」。

> <span class="mention">@热情的狮子</span>：审美还是很重要的，marketing 同事以前做过剪辑师

<span class="mention">@今天群内信息量极大</span> 顺手勾勒了一个多模型宣传片工作流——「gemini 写文案，astra 做 3D，opus 做动效」，<span class="mention">@80-HD</span> 追问「？？」，他补上结尾：「最后小肥鱼直接删库。」

## 工具

### Claude.ai 三倍提速与中文税

<span class="mention">@80-HD</span> 分享了 Anthropic 官方博文 [How We Made Claude AI Faster](https://claude.dev/blog/how-we-made-claude-ai-faster/)：团队用两周 sprint 把 claude.ai 核心体验做到约 3 倍快，全新加载到可输入从 3.1 秒降到 0.55 秒，Claude Code 新会话从 0.8 秒降到 0.3 秒。整个过程由 Claude 在 Slack thread 里驱动，高峰期同时跑 150 多个 thread、一天落地 200 多处改动。

博文里一个案例引发了讨论：Claude 排查 CPU 卡顿时发现高亮已完成的代码块会卡住约一秒，根因是 em dash 等非 Latin-1 字符令 V8 把整个字符串存为 UTF-16，语法高亮正则全部走更慢的双字节路径。修复只需二十行——高亮前把代码块拷成单字节字符串。<span class="mention">@80-HD</span> 由此推断中文内容天然含大量非 Latin-1 字符，用 Claude Code 存在「中文税」。

<span class="mention">@搞仁义毛义仁</span> 认为这不是语言问题而是引擎问题：JavaScript 标准就是 UTF-16，regex 内部实现都要兼容 surrogate pairs。他自己的方案是写一个 lazy enumerator 把任何编码的字符串统一成 char32_t reader，「在上面跑 regex 不管你什么 encoding，都是换个水龙头的事」。

### Sol 代 Astra 与算力缩水

<span class="mention">@今天群内信息量极大</span> 开始大量使用 GPT-6 Sol，「终于又回到了以前 Codex 怎么用都不心疼的世界」。<span class="mention">@开朗的企鹅</span> 体感 Sol「和 5.6 区别不大」，<span class="mention">@直率的鹦鹉</span> 反映近期速度明显变慢，跑任务体感是 Grok 4.7 时长的两三倍。<span class="mention">@80-HD</span> 附和：「屁大点活我去洗个澡都没干完，感觉就是在假干活。」<span class="mention">@随和的企鹅</span> 怀疑 Astra 被挪用了算力，「感觉明显不如第一周」。

<span class="mention">@搞仁义毛义仁</span> 分享了应对小任务的 prompt 技巧：直接告诉 Astra 怎么做，不要让它自行规划无关路径。他另一个观察是 agent 写一堆 unit test 然后反复跑本身不算浪费——运行效率不重要，跑测试不烧 token 却能抓住「文档里没写，或者写了但是 AI 反正经常会看不见的东西」。

## 方法论

### 向量相似度稻草人

<span class="mention">@豁达的灰熊</span> 分享了一篇[小红书文章](https://www.xiaohongshu.com/discovery/item/6ab4b3c4000000001500c082?app_platform=ios&app_version=9.29&share_from_user_hidden=true&xsec_source=app_share&type=normal&xsec_token=CBPqUZeki_LGGJgRYvPrsr-BYxWuiQuAJEGNE2JqnK0cY=&author_share=1&xhsshare=WeixinSession&shareRedId=N0pIQ0c-RU42NzUyOTgwNjY0OTdGOT48&apptime=1790255827&share_id=7c9a489c7cc14f4b8659bb8ab3fd9506&track_code=3xDiTFCUYrS)，标题「向量相似度骗了我们多久」，已有 331 人分享。<span class="mention">@今天群内信息量极大</span> 一句话拆穿了它的定位偏差：文章讨论的是 meaning identity（两句话是否完全同义），但 RAG 解决的是 topic relevance（query 和文段是否相关），两者根本不是一回事。

> <span class="mention">@今天群内信息量极大</span>：这篇文章本身是正确的，但是他是找了一个非常 niche 的稻草人在打。

他随即跑了一个实验：把论文使用的 2023 年旧 encoder 换成 Qwen3 Embedding 8B，meaning identity 的 gap 从 0.3 降到了 0.03，问题在现代嵌入模型上基本不存在了。<span class="mention">@80-HD</span> 点破这是典型的论文写法——「实验做了 idea 试了不是很 work，但是需要文章要毕业，那就造个问题来写一个」。<span class="mention">@豁达的灰熊</span> 回头看了原文后替作者说了句公道话：文章本身定位 hard semantic identity 是清晰的，「搬运的人给造了个新闻学标题」。

<span class="mention">@开朗的企鹅</span> 用一段故事还原了论文可能的诞生过程：老板给了 meaning identity 任务→「这么简单不就是随便拿 embedding 就得了么」→「诶怎么搞不定」→「wow，过一遍模型就好了」→「paper 来咯」。

### 每人自己 vibe UI

<span class="mention">@80-HD</span> 在搓自己的聊天工具时感叹「做一个能用的和做一个好用的」之间有巨大鸿沟——自己给自己搓容忍度很高，给别人用完全是另一种体验。<span class="mention">@搞仁义毛义仁</span> 由此抛出一个判断：只要模型足够强，「'app 给别人用'这种事终归会被消灭」，以后不需要集群的东西都由用户自己集成，开发者只管卖 API 和积木。他把这视为 Java 当年「一次编写到处运行」愿景的真正兑现。

<span class="mention">@洒脱的猫头鹰</span> 指出了盲区：「消费审美和生产审美有鸿沟，大概跟会不会编程用 vibe coding 差不多。」<span class="mention">@80-HD</span> 补充说他调研过能不能像 dsh 那样在手机上现场生成 app，发现 iOS 上根本行不通。今天的宣传片实测恰好印证了这一张力——AI 生成的「平铺直叙」版和有专业审美把控的版本之间差距肉眼可见。

## 闲聊花絮

### 育儿即模型训练

<span class="mention">@冷静的飞鼠</span> 宣布今年生二胎，收到一片祝贺后意外引出了半天的育儿大讨论。<span class="mention">@冷静的飞鼠</span> 甩出 [Paul Graham 的经典文章](https://paulgraham.com/kids.html) 劝人生娃——PG 自比劝人入教的邪教信徒：入教确实让你快乐，因为入教改变了你的心智。

<span class="mention">@80-HD</span> 以实战派身份全程提供 AI 类比。怀孕到出生是「从预训练到后训练再到蒸馏」；娃最近参数量有所提高，但 instruction following「还就是和大肥鱼差不多」；同班同学「不是 Fable 就是 Astra，我家这个就是个大肥鱼」；昨晚睡前娃跟他说自己的大脑「activate 了一部分」。

> <span class="mention">@80-HD</span>：然后娃跟其他娃比起来也挺难受的，同班的感觉不是fable就是astra，我家这个就是个大肥鱼
