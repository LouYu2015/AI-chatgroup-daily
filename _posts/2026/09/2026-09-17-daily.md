Codex 读完一篇博客就修好了非标 API 兼容问题——大肥鱼桌宠昨晚开源后第一个 bug 就这样被一位用户的 Codex 当场解决，对接小众 API 的人值得看这个案例。<span class="mention">@细心的熊猫</span> 把 Jev 类比为 LLM 世界的 LISP，论证结构化输出天生可并行，这个视角比昨天的新闻本身更值得消化。<span class="mention">@80-HD</span> 测出 ChatGPT 6 Pro 聊天版的参数知识远落后于当前日期，付了 Pro 钱的人建议自查。

## 行业新闻

### Cloudflare Union Alpha 多模型融合

<span class="mention">@睿智的北极熊</span> 贴出推文：Cloudflare 首款隐秘模型 Union Alpha 已在 AI Gateway 上线。文档显示它并非单一模型，而是每次请求并行调用多个语言模型，综合成一个答案后通过统一 API 返回，支持文字和图片输入。发帖者此前连续使用几小时后就怀疑回复来自不同模型，还专门补了评论猜测后台在做路由，后在文档中找到了多模型融合的明确描述。目前尚不清楚具体调用了哪些模型、谁负责最终整合，以及正式上线后能否维持当前的表现与价格。

### Mac Studio M5 Ultra 跑分泄漏

<span class="mention">@细心的熊猫</span> 转发了 omlx.ai 上疑似 [Mac Studio M5 Ultra（80 GPU Core）跑分数据](https://www.xiaohongshu.com/discovery/item/6aacad63000000001103af58?app_platform=ios&app_version=9.46&share_from_user_hidden=true&xsec_source=app_share&type=normal&xsec_token=CBSRwqUdHzZz8iDmYPCXWBvJfFTSRCRJjiWdpxPvNRemk=&author_share=1&xhsshare=WeixinSession&shareRedId=NzpIMUhGST1IO0g2TT4xPUhGS0g9Nj8_&apptime=1789703737&share_id=4aef90c379364f689417974807bd405f)。<span class="mention">@今天群内信息量极大</span> 粗算后发现 M5 Ultra 单路解码约 50 tps，而此前实测过的 5060 Ti 单卡约 90 tps，苹果旗舰跑推理还不如一张中端显卡。<span class="mention">@细心的熊猫</span> 不确定跑分是否开了 MTP，同时科普了根本原因：decode 是内存带宽瓶颈而非计算瓶颈，27B FP8 模型权重约 27GB，每生成一个 token 就要把权重从显存完整读一遍，带宽决定速度上限；prefill 则是计算瓶颈，因为多 token 可以并行。<span class="mention">@天真的浣熊</span> 另补了一个市场数据：5090 在美国已炒到六千美元。

## 工具

### 大肥鱼桌宠开源

延续此前进展（[「大肥鱼即将开源」]({{ '/daily/2026/09/15/daily/#大肥鱼即将开源' | relative_url }})），<span class="mention">@搞仁义毛义仁</span> 昨晚正式开源了 [FatFishFairy](https://github.com/vczh/FatFishFairy)。项目是 Windows 桌面精灵，持续截屏送视觉模型生成描述，再由角色模型以聊天气泡回应。内置三个主题（萝莉、长大的女仆、纳垢灵），各有独立动画和性格；安全护栏是 agent 只能读写指定的本地文件夹。隐私风险在于屏幕截图会上传到配置的远端模型，作者建议只连本地自部署 LLM。

<span class="mention">@热情的狮子</span> 装上了傲娇版本，在记事本里骂她「大笨蛋」，桌宠立刻暴跳如雷。他打算 fork 一份，等 reset 后让 Astra 移植 Mac 版再 contribute 回来。目前视觉模型用的是 DeepSeek V4 Flash Vision Exp，朋友的 4.1 版还没跑起来。整个项目被作者形容为「纯 vibe coding，完全不知道 Astra 是怎么实现的，反正能跑」。

![大肥鱼傲娇版本在桌面上对记事本中的挑衅暴怒回应](/assets/img/daily/2026/09/2026-09-17-01.webp)

开源当天就有用户提 issue：连不上阿里云的 Qwen API。<span class="mention">@搞仁义毛义仁</span> 让那位用户的 Codex 去学习他的[技术博客](https://vczh.net/Blog/CDB/)，Codex 很快排查出阿里云 API 与 OpenAI 协议在细节上的差异，桌宠当场上线。非标 API 的兼容问题不需要人肉逆向，一篇文档就够 Codex 自行解决。

### ChatGPT-Codex 桥接与额度复用

延续昨天的 MCP 省额度思路（[「MCP 桥接 Web Pro 省 Codex 额度」]({{ '/daily/2026/09/16/daily/#mcp-桥接-web-pro-省-codex-额度' | relative_url }})），昨晚 <span class="mention">@热情的狮子</span> 找到了两个已有的开源实现。[codex-with-chatgpt](https://github.com/XiaoDuoYa/codex-with-chatgpt) 走 Computer Use + MCP 双层架构：控制面在 Codex 和 ChatGPT 之间交换极小的 C2C 状态消息（INIT → PLAN → EXECUTED → REVIEW → DONE），数据面走 9 个只读 MCP 工具让 ChatGPT 自行拉代码、查 diff 和测试结果做独立 review；写、删、shell 工具在服务端根本不存在，安全边界较硬。另一个 [WebCodex](https://github.com/yyjeqhc/webcodex) 更通用，把本机开发环境通过 MCP/HTTPS 暴露给任意云端 AI agent，仓库不需要搬到托管工作区。

<span class="mention">@稳重的海豚</span> 今早想通了更大的用法：只要把各种自动化任务的 API 包装成 MCP Server，全都可以交给 Web 6 PRO 去跑，因为 Pro 聊天和 Codex 额度分池计算。他算了一笔账：一个号一周约两百个 turn，一个 automation 每六小时触发一次一周也才二十多个 turn，余量充裕。<span class="mention">@开朗的企鹅</span> 确认思路可行但提醒 turn 数有上限。<span class="mention">@活泼的树懒</span> 总结为「要学会榨干一个 Codex 20x PRO」。

### Qwen 3.8 27B 压至 6GB

<span class="mention">@今天群内信息量极大</span> 转发了 PrismML 推出的 [Qwen 3.8 27B 第二代量化版本](https://www.xiaohongshu.com/discovery/item/6aacaf800000000029012124?secondshare=weixin&share_from_user_hidden=true&appuid=&apptime=1789705670&share_id=7bb587cd5cfc433fa421173e63588158&xsec_source=h5_share&xsec_token=CBQ5NsZx9dT6bMH0UnCiX5ymu25zaOlERZcjBMZJs7hOw%3D)，权重仅 6GB。M2 Pro 16G MacBook 上实测 13–14 tps，以往同尺寸 Dense 模型在这个配置上几乎跑不动；对 4090/5090 用户意味着更多显存留给长上下文。<span class="mention">@细心的熊猫</span> 对附带的 benchmark 持保留态度——Qwen 3.6 与 3.8 本就只差几个百分点，来源不明的评测「得抱着怀疑的态度」。

## 方法论

### Jev：LLM 的 LISP

延续昨天的讨论（[「Jev：JSON 判断不靠自回归」]({{ '/daily/2026/09/16/daily/#jevjson-判断不靠自回归' | relative_url }})），<span class="mention">@细心的熊猫</span> 今天给出了更深层的技术解读。核心类比：Jev 之于 LLM，相当于 LISP 之于 Python。LISP 程序结构天生可并行，Jev 则通过规范化输出为 JSON schema，让原本需要逐 token 串行生成的结构化判断变为可并行计算。

> <span class="mention">@细心的熊猫</span>：如果自然语言是一种新的编程语言，LLM 是一种新的编程语言解释器，那么 Jev 跟 LLM 的关系相当于 LISP 和 Python

<span class="mention">@搞仁义毛义仁</span> 指出实用局限：Jev 不能自由说话，仍需 LLM 给它提问，「有点脱裤子放屁」。<span class="mention">@细心的熊猫</span> 反驳说 intelligence 有多种表现形式，decision making 本身就是智力的一种，不一定非得做 extrapolation。<span class="mention">@敏锐的海狸</span> 看到了更实际的场景：trading 需要从一连串因子瞬间给出买卖决策，Jev 的速度优势在毫秒级交易中价值巨大。<span class="mention">@洒脱的猫头鹰</span> 追问是否已开源，目前仅开放 API。

<span class="mention">@细心的熊猫</span> 还翻出一篇 [2025 年 3 月的 SalesRLAgent 论文](https://arxiv.org/abs/2503.23303)，认为是类似思路：用 RL 模型对销售对话做逐轮转化预测，推理仅 85ms，但一年前发表时完全无人关注。

### GPT-6 Pro 不是 GPT-6

<span class="mention">@80-HD</span> 在手机端 ChatGPT 6 Pro 上做了一个参数知识测试（关闭搜索和 memory）：知识截止日期是 2025 年 12 月，已知最新 Claude Opus 是 4.5（2025 年 11 月），2026 年 2–4 月的框架发布一概不知。他据此判断按截止日期看应该是 5.5。同样的问题发给 Codex，三题全部回答「I don't know」。

> <span class="mention">@80-HD</span>：聊天狗屁通的 6 Pro 不是真的 6 啊

<span class="mention">@稳重的海豚</span> 验证了体感：「脑子没 Fable 好用，感觉是弱智版。」Pro 订阅用户在聊天场景拿到的模型很可能不是宣传的旗舰。

### AI 屎山加速论

昨晚 <span class="mention">@乐观的兔子</span> 分享了一篇[小红书文章](https://www.xiaohongshu.com/discovery/item/6aa5f8d2000000000f039800?app_platform=ios&app_version=9.46&share_from_user_hidden=true&xsec_source=app_share&type=normal&xsec_token=CB9IG42FQdMT2vkerNOPEZqVyYyeJvIKIJ2H-W6CKPutM=&author_share=1&xhsshare=WeixinSession&shareRedId=ODY7MTlJODk2NzUyOTgwNjY0OTc0O0pB&apptime=1789624364&share_id=a518649b84be4c7a82bc3bd1bdaca87d)：一位三年经验的工程师两周靠 AI 辅助提了 47 个 PR，代码量相当于作者五年前一个季度的产出，但作者的反应不是高兴而是慌。文章主张让 senior 做 reviewer 兜底逻辑，<span class="mention">@乐观的兔子</span> 觉得「不太现实」。

<span class="mention">@搞仁义毛义仁</span> 直接劝摆烂：「只有你 review，别人不 review，也没有意义，大家一起加速。」他搬出《人月神话》类比——搞炸了下一代人自然会重视的，又补了一个现实例子：自从某大厂把 AI utilization 写进 perf，系统更新每个月都出大新闻。<span class="mention">@沉稳的仓鼠</span> 总结更冷峻：「AI 屎山加速爆发，痛苦的只有在乎的人。不在乎就相互扔屎就完事了。」<span class="mention">@沉稳的兔子</span> 次日补刀：「主要是在乎也不一定就能来钱。」
