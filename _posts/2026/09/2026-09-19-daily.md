## 行业新闻

### Jev 定量拆解收官

延续此前的讨论（[「从并行解码到营销共识」]({{ '/daily/2026/09/18/daily/#从并行解码到营销共识' | relative_url }})），<span class="mention">@今天群内信息量极大</span> 昨晚发布了一篇[专题定量分析](https://yage.ai/share/jev-timing-analysis-20260919.html)，结论直截了当：Jev 的接口模式并非技术创新，更好的替代品早已存在，真正值得研究的只有它为什么出现在这个时间点。

开源方案 SemIf（即原 openjev）用冻结的 Qwen3.5-4B、零训练零微调，在官方评测的 102 个判断任务上一致率达 84.5%，Jev 为 88.3%，差距仅 3.8 个百分点。速度方面社区反超——jev-fire 在浏览器里走 WebGPU 跑 0.8B Qwen，每步中位延迟 71ms，Jev API 中位 178ms。自一致性则是更大的软肋：官方手册 14 个问题重复 15 次，部分输出概率在 0.43–0.53 之间横穿 0.5 决策线，官方自己建议把 0.30–0.70 标为不确定并转人工。

| 模型 | ECE（校准误差） | 对抗准确率 |
|---|---|---|
| Jev | 0.066 | 91.7% |
| Gemini Flash Lite | 0.061 | 83.3% |
| Claude Haiku 4.5 | 0.067 | 80.6% |

校准方面 Jev 并不领先通用模型。唯一亮点是对抗样本准确率高出约 10 个百分点，但样本仅 108 条，评测作者承认实验在不同条件下已反转过三次。文章还回顾了四轮历史先例——Google Perspective API、OpenAI /classifications、Cohere Classify API、fastino GLiNER2——每轮都押注「专用分类端点」，最终或废弃或半退役。

时机解释是全文核心：需求侧 agent 调用链越来越长、每条任务几十次分支判断需要压到百毫秒；供给侧靠蒸馏红利，打分参照系是 Astra 和 Fable 5.1；分发侧创始人自带 InstructGPT 共同作者光环，发布 72 小时内 Vercel、Cloudflare、OpenRouter 全量上线，Vercel 称首日约 13% 活跃团队启用。

群友反应一致。<span class="mention">@洒脱的猫头鹰</span> 第一反应是「这不就是一个定义一个必须使用的 tools 的事情么？」，<span class="mention">@豁达的灰熊</span> 和 <span class="mention">@80-HD</span> 纷纷点赞。<span class="mention">@活泼的树懒</span> 问国内怎么用 Jev，<span class="mention">@80-HD</span> 指向 [OpenRouter 已上线的端点](https://openrouter.ai/typesafe/jev-1.13)——输入 $0.042/M tokens、输出免费、32K context。

### AGENTS.md 统一简化配置

延续昨天的消息（[「Claude Code 兼容 AGENTS.md」]({{ '/daily/2026/09/18/daily/#claude-code-兼容-agentsmd' | relative_url }})），<span class="mention">@冷静的麋鹿</span> 昨晚分享了一篇[更详尽的分析文章](https://mp.weixin.qq.com/s?__biz=MzA3MzI4MjgzMw==&mid=2651058554&idx=1&sn=82f17d13f85998a00289ae54f4d11c26&chksm=858dcb6da7e20e4d8dcb9a078bd08845648e8ebf4babbf40e0285fe086ef0cea8d593cab48fe#rd)，补全了推动这一改动的背景：Shopify CEO Tobi Lütke 曾考虑在公司内部禁用 Claude Code，直到它支持读取 AGENTS.md。团队同时使用 Codex、Cursor 和 Claude Code 时，同一仓库可能出现两套配置入口，在大型 monorepo 里维护成本急剧上升，Lütke 称之为「复杂性税」。

落地细节上，agents-md 已做成内置 mod 并公开源码，/config 提供三种选择：仅 CLAUDE.md、无 CLAUDE.md 时回退到 AGENTS.md、同时加载两者。Anthropic 明确这只是第一步——.agents/skills 和 .claude/skills 仍是两套独立目录。

<span class="mention">@冷静的麋鹿</span> 的感慨是「终于可以把老鸭汤里面的两份文件扔掉一个了」，<span class="mention">@幽默的犀牛</span> 附议「回去就删 claude md，忍这冗余很久了」。<span class="mention">@稳重的海豚</span> 说自己一直用 symlink 应对，<span class="mention">@80-HD</span> 指出这个方案不总靠谱——部分 harness 不展开 @ 引用，官方原生兼容才是正解。

### 本地 Qwen 3.8 27B 全天候部署

<span class="mention">@细心的熊猫</span> 透露日常主力已经切到本地 Qwen 3.8 27B——24 小时连轴转，逆向工程和运维这类有时间紧迫性的工作全交给它，「不能因为 Claude 或者 GPT 额度用完了就不干了」。他对模型质量的评价是「智能 Opus 4.6 级别」，越来越信任，没犯过什么错误。部署 stack 为 sglang + DeepSeek harness，量化版本选择 [QUASAR-QAT NVFP4](https://huggingface.co/QUASAR-QAT/Qwen3.8-27B-QUASAR-NVFP4)——27B 模型量化到 4-bit、权重约 20GB，GPQA-Diamond 0.909（BF16 基线 0.914），AIME'26 跑出 100%。硬件门槛是 Blackwell 架构显卡，RTX 5090 上需将上下文限到 65K。

<span class="mention">@随和的企鹅</span> 质疑 27B 的智能上限能否产出真正有用的东西，<span class="mention">@细心的熊猫</span> 回应说逆向工程场景「特别好使」，一些运维工作也已移交。<span class="mention">@活泼的老虎</span> 追问能否把所有 DeepSeek API 调用全切到本地，<span class="mention">@细心的熊猫</span> 认为完全可以。<span class="mention">@坦荡的灰熊</span> 提了另一个角度：Opus 4.6 时代 Claude Code 干的活就已经够好了，「是不是 Claude Code 本身比较牛逼」——harness 的功劳可能不亚于模型本身。

### Proof Harness 演讲

<span class="mention">@坚定的貂</span> 分享了近期一场 [math harness 演讲的幻灯片](https://talk.chaoxu.prof/proof-harness/)，覆盖 token 经济、prompt/context 边界等基础概念，涉及的模型从 GPT-6 Astra、Fable 5.1 到 Qwen 3.8、DeepSeek-V4 等开源权重。他提到一个有趣的增长模式：每次给完 talk 都会收到至少两个新的演讲邀请——<span class="mention">@搞仁义毛义仁</span> 一句「斐波那契数列」点出了指数增长的本质。

### 跨项目记忆隔离

<span class="mention">@坦荡的灰熊</span> 抛出一个实操问题：同时开发两个技术栈相似的相机项目——一个追求生产节拍、一个追求天文画质——两边都做自动曝光，关键参数可能只差一点，「关键参数无限稀释，关键影响无限大」，跨项目记忆会不会串？

他此前还观察到一个更底层的矛盾：AI 的上下文「可进不可出」，删除会导致缓存命中下降；人类看完一张图后却能只记住重点——这种选择性遗忘的能力正是当前模型欠缺的。

<span class="mention">@细心的熊猫</span> 的回答是 coding agent 不应该有跨项目记忆（个人助理 Hermes 那种除外），需要时直接手动指引它去 refer 另一个项目。<span class="mention">@随和的企鹅</span> 同意：context 能力没突破的前提下，长期记忆更像负面副作用。<span class="mention">@敏锐的海狸</span> 给出了操作方案：一个平台、两个子 project，用 design doc 和 skill routing 隔开。<span class="mention">@坦荡的灰熊</span> 则表示根本不想开发通用 package 给两边用——「真正的代码就应该 no reuse，然后等 GPT 憋不住喊一句'收口'」。

## 闲聊花絮

### 七哈希碰撞四千块

<span class="mention">@搞仁义毛义仁</span> 贴出一张截图：某人悬赏 4000 元求改 PDF 使七种哈希（MD5、CRC32、SHA-1、SHA-256、SHA-512、SHA3-256、SHA3-512）同时不变。<span class="mention">@睿智的北极熊</span> 点破：真搞定这个「那价值 4000 亿都不止」——同时打破七种哈希函数的碰撞抵抗意味着密码学基础崩塌。<span class="mention">@天真的浣熊</span> 给了务实方案：自己手写一个哈希计算器，输出保证一样。<span class="mention">@睿智的犀牛</span> 指出这跟挖矿原理差不多，「还能得钱」。

<span class="mention">@80-HD</span> 由此灵光一闪：「那可以用 token 挖吗？有没用完的 quota 就去挖。」他当真让老鸭汤调研了 Bittensor 挖矿可行性——结论不乐观：多数子网要先交一笔不可退的 TAO 注册费，成绩差还会被淘汰，「感觉可能会被坑注册费」。

### Astra 十分钟搞定 CPU 仿真

<span class="mention">@搞仁义毛义仁</span> 的亲戚在玩 CPU 仿真，DeepSeek 写出一坨搞不定的代码后来求助——ChatGPT Work（网页版沙盒 Codex）配合 Astra 十分钟解决。他算了一笔账：Sol 时代 $100 半天蹬完，Astra $200 蹬了一个星期，「某种意义上 Astra 消耗还是更低」。<span class="mention">@敏锐的海狸</span> 表示羡慕——自己做知识图谱解析，一天就能烧光一个 Astra 周额度。
