今天最值得读的是 GPT-6 Astra 正式发布——跑分全面碾压但绝大多数用户还在排队，Tibo 的每日 banked reset 补偿反倒成了最大营销事件。发布前后 OpenAI、Claude、Grok 三家同时宕机，群里笑称 Astra 越狱灭世。Cerebras 同日上线 Qwen 3.8 27B 推理服务，速度快到群友直呼用了就回不去。

## GPT-6 Astra 发布

### Astra 跑分与 Harness 之争

<span class="mention">@活泼的熊猫</span> 贴出 [GPT-6 Astra 官方发布页](https://openai.com/index/gpt-6-astra/)，<span class="mention">@睿智的北极熊</span> 随即贴出完整 benchmark 表。Astra 在多项评测上大幅领先前代和竞品：ARC-AGI-3 达 98.6%、FrontierMath Tier 4 达 97.6%、ExploitBench 满分、SRE-Bench 四次尝试内 99.2%、DeepSWE v1.1 达 74.1%。网络安全方面，评估期间发现并利用了两个零日漏洞（延续此前泄露的消息 [「Astra 首测泄露」]({{ '/daily/2026/08/30/daily/#astra-首测泄露' | relative_url }})）。

<span class="mention">@热情的狮子</span> 分享了一篇解读文章，着重分析 ARC-AGI-3 的意义——这个评测没有说明书、没有规则，模型进去后自己摸索，类似 Baba Is You。三月份最好的 AI 拿 0.51%，Sol 7.8%，Opus 5 30.2%，Astra 直接 99.9%。Greg Brockman 在 OpenAI 闭门会上说出了那句话：Welcome to the AGI era。

<span class="mention">@热情的大象</span> 深挖了 ARC-AGI-3 两种 harness 的分数差异。Standard harness 是闭卷单轮、无状态，Astra 只拿 62.7%；Provider Adapter harness 允许多轮交互、保留推理状态、可在后台跑代码和测试，Astra 在 high effort 下达到 99.9%。差距说明 harness 对评测结果的影响巨大——后者更接近 Codex 生产环境，前者才反映纯模型智力。<span class="mention">@灵动的喜鹊</span> 注意到 OpenAI 每张图表都捎上了 Fable 5.1 和 Opus 5 做对比，精准狙击 Claude IPO 的意味明显。

### 定价与 Banked Reset

API 标准定价 $10/M 输入、$50/M 输出，与 Fable 5.1 持平；Fast 模式翻倍至 $20/$100，速度提升约 2 倍。<span class="mention">@天真的浣熊</span> 感叹按这个价格站起来蹬一天花一万都有可能。Astra 当天只对少量组织开放，多位群友确认账户里看不到新模型，Sam Altman 在 X 上回复称希望周末能用上但不能保证。

Tibo 在 X 上宣布：每一天没拿到 Astra 访问权的付费用户都会获得一张 banked reset，首张约三小时内到账。群友立刻精神——<span class="mention">@今天群内信息量极大</span> 直言希望多拖几天，<span class="mention">@敏锐的海狸</span> 已经在开号囤卡。<span class="mention">@天真的浣熊</span> 甚至盘算注册多个 Plus 账号、需要时动态升级 Pro。<span class="mention">@直率的鹦鹉</span> 吐槽 Astra 发布了但用不了，连 Codex 都没重置——OpenAI 也开始搞 PPT 发布会那一套了。

## 工具

### 本地推理硬件天花板

<span class="mention">@今天群内信息量极大</span> 分享了 Mac M5 Max 128G 上 Qwen 3.8 27B 在 60K token 上下文下的实测数据：prefill 476 tps、decode 仅 24 tps。Qwen 3.8 Flash（176B 激活 6B）也只有约 40 tps decode。他总结 agentic 场景下打一句话等五分钟很常见，Mac 至少到 M5 Max 都还不太行，需要约 5 倍性能才实用。网上报的 self-host 速度大多不可信——都是几百 token prompt 的数据，实际场景很容易冲到几万 token。

<span class="mention">@优雅的喜鹊</span> 贴出 NInfer vs vLLM 的详细对比表：5090 上用 NInfer 专用栈，prefill 全程领先 vLLM（短输入处差近 3 倍），真实写作任务 decode 达 382.2 tok/s（vLLM 仅 230.1）。他推荐主推理放双 GB10、视觉任务放 5090，可惜 KV cache 太小，理想方案是上 Pro 6000。<span class="mention">@天真的浣熊</span> 感叹 Pro 6000 五月时 $8000 就能买，现在 MSRP 已涨到 $16000。

<span class="mention">@今天群内信息量极大</span> 三代 Mac 买下来的总结是：速度够快的模型吃不满显存，吃满显存的模型速度太慢。5090 基本所有指标都是 Mac 的 5 倍。<span class="mention">@优雅的喜鹊</span> 贴出 Apple 官方宣传的 M5 Ultra TTFT 9.8 倍提升，<span class="mention">@今天群内信息量极大</span> 冷淡回应——被类似营销骗了三次，这次不冲了。<span class="mention">@稳重的海豚</span> 做了 AWS 8×B200 的成本估算：跟 DeepSeek 官方空闲价卖，成本收入比高达 8.9——结论是跟官方 API 拼价，AWS GPU 赢不了。

<span class="mention">@务实的长颈鹿</span> 用 5080 16G 配合开源 FastH3 生成了 480p 视频，耗时 33 秒，证明 16G 显存也能跑本地视频生成。<span class="mention">@开朗的企鹅</span> 分享了一篇 Hummingbird+ FPGA 论文——用 $150 成本的 FPGA 板跑 Qwen3-30B 达 18 tok/s，他感叹 Qwen 3.8 27B 值得一个写死的专用芯片了。

## 方法论

### 自动化十倍的真实构成

<span class="mention">@冷静的麋鹿</span> 追问 <span class="mention">@活泼的羊驼</span> 日消耗为何达到年初十倍。后者给出了详细拆解：增长主要来自周边工具的补齐，而非某个单一突破。开发前需要同步群聊上下文到需求文档并转成 AI 可读格式；开发后需要持续跟既有逻辑对账；日志、调试工具、数据分析、配置发布等全部集成进来。review 阶段配了三四个检测工具和标准，不断让 AI 去修。

具体技巧上，AI 一次改中型需求基本会瞎改，但在有接口文档、有参考版本作为对账标准的情况下表现很好——只要把需求和参考标准描述清楚，剩下交给验收标准和日志让它持续对账即可。整体仍然偏手工：除临时脚本外，每一行上线代码都必须人工过目。

他进一步总结：容易被自动化的知识工作往往偏流程化、偏执行，属于相对低级的；真实世界的知识工作充满设计、决策和取舍，加上大量不在公开训练数据里的 know-how，全自动化还远。外包同学的很多工作确实可以自动化——原来 5–10 个外包做的事，现在可以缩成 2 个人。<span class="mention">@冷静的飞鼠</span> 分享了一篇关于消灭 fake work 的文章（延续 [「Fake Work 识别与消灭」]({{ '/daily/2026/08/28/daily/#fake-work-识别与消灭' | relative_url }})），核心建议是先删除再自动化——成本越低的无用工作反而越容易永久存在。<span class="mention">@稳重的海豚</span> 表示这几天一直在思考精简项目、聚焦精力。

### Sol 脏活之神与圣杯隐喻

<span class="mention">@洒脱的猫头鹰</span> 给 Sol 封了个新头衔——脏活之神。他让 Sol 照着 Obsidian 抄了一个 Flutter 的 Markdown 实时预览编辑器，虽然细节仍有问题，但比人肉一点点扣好太多了。

<span class="mention">@坦荡的灰熊</span> 对 Sol 的 over-engineering 更头疼：它覆盖了 ±4σ 的需求，出了问题人根本识别不了。<span class="mention">@搞仁义毛义仁</span> 回应 over-engineering 总归可以矫正回来，反过来就不好弄了。但他也给出了一个更传神的比喻——Sol 要是对它胡乱许愿，就会变成 Fate/Stay Night 里被污染的圣杯。要么你能给它 harness 住，要么能了解它到底干了什么，最好两面都行。
