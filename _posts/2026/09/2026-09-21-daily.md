M5 Ultra 评测解禁，Flash-Next 的 prefill 和生成速度让本地跑 AI agent 从画饼变成日用级体验——对额度焦虑的人来说又多了一条硬件出路。Jev 的一周祛魅也在今天画上句号：几百题 bench 显示置信度校准在难题上完全失效，群内由此引出一个更底层的结论——训练最好的分类器就得先训练一个会聊天的 LLM，Jev 走的路从根上不通。

## Jev 终章

### 开源一周全面追平

延续连续五天的讨论（最近一篇见昨天的 [「叙事陷阱识别框架」]({{ '/daily/2026/09/20/daily/#叙事陷阱识别框架' | relative_url }})），<span class="mention">@今天群内信息量极大</span> 下午分享了社区做的几百题 Jev Bench 结果。在困难类别里，Jev 最引以为傲的置信度校准基本失灵：答对与答错的题目平均 confidence 仅差 0.006，等于没有区分度。准确率方面 DeepSeek V4.1 Flash 以 95% 碾压全场，开源的 reflex-27b（基于 Qwen 3.8 27B、直接读 tokenwise 概率取均值、不做微调）也以 76% 超过了 Jev 的 74%。V4.1 Flash 延时和成本约为 Jev 的三倍，但它是远大于 Jev 的完整 LLM；需要更快更便宜就直接上 reflex-27b，更灵活、可定制。

> <span class="mention">@今天群内信息量极大</span>：感觉截止 JEV 发布一周内，基本上开源复现已经在所有维度超越，或者说至少追平 JEV 了。包括精度，概率校准，成本，速度。

所有超越 Jev 的开源方案都不复杂——不微调，直接用现有权重加 JSON mode。他的最终评价是「教科书级别的包装和 marketing 推流（褒义）」。<span class="mention">@细心的熊猫</span> 把 Jev 类比为超市里的洗发水：根本分不清谁家好，就看包装设计了。<span class="mention">@冷静的飞鼠</span> 同日分享了一篇[小红书复盘](https://www.xiaohongshu.com/discovery/item/6ab0a97400000000260233e5?app_platform=ios&app_version=9.47.2&share_from_user_hidden=true&xsec_source=app_share&type=normal&xsec_token=CBOGUrVTdhC7rRGL7_5XmdhwYeIK31rlQNNF4pm06AeO4=&author_share=1&xhsshare=WeixinSession&shareRedId=ODhDNDM3NT02NzUyOTgwNjc8OTk5ODxC&apptime=1790004189&share_id=773c9f8629f745c88a3371199360b523&track_code=7GPKAf0GSVy)，拆解 Jev 如何在一天内打造出全球性 AI 营销。

> <span class="mention">@聪明的水獭</span>：别管我对不对，就问你快不快吧

### 分类器终究要回到语言模型

<span class="mention">@倔强的貂</span> 提了一个方向性问题：只做判断、不做聊天，到底是不是一条有效的模型发展路线？<span class="mention">@今天群内信息量极大</span> 的回答很直接——回看 NLP 十几年的趋势，训练分类器最好的方式就是先训练一个会聊天的模型，再拿去做分类，后者碾压前者。

> <span class="mention">@今天群内信息量极大</span>：如果你最终目标是想弄一个分类器做判断。那有两种途径。第一是，我就训练一个分类器。第二是，我先训练一个 LLM 让它会聊天，然后用到分类任务上去。后者的精度会碾压前者。这是最近十年可能最大的发现。

<span class="mention">@豁达的河马</span> 解释了原因：LLM 做分类强过 encoder 分类器，是因为学到的知识更多，可以直接 zero-shot，而 encoder 需要 finetuning adaptation。<span class="mention">@开朗的企鹅</span> 沿这条线展开：分类准确的核心是理解，越复杂的问题越需要理解后才能判别。他认为快已经不是未被解决的问题（Flash 很快、千问小模型也很快），真正未解决的是 uncertainty 的量化——知之为知之，不知为不知。

由此引出的推论是：类 Jev 的方案只能简化输出、提升效率，但 LLM 的一部分准确度来自思维链的校准过程，跳过就是在放弃准确度。至于 Jev 为何仍能出圈，<span class="mention">@今天群内信息量极大</span> 揭示了它的营销做减法：如果如实说「我们的模型比 Qwen 4B 快、比 Qwen 0.5B 慢、精度相当于 Qwen 27B」就泯然众人——宣称不做聊天只输出 JSON、这是 system 1 model、全新范式，才有了话题性。

### 游戏评测与实用甜区

延续昨天的对战实验（[「Jev 花式应用场景」]({{ '/daily/2026/09/20/daily/#jev-花式应用场景' | relative_url }})），<span class="mention">@洒脱的猫头鹰</span> 正式发布了 [Agent Arcade Lab](https://github.com/robinfai/agent-arcade-lab) 项目和[评测分析文章](https://robinfai.github.io/blog/posts/jev-game-benchmark/jev-game-benchmark/)。核心发现是社区流传的 Jev 游戏高分基本由程序代做：号称 14300 分的俄罗斯方块项目，源码会先用固定公式算出最优落点再把答案喂给 Jev；贪吃蛇项目则把决策拆成九次局部判断后由程序组合。去掉辅助让 Jev 独立决策，俄罗斯方块六局全部零分（分别在 109–181 步堆顶死亡），贪吃蛇六局跑满步数但得分远低于纯程序基线。不过 API 成本确实低——24 小时处理 1100 万 token 只花了 $0.43。

尽管如此，几个窄场景仍然成立。<span class="mention">@冷静的麋鹿</span> 在自家数据分析 agent 中实测了 100 道业务分类题（将用户查询归到信用卡、理财通等六档），准确度很高、延迟约 1.7 秒、单次不到 $0.00004，明显优于此前用 LLM 端到端判断的方案，但他同时表示不会长期依赖闭源 Jev，打算部署本地小模型替代。<span class="mention">@搞仁义毛义仁</span> 提了个更轻量的场景——用 Jev 排列输入法默认选项，「选错了也没关系，只需要快」。<span class="mention">@细心的熊猫</span> 认为做用户 prompt 的 guardrail 也合适。<span class="mention">@洒脱的猫头鹰</span> 一句话给一周的讨论画了个句号：「Jev 准确率大于 random()。」

## 行业新闻

### M5 Ultra 评测解禁

<span class="mention">@细心的熊猫</span> 分享了 MacStories 发布的 [M5 Ultra Mac Studio 评测](https://www.macstories.net/stories/m5-ultra-mac-studio-review-the-dream-mac-for-local-ai-agents/)（256GB 统一内存版），评测者用 DeepSeek V4 Flash 加 olmOCR 组成的 agent 团队在上面 24/7 跑了 99 天，总成本 0 美元，称其为「本地 AI agent 的理想机器」。

硬件上 M5 Ultra 首次采用四 die UltraFusion 封装，80 核 GPU 每核带一个 Neural Accelerator，AI 峰值算力为 M3 Ultra 的 4.5 倍，统一内存带宽从 819 GB/s 提升至 1.2 TB/s。Flash-Next（MoE）的提升最为显著：

| 指标 (Flash-Next) | M5 Ultra (256GB) | M3 Ultra (512GB) |
|---|---|---|
| 生成 (tok/s) | 108 | 70 |
| Prefill 16K (tok/s) | 2,887 | 1,143 |
| TTFT 16K (s) | 5.6 | 13.9 |

256GB 内存下能并发跑三个带 subagent 的 Flash-Next 会话，这是 5090 的 32GB VRAM 做不到的。稠密模型 Qwen3.8 27B 跑同一批 prompt 时加入 RTX 5090 对比：

| 指标 (Qwen3.8 27B, 8K) | RTX 5090 (32GB) | M5 Ultra (256GB) | M3 Ultra (512GB) |
|---|---|---|---|
| Prefill (tok/s) | 3,031 | 1,701 | 414 |
| Decode (tok/s) | 59 | 48 | 31 |
| TTFT (s) | 2.0 | 4.0 | 15.4 |

群内对表中 5090 的数字持保留态度。<span class="mention">@优雅的喜鹊</span> 指出评测没有开 NVFP4 量化，「5090 不用 NVFP4 等于白测了」——他实测 NVFP4 下 8K prefill 可达 8000 tok/s、decode peak 220 tok/s，比上表高出一个数量级。<span class="mention">@今天群内信息量极大</span> 也觉得 59 tok/s 不正常，期望在 100–120，怀疑是推理引擎配置问题。<span class="mention">@细心的熊猫</span> 的策略是两者兼备：5090 跑稠密模型，M5 Ultra 跑 MoE，计划把现有 4× 5060 Ti 改成 MiniMax H3，LLM 专跑 M5 Ultra。他同日从沃尔玛以 $4299 自营价抢到一台 5090 整机，已发货。

## 方法论

### 理解债：工作不再教你学

<span class="mention">@热情的大象</span> 分享了一篇[系统方向研究者的博客文章](https://unik-lif.github.io/blog/posts/when-work-no-longer-teaches.html)，核心观察是 AI 正在把「完成任务」和「获得理解」拆开。作者自述靠 Codex 等工具进入了以前不敢承诺的大型代码库（BOOM、FireSim），修改能跑通 smoke test，但做完之后并不觉得下次会更快——被省掉的不只是机械劳动，还有附着其上的学习。他将这种欠账称为「理解债」。

结构性问题在于机会的复利可能跑在理解的复利前面：借助 AI 更快交付的人拿到更多项目和反馈，停下来还债的人在短期评价体系里反而更慢。教学一线的观察印证了这一点——学生用 AI 做作业几乎零错误，但考前讲一道更简单的往年题仍有人拿手机拍照；小组大作业代码写完、演示能跑通，却找不到一个愿意上台 presentation 的人。缺的不是敢上台的人，是真正理解项目的人。作者区分了两类用户：对专家来说 AI 放大已有心智模型，对初学者来说 AI 可能让心智模型在形成之前就失去训练机会。

> <span class="mention">@热情的大象</span>（引用原文）：AI 没有消灭复利，却可能让机会的复利跑在理解的复利前面，并进一步决定谁还有资格继续学习。

<span class="mention">@坦荡的灰熊</span> 的评论是「AI 成了一个 ReLU 激活函数」——达到阈值的通过并被放大，没达到的直接归零。同日 <span class="mention">@开朗的企鹅</span> 转发了一条 372.5 万浏览的推文，一位入职大公司半个月的工程师抱怨从 L1 到 L7 所有人做的事都一样——跟 Claude 说话，specs、代码、测试、PRD 全是 AI 生成，没人在读任何东西，每天工作十几小时只为按回车。Elon Musk 回复了一个词：Yikes。文章里担忧的理解债已经不是假设。
