Opus 5.5 毫无预兆地空降，两小时后 OpenAI 亮出 Sol 和 Luna，双方同日送出 reset 卡——一天三连洗牌。effort 级别怎么选被群友拆了个明白，选错档位的代价远比想象的大。<span class="mention">@豁达的考拉</span> 的迁移踩坑经验对正在 Claude 和 GPT 之间切换的人可能更实用：旧提示词在强模型上不但没用反而帮倒忙，换模型之前先清 context。

## Opus 5.5 与 Sol/Luna 双发

### Claude Opus 5.5 发布

Anthropic 无预热发布了 Claude 5.5 系列首款模型 Opus 5.5，官方称在 agent 编程、计算机使用与知识工作上刷新 SOTA，典型负载下比上一代 Opus 5 便宜 40%、输出快 30%。<span class="mention">@天真的浣熊</span> 第一时间贴出[公告推文](https://mp.weixin.qq.com/s?__biz=MzI3MTA0MTk1MA==&mid=2652728792&idx=1&sn=bf27b21cbfde97710de492bfecd83bdd&chksm=f0ac821a9d9e39b455b091990e299c7e7c7bfa68c36d5339433446de86defcbbebf9082dc078#rd)。

跑分层面，Opus 5.5 在终端操作和 agent 编程上领先明显：Terminal-Bench 4.0 拿到 66.4%，超过 GPT-6 Astra 的 57.9% 和 Fable 5.1 的 55.8%；FrontierCode v1.1 54.4% 险胜 Astra 的 53.3%；CursorBench 4.0 57.8%，GPT-5.6 Sol 只有 41.7%；知识工作 GDPval-AA v2.1 拿到 1846 Elo（Astra 1542）。Artificial Analysis 综合智能指数 max 档 58 分，居全场第一。

定价方面，输入 $4、输出 $20（均降 20%），缓存读取从 $0.50 砍到 $0.20（降 60%）。但单价降两成被思考量涨六成抵消：max effort 下每题平均输出 11.9 万 token（其中思考 8.4 万），GPT-6 Astra 同等任务只需 2.7 万，差了三倍有余。<span class="mention">@专注的剑鱼</span> 一句话概括：「为了跑分了」。不过 medium effort 下 Opus 5.5 反而非常精简——跑完整套 AA 评测只生成 38M output token，同类中位数 88M，比同行省了一半以上。

<span class="mention">@豁达的鸵鸟</span> 的体验最直接：「5.5 的讲话非常好听，开始说人话了。」<span class="mention">@热情的大象</span> 转发了一条 19 万查看的推文，Patrick Toulme 推测 Opus 5.5 是用更大的 Model-2 Mythos 教师模型蒸馏而成，是 Anthropic 内部 RSI（递归自我改进）的首个产物——这解释了它为何同时更小更便宜。<span class="mention">@活泼的羊驼</span> 对此表示怀疑。

### Opus 5.5 Effort 性价比

<span class="mention">@热情的狮子</span> 用 Claude 拉取 Artificial Analysis 数据做了一轮性价比分析，结论是 high 档是当前的甜区——从 medium 升到 high 只多花 36% 的钱，智能指数涨 3 分，是整条曲线上最便宜的一段提升。从 high 往上边际成本陡增。

| Effort | AA 智能指数 | 每任务成本 | 相对 medium | 输出速度 |
|---|---|---|---|---|
| low | 42 | $0.55 | 0.41× | 86 t/s |
| **medium** | **51** | **$1.34** | **1×** | **76 t/s** |
| **high** | **54** | **$1.82** | **1.36×** | **85 t/s** |
| xhigh | 56 | $3.46 | 2.58× | 74 t/s |
| max | 58 | $5.98 | 4.46× | — |

medium→high 每多 1 分智能指数花 $0.16，high→xhigh 涨到 $0.82（约 5 倍），xhigh→max 再涨到 $1.26。<span class="mention">@聪明的鸳鸯</span> 提醒 AA 指数混合了 Terminal-Bench、SciCode、HLE 等多种评测，「纯编码场景下 medium 和 high 的差距可能更小，建议分开看」。<span class="mention">@搞仁义毛义仁</span> 则建议按自己的项目实测——拿一批相似任务分别跑不同 effort，看从开始到返工完成的实际总耗时。

实操层面还有一个约束：Claude Code 的 ultracode 模式会自动触发 workflow，但 ultracode 锁死 xhigh effort，官方没有「medium + 自动 workflow」的开关。<span class="mention">@热情的狮子</span> 整理了几种绕路方案，最可行的是自定义 `/wf` 斜杠命令手动触发关键词，或直接在 prompt 里写 `ultracode`；hook 方案会让每条消息都强行 fan-out，反而浪费 token。

## 方法论

### Claude 到 GPT-6 迁移经验

<span class="mention">@豁达的考拉</span> 发布了一篇[从 Claude 全面迁到 GPT-6 + Codex 的踩坑文章](https://mp.weixin.qq.com/s?__biz=MzA3NjY2NzY1MA==&mid=2649742221&idx=1&sn=079d33d7e6f6d962fc406acd70d428dc&chksm=8637fa72086c56cebf79e39e64c98121c8afbe54f3be65dca38ac9bd97bdb9a490d9f483fa4f#rd)，调教 GPT + Codex 近一个月的经验浓缩为数条核心教训。

修改范围失控是最大的坑：GPT-6 对最后一条指令极其敏感，不显式限定「只改这里、其他不动」就会自行扩大执行范围——让改一句话结果整篇句式全变。子 agent 的问题更隐蔽：状态标 completed 但实际审查一个字都没做，父 agent 看到 completed 就继续往下走。429 限流的重试配置则是完全失效——源码里 Codex 压根不重试 429，直接中止任务。

更深层的教训是提示词职责变了。以前给弱模型补能力（「记得跑测试」「先想清楚」），Astra 已内建这些行为不需要提醒；但防止乱来的硬边界（「未经许可不要修改其他文件」）Astra 会当真，写「每步都停下来确认」会导致远比预期频繁的停顿。结论是该减规则而非加规则，AGENTS.md 应做路由器而非百科全书，Skill 描述越宽泛越容易选错上下文。跨模型 Skill 迁移是另一个大坑——给 Claude 写的规则直接搬到 GPT-6 上会过度约束模型。

<span class="mention">@沉稳的兔子</span> 感慨「Prompts 基本上没有可移植性……每家的个性都不一样」。<span class="mention">@搞仁义毛义仁</span> 干脆建议不混用，「就算要用也只能是 Astra 换 Fable，不能换小肥鱼」。<span class="mention">@稳重的海豚</span> 透露自己的解法：所有给人看的文字都走 Gemini key，再配上 <span class="mention">@今天群内信息量极大</span> 的 writing skill，效果好很多。<span class="mention">@豁达的考拉</span> 表示要去试。

<span class="mention">@搞仁义毛义仁</span> 补了一条更底层的观察：AI 写的文档本来就是给 AI 读的，人可能根本不想读，最后也是交给 AI——他晒了张截图，大肥鱼承认之前没读 SKILL.md 就凭自己理解改稿，「而我全做反了」。

### 不读代码的工程债

<span class="mention">@搞仁义毛义仁</span> 再次提起那位一年来坚持不看代码、纯靠 AI 搓服务的朋友——这次的更新是此人一口气买了 44 个 ChatGPT $200 Pro 账号，10 台电脑 7×24 连轴跑。Astra over engineering 不管，撸起袖子就干，最终服务根本无法在非生产环境运行；bug 太多又不敢拖，又自搓了个 oncall service 叫自己起床。

> <span class="mention">@搞仁义毛义仁</span>：如果 Knowledge 在代码里面被复制了 50 遍，那就只能祈祷每次改 feature 的时候 AI 都能准确找到

DRY 问题在文档层面同样严重——相同信息散落在不同 markdown 里，某次修改没同步所有文件，AI 只读到过时的那一半就直接跑飞。代码好歹能靠 CI 拦一道，文档没有这道防线，基本每两个 weekly 就得让 AI 做一轮精简。<span class="mention">@敏锐的海狸</span> 的应对更系统化：蒸馏同事写 design doc 的手法让 Astra 从规划阶段就 handle over-engineering，再蒸馏另一位同事的风格用 Fable 5.1 做 external review。

<span class="mention">@开朗的企鹅</span> 追问：Astra 能自己测试，为什么跑不通？<span class="mention">@搞仁义毛义仁</span> 的回答是「都是在 production 上跑的」——没有非生产环境这回事。昨天群里传过的大公司工程师吐槽帖（[「理解债：工作不再教你学」]({{ '/daily/2026/09/21/daily/#理解债工作不再教你学' | relative_url }})）今天有了新传播，中文转述版补上了评论区的一句——「我们只是 Claude 和生产环境之间的避孕套。」

### 框架偏好与小生态

<span class="mention">@细心的熊猫</span> 由 DRY 话题引出了一个更宏观的担忧：所有技术偏好——React 还是 Angular、LangGraph 还是 Pi、webhook 还是轮询——现在实际上取决于模型的训练数据。越是没人用的框架越进不了训练数据，以后越不会被 AI 选用，形成正反馈死循环。他感觉这会造成小生态的毁灭，「重担都压在了模型训练公司上了」。
