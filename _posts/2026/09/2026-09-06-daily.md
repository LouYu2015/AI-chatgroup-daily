昨晚到今天，多位群友接力用 Astra + Blender 挑战写实人脸建模，结论一致：建筑和卡通够用，人脸离商业化还远——想走这条技术路线要提前知道天花板在哪。<span class="mention">@聪明的灰熊</span> 关于决策带宽的观察值得细想：AI 能同时给出两个不错的方案，但你选 A 不选 B 的依据本质上无法传达给它。<span class="mention">@今天群内信息量极大</span> 给了 drift 修复的务实思路：让 AI 扫过去大量聊天记录来数据驱动地更新过期 skill。

## 工具

### Blender 人脸建模天花板

延续前一天 <span class="mention">@今天群内信息量极大</span> 用 Astra + Blender 做出建筑模型和卡通 VTuber 的演示（[「3D 建模一条龙」]({{ '/daily/2026/09/05/daily/#3d-建模一条龙' | relative_url }})），昨晚多位群友尝试将同一套工作流用于写实人脸，结果齐齐碰壁。<span class="mention">@神秘的企鹅</span> 用 GPT-6 + Blender + FaceBuilder 插件建 3D 人脸，贴出照片与模型对比后自评「效果不忍直视」。给多张参考图也没有改善，他判断 Blender 建模在人像上有硬上限，远不如高斯溅射（3DGS）。

<span class="mention">@开朗的企鹅</span> 提供 24 张不同角度的参考照片让 Astra 纯手搓，几个小时产出一个光头白模，被群友形容像一拳超人。换用 FaceBuilder 后正面终于能看，但侧面和发型诡异。<span class="mention">@沉稳的仓鼠</span> 也独立跑了一轮，效果类似。<span class="mention">@神秘的企鹅</span> 的总评是：这种质量给到用户，回复只会是「你他妈说这是我？」

Astra 自己对建模进度也不乐观，截图中坦言还在中前期，连再十轮能完成都没有充分把握，短板在建模执行和形体判断而非参考图数量。<span class="mention">@神秘的企鹅</span> 建议必须借助 FaceBuilder 这类专用插件做底座，从立方体开始捏人脸几乎不可能。

<span class="mention">@搞仁义毛义仁</span> 提出系统化验证思路：让 Codex 把模型渲染出来，对照给定照片的多个角度做像素级对比，把每个区域的绝对差和方差都压到阈值以内再算过关。<span class="mention">@开朗的企鹅</span> 确认 Astra 确实在做类似对比，但「感觉很准，下刀的时候不太行」。<span class="mention">@搞仁义毛义仁</span> 估计可能需要几百轮，古法 3D 建模师也是一干好几天一点点捏。

作为对照，<span class="mention">@冷静的麋鹿</span> 用 high 档配合<span class="mention">@今天群内信息量极大</span> 发布的 skill 复现了博丽神社建模，效果不错，进一步印证天花板在于人脸这种精细度极高的对象。<span class="mention">@沉稳的仓鼠</span> 提到一个有趣方向：Blender 白模 + SeedDance 可以作为 AI 视频生成的参考帧，用白模做控制而非直接做成品。<span class="mention">@今天群内信息量极大</span> 昨晚正式发布了此前 3D 实验的[详细博文与 Skill](https://www.superlinear.academy/c/share-your-projects/gpt-6-astra-3d)，涵盖爆炸视图、绑骨动捕到视频生成的完整工作流。

### Astra 各场景体感

Astra 发布后第四天，各场景体感继续分化（延续 [「Coding 与长任务表现」]({{ '/daily/2026/09/05/daily/#coding-与长任务表现' | relative_url }})）。

### Codex /goal 空转陷阱

<span class="mention">@坚定的貂</span> 发现 Codex 使用 `/goal` 的一个 bug：Codex 启动任务后如果在等待某个操作完成，因为当前不在干事就会去检查 goal 状态，发现自己在等待后继续不干事，但这个循环每几秒重复一次，token 迅速烧完。

<span class="mention">@搞仁义毛义仁</span> 建议现在可以不用 /goal，区别不大。<span class="mention">@沉稳的兔子</span> 表示用 Luna 只要目标明确就基本不需要 /goal。<span class="mention">@风趣的穿山甲</span> 也认为 Luna 加足够思考深度是性价比很高的方式。

## 方法论

### 决策带宽才是瓶颈

<span class="mention">@稳重的海豚</span> 分享了一个困惑：想象中 AI 可以同时高质量推进很多项目，但实际上每个项目要保质还得自己投入，而且还要判断做的是不是 fake work。很多「优化」属于 nice to have，覆盖总不全面。

<span class="mention">@聪明的灰熊</span> 回应说瓶颈永远在决策带宽上。AI 能做出看起来不错的决策，但它同样可能偏向另一个也不错的方向，两者之间的取舍对 AI 来说是 arbitrary 的，而人知道选择的依据（哪怕只是个人偏好或一时冲动），但这种依据无法传达。

> <span class="mention">@聪明的灰熊</span>：很多时候AI能做出看起来不错的决策，但其实它也可能偏向另一个也不错的决策，这两个决策选哪个对AI来说可能是arbitrary的，但你知道决策的依据在哪里……然而这种决策的依据是不可沟通的

<span class="mention">@稳重的海豚</span> 补充说偏好本身还会漂移——这段时间偏好这个，过段时间偏好那个，让 AI 学习偏好本身也是一种过拟合。<span class="mention">@聪明的灰熊</span> 认为这无法改变，因为主体性始终在人。

### 聊天记录驱动 Drift 修复

<span class="mention">@稳重的海豚</span> 接着问了一个具体痛点：老鸭汤里积累了大量互相冲突的 priority、planning 等个人规划文件，怎么清理？代码文档的 drift 还好处理，个人层面的更难。

<span class="mention">@今天群内信息量极大</span> 给出的方案延续了此前关于 context 复利的思路（[「Context 复利与偏好训练」]({{ '/daily/2026/09/05/daily/#context-复利与偏好训练' | relative_url }})）：直接问 AI 两个问题。第一，根据最近半年的 AI sessions 聊天记录，看 skills 和 contexts 有哪些需要改动；第二，根据同样的记录，看 axioms、priority、perspectives 需要做哪些更新。AI 扫了他最近半年一两万个 session 后给出的建议他觉得都不错。

> <span class="mention">@今天群内信息量极大</span>：这个思路是通过过去很长时间的真实聊天记录来做出 data-driven 的决策。它不求百分之百 coverage，而是抓大放小，把日常使用中摩擦最大的地方更新掉

<span class="mention">@搞仁义毛义仁</span> 从代码角度补充：很多 Sonnet 4.1 时期生成的文档一堆问题，Sol 之前的模型基本不具备 coding 的同时更新文档的能力，导致大量过期内容，建议用 Astra 全文扫描清理。<span class="mention">@天真的浣熊</span> 更激进，让 Astra 重构所有 skill，跑了一整天。

<span class="mention">@睿智的犀牛</span> 顺便问了一个相关问题：ChatGPT 和 Claude 的聊天记录怎么存下来方便后续检索？<span class="mention">@今天群内信息量极大</span> 指出老鸭汤的 AI Export Skill 已经覆盖了这个需求。<span class="mention">@沉稳的兔子</span> 补充说本地都有存档。

### 重构时先问四个问题

<span class="mention">@活泼的羊驼</span> 分享了一个评估代码变更的四问检查表：① 可逆性，上线了吗、谁依赖，用 `git log -S` 和七彩石开关自查；② 阶段，早期还是收尾，必须问人，代码里不会告诉你；③ 爆炸半径，用 `grep -rl` 查引用方，超两个服务就当公共模块；④ 帽子，重构和加功能不要同时戴，拆成可独立发布的两步。

他感叹 AI 给的方案有时太激进有时太保守，重构时一堆保守方案，review 时才发现不对劲。<span class="mention">@搞仁义毛义仁</span> 的做法相反：鼓励 AI 勇于修改公用代码，反正 CI 够全面。但他也指出 code review 真正挑出的问题更多是用法扭曲或 library scope 没掌握好，而不是不敢改的问题。

> <span class="mention">@搞仁义毛义仁</span>：AI需要有一些概念，虽然你看到的是这些代码，但不代表这些代码都是为了这个app服务的，library就是library，保持compatibility、控制scope、同时敢于做出breaking change，都是balance的一部分

### 微软大规模 PIP 与 Token 限额

<span class="mention">@搞仁义毛义仁</span> 分享了一篇[微软变相裁员报道](https://mp.weixin.qq.com/s?__biz=MzU2OTUyNzk1NQ==&mid=2247744465&idx=1&sn=96e0bc2b25619f84b9fffc4bb664ae85&chksm=fdbdbe05abb37c4cdcdcbca799ab8688bb6744f41ff10c624b4eeb92f8c889443719516eac75#rd)。报道称微软正大规模将员工放入 PIP 或 GVSA 流程，约 25% 的员工受影响；绩效低于 60 分不能内部转岗，被 PIP 的还面临两年再雇佣禁令。
