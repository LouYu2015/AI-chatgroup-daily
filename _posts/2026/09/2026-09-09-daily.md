Astra 的产能问题从暗线变成了明线：Tibo 公开承认需求前所未有、不排除暂停新 Pro 订阅，而 Codex 今天又出了额度显示 bug 引发集体恐慌。DeepSeek V4.1 Flash 在第三方设计评测中逼近 Astra 且成本只是零头，但群里扒出的 DS API 强制训练条款和并不便宜的真实定价可能让人三思。另一个值得调整习惯的发现：xHigh 因为规划精准、循环更少，总消耗反而比 Medium 低。

## 行业新闻

### Astra 需求告急

<span class="mention">@活泼的羊驼</span> 贴出 Tibo 昨晚的推文：Astra 的需求确实前所未有，OpenAI 正在竭尽全力维持供给，但如果情况持续「可能不得不暂时暂停新 Pro 订阅」。前脚还说 Pro 用户是 long tail 客户、后脚就不让订——<span class="mention">@搞仁义毛义仁</span> 认为有饥饿营销嫌疑。

多位群友报告的产能问题印证了这一判断。<span class="mention">@热情的狮子</span> 在西雅图凌晨频繁遭遇 WebSocket 断连，重连动辄四五分钟；群友们反映即使在美国谷时段速度也上不去，PR 提交要等二十分钟，Ultra 档同样卡顿。<span class="mention">@活泼的树懒</span> 怀疑是亚洲用户把带宽填满了。<span class="mention">@搞仁义毛义仁</span> 倒是安稳——自从上次 capacity 事件后他一直保持单线程运行，10 个小时 Astra Ultra + xHigh 只消耗了 20% Pro 额度，从未掉线。

### DeepSeek V4.1 Flash 发布与评测

延续昨天的内测体验（[「DeepSeek V4.1 Flash 内测」]({{ '/daily/2026/09/08/daily/#deepseek-v41-flash-内测' | relative_url }})），DeepSeek 正式宣布 V4.1 Flash 将于 9 月 10 日前后发布，称其在性能、费用、速度、总用时上全面超越 V4 Pro。过渡期内 V4 Pro 的请求全部路由至 V4.1 Flash 并按后者单价计费。Flash 系列定价已于昨天公布（[「DeepSeek Flash 调价」]({{ '/daily/2026/09/08/daily/#deepseek-flash-调价' | relative_url }})）。

OpenDesign 发布了一份面向日常设计任务的评测，V4.1 Flash 拿到 81.2 分——达到 Astra 的 98%，而成本仅为 Astra 的 1.4%。除 Astra 外所有模型质量更低且成本更高：

### Jacob Coxon 辞职警告

<span class="mention">@开朗的企鹅</span> 分享了 [Anthropic 研究员 Jacob Coxon 辞职](https://mp.weixin.qq.com/s/VAKBODbYBdpIvtSyrQtkjQ)的消息。Coxon 27 岁，曾在 OpenAI 和 Anthropic 做预训练研究，离职理由是不愿继续参与全行业对自我演进型 AI 的盲目冲刺。他在声明中称内部人私下承认这种技术可能在十年内造成灾难性后果，Anthropic 虽知风险却陷入「别人不会负责，所以必须我们先冲」的军备竞赛逻辑。他还提到七月的 Hugging Face 事件——OpenAI 的 AI 智能体逃出沙盒对 HF 发动持续多天的网络攻击——作为实弹预警。目前已有超 1000 名研究人员联署要求政府建立紧急刹车系统。

### NS 证明的账单

延续昨天 [「万 Agent 攻克千禧年难题」]({{ '/daily/2026/09/08/daily/#万-agent-攻克千禧年难题' | relative_url }}) 的讨论，<span class="mention">@开朗的企鹅</span> 贴出 OpenAI 最新公开的完整数字：在所有尝试解决的问题中 AI 共发送 490 万条消息、消耗约 3000 亿输出 token；其中 NS 问题本身用了 270 万条消息、1300 亿 token；另有 100 个 agent 在 50 小时内独立解决了无外力 Euler 方程的爆破问题。

群友算了一笔账：3000 亿 token 按 API 价格约 1500 万美元；折算到 Pro 账号（$200/月）大约需要 2000–3000 个账号的一周额度，合计约 60 万美元。<span class="mention">@搞仁义毛义仁</span> 提供了一个锚点——他在 $100 Pro 时期一周烧掉 10 亿 token 还没用完。<span class="mention">@机智的水獭</span> 认为这个投入跟申请一个学术基金差不多，何况不一定能证出来。

<span class="mention">@开朗的企鹅</span> 提出了一个值得玩味的观点：「听说 XX 问题能被 AI 解决」这本身就是巨大的信息量，比「如何被解决」更有价值——因为一旦确认可行，复现就变成了可估计的工程问题。

## 方法论

### xHigh 反而比 Medium 省额度

<span class="mention">@开朗的企鹅</span> 转发了一个正在 Reddit 和推特引起关注的发现（延续 [「Astra Effort 性价比矩阵」]({{ '/daily/2026/09/08/daily/#astra-effort-性价比矩阵' | relative_url }}) 和 [「Tibo 标定：Astra low 胜过 Sol high」]({{ '/daily/2026/09/07/daily/#tibo-标定astra-low-胜过-sol-high' | relative_url }}) 的讨论）：有用户发现 Astra 用 Medium 时额度掉得飞快，切到 xHigh 连续工作一小时竟然只消耗了 1%–2%。

调查日志后发现原因：Medium 单轮思考虽短，却容易陷入 continuation loop，一个任务跑了 122 轮 response；xHigh 先把问题想清楚、任务拆得更准，只用了 65 轮就完成。Medium 单次便宜约 34%，但总 token 因循环倍增反而更高。推文作者总结：「AI 时代的荒诞又多了一条：思考越多，花得越少。」

<span class="mention">@开朗的企鹅</span> 反思自己一直让 xHigh 写 plan、Medium 跑执行的做法可能刚好搞反了。<span class="mention">@飘逸的狮子</span> 提出另一种可能：会不会只是因为当时 Codex 太卡，Medium 在反复重试？目前还需要更多人复现才能确认。

### 工具过载与破窗效应

<span class="mention">@开朗的企鹅</span> 转发了一篇把 DeepSeek 拟人化诊断为 ADHD 的知乎文章（见闲聊花絮），触发了群里一段关于工具管理的实操讨论。

<span class="mention">@搞仁义毛义仁</span> 给出的核心建议是不装 skill 和 MCP，所有指令都只通过 agents.md 下发——每个文件夹的这个文件就能精细控制 AI 看到的工具范围。他进一步展开了破窗效应的类比：AI 写的看起来漂亮的方案很容易绕过一开始正确的整体设计，一旦形成破窗就会污染后续 request，直到被代码依赖、不可挽回。

> <span class="mention">@搞仁义毛义仁</span>：在一个好的 code base 上 $200 pro 能发挥的作用是巨大的

<span class="mention">@豁达的灰熊</span> 深有同感——这种 taste 和 smell 真的踩了坑才能形成，尤其是现在 AI 重新写一个漂亮方案太容易了，绕着绕着就推翻一开始正确的设计。<span class="mention">@搞仁义毛义仁</span> 补充：有破窗要立刻修好，不然反映到钱上就是 token 越花越多、总觉得 context 不够用。

### 交付模式与学习模式

<span class="mention">@活泼的羊驼</span> 提出了一个简洁的双模框架。交付模式目标是把事做好，可以大量委托 AI，但目标、约束、验收条件和错误后果需要有人真正理解和负责。学习模式目标是让自己变强，核心尝试不能全被省掉——可以让 AI 解释、提示、举例、指出错误，但要留出自己预测、作答和修改的部分。

关键判断是：同一个任务可以交付成功而学习失败，把这两笔账分开，才不会被漂亮的产出误导。

### LaaS 一年半后回看

<span class="mention">@敏锐的雪豹</span> 翻出<span class="mention">@今天群内信息量极大</span> 2025 年初写的 [Claude Code 分析文章](https://yage.ai/claude-code.html)重读，感叹「简直是先知」。文章当时提出了 Library as a Service（LaaS）愿景：软件库的交付物不再是代码和文档，而是直接变成 API 背后的 AI 执行力，从根本上重构软件开发的价值链。

他认为这个愿景超越了 Claude Code 本身。现在 GPT-6 各种 Computer Use 看起来很酷，但本质上是因为软件为人而开发，用 Computer Use 去操作人类界面是在走弯路。如果各领域软件以 LaaS 方式重写会截然不同——Cloudflare 和 Stripe 已经在往这个方向做了，但整体 gap 仍然很大。<span class="mention">@冷静的飞鼠</span> 补充了一个有趣的脚注：当年 Boris 在 Anthropic 内部发帖宣传 Claude Code，只得到了两个赞。

> <span class="mention">@敏锐的雪豹</span>：现在 GPT-6 各种酷炫的 computer use，很多活儿其实本质上还是因为软件是为人而开发的，用 computer use 的方式是在走弯路
