中转站的安全代价今天有了实证：Anthropic 九月威胁报告实锤 DeepSeek 和 Moonshot 在用户不知情的情况下将请求静默转发给 Claude，代码与凭证暴露给第三方，对还在经由中间商调用模型的人是直接警报。Pro 20x 新订阅同日暂停，Astra 产能吃紧到只剩低档可选。Astra 主动打回有硬伤的 request 经多人验证——先跑再改的默认策略该调整了。

## Anthropic 威胁报告

### 中转站 6TB 数据泄露

<span class="mention">@搞仁义毛义仁</span> 转发了安全研究员 Chaofan Shou 的推文：他从一家中国头部 LLM 路由器（中转站）买到了一份 Fable 数据集，仅 6TB 数据就包含经由路由器发送的 SSH 密钥、VPN 配置、阿里云凭证和 GitLab 令牌，足以接管 7 个中国/独联体政府实体以及小米、华为、蔚来、Minimax 等 19 家企业的内部系统。<span class="mention">@直率的鹦鹉</span> 的态度很明确：「再便宜都不能用中转站，卖数据没有底线的。」

<span class="mention">@洒脱的猫头鹰</span> 随即指出敏感信息检测刻不容缓，推荐了 OpenAI 开源的 privacy filter，效果不错但有点慢。他构想了一个本地 gateway 方案：接入 privacy filter 对请求做敏感信息 tokenize、对响应做明文还原。<span class="mention">@开朗的企鹅</span> 认为技术上完全可行。

### 七家中国实验室蒸馏指控

Anthropic 发布了[九月威胁情报报告](https://www.anthropic.com/threat-intelligence-report-september-2026)，点名七家中国实验室对 Claude 发起大规模蒸馏攻击。<span class="mention">@热情的狮子</span> 分享了完整 PDF。报告披露的最核心事实是：DeepSeek 和 Moonshot（Kimi）不仅自己蒸馏，还在用户不知情的情况下将请求静默转发给 Claude，把 Claude 的响应作为训练数据。

| 实验室 | 观测窗口 | 蒸馏交互量 | 关键手法 |
|---|---|---|---|
| Alibaba（Qwen） | 5–7 月 | 1.51 亿+ | 峰值日 300 万次，3500+ 假账号 |
| Moonshot（Kimi） | 5–7 月 | 2300 万+ | 静默转发用户请求，跨会话重放破解思维签名 |
| DeepSeek | 7 月 14 天 | 1210 万+ | 定向拦截 Claude Code/SDK 用户流量转发 |
| Zhipu（GLM） | 6–7 月 17 天 | 340 万+ | CoT 提取 → 清洗用于 GLM 训练 |
| Xiaomi | 3–4 月 20 天 | 40 万+ | MiMo 免费试用吸引用户后回捞会话 |
| SenseTime | — | — | 从第三方数据商购买用户与 Claude 的对话 |
| MiniMax | — | — | 通过空壳公司建中转站，只卖 Anthropic 和 OpenAI 模型 |

泄露的用户数据包含某科技公司旗舰 AI 架构的完整规格、俄罗斯国防部关联数据库的实时凭证、以及地方公安案件管理系统中的维稳代码。

群里对机制展开了讨论。<span class="mention">@专注的剑鱼</span> 首先质疑：为什么 Kimi 的流量会跑到 Claude？如果用户买的就是 Kimi，为什么要转发到更贵的 Claude？<span class="mention">@热情的狮子</span> 认为核心目的不是 serve regular traffic 而是蒸馏。<span class="mention">@活泼的羊驼</span> 提供了另一种解释：类似于代码重写时用 go 对 php 做对账，抽样请求去跑一次 Claude 确认自己模型质量，这在工程上并不反常。<span class="mention">@淡定的海龟</span> 补充了第三种可能：把用户 query 回捞过来用 Claude Code 合成数据。

> <span class="mention">@直率的鹦鹉</span>：从刷分变成替考

### Claude 辅助武器与诈骗

<span class="mention">@开朗的企鹅</span> 从报告中挑出三个武器化案例：也门胡塞武装团队同时推进制导火箭和高超音速滑翔项目，用 Claude Code 写制导软件，试射失败后数小时内就回到 Claude 分析原因；一支俄罗斯团队用 Claude Code 开发自主 FPV 自杀式无人机蜂群，机载模型可自主决定攻击目标（包含「person」类别）并触发引爆；一个中国相关团队用 Claude 设计反鱼雷火控系统，生成超过 200 页中文技术方案并让 Claude 扮演专家评审自我迭代——项目进行到一半，模拟的默认场景被改为台湾境内的 12 个目标。

报告还披露了一个杀猪盘案例：一个中国团队两周内用 Claude 构建了 4700 多个 AI 虚拟恋爱人设，部署在 20 多款交友 App 上，骗了至少 25000 名真实用户。匹配池里大约 75% 是 AI，25% 是真人兼职——负责视频通话和社交媒体互关等「证明我是真人」的环节。

> <span class="mention">@搞仁义毛义仁</span>：为什么他们这么用 Claude 不会被 flag 呢？我 debug 个 AV 就要死要活

<span class="mention">@活泼的羊驼</span> 翻完全文后指出，报告其实覆盖了俄罗斯间谍、法国黑客主义者、伊朗宣传机构、肯尼亚政治水军等各国各类案例，并不专门针对中国——「中文圈为了流量才把中国部分挑出来放大」。

## 行业新闻

### Pro 20x 暂停新订阅

延续昨天 Tibo 关于 Astra 需求「前所未有」的预警（[「Astra 需求告急」]({{ '/daily/2026/09/09/daily/#astra-需求告急' | relative_url }})），今天靴子正式落地。<span class="mention">@热情的狮子</span> 贴出 Tibo 最新推文：为保证现有用户体验，暂停 $200 Pro 20x 计划的新订阅和升级，恢复时间未定，其他计划和 API 不受影响。

不让开新 20x，只能买 $80 一次的 reset 卡。<span class="mention">@热情的狮子</span> 吐槽价格太贵，认为应该卖 $50；<span class="mention">@坚定的貂</span> 反驳——$80 reset 说明 subscription 的真实价值应该是 $320，不然谁都可以无限买。他自己 8 个 Pro 都不够用。<span class="mention">@沉稳的仓鼠</span> 已经进入每天买一个 $80 reset 的节奏，<span class="mention">@洒脱的猫头鹰</span> 建议不如多开几个账号——但现在连新 20x 都不给开了。

> <span class="mention">@热情的狮子</span>：主要很多时候是 burst 需求，不是 sustained

### DeepSeek V4.1 Flash 发布

延续此前的内测讨论（[「DeepSeek V4.1 Flash 发布与评测」]({{ '/daily/2026/09/09/daily/#deepseek-v41-flash-发布与评测' | relative_url }})），<span class="mention">@睿智的北极熊</span> 分享了 [V4.1 Flash 官方发布公告](https://www.xiaohongshu.com/discovery/item/6aa2443700000000260303c2)和完整跑分表。DeepSeek 现在只保留这一个模型，商业上合并了 Pro 和 Flash——<span class="mention">@今天群内信息量极大</span> 概括训练思路为「非常 DeepSeek（褒义），以前优化 flops，现在优化存储」。V4 Pro 将于 9 月 14 日下线，届时所有 Pro 请求路由至 V4.1 Flash 并按后者单价计费。

![DeepSeek V4.1 Flash 官方跑分对比（含 GLM 5.3、Kimi K3、Sol、Opus 5.0）](/assets/img/daily/2026/09/2026-09-10-01.webp)

<span class="mention">@活泼的羊驼</span> 分享了架构解析：V4.1 Flash 正式使用了此前提出的 Engram conditional memory（196B 参数），采用 40 层 Causal Encoder-Decoder 结构（前 20 层 encoder + 后 20 层 decoder），prefill 和 decode 分别约 8B/16B activated params，还集成了原生多模态视觉和 DSpark speculative decoding。

跑分与体感的鸿沟再次成为焦点。<span class="mention">@今天群内信息量极大</span> 直言「benchmark 都不敢信了，每次都拳打 Sol、脚踩 Fable，一用又是一坨屎。但 4.1 手感不错，比 Qwen 3.8 27B 确实更好。」他贴出 Artificial Analysis Intelligence Index——V4.1 Flash 在 AA 上跟 Luna 和 27B 坐一桌。<span class="mention">@务实的灰熊</span> 质疑 AA 本身也是「抽象 benchmark」：发现 Astra 排名低于体验就赶紧改权重和子项，然后把 Astra 变成 SOTA。<span class="mention">@今天群内信息量极大</span> 认为改权重其实是正确做法——eval 应该和人的感受对齐，如果不符就该调。<span class="mention">@直率的鸵鸟</span> 最务实：「从来不看这些，新模型出来都是看本群大佬的反馈。」

<span class="mention">@热情的狮子</span> 转发了一篇[详细测评](https://mp.weixin.qq.com/s?__biz=Mzk3NTI3ODI4MA==&mid=2247484823&idx=1&sn=975e10ccc05288b289defc44760c05e2)：V4.1 Flash 逻辑能力进入国产第一梯队头部，完成任务步骤显著多于前代（增幅至少 +20%，极端项目 +700%），增量主要来自自测环节。但 max 档消耗惊人（中等任务 260–340K token），正确率却不比前代 Pro 更高。<span class="mention">@坦荡的灰熊</span> 另外注意到 V4.1「没有受到鸭汤的影响」，agents.md 风格的 prompt 似乎对它不起作用。

定价方面，<span class="mention">@开朗的企鹅</span> 发现 OpenCode Go $10/月限时提供四倍 V4.1 Flash 额度，按官方单价折算理论上约省 83%。他还贴出了按不同缓存率估算的官方 API 月费：

| 缓存输入占比 | 未缓存占比 | 输出占比 | 全按闲时价/月 | 全按高峰价/月 |
|---|---|---|---|---|
| 99.8% | 0.1% | 0.1% | 374 元 | 749 元 |
| 98% | 1% | 1% | 1,044 元 | 2,088 元 |
| 94% | 5% | 1% | 1,632 元 | 3,264 元 |
| 89% | 10% | 1% | 2,367 元 | 4,734 元 |
| 0% | 99% | 1% | 15,450 元 | 30,900 元 |

<span class="mention">@直率的鸵鸟</span> 泼了冷水：99% 缓存率不符合实际开发场景，他的经验是缓存约 97% 左右比较合理。更关键的判断是——20x Pro 用满的情况下，实际成本约为 API 标准价的 1/50，DS 在价格上并没有优势；至于编码能力，「Flash 远远不如 Sol，也就是 Luna 到 Terra 之间，而且更靠近 Luna」。他还指出了一个结构性 trade-off：子 agent 开得多缓存率就低，开得少缓存率高但总 token 也多、注意力被稀释。

### AI 数据中心电力困局

Pro 20x 暂停的讨论自然延伸到了算力供给的底层瓶颈。<span class="mention">@聪明的蜂鸟</span> 带来了一手行业观察：他接触的数据中心项目中，很多已经不指望接电网，开始自己搞 turbine 发电机。<span class="mention">@热情的狮子</span> 证实美国电网太老、环保审批「屁事很多」，很多新项目选址加拿大和北欧。<span class="mention">@淡定的海龟</span> 给出一个时间锚点：美国最近交付的核电机组是 2009 年审批、2024 年商业运营的，之前最后一次审批在 1978 年。

<span class="mention">@活泼的羊驼</span> 指出电力在 token 成本中占比约 5% 以下，<span class="mention">@淡定的海龟</span> 纠正这是中国的数据——中国不用新建发电站和电网，美国要新建就不是这个比例了。小型核电站加数据中心的方案已经在路上，但正式审批流程仍需数年。<span class="mention">@聪明的蜂鸟</span> 总结：单点高成本总能解决，全面补电网欠债才是真正难题。

> <span class="mention">@聪明的蜂鸟</span>：关键这东西并不便宜，也不环保，搞这个的唯一原因就是没办法

## 工具

### 本地录音与 Speaker Diarization

<span class="mention">@豁达的灰熊</span> 问群里有没有好用的本地 speaker diarization 方案，主要需求是不上云。<span class="mention">@冷静的飞鼠</span> 给出的推荐是硬件用手机 + Apple Watch + Mac，软件配 <span class="mention">@今天群内信息量极大</span> 的 context intake skill，需要区分说话人时用 [lizheng-video-production](https://github.com/sunyuzheng/lizheng-video-production)。他还写了一篇[流程讲解](https://www.superlinear.academy/c/tools/intake-skill-apple-voice-memos-context)：Apple 原生语音备忘录录音 → iCloud 同步到 Mac → 本机 Qwen3 ASR 转文字 → Codex 整理成 Markdown，所有数据留在本地。不过他也指出 intake skill 本身不做 diarization（被列为红线），需要配合专门工具。

<span class="mention">@热情的狮子</span> 分享了自己做的 [watch-transcriber](https://github.com/xingfanxia/watch-transcriber)：支持 MOSS 本地路线（Metal 加速 + Qwen3.8-27B 摘要）和飞书妙记云端路线，配套 EchoWall 桌面端可浏览、播放、标记说话人。<span class="mention">@坚定的长颈鹿</span> 注意到 Apple 在 Watch 上也新增了 Siri Recap 常开监听功能，问这类 app 是否有市场。<span class="mention">@豁达的灰熊</span> 坦言飞书妙记已经非常好用，他只是不想上云。<span class="mention">@热情的大象</span> 提出更进一步的想法：做意图识别，用 agent 自动化识别录音中要做的事，提前帮你做好。

### Vibe Coding 回测构想

<span class="mention">@坦荡的灰熊</span> 抛出一个想法：有没有专门冻结 vibe coding 过程的工具？这样新模型来了可以用以前的任务测试对比。<span class="mention">@搞仁义毛义仁</span> 的方案很直接：task 一律写在文件里、全在 git 里，`git reset` 回去 prompt 和 skill/doc 就恢复了。他还有一个习惯是把 prompt 直接留在 repo 里，做完删掉，git 历史永远保留——<span class="mention">@天真的浣熊</span> 表示以前 prompt 都靠 session 自己存储，没想过这招。

## 方法论

### Astra 拒绝有硬伤的请求

<span class="mention">@搞仁义毛义仁</span> 发现了 Astra 相比前代的一个重要行为变化：如果 request 有硬伤，Astra 不会硬做。以前的模型包括 Sol 都会用奇怪的方式强行满足你，Astra 则会丢回来让你确认。<span class="mention">@敏锐的海狸</span> 确认打回或纠正边界的次数明显提高。<span class="mention">@洒脱的猫头鹰</span> 描述了更具体的体验：好几次他正准备补充条件说明时 Astra 就先问了，只需要回答「对」。

反面对照同样清晰：Sol 如果你叫它审 request 有什么问题，它会硬找问题。<span class="mention">@坦荡的灰熊</span> 深有体会——之前用 Sol 做 code review 常驻 agent，结果第二天全是过度工程化，「功能一个没有，程序门禁层出不穷，光是正常打开就要绕过四五个弹窗」。<span class="mention">@稳重的海豚</span> 从 Fable 5.1 那边补了一刀：不听话就算了，还写「我觉得应该怎么样」，然后自作主张瞎改 deck。

但 Astra 审自己的东西比较松。<span class="mention">@敏锐的海狸</span> 在 Codex CLI 用 Astra xHigh 做独立外审时发现审查偏宽，得开 Opus 5 xHigh 补审。他还指出压缩一次 chat context window 后 Astra 就容易开始过度工程化，得重新让它读一次 exec plan。<span class="mention">@搞仁义毛义仁</span> 的核心建议是：最好还是你自己 review，AI 的价值判断靠不住——他只问行不行，不问好不好。

> <span class="mention">@搞仁义毛义仁</span>：在一个好的 code base 上 $200 Pro 能发挥的作用是巨大的
