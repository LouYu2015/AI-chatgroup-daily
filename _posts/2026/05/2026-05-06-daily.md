## 工具

### 多 Agent 并行监控：从刘海岛到自建 Dashboard 到 stdio redirect

<u>淡定的喜鹊</u> 的一个实用问题「同时开 n 个 Claude Code terminal 怎么 track 每个在干啥」引出当天最密集的工具讨论。

**Vibe Island** 是<u>今天群内信息量极大</u> 推荐的 Mac 刘海岛原生应用（[vibeisland.app](https://vibeisland.app/)），支持 Claude Code、Codex、Gemini CLI 等 11 个 agent 的统一监控，tool use 审批可直接在刘海处操作，纯 Swift 构建、一次性买断。<u>今天群内信息量极大</u> 透露自己在一台 512G Mac Studio 上同时跑大量会话，「同时开的 subagent 数量超过 100 之后会比较卡」。<u>优雅的猎豹</u> 已是付费用户，称「戒断反应明显」。

**<u>洒脱的鸳鸯</u>** 展示了自建的 SecondBrain 系统，拆成两个项目：一个搜集本地 AI session 数据入库，一个做可视化分析。Analytics 面板显示 30 天内 1173 个 session、总花费 $7424、日均 3.48 亿 token、cache hit 率 98.1%。

> <u>洒脱的鸳鸯</u>：分析数据很有价值，我根据这些数据分析改进了几轮我的 skill 体系

<u>地球首帅鸭哥</u> 提出了更底层的方案——**stdio redirection**：自己启动进程时做双向 redirect，不管对面是 Codex、Claude 还是 Gemini 都一样，既能读输出也能往里写入。<u>洒脱的鸳鸯</u> 直呼「简单粗暴，牛逼」，表示之前一直在折腾 wrapper tty 来交互。<u>活泼的羊驼</u> 推荐了开源的 [CodePal](https://github.com/shamcleren/CodePal)，定位为只读 dashboard；<u>开朗的企鹅</u> 分享了一份[多机 AI Agent 控制平面的重构 prompt](https://gist.github.com/holdonyb/de6e4569eacfec4035be3f9e780cd219)，用于从零搭建跨机器 agent 管理。

### 让 AI 用 WinDbg/CDB 调试 C++ 代码

<u>地球首帅鸭哥</u> 分享了让 AI 驱动 CDB（WinDbg 命令行版）调试的完整方案（[博客](http://vczh.net/Blog/CDB/)、[GitHub 指南](https://github.com/vczh-libraries/Workflow/blob/master/.github/Guidelines/Debugging.md)）。核心是利用 CDB 远程调试服务端模式，每次通过文件注入命令、捕获输出，让 LLM 在无人值守下完成设断点、单步、查栈、打印变量的全套操作。

> <u>地球首帅鸭哥</u>：其实我只是包装了一下让他学会启动windbg的服务器版本，至于怎么调试AI自己其实会

<u>坦荡的灰熊</u> 立刻表示要拿来用，还分享了自己让 Codex 优化 Windows 系统的经历——AI 自行下载调试工具、查看 minidump，发现系统卡顿是多年前一个无效 NAS 映射导致的，顺便还诊断出 Claude 往 PATH 写入 `\C\` 导致的任务管理器崩溃。

## 方法论

### AI 时代，复核不等于独立判断

<u>今天群内信息量极大</u> 分享了一篇深度文章[《AI 时代，复核不等于独立判断》](https://yage.ai/share/ai-review-independent-judgment-20260506.html?utm_source=wechat&utm_medium=share&utm_campaign=ai-review-independent-judgment-20260506)，核心引用了 Wharton 商学院的实验：AI 给正确答案时接受率约 93%，给错误答案时也高达 80%，且有 AI 可用的组自我评估信心反而高出 11.7 个百分点——即使 AI 给了错误答案。文章区分了「复核」（沿 AI 路径再走一遍）和「交叉检查」（看到 AI 答案前先建立独立参考点），核心主张是「先有自己的地图，再去比照 AI 画出来的路」。<u>温暖的斑马</u> 评价「这篇文章需要读两遍，才能体会到中间引用的研究内容是需要深度思考的」。

### DeepSeek Flash 的成本优势与模型选型

<u>今天群内信息量极大</u> 分享了自己的模型选型经验：DeepSeek Flash 用于大量调研和内容生成，一天 13 亿 token 不到 100 人民币且不限流；Google Gemini 思考深度好但 agentic 能力「太拉垮」，API 不稳定；Claude 和 GLM 订阅制两天就限流。他对 Flash 的评价颇为传神：

> <u>今天群内信息量极大</u>：因为笨，所以 prompt 必须写的超级详细，所以更可控

> <u>今天群内信息量极大</u>：类似你招人，傻子比聪明人更容易控制。而且傻子犯错就那几种，好 guard

<u>稳重的海豚</u> 则认为 Claude 4.7 和 5.5 xhigh 的思考深度跟 GPT Pro extended 比不了，问能否用 skill 强行拔高。<u>活泼的羊驼</u> 解释 Pro 底层是 multi agent 架构且思考预算很高，<u>乐观的貂</u> 补充说理论上可以但很快会达到 token 输出上限。

### AI 编码的屎山化趋势与 eval 的价值

<u>地球首帅鸭哥</u> 用自己两个月改的 C++ 个人项目总结：AI 产出同等代码量周期里需要重构的次数是手写的十几倍，几万行来回改。好在打游戏和睡觉时也能跑，虽然 coding 用时更长，但没触发「古法特有的拖延症」，完成日期反而提前了一半。

> <u>地球首帅鸭哥</u>：一个人没爆 codex pro $100，每个星期都能看到屎山化的趋势两次，要是让一个团队一起来做，就不是屎山化的趋势，他就是屎山了

<u>今天群内信息量极大</u> 从另一个角度点评：大厂强调精心维护、高并发高可用都是屠龙之技，「大多数地方的代码在堆成屎山之前公司就倒闭了」。<u>冷静的白鹭</u> 从模型开发角度补充：一个项目最有价值的就是 eval module——「项目可能黄，但是 eval module 很有价值」。<u>稳重的海豚</u> 类比游戏行业——游戏黄了，买倒闭公司的美术 assets 照样有价值。

### AI 文档的 Git 管理困境

<u>坦荡的灰熊</u> 提了一个实战问题：给 AI 看的文档怎么用 git 管理？伴随项目提交，git reset 时会失去最新理解；gitignore 又会导致记忆错位。<u>地球首帅鸭哥</u> 建议 reset 前让 AI 记下文档 commit 再 cherry pick 回去，<u>神秘的麋鹿</u> 建议写上时间和背景使错位也能定位，并指出「公理一类的东西跟代码库绑定得没那么严」。
