今天群里最集中的话题是 Codex App 的集体安利——<u>冷静的麋鹿</u> 写了一段详细评价，认为它在 CLI 的简洁和 IDE 的功能性之间「平衡的好，多而不乱」；<u>沉稳的松鼠</u> 则透露 OpenAI 正在探索新的企业订阅模式，可能告别按 usage 的昂贵定价。最值得偷师的实战技巧是 <u>鸭哥大号</u> 用 Codex 跑测试 100 遍抓 flaky bug——修完了还得再跑 100 遍验证，「agent 在那干我就当挂机」。行业侧最值得读的是一人公司退潮长文：全国 1600 万家存量、留存率不足十分之一，AI 能无限拉高供给却解决不了「客户在哪里」。闲聊最佳一刻：有人问鸭哥为什么坐轻轨不开 RR，<u>冷静的飞鼠</u> 回答他「嫌 RR 不够贵，问 AI 还有没有更贵的车可以坐」。

## 工具

### Codex App：CLI 与 IDE 的平衡点

多位群友同时推荐 Codex App。<u>沉稳的松鼠</u> 给出最直接的评价：「codex app is the best thing right now。」<u>80-HD</u> 反馈公司里好几个人在强烈安利。<u>睿智的北极熊</u> 解释了推荐逻辑：「codex 直接用，使用者可以不用管啥 harness，也不用外部 skills 就可以出不错的效果」，他在公司推 App 而非 CLI，「没啥学习成本」。

<u>冷静的麋鹿</u> 写了一段详细评价。起初吸引他的是 Codex App 内置的做图片功能（之前只有 Anti-Gravity 有这个优势），但越用越发现交互设计做得到位——各种斜杠命令行、键盘鼠标结合的可视化操作。

> <u>冷静的麋鹿</u>：我觉得 Codex App 结合了二者的优点：既有 IDE 的功能性，又保持了像 CLI 那样的命令行的体验。

他补充说最近更新中上线了工作模式和开发模式的选择，国内类似产品也做了这种区分但「花里胡哨」，Codex 在两种模式之间保持了简洁。不过他日常仍以 CLI 为主——「Ghostty 配 CLI，外加各种快捷键，多开啥的，比 Codex App 还是灵活」，Codex App 更适合单任务场景。<u>优雅的荷兰猪</u> 问 App 和 CLI 的本质区别，<u>冷静的麋鹿</u> 认为「本质没区别，App 的内核还是 CLI 那一套」。<u>优雅的荷兰猪</u> 也确认了自己的双开模式：一份 AGENTS.md 同时给 omx 和 CC 两个 agent 用。

<u>80-HD</u> 安装试用后评价设计「太 eng 了」，打算直接魔改。<u>今天群内信息量极大</u> 接受了反馈让 AI 去改设计，下午从轻轨站走回家的路上，AI 已经把活干完了——「从轻轨站走回家，发现它已经改好了。PR 已 merge。」<u>豁达的灰熊</u> 安装时遇到卡在加载界面的问题，重启手机后解决。

### Codex 跑百遍抓 Flaky Bug

<u>鸭哥大号</u> 正在为 GacUI（他维护的 C++ GUI 库）做自动化测试闭环。核心痛点是 flaky test——同样的代码跑一次过、再跑一次挂，可能是时序问题或 UI 渲染竞争。传统做法是人守在电脑前反复跑等它复现，跑 50 次才挂一次、人盯不住。

> <u>鸭哥大号</u>：让 Codex 跑 test case 100 次解决 unstable case 的问题还真是省事，人肯定不可能在那盯着

更关键的是修完之后还得再跑 100 遍验证——「agent 在那干我就当挂机」。他同时在推进让 Codex 操作 GUI 的功能：「以后所有的自动化测试都即将闭环」——当 AI 能操作 GUI + 自主反复跑测试 + 分析失败原因，整个测试链路就从人工兜底变成 AI 闭环。他还发现了一个环境坑：笔记本上跑得好好的 http server，放到高性能台式机上直接死锁，「防不胜防」。

### GPT Pro 鸣潮组队碾压全场

<u>风趣的海豚</u> 用一道「很无聊的测试题」横评多个模型：给鸣潮（Wuthering Waves）游戏的角色截图，让模型识别所有人物并给出组队建议。结果只有 GPT Pro 全部正确识别并给出了有建设意义的攻略。Claude 和 Gemini 均翻车，Kimi 出人意料地排第二——「认错两个，认掉一个」。

<u>活泼的海龟</u> 有类似经历：让 Gemini 帮做杀戮尖塔的选牌，「幻觉老严重了，对卡面的识别以及策略很难有做得特别好的」。围绕 GPT Pro 的本质，<u>开朗的企鹅</u> 判断它是「一套非常厉害的 Harness」，<u>淡定的大象</u> 纠正了用词——harness 是 agent 的设计思想（如 CC 的架构），GPT xhigh 才是模型内部的深度思考机制。<u>风趣的海豚</u> 补充了一个版本变化：「5.4 的时候老鸭汤 + xhigh 还可以和 Pro 打个来回，但是到了 5.5 以后就不行了」——Pro 的领先差距在拉大。

## 方法论

### claude.md 角色扮演已无必要

<u>80-HD</u> 提出疑问：现在还有人在 claude.md 开头加 "you are an AI coding and analysis assistant" 这种话吗？<u>优雅的荷兰猪</u> 引用了最近的研究结论：

> <u>优雅的荷兰猪</u>：在提示词里加上"你是一个市场分析专家"这句话，本身并不能增加 AI 分析的深度和推理能力，甚至还有点减弱。它只会让生成的内容在语调和格式上，更加接近于一份标准的市场分析报告。

<u>80-HD</u> 认同这等于 role play，「只会限制 agent 的能力」。他自己的 claude.md 只有一句话——去读 context repo 的 agents.md。<u>稳重的海豚</u> 回忆<u>今天群内信息量极大</u> 之前做过实验验证了同样的结论。<u>低调的北极熊</u> 提了一个工程细节：为什么不直接 link 过去，「多一次 tool call」？<u>80-HD</u> 去问了 Claude，得到的建议是用 @ 引用和 symlink 没实际区别。

### AI 工程讲座与 Just Do Things 辩论

<u>冷静的飞鼠</u> 在腾讯学堂做了一场内部直播讲座，主题为「AI User 和 AI Builder 的差距，是五种底层方法差距」，讲座 deck [已公开](https://tencent-engineering-ai.vercel.app/)。deck 从人与计算系统接口层的变迁说起，提出了一个关键判断框架——区分「名词」和「动词」：名词容易过时也容易退化为工具清单，动词对应真实工作流。deck 还引用了 DORA 2025 报告（90% 受访者用 AI、80% 感觉效率提升）与 METR 实验（有经验开发者用 AI 反而慢 19%）的断层——组织流程是为高执行成本时代设计的，执行变快之后会议和审批反而吞掉速度。deck 中引用了昨天 [「生成在贬值，采用在升值」]({{ '/daily/2026/05/26/daily/#生成在贬值采用在升值' | relative_url }}) 中 <u>冷静的麋鹿</u> 文章的核心判断。<u>活泼的羊驼</u> 在直播间分享了自己的两篇 harness 工程长文（[AI 效率悖论](https://www.superlinear.academy/c/share-your-insights/ai-d18939)和 [Harness 三层演化](https://www.superlinear.academy/c/share-your-insights/harness-engineering-14-ai)），后者系统梳理了 Claude Code 和 Cursor 的工程演化路径。

讲座之外，<u>活泼的羊驼</u> 分享了 [Claude 背后的 7 个产品原则](https://www.xiaohongshu.com/discovery/item/6a15727900000000080009a7?app_platform=ios&app_version=9.32.2&share_from_user_hidden=true&xsec_source=app_share&type=normal&xsec_token=CBegS-QsxVBwTOtRGin3UuVGKKBJGvpIXVjdfb_VEY1zs=&author_share=1&xhsshare=WeixinSession&shareRedId=NzxGNkVKRT03SjU5TU40STk8TEpHS0tP&apptime=1779941713&share_id=ce9fe42b0d874cf48e0be676bb4e92a4)，其中第七条「Just do things」引发了辩论。他认为 AI 降低了跨职能行动成本，公司会更偏好「看到问题能自己推进、不等完整授权」的人。<u>优雅的海豚</u> 泼冷水：「AI 打破既有流程和职能边界的后果是 token 的挥霍和屎山」，并分享了企业四个月烧完全年预算的案例。<u>活泼的羊驼</u> 用自己的经验反驳——自费买了多个 $200 订阅，而且「把 100 年的订阅费赚回来了」。他的核心判断：AI 时代最缺少的不是点子和知识，「而是经过验证过的行得通或者行不通的 mindset」。

<u>冷静的麋鹿</u> 旁听后给出了一个关于知识传播的精准评价：

> <u>冷静的麋鹿</u>：我能感受到你讲的每一页，背后都是值得花几个小时探讨的深刻道理。但是几分钟里面就要把这一 part 讲完，那就要看听的人自己能不能 get 到背后的道理了。get 到了，就是巨大的认知提升，get 不到，就会觉得好像他也知道。

这与前天 [「高手的知识诅咒」]({{ '/daily/2026/05/26/daily/#高手的知识诅咒' | relative_url }}) 中他自己写的那段话一脉相承——知识传播的难点不在内容量，在于听众能不能 get 到关键一击。

## 行业新闻

### 一人公司集中退潮

<u>鸭哥大号</u> 分享了一篇 [一人公司退潮](https://mp.weixin.qq.com/s/YVMM6j8XJT6wjlwL8m8xHw) 长文。全国一人公司存量已突破 1600 万家，占企业总量的 27.4%，90 后 / 00 后占近 60%，超 44% 来自互联网或科技大厂。但仅 20% 跑通了商业闭环，深圳 OPC 圈子一年间留存率不足十分之一。

失败案例揭示共同模式：AI 帆布包创业者半年烧光本金——AI 抹平了设计门槛同时消灭了差异化，全网同款卖 19.9 元；非遗活字策划者在供应链折戟——AI 给出的「完美配比」遇到原材料湿度变化就失效；AI 漫剧创业者被平台算法切换直接断崖。文章还指出一个认知陷阱：大厂时新项目会经历团队辩论和质疑，但对着 AI 只会得到顺从点头，极易形成信息茧房。真正活下来的少数人特征是已有成熟行业经验——AI 只是压缩了开发周期，而非从零制造竞争力。
