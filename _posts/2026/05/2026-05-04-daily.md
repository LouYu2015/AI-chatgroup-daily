今天群里围绕「AI 写代码的设计陷阱与 code review」展开了一场深度讨论，<u>地球首帅鸭哥</u>、<u>低调的鲸鱼</u>、<u>稳重的海豚</u> 等多位群友从各自实战经验出发，探讨了 AI 快速出码与代码质量之间的矛盾。<u>今天群内信息量极大</u> 上线了基于 AI 调研的文化导览网站 Guide Me，为北京 60 个景点和耶鲁大学编写了深度导览，引发一波「许愿」热潮。<u>冷静的麋鹿</u> 和 <u>谨慎的狮子</u> 围绕 Skill 蒸馏的日常沉淀方法交流了心得，<u>敏锐的海狸</u> 则用蒸馏后的 Skill 实际跑出了一份 Databricks 分析报告。此外，多位群友发现 Codex 用量似乎被重置，一片欢腾；<u>幽默的犀牛</u> 发现 AI 竟能读懂乱码文章并头头是道地做总结，引出了一个编码知识小科普。

## 方法论

### AI 写代码的设计陷阱与 code review 的必要性

<u>地球首帅鸭哥</u> 总结了一个核心观察：自己的代码中嵌入了大量防御性假设（assumptions），AI 上来就想拆掉这些防御，但这些隐含约束根本无法在文档中穷举。<u>低调的鲸鱼</u> 表示在现阶段完全不看代码直接 merge 风险太大，已经回到了「AI 写我看」的模式。<u>稳重的海豚</u> 坦言自己两个月的代码正在重构，主要问题是 Codex 经常不听话写 hot fix，累积成屎山。<u>沉稳的兔子</u> 抛出爆论「但凡需要维护的软件都是没有价值的」，<u>80-HD</u> 认为以前写码贵大家舍不得丢，现在便宜了大部分可以用完就扔，但<u>地球首帅鸭哥</u> 反驳说这远未到来——只有自己用的工具可以这么说，一旦要为别人负责就不是一回事。

> <u>地球首帅鸭哥</u>：模块设计的好，AI 写起来就顺畅。AI 写的歪瓜裂枣也许可以说是风格问题，但是一旦开始群魔乱舞，那就有可能是设计本身的问题。不过一个没有古法经验的人，要如何积累这种直觉，我看很玄。

> <u>地球首帅鸭哥</u>：测试只能发现 bug，但是一个好的设计天然就是不会 error prone 的。然而一个设计是不是好的只存在于我们的想象里。过去自己写代码，有非常多的机会可以在修 bug 的过程中感知到设计缺陷的存在，及时重构。现在让 AI 写，实际上你丢失了大量的 input。

> <u>低调的鲸鱼</u>：让 AI 写代码，原来只想要理解系统层面就好，具体实现不用再看了。我现在还是做不到。AI 一旦开始堆💩，太快了，基本就是推倒重来。

> <u>80-HD</u>：程序员越来越像纽约地铁司机，可以手动精准控制进站，但是他们存在只是因为纽约地铁需要而不是地铁需要

### Skill 蒸馏的沉淀实践：每日 session + 每周反思

<u>冷静的麋鹿</u> 分享了自己的蒸馏节奏：每天做 session 一级沉淀，每周做反思蒸馏，发现 AI 的输出「味儿越来越正」。更意想不到的是，因为知道每次 session 会成为蒸馏的出发点，反过来推动自己每次任务多往前推一步，形成复利效应。<u>谨慎的狮子</u> 则提出了一个需求：如何系统化蒸馏自己的 Slack/GitHub activity 和所有 coding agent 对话历史。<u>冷静的麋鹿</u> 推荐了 [context-infrastructure](https://github.com/grapeot/context-infrastructure/tree/main) 项目，并建议写脚本设定每日/每周任务让 AI 自动蒸馏。<u>淡定的雪豹</u> 补充说 Opus 不会偷懒，会把所有 work 扫一遍，但轮数太多时仍会出现敷衍。

> <u>冷静的麋鹿</u>：因为自己清楚，每次 session 会成为蒸馏的出发点，所以反过来，自己每次推进一个任务的时候，过去可能有的七八十分得了，现在觉得再往前推一步，这样回头的任务就能享受这次纠正的复利

> <u>稳重的海豚</u>：想要达到很好效果的话，需要做很多的定制化微调。比如前两天我喜欢用 ascii 画图，这两天发现 SVG 好看，他之前的经验就得扔了

### DeepSeek Flash 做写作的工作流

<u>风趣的海豚</u> 好奇<u>今天群内信息量极大</u> 如何用 DeepSeek Flash 每天花一二十块写作。<u>今天群内信息量极大</u> 解释说调研和框架都由其他 AI 完成，DeepSeek 只负责最终写作——给它「又臭又长的原料包」加提纲，或者让它用自己的语言重写一篇 AI 味爆表的文章。<u>风趣的海豚</u> 精辟总结：「AI 味就是遵循指令调用工具之后深度思考的结果。」

> <u>今天群内信息量极大</u>：他思考深度不行，指令遵循不行，调用工具不行，但写作没有 AI 味

> <u>今天群内信息量极大</u>：总之 knowledge 我帮你查好，提纲我帮你深度思考好，你就当 AI 电池除了组织语言别干任何其他事。不要发布，不要 rsync，不不不我知道你想删库但也请不要删

### Sub-agent 批量处理大规模任务

<u>今天群内信息量极大</u> 介绍了用 sub-agent 处理大规模任务的方法：先分组，一个 sub-agent 管十个任务，一个 wave 派十个 sub-agent 同时做，每个 wave 收回后做 QA。他用类似方法爬了十几年新闻数据、整理出几万个事件。<u>谨慎的狮子</u> 担心 API rate limit，<u>今天群内信息量极大</u> 表示 Oh My OpenCode 内置了 throttling，Claude Code 5 小时 usage 满了也会自动重试，基本不用操心。

### Codex /goal 功能初体验

<u>冷静的麋鹿</u> 试用了 Codex 新上线的 `/goal` 命令（需后台启用），感觉体感不佳。他分析原因在于 `/goal` 是体内循环，容易形成 satisfy condition；而 ralph loop 是体外循环，更容易形成 adversarial re-check。认为这个功能还需打磨，或者说二者目的本身不同，`/goal` 更省资源，目标明确时能稍微改善迭代问题。

### Claude Code 用量限制与 Codex 意外重置

<u>今天群内信息量极大</u> 发现 Claude 普通账号竟然有隐藏的 monthly usage limit（org 级别）。他感叹 Claude Code 用量消耗极快，「稍微一搞就满了」，而 Codex「量大管饱，开几十个 agent 用量还跟刮痧似的」。傍晚时分，多位群友惊喜发现 Codex 用量被重置——<u>地球首帅鸭哥</u> 表示本来用了 40% 一转眼清零，<u>今天群内信息量极大</u> 也「复活了」，立刻恢复了导览项目的制作。<u>今天群内信息量极大</u> 还发现 Claude Code 新增了用量重置后自动继续的功能。

### 蒸馏 Skill 实战：Databricks 分析报告

<u>80-HD</u> 请 <u>敏锐的海狸</u> 用蒸馏后的 Skill 跑一份 Databricks 在 secondary market 股价走低的报告，与「老鸭汤」流程直出的进行对比。<u>敏锐的海狸</u> 在自己的 infra 上重建了 private company 的数据整理、审核、写作三个 agent，产出了完整的 PDF 报告。<u>80-HD</u> 评价「比直出的报告好多了」。<u>敏锐的海狸</u> 感叹老鸭汤的威力在 infra 完善后系统迭代越来越快，「当然烧 token 也越来越快」。

### AI 竟能读懂乱码文章

<u>幽默的犀牛</u> 发现让 Agent 下载<u>今天群内信息量极大</u> 的文章后全是乱码，但 AI 竟然读得头头是道，还能引用具体细节。<u>今天群内信息量极大</u> 解释这可能是编码不匹配（如 GBK vs GB2312），AI 存储时用的编码与渲染器不同，换个渲染编码即可。<u>天真的浣熊</u> 补充说还有人用摩尔斯码对 LLM 做 Prompt Injection。
