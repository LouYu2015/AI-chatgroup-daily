今天群里围绕「AI 写代码到底该不该看、怎么看」展开了一场深度讨论，<u>地球首帅鸭哥</u> 提出 AI 总爱拆掉代码中的防御性假设，<u>低调的鲸鱼</u> 也从实践中回归「AI 写我看」的模式，二人与多位群友碰撞出不少工程智慧。与此同时，<u>冷静的麋鹿</u> 分享了 skill 蒸馏的复利效应，<u>今天群内信息量极大</u> 则上线了 AI 驱动的城市文化导览网站 Guide Me，从北京 60 个景点一路做到耶鲁和火奴鲁鲁，还顺手揭示了用 DeepSeek Flash 专职写作的独特工作流。此外，<u>冷静的飞鼠</u> 分享了 FDE 模式的深度访谈，<u>淡定的喜鹊</u> 透露🍌厂终于可以用上 Claude Code 和 Codex，而<u>地球首帅鸭哥</u> 让 Codex 排查了半天摄像头故障，最后发现是物理开关被碰到了。

## 方法论

### AI 代码的防御性假设与 Code Review 常态化

<u>地球首帅鸭哥</u> 分享了一个核心洞察：自己代码中大量防御性假设（如运行到某处时数据结构必然满足某些 pattern）被 AI 视为可拆除的冗余，而这些假设根本无法用文档写清楚。<u>低调的鲸鱼</u> 表示自己也回归了「所有代码都看」的状态，AI 的价值在于加速而非替代。两人都强调，AI 写代码速度极快，但如果不做 review，「三天必坏」甚至「一个下午就没了」。

> <u>地球首帅鸭哥</u>：我试了很多方法让 AI 试图明白哪里可以改哪里不能改，但是实际上没办法表达，看来这就是 taste 的一部分

> <u>低调的鲸鱼</u>：AI 一旦开始堆💩，太快了，基本就是推倒重来

> <u>地球首帅鸭哥</u>：模块设计的好，AI 写起来就顺畅。AI 写的歪瓜裂枣也许可以说是风格问题，但是一旦开始群魔乱舞，那就有可能是设计本身的问题

<u>80-HD</u> 和<u>直率的海豚</u> 也分享了各自的 review 工作流：先让 AI review 一轮附上 PRD/plan/spec，再交给同事 review，形成「套娃式」质量保障。<u>稳重的海豚</u> 则吐槽 Codex 经常不听话写一堆 hot fix，两个月下来就得铲屎重构。

### 一次性代码 vs 可维护软件的哲学讨论

<u>沉稳的兔子</u> 抛出「爆论」：但凡需要维护的软件都是没有价值的——未来是写「厕纸」挣快钱的时代。<u>80-HD</u> 认为有一定道理，以前写码贵大家舍不得丢，现在便宜了可以每次重来。但<u>地球首帅鸭哥</u> 指出这离现实还很远，只有自己用的工具可以这么说，一旦要为别人负责就完全不同。

> <u>地球首帅鸭哥</u>：技术都是会发展的，但是我觉得 2026 年讨论这个依然像是在讲科幻片，完全看不到短期内落地的可能

<u>80-HD</u> 将程序员比喻为纽约地铁司机——「可以手动精准控制进站，但他们存在只是因为纽约地铁需要而不是地铁需要」，主要作用是担责任和骂用户不会用。

### Skill 蒸馏的「复利效应」与工具链

<u>冷静的麋鹿</u> 分享了自己的蒸馏实践心得：每天做 session 级沉淀，每周做反思蒸馏，味道越来越正。一个意想不到的副作用是，因为知道每次 session 会成为蒸馏出发点，自己做任务时反而更有动力把事情推进到位，形成正向复利。他分享了 [context-infrastructure](https://github.com/grapeot/context-infrastructure/tree/main) 仓库作为参考。

> <u>冷静的麋鹿</u>：一方面有一种，我在当老师，不要胡来。又有一种，这事儿有复利，可以多下点功夫。

<u>谨慎的狮子</u> 想把自己的 Slack/GitHub 全部交互历史系统化蒸馏，但面临量太大（几千个 PR）导致 Claude 看几个就罢工的困境。<u>今天群内信息量极大</u> 建议用 sub-agent 分组并发处理，每个 sub-agent 管十个任务、分波次执行加 QA，他自己用类似方法爬了十几年新闻数据整理出几万个事件。<u>淡定的雪豹</u> 补充说 Opus 不会偷懒会扫完所有 work，但轮数多了确实会开始偷工。<u>稳重的海豚</u> 则提到个性化定制的难题——自己的偏好经常变（比如前两天喜欢 ASCII 画图，过两天又换 SVG），导致之前的蒸馏经验要推翻。

### Codex /goal 功能初体验

<u>冷静的麋鹿</u> 测试了 Codex 新上线的 /goal 命令（需后台启用），体感不佳。他分析 /goal 的实现机制是「体内循环」，容易形成 satisfy condition，而 ralph loop 是「体外循环」，更容易形成 adversarial re-check，二者目的不同，/goal 胜在更省 token。

### 用 DeepSeek Flash 做「无 AI 味」写作

<u>今天群内信息量极大</u> 透露自己用 DeepSeek Flash 做最终写作，每天花费十几二十块人民币。工作流是：其他 AI（Claude/Codex）负责调研和框架，DeepSeek 只做组织语言的「文秘笔杆子」。<u>风趣的海豚</u> 总结出一个精妙洞察——「AI 味就是遵循指令调用工具之后深度思考的结果」。

> <u>今天群内信息量极大</u>：他思考深度不行，指令遵循不行，调用工具不行，但写作没有 AI 味

> <u>今天群内信息量极大</u>：knowledge 我帮你查好，提纲我帮你深度思考好，你就当 AI 电池除了组织语言别干任何其他事

> <u>今天群内信息量极大</u>：不要发布，不要 rsync，不不不我知道你想删库但也请不要删

## 工具

### Guide Me City：AI 驱动的城市文化导览

<u>今天群内信息量极大</u> 发布了 [Guide Me](https://guideme.city/beijing/?utm_source=wechat&utm_medium=social&utm_campaign=launch) 城市文化导览网站，首期覆盖北京 60 个景点，用 AI 调研每个景点的深层文化故事——太庙祭祀的门道、798 锯齿形屋顶的由来、雍和宫为何能用黄瓦等。他还应<u>敏锐的海狸</u> 的请求快速生成了 [耶鲁导览](https://guideme.city/yale/)，并透露火奴鲁鲁版也在制作中。整套系统使用 sub-agent 并发调研，Codex 负责大规模景点数据处理。

> <u>今天群内信息量极大</u>：在纽约住了五年，最近开始看纽约的景点，发现中央公园里面有一个三千五百年前的埃及方尖碑……让我意识到原来我 miss 了这么多有意思的历史故事

<u>80-HD</u> 指出 GLM 生成的导览翻译腔较重，<u>今天群内信息量极大</u> 坦承切到 GLM 后质量可感下降且偶发幻觉。

### Claude Code 用量、Codex 重置与各平台成本对比

群友们围绕 AI 编码工具的用量和成本展开了广泛讨论。<u>今天群内信息量极大</u> 表示 Claude Code 用量消耗极快，「稍微一搞就满了」，而 Codex 则「量大管饱，开几十个 agent 用量还跟刮痧似的」。DeepSeek API 没有订阅模式，他曾一小时烧掉 100 美元。当天 Codex 意外重置了用量，<u>地球首帅鸭哥</u> 惊喜发现从 40% 直接归零，<u>今天群内信息量极大</u> 原本只剩 3 小时也满血复活。此外 GLM 也开始加 weekly 血条并涨价 150%。<u>敏锐的海狸</u> 感叹一个周末就烧掉了一个 Cursor Ultra 账号。

### <u>敏锐的海狸</u> 的私有公司分析 Agent 系统

<u>敏锐的海狸</u> 应<u>80-HD</u> 之邀，用自建的数据整理+审核+写作三 agent 系统生成了一份 Databricks 二级市场分析报告，并表示在「老鸭汤」蒸馏体系加持下系统迭代越来越快。<u>谨慎的松鼠</u>、<u>淡定的喜鹊</u> 等也反馈蒸馏后调研报告质量和工作效率有明显提升。

### 🍌厂开放 Claude Code 与 Codex

<u>淡定的喜鹊</u> 透露🍌厂终于可以用上 Claude Code 和 Codex，目前处于 phased rollout 阶段。<u>天真的浣熊</u> 补充🍌现在可以直接 host Claude 和 GPT。<u>淡定的喜鹊</u> 表示之前用 Kiro 的 Opus 好像没有 hard limit，上个月用了 160% 还没人找。

### OpenCode 与 Oh My OpenCode 更新后的 Racing Condition

<u>今天群内信息量极大</u> 更新了 OpenCode 和 Oh My OpenCode 后遭遇诡异的 racing condition——OpenCode 端打一句话会有两三个 agent 同时回答，Oh My OpenCode 端也有独立的并发 bug，让 Claude Code 修了一整天。<u>优雅的剑鱼</u> 表示试了一圈 OpenCode 后体验不如 Claude Code，现在直接用 Claude Code 连本地模型。

## 闲聊花絮

### AI 能读「乱码」背后的编码故事

<u>幽默的犀牛</u> 发现让 Agent 下载<u>今天群内信息量极大</u> 的文章后显示为乱码，但 AI 竟然能正常阅读并准确总结内容。<u>今天群内信息量极大</u> 解释这很可能是编码不匹配（如 GBK vs GB2312）的问题，AI 本身以正确编码读取所以不受影响，换个渲染编码就能修复。<u>天真的浣熊</u> 补充说还有人用摩尔斯码做 Prompt Injection。

### 笔记本摄像头的物理开关

<u>地球首帅鸭哥</u> 让 Codex 排查笔记本摄像头故障排查了半天毫无结果，几小时后猛然意识到——摄像头有个物理开关，可能是不小心碰到了。

> <u>地球首帅鸭哥</u>：从来不知道那个东西能动

### AI 自动发报告的「心跳」惊喜

<u>稳重的海豚</u> 正在开会时收到 AI 自动发来的产品剖析 memo，感慨打开 heartbeat 功能后 AI 会自己搞出很多有价值的东西。
