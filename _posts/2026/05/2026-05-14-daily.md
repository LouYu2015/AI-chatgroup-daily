今天最值得细读的是 <u>今天群内信息量极大</u> 对 Anthropic 垂直行业扩张的分析——四天内连续推出金融、法务、SMB 三套行业方案，核心判断是 AI 产品的「复用单位」正在从代码迁移到行业 know-how，打包起来卖。<u>80-HD</u> 读完当场用今天刚上线的 Codex Mobile 跑了一份「Anthropic 下一步进哪个行业」的调研。工具话题占据了下午大半时间：<u>洒脱的狐狸</u> 一句「OpenCode 怎么用」引出六位群友各自分享 Codex / OpenCode / OMO 的选型逻辑和工作流偏好，是近期最完整的一次横向对比。

<u>细心的熊猫</u> 在另一条线上观察到 AI 时代招聘市场出现了荒诞循环——AI 自动生成的假简历对上不真正招人的假岗位，信息「疯狂流通」但找工作反而更难了。闲聊方面，昨天被 GPT 和 Gemini 双双拒绝的 Elsa 刻章图今天在 Grok 上一发成功；群友讨论了 AI 正在塑造下一代人的语言和手势——<u>今天群内信息量极大</u> 发现自己孩子打电话已经不会比划「6」了，而是手掌平贴耳朵，像在用 iPhone。

## 行业新闻

### AI 复用单位从代码走向行业 know-how

<u>今天群内信息量极大</u> 发布 [当 AI 开始卖行业，不再是卖代码](https://yage.ai/share/claude-vertical-solutions-20260514.html?utm_source=wechat&utm_medium=share&utm_campaign=claude-vertical-solutions-20260514)，拆解了 5 月 11–14 日四天内集中发生的三件事：OpenAI 成立 DeployCo 子公司派驻工程师到客户现场、Anthropic 发布覆盖 12 个法律领域的 Claude 插件并与 20+ 法律科技公司完成集成、紧接着推出 Claude for Small Business（15 个预置工作流，免费接入 QuickBooks / PayPal / HubSpot 等 SMB 常用工具）。

核心判断：AI 产品的「复用单位」经历了 token → 完成编程任务 → 行业 know-how 的三级跳。三套垂直方案共享同一个架构——预打包的领域指令、行业数据连接器、sub-agent 任务分解——但分别落地金融、法律、SMB。如果行业 know-how 确实可以被编码成机器可执行的标准化配置，Anthropic 就是在建「认知劳动的 SaaS 层」。文章也点出了这套判断的脆弱面：如果模型强到能直接从自然语言推断出 QuickBooks 数据结构，预打包的工作流还值钱吗？目前的答案是「暂时值」——壁垒不只是智能，还包括已授权的操作环境和合规框架。这与 5/11 的 [「DeployCo：OpenAI 与 Anthropic 同日建 JV，赌注完全相反」]({{ '/daily/2026/05/11/daily/#deploycoopenai-与-anthropic-同日建-jv赌注完全相反' | relative_url }}) 和 5/13 的 [「Anthropic SaaStr：Claude 不替代 SaaS，而是串联 SaaS」]({{ '/daily/2026/05/13/daily/#anthropic-saastrclaude-不替代-saas而是串联-saas' | relative_url }}) 形成了完整的三篇连续分析。

<u>80-HD</u> 提出了一个实操视角——「从 A 家招聘广告也能看出来他们的动作」。<u>今天群内信息量极大</u> 觉得这个信号很有意思，<u>80-HD</u> 随即用 Codex Mobile 跑了一份调研，按证据强度排出 Anthropic 最可能的下一批行业方向：金融/保险（概率最高，已有 10 个 finance agent templates）→ 医疗支付方 → 生命科学 → SMB → 公共部门 → 网络安全。<u>风趣的穿山甲</u> 则从组织结构角度评论：FDE 和传统的 Solution Engineer 有本质区别，「在代码编辑成本为零的时代，转型会走得更快更深」。

## 工具

### Codex Mobile 正式上线

OpenAI 宣布 [Codex 进入 ChatGPT 手机端](https://openai.com/index/work-with-codex-from-anywhere/)（iOS / Android），用户可在手机上远程控制桌面 Codex 会话——审批操作、追加上下文、跨 thread 工作。同批发布的还有 Remote SSH GA、Hooks GA、Programmatic access tokens 和 HIPAA 合规支持。目前手机远程功能仅限 macOS 主机，Windows 尚未支持。

<u>80-HD</u> 第一时间试用：老鸭汤可以直接续上，但吐槽连 Markdown 都不能渲染。<u>今天群内信息量极大</u> 表达了同样的困惑——Claude Code mobile、Codex mobile、OpenCode web 全都不渲染 Markdown，他自己在 OpenCode Android 客户端里实现了一遍，「感觉除了 url images 可能有风险以外，其他蛮顺滑的」。<u>孔哥仁且义孟哥义且仁</u> 一语道破：「ChatGPT 本身就是渲染 markdown 的……为什么换个 tab 就没有，问就是懒。」

值得一提的是这个功能的上线时机——与两天前 [「HAPI：手机远程操控 coding agent」]({{ '/daily/2026/05/13/daily/#hapi手机远程操控-coding-agent' | relative_url }}) 几乎同步。<u>今天群内信息量极大</u> 在群里分享了自己的 [OpenCode Android 客户端](https://github.com/grapeot/opencode_android_client)作为替代方案。

### OpenCode / OMO / Codex 实战选型

<u>洒脱的狐狸</u> 问了一句「OpenCode 大家是怎么用的？推荐用 OMO 吗？跟 Codex 比有什么区别？」引发了当天最长的工具讨论。六位群友各有立场：

**<u>冷静的麋鹿</u>**：从早期就用 OpenCode + OMO，核心优势是 subagent 主动性和长任务自我驱动。但「现在跟 Codex、Cowork 功能大家交叉的已经差不多了」。

**<u>80-HD</u>**：OMO 让简单任务变慢，偶尔不听话有自己想法。但别人的经验不能替代自己试——「跟小马过河一样」。

**<u>风趣的海豚</u>**：OMO 在几个月前 Codex 不够强大时是「用时间换能力和深度」的利器。但有两个问题——OMO 没法简单关掉，导致日常小任务太重；自从 Codex 升到 5.5 加了 goals，「绝大多数情况下感觉似乎用处不大了」。他强推了 [Superpowers](https://github.com/obra/superpowers) 框架——一套可组合的 coding agent 技能集，支持 Claude Code / Codex / OpenCode 等多个 harness，核心是让 agent 先澄清需求再拆分任务，然后进入 subagent 驱动的开发模式。

**<u>今天群内信息量极大</u>**：建议先试 vanilla OpenCode 不装 OMO，「它本身就蛮 Codex 平替的，加了 OMO 会有一些功能，也有很多代价」。他自己的模型配置是 Codex 订阅 + DeepSeek + GLM。

**<u>孔哥仁且义孟哥义且仁</u>**：「不用管 agent 调度，以前试图管过，不过用处不大。context window 什么的反正都是爆十几次，再怎么管也一样。」

<u>洒脱的狐狸</u> 最关心的是 OMO 的自动调度是否会与自己手动指挥 subagent 的习惯冲突。<u>80-HD</u> 的回答是「有时候会，绝大多数时候不会」。

## 方法论

### AI 时代招聘的双向伪造困局

<u>细心的熊猫</u> 观察到一个反直觉的现象：AI 让找工市场反而更需要人力了。一边是 AI 自动化生成的假简历和自动投递，一边是没钱招人但还挂着招聘启事「显得自己蒸蒸日上」的 startup。大公司也不好过——等面试流程走完，组的老大已经换坑，项目被解散了。

> <u>细心的熊猫</u>：信息疯狂流通，但是最后招人和找工作变得越来越难

他进一步指出 AI 的能力边界在于 know-how——「需要一个人在实际操作中日积月累形成的经验，等这玩意儿被 AI 学到的时候，这个 know-how 已经不值钱了」。<u>今天群内信息量极大</u> 接了一句「这 exactly 就是 context infra」——正是行业 know-how 需要被系统化编码的原因。<u>80-HD</u> 提出了日结零工化的可能性，<u>细心的熊猫</u> 反驳：「小活儿还行，大活儿需要 break down 成小活儿，这又是一个 full time job。」这条线索与 5/12 [「"Coding is Solved" 与码农的两极分裂」]({{ '/daily/2026/05/12/daily/#coding-is-solved-与码农的两极分裂' | relative_url }}) 的职业焦虑讨论形成了延续。

### 语言混沌反而让 Claude Code 更稳

<u>坦荡的灰熊</u> 分享了一个反直觉的发现：prompt 语言「混沌」一点（中英混杂、措辞不精确），Claude Code 反而做得更稳健。他的推测是：语言混沌迫使模型大范围搜索上下文，反而导致它更深入地了解了项目背景。<u>孔哥仁且义孟哥义且仁</u> 联想到 C++ 的风格——凡类型都要靠推导而不是明着写出来。

## 闲聊花絮

### Grok 生图续集：Elsa 终于到手

昨天 [「GPT Image 2 vs 迪士尼法务」]({{ '/daily/2026/05/13/daily/#gpt-image-2-vs-迪士尼法务' | relative_url }}) 中 GPT 和 Gemini 双双拒绝生成 Elsa 刻章图，今天 <u>稳重的海豚</u> 建议试试 Grok，<u>今天群内信息量极大</u> 在 SuperGrok 上一发成功，生成了一张黑白线稿版 Elsa。他感叹「grok 牛逼」。<u>孔哥仁且义孟哥义且仁</u> 补充 Grok 在内容政策上比其他模型宽松——真人限制较多，二次元容易一点。

<u>孔哥仁且义孟哥义且仁</u> 从商业模式角度观察到一个有趣现象：某些 AI 平台用聊天收入补贴画图——「lifetime 一美元每天出几百张」。

> <u>孔哥仁且义孟哥义且仁</u>：这个市场真的太庞大了，居然有人花那么多钱就为了跟 AI 聊骚

<u>今天群内信息量极大</u> 晚间进一步测试 Grok 的中文能力，发现它甚至知道微信界面风格，不过很多图仍然会被审核——「可能我关键字太黄暴了」。

### AI 文化霸权与新一代"AI 口音"

<u>灵动的北极熊</u> 抛出一个问题：AI 对语言、文字、代码、音乐的品味会不会逐步改变所有人？<u>风趣的海豚</u> 说「已经造成实际影响了」，不过他也指出人类历史上品味一直是集中向寡头垄断的。<u>孔哥仁且义孟哥义且仁</u> 承认会的，「不过无所谓，现在又不是就没有霸权」。

<u>今天群内信息量极大</u> 提到新一代小孩说话已经开始像 AI。<u>风趣的海豚</u> 预言未来会出现鄙视链——「你信不信未来会出现你说话像豆包和你说话像元宝的鄙视链」。

更直观的代际印记是手势：<u>今天群内信息量极大</u> 说孩子们打电话不会比划「6」了，都是把手掌伸平放在耳朵边上，像 iPhone 那样。<u>倔强的海狸</u>：「看动作知出生时代。」<u>细心的熊猫</u> 追问：「那如果想表达睡觉怎么办？」<u>风趣的海豚</u> 给出了精确区分：「挨着不动是睡觉，隔着摇是电话。」
