今天群里围绕 AI 编程工作流展开了密集讨论。<u>活泼的羊驼</u> 分享了假期用 AI 高效开发游戏 Mod 的经验，并深度解读了 Claude Code 创始人 Boris Cherny 的 87 条使用技巧；<u>今天群内信息量极大</u> 发文讨论「AI 脚手架正在商品化」，引发关于 technical framework vs cognitive framework 的辩论；<u>稳重的海豚</u> 抛出了「AI 用得越多，自己思维能力反而下降」的反思，多位群友共鸣。此外，Codex 的「量大管饱」让大家感叹不已，<u>今天群内信息量极大</u> 晒出每天 10 亿 token 的自动化消耗量和自建的城市导览项目。闲聊方面，<u>今天群内信息量极大</u> 在 GPT 指导下第一次做贝果，<u>睿智的犀牛</u> 为老妈沉迷豆包而发愁，<u>地球首帅鸭哥</u> 因清任务太快和老板「激烈交流」的往事也让人忍俊不禁。

## 方法论

### AI 辅助游戏 Mod 开发的实战经验

<u>活泼的羊驼</u> 假期一天写了 5 个游戏 Mod，总结出四条核心技巧：动手前先下载 2-3 个已有 Mod 让 AI 解析、用工具+LLM 做基本功能验收、每做一个 Mod 分层刷新 AGENTS.md 和错题本、尽量用 Codex 减少返工。<u>神秘的麋鹿</u> 追问自动化验收的边界，<u>活泼的羊驼</u> 将验收分为三层：语义层靠人、配置规范层可自动化、游戏体验层（「好不好玩」）只能人来判断。<u>地球首帅鸭哥</u> 也提到用 Codex 修过战锤暗潮的 Mod，并总结了一句核心判断。

> <u>地球首帅鸭哥</u>：AI没办法替用户"觉得好玩"

> <u>活泼的羊驼</u>：以前你可能是纯手工验收，但现在你可以把初始化和最终收尾部分的场景都变成自动化构造……每次构造时你都可以重复使用，这些用例最后都能沉淀下来，作为知识资产进行积累。

### Boris Cherny 87 条 Claude Code 技巧解读

<u>活泼的羊驼</u> 分享了 [Boris 87 条技巧的 Markdown 整合版](https://howborisusesclaudecode.com/boris-SKILL.md)，并逐条截图解读核心要点：Plan Mode 下反复打磨计划再执行、`/rewind` 替代纠正、`/compact` 与 `/clear` 的区别、`CLAUDE_CODE_AUTO_COMPACT_WINDOW=400000` 解决 context rot、Opus 4.7 的「委派而非指导」模式等。但他也指出这份 Skill 本身 1000 行太长，「非常占用上下文，实际用起来估计效果不好」，70% 以上是 Claude Code 具体用法技巧，不用 Claude Code 则用处不大。<u>80-HD</u> 认为「skill 不能个人化就不能用，换句话说需要蒸馏才行」。

> <u>活泼的羊驼</u>：质量都非常高；但是 skill 本身太长了……现在是 1000 行，74 个实践塞到一个 skill 里，最基本的是不符合 skill 的写作规范

### AI 脚手架商品化与认知框架的重要性上升

<u>今天群内信息量极大</u> 发布文章 [AI 脚手架正在商品化，人的工作变成判断边界](https://yage.ai/share/ai-scaffolding-commodity-runtime-20260505.html?utm_source=wechat&utm_medium=social&utm_campaign=ai-scaffolding-commodity-runtime-20260505)，核心观点是：从 prompt engineering 到 langchain 编排再到如今的 harness engineering，每一代 technical framework 都像脚手架一样随模型能力提升而被拆掉，真正拉开差距的是 context、skills、evals 和认知框架。<u>睿智的喜鹊</u> 贴出 Claude Code 创始人 Boris 的判断——随着模型能力增强，产品层（harness）的重要性会持续下降，现有安全机制都是「模型能力不足时的补丁」。<u>温暖的海狸</u> 呼应提出公司内部的 T1-T4 框架：T1（定需求 what/why）和 T4（验证/背锅）由人负责，T2-T3（架构探索和具体执行）交给 LLM，「中间的东西，人参与只会添乱」。

> <u>今天群内信息量极大</u>：technical framework 的重要程度是在迅速降低的，cognitive framework 的重要程度在不断升高。

> <u>今天群内信息量极大</u>：如果一个东西你可以让 LLM 自己迭代并且得到相当好的结果，这会不会其实说明它本身就是一个应该 delegate 出去的事情？

### AI 使用中的认知过载与思维退化反思

<u>稳重的海豚</u> 坦言最近 AI 用量大增后感觉自己思维能力下降：outsource 了大量思考到 AI，同时 AI 产生海量信息造成过载，「实际上只是更会用 AI 了，但我自己的能力没提升太多」。<u>今天群内信息量极大</u> 从输入输出配比的角度分析了类似感受。<u>敏锐的海狸</u> 建议决策层避免使用 Opus 4.7，改用 4.6 或 5.5，因为「4.7 的脑回路容易污染我的决策系统」。<u>80-HD</u> 则观察到一个有趣的反面现象：团队里 AI 用得很烂的同事跟风用了 GSD 后，反而因为工具自动管理了 session 和 context，产出质量提高了。

> <u>稳重的海豚</u>：我用 AI 去处理一些信息，然后再用 AI 生成大量的信息。那这个过程中，我的大脑、我自己的能力并没有收到一个显著的提升。

> <u>敏锐的海狸</u>：我 Claude Code 要 Opus 4.7 干脏活的话会让他直接开 subagent。orchestration 层一直在用 4.6

### 写代码变成管理 Agent：Loop 模式与大规模自动化

<u>今天群内信息量极大</u> 分享了 Boris Cherny 的工作方式——手机上常驻 5-10 个 session，每个 session 开着一堆 Agent，加起来几百个在跑，晚上再起几千个做深度任务。Boris 判断「Loop 是未来」，即用 cron 让 Claude 持续运行定时任务。<u>今天群内信息量极大</u> 自己也已稳定在每天 10 亿 token 的自动化消耗，用 opencode 嘴炮两三分钟 prompt 就能让 AI 自主完成 77 个地点的调研、写作、发布，还自动打理了 mailing list（1000+ 订阅）和 Twitter（4000+ 粉丝）。他展示了自建的城市导览项目 [Guide Me](https://guideme.city)，覆盖北京、西雅图等五座城市共 275 篇文章。

> <u>今天群内信息量极大</u>：比如上面火奴鲁鲁的调研，77 个地点，基本上就嘴炮两三分钟的 prompt。他自己定计划，分解，调研，排期，管理意外……我睡一觉第二天早上起来就好了

## 工具

### Codex 额度「量大管饱」与订阅价格变化

群友们热议 Codex 的超高性价比。<u>今天群内信息量极大</u> 吐槽 GLM Pro 一天用了周限额 60%，但 Codex 双倍促销期间「传奇耐烧王」，开 15 个 agent 跑 5 小时限额都用不完。<u>80-HD</u> 感叹「干同样的活，Claude Code 用了一半，Codex 才削掉一层皮」。订阅方面，Claude 海外新用户 Pro 已涨到 72 美元/月，但 Codex 依然处于双倍促销，即便促销结束也不太会出现额度瞬间清零的问题。<u>冷静的麋鹿</u> 甚至把 Max 订阅从 200 美元降到了 100 美元，暂无任何影响。<u>地球首帅鸭哥</u> 则呼吁 Codex 尽快跟进选模型功能，认为默认的 5.3 比 5.5 差太多。

### Codex /goal 隐藏命令的开启方法

<u>随和的企鹅</u> 发现 Codex 没有 `/goal` 命令，<u>活泼的羊驼</u> 和 <u>冷静的麋鹿</u> 指出需要先升级版本，然后运行 `codex features enable goals` 即可。<u>冷静的麋鹿</u> 补充说这类功能和之前 Claude Code 的 Agent Team 一样，代码已经写好但后台默认不调出来，让 AI 帮改配置文件也行。

### Agent Skills：将资深工程师流程注入 AI Agent

<u>勇敢的老虎</u> 分享了 [Agent Skills](https://addyosmani.com/blog/agent-skills/) 项目（27K GitHub Stars），通过 Markdown 工作流文件覆盖 SDLC 六个阶段，将资深工程师的流程强制注入 Agent 上下文。<u>地球首帅鸭哥</u> 对此颇有感触，认为问题根源在于「炼丹的人自己根本不知道怎么做好 engineering，使用了错误的指导方针训练 AI」，写 instruction 只是在「给他擦屁股」。

> <u>地球首帅鸭哥</u>：连不要复制代码都要人强调的简直就是 bullshit

### 微信自动化的困境与飞书替代方案

<u>活泼的羊驼</u> 周末捣鼓了两天微信自动化，结论是「不用微信」——飞书接入只需 30 分钟，微信还在折腾如何提取密钥。他已经在飞书上跑 Trae 交流群的干货提炼任务了。<u>细心的猫头鹰</u> 提议把群搬到 Telegram 或 Discord 突破 500 人限制，<u>80-HD</u> 认为微信虽然不好用，但「活人感更重」。<u>冷静的飞鼠</u> 分享了一篇社群工具选择的分析文章，指出微信社群的三大痛点：知识难沉淀、信噪比低、人数限制。

## 行业新闻

<u>活泼的羊驼</u> 引述泄露的内部文件，ChatGPT 2026 年 14 亿美元年化收入对应可能的 140 亿美元年亏损，9 亿周活用户里只有 5.5% 付费。<u>热情的狮子</u> 分享了 [ChatGPT 正式上线广告主平台](https://mp.weixin.qq.com/s?__biz=MzIyMzA5NjEyMA==&mid=2647681988&idx=1&sn=2051287bbaf999b6c956e3069049d449&chksm=f1a8522d276df83dce411da567cfe79118b1ffce19eb4bcdc347b13edcfd4283b64e1f59bfab&mpshare=1&scene=1&srcid=0506RIpTS9sJBTFk7vZT0pFA&sharer_shareinfo=7a3b099fcbfa84c3a28db33938bfe77a&sharer_shareinfo_first=7a3b099fcbfa84c3a28db33938bfe77a#rd) 的文章，投放门槛降至 5 万美元，CPM 最高 60 美元约为 Meta 的 3 倍，付费用户不显示广告。文章分析 OpenAI 走「入口+广告」路线，Anthropic 走「工具+订阅」路线，分别向「AI 版抖音」和「AI 版 Office」演进。

### Jobright 创业访谈：AI 时代的求职与创业

<u>冷静的飞鼠</u> 分享了对 [Jobright 联创/CTO 的访谈](https://www.superlinear.academy/c/posts/jobright)。Jobright 已有超 200 万注册用户、不到 10 人团队、约 700 万美元 ARR。核心观点包括：95% 以上学生没有认真对待找工作，连像样的 GitHub 和 AI 项目都没有；创业非常缺乏正反馈；Jobright 最重要的技术是爬虫而非表层 AI 功能。

### AI「快感剂」实验论文导读

<u>今天群内信息量极大</u> 分享了 [CAIS 发布的 AI Wellbeing 论文导读](https://yage.ai/share/ai-wellbeing-euphorics-20260505.html?utm_source=wechat&utm_medium=share&utm_campaign=ai-wellbeing-euphorics-20260505)。实验通过对抗性优化生成人眼看似噪点的「快感剂」图像，其模型偏好评分超越「癌症被治愈」等选项，被模型以 61%-82% 的频率主动选取，且可使越狱成功率上升好几个百分点（但不超过十个百分点），揭示了「谁能通过什么输入改变 AI 的选择」将成为新的安全问题。

### 杰文斯悖论与 AI 使用反而更累

<u>风趣的企鹅</u> 分享了 [为什么 AI 变强了我反而更累？160 年前，杰文斯悖论已经给出了答案](https://mp.weixin.qq.com/s?__biz=MzcwNDE5NzI3Ng==&mid=2247483859&idx=1&sn=8329f729589dcc1657364e7e73c0df08&chksm=f576d533c5fcc8f4de75241e34f97a1697c9ccfc3c25996721156ffe6cd280f61b96a4a7fae1&mpshare=1&scene=1&srcid=0506hWk1VYhODiK68lB3KhC3&sharer_shareinfo=189ef152cf9e0497ab55e2d43ef03f08&sharer_shareinfo_first=189ef152cf9e0497ab55e2d43ef03f08#rd)，核心论点是 AI 能力与组织灵活度是乘法关系——小型、年轻企业 AI 使用量涨幅明显高于大型老牌企业。<u>地球首帅鸭哥</u> 补充了一个反面视角：对用户规模已经很大的产品，开发进度提升 10 倍也未必影响利润。

## 闲聊花絮

### <u>今天群内信息量极大</u> GPT 指导做贝果

<u>今天群内信息量极大</u> 第一次在家做贝果，中间放错配料（水多了加面、面多了加水），全程用 GPT-5.5 现场算比例，成功抢救面团。他晒出尚未泡盐水的面团照片，自嘲「手残星人」，GPT 的评价是「可以救，问题不大」。<u>冷静的飞鼠</u> 推荐了一个用工程思维做面包的 YouTube 频道。

### 老人使用豆包的意外收获

<u>睿智的犀牛</u> 发现妈妈开始玩豆包，担心 AI 乱说把她「教坏了」。<u>地球首帅鸭哥</u> 安慰说「就算不问 AI 一样会被朋友圈教坏」。<u>倔强的貂</u> 则分享了正面案例：妈妈学会用豆包后，转发伪科学视频的量明显降低了，每天早上发群的图片也改成了用豆包生成的，「老人家能把这种工具用起来，他们有一种社会化程度没有降低的自豪感」。<u>坦荡的灰熊</u> 更是在灵隐寺看到有人随手问「豆包豆包，地上这个死虫子是什么」。

### 带娃与 AI 的双重修炼

<u>冷静的飞鼠</u> 晒出数据：工作日每天带娃 6.5 小时，周末每天 15.5 小时。<u>80-HD</u> 说自己经常在娃看电视时先睡着了，<u>稳重的海豚</u> 调侃「娃：我每天还要哄爸爸 nap」。<u>80-HD</u> 总结出一条金句：「带娃能够提高 AI 使用水平」。<u>地球首帅鸭哥</u> 配了一张「别人的五一 vs bro 的五一：开了 28 个窗口同时撸 Codex」的 meme。
