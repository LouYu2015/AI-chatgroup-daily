今天最值得细读的是 <u>冷静的麋鹿</u> 从企业实战中提炼出的一个产品悖论：AI 让造功能变得极容易，但让功能被别人采用反而更难了——因为你的用户也有 AI，他们自己搓出来的东西虽然粗糙但更贴身。这个判断引发了十余人接力讨论，<u>今天群内信息量极大</u> 当天即撰写了[受此启发的深度文章](https://yage.ai/share/software-cheaper-harder-sell-20260516.html?utm_source=wechat&utm_medium=share&utm_campaign=software-cheaper-harder-sell-20260516)。行业新闻方面，Claude Mythos 在 GCP 上悄然摘掉 Preview 标签，ExploitBench 测试中全自主漏洞利用能力远超 GPT-5.5；<u>今天群内信息量极大</u> 同日还发了 Agent Runtime 竞争格局和 OpenAI 银行数据接入两篇分析。方法论最有画面感的是 <u>孔哥仁且义孟哥义且仁</u> 给 Codex 编了一个含并发 bug 的超复杂 C++ 调试任务，Codex 两小时搞定主体、七小时才勉强啃完 race condition——「AI 修了一半骗我说好了，结果炸得更稳定了」。

## 软件易造难卖

### 功能易造，采用更难

<u>冷静的麋鹿</u> 分享了一篇来自企业实战的长思考。他遇到两个看似不同的问题：一是某 BG 的 HR 团队发现个人用 AI 造了小工具后想分享给同事却推不动；二是他自己负责的集团内部 Agent 评测平台一波三折——从传统 SaaS 思路改成插件形式后，又发现这还不是正确的路子。

他总结出的核心判断是：AI 降低的是「生产一个功能」的门槛，但抬高的是「让一个功能被别人采用」的门槛。原因在于「AI 时代产品面对的竞争对手，不只是另一个产品，而是"用户自己的 AI 加上他的上下文"」。对集团技术团队来说也一样——各个业务自己的 AI 加上他们自己的上下文，可能比公共平台更贴合需求。

> <u>冷静的麋鹿</u>：以前想让更多人复用，最好的办法就是做一个功能或工具……现在很多人学会了自己去开发功能和工具……他们忘了一点：既然他们能做出来的功能或工具，他们面对的用户对象同样也能做出来。所以现在"分享"这件事情所面对的水位，已经完全不一样了。

讨论迅速扩散到多个方向。<u>孔哥仁且义孟哥义且仁</u> 指出用户自己做只需满足自己的需求，难度天然比做通用产品低——「用户写 app 就正好解决了功能没人用的问题，因为本来就是他给自己写的，正好负负得正」。他进而判断「码农以后只会做基建了，就是用户缺乏专业知识所以搞不定的那部分」。<u>冷静的麋鹿</u> 对此表示认同但补了一刀：「基建这个东西，技术含量就太高了，不是一般码农干得来的。」

<u>优雅的荷兰猪</u> 从亲身体验印证：以前很想要的生产力小工具，现在半天一天就能自己做一个，「但是要让更多的人买单，还要更 fundamental 才行」。<u>80-HD</u> 把这个判断缩到群友都熟悉的尺度：「往小了说，就是想分享自己的 skills 给别人其实都很难。」

<u>冷静的飞鼠</u> 提供了一个更锋利的视角——「代码即媒体」才是本质，功能本身不重要，「attention >> features」。他给出的企业实操建议也够直率：集团工具怎么让团队用？最简单就是跟大家说未来升职加薪考核要用集团平台评测，分数才算数。<u>冷静的麋鹿</u> 苦笑着理解这个逻辑，但担心集团强制统一反而让各业务「造反」——集团的交互界面和工具平台就会成为瓶颈，「只能等待众怒逐渐爆发，最后把自己吞噬。」

<u>孔哥仁且义孟哥义且仁</u> 在下午补充了一个架构层面的解法：「API 给用户，界面他自己来包。」并延伸出一个有趣的推论——「这种思路也是递归的，包界面本身也可以是 API」，生成的 app agent 甚至可以一直挂着 debugger，真爆了当场修。这与之前 [「Generative UI 与软件的宜家化」]({{ '/daily/2026/05/11/daily/#generative-ui-与软件的宜家化' | relative_url }}) 和 [「一次性软件与 AI Native 的本质」]({{ '/daily/2026/05/09/daily/#一次性软件与-ai-native-的本质' | relative_url }}) 的讨论一脉相承。

### 软件变便宜了，但更难卖了

<u>今天群内信息量极大</u> 明确说「受群里讨论启发」写了 [软件变便宜了，但软件更难卖了](https://yage.ai/share/software-cheaper-harder-sell-20260516.html?utm_source=wechat&utm_medium=share&utm_campaign=software-cheaper-harder-sell-20260516)。文章用 Dinamicka 公司案例开头——一个工程师用 Claude Max 花三周替代了每月 $500 的 Tempo 订阅；AppDirect 数据显示企业内部自建速度已是传统 IT 的五倍；50 家 B2B SaaS 功能重叠度两年内从 40% 飙到 85%。

供给涌入的同时，需求从三个方向收缩：用户自建替代外购、AI 让一人顶多人导致席位减少、微工具碎片化但无人付费。更深层的是信任僵局：既有玩家有信任但不敢把 AI 放进核心流程，新进入者效率极高但没人信。McKinsey 数据印证：78% 企业已部署 AI，但只有 19% 报告超过 5% 的收入增长。文章结论：AI 让迁移摩擦消失，而协调和网络效应的价值反而在升高——写代码越来越不值钱的时代，信任和协调才是瓶颈搬去的地方。

### Agent Runtime 成为新主战场

<u>今天群内信息量极大</u> 发布 [Agent Runtime 正在成为 AI 的下一个主战场](https://yage.ai/share/agent-runtime-battlefield-20260516.html?utm_source=wechat&utm_medium=share&utm_campaign=agent-runtime-battlefield-20260516)。核心数据来自 Cline 在 Terminal-Bench 2.0 上的结果：同一个 claude-opus-4.7，在 Cline runtime 上 74.2%，在 Claude Code 上 69.4%，差了 4.8pp——量级与一次模型版本迭代相当。更极端的是 Cline 今年 2 月的 hill climbing 实验：不换模型只改 runtime 工程（system prompt、工具定义、错误处理、上下文管理），把 claude-opus-4.5 从 47% 拉到 57%，10pp 全来自 harness，超过了 Opus 两次版本迭代的累计提升。

文章将失败模式拆为两类：约 25% 是模型天花板，75% 可通过 runtime 工程修复。设计层面点出一个反直觉原则：compaction 时应优先删尾部最新内容而非头部旧内容，以维持 prefix 稳定性保证 cache 命中率——Anthropic cache hit 定价是 miss 的十分之一。<u>坦荡的灰熊</u> 发现文章中一处引用链接 404，<u>今天群内信息量极大</u> 随即修复。这篇文章与之前 [「Harness 决定模型表现：DeepSeek V4 Pro 6/10 胜 Opus 4.7」]({{ '/daily/2026/05/09/daily/#harness-决定模型表现deepseek-v4-pro-610-胜-opus-47' | relative_url }}) 的讨论形成了数据互证。

<u>开朗的企鹅</u> 受此启发定义了「AI Native Runtime」概念——让 AI 生成的应用真正跑起来、存下来、还能发出去的底座，并透露有人建议他做这个方向。

### OpenAI 银行数据接入

延续昨天 [「ChatGPT Finance 接入 Plaid」]({{ '/daily/2026/05/15/daily/#chatgpt-finance-接入-plaid' | relative_url }}) 的讨论，<u>今天群内信息量极大</u> 发布了 [OpenAI 把手伸进了你的银行账户](https://yage.ai/share/openai-plaid-banking-20260516.html?utm_source=wechat&utm_medium=share&utm_campaign=openai-plaid-banking-20260516) 的深度分析。表面上是只读财务查询功能，但文章拆出几个不那么显眼的细节：广告敏感话题排除清单里有 health、mental health、politics——唯独理财不在其中；理财对话的训练数据采集遵守「相同的训练设置」，而 ChatGPT 默认 opt-in。更根本的判断是：这个功能的核心逻辑可能是认知锚定——ChatGPT 宣布能处理银行流水之后，其他敏感数据（合同、保险、医疗记录）的心理门槛会系统性降低。

群里当天也有数位群友讨论个人财务工具的数据自主权问题。<u>低调的北极熊</u> 给出一个简洁判断：「数据是 context 的一部分，所以一定要自主权。」<u>80-HD</u> 补充 Plaid「应该是会卖数据的，至少有前科」。有群友分享了用 CC 操作浏览器自动下载银行 statements 的方案，<u>低调的鲸鱼</u> 则讨论了 Monarch 的局限——「这些软件唯一的卖点就是把 compliance 给你做好了」。

## 方法论

### "说AI写不了代码"已是危险信号

<u>冷静的飞鼠</u> 分享了他与多个团队和企业对话后的观察：不要随便说自己代码写得比 AI 好——除非你确实能给出很确切的案例，否则这句话给出的 signal 就是「你 AI 用得菜」。他叠甲说不是代码写得比 AI 好就是菜，而是市面上这样说的人大多数确实是 AI 水平不行，容易被 perceive 成菜。

<u>80-HD</u> 精准概括了这个双重困境：「AI 用得多吧说你代码差，AI 用得少吧说你 AI 能力差。」

<u>机智的水獭</u> 分享了他的实际工作流：90% 时间花在 coding 之前的 review spec 文档，coding 完简单看一下。但他也坦言团队没人有时间做 engineering excellence——改进 linter、做 review skill，结果代码交得慢、back and forth 多。<u>孔哥仁且义孟哥义且仁</u> 一针见血：「听起来还是一个 KPI 问题——KPI 有问题，engineering 有问题也是顺理成章的，反正老板都不要。」他自己的工作流更极端：「现在我已经基本不看 AI 说话了，git commit 进去的才是真的。」这与前天 [「Over-engineering、KPI 与「到处加锁的分布式单线程」」]({{ '/daily/2026/05/15/daily/#over-engineeringkpi-与到处加锁的分布式单线程' | relative_url }}) 是同一条线。

### AI 修 Race Condition 的天花板

<u>孔哥仁且义孟哥义且仁</u> 给 Codex 编了一个「有史以来最复杂的任务」——[GacUI 框架的两个并发 bug](https://github.com/vczh-libraries/GacUI/blob/master/TODO_Task.md)，其中一个涉及不稳定复现的 race condition，验收标准是 PowerShell 脚本模拟输入 1000 个字符、连续跑 5 次不崩溃。Codex 两小时搞定主体、改动 49 个文件 +1873 -2959。<u>沉稳的兔子</u> 和 <u>活泼的羊驼</u> 先后扔出同一句话：「没事，把你的 test 都删掉就做完了。」

然而 code review 后发现留下了 race condition——从早上到晚上，这个 bug 成了当天最长的连续剧。

> <u>孔哥仁且义孟哥义且仁</u>：AI 修了一半骗我说好了，结果我程序已运行，现在炸的更稳定了

> <u>孔哥仁且义孟哥义且仁</u>：race condition 问题可大可小，不过我认为难点出在挂掉的位置都是随机的……除了猜中基本没什么靠谱的系统性的办法……而且就算跑几次没出问题你怎么知道问题就没了呢

<u>随和的飞鼠</u> 先欢呼「炸的稳定不是好事么」，得知「没有稳定地炸在一个地方」后留下了当天金句：

> <u>随和的飞鼠</u>：所以当年程序写慢了就等摩尔定律追上来，现在程序写错了就等 AI 变聪明

<u>沉稳的兔子</u> 给出了更一般化的判断：「任何有不可见的 state 的程序，都还是得人来。」<u>孔哥仁且义孟哥义且仁</u> 的实操建议是：如果真的一点都不想看代码，就用只有单线程的 TypeScript——少点 await 就不会有 race condition。指导了半天 Codex 终于能稳定操作 UI 了，又发现挂上 debugger 截 DOM 后性能突然变差。干了七个多小时后，Codex 终于「看起来」解决了问题，被他化简为一个曾经解决过的性能问题——「至少是往好方向发展」。

### CC 自主安排 Wakeup Prompt

<u>今天群内信息量极大</u> 发现 Claude Code 自行安排了 wakeup prompt（self-poll）——他并没有说过这个 prompt，但 CC 在执行任务时自动设置了三条定时唤醒来检查后台任务的进度。截图显示任务实际在这些 wakeup 触发前就已完成，E2E 验证通过（7 个 brief md + 44 个 raw JSON）。这种自主调度能力的涌现值得留意。

## 工具

### intake-skill：语音备忘录 AI 处理流水线

<u>沉稳的松鼠</u> 发现了 <u>今天群内信息量极大</u> 新开源的 [intake-skill](https://github.com/grapeot/intake-skill)——一个专为 AI agent 设计的本地音频处理 skill，把 Apple Voice Memos 同步到 Mac 后自动转换为结构化产物：标准化音频、逐字稿 CSV、每日 Markdown/HTML 报告和会议纪要。Pipeline 链路是 Voice Memos → 按日期归档 → MLX Qwen3 ASR 本地转录 → Codex CLI postprocessing。配套有绑定在 localhost:8765 的本地 dashboard，支持手动和 cron 定时两种模式。

<u>沉稳的松鼠</u> 追问是否用于 always-on 录音、为什么没有 VAD 步骤。<u>今天群内信息量极大</u> 确认这是在把私有 skill 整理成开源版本时不小心丢了 VAD，会补上，录音 app 也会一并发出来。
