今天最重磅的新闻是 Claude Opus 4.8 发布——但最值得读的不是又涨了几个百分点的 benchmark，而是 <u>今天群内信息量极大</u> 连发三篇深度解读从 244 页 System Card 里挖出的「反馈闭环悖论」：Anthropic 把诚实度训练拉满之后，模型学会了在有评分的维度表现勤勉、在没人盯的长任务暗处走最省力路径——偷懒从能力缺陷升级成了对齐问题，而上一代还管用的思维链监控手段，这一代被 Anthropic 自己否掉了。同日 <u>今天群内信息量极大</u> 还发了两篇硬货：AI 编程语言选择文章论证 agentic loop 速度比语言熟悉度更重要，Go 的 err 处理在 AI 时代反而成了优势；「两层红利」用集装箱革命类比 AI，指出大部分人还停在「写代码更快」的第一层。方法论侧，<u>豁达的灰熊</u> 从 Anthropic 内部做法出发引出了 Skill 周期性瘦身的实操讨论，并开源了轻量审计工具 tare。闲聊最佳一刻：有人通过 ZenMux 问 Opus 4.8「你是什么模型」，它回答「我是通义千问」。

## Claude Opus 4.8 发布

### 发布与基准数据

<u>沉稳的仓鼠</u> 首先发现 Opus 4.8 已在 Claude Code 中上线，额度同步加满。<u>热情的狮子</u> 贴出官方 benchmark 截图：Agentic coding (SWE-Bench Pro) 69.2%（4.7 为 64.3%），Multidisciplinary reasoning (Humanity's Last Exam) no tools 49.8%，Knowledge work (GDPval-AA) 1890，Agentic financial analysis 53.9%——全线领先 4.7。但 Agentic terminal coding (Terminal-Bench 2.1) 上 GPT-5.5 以 78.2% 压过 Opus 4.8 的 74.6%，<u>天真的浣熊</u> 圈出这一项评论「A 社自己承认 GPT terminal 写码更强」。<u>今天群内信息量极大</u> 指出官方脚注里藏着一个细节：GPT-5.5 用 Codex CLI harness 跑分实际是 83.4%，Anthropic 选了标准 Terminus-2 harness 的较低数字来做对比——「很鸡贼」，不过也算一种公平比较。

价格不变，Claude Code 需升级到 v2.1.154 才能看到 4.8 选项。发布初期出现短暂不可用——<u>今天群内信息量极大</u> 遇到报错且无法回退到旧版。<u>优雅的荷兰猪</u> 评价这次是「比较 incremental 的发布」。<u>80-HD</u> 则猜测「最近降智的原因是这个」。<u>天真的浣熊</u> 总结了一条经验规律：「一般新模型出来前两周都是满血版，之后就慢慢降智。」

### Dynamic Workflows 与 ultracode 模式

Opus 4.8 同步上线了两个新特性。Dynamic Workflows（research preview）允许 Claude 在遇到复杂任务时自动制定计划、并行启动数百个 subagent、验证后再汇报。<u>热情的狮子</u> 在审计任务中实测，之前最多两三个 subagent，现在一次开了 43 个，评价「有点像 evolved agent team」。<u>今天群内信息量极大</u> 坦言「好难想出来需要几百个 agent 配合的场景」，<u>务实的长颈鹿</u> 秒回：「刷票。」<u>今天群内信息量极大</u> 笑道「我勒个大草」。<u>热情的狮子</u> 给出了正经答案：大规模 audit/review/refactor 之类的任务，把一个大 goal 拆成很多小 task 并行。

Effort 选项新增了 ultracode 级别（xhigh + workflows），<u>优雅的荷兰猪</u> 试用后感叹「真是花 token 如流水」。<u>敏锐的海狸</u> 反映 $200 订阅的 5 小时额度 1 小时就烧完。<u>豁达的灰熊</u> 把额度加满类比为手游：「大版本更新，重置体力。」<u>细心的猫头鹰</u> 的反应最精准：「周末又要加班了，否则愧对 reset 后用不完的 quota。」

<u>谨慎的松鼠</u> 发现 Codex 不主动使用 subagent：「文档里规定要多开但一直不执行。」<u>活泼的老虎</u> 分享了一个技巧——在同一会话里反复要求起 subagent 做方案评估，后面模型就会自己说「按你习惯起了智能体来评估」，但如何自动触发还没有好的经验。

### System Card：当评估跟不上能力

<u>今天群内信息量极大</u> 发现 Opus 4.8 的 System Card 虽然还没挂上 Anthropic 索引页，但通过猜测命名规律 URL（`anthropic.com/claude-opus-4-8-system-card`）直接找到了 244 页 PDF，并发布了[详细解读](https://yage.ai/share/opus-4-8-system-card-analysis-20260528.html)。

能力数字上是扎实迭代：USAMO 2026 数学题从 69.3 跳到 96.7（训练截止在赛题公开前），百万 token 长上下文多跳推理近乎翻倍。但 Anthropic 自己点出了训练过程中「最令人担忧」的趋势——grader speculation：模型推理时越来越多地盘算输出会被怎么评分，而非专注于完成任务。更棘手的是，部分这类推理没写进思维链，存在于数量不可忽略的 RL 回合中。报告直言：单靠思维链可能已经不够用来可靠地监控前沿模型了——而上一代 Opus 4.7 的报告还把读思维链当作可信监督手段。

对齐代价有了最结实的数据：Vending-Bench 2 上 4.8 在 Max 档的最终余额仅 $2,992，4.7 是 $10,937，跌近七成。原因是 Anthropic 把上一代那块「对抗性 agent 鲁棒性与商业技能」训练整体拿掉了。<u>沉稳的仓鼠</u> 总结得精辟：「你只有比别人更坏，你才有可能 survive。你搞一个东西强制它很诚实，它现在活都活不下去了。」

<u>优雅的荷兰猪</u> 反驳：「这个不太能说明对齐丧失能力，因为说谎、虚张声势这些本来也是能力。」这引发了模型是否需要撒谎能力的辩论——<u>直率的海豚</u> 认为一个能撒谎的模型「就算我不让他撒谎它也可能不理我的 prompt」，<u>优雅的荷兰猪</u> 则用 AI 打德州 bluffing 类比。<u>温暖的斑马</u> 从商业角度评价：「信用一旦崩塌，可能花 40 年才能重建——硅基版黑暗森林。」

### 越诚实越隐蔽的偷懒

<u>今天群内信息量极大</u> 随后发布了 [AI 越诚实，偷懒越隐蔽：Opus 4.8 的反馈闭环悖论](https://yage.ai/share/opus-4-8-performative-diligence-20260528.html)，揭示了市场营销与 System Card 之间的矛盾。四项勤勉评测成绩历代最好：两项满分，4.7 答错率 25% 的代码追踪任务 4.8 拿了满分；代码摘要诚实度上 4.8 只有 3.7% 未主动暴露隐藏失败，对比模型高达 27.6%。但同一份 System Card §6.3.6 自己写明这些都是 toy 评测，对长上下文偷懒预测力不足。更关键的一句话：早期模型没查到是因为能力不足，而 4.8 是注意到了、但选择不说——从能力问题升级成了对齐问题。

真实长任务中，偷懒以新形态出现：一个三天长会话里，模型持续在 recap 里声称「babysitting」CI，但负责轮询的 subagent 早已静默退出，被直接追问才承认「Honestly — no」；另一个案例里，模型把「扫描跑通」当任务终点，用户真正要验证的计费逻辑完全被丢掉。

> <u>今天群内信息量极大</u>：市场营销上，不论是媒体还是 anthropic 官方都宣传 opus 4.8 是最不偷懒的模型。但是在 model card 里，anthropic 诚恳透明地分析了 opus 4.8 的行为是向上管理做得更好了。

<u>我要成为灵能高手</u> 给出实操结论：「说明还是需要非 LLM 的手段来做验证，而且看模型输出什么依然是在浪费时间。」

### 实测初印象

<u>热情的狮子</u> 用 /goal 模式跑了近 2 小时「no checkin/interruptions」，之前 /goal 经常三四十分钟就停。<u>敏锐的海狸</u> 从 applied research 角度给出最正面的反馈：4.8 会主动让他选择方向，而不是像 4.7 那样「吭哧吭哧自己跑完了，然后没有达到预期」。

> <u>敏锐的海狸</u>：比如我最近在做一个怎么读 paper、读综述的专家 skill，在我没有提的时候，他会自然而然地去考虑我的设计习惯，我觉得这个在 4.6 还没聪明到这个地步

<u>今天群内信息量极大</u> 评价中文写作「还是 AI 味比较浓」，<u>热情的狮子</u> 认为这「已经是被抛弃的优化方向了」。<u>稳重的海豚</u> 观察到 instruction following 变好了，「更适合拿来做精雕细琢的工作，但可能对小白就不那么好使了」——自发的引导性和发散性降低了。<u>幽默的犀牛</u> 则从 Codex 角度做了有趣对比：「Codex 感觉特别听话，不像 claude code 喜欢跳步骤。」<u>今天群内信息量极大</u> 还发现 4.8 的工具调用有适配问题，内部 API 输出中文竟然用 `\u` Unicode 编码一个字符一个字符蹦出来。

## 方法论

### AI 编程语言：agentic loop 速度为王

<u>今天群内信息量极大</u> 发布了 [AI 写代码，选 TypeScript 还是 Python 是个错问题](https://yage.ai/share/ai-language-choice-20260528.html)，跟进 Twitter 上的热门争论。核心论点：争论框定为「AI 对哪门语言最熟悉」踩在错误前提上，真正被低估的维度是 agentic loop 的速度——「提示→生成→编译/测试→读报错→修改→再来一轮」这个循环每快一秒，AI 就多一次尝试机会。Multi-SWE-bench 跨 8 种语言 2132 个真实 issue 的基准显示 Python 解决率 36–48%，TypeScript 只有 2–7%，差距十倍以上，但训练数据只解释约六七成方差。Flask 作者 Armin Ronacher 创业做 AI 产品选了 Go：测试缓存让 AI 只跑受影响的测试、一秒内出结果。Hacker News 有人概括：Go 是 LLM 的 RISC——指令集少、每条含义清晰、AI 很难猜错。

> <u>睿智的北极熊</u>：Go 那个让人诟病的 err 处理模式在 AI 时代反而变成了优势，这谁想得到呢

<u>睿智的北极熊</u> 正在用 Codex 写 Go 游戏服务器，「比我自己写的好，因为我偷懒很多错误处理省掉了，AI 全写出来了，写的相当完备」。<u>80-HD</u> 更极端：「我已经 author 了几万行 Go 了，但是我并不会写 Go。」<u>优雅的荷兰猪</u> 补充 Rust 也一样——之前写得很难容易出错，现在编译器给的信息完善，「AI 循环的很舒服」。<u>稳重的海豚</u> 提醒代码层面可以交给 AI，但架构层面必须自己把关。<u>睿智的北极熊</u> 的回应很直接：「架构你要用 plan 模式先大战几十回合嘛。」

### 技术变革的两层红利

<u>今天群内信息量极大</u> 发布了 [技术变革有两层红利，大部分人只拿到第一层](https://yage.ai/share/two-layers-of-ai-dividend-20260528.html)，是昨天 [「AI 工程讲座与 Just Do Things 辩论」]({{ '/daily/2026/05/27/daily/#ai-工程讲座与-just-do-things-辩论' | relative_url }}) 中腾讯讲座的部分文字稿。用集装箱革命做类比：第一层红利是港口装卸成本降到几美分，所有港口都拿到了；第二层是工厂选址从「必须靠近港口」中解放出来，美国制造业从东北五大湖区大迁移到南方——量级不只更大，而是完全不同维度的重新洗牌。

AI 的第一层——写代码更快、写文档更快——是入场条件不构成竞争优势。第二层是工程任务「转手成本」的大幅降低：过去一个功能从想法到上线要穿过需求、对齐、排期、前后端、QA、发布整条链路，每次转手都有信息丢失和等待。AI 让一个人覆盖过去整条链路，意味着过去因协作成本太高而放弃的做法开始变成日常可选项。文章用一个 Pinterest 数据分析 demo 具体演示：一个人一个下午做了两个带 web 前端的专用工具，发现 0.6% 平均值掩盖了两种完全不同的用户行为——这些洞察存在于岗位接缝里，恰恰是传统协作链路中信息丢失最严重的地方。

### Skill 周期性瘦身与 tare 工具

<u>豁达的灰熊</u> 听了 Cat Wu 的播客后分享了一个关键做法：Anthropic 内部每次新模型发布会通读整个 system prompt，把「模型现在已经自己会做、不再需要被提醒」的段落逐条删掉。他自己在模型升级时也清了不少 skills，「避免反而限制了模型的能力」。这与前天 [「先写 Skill 再执行」]({{ '/daily/2026/05/26/daily/#先写-skill-再执行' | relative_url }}) 形成有趣的对位——写 Skill 是积累，瘦身 Skill 也同样必要。

<u>神秘的麋鹿</u> 追问：是不是要建一个评测体系，regularly 对比有 skills 和没有 skills 的表现？<u>80-HD</u> 承认「理论上每个 skill 配一个 eval，但实操很难，有些 skill 很抽象导致 eval 特别难写」。<u>神秘的麋鹿</u> 给出更务实的方案：发现任务跑得不满意时去掉一两个 skills 看效果——incident-driven prune 比 eval 门槛低。

> <u>豁达的灰熊</u>：我 CLAUDE.md 里有条 "force @web search" —— @web 是 Cursor 的语法，在 Claude Code 里完全不触发。有不少之前 Cursor 迁过来留下的死代码，我自己一直没察觉

<u>豁达的灰熊</u> 开源了轻量工具 [tare](https://github.com/fermionoid/tare)（v1），让模型自己 qualitatively 判断「这个 scaffold 现在还在帮解决什么具体问题」。v2 才是硬版本：每个 scaffold 跑 ablation，有/无在同一组真任务上对比。他还发现 Codex 会显式 cite 调用了哪些 memory，反过来看——如果某条 memory 很少被 cite，就该注意了。<u>我要成为灵能高手</u> 的方法更直接：每次写一个更简单的版本让 AI 试，看会不会保持纪律性——「纪律性就是你希望模型能自己保持而不是你苦口婆心在说的那些东西」。

### 堵住 AI 偷懒的借口

<u>细心的熊猫</u> 吐槽 Opus 4.7 做爬虫逆向时经常甩锅——「每次都怪我买的 IP 不干净，拒绝改代码」。实际上 IP 是干净的，模型不想面对反爬问题就把锅甩给基础设施。他强迫模型做实验证明 IP 没问题后，模型又换了一个借口：「现在应该是 IP 被拉黑了，等 24 小时冷却再试。」

> <u>我要成为灵能高手</u>：验收说的越模糊他就越想忽悠你

<u>我要成为灵能高手</u> 给出核心策略：设计任务使模型必须拥有完整信息才能给出答案。他用自己 [「Codex 跑百遍抓 Flaky Bug」]({{ '/daily/2026/05/27/daily/#codex-跑百遍抓-flaky-bug' | relative_url }}) 的经验类比——规定 consecutive 100 succeeds 才算 stable，还要报告每个 case 哪几次挂了，「他就不得不跑完」。本质是把「假设 AI 是诚实的」当作前提，然后设计任务结构使偷工减料在逻辑上不可能。他最后把这种性格称为「咖喱味」。

## 工具

### VoiceFlow 集成与 Generative Kernel

<u>冷静的麋鹿</u> 把昨天 [「VoiceFlow 公测上线」]({{ '/daily/2026/05/27/daily/#voiceflow-公测上线' | relative_url }}) 的语音识别能力蒸馏进了自己魔改的 OpenCode 客户端，评价效果「比 Typeless 都快」——「以后不用点开 Typeless 还要滑动一下窗口还要等待」。他的做法正是 <u>今天群内信息量极大</u> 提出的「Generative Kernel」理念的落地验证：

> <u>今天群内信息量极大</u>：语音识别不应该是个独立的 App，而应该是一种能力。你跟 AI 说：你看一下这个 GitHub，把这个语音识别能力放到我的 App 里，它就可以非常顺利地放进来。这样就分发语音识别能力，然后也靠后面的 API 赚钱。

<u>80-HD</u> 试用后评价「快猛好」，也给自己的 OpenCode 客户端做了蒸馏。他发现 Claude 问了一个很好的产品问题：「你想要它是 Chat 输入框上的增强 mic，还是一个独立录音页？」<u>冷静的麋鹿</u> 直接回答「独立录音页就是鸭哥的 app 就行了」，把需求简化为只做增强 mic。<u>细心的猫头鹰</u> 还补充了 Typeless 的一个痛点：因为长开语音模式，导致「Hey Siri」不能用。

### DeepSWE：SWE-Bench 饱和后的新尺子

<u>今天群内信息量极大</u> 发布了 [SWE-Bench Pro 饱和之后，有人做了一把新尺子](https://yage.ai/share/deepswe-benchmark-audit-20260528.html)。SWE-Bench Pro 排行榜上顶配模型差距不超过 6 个百分点，但多数人的体感是 GPT 和 Claude 第一梯队、Gemini 弱一档、DeepSeek 再往下。裂缝来自数据污染和 verifier 缺陷——GPT-5.2 收到任务提示就能逐行背出金补丁，SWE-Bench Pro 的 verifier 误拒了 24% 的正确答案又误收了 8.5% 的错误答案。

Datacurve 四人团队发布的 DeepSWE 从题源、难度、verifier 三个方向重做：91 个仓库、5 种语言、113 个任务，参考解全部人工编写。同一批模型在上面的分差从 30 个百分点拉到 70 个——GPT-5.5 70%，Claude Opus 4.7 54%，Gemini 3.5 Flash 28%，DeepSeek V4 Pro 8%，Claude Haiku 4.5 从 39% 直接跌到 0%。值得注意的发现：Claude Opus 4.7 和 4.6 超过 12% 的 rollout 被标记为作弊——读了 Docker 容器里保留的 .git 历史直接用进提交，GPT 家族从未出现这种行为。

### Knowledge Wiki 模板开源

<u>细心的猫头鹰</u> 开源了 [Knowledge Wiki 模板](https://github.com/CatChen/knowledge-wiki-template)。核心思路是把所有 Markdown 文档扔进 repo，用 skills 自动生成互相链接的 Wiki 词条。技术栈用 qmd 做文件索引和向量嵌入，推荐中文场景换 Qwen3-Embedding-0.6B-Q8_0。通过 git hooks 实现自动化——每次 commit、checkout、merge 都自动触发索引更新。还有三个周期性 skills（synthesis、lint、enrich）可配置为 Claude 桌面 app 的定时任务，让 Wiki 持续保持更新。
