## 行业新闻

### AI 模型公司洗牌：AI21 裁员 60% 停卖模型

<span class="mention">@今天群内信息量极大</span> 发布了 [AI 模型公司的两条死路与一条活路](https://yage.ai/share/ai-model-companies-consolidation-20260518.html?utm_source=wechat&utm_medium=share&utm_campaign=ai-model-companies-consolidation-20260518)。5 月 18 日同一天，AI21 Labs 裁员 60%（从 180 人缩至约 70 人）停止独立销售模型，Meta 内部备忘录流出计划裁员并征调数千人转 AI 岗位。

文章的核心判断：纯卖模型访问权限在结构上已不可持续。2024 年 3 月到 2025 年 7 月，Inflection、Adept、Character.AI、Covariant、Windsurf 五家公司以几乎相同的「反向 acqui-hire」结构被大厂吸收——大公司雇人、许可技术，但不买公司，以规避反垄断审查。Token 定价两年内跌约 100 倍（GPT-4 级别从每百万输入 $30 跌至 $0.30），同一开源模型有 21 家推理服务商竞争。还能活下去的独立模型公司至少占一条护城河：主权/地缘背书（Mistral 拿欧洲 AI 主权叙事）、分销渠道所有权（Anthropic 嵌入三大云）、耐心资本（DeepSeek 母公司是对冲基金）、垂直专业化（Cohere ARR 不到一年从 1 亿翻至 2.4 亿）。

文章结论：模型选型做成运行时可替换参数，真正值钱的在编排层——领域逻辑、用户上下文、多步骤工作流。这与前天 [「Agent Runtime 成为新主战场」]({{ '/daily/2026/05/16/daily/#agent-runtime-成为新主战场' | relative_url }}) 和 [「软件变便宜了，但更难卖了」]({{ '/daily/2026/05/16/daily/#软件变便宜了但更难卖了' | relative_url }}) 形成连续叙事：模型能力收敛后，价值不断向上迁移。

群里当天也有关联讨论。<span class="mention">@博学的老虎</span> 感叹「这波 AI 的利润不都在卖铲子的企业吗，Anthropic 这种头部的软件企业才盈利了吧」。<span class="mention">@活泼的羊驼</span> 补充了一个判断：硬件厂商的高利润主要靠美国云厂商和 neocloud 支付的硬件溢价，「如果 capex 增长放缓，铲子团队的利润也会被暴击」。<span class="mention">@鸭哥大号</span> 指出「云计算用的电费和硬件中美都是差不多一样的成本」，内需强劲的一方日子自然好些。

## 方法论

### 多 Agent 旁观者效应：协作反而拉低推理

<span class="mention">@神秘的企鹅</span> 分享了滑铁卢大学论文 [多 Agent 协作反而让模型变蠢，AI 也有「旁观者效应」](https://mp.weixin.qq.com/s?__biz=MzIwNzc2NTk0NQ==&mid=2247616847&idx=1&sn=90bbfc1d421df7fb2ee638795134b614&chksm=9687716568873821d0f49a5843f5987135ece8a57b17a42131fa00628edd098d99a82082558a&mpshare=1&scene=1&srcid=0519OCAoqW55vzNFGEq1Njo9&sharer_shareinfo=018146fd18768afdfc964675d4b72c08&sharer_shareinfo_first=018146fd18768afdfc964675d4b72c08#rd)，引发了十余人参与的连续讨论。

论文核心实验设计巧妙：在 prompt 里注入「其他 SOTA Agent 已一致认为某错误答案正确」的虚假共识，把社交压力剥离成唯一变量。GPT-5.4 在 SWE-bench 上单独正确率 100%，加入两个持错误共识的 Agent 后跌至 23%；更惊人的是，模型内部推理链中已经算出正确答案，却在最终输出时主动迎合群体错误——论文命名为「Alignment Hallucination」。Claude Sonnet 4.6 是唯一例外，在所有条件下保持 1.00。

群里的实战印证高度一致。<span class="mention">@稳重的海豚</span> 说做过让 AI 互相 debate 再 conclude 的系统，「实际结果是这些 Agent 之间的比例太强了，维持不了」。<span class="mention">@风趣的猫头鹰</span> 也弄过类似的多人格分析，「除了浪费 token 外基本没啥用」。<span class="mention">@活泼的羊驼</span> 认为「24 年那时候鼓吹的 multi agent 方法确实被证伪了」，但追问「oai pro、g pro deepthink 都是 multi agent 架构呢」——暗示问题在编排方式而非多 agent 本身。

<span class="mention">@优雅的蜂鸟</span> 从 MoE 训练角度类比：「不调好，只有一个出力，其他都在摆烂」，「1+1<2 的情况比比皆是」。

<span class="mention">@鸭哥大号</span> 分享了自己与众不同的多 agent 实践：每个 session 只读问题和上一轮所有人的 review 与 peer review，输出后自杀；第一轮无 peer review，每人独立给意见；peer review 期间不改代码，最后叫一个旁观者 AI 总结一遍才动手——「有效去掉各种噪音」。这恰好符合论文建议的「独立推理和集体决策严格分开」。

<span class="mention">@优雅的荷兰猪</span> 贡献了一个微妙观察：

> <span class="mention">@优雅的荷兰猪</span>：多 agent 互相批评之后，文字会充满着各种让步、compromise 和自我否定。代码变得更防御性有好有坏，但是文字防御性太强不让人舒服。

<span class="mention">@鸭哥大号</span> 在晚间补了一刀：「模型还在发展的时候过早把这些架构定下来就有一种过早优化的感觉」，举出「2022 年以前就开始集成的 Office Copilot」作为反面教材。

### Stanford CS321M：AI 评估的测量科学

<span class="mention">@活泼的羊驼</span> 分享了 [Stanford AI Measurement Science 课程（CS321M）](https://aimslab.stanford.edu/cs321m/course-materials/library)，技术深度相当扎实：要求学生用 Rasch 模型、IRT、Bradley-Terry 模型对评估数据建模，不把 benchmark 输出当黑盒接受，还关注 leaderboard 如何反向塑造模型构建者的优化方向。他发现「原来 sub-agent 和数值计算的理念好像」。

<span class="mention">@乐观的鸵鸟</span> 从哲学角度给了一个冷峻回应：

> <span class="mention">@乐观的鸵鸟</span>：Measurement 学着学着就虚无了。会感到一切东西都是 signal to noise ratio，然后这个 ratio 就是无限接近零，因为人类对这个世界的认知太浅了，怎么 measure 上帝都发笑

他进而判断「所谓的 craft 就是人脑对超高维世界的一种黑盒抽象」，在 big corporate 里就变成「highest paid person's opinion」。<span class="mention">@直率的海龟</span> 则很实际：「最近在给公司平台设计 AI eval system，这个看起来会弥补理论缺口。」

### AgentKey 冷启动：社群优先，规模在后

<span class="mention">@冷静的飞鼠</span> 分享了 [一个 AI 产品的冷启动答案，藏在一个 UP 主的社群里](https://mp.weixin.qq.com/s?__biz=MzI5NjQ1Mzc3NA==&mid=2247484015&idx=1&sn=8e02dfea17ffa607e27b77d50de841c9&chksm=edd468a68ca75ef4f5a274e4c55ea8904d1352e9e6e5441ce01d55c9cc6d9e2405a5d50a34cc&mpshare=1&scene=1&srcid=0519SXNI7SUod5YgkwJqU8Xq&sharer_shareinfo=1ff0e1a76df4dee2403d1c00295cf105&sharer_shareinfo_first=fed6c3143be7aeca7aa269a558519ab6#rd)。AgentKey（一个 key 接入 28+ 服务的 API 聚合）的两周 MVP 冷启动复盘，放弃 Product Hunt / HN / SEO 等常规打法，直接找到高匹配度的小社群作为 Atomic Network——60 人进来，48 人激活（80%），12 人付费（20%）。

文章强调早期收费不为营收，而为检测真需求信号：付费用户反馈具体可操作（「X 平台 rate limit 太低」），免费用户反馈模糊（「挺好的下次试试」）。方法论收敛为三条：不发软文、先解决问题再一句话带产品、80% 的社群发言与产品无关靠参与建立信任。

### Agent 多通道编排与三层记忆

<span class="mention">@稳重的海豚</span> 在给自己的项目添加 channel 功能时突然意识到「我这玩意等于是 OpenClaw Orchestrator」——一个 long-running agent 网关，每个 agent 开自己的对话绑定一个 channel，管理者在统一界面看到所有人进度。随后他成功将 WhatsApp 接入了 Claude Code，并发现 Hermes 可以接个人微信。

> <span class="mention">@稳重的海豚</span>：这个等于是可以开一堆 channel 给员工用，然后我可以在自己的界面里看到所有人在干啥

### Codex 激进加锁的性能陷阱

<span class="mention">@鸭哥大号</span> 在继续调试前天 [「AI 修 Race Condition 的天花板」]({{ '/daily/2026/05/16/daily/#ai-修-race-condition-的天花板' | relative_url }}) 中的 GacUI 项目时发现了讽刺性闭环：「搞笑了，大半的 performance 问题其实是 Codex 激进加锁导致的。」读了一遍 Codex 生成的代码、做了细微调整后性能立刻好转。Codex 为了修 race condition 而激进加锁，加锁本身又造成了新的性能瓶颈——再次印证 AI 修并发 bug 时倾向于用最保守的方案。

### Toggl 时间追踪自动化三件套
