### AI 音乐串烧溯源全流程

<span class="mention">@今天群内信息量极大</span> 在 B 站刷了十来个小时「电子斗曲曲」乐队的年度串烧视频后，感慨 1999-2000 年华语乐坛集中爆发了一大批歌手。感慨完「想了想，觉得还是不能活在 30 年前」，转身给 AI 布置了一条完整的音乐溯源流水线：下载串烧视频 → 语音识别拿到歌词 → 根据歌词反查歌曲和作者 → 去重后到 YouTube / Tidal 找原版 → 下载转码为音频。

最终产出约 760 首曲目的[对照表](https://yage.ai/share/online-media-source-links-20260525.html)，跨度从邓丽君 1979 年《甜蜜蜜》到 2016 年《告白气球》。整个流程沉淀为可复用的 [online-media-skill](https://github.com/grapeot/online-media-skill)，设计思路是明确划分 CLI 与 AI agent 各自的职责边界：下载媒体、写元数据、运行 ASR 是 CLI 负责的确定性任务；搜索网页、判断歌词归属、核实匹配则交给 agent 做判断。技术栈上 YouTube 走 yt-dlp + ffmpeg，Tidal 走 streamrip 拉 FLAC，ASR 默认用 Qwen3-ASR-1.7B 在 Apple Silicon 本地运行。

### Skill 生态系统公开

<span class="mention">@今天群内信息量极大</span> 同日公开了自己的 [Skill 生态系统](https://github.com/grapeot/context-infrastructure/blob/main/docs/SKILL_ECOSYSTEM.md)，包含十几个可独立安装的 public skill repo，覆盖范围极广：Web 搜索（Tavily）、文档（GDocs）、邮件（Outlook / Resend）、消息（iMessage）、agent 运维（OpenCode 批量任务管理、本地 HTTP process launcher）、AI token 用量 dashboard、Typefully 发帖与 Twitter 分析、Stripe 只读财务分析、在线媒体下载与 ASR、AI-first PPTX 编辑、Gemini / GPT 文生图、Apple Health 数据分析，甚至咖啡烘焙日志抓取。

他同时分享了 [intake-skill](https://github.com/grapeot/intake-skill)，专门把 Apple Voice Memos 自动转化为本地归档——标准化音频、转写 CSV、每日报告和会议记录 Markdown，使用 MLX Qwen3-ASR 在 Apple Silicon 本地运行。

## 方法论

### 多 Agent 读写分离

<span class="mention">@活泼的羊驼</span> 梳理了群友 <span class="mention">@幽默的浣熊</span> 一个月前发表的新文章 "Multi-Agents: What's Actually Working"——他在开头自述：十个月前写了《Don't Build Multi-Agents》，现在观点已更新。核心修正：多 agent 系统效果最好的方式是「写入保持单线程，额外的 agent 贡献的是智能而非动作」。

真正的区分不是单 agent vs 多 agent，而是任务以「读」（研究、分析、信息搜集）为主还是以「写」（代码生成、内容创作、文件编辑）为主。这也解释了为什么 Anthropic 用多 agent 做 Research，却用单线程做编码。成本数据同样值得注意：agent 通常比聊天多用约 4 倍 tokens，多 agent 系统约为聊天的 15 倍。

<span class="mention">@坦荡的灰熊</span> 从实践角度反对：「太慢了，agent 之间的多一轮交互，不如多跑一次代码。」<span class="mention">@活泼的羊驼</span> 还指出了一个陷阱——谄媚式纠正（sycophantic correction）：模型不是朝真相纠正，而是「反思」后朝它认为用户想要的方向修改，在纠正循环里初始答案可能比「纠正后」的版本更正确，「盲目让 agent 自我反思可能让结果更差」。

### AI 内容不问出处

<span class="mention">@鸭哥大号</span> 提出判断：很快就不需要问一个视频或文章是不是 AI 做的了，「说一个视频是 AI 做的就和说一个小孩将来一定学不会数学一样，绝大多数情况下就是对的」。

> <span class="mention">@鸭哥大号</span>：我觉得应该推广码农对待代码的态度，你从来不会去想一段代码是AI还是人写的，都是直接看内容，行就是行不行就是不行

<span class="mention">@稳重的熊猫</span> 用软件工程原则呼应：「care about the interface and care about unit test result. Don't care about how you implement it.」——不管是 coding agent 还是其他软件工程师，对齐接口和测试结果就够了。

### 简历造假的认知距离

<span class="mention">@活泼的羊驼</span> 分享了一条推文，描述 Agent 时代应届生可以通过蹭开源、P 图简历来 reward hack 面试。<span class="mention">@今天群内信息量极大</span> 的反驳比喻精彩：「intern/应届生和面试官认知差距很大，简历再漂亮一聊就露馅。类似人类试图通过广播向外星人证明自己很厉害，一看通信方式是模拟调幅广播。」另一个版本：「或者小学生试图威胁别人，一看门上贴的小纸条有个拼音。」

<span class="mention">@细心的熊猫</span> 指出这在美国行不通——「面试起码见 6 个人，6 个人都得失败的概率很低」。<span class="mention">@务实的灰熊</span> 从面试官视角确认「绝大部分都这样，简历写了一堆牛逼项目，一问三不知」。<span class="mention">@稳重的海豚</span> 的面试方法论最干脆：「我面试都不看简历，面试完之后再看。」
