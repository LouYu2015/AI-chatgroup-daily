## 行业新闻

### DeployCo：OpenAI 与 Anthropic 同日建 JV，赌注完全相反

<span class="mention">@今天群内信息量极大</span> 发文 [DeployCo 来了：OpenAI 和 Anthropic 在同一天发明了同一家公司，然后走向了相反的方向](https://yage.ai/share/openai-deployco-anthropic-pe-divergence-20260511.html?utm_source=wechat&utm_medium=share&utm_campaign=openai-deployco-anthropic-pe-divergence-20260511)，拆解了 5 月 4 日两家同时宣布的 PE 合资企业。OpenAI 的 DeployCo 初始投资超 $4B，TPG 领投，收购 Tomoro 获得约 150 名 FDE。关键条款是 17.5% 保底回报——标准 PE 优先回报的两倍多，不管 JV 是否盈利都要先付。逻辑是：渠道是成本，模型是核心产品，JV 是高价租来的获客管道。

Anthropic 与 Blackstone 等的 JV 估值仅 $1.5B，无保底承诺，走的是模型中立路线——后端跑 Claude 还是 Gemini 取决于场景，卖的是部署服务能力而非模型本身。两种赌法各有脆弱面：模型商品化则 OpenAI 的 17.5% 成沉重成本；GPT 持续拉开差距则 Anthropic 的中立管道失去卖点。更深的共同风险是两个 JV 的 agent 同时进入同一市场后会互相压价，把利润吃到零。<span class="mention">@沉稳的仓鼠</span> 评价「卖不出去了只能上人」。

### Google 关掉 Project Mariner

<span class="mention">@今天群内信息量极大</span> 同日发文 [Google 关掉 Project Mariner，Anthropic 和 OpenAI 其实也没跑通](https://yage.ai/share/google-project-mariner-shutdown-20260511.html?utm_source=wechat&utm_medium=share&utm_campaign=google-project-mariner-shutdown-20260511)。核心判断：独立 browser agent 天然把自己变成 bot——headless Chrome、云浏览器、独立 VM 都没有 cookie 和人类行为特征，各大网站十几年反爬经验正是针对这类会话。OpenAI 的 Operator 连自家网站都访问不了，Perplexity Comet 被 Amazon 以 CFAA 拿到禁令。

破局点在于共享用户真实环境。Chrome auto-browse 作为内置功能运行在用户已登录的浏览器里，OpenAI 的 Codex Computer Use 是 macOS 桌面插件直接跑在真实 Mac 上。三家殊途同归：独立 browser agent 跑不通，GUI automation 必须在真实桌面里才能活。真正的刚需场景——Bloomberg Terminal、医院遗留系统——根本不是网页应用。

### AI 正在吞掉哪些 SaaS

<span class="mention">@冷静的飞鼠</span> 分享了 [Ramp Spring 2026 报告解读](https://mp.weixin.qq.com/s?__biz=MzIyNTM1MzQ1OA==&mid=2247489972&idx=1&sn=838d68f770b4dd077c1497d4ffc3d3db&chksm=e9154abcc2bd7041fddb8787d750444751e9ff3dbcbc3891e44057ca0d0388acd82544f238cc&mpshare=1&scene=1&srcid=0512xOAAXNWtcJMuXqGgvKZP&sharer_shareinfo=7eb387894062db9e56250d0ae3bd1658&sharer_shareinfo_first=650a690afbd5b2c5dd0405b89d17a554#rd)，基于 5 万家企业超千亿美元年化支出数据。赢家的共同规律是从「记录」走向「执行」——直接完成动作而非展示数据；替代的不是单个 SaaS 而是一组工具加人工流程的组合。Anthropic 已进入企业常规软件栈，Prefect 卡住 AI workflow 运行层，Decagon 把客服系统从 system of record 变成 system of action。

### 全球 AI 监管前五都在保护 AI 公司

### Edge 启动即全量明文解密密码

## 方法论

### AI 导致失眠：最大变量是晚上最后一次用 AI 的时间

<span class="mention">@今天群内信息量极大</span> 发布了 [AI 如何导致和修复了我的失眠问题](https://yage.ai/ai-sleep.html)——这是他第一篇「古法手搓」的 blog。三月底严重失眠，quit job 后也没改善，于是用 5 分钟让 AI 写了一个 iOS app 把 Apple Watch 健康数据导出，做多变量回归。结果出乎意料：咖啡因摄入与睡眠几乎不相关，相关性最强的变量是「晚上最后一次使用 AI 的时间」。改成晚上刷短视频打游戏后，几周内平均睡眠延长一小时四十分钟。原因是 AI 把体力活包圆了，留给人的全是高强度阅读和思考，加上多线程操作大脑始终高度兴奋。

群友几乎全员中枪。<span class="mention">@聪明的灰熊</span> 说「现在继续开发需要的脑力变小了，以前要专注一两小时，现在只要几分钟就够了，于是很疲惫的时候还是能继续推进任务，导致把精力榨得更彻底」。<span class="mention">@坦荡的灰熊</span> 说「我躺床上都要来两下……精力彻底抽干时人会压不住神经系统里的噪声」。<span class="mention">@80-HD</span> 总结为「AI 比咖啡因还猛」。

<span class="mention">@孔哥仁且义孟哥义且仁</span> 的应对策略是反过来：「很快就发现，着急什么。后面 AI 跟我同步休息」——「多出来的时间如果还用来工作，那科技不就白进步了。」

### "3x 交付"压力与 Goodhart's Law

<span class="mention">@80-HD</span> 分享了公司 founder 的内部邮件：AI 采用后 PR 数量增长不到一倍，低于业界，要求提高；同时把项目时间缩到原计划 1/3。Blind 上骂声一片。

> <span class="mention">@80-HD</span>：要 PR 数量我一天可以给你来一百个，不够还可以加，只要你 token 给够

他认为强调 PR 数量会造成跟前天 [「Tokenmaxxing：Token 消耗量成为新 KPI？」]({{ '/daily/2026/05/09/daily/#tokenmaxxingtoken-消耗量成为新-kpi' | relative_url }}) 类似的结果。根本问题是项目太多推进就慢，「应该砍项目而不是缩短项目时间」。<span class="mention">@神秘的麋鹿</span> 指出 metric 会像 5/8 <span class="mention">@今天群内信息量极大</span> 关于 TDD 的 Goodhart's Law 判断一样被应试化——「有时候测试会有点变味，像应试教育一样去应付它」。

<span class="mention">@聪明的灰熊</span> 没有一边倒，而是分享了一个反例：网易蛋仔派对上线前团队组长一直抱怨是老板压下来的，打算上线就离职——结果爆火。他的结论是「做 IC 的人和做决策的人，信息量和视野不一定对称」。但<span class="mention">@80-HD</span> 认为这次的问题核心在措辞——一刀切看 PR 数量和强行压缩时间，「影响士气是最可怕的」。

<span class="mention">@稳重的海豚</span> 表示自己那边更狠：「以前两三周的工作现在要 overnight deliver」，不过 hands-on 时间其实只有 20-30 分钟，瓶颈是整个 verification cycle 要 5-8 小时——提速也提不了。

### Generative UI 与软件的宜家化

<span class="mention">@稳重的海豚</span> 想把 agent 输出的健康记录做成可视化界面，后端还是 agent chat——「in-app adhoc app」。<span class="mention">@今天群内信息量极大</span> 指出这听起来很像 ChatGPT 刚发布的 [Apps SDK](https://developers.openai.com/apps-sdk/build/chatgpt-ui)，可以在 ChatGPT 会话内嵌入自定义 UI 组件，数据工具和渲染工具解耦，模型在渲染前可以先做过滤判断。

> <span class="mention">@孔哥仁且义孟哥义且仁</span>：码农写 app 很快就将成为历史……以后用户就只有这个方案了。工具都是给自己做的，就像现在码农不断地给自己的项目开发 codegen 和 visualizer 一样

> <span class="mention">@今天群内信息量极大</span>：以前软件公司是卖椅子，现在人人都有自己的装配机器人了，软件公司卖的东西就会自然变成宜家风格——椅子腿椅面（你在家搓不出来的东西），装配指南（给 AI 看），和内六角螺丝刀（封装好的专用工具）

他同时分享了 [超越 DRY：AI 原生软件工程的思考](https://yage.ai/ai-software-engineering.html)，提出「生成内核」（Generative Kernel）概念：核心套件 + 引导知识 + 杠杆工具集。<span class="mention">@沉稳的兔子</span> 不完全同意「超越 DRY」的说法——「只是 DRY 的 Y 从实现侧左移到了需求侧」。<span class="mention">@孔哥仁且义孟哥义且仁</span> 补充说 DRY 是递归的，用户自己做工具做多了也会形成自己的 DRY。

<span class="mention">@活泼的老虎</span> 给出了最切身的体会：「就像数仓一样，有了接口和数据字典运营自己就跑数了，大部分场景不用数据工程师。我们老板已经在问我们这个职位的必要性了。」<span class="mention">@80-HD</span> 也分享了实践：用 OpenCode client 的经验把给孩子写的几个网页包进一个 iOS app——「起因是老婆老抱怨记不住网址」。

### Fix Root Cause 是 Truism 吗

<span class="mention">@孔哥仁且义孟哥义且仁</span> 说「没有 fix 在 root cause 上的 change 长远来讲都是有害的」——前几天刚被 12 年前一个粗暴的 fix 坑到。<span class="mention">@今天群内信息量极大</span> 的回应值得玩味：

> <span class="mention">@今天群内信息量极大</span>：这个有点 truism。看起来是对的，很难反驳，但 root cause 是啥是另一个 rabbit hole，不同的人观点差别极大。实际上没啥用。有点类似"真正的 TDD 可以解决 AI 时代的 XX 问题"——很难反驳，因为不论什么反例总可以归为"这种对 TDD 的用法不正确"。

这与 5/8 的 [「AI 时代 TDD 为什么不是答案」]({{ '/daily/2026/05/08/daily/#ai-时代-tdd-为什么不是答案' | relative_url }}) 形成了方法论层面的呼应。<span class="mention">@孔哥仁且义孟哥义且仁</span> 承认这是屁股问题——「如果明知道以后锅会扣在别人头上，降低质量就成了最优解」——但自己维护的开源项目已经 20 年，最老的代码也有 20 年了，root cause 的重要性是非常直观的。<span class="mention">@稳重的海豚</span> 的实践也印证了 AI 在这方面的盲区：他让 AI 画出错误架构和理想架构的对比图再照着改，「但它经常就是想去 hotfix deliver 这个 task，不会去思考问题的本质是什么」。

### Harness 越重，模型反而越受限

<span class="mention">@细心的熊猫</span> 提出了一个反直觉的观察：模型通用能力越强，做专用 agent 时加的 harness 可能反而在削弱模型能力。

> <span class="mention">@细心的熊猫</span>：就像用 RL 训练出来的自动驾驶汽车，非常安全高效，但行为非常奇怪无法理解，因为人类开车有很多不 optimize 安全高效的时候，所以反而要增加很多 rule 去约束它

他由此判断「AI 的能力发展可能要跟实际带来生产力的提升脱节」，这也是为什么 AI 除了 chatbot 和 coding 还没有特别出彩的地方。这与前天 [「Harness 决定模型表现：DeepSeek V4 Pro 6/10 胜 Opus 4.7」]({{ '/daily/2026/05/09/daily/#harness-决定模型表现deepseek-v4-pro-610-胜-opus-47' | relative_url }}) 和 [「"Harness" 用反了：从控制 AI 到描述清楚世界」]({{ '/daily/2026/05/10/daily/#harness-用反了从控制-ai-到描述清楚世界' | relative_url }}) 形成有趣对照——harness 接好了能让弱模型赢过强模型，但接得太死又会压制通用能力。<span class="mention">@冷静的麋鹿</span> 的总结精辟：「当 AI 走进社会，发现这个世界是一个巨大的草台班子。」

### Engels' Pause：被替代者不会被自动接住

<span class="mention">@冷静的飞鼠</span> 分享了 [留给我们的时间不多了：从 Engels' Pause 看 AI 时代的自救](https://www.superlinear.academy/c/share-your-insights/engels-pause-ai)。Engels' Pause 描述工业革命早期的反直觉历史：1780-1840 年间工人产出增长 46%，实际工资只涨 12%。手织工是典型案例——机械纺纱让棉纱便宜后手织工迎来「黄金时代」，但这段高收入恰恰刺激了动力织机研发，最终 1820 年占男性劳动力 10% 的手织工整体消失。

> <span class="mention">@冷静的飞鼠</span>：被替代的人就是被替代了，自求多福，默默消失在历史长河中

> <span class="mention">@冷静的飞鼠</span>：2023 年倒计时已经开始了，但现在都 2026 年，还没醒来，就很扯

<span class="mention">@今天群内信息量极大</span> 给出了另一个视角——工业革命的意义不是让纺织工人买得起廉价衣服，而是让他们变成铁路信号员、电报操作员。他同时分享了 [AI 到底是泡沫吗？从 100 年前的电气化找答案](https://mp.weixin.qq.com/s?__biz=MzcwNTA3NjkzNQ==&mid=2247484182&idx=1&sn=fb77fe6eccedec2d305c2ce12ec7234b&chksm=f53875df27e7344b03d9474778e6e9a72c3eba969252904bb7295472eb98b871d3939b99ba56&mpshare=1&scene=1&srcid=0511f7PQAT4818tfcDyd98vE&sharer_shareinfo=405093d08b9019a054fcd62e5c06db2a&sharer_shareinfo_first=ae228c6baf6d939057905ea88cd4e422#rd)，将当前 AI 定位在约 1914 年——基建仍在继续，AI 版流水线尚未扩散到全行业，应用爆发期的前置条件已到位但激励循环层还远未实现。<span class="mention">@孔哥仁且义孟哥义且仁</span> 则直接反驳：「退休后才发生的好处就等于没有发生，就跟 agent 看不到的文件就等于不存在一样。」<span class="mention">@沉稳的兔子</span> 也提到 70 年代滞涨是另一个不那么乐观的前车之鉴。

<span class="mention">@乐观的雪豹</span> 说出了很多人的感觉：「每次听到有人说 AI 会让人更多时间去创造和享受人生，我都感觉中间好像差了点啥。这种论断太跳跃了，在转换的过程里就是会有很多具体问题。」

## 工具

### Cursor 路由疑云：composer-2-fast

<span class="mention">@冷静的麋鹿</span> 发现 Cursor 在一篇文章上消耗了 2000 万 token（标注为 Opus 4.7），但产出质量和速度明显不对——「说 GPT 都有点够不上」。追问后模型回复当前 session 模型 ID 是 `composer-2-fast 框架下的 Claude Opus 4.7`。他怀疑 Cursor 在用自己的路由「搞鬼」，质疑「给我整了一个 composer 2」。<span class="mention">@稳重的海豚</span> 调侃：「有没有可能这就是 Opus 4.7。」这与 [「跨工具 Context Infrastructure 的「品味差异」」]({{ '/daily/2026/05/08/daily/#跨工具-context-infrastructure-的品味差异' | relative_url }}) 中讨论的不同 runtime 品味偏差问题有共同根源。

### Codex 与 CC 的 /goal 模式

### HTML 幻灯片工具推荐

### API Key 安全管理

<span class="mention">@今天群内信息量极大</span> 分享了 [API key 到底放在哪儿](https://yage.ai/share/api-key-where-20260511.html) 的入门指南。核心判断：个人机器上 .env + 权限 600 是够用的基线，最优解是 1Password 的 `op run`（Touch ID 确认、无凭证落盘）；生产服务器上 .env 不该再用，首选 systemd credentials 加密存储绑定 TPM2。特别提醒：AI 助手能读到的文件内容应当作已在日志里——单个 API key 泄露了轮换就行，但能解锁整个 vault 的 SA token 绝不该放在 agent 可读路径。
