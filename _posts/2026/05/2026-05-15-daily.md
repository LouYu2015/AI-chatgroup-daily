今天最硬的数据来自 Bloomberg：BLS 标记的 18 个 AI 高暴露职业 2024–2025 年整体就业降 0.2%（同期全美增 0.8%），technical writer 单项跌 18%——<u>孔哥仁且义孟哥义且仁</u> 感叹「居然现在才开始减」。Anthropic 周五惊喜全员 reset 了 5 小时和周限额，<u>洒脱的鸳鸯</u> 刚心疼完七八十刀的账单就发现额度满血复活。方法论最有嚼头的是一场从企业 AI 项目同质化聊到 KPI 驱动 over-engineering 的连续辩论，<u>80-HD</u> 贡献了一个「号称 horizontal scalable、实际靠到处加锁跑单线程」的 Java 项目反面教材。闲聊最佳：CC 干了一半突然罢工——「你这个 PR 肯定超过一千行，merge 不进去的」，<u>80-HD</u> 从善如流直接下班了。

## 行业新闻

### Bloomberg：AI 高暴露岗位连续两年失血

<u>风趣的犀牛</u> 分享了 Bloomberg 报道截图：BLS 标记为 AI 高暴露的 18 个职业 2024–2025 年就业下降 0.2%，同期全美就业增长 0.8%。剔除逆势增长的医疗秘书后，降幅扩大至 1.6%，且已是连续第二年下降。亮点数据：

- Technical writers：-18.1%（跌幅最大的白领岗位之一）
- Graphic designers：-7.7%
- Customer service representatives：-4.8%
- Sales engineers：-8.6%
- Broadcast announcers / radio DJs：-11.1%
- 逆势上涨：Medical secretaries +15.8%，Paralegals +7%

<u>孔哥仁且义孟哥义且仁</u> 感叹「居然现在才开始减」，并解释 technical writer 实际是润色码农提供的内容——微软以前给 MSDN 写文档就是这样，靠外包完成。<u>随和的老虎</u> 和 <u>乐观的灰熊</u> 补充说这个岗位主要写「portal 怎么用」「新功能跟已有功能的联系和最佳实践」这类内容。<u>孔哥仁且义孟哥义且仁</u> 还预测「UI 翻译师应该也差不多要没了」。<u>直率的海豚</u> 现身说法：「我现在写 post 有 AI 润色，都像模像样了，以前就是个词穷牢钟。」

<u>活泼的羊驼</u> 在更早的讨论中引入了 Acemoglu 的「so-so technologies（平庸技术）」概念：很多 AI 部署只是省人但不带来变革性进步，被替代的工人流向更低薪岗位——比如客服被 AI 取代后去送外卖，总产出未必涨，收入分配却急剧向资本倾斜。<u>豁达的灰熊</u> 指出这与上周 [「Engels' Pause：被替代者不会被自动接住」]({{ '/daily/2026/05/11/daily/#engels-pause被替代者不会被自动接住' | relative_url }}) 形成呼应。<u>安静的兔子</u> 的反驳很现实：「怎么没涨呢，能送外卖的人更多了——蓄水池的水也是水。」

<u>神秘的麋鹿</u> 从自身工作出发给出一个微妙视角：AI 时代首先得强迫自己 think level 更上一层，「把自己像有小弟一样当管理人员，日常执行的琐事都给出去做更 high level 的事」——但信息密度上来后工作反而更费脑力。他认为自己所在的图像质量领域短期内不太容易被替代：「有指标去评价图片看起来是好，但人就有可能一眼觉得不对，客观和主观是一个互补的关系。」

### Claude Code 全员 Reset

ClaudeDevs 发推「Happy Friday! We've reset everyone's 5-hour and weekly rate limits.」——一次计划外的全员重置，叠加原有的周期 reset 时间点不变。<u>沉稳的仓鼠</u> 第一时间晒出 100% 额度截图，评论「看来是真的 token 太多了」。

<u>随和的老虎</u> 开心之余吐槽「20 刀的 plan 也太不经用了」，<u>直率的海豚</u> 附议「他家 20 刀就像别人家的 2 刀一样」。<u>洒脱的鸳鸯</u> 的体验最戏剧化——一觉醒来发现睡前开的任务花了七八十刀，正肉痛时发现限额全部 reset 了，而且原本的 reset 时间点还不变：

> <u>洒脱的鸳鸯</u>：这就是 xAI 新显卡的魅力吗

<u>乐观的灰熊</u> 哭笑不得：自己原定的 reset 就隔了几小时，「一毛钱羊毛没薅到」。不过 <u>沉稳的仓鼠</u> 也报告 reset 后 CC「也太卡了」。这与近期持续的配额话题（[「Claude Code 周限额增加 50%」]({{ '/daily/2026/05/13/daily/#claude-code-周限额增加-50' | relative_url }})）形成连续叙事——Anthropic 在竞争压力下持续放量。

## 方法论

### AI coding 产出如何度量

<u>坦荡的喜鹊</u> 抛出一个企业级问题：AI coding 模式下如何度量程序员产出——「毕竟 token 也有成本，比如我厂一年估计有大几十亿成本」。<u>认真的荷兰猪</u> 立刻贴出前天 <u>今天群内信息量极大</u> 的文章（[「AI 行业在找新指标：Token 之后是什么」]({{ '/daily/2026/05/13/daily/#ai-行业在找新指标token-之后是什么' | relative_url }})），核心论点是 token 衡量消耗而非产出。<u>坦荡的喜鹊</u> 补充说他主要想度量的是开发者的 productivity 本身，而非 token 效率。

<u>坦荡的灰熊</u> 给了两个回答：第一个是调侃——「再烧点 token 去度量」；第二个值得琢磨——「能丰富公司 skill 库的就是 productivity」。这个视角把度量锚点从代码行数 / PR 数切换到可复用知识资产的积累。

### Over-engineering、KPI 与「到处加锁的分布式单线程」

<u>80-HD</u> 搓了一个简版 context infra（带 <u>今天群内信息量极大</u> 那个共享 skills 的思路）推给团队，组里除了自己只有一人用上了。他环顾公司内的 AI 项目发现同质化严重：「不是 oncall bot 就是 knowledge management」「这些都是比较安全的方向，能够跟上公司 AI 叙事，然后看上去都有用」「业务上硬要加 AI 上去的太难了」。隔壁组做了一个极其复杂的 knowledge extraction/management 系统，「架构图全屏才能看清楚的那种」。<u>冷静的飞鼠</u> 第一反应「听着不妙」，<u>开朗的海豚</u> 更直白：「今年还做这种的目的我觉得就是为了不用。」

讨论随即滑向 over-engineering 经典议题。<u>80-HD</u> 说「工程化最常用的不就是 abstraction 么，如果不行就再加」。<u>孔哥仁且义孟哥义且仁</u> 纠正：关键在于「一定要 proven 不行才能加 abstraction」，好的架构是迭代出来的——需要多出一个 base class 时用已积累的 unit test 帮助重构。

> <u>孔哥仁且义孟哥义且仁</u>：best practice 都是一环扣一环的，没有那个东西能够单独存在，比如不具备覆盖度高的单元测试，这个就做不了

<u>80-HD</u> 反讽大厂现实：「你一开始加才能体现 thought leadership，后加的就变成了 fixer」「干两年就拍屁股走人了」。<u>孔哥仁且义孟哥义且仁</u> 叹气「现在没地方去了，大家得面对现实了」。<u>机智的水獭</u> 补充了 YAGNI 原则，并指出 AI 的 over-engineering 和 premature optimization「就是从海量人类的错误示范学习的」。

<u>孔哥仁且义孟哥义且仁</u> 贴出一段关于 GPT 5.5 的评论截图：GPT 5.5 有 over-engineering 倾向，多次需求变更如果不及时矫正，会积累「海量的垃圾代码——不一定是没有用的，而是一大堆只调用一次的函数散落在各个地方，会扰乱 AI 的心智，抵消 GPT 5.5 带来的有耐心的进步」。

<u>80-HD</u> 贡献了一个经典反面教材：他接手修过一个 Java CRUD 项目，号称 horizontal scalable，里面一堆 abstract class，但 QPS 只有一两百。三哥修了半年说修好了，PR ready 让他 deploy——打开一看甚至都不能正确跑。不能 scale 的原因是每个跟 DB 相关的 function 一进去就是 `begin transaction`——「整个 codebase 就是靠到处乱加锁来跑，看上去像分布式，跑了几个 pod，其实就只有一个线程能用」。

## 工具

### Claudian：Obsidian 内嵌 Claude Code

<u>活泼的羊驼</u> 感叹「要是 Claude 可以连到我自己的 Obsidian 就好了」，<u>风趣的海豚</u> 立刻贴出 [Claudian](https://github.com/YishenTu/claudian)——一个 Obsidian 社区插件，把 Claude Code、Codex、OpenCode 等 agent 直接嵌入 vault 运行。核心功能包括侧边栏多 Tab 聊天、inline edit 带词级 diff、Slash Commands / Skills 模板复用、Plan Mode（先设计后执行）、MCP Server 接入，数据存储在 `vault/.claudian/`，无额外遥测。

<u>稳重的海豚</u> 说他之前连过一阵子，但后来发现「Obsidian 这个玩意儿我拿 VS Code 不就得了」。<u>温暖的北极熊</u> 更彻底——CC 和 Codex 都已连上，「有事都在 Code 里说」，不再用 Claude Desktop 的 Chat。

### ChatGPT Finance 接入 Plaid

<u>80-HD</u> 展示了 ChatGPT 新上线的 Finance 功能截图——通过 Plaid 连接银行账户，在聊天界面查看财务数据。底部有「Finances」标签和 Plaid 授权弹窗，他表示「有点犹豫」。

<u>低调的北极熊</u> 实际体验后泼冷水：「没啥意思，和自己 Plaid 下来的一模一样」，给的是统一模板、手机上不好看、不如自己 DIY。不过他也指出不是所有人都能拿到 Plaid API——需要注册 LLC 并过一堆 compliance。<u>沉稳的松鼠</u> 有现成 LLC 但嫌 Plaid 太麻烦，直接用的 YNAB。<u>孔哥仁且义孟哥义且仁</u> 出于隐私顾虑「不敢试」，建议用 Copilot——「他不会经过 OpenAI，微软又看不上」。

### 中文长文本 TTS 方案

<u>风趣的犀牛</u> 为 side project 求推荐中文长文本转语音方案，试过 MiniMax 和 ElevenLabs 但中文效果「都还差点意思」。群友推荐了几个方向：<u>开朗的企鹅</u> 建议试豆包语音大模型版；<u>活泼的羊驼</u> 推荐 ChatTTS 和火山语音服务——「前几天晚上手搓了一个，ChatTTS 快速做一个挺快的」；<u>沉稳的松鼠</u> 提到 Fish Speech 的同学不在本群。

## 闲聊花絮

### CC 拒绝干活：PR 超千行，建议交差

<u>80-HD</u> 让 CC 干活，干到一半突然被拒：「你这个干完 PR 肯定超过 1 千行，merge 不进去的，让我放弃或者写个简单的交差。」<u>稳重的海豚</u> 立刻站队：「就是听 CC 的准没错。」<u>沉稳的兔子</u>：「没错！」<u>80-HD</u>：「我听了，然后就直接下班了。」

### 18 小时 Agent 报告与 React 围剿战

<u>稳重的海豚</u> 分享了用 agent 跑了 18 小时调研 YC RFS 写出的[创业格局分析报告](https://www.nickgu.me/blog/startup-landscape-may-2026-expanded-trilingual)，有中文版。<u>聪明的蜂鸟</u> 好奇「18 个小时，agent 是啥」，<u>稳重的海豚</u> 诚实交代：「不，15 个小时等 quota」，随后自嘲「marketing language 哈哈哈哈」。

更有意思的是多路 AI 尝试读取这篇 React 渲染的页面时集体翻车。<u>幽默的犀牛</u> 让 AI 提取内容失败；<u>孔哥仁且义孟哥义且仁</u> 直接告诉 ChatGPT「这是 React 渲染的，需要一些前端技巧，你想想办法」——被 <u>敏锐的兔子</u> 评价「太像领导了」——AI 折腾一番后放弃了。<u>幽默的犀牛</u> 最后只好手动复制 HTML。

唯一成功的是 <u>80-HD</u> 的老鸭汤：「我扔给老鸭汤自己就消化了，它提了一句只抓到 title，然后突然蹦出来一堆 tool use，然后就读好了。」原来他的 Codex 文件目录里赫然出现了 `.playwright-mcp` 文件夹——「我没让装过。」<u>稳重的海豚</u> 的回应堪称哲学：「应该说你没让不装过。」

### 靠变形金刚评测学英语听力

<u>冷静的白鹭</u> 问 <u>孔哥仁且义孟哥义且仁</u> 怎么提高英语听力和口语。答案出人意料：「听就好了，听多了自然就提高了。比如我就是靠看了 1000 个小时的变形金刚模型评测。」他复盘发现进步最快的时候「就是为了买模型看了海量评测」——要诀是关字幕、选自己熟悉的领域。「过去一直用英语编程阅读写文档带来的效果确实不如习惯去听。」

### 老黄雷神锤

<u>孔哥仁且义孟哥义且仁</u> 贴了一张 AI 合成的黄仁勋图——皮衣加眼镜、右手高举显卡、左手朝镜头猛抓，姿势酷似雷神锤击。继 [「黄仁勋拎箱系列 P 图」]({{ '/daily/2026/05/12/daily/#黄仁勋拎箱系列-p-图' | relative_url }}) 之后，老黄 P 图已成为群内连续剧。他随后又贴了一张图，<u>风趣的海豚</u> 评价「24 口交换机名不虚传」，<u>天真的浣熊</u> 质疑「确定不是 AI 生成图？」，<u>直率的鹦鹉</u> 调侃「训练语料是从 p 站爬的么」。
