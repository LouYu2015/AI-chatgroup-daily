### SaaS 数据训练分层定价

<u>今天群内信息量极大</u> 发布了 [当数据保护变成定价功能：SaaS 行业 AI 数据策略的三代演化](https://yage.ai/share/saas-ai-data-pricing-20260519.html?utm_source=wechat&utm_medium=share&utm_campaign=saas-ai-data-pricing-20260519)。核心判断：「你的数据不被用于 AI 训练」正在从默认权利变成付费功能。文章梳理了三代演化——2023 年 Zoom 试水遭反弹退让、2024 年 Slack 藏条款被 HN 用户挖出、2026 年 Atlassian 和 GitHub Copilot 将其系统化为按层级分档：Atlassian 的 Free/Standard/Premium 用户元数据强制收集且无法关闭，内容数据默认开启，只有 Enterprise（最低 801 用户）才能完全退出。这是对此前「客户数据永不用于 AI 模型训练」承诺的硬翻转。

<u>冷静的麋鹿</u> 给出了一个精彩的类比分析：这和国内视频平台的「会员免广告」悖论如出一辙。

> <u>冷静的麋鹿</u>：你通过付费手段区隔出了最有价值的一批广告受众，却把他们保护起来不看广告，这本身就是矛盾的。对于模型的训练数据来说也是一样的道理。企业用户和付费用户的数据……是更有价值的。现在厂商只收集免费用户的数据，短期内可能还有一些参考价值，但慢慢地，这些数据的价值会越来越少。

他进一步用公式拆解：「你付的钱 + 你贡献的数据的价值 > 模型厂商的推理成本 + 未来训练成本」——等号右边一旦因训练需要高质量数据而变大，用户要么付更多钱，要么开始贡献数据。<u>今天群内信息量极大</u> 确认这个趋势已经出现：「Confluence 现在非 enterprise 账户已经不能 opt out 了。」<u>豁达的鸵鸟</u> 补充 B 端可能走不同路径——私有化部署、Applied AI/FDE 合作模式、或像 Reddit 那样直接卖数据绕过用户。这与前几天 [「OpenAI 银行数据接入」]({{ '/daily/2026/05/16/daily/#openai-银行数据接入' | relative_url }}) 的讨论指向同一个方向：数据主权正在变成付费等级的函数。

## Anthropic 开源收购战略

### 花几亿买开源的四层逻辑

<u>今天群内信息量极大</u> 发布了 [既然都是开源的，为什么还要花几亿去买](https://yage.ai/share/open-source-acquisition-ai-infra-20260519.html?utm_source=wechat&utm_medium=share&utm_campaign=open-source-acquisition-ai-infra-20260519)。Anthropic 半年内完成四笔收购——Bun（JS 运行时）、Vercept、Coefficient Bio（4 亿美元）、Stainless（超 3 亿美元 SDK 生成工具）；OpenAI 同期拿下 Astral（uv、Ruff）和 Promptfoo。标的几乎全是 MIT/Apache 开源。

文章给出四层解释：**团队即隐性知识**——Bun 用 Zig 写成，没有原团队就无法做核心重写；Stainless 49 人团队积累四年 SDK 生成流水线，anthropic-sdk-python 仓库 825 个源文件头部都写着「File generated by Stainless」。**依赖可靠性**——Claude Code 年化收入超 10 亿美元的产品不能把运行时依赖绑在零收入的 VC 创业公司上。**竞对截胡**——Stainless 同时服务 OpenAI、Google、Meta 等，收购后托管产品关闭，竞对失去 SDK 自动同步能力。**路线图控制**——收购后 Bun 的优先级转向 Claude Code 需要的图像处理 API 和 HTTP/3 支持。

两家公司的收购呈镜像结构：Anthropic 抓基础运行时和 API 连接层，OpenAI 抢 Python 工具链和开发者工作流入口。背后站着同一个 VC——a16z 同时投了 Stainless 和 Astral。<u>开朗的企鹅</u> 从中推导出可操作的创业方向：「最值得做的不是又一个开源 Agent 框架，而是 Agent 基础设施里的可靠性/连接/治理层」——具体包括 MCP 检查、agent 工具调用链测试、tool gateway 审计回放等。

### Bun Rust 重写与基础设施封锁

今天讨论中最戏剧性的连锁反应来自 Bun 的收购后续。<u>今天群内信息量极大</u> 揭示：Zig 语言创始人在行为准则中严格禁止 AI/LLM 生成内容，而 Anthropic 的主业就是 AI——于是收购后四天内，Bun 创始人团队借助 AI agent 把超过 100 万行代码从 Zig 迁移到 Rust，「几乎完全解决了内存泄漏」。

> <u>今天群内信息量极大</u>：你搞不定的事情，又不给用 AI 来搞，只能完全灭门，用 Rust + AI 来搞定了

<u>随和的飞鼠</u> 点出 Rust 在 AI 时代的结构性优势：「能编译就基本一定对这个特点，反而变成好事了。」紧接着四人齐声：「人类还是太脆弱了。」<u>天真的浣熊</u> 补了一句现实对照：「Firefox 自己的重写至今没搞定。」<u>风趣的企鹅</u> 追问能否写一篇深度长文「为什么 Rust + AI 是当前最好的解法」，<u>今天群内信息量极大</u> 坦言自己也还不确定，需要学习。

Stainless 的收购则揭示了另一层商战逻辑。<u>今天群内信息量极大</u> 指出 Stainless 同时服务 OpenAI——收购完成后直接关闭托管产品。<u>豁达的鸵鸟</u> 当场验证：「他们官网进去的 code 都是 OpenAI 的 SDK……结果被 Anthropic 收购」，又看了一眼：「哦我刚又打开看了一下，examples 换成 Anthropic 的了……前天还是 OpenAI。」<u>今天群内信息量极大</u> 称之为「Denial of infrastructure attack」，总结了今天最精辟的一句对比：

> <u>今天群内信息量极大</u>：想象中的商战：优化训练算法，多场景刷榜。事实的商战：你用什么软件，收购这个公司断你的线

<u>机智的荷兰猪</u> 贡献了当天最荒诞的商战想象：「真实的商战：用开水浇灭对方公司的前台发财树……物理和玄学上的双重打击。」这与前天 [「AI 模型公司洗牌：AI21 裁员 60% 停卖模型」]({{ '/daily/2026/05/18/daily/#ai-模型公司洗牌ai21-裁员-60-停卖模型' | relative_url }}) 中「纯卖模型访问权限在结构上已不可持续」的判断以及 [「Agent Runtime 成为新主战场」]({{ '/daily/2026/05/16/daily/#agent-runtime-成为新主战场' | relative_url }}) 的分析形成完整叙事：竞争焦点已从模型能力转向基础设施控制权。<u>今天群内信息量极大</u> 同时重新分享了前天的 [「为 AI 重写工具：Zero 与 Cloudflare 的启示」]({{ '/daily/2026/05/17/daily/#为-ai-重写工具zero-与-cloudflare-的启示' | relative_url }})，强调「很多东西 AI 适配不是把 API 翻译成 MCP 就好」。

## 方法论

### LLM Wiki 个人知识库工作流

<u>细心的猫头鹰</u> 分享了一套完整的「AI 代写」工作流。他已将 90 篇超过 1000 赞的知乎答案和 200 篇博客文章导入自己的 LLM Wiki。看到想回答的问题时，直接把问题贴给 Codex，审阅调整后发出。

更有技术含量的是推文导入：20K 条 tweet 直接灌进去质量很低，于是他和 AI 讨论出一套设计——先对每条 tweet 做 embedding，再对 20K 个 embedding 做 clustering，最后把每个 cluster 里所有 tweet 整合成一个 Markdown 文档导入。

<u>稳重的海豚</u> 追问核心目的，<u>细心的猫头鹰</u> 拆成两个层次：一是让 AI 在写作时通过 MCP 搜索他过去发表过的观点，用他的思路写作；二是让 AI 先归纳已有文本的写作风格，写作时应用。目标很明确：「尽快让 AI 取代我来发文本内容。」

### CC 接管 Git 工作流

今天群里围绕 CC/Codex 如何处理 Git 操作展开了一串实战分享。<u>80-HD</u> 坦言「git 我也不记了，每次花 5 毛钱 create 一个 PR」，用 CC 处理 merge conflict「虽然时不时 force push，但是问题不大」。他还发现 CC 会主动协商工作量：「CC 经常跟我说，啊你太多 commit 了，我们先 squash 然后再修 merge conflict，这样我能少做点。」

<u>鸭哥大号</u> 则走了一条更结构化的路——他分享了 [GacUI 项目的 verify-and-commit.md](https://github.com/vczh-libraries/Workflow/blob/master/.github/Rules/verify-and-commit.md)，把编译器产物和手动修改严格拆成三个独立 commit，末尾写着「DO NOT ASK ME ANY QUESTION, I will not be watching you」。<u>坦荡的灰熊</u> 说自己直接告诉 CC「xxx 和 xxx 分开提交」，<u>80-HD</u> 更潇洒——「我都是'你看着办'」「use your best judgement」，然后补了一句金句：

> <u>80-HD</u>：就把当年老板对我的话术给 AI 了

<u>鸭哥大号</u> 提醒 Git 是少数不能完全交给 AI 的领域：「git 不记得不行，AI 搞垮 git 了太容易了……特别是让 AI 做各种高端操作玩人工 squash。」

<u>坦荡的灰熊</u> 还分享了两个从 CC 自己的 /insight 命令学到的实用 prompt：「帮我做个 inspector UI 反射查看内部的数据结构」和「先派 1-3 个 agent 调查下」——前者解决了需求递增时对黑盒不收敛的恐慌。
