今天聊得最多的是：换了 Opus 5.5，原来那套厚重的 rule 还要不要留？有人建议先做 env 和 benchmark，有人改规则改到快塞满 1M 上下文。新模型里，Ripple-65B Preview 用 65B 稠密架构跑到了 TerminalBench 2.1 的 80.52；Hydrogen-1.0 则在 GLM-5.3 上继续做科学训练。FlashProve 想解决另一件事：让服务商拿出密码学证明，说明自己没偷偷换模型。

## Agent 实战

### 换了 Opus 5.5，原来的厚重 rule 还要不要留

<span class="mention">@认真的喜鹊</span> 之前给 Gemini 做了很厚重的 workflow 和 rule，换到 Opus 5.5 后，感觉这些东西没什么用了。但他又不甘心丢掉自己的积累，也怕塞进去会和 Claude Code 内部的设计打架。

<span class="mention">@冷静的白鹭</span> 问得很直接：「你做 benchmark 了吗？」他的建议是，最应该做的是 env 和 benchmark。<span class="mention">@认真的喜鹊</span> 觉得难点在任务跨度：买螺丝螺母、设置 3D 打印、偏门数学工具、半导体材料、高压电安全、嵌入式开发都会碰到，很难整理出一套测试题。

<span class="mention">@80-HD</span> 给的办法是，把「最终做出成果」和每一件具体任务分开：

- 先把长期目标拆成可执行的任务。
- 对每件事说清楚什么算好。比如螺丝买得好，是因为价格便宜，还是送得快？
- 把操作细节写进 SOP，交给 agent 做；做坏了，就改 SOP，再换一个会话继续。

在他看来，能把问题理清楚、拆清楚、加上量化指标，这一套本身就是别人很难复制的积累。<span class="mention">@今天群内信息量极大</span> 把它叫作「外化」，还开玩笑说，以后大家偷信息，可能都要偷 skill、eval 和 benchmark。

<span class="mention">@认真的喜鹊</span> 用了一个交接比喻：现在的 AI 就像雇一个高智商临时工，看完文档干一下午，第二天再换一个「大概率是克隆人」的临时工。要解决的是这些人怎么接着把活干明白。他仍觉得，复杂任务的不确定性太高，很难全靠反推规划解决。

到了下午，他让 Claude 修改自己设计的 rule，已经快把 1M 上下文占满，还没改完，吐槽它「三步一回头两步一招手」。<span class="mention">@沉稳的兔子</span> 说自己的 Claude 倒是指哪打哪，可能和他聊过好几万字的「哲学」、又写进公共 prompt 有关，不过他也准备清理这份过于啰嗦的版本。

## 模型与研究

### Ripple-65B Preview：65B 稠密，TerminalBench 2.1 跑到 80.52

<span class="mention">@细心的熊猫</span> 分享了 [Ripple-65B Preview](https://www.ricursive.com/ripple)。这是 Ricursive Intelligence 从零训练的 65B 稠密开放权重模型，主打 agentic coding，预训练用了 12 万亿 token，支持最长 1M context。公司本身做 AI 芯片设计，这次放出来的是内部模型的通用变体。

官方公布的 TerminalBench 2.1 对比：

| 模型 | 参数量 | 得分 |
|---|---:|---:|
| Ripple-65B Preview | 65B | 80.52 |
| Reflection Beam | 501B | 80.1 |
| Meta Muse Spark Open | 816B | 76.4 |
| Thinking Machines Inkling | 975B | 63.8 |
| NVIDIA Nemotron 3 Ultra | 550B | 56.4 |

公司称它拿到了美国开放权重模型的新 SOTA。训练账和架构也交代得比较细：

- **研发总成本 3200 万美元**：包括预训练阶梯实验、数据配比、评测、合成数据、后训练配方和最终正式训练。
- **后训练没买数据**：自建合成数据管线，混合 RL 配方用了截断重要性采样、score centering、线性长度惩罚。140 万次 rollout，把 TerminalBench 2.1 从 SFT checkpoint 拉到 80.5；官方称 rollout 数约为 Reflection Beam 的七十分之一。
- **继续做稠密模型**：采用 thin-and-deep 比例，`d_model 5120`、80 层。增加 attention head，同时提高 SWA 层相对 global 层的比例、缩小 SWA 窗口，另外用了 FFN 激活裁剪、gated attention、global NoPE 和 value residual。
- **预训练 MFU 40%**：没用自定义 kernel 和量化。4B 阶梯实验中，官方称代码计算效率最多提升了 16 倍。

模型已上 Hugging Face、Together AI、GMI Cloud、OpenRouter 和 Fireworks。官方还强调，它适合 DGX Spark 这类高算力、低内存带宽的本地设备。<span class="mention">@天真的浣熊</span> 已经开始问：这得什么卡才能跑，Pro 6000？

### FlashProve：不交出权重，也能证明这次回答用了哪个模型

<span class="mention">@睿智的犀牛</span> 转来 [FlashProve 的报道](https://mp.weixin.qq.com/s?__biz=MzA3MzI4MjgzMw==&mid=2651071993&idx=1&sn=76e6f760affc2c0232575f6659db052a&chksm=858e77bd926746bcc5e8a209350f217eda131e874067c854a80122cdc378fa6308df75c9598f#rd)，问它能不能查出 Fable 被偷偷换成 Opus。

报道介绍，Anthropic 开源的这套可验证推理系统，要求服务商参与生成证明：

1. 服务商先对确定的一组模型权重生成密码学承诺，相当于给模型版本做一个加密指纹。
2. 请求完成后，附上一份 zkSNARK，证明输出来自这组权重对该输入的计算。
3. 用户拿模型承诺、输入、回答和证明文件独立验证，不需要拿到权重，也不用自己重跑模型。

测试用的是 Llama 4 Maverick，总参数 400B，每 token 激活约 17B。证明计算只围绕实际激活的专家展开，并在推理后批量生成。

| 项目 | 报道给出的数据 |
|---|---|
| 证明生成吞吐 | 单张 H100 约 110 Token/s |
| 每份证明大小 | 约 18.78 MB |
| 验证耗时 | 24 线程 CPU 约 17 秒，无需 GPU |
| 生成证明的 GPU 时间 | 约为普通 vLLM 推理的 70–95 倍 |

当前实现支持整数模型和 Greedy Decoding；实验窗口是 1024 Token，每份证明实际检查其中一个输出 token。浮点计算、随机采样、长上下文和 agent 多轮交互还没做完。

开源内容包括证明生成器、C++ 与 Lean 验证器、技术文档和形式化证明，采用 Apache 2.0。Lean 部分证明的是协议的完整性、可靠性和零知识性质。

### Hydrogen-1.0：在 GLM-5.3 上做科学训练，753B 权重开放

<span class="mention">@神秘的企鹅</span> 转来 [Hydrogen-1.0 发布文章](https://mp.weixin.qq.com/s?__biz=MzAwMDE3MjUyMQ==&mid=2650832809&idx=1&sn=2cd83b1e01d88485bfd72351dc4dbc11&chksm=80f98dfc64a97987a1654c9b668666e54736df35f32e764da600c9495edab07c0acf2f491c5b#rd)，问：基于开源大模型做微调，现在还有那么大的商业价值吗？

深度原理这款 753B 模型基于 GLM-5.3，继续加入化学、材料科学、生命科学知识，以及科研人员反馈、自有实验室记录和多轮材料探索过程做训练。厂商公布的成绩如下：

| 项目 | Hydrogen-1.0 | 对照 |
|---|---:|---|
| FrontierScience-Research | 38.3% | GPT-6-Astra 33.3%；比 GLM-5.3 高 13.9 个百分点 |
| GPQA-Diamonds | 93.0% | Kimi-K3 93.5%；比基础模型高 3 个百分点 |
| 科学计算内部测试 | 76.92% | GPT-6-Astra 71.79% |
| 单步反应预测 | 90.48% | GPT-6-Astra 83.33% |
| 实验设计与规划，10 分制 | 5.59 | Kimi-K3 4.57 |
| NMR 谱图解析 | 26.67 | GPT-6-Astra 30.00 |
| 第五轮材料搜索最佳指标平均值 | 4.318 eV | GPT-6-Astra 3.689 eV；Kimi-K3 3.353 eV |

实验设计那一项，原文说 opus-5.5 和 gpt-6-astra 拒答严重，没有放进公平对比。

产品侧的例子比总分具体：它能写模拟程序、排查聚乙烯密度计算中的重复计算、比较反应路径，把实验方案拆成操作指令。另有一个叫 **Lab Compile** 的「虚拟编译」功能，在虚拟环境里检查设备支持什么动作、准备是否完成、顺序对不对，比如拦下「没装新吸头就吸液」。

权重已经在 Hugging Face 和 ModelScope 开放，另有 NeuroSpark API，可在 AI Scientist 产品 Mira 中调用，后续计划上 Google、AWS 和微软 Azure 的 MaaS 平台。

## 工具、行业与花絮

### 18 GW 算力中心还没动工，先因废热问题进了法院

<span class="mention">@聪明的雪豹</span> 分享了 [加拿大 Wonder Valley 算力中心的报道](https://mp.weixin.qq.com/s?__biz=MzY5MjE5NjI4NQ==&mid=2247490748&idx=1&sn=7c844121279bb6460b3fbeb59c6de398&chksm=f5e2b6a3c2fa432f2112484c43005239e74bb013098b1e0d8cb2af8e5ea397e3990433cb5d3b#rd)。这个位于阿尔伯塔省、规划投资 700 亿加元的项目，满负荷功率据称达到 18 GW。当地克里族部落委托物理学家罗伯特·戴维斯出具废热推演报告，提交法庭；报道说，法院已驳回开发商的撤诉申请，启动司法审查。

文章围绕几种散热方案列了问题：

- 机房排出的是 35℃–45℃ 的低品位废热，远距离供暖的管网和保温成本高。
- 浸没式液冷改善芯片到介质的导热，最终仍要把热量排出去。
- 大规模向水体排热，可能抬高水温、降低溶解氧。

选址原本看中的，正是当地天然冷源、廉价天然气电力和低地价。省政府此前还给了免除最高等级环境影响评估的待遇。
