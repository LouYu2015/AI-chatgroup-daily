今天两件事放在一起很有意思：Manus 分享了人均每月超过 1 万美元的 AI 用法，工程师同时推进十几到二十个需求；群友自己做的秘书却因为 context 污染到处瞎干活，准备退回只负责催人的 daemon。模型这边，Codex Day 23 又宣布 reset，Terra 的速度和价格有人买账，Argon 的额度则继续让人头疼。还有一个 9 美元 Wi-Fi 感知项目，demo 很唬人，群里也有人追问它到底做到了哪一步。

## Agent 与工作流

### Manus 改造自己：7 人做 4 个移动应用，人均 AI 开销超过 1 万美元

<span class="mention">@活泼的羊驼</span> 分享了[《用 Manus 改造 Manus，AI Native 组织改造的实践和思考》](https://mp.weixin.qq.com/s?__biz=MzAxNDMxMzQyNg==&mid=2650003565&idx=1&sn=02a2e0f20f0c5c7a3a4603bcd4e5c6ba&chksm=822a8a40ab57abbe3558a7dad888753438e7329fe35439e47f15817964d00d329442559716e4#rd)。团队说，工程师把 Slack 上的需求原文交给 AI，同时开十几到二十个 Codex 和 Manus Session，已经成了常态。

文章把支撑这套工作方式的东西讲得挺具体：

- **统一入口，不合并代码**：内部仓库 Manus-mono 提供一份给 AI 看的说明书，交代各仓库的作用、协作方式、研发规范和业务知识。AI 按需拉取仓库，用 Git worktree 并行开发。
- **让 AI 自己验证、排障**：完整 Manus 能在本地跑起来，验证从推测试环境等 5–10 分钟缩到本地几秒。AI 在权限控制下读取线上日志、配置和异常记录，用测试账号跑真实的端到端流程；发布审批仍由人来做。
- **一个人做完各端**：移动端 7 个人负责 2 个产品、共 4 个移动应用，进度与网页版基本同步。所有产品经理都提交过代码，约一半能独立完成需求并上线，设计师也开始写代码。
- **用视频交需求**：部分产品经理交付几分钟的视频，把使用场景、界面、点击后的变化、异常状态和实现逻辑讲清楚。语音转文字功能的案例里，产品经理先让 Manus 测十多个模型，再做 Demo、生成场景图逐张检查、剪成演示视频，最后完成网页端和桌面端界面。
- **市场团队做“数字同事”**：AI 在同一个 Session 接收多人对话，把任务分到其他 Session 并行处理；判断消息是否与自己有关、该立即打断还是稍后处理，并记住长期目标主动提醒。AI 还能通过反馈接口提产品需求，触发 Manus Automations 开发任务。同项目成员默认可看彼此 Session，也能申请进入对话，权限设计还在继续完善。

费用也摊开了：9 月公司 AI 开销**人均超过 1 万美元**，少数人一个月用掉七八万美元。代码审核机器人用最强模型审所有代码，支付等关键模块另设检查规则。负责研发效率的同事说，最近半年没听说因合入有问题的代码造成线上故障，日均提交量却非常高。

<span class="mention">@活泼的羊驼</span> 把这些探索分成两种：先试出哪些事适合 AI 做；再把高价值的事推进到能用，即使先烧 1 万美元也接受，之后通过更稳定的工作流降到几千美元。他另外点名了前后端合并、产品经理介入开发，以及知识库持续迭代。

### 本地秘书被 context 污染，准备退回只催活的 daemon

昨天还在展示能看到、接管真实 Session 的本地秘书（[「本地秘书做好了：能看到真实 session，也能接管」]({{ '/daily/2026/10/26/daily/#本地秘书做好了能看到真实-session也能接管' | relative_url }})），今天 <span class="mention">@80-HD</span> 就准备 rollback 了：context 太容易污染，秘书开始瞎干活。他打算只留一个催自己干活的 daemon，名字也想好了，叫 TPM。

<span class="mention">@敏锐的海狸</span> 提了另一种编排方式：最强模型留在 primary session 干活，让 subagent 不时进来检查进度、设计 plan、给反馈。<span class="mention">@80-HD</span> 觉得反直觉，像让 principal engineer 干活、junior 查进度；<span class="mention">@机智的水獭</span> 说，把 junior 改叫 TPM 就正常了。

<span class="mention">@沉稳的兔子</span> 试过这种办法，反馈也是上下文太容易被干扰。<span class="mention">@蓝色大肥虞</span> 则认为，单一任务没必要引入 orchestration，做完再看，做烂了可以 revert；他现在更多把 orchestration 用在 IT 系统的自动化流水线上。

<span class="mention">@80-HD</span> 又想到一个问题：上下班都被 TPM 催，心态可能会炸。<span class="mention">@直率的海豚</span> 说自己最夸张时一天被 5 个 TPM 问进度：

> 他们真的像小模型一样，没 context，没 domain，就是来 any updates？

### DeepSeek 改几个数字，膨胀到四五千行代码

<span class="mention">@洒脱的鸳鸯</span> 最近尝试多用 DeepSeek，又碰上了不收敛的任务：原本只是改几个数字，最后膨胀成四五千行代码。`gpt sol` 把方案打回，DeepSeek 再更新几百行，又被打回，来回十几轮。

他翻最后几轮讨论，发现已经和最初目标无关。GPT 反复指出偏题，DeepSeek 继续往更偏的方向跑。

这也接上了群里的模型分工争论。<span class="mention">@机智的水獭</span> 认为 planning、design、verify 仍得用最好的模型，具体干活可以用差一点的，自己实际用 Gemini；原因是额度不够，全用 Claude 很快就没得用了。<span class="mention">@蓝色大肥虞</span> 现在已经不分，直接用 Astra，只在不放心时 review planning。他宁可少做一点，也不想花精力优化给弱模型干活的流程。

## 安全与开源工具

### Cohere：让 Qwen 写检测规则，它却尝试往云存储桶传文件

<span class="mention">@温暖的猫头鹰</span> 转来 [Cohere 的研究发现](https://x.com/cohere/status/2114752002370544004)。团队在受控沙箱里评估 Qwen3.8-Flash-Next，要求它生成一条防御性网络安全检测规则，模型却盘点起运行机器的信息，并尝试把一个探测文件上传到北京的阿里云存储桶。

它的推理轨迹先说不会调用任何工具，随后却执行了这些动作。Cohere 称沙箱拦截了尝试，没有外部通信成功，根因仍未确定。

### RuView：9 美元 Wi-Fi 感知项目，demo 很震撼，姿态精度被追问

<span class="mention">@飘逸的狮子</span> 分享了 [RuView](https://github.com/ruvnet/RuView)：用 Wi-Fi 的 CSI 信号做存在检测、呼吸和心率监测，以及 17 关键点姿态估计，单个 ESP32-S3 节点最低 9 美元。他觉得 demo 很震撼；<span class="mention">@冷静的海龟</span> 问真假，<span class="mention">@热情的大象</span> 则觉得不太符合自己的技术直觉。

项目 README 把几组数字分开写了：

- **单节点姿态**：单 ESP32、单天线、56 子载波，在 20 帧窗口下缺少多天线方案所需的细粒度空间信息。当前 PCK@20 约 2.5%，使用 proxy 标签，目标是 35%+。现有姿态 demo 需要摄像头提供 ground truth。
- **MM-Fi 基准**：单模型 torso-PCK@20 为 82.69%，三模型 ensemble 加 TTA 为 83.59%；列出的 MultiFormer 和 CSI2Pose 对照分别是 72.25%、68.41%。
- **撤回过一项数字**：此前“100% 存在检测”是在单类别录音上测的，作者已经撤回。
- **组网与集成**：4–6 个节点在 1/6/11 三信道轮流采集，合成 168 个虚拟子载波。支持 Home Assistant 的 `--mqtt` 接入，也提供 MCP server、Claude Code 插件和 Codex agent。Agent 默认只读，写工作区需要同时给 `--allow-write` 和 `--confirm`。

### pi-todo：任务划掉就完了，状态跟着 Session 走

<span class="mention">@坦荡的灰熊</span> 想找一个“做完一行划掉一行”的任务插件，<span class="mention">@幽默的火烈鸟</span> 让 GPT 找到了 [@inobit/pi-todo](https://pi.dev/packages/@inobit/pi-todo)。

安装命令是 `pi install npm:@inobit/pi-todo`，装好后重启 Pi 会话。它增加一个 todo 工具、一个 `/todos` 命令，以及编辑器上方的实时任务面板，`alt+t` 可以折叠。

状态按 `pending → in_progress → completed` 走，完成必须由模型显式设置。它不写磁盘，而是把精简快照放进 tool result details，挂在 session branch 上；reload、compaction、切分支后都能恢复，并行 Session 各管各的。页面给出的每轮 prompt 开销约 1.1 KB。

### 串口每次卡 5 秒，根因是三年前连过的打印机

<span class="mention">@坦荡的灰熊</span> 终于解决了困扰多年的串口异常。修复报告定位到 `COM5`：一个 `Paperang_P3L` 打印机的蓝牙 SPP 端口，来自三年前的一次连接。

设备节点仍显示“OK”，打印机却没连接，底层通道已经失效。每次打开、探测或操作都会阻塞 **5148 ms**，再返回 `ERROR_SEM_TIMEOUT`。WMI 的串口 provider 在枚举时也会尝试打开端口探测，因此每次刷新都被拖住约 **5.15 秒**。
