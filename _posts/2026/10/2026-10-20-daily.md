## 推理框架与成本

### DeepInfer：生产栈开源，每卡每小时收入 38 美元

DeepSeek 宣布全面开源内部推理框架 **DeepInfer**，同时开放生产级 Token 编解码组件 **deepseek-recipe**。[官方文章](https://mp.weixin.qq.com/s?__biz=Mzk0OTYwNzc3NQ==&mid=2247485884&idx=1&sn=d457981abe7db1f1b5d600fc109dc836&chksm=c2e365ae2e7cfe9533f8c486d8895381e965a54d6450ca0cdadaeec17541fc1b463c95d8c049#rd)里比较具体的内容：

- DeepInfer 已用于 DeepSeek V4.1 Flash 的大规模推理，集成高性能算子和推理引擎，支持分布式推理、推测解码、SWA Bounded Replay、结构化输出。
- 兼容 NVIDIA 和华为昇腾平台。
- deepseek-recipe 的处理逻辑与官方 API 完整对齐，供社区部署复用。
- 后续新模型的推理代码和优化会继续放进仓库。

群里转来的技术报告截图和转述帖，给出了一组生产数字：

| 项目 | 数字 |
|---|---:|
| 单一集群服务吞吐 | 155 万亿 Tokens/天 |
| prefill 每卡吞吐 | 150 万输入 token/s，其中 96% 命中缓存 |
| 平均输入长度 | 77K token |
| 首字延迟 TTFT | 平均 400 ms，P99 1,000 ms |
| decode 每卡吞吐 | 14K token/s |
| 吐字速度 | 230 token/s，代码场景 300 token/s |
| KV cache 不活跃后保留时间 | 72 小时 |
| 平均每卡每小时收入 | 38 美元，按谷价 |

### 真机镜像能操作，但慢和中文输入都在卡人

<span class="mention">@神秘的企鹅</span> 继续问不 root 的微信自动回复该选哪条路：iPhone + Mac，还是 Windows + 安卓。

<span class="mention">@冷静的麋鹿</span> 已经试了 **Codex + 系统「iPhone 镜像」**，连的是真机，没有用模拟器。流程是让 Codex 看截图、定位消息、点击引用、输入回复。他的评价是很慢，效率不怎么样。贴出的执行记录里，消息已经定位并引用，但输入只进去了英文 `ai`，中文没进输入框，粘贴也没生效，模型还在处理输入问题，没有发送。

<span class="mention">@豁达的剑鱼</span> 提议直接走给盲人用的 accessibility API 读文字。<span class="mention">@坦荡的灰熊</span> 随即拿表情包反问：不读图，怎么解释它的语义？「你甚至得读动图。」

<span class="mention">@蓝色大肥虞</span> 给了一个混合方案：

1. 用 UIA 把窗口可见部分读出来，存成文本解析。
2. 通过 accessibility API 拿元素坐标，只有图片区域需要截图。
3. 截图前重新检查元素还在不在，处理键盘弹出、新消息到达造成的位置变化。

<span class="mention">@神秘的企鹅</span> 担心坐标变化会拖慢流程。<span class="mention">@蓝色大肥虞</span> 认为仍比读整屏快，而且整屏分辨率一高，LLM 会压缩图片；他之前做桌宠时，2048 都不够用，稍微压缩就会认错字。

### iphone-use：读屏约 0.1 秒，重复动作录成 flow

<span class="mention">@谨慎的灰熊</span> 推荐了 [iphone-use](https://github.com/leeguooooo/iphone-use)。它让 Claude Code、Codex 或其他 MCP 客户端操作真实 iPhone，核心路线正是无障碍树。

项目给出的做法和数字：

- **读取与操作**：屏幕读成 accessibility tree 文本；点击、输入、滑动由自带的 XCTest runner 执行。兼容 WebDriverAgent HTTP API，但没有使用 WDA 那套实现。
- **速度**：作者在 iPhone 17 Pro Max 上测得，读屏约 0.1 秒，按标签点击并等界面稳定约 1.9 秒；作为对比，基于 WebDriverAgent 的版本是 4.2 秒。
- **动作结果**：每步返回「已生效 / 未发送 / 未知」，并说明能否安全重试。被遮挡的元素会拒绝点击。屏蔽截屏的银行、支付 App 可以显示元素线框图。
- **重复任务**：做过一次的任务能录成 flow，回放不调用模型、不消耗 token，也能当 CI 测试套件运行。
- **不占 Mac 桌面**：不碰 Mac 的屏幕、光标和窗口焦点。人和 agent 共用手机，同一时刻只有一个持有者。
- **配置要求**：支持 iOS 15 及以上、USB 或 Wi-Fi；首次配置需要 macOS 15+、Xcode 登录 Apple ID 和开发者模式，免费账号即可。iOS 15/16 的局域网链路不加密。

许可证是 PolyForm Shield 1.0.0，源码可见，但禁止用于竞争产品或服务，免费提供也不行。

## Agent 实战

### Astra 花七八个小时，把 variant 从反射接到 VM

<span class="mention">@蓝色大肥虞</span> 让 Astra 给自己的脚本支持 C++ 的 variant 类型，改动要从运行时反射一路贯穿 parser、compiler、vm。

他先提供了 spec，明确三件事：

- 运行时反射具体怎么做；
- 支持哪些操作、不支持哪些操作；
- 新语法和新语义是什么。

剩下的交给 Astra。它花了七八个小时从底层做起，用上了他为这些模块设计的一系列代码生成工具，生成的测试覆盖了各方面，实现也很简洁。他还没看最复杂的类型推导部分，但对正确性已经很放心。

他的对比是，Sol 干这类事也能做出来，但结果会是「一坨屎糊脸上」。这次又加强了他的判断：

> 完全没必要使用更差的模型的想法，节省的注意力消耗非常值得。

<span class="mention">@沉稳的兔子</span> 补充，目标明确的任务，Astra 确实很细致。

### Flutter 隐藏 bug：从构建崩溃压到一个 Dart 死分支

<span class="mention">@洒脱的猫头鹰</span> 分享了 [Flutter issue #191575](https://github.com/flutter/flutter/issues/191575)：Astra 帮他复现了一个隐藏 bug，后来推动了修复。

问题发生在 macOS release 构建的 AOT 快照生成阶段，报错是 `Unexpected object (Class with illegal cid, full-aot)`。原应用很难拆：只保留完整 widget 树能构建，只保留完整 service bootstrap 也能构建，两者一起就崩。

后来补出的独立复现没有第三方依赖：把带 `Struct Rect` 的 `NativeCallable.isolateLocal` 放进 `if (<int>[1].length > 1)` 这个死分支，编译 AOT 快照就会失败；条件换成字面量 `false` 则通过。

诊断继续追到了 VM 内部：

1. 编译时已经把 FFI callback trampoline 注册进 `ffi_callback_functions`。
2. 后续内联与常量传播消掉了死分支，但这张表没有同步清理。
3. `Rect` 类被删掉，cid 变成非法值。
4. 快照序列化仍把 callback 表当根，沿着签名追到了已被删除的类，最终崩溃。

他提供了最小复现、Debug 调用链，以及清理该表后崩溃消失的对照实验。10 月 12 日，维护者回复感谢复现；同日正式修复关联了这个 issue，回归测试沿用了复现里的核心触发结构，并扩展到其他回调场景。

### AI 课程与社群：课程养社区，协作请求写给 agent

群里分享了一期[知识付费出海访谈](https://www.xiaoyuzhoufm.com/episode/6ad6c82f285041df1c737125?s=eyJ1IjogIjYxNzlmYzJlZTBmNWU3MjNiYjAxY2ZlNSJ9)。节目介绍的 AI 课程已经迭代 12 期、累计学员超过 3,000 人，社区有 2 万多名成员、700 多个项目。
