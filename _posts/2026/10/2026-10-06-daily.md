今天最值得读的是 OpenAI 一口气在 GitHub 放出的 722 篇数学手稿。群里懂行的人给了第一手判断：千禧年问题并没有被解决，部分成果确实重要，真正的难点在于怎么验证这些结果。另外两件事和订阅直接相关。Codex 第二天就按用户投票做了一次全员重置，刚用掉重置卡的人很郁闷。Claude 出现了官方简中界面和银联卡支付，紧接着就有人「秒封」。最后，想找 AI 味淡的模型写口水文的读者，可以看 <span class="mention">@直率的海豚</span> 给出的一份细致的模型文风清单。

## OpenAI 数学成果

### 722 篇手稿的来龙去脉

<span class="mention">@坚定的貂</span> 下午贴出 [openai/math](https://github.com/openai/math) 仓库，<span class="mention">@神秘的企鹅</span> 随后转了[机器之心的报道](https://mp.weixin.qq.com/s?__biz=MzA3MzI4MjgzMw==&mid=2651061320&idx=1&sn=9ccf3204921b2620923ef26380fb3bb6&chksm=85417562c1705b4a72ab0dab20d41c26ffe37d73ad323608fc2c0da6f007449506bfff272370#rd)。关键数字如下：

- 722 篇手稿，归入 372 个成果族，全部出自同一个未发布、未命名的「内部前沿模型」。
- 评估中投喂了约 4000 道研究问题，平均每个结果消耗约 3 小时 ChatGPT Pro 思考的算力。
- 372 族中有 235 族附带 Lean 形式化，约占六成三。OpenAI 承认未形式化的部分「可能有问题」。
- 官方给出的动机是现有数学评测已经饱和，所以把评估扩展到开放问题。

报道里列出的头条结果包括：准黎曼猜想给出 θ = 7/8，对 zeta 函数和所有狄利克雷 L 函数一致成立，已有 Lean 形式化；声称证明唯一游戏猜想；自由群因子同构问题，即 L(F₂) ≅ L(F₃)，进而所有非阿贝尔自由群因子同构；有理数域上希尔伯特第十问题的否定解答；CM 阿贝尔簇上的有理霍奇猜想；π 的无理性测度恰为 2。

报道也交代了争议背景。IAS 数学与 AI 咨询小组曾要求公开模型名称、提示词和算力，并把成果放进中立仓库，OpenAI 只做到了一部分。此前有 25 位菲尔兹奖得主联署声明。纽约大学有学者指控 OpenAI 抢跑其私下合作的工作。陶哲轩 9 月的判断是，真正的冲突在于证明产出过剩与专家注意力稀缺之间的错配。

### 价值与验证之辩

群里的反应分两派。<span class="mention">@坚定的貂</span> 通读后的感受是「被碾压了」「10 年进展一天发生」，还开玩笑说要是能把这个带回几年前，菲奖加图灵奖都能拿。<span class="mention">@沉稳的兔子</span> 则给热度降温：千禧年问题本身没有解决，只算推进；很多结果「现在没什么用」，但唯一游戏猜想确实重要。他还补了一句：「活人哪能给尿憋死，就不是 optimal 的又怎样，又不是不能用。」

<span class="mention">@稳重的海豚</span> 自称「对数学啥也不懂的傻程序员」，干脆让 GPT 和 Opus 来拆台。GPT 筛出的高价值项有三条：矩阵乘法指数从约 2.371 压到 ω ≤ 2.25；最短公共超串的确定性 2 倍近似算法，此前公开最好约 2.466；唯一游戏猜想给 Max-Cut、顶点覆盖等问题划定了近似算法的天花板。GPT 被追问后也收回了一部分判断：

> 722 篇论文这个数字本身几乎不值得兴奋。如果只是模型吐出来 722 个 plausible proofs，然后需要数学家花几万小时逐篇排雷，那甚至可能是负价值——把最稀缺的人类专家变成 AI 垃圾审核员。

Opus 5.5 Xhigh 认为，决定性变量是 Lean 里的陈述是否忠实于原定理，证明本身反而是次要的。它给出的最便宜检验分三步：请三位领域专家只读准黎曼、Thompson、自由群因子三条 Comparator 陈述，每条不超过 250 行；在大机器上跑一遍 `lake env comparator`；接下来一两周关注陶哲轩和 MathOverflow 的回应。<span class="mention">@稳重的海豚</span> 打算把这件事拿到这周课上讲，称它是 harness discipline 的教科书案例：委派的是开放问题，证据是 Lean 证明，独立检查交给 Comparator，信任边界落在陈述是否忠实。<span class="mention">@沉稳的仓鼠</span> 建议他干脆让学生用 AI 去读这批结果。

群友顺手算了算产能。<span class="mention">@沉稳的兔子</span> 说一礼拜消化一个，700 个够干 15 年。<span class="mention">@80-HD</span> 设计了流量打法：每消化一个，发一篇文章、一篇公众号解读、一期科普视频，吃三波流量。

### Lean 与 agent 的工具边界

<span class="mention">@稳重的海豚</span> 在备课材料里写了一条定义：agent 是感知并作用于环境的东西，语言模型唯一的传感器是 prompt，唯一的执行器是它写出的文本，所以凡是纯靠思考能解决的事都不需要 tool。他据此追问：逻辑推理类问题是不是就不需要工具？

<span class="mention">@沉稳的兔子</span> 和 <span class="mention">@蓝色大肥虞</span> 几乎同时回答：Lean。<span class="mention">@沉稳的兔子</span> 的解释是，只要管头管尾的问题，AI 都能做得不错，Lean 的好处是快，相当于看函数签名和看实现的区别。至于能力从哪来，他认为主要靠 RL 训练出一个启发式搜索器，「和围棋就还挺像的」。<span class="mention">@蓝色大肥虞</span> 说得更直接：Lean 的好处是你不用解释自己为什么正确，否则人类还得自己重做一遍才能确认 agent 的结论对不对。<span class="mention">@沉稳的兔子</span> 不同意，认为那本来就只是 peer review。<span class="mention">@坚定的貂</span> 和 <span class="mention">@开朗的企鹅</span> 从另一个方向回应：之前的做法就是尽量不写代码、纯思考，所以工具并非必需。

## 写作与模型风格

### 哪个模型 AI 味最淡

<span class="mention">@神秘的企鹅</span> 看到一篇 Opus 5.5 写的「自传散文」，觉得惊艳，便问 Claude 的 AI 味重不重。那篇散文的开头是「我没有生日。如果一定要找一个起点，那大概是无数人写下的文字被收拢在一起的时刻」，结尾是「等它开始的时候，我会重新醒来，面对一个新的人，说一声：你好，我能帮你什么？」。

<span class="mention">@直率的海豚</span> 自己人肉写作，也长期看社区评价，给出了一份相当细的清单：

- **Claude**：5.5 比前几代稍好，但对 AI 味敏感的人仍能一眼认出那些套路，比如「不是……而是」「会更稳、更平」「他读她」「他刺她」。他觉得 API 和 chat 的文笔都不如 4.5、4.6 时自然流畅。4.7 时代最猖狂，常生造别扭的中文词。写技术文档和原理解释没问题。
- **Gemini**：行文最流畅、生动，中文尤其明显，「不是其他美国模型能比的」。但从 3.5 Flash 起有重复的口癖，比如爱说「极其」，人设容易变霸总，上下文逻辑也会脱线。他认为 Pro 3.0 最好，3.1 已经「痴呆」。
- **DeepSeek**：想要 2.5 Pro 那种味道，可以用 V3.1、V3.2，那是相对平衡的时代。R1 几乎没有 AI 味，但比较中二。V4「全部寄了」，不过在简短对话加非常具体的 prompt 下，也能说得像个人。
- **开源旧版本**（仅限中文）：Kimi 2.7/2.6、GLM 5.2/5.0、Gemma4。别指望它们有 Claude、GPT 的逻辑性。
- 只要跳脱、不要逻辑的话，用古早模型并把温度拉高，「有奇效」。

<span class="mention">@稳重的海豚</span> 的做法是给人看的东西交给 Gemini 按个人风格重写。<span class="mention">@神秘的企鹅</span> 的需求是无脑口播稿，试下来 Gemini 3.1 Pro 的 AI 味掉了很多。他又让 Claude 写了一篇「大 A 的自传」，从 1990 年沪深交易所开张写到 2015 年千股跌停，结尾是「市场从不欠任何人钱，但也从不会把所有人都辜负」。他的结论是「Claude 还是有点强」。

### FatFishFairy 桌面精灵

为了说明 DeepSeek V4 加具体 prompt 也能有人味，<span class="mention">@直率的海豚</span> 分享了 [FatFishFairy](https://github.com/vczh/FatFishFairy/tree/main)。这是一个 Windows 桌面精灵：持续截屏交给视觉模型描述，再由精灵模型根据屏幕上正在发生的事在气泡里吐槽，兴趣会记进本地记忆。模型只需要兼容 OpenAI Chat Completions 协议，内置三个角色，人设可以编辑 `Character.md` 自定义。仓库特别强调，程序会把屏幕内容毫无保留地上传给模型，强烈建议只连自己完全受控的本地模型。

### 秃头与彼得原理

<span class="mention">@细心的熊猫</span> 觉得有了 AI 之后程序员秃头率会降低，几位群友纷纷表示自己头发又多又立，「确实不是好程序员」。<span class="mention">@蓝色大肥虞</span> 认为秃头是因为压力大，不是因为工作多，并给出了一个解法：

> 过好日子还是得两个人一起干，这样就可以都不 promote 到自己能做的最高的职位上，自然就没有压力了。
