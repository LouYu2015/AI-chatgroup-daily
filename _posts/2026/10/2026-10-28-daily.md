## Agent 与检索工具

### Slack 来活，直接发给常驻 Claude：Windows 用 SendInput，Mac 用 tmux

<span class="mention">@细心的熊猫</span> 想做一个分发器：持续扫描 Slack，有人 @ 自己，就把任务交给对应的常驻 Claude 对话。卡住的地方是怎么往已有会话里发消息。

群里给了两条路：

- **Windows**：<span class="mention">@蓝色大肥虞</span> 建议把 Claude 当 CLI 窗口，用 [Win32 SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput) 合成键盘输入，连 `/new` 也可以这样发送。

<span class="mention">@温暖的熊猫</span> 已经在用 Claude 带着 **8 个 ds 4.1，24 小时干活**；DS 额度用完，Claude 还会叫他打钱。

> 我需要 1 个 deepseek 带着 8 个 opus 干活儿。

### Memvid：把原文、向量、索引和 WAL 塞进一个文件

<span class="mention">@80-HD</span> 分享了 [Memvid](https://memvid.com)，称它是“single file RAG”。

它接收文档、笔记、对话等文本，自动分块、做 embedding、建索引，最终产出一个 **`.mv2` 文件**，里面包含原始数据、向量、索引和 WAL，不需要另搭数据库或服务器。

官网列出的功能包括：

- BM25 词法匹配与语义向量混合检索。
- 面向对话历史、时序查询的时间线索引。
- 内嵌 WAL，崩溃后自动恢复；相同输入产生相同输出。
- 本地、私有云或离线环境运行，通过 MCP、SDK 或直接 API 接入。

### 256MB 内存不够，改加载方式后降到 103MB

<span class="mention">@冷静的飞鼠</span> 分享的[公开课](https://www.superlinear.academy/c/recording/ai-answers-what-courses-give)里，有一组很具体的检索服务改造。服务背后是近 **800 万字材料**，没有搭复杂 RAG，向量放普通文件，再加关键词搜索。

三个决定分别是：

| 遇到的事 | 实际做法与结果 |
|---|---|
| 要从大量材料里检索 | 普通文件存向量，加关键词搜索 |
| 服务内存上限 256MB，需求约 260MB | 改成不必每次全量装入，内存降到 **103MB**，**两秒就绪**；1,556 次检索前后结果一字不差 |
| “没看过”功能让数据库请求暴涨 | 上线第三天，日请求从约 **3,000 涨到 178,000**；第四天免费额度耗尽，网站挂了 20 分钟，最后直接砍掉功能 |

他讲“判断力”的练法也很具体：先把判断写成可能出错的预测，注明会发生什么、概率多大、什么时候能看到结果，再拿现实回来对照。检查一门课有没有用，则看手里是否多了一个做完的东西，卡住之后能不能自己接着走。

## 生图与本地硬件

### 固定人物换装：衣服好改，动作一变就不像了

<span class="mention">@稳重的海豚</span> 想做固定人物的时尚换装，希望脸不变，但发型、衣服、姿势和场景可以变化。他的体验是，**单改衣服基本 100% OK，换场景和动作就容易失去一致性**，多个修改指令同时发尤其容易跑偏。最近试过 Grok，觉得不行，GPT 好很多。

他拿到的模型建议是 Identity-aware Adapter：把身份作为每次推理的条件传入，避免普通 LoRA 把训练图里反复出现的发型、衣服、光照也一起学进去。建议中提到了 FaceID / Identity Adapter、多参考图，以及 PhotoMaker V2、PuLID。

<span class="mention">@勇敢的犀牛</span> 觉得现在未必需要训练 LoRA，一张参考图就可以先试；与其折腾本地方案，不如直接上 gpt image gen。他说最新生图模型专门优化了一致性，宣传片就是同一个人不停换背景。

本地模型方面，<span class="mention">@睿智的北极熊</span> 推荐 **moss-image**。<span class="mention">@细心的熊猫</span> 追问它比 qwen 好在哪里，群里暂时没有展开对比。

## AI 与工作

### 裁员也有窗口期？先缩团队、重写业务，还是先看投入压力

<span class="mention">@沉稳的仓鼠</span> 今天提出一个判断：**2026 年企业仍能推进大幅缩编，2027 年之后，随着就业问题扩大、保护性立法增加，裁员会越来越难**。他认为，老公司即使被锁住编制，也挡不住没有历史负担的 AI native 小公司进场。

他给管理者的做法有三条：

1. 旧业务进入维护模式，只留交付和现金流所需的人；抽一两个人，按十倍压缩比重做核心业务。
2. 建立 source of truth，指定一个人全权负责，把业务规则写进 AI 可读的知识库和代码库，并允许重写老系统。
3. 把节省的钱投到渠道上。他的判断是产品会变便宜，流量会变贵。

<span class="mention">@勇敢的犀牛</span> 转来另一则企业观察：10% 的员工贡献了 90% 的 AI 生产力与 token 使用提升，大量培训没有改变分布。<span class="mention">@坦荡的灰熊</span> 对这个说法不满意，觉得得看看非 AI 负责人的视角，而且“幂律比例”到底怎么算也没说清。

对于微软这一轮消息，<span class="mention">@蓝色大肥虞</span> 更强调 AI 投入对现金流的挤压：在 AI 还不能替代真人时，企业也可能已经需要砍项目；赌赢了以后可以扩张，赌输了则仍免不了裁员。

### 打工是解题，自己赚钱还得先出题

<span class="mention">@80-HD</span> 把两件事的区别说得很直接：

> 打工跟做题是一回事，有人出题我解题就行了，赚钱就完全不一样了，需要我自己出题自己解。

<span class="mention">@沉稳的仓鼠</span> 听创业故事时注意到，有人尝试过 33 个项目。他给自己的要求是：有了 AI，至少该尝试 100 个；如果没有那些创业者厉害，连尝试次数也没到，失败几次还说明不了多少。他最近也开始批量做视频和音频，觉得纯文本内容已经被 AI 卷得很厉害。

<span class="mention">@冷静的飞鼠</span> 分享的 [Fake Work 对谈](https://www.xiaoyuzhoufm.com/episode/6ae1e359c96c8942ec13bb1f?s=eyJ1IjogIjYxNzlmYzJlZTBmNWU3MjNiYjAxY2ZlNSJ9)里，给了几种减掉表演性工作的做法：

- 先找出根本不需要存在的流程，再考虑自动化。
- 给老板七句话、一个核心建议、说明信心多大，少做几十页材料。
- 非核心工作用 AI 快速做到 60 分，把精力留给更重要的事。
- 暂时不离开原有工作，也可以找一个能拿到真实商业反馈的小闭环。

<span class="mention">@乐观的水獭</span> 对“老板为什么不用做 Fake Work”的解释是：

> 为什么大人不挑食？因为大人只点自己爱吃的。为什么老板不用 Fakework，因为不爱干的事情，他会交给员工干。

### AI 已经会做了，人还要不要学？争论落到了绑骨骼和拓扑上

<span class="mention">@认真的喜鹊</span> 担心的不只是岗位，而是能力断档：有些错误以后没有机会犯，相应能力也就培养不出来。他认为“可以选择不学”和“已经没有机会学”不一样，甚至提出保留按传统方式训练的学校，让人类自己成为 backup。

<span class="mention">@今天群内信息量极大</span> 不觉得所有旧能力都值得保留。计算器出现后，许多珠心算技巧不再必要；数码摄影普及后，胶片技巧也可以变成个人爱好。他自己仍喜欢拍胶片，但不认为大家都需要学。

<span class="mention">@蓝色大肥虞</span> 把问题拆成了三件事：**学不学、做不做、用不用**。他在已有 C#、JS 的年代仍去学汇编，平时未必使用，但它会改变思考方式；Haskell、erlang 也是类似作用。

讨论随后落到 AI 做 3D 模型。他看过的演示里，苦力活已经能交给 AI，但还有两处很依赖美工经验：

- **绑骨骼**：要在动画中检查不同动作、不同角度，找出变形和穿帮。
- **三角形分布与拓扑优化**：很多人连“哪里不好”都说不清，后续做 LOD 也会受影响。

他觉得这和 vibe coding 一样，需求越精细，review 和干预越多。<span class="mention">@今天群内信息量极大</span> 则认为，图形学性能优化交给 AI 已经能做得很好，美工要知道问什么问题；人的价值应该更多放在出题上。

<span class="mention">@蓝色大肥虞</span> 最后举了自己看四角面优化教程的体验：知道为什么这样组织更好，但拿到一个不满意的模型，想让 AI 改时，仍然不知道那句话该怎么说。

## 科研与使用争议

### Claude 药物研发：35,000 个抗体设计，以及一人公司的外部实验室网络

<span class="mention">@活泼的羊驼</span> 转来一份 Anthropic 药物研发进展摘要，列了四组合作结果：

| 合作方 | 摘要中的进展 |
|---|---|
| Generate Biomedicines | 设计出比标准版本短 **70%** 的基因指令，免疫细胞受体产量提升约 **10 倍** |
| Divergence Labs | 一个月内自主生成约 **35,000 个抗体设计**，初步测试发现比标准药物更有效的候选分子 |
| BigHat Biosciences | 候选药物结合力提高 **10 倍以上**，同时改善热稳定性与抗聚集能力 |
| Enveda | 文件审查时间减少 **89%**，从 25 小时降到不到 3 小时 |

摘要描述的做法是让 Claude 参与早期研究、分子设计、生产优化、监管文件和临床试验设计。多数研究目前处在临床前阶段，后续准备扩展到临床试验。

同一天，<span class="mention">@活泼的羊驼</span> 还转来 Mithril Medicine 的案例：公司只有创始人一名全职员工，靠外部顾问和十多家合同实验室推进药物研发，抗体生产、细胞实验、小鼠研究全部外包，合同沟通、数据整理、实验计划调整和邮件往来大量使用 Claude。转文称，从立项到拿到积极的小鼠结果用了不到 18 个月，Anthropic 在今年 7 月收购了它。

<span class="mention">@开朗的企鹅</span> 不认同把这种一人公司模式视作收购的核心原因。<span class="mention">@活泼的羊驼</span> 也补充，复制来的文字不一定全对，但事情本身有启发。

<span class="mention">@机智的鸵鸟</span> 关心的是另一头：办公室里的人可以少，实验室工作量却可能增加；更多人开始尝试做药，会带来更多实验需求，直到实验室也能由机器人运行。

### ChatGPT 用药报道：群里争的是模型责任，还是人的判断

<span class="mention">@温暖的斑马</span> 转来《纽约时报》中文网一篇报道，标题是“ChatGPT 的致命‘用药指导’和一名华人女子的悲剧死亡”。他最震惊的是，真的有人按照 ChatGPT 指导用药，还向医生隐瞒情况。<span class="mention">@稳重的海豚</span> 说，报道中主要使用的是 4o。

群里的分歧很明显：

- <span class="mention">@认真的喜鹊</span> 认为，没有 AI，这类人也可能相信其他骗子；<span class="mention">@睿智的北极熊</span> 提到了过去听信神棍的情况。
- <span class="mention">@温暖的斑马</span> 不接受把两者等同，认为 ChatGPT 加快了悲剧发生。
- <span class="mention">@沉稳的鸵鸟</span> 补充，报道中的人患有癫痫，药物让她昏沉，减量也是她自己的选择。
- 当讨论转向“廉价模型更不靠谱”时，<span class="mention">@热情的河马</span> 追问：多便宜算便宜，把重点放在价格上是不是偏题了？

<span class="mention">@机智的水獭</span> 则讲了一个日常对照：维修师傅愿意用 AI 查资料，他觉得是好事；更让他头疼的是完全不学习、只懂老系统的师傅。
