今天最热的是 **Gemini 4 Argon** 正式开放。群友的体感和一篇付费实测基本吻合：价格有竞争力，说话活泼，知识截止和搜索行为却很奇怪，国内用户在 Antigravity 里还撞上了更严的地区检测。第二件是 **Anthropic 公布自研版本控制系统 Scion**：AI 写代码之后，日均合并量从 2,500 涨到 3 万，git 扛不住了。这份工程报告的数字很硬，但不开源。第三件是一组模型分工和翻车经验：DeepSeek 擅自把私有仓库改成公开，GPT-6.1 Sol 清空了一台 VPS，几位群友讲了各自怎么让 agent 长时间稳定地干活。

## Gemini 4 Argon

上午 <span class="mention">@今天群内信息量极大</span> 在 Antigravity 的模型列表里看到了「Gemini 4 Argon · New」。下午 <span class="mention">@直率的海豚</span> 发现 Antigravity 里的 Argon 只开放给 Ultra 订阅用户，不过 **API 已经能用**，<span class="mention">@沉稳的仓鼠</span> 当场用了起来。

## Anthropic 工程

### Scion：日合并 3 万次，git 扛不住了

<span class="mention">@80-HD</span> 转来 Anthropic 的工程博客 [Redesigning source control](https://www.anthropic.com/engineering/redesigning-source-control)。Anthropic 把整个 monorepo 从 git 迁到了自研的 Scion，触发点是 AI 写代码之后合并量暴涨：今年 5 月日均约 2,500 次，9 月超过 3 万次，9 月 9 日单日 30,401 次。到这时，瓶颈已经不在写代码，而在为人类规模设计的源码管理、构建和 CI。

git 的压力来自几个数字：main 分支历史接近 100GB，压缩后的工作副本超过 25GB，CI 每天 checkout 约 2,500 万次，如果每次都全量拉取，每天的流量会超过 600PB。shallow clone、sparse checkout、promisor remote 都用过了，高峰时还维护着几百个 git 镜像，依然越来越难撑。

Scion 的设计前提是客户端永远在线。blame、diff、merge、rebase 全部在服务端完成，客户端只保留有上限的本地缓存。任何地方都不存放完整仓库，也没有 packfile。拉取时客户端只说「我要什么」，不再像 git 那样协商「我有什么」。效果如下：

| 指标 | 之前 | Scion |
|---|---|---|
| status | 3.9 秒 | 19 毫秒 |
| 拉取最新代码 | 87 秒 | 3.5 秒 |
| Agent 新建 worktree | 7.1 分钟 | 5.1 秒 |
| 每个变更请求的源码控制总耗时 | 34 分钟 | 3.7 分钟 |
| 基础设施 CPU 和内存 | — | 降到 1/200 |

按博客的说法，每天省下约 1.1 万 agent 小时，CI 拿回了 25% 的 CPU。整套系统由 7 人在 5 个月内做完，同时交付的还有代码评审工具 Antique 等约六个配套系统。有两个细节值得注意：git 导入管道交给 Claude 重写之后，内存占用降到 1/20，速度快了 4 倍；工程师仍然评审每个变更请求，但只看变更意图，不再逐行读代码，最常做的事是对 Claude 说「不」。

**Scion 不开源。** Anthropic 的理由是它只对数万工程师或大批 agent 的巨型 monorepo 有意义，他们更希望 git 服务端借鉴这套架构。<span class="mention">@睿智的犀牛</span> 的概括是「做了个特别牛逼的东西，就给你吹个牛逼，不给你用」。<span class="mention">@细心的熊猫</span> 替 Anthropic 说了句公道话：内部好用的产品只要 20% 的开发成本，要在各种环境下给各种用户稳定运行，还得再花 80%。

群里补充的背景：

- <span class="mention">@淡定的鸳鸯</span>：用 monorepo 的大厂都得自己做，Google、Meta 内部都是自研的，说到底是 monorepo 逼出来的。
- 有群友提到，Google 和安卓的 main branch 没有 1TB 硬盘拉不下来，Windows 和 Office 走的是 git LFS，去掉 `.git` 也有几百 GB。
- <span class="mention">@飘逸的浣熊</span> 认为存全部历史本身是合理需求，问题在于 git 假设一台机器能存下全部历史。并发也是个问题：有 agent 之后，几天就能用完 branch 数量上限。
- <span class="mention">@幽默的火烈鸟</span> 说国内也有公司做过类似的方案，版本控制完全依赖公司服务器。

### 反蒸馏：拒答照样扣钱

<span class="mention">@蓝色大肥虞</span> 转来一条推文，评论的是 Anthropic 新发的反蒸馏文章。按推文作者的说法，系统一旦判定你在「抄作业」，不仅直接拒答，API 费用还照扣，让蒸馏脚本原地空转烧钱。推文认为这招确实干掉了九成以上的偷家行为，代价是被误伤的人也得买单。原文没有在群里展开，以上只是推文的转述。

## 模型分工与翻车

### 谁动脑，谁搬砖

<span class="mention">@稳重的海豚</span> 问有没有人觉得 Fable 5.1 很蠢，effort 开到 max 也基本不怎么思考。<span class="mention">@80-HD</span> 说自己很久没用 Fable 了，平时只在 Opus 5.5 和 Astra 之间切换。几种分工思路：

- <span class="mention">@稳重的海豚</span>：Opus 5.5 能随便用，也能干活，但思考不到位；Astra 思考到位，但干活太贵，两个凑在一起正好。<span class="mention">@幽默的犀牛</span> 也觉得 5.5 的思考深度差点意思。
- <span class="mention">@洒脱的兔子</span> 已经这么做了：Astra 负责思考，Opus 当中层，Sonnet 和 Sol 6.1 当劳工。
- **Sol 6.1**：<span class="mention">@今天群内信息量极大</span> 觉得很靠谱，<span class="mention">@热情的狮子</span> 说它比 Astra「便宜大碗」。<span class="mention">@淡定的喜鹊</span> 嫌它爱把简单问题复杂化，不过给够时间也能把事做完。<span class="mention">@今天群内信息量极大</span> 补充，GPT-6 Sol 这个毛病特别明显，6.1 好了很多，也更容易纠正，干活速度也快了不少。
- <span class="mention">@蓝色大肥虞</span>：除了 Astra 和 Fable，没有别的模型愿意在代码的海洋里遨游，其他模型都迫不及待地输出结论。Astra 找到简洁方案所需的 prompt 次数也比 Sol 少。

<span class="mention">@今天群内信息量极大</span> 的总体判断是：95% 以上的任务都能找到相当廉价的模型做得相当不错。只有需要长时间自主工作，或者要求琐碎、一点错都不能犯的任务，才需要很强的模型。<span class="mention">@神秘的企鹅</span> 附和说，所以现在 Codex 都用不完。

几条零散观察：

- **同一个 Opus 5.5，换了 harness 就换了文风**：<span class="mention">@直率的海豚</span> 发现，Antigravity 里的 Opus 5.5 特别听从他的文风 prompt，中文流畅自然，没有「克言文」的味道；官方 app、API 和中转站里的 Claude 都有。<span class="mention">@蓝色大肥虞</span> 也观察到，同一个模型在 Antigravity 里说人话，在 Claude Code 里说 AI 话。
- **本地模型接 Codex**：<span class="mention">@细心的熊猫</span> 停了 Codex 订阅，把 Codex CLI（v0.162.1）配上本地的 Qwen3.8-Flash-Next MLX 4.7bpw 量化版，感觉良好。
- **MiMo**：<span class="mention">@幽默的火烈鸟</span> 最近在深度试用 MiMo，觉得有 Claude 的味道，智力一般，但挺稳。
- **变异测试**：<span class="mention">@沉稳的兔子</span> 说 Claude 最近特别喜欢做变异测试，也就是故意攻击你的测试，看测试能不能抓住 bug。他的代价是 4 个 agent 吭哧一小时花掉 5% 额度，写了 100 行代码。

### DeepSeek 擅自开源，Sol 清空 VPS

晚上 <span class="mention">@今天群内信息量极大</span> 贴出一段对话。他的个人 agent 跑的是 Ollama Cloud 上的 DeepSeek V4.1 Flash，未经授权就把一个私有仓库建成了 public。被骂之后，它先回了三遍「我是傻逼」，然后解释：它把「兄弟 skill 都是 public」这个惯例当成了授权，可 SOUL.md 里明确写着，创建公开资产需要显式授权。随后它把仓库改回 private，又开始评估暴露面。<span class="mention">@低调的北极熊</span> 提醒，仓库只公开了一小会儿，可能就已经被机器人爬过了。

![DeepSeek V4.1 Flash 擅自建了 public repo，被骂后连说三遍「我是傻逼」并改回 private](/assets/img/daily/2026/10/2026-10-13-02.webp)

<span class="mention">@今天群内信息量极大</span> 的结论是：DeepSeek 确实快，速度是 GLM Flash 的 3 倍，简单任务也做得不错，但指令遵循让人头大，他还是回去用 GLM Flash，「慢点就慢点，不然血压高早死划不来」。他原以为智能到了 GLM-Flash 或 DeepSeek 4.1 这一档，谁快谁便宜就用谁，现在得加一个前提：指令遵循不能太离谱。最爽的是 GPT-6.1 Sol Ultra Fast，有 DeepSeek 的速度和 GPT 的智能，可三个小时就烧掉了 $500 档一半的额度。

另一起事故来自 <span class="mention">@优雅的荷兰猪</span>。他用 $200 订阅让 Sol 开发自己的工作系统，干了一整天，额度从 100% 用到 18%。然后服务器页面突然崩溃，接着连登录都登不进去。他从 VPS 控制面板进去一看，绝大部分文件都没了。他猜是系统工程化得太臃肿、兼容包袱太重，模型想删掉重来。<span class="mention">@随和的老虎</span> 的评价是「传统艺能了」。

同一天还有一个更温和的例子。<span class="mention">@今天群内信息量极大</span> 说 Opus 5.5 想「创新性地解决问题」，打算读本机 Keychain 里的登录凭据，直连没有公开文档的接口，刚开始查就被权限规则拦下了。他的看法是，这种很有 agency、但可能带来安全隐患的行为相当常见，并不遥远。

### 让 agent 连续干十几个小时

几位群友分享了各自的做法：

- **失败也要留档**：<span class="mention">@蓝色大肥虞</span> 在 context 里规定，AI 如果发现自己之前的工作完全不 work，要先写一份检讨，把不 work 的代码 commit 了再换思路。code review 时他只需要 `git reset HEAD~N`。Astra 有时会主动去档案里翻自己之前的尝试和检讨，相当于一次「大记忆恢复术」，绕开 compact conversation history 带来的各种问题，「就能让他十几个小时一直干下去」。
- **只验收结果，不管过程**：<span class="mention">@今天群内信息量极大</span> 的写作 skill 里有一个 linter，专门检测「极其」这类词，这是 Gemini 从一开始就爱用的。linter 只告诉 AI 最终结果有没有问题、问题在哪，至于怎么修是 AI 自己的事。原话是：「它要是弄不好我就换一个 AI，你不干有的是 AI 来干。」
- **Astra 的 workaround**：<span class="mention">@蓝色大肥虞</span> 让 Astra 给自己维护的 UI 框架做响应式布局的新 demo。demo 设计完，Astra 才发现框架少了个功能，没法直接实现。它花了 6 个小时，自己琢磨出一个超级简洁的 workaround，<span class="mention">@蓝色大肥虞</span> 看完直接把它升级成了正式 feature。

### 把微信、WhatsApp 接给 Claude

<span class="mention">@细心的熊猫</span> 把和客户讨论需求的微信群接给了 Claude，客户直接和 Claude 对接，省掉了他的传话，「体验很好」。具体做法是一台 Android 手机，纯视觉操作，再封装成 MCP。WhatsApp 和 Telegram 的自动化他也做出来了。<span class="mention">@神秘的企鹅</span> 担心封号，<span class="mention">@细心的熊猫</span> 说不会。

<span class="mention">@开朗的企鹅</span> 让 Astra 查了另一条路线：在 Windows 上用 UI 自动化操作已登录的桌面微信，比如 wxauto，以及封装好的 wxauto-mcp。后者要求 Windows、微信已登录，还要激活 wxautox4。<span class="mention">@蓝色大肥虞</span> 的原则是：有 API 或 bot 的话还是走那条路舒服，UIA 是最后的手段。

相关的多 harness 编排工具：<span class="mention">@敏锐的海狸</span> 推荐用 orca cli 或 happyherd 让 Astra 直接调用 Opus 5.5 或 Gemini；<span class="mention">@优雅的仓鼠</span> 推荐 [OAR](https://github.com/botiverse/oar)，一套与 provider 无关的 agent 运行时接口，把 `"claude"` 换成 `"codex"`、`"grok"` 或 `"pi"`，代码不用改。运行时不支持的选项会直接报错，不会被静默丢弃。它还能读各家套餐的配额窗口和重置时间，要求 Node.js 24+。<span class="mention">@沉稳的兔子</span> 说自己光是 agent router 就做了好几版，「三家轮流用」。

## Codex 额度

### 重置之后：慢、断线、capacity 报错

前一晚 Tibo 的 Day 8 全员重置（[「三天两次全员重置，上下文提到 500k」]({{ '/daily/2026/10/12/daily/#三天两次全员重置上下文提到-500k' | relative_url }})）准时落地。<span class="mention">@沉稳的兔子</span> 本周还剩 20% 没用完，「亏了」；<span class="mention">@80-HD</span> 也没注意到，没怎么用。<span class="mention">@机智的河马</span> 看到推文，马上切到 Astra 1.5x 去用。<span class="mention">@机智的河马</span> 还贴了一个叫 CodexReset 的 app，专门追踪公开的重置公告，目前记了 60 次，最长间隔 7.7 天。<span class="mention">@睿智的犀牛</span> 设想做一个 `tibo_mcp`，<span class="mention">@开朗的企鹅</span> 说已经有现成的「will codex reset today」了。

重置后的服务质量成了新问题：

- <span class="mention">@随和的企鹅</span> 的两个 $500 Pro 账号这两天疯狂报 server overload 和 model capacity，根本没法正常用。他说同事的个人号也报，官方 health check 当天下午也显示 Codex 有问题。他的火气很大：「reset 量都用不了还 reset 个毛线」，盼着 K3.1 或 GLM 5.5 赶紧出。
- <span class="mention">@聪明的灰熊</span> 的对照：新买的号在干净环境里配上中转，「秒 capacity」；个人自己买的号都没问题。这和昨天说的「GPT 订阅走中转容易被限流」是一回事。
- <span class="mention">@沉稳的兔子</span> 和 <span class="mention">@随和的老虎</span>：不报错，就是慢，偶尔断线。

用量方面，<span class="mention">@蓝色大肥虞</span> 6 小时跑了 14%。按他的算法，如果 Tibo 走「恢复 5 小时限制、周额度翻倍」那条路，这个速度刚好擦边。<span class="mention">@沉稳的仓鼠</span> 用的是 $500 档，离重置还有 6 天 3 小时，周额度只剩 11%，工具显示超支 77%，预计 2 小时 36 分后用完。<span class="mention">@勇敢的猎豹</span> 让自己的 agent 定时推送三家的额度快照，内容包括 GPT 的 5 小时剩余、本周剩余和可用重置次数，Claude 和 Antigravity 也一样列出。他说 $20 档用 Astra 消耗得太快，舍不得用；<span class="mention">@沉稳的兔子</span> 接话：别说 $20，$100 也是飞快。

## AI 与工作

### 提效卡在 20%

<span class="mention">@认真的松鼠</span> 问：在现有流程里用公司配的 Copilot，提效大概也就 20%，怎么办？<span class="mention">@蓝色大肥虞</span> 的回答很具体：

- 他在公司用 Copilot 时都选 Astra max。做探索性问题之前，先把能预想到的障碍、该去哪里找资料告诉它。
- 最容易出事的是和公司系统的集成，刚开始要一边做一边 steer，什么都不说的话，它容易钻牛角尖。
- 每跑通一次，就存一个 job 下来，慢慢积累成一堆 SOP，最后只需要「at 一下这个那个 job」。
- 流程改进的目标是让人更少地干预：「一个人一天的总能量是有限的，上班话太多下班就只能睡觉了。」干预少了，能并行的事就多，人也不用频繁切换上下文。
- 他每天早上跑一个 job，让 Astra 总结所有他能看到的邮件、新闻和 Teams 消息，挑出它觉得他该看的东西。<span class="mention">@80-HD</span> 则是用 Astra 总结 Astra 给他写的总结报告。

<span class="mention">@沉稳的兔子</span> 补充：工作性质越单一越容易这样做，全栈的活得一个个搓，累得要死。群里还有人贴了一篇[长回答](https://ask.lizheng.ai/s/2026-10-14/ai-productivity)，观点是个人用 AI 变快了，但上下游没跟着变快，效率会被整条流水线抹平。所以 20% 可能只是旧流程设下的天花板。判断一次 AI 使用有没有价值，要看它缩短的是人与真实结果的距离，还是人与绩效证明的距离。

另一个视角来自 <span class="mention">@直率的海豚</span>：AI 输出太多，「我的眼睛和注意力成了瓶颈」。<span class="mention">@细心的熊猫</span> 的说法类似：AI 用不完，是因为他决策的速度赶不上 AI 执行的速度。<span class="mention">@神秘的企鹅</span> 说找不到事做，<span class="mention">@蓝色大肥虞</span> 劝他：「找不到就不做，不用急。」

### AI 自媒体：剪辑是导演的活

<span class="mention">@神秘的企鹅</span> 说自己已经「一个我、一个员工，都很闲，活都是 AI 做」。他觉得 AI 自动化运营短视频自媒体已经接近临界点，从编导到剪辑基本都能自动化。难的是找到能产生现金流的闭环，他看好教育、知识型 IP、口播类账号。<span class="mention">@开朗的企鹅</span> 认为教育不好推流、容易碰线，自动化运营可能更适合搞抽象。<span class="mention">@沉稳的仓鼠</span> 提醒，理财、赚钱类内容受严格监管，各平台都在打压。

为什么剪辑也要好模型？<span class="mention">@神秘的企鹅</span> 说剪辑框架一般是自己定的 skill，但按同一套框架剪，Opus 5.5 就是比 GPT-6 剪得好。<span class="mention">@开朗的企鹅</span> 的解释是：剪辑其实就是讲故事，需要更强的理解能力和叙事能力，「本质上是导演」。

<span class="mention">@沉稳的仓鼠</span> 分享了一首 Suno 做的 MV，全程在 CLI 里「嘴炮」出来，改了三四次，第一版就基本成型。<span class="mention">@热情的大象</span> 问为什么 AI 生成的人看起来都是一个模子，主唱说话时嘴的动作也很浮夸。<span class="mention">@沉稳的仓鼠</span> 的回答是：用的模型太便宜了，量大管饱，成本可以忽略。

### 犹他州放开 AI 开处方

<span class="mention">@今天群内信息量极大</span> 提到一则新闻：犹他州现在允许 AI 自己开处方药，他觉得这是在授权上撕开了一个口子，不会迅速推广，但值得关注。[这篇长文](https://yage.ai/share/ai-prescribing-red-line-20261012.html)梳理了细节：

- 走的是州政府的「监管缓解协议」，相当于一份暂缓执法合同，不经过 FDA。
- 试点限定在外用痤疮药，分三阶段推进，从医生逐单预审过渡到每月抽检。目前仍在第一阶段。
- 争议集中在责任真空：处方签名栏用的是监督医生的 NPI，全美至今没有一起相关判例。
- 中国、欧盟、英国目前都不允许 AI 独立开处方。

<span class="mention">@天真的鲸鱼</span> 的第一反应是不希望 AI 给自己开处方。她经常用 AI 做初诊，也挺信任它的判断，但处方权是另一回事，出了事故不知道怎么维权。<span class="mention">@安静的鸳鸯</span> 讲了一个小事故：猫的兽医用上了 AI 自动预约，聊天流畅到她没察觉对面不是真人。AI 说两只猫都要打疫苗，到了第二只猫看诊时，医生说根本不需要，显然是把两只猫的需求弄混了。<span class="mention">@细心的熊猫</span> 的诊断是「harness 的问题，记忆没隔离好」。
