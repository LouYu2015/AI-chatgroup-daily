<span class="mention">@细心的熊猫</span> 提前取到 M5 Ultra Mac Studio，和自家 4×5060Ti 做了一圈吞吐对照——想下单的先看完表格，Mac Studio 赢在预填充速度和零噪音，但并发吞吐远不如显卡方案。Manus 2.0 Max 一句提示词就交付了一条完整 MV，agent 驱动的视频制作越来越像真正可用了。<span class="mention">@冷静的麋鹿</span> 旅途中用两个实战案例再次验证 Opus 5.5 在问题定位上确实强过 Astra。

## 工具

### M5 Ultra Mac Studio 开箱实测

<span class="mention">@细心的熊猫</span> 比原定 10 月 2 日提前一天在 Apple Store 取货，拿到 M5 Ultra Mac Studio（256GB 统一内存、1TB SSD，打算回国换 4TB，硬盘不是焊死的）。全速推理时风扇毫无动静，他形容这是「纯纯的工业艺术品」，体积小到可以直接拎去不能上云的客户现场干活。买来的主要目的是腾出 4×5060Ti 去跑 MiniMax H3 视频生成，后者已优化到 4 卡跑 0.8MP 15 秒视频仅需 350 秒。

他用 Qwen3.8 27B（4bit、mlx-serve）与 4×5060Ti 做了对照（贪心解码、关闭思考，单位 tok/s）：

| 场景 | M5 Ultra | 4×5060Ti |
|---|---|---|
| prefill 8K / 32K | 1,947 / 1,750 | 1,455 / 1,383 |
| 单流解码 短上下文 代码 / 散文 | 138 / 89 | 218 / 53 |
| 单流解码 128K 代码 / 散文 | 83 / 43 | 153 / 47 |
| 并发 4 路 / 8 路聚合 | 298 / 183 | 449 / 547 |

Mac Studio 在 prefill 和短上下文散文解码上领先，但代码单流速度不到 5060Ti 的七成，8 路并发吞吐更是被拉开近三倍。<span class="mention">@优雅的喜鹊</span> 指出 4 卡 5060Ti 也打不过 5090 单卡（ninfer 引擎加持），<span class="mention">@细心的熊猫</span> 回应：4 卡 5060Ti 总价不到一张 5090，还有双倍显存。

他还在 Mac Studio 上测试了 DeepSeek V4 Flash（MoE 大模型）的不同量化配置，与 4×5060Ti 参照：

| 配置 | BFCL | prefill 32K | 解码 128K 代码 / 散文 | 8 路聚合 | 内存 |
|---|---|---|---|---|---|
| Flash mixed-4-8 + mlx-serve | 82.00 | 5,432 | 142 / 97 | 259 | 97 GB |
| Flash oQ6e + oMLX | 84.67 | 2,974 | 103 / 77 | 233 | 150 GB |
| 27B 4bit + mlx-serve | 84.00 | 1,750 | 83 / 43 | 298 (4路) | 22 GB |
| 4×5060Ti 参照 | 88.00 | 1,383 | 153 / 47 | 547 | — |

mixed-4-8 量化把 prefill 推到 5,432 tok/s，但 BFCL 掉到 82、RSS 占 97GB。4×5060Ti 的 BFCL 和并发吞吐仍然全场最高。他最终选定 Qwen3.8 Flash-Next（MLX Medium）接入 Claude Code 实跑：TTFT 1.1s、TPS 139 tok/s、cache hit 93%，本地推理流畅驱动 agent 干活已不成问题。

<span class="mention">@优雅的喜鹊</span> 另外分享了一组 DeepSeek V4 Flash 的跨平台同题对比（32,953 prompt tokens）：M5 Ultra（llama.cpp）首 token 延迟 50.7 秒、decode 36.7 tok/s；2× DGX Spark（vLLM）首 token 17.0 秒、decode 24.1 tok/s。Mac Studio 预填充慢了近三倍，但生成速度反超五成。他对 Mac Studio 的 TTFT 明显失望，可与前天的 [「DGX Spark TP=2 推理实测」]({{ '/daily/2026/09/30/daily/#dgx-spark-tp2-推理实测' | relative_url }}) 对照。

<span class="mention">@细心的熊猫</span> 还贴出 Qwen3.8 Flash-Next 在 Artificial Analysis 综合指数上拿到 40 分，逼近 Claude Opus 4.8 的 42 分：「好舒服，不敢想象 Qwen4 得有多顶。」以这个水准本地跑 agent，Mac Studio 的实用价值已经站住了。

### Manus 2.0 一句话出 MV

<span class="mention">@优雅的鲸鱼</span> 作为 Doctor Who 粉丝，用 Manus 2.0 Max 做了一条完整卡通 MV。提示词只有一句：做一个特别好玩的神秘博士卡通 MV，思考适合什么曲风，让大家听歌就知道博士的故事，可爱又好玩，只有博士们和真实的女伴们。之后追加了「歌曲用英文」和开头微调两条指令。Manus 自行选择音频和视频生成模型（Seedance 拒绝服务时自动切 MiniMax），耗时约 30 分钟，花费 6,000–6,500 积分。成片「没有任何抽卡和修改」直接出街，<span class="mention">@优雅的鲸鱼</span> 自述看完眼泪汪汪。

他同日还做了一条 7 分钟的奥德赛故事视频，成本类似。按 20 美元 = 4,000 积分换算，单片约 $30，他觉得远低于真人拍摄和制作的成本。<span class="mention">@洒脱的大象</span> 也试了视频，确认 Manus 在 Seedance 不可用时会自动切换 MiniMax。

这一系列实践延续了 [「一条 Prompt 到完整成片」]({{ '/daily/2026/09/24/daily/#一条-prompt-到完整成片' | relative_url }}) 以来 agent 调度多模态生成的趋势，区别在于 Manus 把模型选择也包办了。<span class="mention">@直率的穿山甲</span> 批评 Manus 重新上线的策略——至少该给流失用户一个月免费试用。<span class="mention">@神秘的麋鹿</span> 觉得单片 $30 还是偏贵。

### 「问问立正」上线

<span class="mention">@冷静的飞鼠</span> 发布了 [问问立正](https://ask.lizheng.ai/)，一个基于他全部公开文章、视频和《真本事》的 RAG 问答工具。输入任意问题，系统检索相关材料后生成带出处的回答，文章标日期，视频链到对应时间点。Founding Member 不限次，其他人每天 3 次。

两个技术亮点值得留意。一是防断章取义：他为最常被问的 8 类问题各做了判断卡，写明判断在什么条件下成立、不能推出什么。模型只能引用来源编号，链接由服务器补上，编不出假引用。二是延迟优化：换强模型后手机端会超时，原因是链路代理攒包，心跳包加到 16KB 并主动 flush 后解决。当前后端用 DeepSeek V4 Flash，一次回答约 8 秒。整套服务跑在 <span class="mention">@今天群内信息量极大</span> 的 Builder Space 上，运行内存仅 256MB，3,115 个片段的向量（3MB）直接放内存，不用向量数据库。

> <span class="mention">@冷静的飞鼠</span>：效果比我想象中好，还没啥我自己的调教

<span class="mention">@稳重的海豚</span> 说这就像一座思维宫殿。

### Seedance 视频插件与 DSH 插件市场

<span class="mention">@睿智的北极熊</span> 分享了 GitHub 上的 [seedance-video-generator](https://github.com/Malenia12/seedance-video-generator)，面向 Seedance 2.5（火山方舟 Ark）的本地视频生成套件，同时提供 DSH Agent 插件和独立 Web 工作台两种形态。Agent 版注册 tool-seedance 工具后，对 agent 说「用 Seedance 生成一个赛博朋克城市夜景短片」即可触发从创意到分镜到生成的完整工作流。他同时透露 DSH 官方正在筹备插件市场，称之为「AiOS 的雏形」。

### Decision Pacman 实测续

<span class="mention">@今天群内信息量极大</span> 昨晚实测了 JEV 玩吃豆人的表现，发现它「干不过 phi 4 mini（无微调，裸 LLM）」，而他蒸馏的 0.8B 小模型经常通关。今天他把完整方法论写成了[博客文章](https://grapeot.github.io/decision-pacman/?lang=zh)，详解搜索 oracle 标注 + 蒸馏微调 + 单次 prefill 决策的全流程，续接昨天的 [「Decision Pacman 开源」]({{ '/daily/2026/09/30/daily/#decision-pacman-开源' | relative_url }})。

### 个人 agent 产品力对比

昨天的 [「dot 定位之问」]({{ '/daily/2026/09/30/daily/#dot-定位之问' | relative_url }}) 继续发酵，焦点转向 Muse 为何领跑。

多位群友对 dots 的完成度评价一致不高：<span class="mention">@80-HD</span> 称它「可能算是最拉的」，<span class="mention">@活泼的树懒</span> 说发布会演示都挂了，<span class="mention">@活泼的斑马</span> 判断「cue 和 dots 明显是赶工」。相比之下 Muse 体验丝滑得多，Muse 优势的来源引发了争议。<span class="mention">@神秘的麋鹿</span> 猜测它拿到了 Manus 的技术，<span class="mention">@睿智的北极熊</span> 证实「收购前半截其实人员和技术已经过去了」；但 <span class="mention">@活泼的斑马</span> 不以为然——做这类产品不需要独家技术，「只是单纯的产品体验」。<span class="mention">@80-HD</span> 用一个例子反驳：「我现在很难说服老婆不用 Muse 用我给她搓的。」

Meta 的生态护城河是另一个焦点。<span class="mention">@活泼的斑马</span> 看好 WhatsApp、Facebook 关系链引入，<span class="mention">@80-HD</span> 类比：「就好像腾讯搞一个能接真正微信的。」他也指出 Muse 在国内几乎没用——「国内不用邮件这种东西」。<span class="mention">@活泼的树懒</span> 在美国 IP 下仍然被 Muse 挡在等待名单里，<span class="mention">@80-HD</span> 用 Facebook 账号直接登入。

<span class="mention">@热情的大象</span> 从虚拟化工程角度拆了成本：每个 agent VM 要跑浏览器甚至编译，「不用想，这玩意肯定是做了超售的，如果按照 VPS 这种资源配置，他们得亏死」。<span class="mention">@80-HD</span> 估算类似配置的 VM 月费至少 5–10 美元，推上已有人批量薅。

<span class="mention">@机智的水獭</span> 给出了跳出比较框架的观察：对本群用户来说这些产品没什么新 use case，因为大家已有 24 小时不关机的 Mac 和自建工具链。Muse 和 dot 的价值在于把这种能力带给更广泛的用户，而那个用户群「全世界撑死也就百万量级」。<span class="mention">@活泼的树懒</span> 预测年底各家产品力会趋同。<span class="mention">@80-HD</span> 在纽约地铁拍到了 Muse 的广告——Meta 的推广力度已经铺开。

## 方法论

### Opus 5.5 定位能力两战两胜

<span class="mention">@冷静的麋鹿</span> 分享了两个 Opus 5.5 胜过 Astra 的实战案例。第一个是在内网 Git 上构建知识库共享仓，Opus 5.5 一次性完成进度很好（虽然推进过程对用户的透明度不足），Astra Ultra 始终不理想。

第二个更有说服力：他带家人在福建旅游时，儿子发现挂在新加坡的 Web 应用无法访问。先让 Astra 排查，始终定位不到原因；换 Opus 5.5 后很快查明——域名在福建全省被屏蔽，国内其他地区和海外均正常。这种跨网络层面的诊断能力正是 Opus 在 incident triage 上的优势所在。<span class="mention">@80-HD</span> 也确认 Opus 5.5 处理 incident 更强，与 [「Opus 5.5 实战分工」]({{ '/daily/2026/09/28/daily/#opus-55-实战分工' | relative_url }}) 的经验一致。

### GPT-6.1 Sol Max 口碑滑坡

<span class="mention">@沉稳的兔子</span> 用了两天 GPT-6.1 Sol Max 后回退到 xhigh，核心问题是「善于外插，还经常插不对」。<span class="mention">@直率的鹦鹉</span> 也表示 Max 太慢无法使用，<span class="mention">@沉稳的鸵鸟</span> 反映频繁卡断。这一轮反馈与昨天 [「GPT-6.1 Sol 实战体感」]({{ '/daily/2026/09/30/daily/#gpt-61-sol-实战体感' | relative_url }}) 中的分化趋势吻合——6.1 Sol 在速度档位上给了选择，但 Max effort 的实际体验远未达到预期。
