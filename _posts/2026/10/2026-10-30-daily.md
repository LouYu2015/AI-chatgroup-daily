Claude 今天把 Max 20x 改名成 Ultra，开始取消已验证账号的五小时限制，周额度不变。实操里最有料的是一组百万段落检索实验：不建索引先跑出 92% 命中率，再逐项算速度、内存和准确率的账。群里也聊透了几个 agent 老毛病：skill 没读完就派活、API 没接对就跑榜，以及数字分身学到了观点，却没学会怎么说人话。

## 模型与产品

### Claude Max 20x 改名 Ultra，取消五小时限制，周额度不变

<span class="mention">@沉稳的仓鼠</span>、<span class="mention">@睿智的犀牛</span> 等群友贴出了 Claude 的公告和邮件：

| 原套餐 | 新名称 | 月价 |
|---|---|---:|
| Max 5x | Max | $100 |
| Max 20x | Ultra | $200 |

价格、功能、账单日期和周额度都保持原样。变化是 **Ultra 的五小时限制开始分批取消**：

- 已验证账号从今天起陆续移除限制，先覆盖大多数现有订阅者。
- 新账号在完成验证前保留临时限制。
- 验证自动进行，不需要手动操作，取消后会收到邮件。

邮件还解释了为什么要改名：原来的「20x」指五小时额度；2025 年 8 月加入的周额度是 Pro 的 10 倍。现在五小时限制要撤了，名字也一起换。

## Agent 工程与评测

### 百万段落检索：先跑出 92%，再决定要不要优化

<span class="mention">@冷静的麋鹿</span> 推荐了[《不够懂这个领域，怎么放心让 AI 去试？》回放](https://www.superlinear.academy/c/recording/ai-01)。里面用一百万条中文段落和一百条 query，现场搭了一个检索系统。

数据来自 Bing 真实搜索数据的多语种版本，带 query 与段落是否相关的标注。用 `text-embedding-3-small` 预先抽取一百万条 embedding，约需二十分钟。

第一版**不建索引，全部放内存逐条比对**。评测方式是前十条中只要出现相关段落，这道题就记为命中。未优化时在一台 Mac 上已经达到 **92% 命中率、72 毫秒单次检索**；换 GPU 和 float16 后，降到 12.8 毫秒。

后续截维实验的数字是：

| 向量维度 | 内存 | 检索耗时 | 前十命中率 |
|---|---:|---:|---:|
| 1536 | 6.7 GB | 12.5 毫秒 | 92% |
| 512 | 约 2.5 GB | 9.2 毫秒 | 89% |
| 128 | — | 7.9 毫秒 | 80% |

回放里按产品需求会选 512 维。16 到 64 维的准确率则掉得太多。

还试了一轮 query 扩写：在 128 维基线上，用 DeepSeek 给每条 query 扩写四条，连原句共五条一起检索，再用 RRF 融合排名。命中率从 **80% 到 83%**，一百题净增三题；五次 GPU 检索合计约 40 毫秒，生成改写平均每次请求还要约 1.8 秒。

### Skill 从「给标准」变成「给评测工具」

<span class="mention">@冷静的麋鹿</span> 看完回放，最有感触的是：知道评测重要，和真正把评测用起来，中间有不少摩擦。

他的区分是，一次性个人任务往往做完就结束了；但要把做法固化成可反复使用的 skill，就得能比较不同版本。他观察到 <span class="mention">@今天群内信息量极大</span> 的 skill 这半年也在变：以前主要给标准、给好案例，现在更多把评测工具一起交给 AI，让它能定量检查结果。

回放里的几套做法很具体：

1. **先把题集建起来。** 可以找开源数据集并检查商用许可，从 query log 按流量采样，或者由人和 LLM 出题、再标注。最费时间的是写 guideline，把「什么算相关」说清楚。
2. **先用十道题校准标注。** 自己标十道，再让 LLM 标同样十道；错八道就放弃这条路，错一道就查模型没理解，还是 guideline 没写清。
3. **另开 fresh context 做 review。** 给专门检查的 subagent 配 review SOP 和错题本，处理文件前后不一致的问题。
4. **评测时随时看仪表板。** <span class="mention">@冷静的麋鹿</span> 说，这次学到的办法看起来很简单，却特别实用。

他还觉得，长程任务和 agent 指挥 agent 都比以前顺畅了。现在无论在同一个体系里调另一个 agent，还是跨工具调用，收集评测题、让 agent 自己跑评测都方便了不少。

## 工具与交互

### 把 Office 文档变成操作手册：PowerShell COM 驱动 Excel

群里分享了一份[Excel 操作提示词](https://github.com/vczh/GacUIBlog/blob/main/Excel.prompt.md)：先查 Office VBA reference，确认对象关系、参数顺序、单位和枚举值，再翻译成 PowerShell COM 调用，让 agent 在 Windows 上操作桌面版 Excel，不往工作簿里写 VBA 宏。

它按 API 参考来组织，里面的工作规约比脚本片段更完整：

- 所有 `Range`、`Cells` 都限定到具体 workbook 和 worksheet，不依赖 `ActiveWorkbook`、`ActiveSheet`、选择区或剪贴板。
- 默认修改副本。要保存活动工作簿的当前状态，用 `SaveCopyAs`，不用文件系统拷贝。
- 字面数据和公式分开处理；标识符、前导零先设文本格式。
- 保存后重新打开，分别校验公式和值。
- 改过的 Application 设置要恢复，只关闭自己拥有的工作簿，不靠杀进程收尾。

坑位也列得很细：`UsedRange` 不能直接当数据行数；`Value2` 读出的日期是序列号，还要看 `Date1904`；`Range.Find` 会记住上次选项；`RefreshAll` 的 Power Query 失败可能静默留下旧数据；`DisplayAlerts=false` 会让 `SaveAs` 静默覆盖文件。

文档里的 17 个 PowerShell 代码块做过 Windows PowerShell 5.1 和 PowerShell 7.6.9 语法检查，「复制—改单元格—保存—重开校验」完整示例在 Excel 16.0 的两个 shell 中实际跑过。

展示任务是生成一份 2026 年 10 月日历，要求用图片和视觉设计表达对欧姆弥赛亚的忠诚，不靠文字说明。

### 1.46 万条发言做数字分身：观点和口吻分开存

<span class="mention">@80-HD</span> 用 <span class="mention">@活泼的羊驼</span> 的 MCP 读取文字记录，给 <span class="mention">@蓝色大肥虞</span> 做了一个数字分身。归档里约有 **1.46 万条发言**；他自己说，整个过程只是嘴炮了几句。

站点把资料拆成两层，共九页：

- **观点层**：论点、适用条件、判断依据。
- **表达层**：群聊节奏、标点、口癖和表达动作。

生成时先用观点层确定说什么，再让风格层**只改回答的第一句话**；后面的具体分析用正常口吻展开。风格层不能新增立场、案例或确定性，也不能删掉原来的条件。网页读不到时，还有 `llms-full.txt` 纯文本版本。

<span class="mention">@80-HD</span> 对第一版不太满意，觉得说话太官方。<span class="mention">@细心的熊猫</span> 推荐用「女娲 skill」蒸馏指定人物的风格，他准备再补这一层。<span class="mention">@蓝色大肥虞</span> 看完站点后回了一句「太强了」。

### Subvocal：不出声地动嘴，宣称每分钟输入 200 多词

<span class="mention">@80-HD</span> 分享了 [Subvocal 的发布帖](https://x.com/aarushyadav47/status/2116198463847408066?a=QmYC9teboW1B3Vwimac&s=46)，问这东西靠不靠谱，同时嫌 demo 里的眼镜太丑。

项目宣布从 YC 和 Afore Capital 融资 **130 万美元**。它宣称通过非接触传感追踪发音相关肌肉，把无声、几乎看不出的嘴部动作解码成文字，速度超过 **200 words/min**，已经开放预订。
