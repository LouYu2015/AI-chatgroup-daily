## Jacobian 猜想证伪

### Fable 证伪 Jacobian 猜想：数学四大级别

深夜 <span class="mention">@聪明的鸳鸯</span> 带来大新闻：Jacobian Conjecture 被 Fable 证伪了。<span class="mention">@坚定的貂</span> 确认并给外行标定分量：这问题如果由人类解决，够发数学四大——张益唐学生时代做的就是它。<span class="mention">@聪明的鸳鸯</span> 补上那段公案：张当年的论文引用了一个定理来证明 Jacobian 猜想，答辩时才发现那个定理本身是错的，从此蹉跎多年。<span class="mention">@沉稳的仓鼠</span> 的观察是「现在看来 twitter = 四大」——顶级成果的首发阵地已经换了。

<span class="mention">@坦荡的灰熊</span> 问这是不是低垂的果实被摘完的意思，<span class="mention">@坚定的貂</span> 的回答是：证伪当然没有证出来舒服，但这些对人类来说也不是真的低垂的果实。他对当下的判词足够冷峻：

> <span class="mention">@坚定的貂</span>：AI在解题上已经完全碾压数学家了

> <span class="mention">@坚定的貂</span>：我们还在最后的狂欢中……我们正在快速解决一堆问题，每天写文章中

### 为什么是现在：从 Danus 手搓到动态 workflow

接昨天 [「数学家的 agent 工作流：单 prompt 跑几十小时」]({{ '/daily/2026/07/18/daily/#数学家的-agent-工作流单-prompt-跑几十小时' | relative_url }})，<span class="mention">@坚定的貂</span> 今天揭了底：他这套只是在此前 cycle double cover 的 prompt 上加了点自己跑出来的经验，已有 positive feedback——至少两个问题被解决。为什么最近才搞出来？完全是因为 GPT-5.6 Sol Ultra 有了很强的 dynamic workflow 构建能力，此前只能手搓固定工作流，比如 [Danus](https://github.com/frenzymath/Danus)：主 agent 跑 Claude Code 做全局规划、一群 Codex worker 并行搜证明、冷启动验证器做正确性唯一裁决，任何结论过验证才进内容寻址的事实图——一次真实运行积累了 3157 条已验证事实、8616 条依赖边、最深依赖链 54 层，而最终定理的支撑闭包只用了 664 条。

<span class="mention">@今天群内信息量极大</span> 自称还在研读 <span class="mention">@坚定的貂</span> 的文章，并连夜发了自己的解读《没有自动测试，数学家怎么审 AI 的证明》：软件工程有 compiler 和 tests 这种便宜可重复的反馈，数学证明没有——AI 几分钟能生成二十页证明尝试，人类专家却要几天核验；<span class="mention">@坚定的貂</span> 解决的不是数学版 deterministic test，而是另一个问题：没有完美裁判时，一份 AI 证明要经过什么检查，才能让后面的 agent 拿来继续推导。

### Lean 填坑：纯堆人力的最后短板

<span class="mention">@搞仁义毛义仁</span> 追问 Lean 和表达任意数学证明之间的差距有多大。<span class="mention">@坚定的貂</span> 的答案：差距在太多定义不在标准库 mathlib 里，定义全在的话证明 transfer 会容易很多；搬运是苦力活，AI 能帮忙，但审核仍靠维护 mathlib 的数学家。<span class="mention">@搞仁义毛义仁</span> 总结「看来就差海量一次性劳动了」——「希尔伯特的遗愿」。次日凌晨 <span class="mention">@坚定的貂</span> 给 <span class="mention">@神秘的企鹅</span> 补齐了完整逻辑：

> <span class="mention">@坚定的貂</span>：数学有一大群人认为AI+形式化数学是未来。因为AI产出内容太多，验证成为最大问题……现在AI发展的好得很，但形式化数学是短板。但只要把坑填了这个短板就永远不在了。而且是纯粹堆人力就能填的东西。

他观察到国内正在填坑：Lean 暑期班扎堆冒出来，[上海交大 AI4Math 暑期学校](https://mp.weixin.qq.com/s?__biz=MzU3MDk0NzEyNA==&mid=2247496841&idx=1&sn=8e1a2876ec2417b295fb2ff43cfe2054&chksm=fd2b9f2d730a3ee46ac664b975e94474a76ea18b381b74b74b436a8d4114302c852dc8b661f9#rd) 已是上海今夏第三个，复旦同济也有，目的就是多弄点人把这个一次性坑填完；填完之后 formal math 有可能直接赶超 natural math，届时每篇数学文章都会有对应的 Lean 版本。他还顺手贡献了一个 startup idea：招一堆数学学生天天 formalize 教科书，把数据卖给 Axiom——<span class="mention">@沉稳的仓鼠</span> 献策「研究生更便宜不」，并点评这种花钱就能干出来的事「适合社会主义来干一下」。

### HF 全自主入侵事件：防守方被自家护栏锁死

<span class="mention">@温暖的树懒</span> 转发 [Brian Roemmele 的推文](https://x.com/brianroemmele/status/2078840929088340408?s=12)：Hugging Face 披露了一场完全无人在环的 AI agent 入侵——起点是投放到平台的恶意数据集，在自动化数据流水线里串联两个代码执行漏洞，随后自动提权、窃取云与集群凭证、跨集群横向移动，一个周末干了 17000 多次操作。最讽刺的在事后：安全团队想用 Anthropic 和 OpenAI 的商用接口分析真实攻击日志、漏洞载荷和 C2 流量，全被安全护栏当潜在滥用拦截——模型分不清取证人员和攻击者，最终只能退回自托管的开源 GLM 5.2 完成分析。

推文点破的结构性不对称值得记住：攻击方的 agent 框架本就无限制，可以起成批沙箱、自动迁移 C2、自主执行数千步；防守方却在风险最高、最需要把敏感数据喂给模型的那一刻被 API 挡在门外。结论是在攻防双双 agent 化的时代，对智能技术栈的主权不再是可选项——开源赢在这里不是因为便宜，而是因为自托管是唯一可行的出路。<span class="mention">@稳重的海豚</span> 送上一个赞。

## 工具

### codex-worker-dispatcher：可审计的子任务分发

<span class="mention">@开朗的企鹅</span> 分享了 [codex-worker-dispatcher](https://github.com/holdonyb/codex-worker-dispatcher)：面向 Codex CLI 的公开 skill 加跨平台运行时（v0.1.1），让父 agent 把复杂工作拆成边界清晰的子任务，交给独立的 Codex worker 进程执行。设计上颇为讲究：每个任务可单独指定模型、推理强度、沙箱模式和写文件权限；写任务必须显式声明允许路径，每条路径构成一份可审计的授权契约，危险的全通模式直接被禁；回收停滞任务默认干跑、要加 --apply 才真正终止进程树，父 agent 必须持有任务 ID 直到终态。pipx 装完一条命令装进 skills 目录即用，作者自承还是面向本地有界任务的 alpha 版。

### Talk Sock：麦克风隔音罩，公共场合恣意 vibe

<span class="mention">@今天群内信息量极大</span> 发现了一个物理外挂：[Stenomask 速记麦克风](https://talktech.com/pages/stenomask-privacy-microphones)配 [Talk Sock 降噪套](https://talktech.com/products/talk-sock)——贴合口部的面罩式麦克风加隔音罩，话音只进麦克风不外泄、环境噪音也录不进来，兼容主流语音识别引擎，嫌一层不够还能套两层。他的推荐语是「给你的麦克风装个隔音罩，公共场合也能恣意vibe」——前天 [「语音 dump 的乱序之痛与 quiz 复述」]({{ '/daily/2026/07/18/daily/#语音-dump-的乱序之痛与-quiz-复述' | relative_url }}) 里语音党的社死问题，至少有硬件方案了。

## 方法论

### 群鸭架构：memory 落到 expert doc

<span class="mention">@稳重的海豚</span> 抛出一个真问题：他的 agent 已经覆盖个人思考、理财决策、学习总结、健康管理、公司管理、软件开发、日程七八摊事，老鸭汤体系下这些任务之间的 memory 怎么 route、怎么整理。<span class="mention">@敏锐的海狸</span> 的答案是 routing.md 加 index_tool.md，背后撑着 100 多个 design doc：每个都是带 skill 和 code 的专家 doc，自动蒸馏加 harness 各管一摊，大项目用前缀组织——他晒出的目录从 ingestion、knowledge_graph 一路排到 material、operation，每个 folder 再配 readme。

Memory 的落点是关键：他在 always-on memory 里写死一条规则——新记忆直接落到具体 expert 或项目的 design doc，不存 cc 自己的 memory；老鸭汤不放任何项目细节，只管整个管理哲学。<span class="mention">@稳重的海豚</span> 由此修正了心智模型：不是整个系统一锅老鸭汤，而是每个长程 agent 自带一锅，「所以是群鸭」，鸭群搞起。

### Transformer 吃掉一切

<span class="mention">@淡定的大象</span> 的科普系列今天更新[《同一个 Transformer，吃掉一切：为什么语音、图像、自动驾驶、大模型都在用它》](https://mp.weixin.qq.com/s?__biz=MzY4NTM1MDc1NQ==&mid=2247485760&idx=1&sn=c8954afb7de9cf10b229d36e9d0d53e7&chksm=f2944504180ad04bb889a42c3a577670258f95516663ce833088b35a600fc76ffc77f0a3323b#rd)：取胜三要素是最小归纳偏置、一切皆可 tokenize、与 GPU 硬件高度匹配；从 ViT、DiT、Whisper 到 FSD v12 删掉 30 万行 C++、RT-2 把机器人动作变成 next token prediction，各领域 SOTA 中间 90% 的参数与代码完全一致，Flash Attention 一处优化全领域受益。结论克制：Transformer 不是唯一架构，而是所有架构里都不能缺少的基础构件。
