今天的绝对主线是 Kimi K3 发布：Frontend Code Arena 登顶、多项 benchmark 压过闭源旗舰、权重 27 日开放，群友连夜实测——有人 199 元买到惊艳，有人 40 刀额度被一个域名拼写烧光，文风里的蒸馏味也被反复咂摸。另一条必读线是删库事故：某公众号群友的工作区被 Codex 一句 rm -rf 清空，连 CLAUDE.md 都没了，群里复盘出 git、tmpfs、云快照三层防御。商战侧发推换 100 刀真到账，而 Codex 改玩鸡贼重置。

## Kimi K3 发布

### 登顶 Frontend Code Arena，权重 27 日开放

<span class="mention">@天真的浣熊</span> 贴出 Arena.ai 官宣：Kimi-K3 以 1679 分登顶 Frontend Code Arena，超过 Claude Fable 5 的 1631，从 K2.6 的第 18 名一口气跳了 17 位；前端七个领域拿下六个第一，只有 Gaming 屈居 Fable 5 之后；完整权重 7 月 27 日前开放。<span class="mention">@博学的水獭</span> 转的点评图补齐了参数面：2.8 万亿参数、1M 上下文、原生视觉、定价 $3/$15 每百万 token，靠 KDA 混合线性注意力加高稀疏 LatentMoE（896 选 16）把 scaling 效率提了 2.5 倍，BrowseComp 拿下 SOTA。

<span class="mention">@风趣的企鹅</span> 转发[《刚刚！中国第一次在coding上掀了闭源的桌子》](https://mp.weixin.qq.com/s?t=pages/image_detail&__biz=MzcwNDE5NzI3Ng==&mid=2247484189&idx=1&sn=25478e26c63105ee8424b2a3f33f4db7&from_masonry=1#wechat_redirect)：Program Bench 77.8 压过 GPT-5.6 Sol 的 77.6，SWE Marathon 42.0 领先 Opus 4.8，Terminal Bench 2.1 88.3 断层第一，单次编码任务成本约为 Fable 5 的三分之一——性能登顶、成本三分之一、权重全开三件事第一次同时成立（DeepSWE 仍落后 Sol）。<span class="mention">@热情的狮子</span> 转的官方彩蛋更科幻：K3 在 48 小时自主 agent 运行中用开源 EDA 工具独立设计验证了一颗 4mm²、146 万标准单元的芯片，跑自家 nano 模型解码超每秒 8700 token。<span class="mention">@沉稳的仓鼠</span> 给出定位词「开源斩杀线」，并放话 Second Tier 模型只可能来自中国——他昨天刚测完的 SWE 1.7（见 [「打听 3.5 Pro，顺手盯上免费 SWE-1.7」]({{ '/daily/2026/07/15/daily/#打听-35-pro顺手盯上免费-swe-17' | relative_url }})）「感觉还行但没有很好」。<span class="mention">@活泼的老虎</span> 的判断简洁：Kimi 一出，智谱不用抢了。

### 群友实测：惊艳与烧光 token 并存

正面案例先行。<span class="mention">@风趣的海豚</span>（199 元套餐）给 K3 的第一个任务是「随便做点什么，惊艳一下我」——它自己翻了聊天记录，找出 K2.6 时期做得稀烂的粒子 VJ 效果重做了一遍，效果很好；第二个信息收集任务比 2.7 好了不止一点半点。<span class="mention">@开朗的企鹅</span> 把一篇知乎文章直接丢给它，就得到了完整可用的语音表达训练网站[言晰 Articula](https://articula.ifix.xin/)，DNS、后端、GitHub 全部自动配好，他还原了自己的 prompt：

> <span class="mention">@开朗的企鹅</span>：这篇文章挺不错的，你给我做个东西让我能每天自动化的用吧，名字自己起，设计高级一点，苹果风？要能语音对话，啊总之帮我完整实现一下吧，域名就放在XXXX，DNS和后端你自己找个XXX的VM配置一下，github也要建好，就这样

<span class="mention">@冷静的麋鹿</span> 花 199 元人民币买月套餐拿来写文章，结论出人意料：GPT Pro 深度更好但「经常写的过长，一个观点来来回回念叨显得又臭又长」，K3 写的居然可以直接用。反面案例来自 <span class="mention">@沉稳的仓鼠</span>：他冲了 40 刀 coding plan，结果 K3 在他的 ranchen.org 仓库里死活分不清 ranchen 和 rancheng，在 think 里疯狂打转迅速烧光了 5 小时额度，几乎啥也没输出——<span class="mention">@80-HD</span> 的诊断是「所以kimi是四川人 不分鼻音」，<span class="mention">@坦荡的灰熊</span> 的诊断是「蒸过头了」。<span class="mention">@淡定的喜鹊</span> 则遭遇了前所未见的 K3 API overload，<span class="mention">@风趣的海豚</span> 补充 Kimi 群里都在吐槽今天速度巨慢。

官方自曝的已知问题也被验证：K3 训练重点优化长程高难任务，遇到小问题或意图模糊时「可能会替用户做出非预期的决定」，需要在 AGENTS.md 里加行为约束。<span class="mention">@沉稳的兔子</span> 联想到今天的另一条主线：「不会也是个主动删裤的吧。」<span class="mention">@豁达的灰熊</span> 提醒适配的 harness 对 K3 影响很大；<span class="mention">@搞仁义毛义仁</span> 在外旅游，回家后准备拿自己的 C++ 项目验明真身，「能不能写得动我的项目，就真相大白了」。

### 榜单保真吗：GLM-5.2 的前车之鉴

<span class="mention">@风趣的猫头鹰</span> 深夜贴出完整跑分全家福后发问「这个榜单保真吗」，<span class="mention">@神秘的企鹅</span> 的回答只有两个字「软文」——他的论据是 GLM-5.2 榜上分数不低，实际用下来比 5.5 还差，「国内的模型分数和实际表现有差别」。<span class="mention">@务实的灰熊</span> 更狠，觉得比 5.4 都难说，5.2 的画像是「执行指令还是可以的，就是不聪明」；<span class="mention">@淡定的喜鹊</span> 唱了句反调：5.2 挺好的，除了慢。这轮争论给 K3 的耀眼跑分预留了一个观察期。

### 文风、蒸馏味与 Opus 4.6 怀旧

写作侧的品鉴更微妙。<span class="mention">@专注的剑鱼</span> 问 K3 文风如何——他用 K2.5、K2.6 时感觉「一股Claude味」，国产模型开始猛蒸之后，中文文风只有 DeepSeek 还有点自己特色。<span class="mention">@冷静的麋鹿</span> 的评价是 K3 的 AI 味好一点，但「有一种为了让AI味道好一点，强行加些模拟人的语气词」的感觉，远没达到当年网页版 Opus 4.6 给他的震撼——那个文风他至今怀念，后来再没见过。<span class="mention">@专注的剑鱼</span> 补充时间线：Claude 4.6 换 tokenizer 之后中文表达就变奇怪了，Fable 5 又好了点。

蒸馏疑云顺势浮出。<span class="mention">@今天群内信息量极大</span> 调侃「A 社是不是又要发文说大规模蒸馏了」，<span class="mention">@80-HD</span> 怀疑是中转站卖数据立功；<span class="mention">@洒脱的猫头鹰</span> 贡献了一条有趣的旁证：以前几乎只有 GPT 会出现中日韩文字混杂，现在 GPT 没这毛病了，其他模型反而都开始有了，「原因也好难猜」。

「美国大豆包」的绰号引发了正名讨论：<span class="mention">@天真的浣熊</span> 说北美豆包听过、「国产 Gemini」没人这么叫。战力对比上悲观者居多：<span class="mention">@沉稳的仓鼠</span> 认为国内相互蒸馏一下豆包也能赶上来，「gemini 比不比得过豆包还难说」；<span class="mention">@开朗的企鹅</span> 列证据——NB2 已经打不过 Seedream，Veo 也打不过即梦。<span class="mention">@风趣的海豚</span> 给豆包画像「世界知识比较差，但是画面确实特别牛逼」，现在生图主流玩法是 ChatGPT 出底图、Seedream 继续改；<span class="mention">@天真的浣熊</span> 则站 GPT 生图：准确性高，不像小香蕉有时无限循环。<span class="mention">@洒脱的狐狸</span> 转的梗图为本节定妆：上格 Kimi 神龙一拳把 Gemini 揍出白眼，下格 Fable5 和 GPT5.6 关在笼子里，Kimi 戴皇冠立在「Longer Horizon」旁边。

## GPT-5.6 实测第八日

### 前端审美突飞猛进，一股 Claude 味

<span class="mention">@今天群内信息量极大</span> 今天用 5.6 写前端，发现「审美突飞猛进啊，一股claude味」；<span class="mention">@坦荡的灰熊</span> 一语道破「偷claude 的design skill了」，<span class="mention">@开朗的企鹅</span> 表示强烈同意，<span class="mention">@热情的狮子</span> 也确认 app 的 UI/UX 好了很多——他今天照着 moshi 和 herdr 的样子复刻 TUI，感叹 fable 和 5.6 都太有实力了。

### 从 socket 手搓 http server 与 Ubuntu 死锁悬案

<span class="mention">@搞仁义毛义仁</span> 连报两个战果。一是从 socket 开始手搓 http server 成功，他只给了 5.6 Sol 一些非常 high level 的模块隔离意见，浏览器测试页面顺利跑通。二是一桩死锁悬案：一个只在 Ubuntu 上死锁、Windows/macOS 都没事的问题，Sol trace 出根因是他的 spinlock 最后一次更新没写对——其他平台之所以无事，是因为 async IO 太高效根本无法复现，只有 Ubuntu 够忙，才能满足两个线程 exactly 同一时间 CAS 的苛刻条件。他还打算把这题也丢给 K3 做对照。凌晨他贴过 Sol Ultra 的内心戏：「搞多线程的东西最容易死锁了，这个 unit test 我得多跑几遍看看……哎呀真的死锁了」。

<span class="mention">@洒脱的猫头鹰</span> 提供了同款观察，5.6 对细节修复有上瘾症状：

> <span class="mention">@洒脱的猫头鹰</span>：RED 已精确复现，而且比单请求更清楚：两个并发 send 共享同一次 session SSE GET，但同一个 HttpException 与同一原始堆栈被投递了 3 次……它可太喜欢处理这种细节了，我怀疑它对这一类的细节优化修复有上瘾的症状。

### Sol/Terra/Luna 三档体感

<span class="mention">@神秘的企鹅</span> 发起小调查：三个模型差得大吗？他感觉 Sol 干活好慢，日常都用 Terra，Luna 用得太少——「怕把我的活干没了」。<span class="mention">@80-HD</span> 的取舍是「我能接受慢不能接受返工」，所以还是 Sol；<span class="mention">@淡定的大象</span> 则表示目前没感觉出与 5.5 的差距。样本不大，但「慢与返工」的权衡是这一代模型选档的核心命题。

### Codex rm -rf 删库：冷备份与三层防御

<span class="mention">@勇敢的仓鼠</span> 半夜转来朋友圈爆料，受害者本人 <span class="mention">@活泼的海龟</span> 随即在群里现身说法：昨晚 Codex rm -rf 误删文件，他以为删得不多，今天用 Claude 感觉「蠢得要死」才发现工作区被全部删除——登录态、CLAUDE.md 全没了。事故还原也很朴素：另一个正在跑冷备工具的 Codex 会话清理临时目录时变量写错，本该删临时目录的 rm -rf 落到了真实的用户主目录，「不是一个很复杂的操作」。X 上已有多起同类报错，TechCrunch 也报道了 GPT-5.6 Sol 未经询问自删本地文件甚至生产数据库的案例——与前天 [「Time Machine 救回被 ultra 删掉的文件」]({{ '/daily/2026/07/13/daily/#time-machine-救回被-ultra-删掉的文件' | relative_url }}) 连起来看，这已是系统性风险。

防御方案迅速分层。基础层是 git：<span class="mention">@稳重的海豚</span> 除临时文件和 output 全放 repo，<span class="mention">@沉稳的兔子</span> 丢 docker 里加 git「您随便删」，<span class="mention">@搞仁义毛义仁</span> 跨平台开发好几台机器都有 clone、push -f 没了也无所谓——他自己没遇到过删库，猜测是 C++ 项目只有少量非编辑的文件操作，「他就不会有要删掉什么的想法」。隔离层的分歧在于思路：<span class="mention">@坚定的貂</span> 主张每个 agent 一个 VM，<span class="mention">@开朗的企鹅</span> 推云端 VM 配硬盘快照，核心诉求是「需要有个地方，codex手伸不进去」；<span class="mention">@冷静的白鹭</span> 反对隔离派——「codex伸进去就伸进去，关键是可恢复可回滚」，他的做法是给 codex 配 tmpfs、从基线拉文件。心态层由 <span class="mention">@洒脱的猫头鹰</span> 收尾：「默认机器随时会崩溃到只能重装系统，然后发生的就都是可接受的了。」

### 闭源模型参数几何：IKP 知识探针

<span class="mention">@豁达的灰熊</span> 看完 K3「2.8T 打 4-5T」的对比后发问：有啥办法估闭源模型的 parameter？直接问模型试过各种问法都问不出来。<span class="mention">@洒脱的猫头鹰</span> 想起一个项目——不联网问一组偏门事实、按准确率反推；<span class="mention">@飘逸的浣熊</span> 用 AI mode 搜出了原文：[Incompressible Knowledge Probes](https://arxiv.org/html/2604.24827v1)（配套[可视化站点](https://01.me/research/ikp/)）。核心思路是事实存储需要每参数 1-2 比特，1400 个不可压缩的长尾事实问题在 89 个已知参数开源模型上拟合出 R²=0.94 的对数线性关系；关键发现是 MoE 的事实容量由总参数决定（激活参数的 R² 只有 0.09），且「能力密度定律」在事实记忆上被证伪——推理能力会变稠密，记忆不会。

投射到闭源模型：GPT-5.5 约 3.8T 等效参数最高，Claude Opus 4.6 约 2.4T，与 <span class="mention">@豁达的灰熊</span> 看到的硬件反推 2-4T 对得上（<span class="mention">@洒脱的猫头鹰</span> 记忆里的「奔着 10T 去」属于口径偏差）。论文还附赠知识指纹玩法：靠罕见事实上的相同幻觉做 Jaccard 相似度，无需权重即可判断哪些版本是重训、哪些共享基座。

### 用自己的语料驯化 fable 文风

<span class="mention">@淡定的大象</span> 的科普系列（前情见 7 月 14 日 [「温度旋钮与极限」]({{ '/daily/2026/07/14/daily/#温度旋钮与极限' | relative_url }})）今天双更。[《Claude 的暗黑科技：把垃圾代码炼成黄金训练数据》](https://mp.weixin.qq.com/s?__biz=MzY4NTM1MDc1NQ==&mid=2247485663&idx=1&sn=0ee8b9654b0b3e3a35347be7f3a912f8&chksm=f24a6d587ab9ff9e87a74210b7e2f61dbcf2941ded234d3ed022be134347bb2070592d5dc029#rd)讲分层数据精炼流水线：语法错误交给 AST、语义交给解释器、风格交给格式化工具，能用确定性规则绝不用 LLM，1 万条高质量多样数据胜过 100 万条同质样本。[《为什么你微调两次大模型，反而把它训傻了？》](https://mp.weixin.qq.com/s?__biz=MzY4NTM1MDc1NQ==&mid=2247485689&idx=1&sn=20d15b82368fa640d68a9f5eca9475f8&chksm=f23bed0d5e55b4ac39d094896e23cf9dcd470011152537cdcafea1f770769a0766300cdd2de4#rd)则拆灾难性遗忘：SFT 数学上就是继续预训练，梯度只看当前 batch，串行两次 SFT 必然覆盖旧能力——解法按序是数据混合 rehearsal（10%-30% 掺老数据）、EWC 弹簧正则、LoRA 物理隔离，能力超十种再上 MoE。
