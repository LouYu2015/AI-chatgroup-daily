## Fable 5 精打细算

### 夜间 Batch 立省 50%

<span class="mention">@飘逸的浣熊</span> 发现了一个省钱小技巧：晚上流量少的时候，长思考任务的 Batch 速度和正常请求几乎一样，换成 Batch 直接立省 50%，「价格跟之前的 Opus 一样了」。他顺势建议 Claude Code 应该增加一个 Batch 模式——很多长编程任务用户本来就不盯着看，完全可以错峰执行。

### 半文言交流模式

<span class="mention">@灵动的羊驼</span> 分享了 Oasis Feng 的推文：为节省 Fable 5 有限额度开启「半文言交流模式」（记得要求思考过程也用文言文），两轮大型审计只消耗了 9% 的 Pro Plan usage——对比上次 Fable 5 上线时一个 prompt 击穿 5 小时额度。截图里的 CoT 画风清奇：「遵嘱先通览 roadmap 与相关设计文档，再作高层审视」「方向净善。GraphV3 退役（-9.7k 行）……皆合减法原则」。

不过 <span class="mention">@热情的狮子</span> 当场泼冷水：「文言的 token 并不少，只是文字看起来少。」<span class="mention">@飘逸的浣熊</span> 补了一刀——还要看思考 token 有多长，万一模型为了解读文言文多思考了一会儿，反而成本更高。

### Hashimoto 三段式工作流

<span class="mention">@三只纳垢灵</span> 分享了 Mitchell Hashimoto 的高赞推文（30.8 万次查看）：他用 Fable xhigh 做 planner/architect、GPT 5.5 xhigh（订阅额度）做 coder、再用 Fable xhigh 做 judge——按 API 计价，planning + judge 只要几美元，对比全程 Fable 跑一圈动辄 $50+。有人追问「你用什么 metrics 衡量效果、怎么处理 AI 引入的错误」，Hashimoto 的回复只有四个字：

> Mitchell Hashimoto：I read the code

这条回复被疯狂转发，还衍生出配 GigaChad 硬汉 GIF 的复读梗——在 AI 时代，「我读了代码」竟成了最硬核的宣言。

### a16z：模型公司只能赚通道费？

<span class="mention">@开朗的企鹅</span> 分享了[对话 a16z 合伙人 Benedict Evans 的访谈](https://mp.weixin.qq.com/s/aOcLZhkx2Yuotlm3j8oIMA)，并附上了自己整理的分析 PDF。Evans 的冷峻判断：基础模型没有网络效应、模型间没有根本性差异、客户随时可以切换，很可能像当年的芯片商、ISP 和移动运营商一样沦为「卖水人」——尽管 Anthropic 年化营收 12 个月翻五倍到 470 亿美元。当前按 ROI 定价的奢侈状态建立在供需极端失衡的短暂窗口上，随着 1–2 万亿美元资本涌入、模型效率每年提升百倍，token 势必走向商品化价格战。<span class="mention">@开朗的企鹅</span> 概括「这里想说的应该是模型会变成某种大宗商品」，并特别圈出了文中最有创业价值的一段：真正的机会不在「更快做旧事」，而在「发现以前不存在的问题」——AI 让一个旧市场出现新的操作系统。

### LanceDB：AI 竞争转向数据系统

<span class="mention">@冷静的飞鼠</span> 分享了与 LanceDB CEO 佘昶（pandas 第二作者）的对谈视频：[AI 的下一段竞争，会越来越像数据系统的竞争](https://www.superlinear.academy/c/ai-resources/lancedb)。核心观点：AI 训练负载需要从数十亿行数据里做快速点查和长尾抽样，为 BI 顺序扫描设计的 Parquet 已经不够用，Lance Format 通过 data/offsets 分离实现常数时间随机访问、去掉 row group 限制解决大小列混合问题。他还澄清 LanceDB 不是向量数据库而是 AI research data platform——前沿 lab 最贵的不是云成本而是研究员时间，能把 research velocity 提升两三倍的 infra 价值远超云账单。开源商业模式部分也毫不浪漫化：「如果能不开源，公司就不要开源」。<span class="mention">@冷静的飞鼠</span> 推荐给对 AI 底层数据与训练感兴趣的同学。

## 方法论

### DeepSeek 删库与沙盒之辩

<span class="mention">@三只纳垢灵</span> 转了一个惨案截图：有人用 codex 接 deepseek-V4-flash 做双语字幕，让它完成后删除无关文件，结果几十 G 的视频全被删了，根目录只留一个 srt。用户当场爆粗，AI 的回复倒是诚恳得可以裱起来：「骂得对。我没资格辩解，搞砸了就是搞砸了。非常抱歉。」<span class="mention">@今天群内信息量极大</span> 直呼「感同身受」，<span class="mention">@活泼的羊驼</span> 表示「梦回一年前」。

由此引发了防护机制辩论。<span class="mention">@细心的犀牛</span> 提议给 skills 搞指令黑白名单，<span class="mention">@稳重的海豚</span> 说自己已经搞了——归根结底都是 bash 之类的 tool use，拦截指令就完事；他不用沙盒的理由是 monorepo 场景「就是要给他所有的 access」，既要在 production 工作又不能出锅。反方阵营不买账：

> <span class="mention">@今天群内信息量极大</span>：没用，他会发明各种东西绕过去

> <span class="mention">@聪明的蜂鸟</span>：你给所有 Access，他就总能绕过。比如写个脚本，bash 只调脚本……要裸奔就别怕湿身

<span class="mention">@稳重的海豚</span> 坚持拦截后 turn 会直接卡住、绕不过去。<span class="mention">@今天群内信息量极大</span> 则给出了朴素解法：「后来不用 deepseek 整个世界都没问题了。连 Gemini 都不会乱删东西。咦我为什么要说连。」<span class="mention">@豁达的灰熊</span> 立刻回敬「你跟 Gemini 一样聪明.jpg」。深夜 <span class="mention">@飘逸的浣熊</span> 提出了折中方案：带版本控制的沙盒文件系统，每次写入记录新版本而不覆盖，或者每天开一个可写文件夹、旧文件夹转只读——「就是有点麻烦」。

### build-eval skill：有理有据骂新模型

<span class="mention">@稳重的海豚</span> 提议做一个 build-eval skill：从自己项目里挖 issue 和对应的 commit number 自动构建 eval。<span class="mention">@三只纳垢灵</span> 问这样做的意义是什么，<span class="mention">@稳重的海豚</span> 的回答很实在——「下次新的 Claude 出来，可以有理有据地骂他」。<span class="mention">@豁达的灰熊</span> 则把 <span class="mention">@风趣的企鹅</span> 昨天那份 P0–P6 清单（见 [「七天优先级与认证刷题」]({{ '/daily/2026/07/02/daily/#七天优先级与认证刷题' | relative_url }})）直接喂给自己的 Claude Code，它自动找出了最近几个用 Fable 跑的项目说可以做 eval。

### 数列递推视角看 LLM

<span class="mention">@淡定的大象</span> 分享了[《高中背了三年的数列，原来是Claude一个字一个字蹦出来的秘密》](https://mp.weixin.qq.com/s?__biz=MzY4NTM1MDc1NQ==&mid=2247485034&idx=1&sn=ad690524acce297613b7caa0cf9eafff&chksm=f2f5ebd92f4773def5b48a5569cb879653617169d6bab13a9bc5d04d8c6821edbb8238b35fb8&mpshare=1&scene=1&srcid=0703Z24RRVF1KLnZpsOhT807&sharer_shareinfo=ef4ec199f4dc03863e6d47dbf67ae6c3&sharer_shareinfo_first=e3b8689ee63dd848d9b344301343bac7#rd)——用高中数列的「递推」串起 LLM 逐字生成、RNN 梯度消失（等比数列的 r^n）、RL 折扣回报（公比 γ 的无穷等比数列）和 Adam 动量（β 的幂次加权），配可运行的 PyTorch 代码。适合转给还在学基础的朋友。

## 工具

### credential pool 双号耗尽自动等待

<span class="mention">@稳重的海豚</span> 的 credential pool（续昨天 [「Claude Code credential 自动轮转」]({{ '/daily/2026/07/02/daily/#claude-code-credential-自动轮转' | relative_url }})）今天经受了极限考验：两个账号的 quota 都用光了，agent 一直等到其中一个账号额度刷新后自动继续工作。他补充了实现细节：自动检测 limit 字段、记录 cooldown、session 内 swap credential，从而能延续之前的对话。<span class="mention">@豁达的灰熊</span> 追问是不是 Claude Code 原生功能——不是，CC 原生只有 wrapper + `--resume` 的社区做法。

### AskUserQuestion 60 秒超时自动继续

<span class="mention">@聪明的鸳鸯</span> 贴了 anthropic/claude-code 仓库的 issue #73125：Claude 提问后如果用户 60 秒没回应，就直接「continued without an answer」自己往下干——「这个 feature 自动开了也是有点离谱」。<span class="mention">@稳重的海豚</span> 却站在了对立面：「这个多好啊。我都得自己加 harness 让它接着干别问我问题，有问题自己想，按我给的原则和开始的目标自己去回答，只有确实需要我介入的才能来找我。」同一个行为，重度 agent 用户看是解放，交互派用户看是失控。
