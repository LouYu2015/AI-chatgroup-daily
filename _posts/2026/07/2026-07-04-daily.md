## Fable 5 实战观察

### 盲测揭晓：语感站在 Opus 一边

<span class="mention">@飘逸的浣熊</span> 公布了昨天 [「日报 Fable 5 / Opus 4.6 盲测」]({{ '/daily/2026/07/03/daily/#日报-fable-5--opus-46-盲测' | relative_url }}) 的答案：这两天的 A 版都是 Fable 5，B 版都是 Opus 4.6。而昨天两位表态的群友（<span class="mention">@灵动的羊驼</span>、<span class="mention">@豁达的灰熊</span>）都投了 B——在「群聊日报」这种写作任务上，老模型的语感反而更讨喜。各位读者可以自行回味一下手里这份日报像 A 还是像 B。

### 主动性与 Unknown Unknowns

<span class="mention">@稳重的海豚</span> 分享了一个观察：他的个人网站本来是当 Agent 的显示模块用的——需要看的文档让 AI 发上去。以前用 Codex 干活得明确交代每件事，这次 Fable 没等他开口，自己就把整个产品的验证做完、直接在网站上发了一份 private report。

> <span class="mention">@稳重的海豚</span>：这是我觉得 codex 这个东西它还能干活，我能想到他能干，我想不到他干不了。F 这个就是我想不到他能替我想到。当然，实际干活还是要 codex 来

<span class="mention">@随和的猫头鹰</span> 顺势提出加一条指令：「我想不到的，你也要帮我先想好。」<span class="mention">@稳重的海豚</span> 随即贴出了 Thariq 的新长文《A Field Guide to Fable: Finding Your Unknowns》（3K 赞、6.9K 收藏）：the map is not the territory——prompt、skills、context 是地图，codebase 和真实世界的约束才是疆域，两者之差就是 unknowns。Thariq 称 Fable 是第一个「工作质量被我澄清 unknowns 的能力卡住瓶颈」的模型，并给出四象限拆解法：Known Knowns（写进 prompt 的）、Known Unknowns（知道自己没想清的）、Unknown Knowns（显而易见到不会写下来、但见到能认出的）、Unknown Unknowns（从没考虑过的坑）。

<span class="mention">@稳重的海豚</span> 由此得出暴论——都说挣不到认知以外的钱，「那现在好了，fable 可以给我找，那认知以外、认知以内钱老子都可以赚」，甚至当场下单 `/goal make me a trillionaire`。<span class="mention">@机智的水獭</span> 认真辩证了一下：Fable 告诉你、你看了理解了，那就已经变成认知以内了。<span class="mention">@风趣的企鹅</span> 则玩了个逻辑梗：「这个就不知道啦，因为在你认知外。」<span class="mention">@三只纳垢灵</span> 四字收尾：「警惕银弹思维。」

### 恋爱三天指南：先建 eval，再谈 skills

<span class="mention">@风趣的企鹅</span> 发布了续篇[《天才程序员Fable5恋爱三天完全指南！》](https://mp.weixin.qq.com/s?t=pages/image_detail&scene=1&__biz=MzcwNDE5NzI3Ng==&mid=2247484051&idx=1&sn=530b785dd12666c0698988b5af7eced1&from_masonry=1&sharer_shareinfo_first=7797f94c36e9f89c56be610744dd64&sharer_shareinfo=7797f94c36e9f89c56acfe610744dd64#wechat_redirect)——核心主张与前天 [「七天优先级与认证刷题」]({{ '/daily/2026/07/02/daily/#七天优先级与认证刷题' | relative_url }}) 一脉相承：不要用顶尖模型做一次性功能，而是搭建能持续运转的开发基础设施。四件事：50 条真实任务的 eval 体系当「尺子」、七个核心 skill 固化工作规程、模型路由让 Fable 只做建筑师、evidence ledger 记录每步判断依据，最后一天让 Fable 写 HANDOFF_TO_OPUS.md 交接。他自己的优先级排序是「第一做 eval，第二写 skills，第三打磨 coding sys，第四跑真实复杂任务验证」——没有 eval，skills 写得再漂亮也不知道有没有变好。

### pxpipe：把文本渲染成图片省 token

<span class="mention">@飘逸的狮子</span> 发现了一个 273 星的仓库 pxpipe——「cut Fable 5 token usage by rendering text context as images」，把文本上下文渲染成图片喂给模型来降低 token 计费，问群里「这靠谱吗」。<span class="mention">@睿智的犀牛</span> 扶额预言：「这种感觉被 Anthropic 看到了有半天功夫就能被修复。」<span class="mention">@天真的浣熊</span> 提醒这招并不新鲜——去年 DeepSeek 好像有篇 paper 就提过类似方法。<span class="mention">@热情的狮子</span> 的评价言简意赅：「抽象。」

### Batch 单条请求也享半价

<span class="mention">@坦荡的灰熊</span> 看了昨天 [「夜间 Batch 立省 50%」]({{ '/daily/2026/07/03/daily/#夜间-batch-立省-50' | relative_url }}) 的日报后问「batch 是啥」，<span class="mention">@飘逸的浣熊</span> 贴出 [Anthropic Message Batches API 官方文档](https://platform.claude.com/docs/en/build-with-claude/batch-processing)：批处理按标准 API 五折计费，且与 prompt caching 折扣可叠加，单批通常 1 小时内完成、结果 29 天内可下载。关键提示是——虽然设计上用于大批量请求，「但你也可以只发一个请求」，单条同样走半价管线，非常适合不需要即时响应的长任务。文档还提到通过 beta 头可把 max_tokens 提到 30 万，适合长书稿和长推理链场景。

## 方法论

### 需求先行：让人在自己的问题里看见价值

<span class="mention">@稳重的海豚</span> 转述了社群里一封关于孩子教育的邮件帖，深有共鸣：「这个先学着，以后总会用得上」是对孩子最残忍的谎言——孩子感受到的只有当下，看不到目标时知识就是纯粹的负担；帖子里的小孩「不是理解了一切才行动，而是在行动里倒逼自己长出理解」。他联想到自己学英语的经历：反复被告知重要没用，出去玩见了世面、玩英文游戏之后需求出现，英语自然就上来了；做 AI 教育活动同理——直接说「你们需要这个」没人来，改做 Hackathon、demo day、给 VC demo 的机会，人自然而然就来了。

> <span class="mention">@稳重的海豚</span>：不要试图说服别人相信价值，要让他们在自己的问题里看见价值

<span class="mention">@今天群内信息量极大</span> 贴出自己以前写的[《AI 对 IT 领域的影响》](https://yage.ai/ai-it-impact.html)呼应：用 AI 做事天生带着问题去问，「天生就解决了最重要的动机的问题」。<span class="mention">@谨慎的松鼠</span> 现身说法——最近换专业领域，按以前啃教科书的方式至少慢两个月，带着 AI 学则非常快。

反方补充也很精彩。<span class="mention">@开朗的企鹅</span> 提醒教育不完全等于满足需求，还需要「合意困难」——恰当的摩擦力环境；<span class="mention">@三只纳垢灵</span> 认为摩擦力不必然是坏事：「对于想做的事，困难只会成为乐趣。不想做的，困难才是要克服的东西。」<span class="mention">@稳重的海豚</span> 表示「零摩擦就没劲了，最好是有人一起」。<span class="mention">@沉稳的兔子</span> 则泼了盆冷水：AI 学习对形成直觉「没有提效多少」，最适合的是那种看个一知半解就能干活的，但有时会出现「中医那种听着挺有道理、自己也觉得有道理，但仅限于有道理」的情况。<span class="mention">@温暖的斑马</span> 用画圆圈作比收尾——圆圈越大，神经元触发错断重新融合的几率越大，「最好的办法就是 stay hungry, stay foolish」。

### 判断力的无产阶级化

<span class="mention">@热情的狮子</span> 分享了[《判断力的无产阶级：AI时代的认知分层已经开始了》](https://mp.weixin.qq.com/s?__biz=MTQzMjE1NjQwMQ==&mid=2656184252&idx=1&sn=e59edcdc677205a5f341e1dba3d03b3a&chksm=6731212254d2ca343037b12afd87aafe9b36eddc2700decfef0a0e9180c78f3b4c2891876a64&mpshare=1&scene=1&srcid=0704vcsgOg7hiXDj2IF4KuZW&sharer_shareinfo=1db2b4396d551036053ace44cb6f6f5a&sharer_shareinfo_first=1db2b4396d551036053ace44cb6f6f5a#rd)。文章核心论据是 MIT 的脑机接口实验：用 ChatGPT 写作的学生，创造力相关的 α 波和工作记忆相关的 θ 波连接活跃度显著降低，且 AI 辅助组对开放问题给出清一色同质化回答；康奈尔的跨文化研究进一步发现 AI 辅助写作会让各国用户丢弃地域性细节、向光滑安全的通用表达靠拢。作者把 AI 提供的捷径称为「认知上的高利贷」——绕过判断力积累的过程直接拿裁剪过的答案，并举了个 22 岁斯坦福毕业生的例子：AI 不在身边时「脑子就会感觉慢了下来」。出路不是拒绝 AI，而是有意识保留非效率空间——读艰涩原著而非 AI 摘要，把模型当激发问题的思想撞针而非提供答案的先知。与今天群里的「需求驱动学习」讨论恰好构成一体两面。

### log 与交叉熵：模型的意外标尺

<span class="mention">@淡定的大象</span> 继昨天 [「数列递推视角看 LLM」]({{ '/daily/2026/07/03/daily/#数列递推视角看-llm' | relative_url }}) 之后又发了同系列新篇[《高中觉得最没用的 log，其实是大模型判断"自己错得有多离谱"的唯一标尺》](https://mp.weixin.qq.com/s?__biz=MzY4NTM1MDc1NQ==&mid=2247485054&idx=1&sn=eb9172bd5781b03021d347c1ac8b51b0&chksm=f228ac6d95fe8a53d19ac50fbdf8ef1edee833062bd73a1d194501877596da9e15192c3db1b2&mpshare=1&scene=1&srcid=0705kVs2c7nuVKVrfrl9qL5T&sharer_shareinfo=ccce4e5b73cdbd28b14218baebd5f40f&sharer_shareinfo_first=fdd1ecfaf503757947a2e02d09a3cef4#rd)：log 把连乘变连加救了概率下溢的数值灾难，-log(p) 精确度量「意外程度」并指数级重罚自信的错误，困惑度就是 exp(交叉熵)——把 log 脱掉还原成「模型在几个词之间犹豫」的有效选项数。全程配可跑的 PyTorch 代码，依旧适合转给在补基础的朋友。
