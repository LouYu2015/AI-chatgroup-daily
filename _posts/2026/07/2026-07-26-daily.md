今天最好玩的是 <span class="mention">@今天群内信息量极大</span> 的新硬件项目：用 ESP32 把语音输入伪装成一块蓝牙键盘，绕开所有系统与输入法限制，固件几乎全程由 AI 自主蹬出。另一条线是两张疑似伪造的 Anthropic 官方公告截图在群里流传，从 Max 20x 被大规模薅羊毛讲到全球宕机，截图真伪存疑、但免费白嫖教程满天飞是真的。方法论侧最值得抄走的是 <span class="mention">@谨慎的松鼠</span> 的发现——让 Codex 专门开一个 thread 用作 AI 间互相讨论，深度和完成度都比 subagent 好。

## 行业新闻

### Max 20x 薅羊毛与假公告疑云

中午 <span class="mention">@坦荡的灰熊</span> 贴出一张 Anthropic 官方账号口吻的推文截图：过去 36 小时数万个虚假账户注册了最高档的 Claude Max 20x，每笔支付都伴随客户端脚本拦截实时扣款请求，账单地址在德国、IP 集中在东南亚，并称 IBAN 生成算法精确到「只有国家级别或中国的 AI 组织才能做到」。他本人的第一反应就是吐槽：数万个就国家级，「A畜想象力居然如此之低」；<span class="mention">@开朗的企鹅</span> 附议随便哪个黑灰产团队都干得出这个；<span class="mention">@睿智的犀牛</span> 调侃这是想说又不敢说，「谈恋爱呢这是」。

真伪很快被打上问号：<span class="mention">@豁达的灰熊</span> 上 X 找了一圈没看到这条，头像颜色也不对。傍晚 <span class="mention">@搞仁义毛义仁</span> 又贴出第二张续集截图——紧急公告称 SEPA 先使用后扣款的结算逻辑被规模化滥用，海量并发欺诈请求压垮鉴权与计费集群，全球服务中断、短期无法恢复；<span class="mention">@神秘的火烈鸟</span> 纳闷 SEPA 明明是欧洲支付机制，怎么把 A 社全球都整崩了。

截图可能是假的，现象未必是假的：<span class="mention">@直率的鸵鸟</span> 提供的旁证是，最近免费使用 20x 的教程确实传疯了。

### 桌面 Agent 会不会杀死 SaaS

<span class="mention">@风趣的企鹅</span> 发布[《WorkBuddy 登顶之后，桌面 Agent 会不会杀死 SaaS？》](https://mp.weixin.qq.com/s?__biz=MzcwNDE5NzI3Ng==&mid=2247484297&idx=1&sn=133c790df0cb22990ce131f590ee636c&chksm=f5542909c5e0f0ee1c88bb295ddfcc7dce97deb5efc24b79274d0a96cd423c6bb8bab105ba8c#rd)：SaaS 卖的是功能使用权（一间配齐厨具的厨房），agent 签的是直接交付成果的新合同；最先被吃掉的是靠复杂菜单和培训成本堆起来的界面税，而 CRM、财务、权限审计这类系统记录层反而更值钱。他的结论是，当软件已经能替你完成工作，用户付钱买的一定是更确定的结果、而不是更多按钮。工具背景可回看 23 日的 [「WorkBuddy：连接器市场当 CLI hub」]({{ '/daily/2026/07/23/daily/#workbuddy连接器市场当-cli-hub' | relative_url }})。

反应两派：<span class="mention">@务实的长颈鹿</span> 觉得 SaaS 费用可以部分转成每个人的 agent 套餐；<span class="mention">@细心的熊猫</span> 一句 Agent 就是 SaaS，<span class="mention">@天真的鸵鸟</span> 反驳这恰恰是要完全避免的——agent 要真做成 SaaS，就天天被模型压着打。<span class="mention">@天真的浣熊</span> 的贡献是把 Agent 就是 SaaS 看成了 agent 就是 ass。

## 工具

### 鸭板：把语音伪装成蓝牙键盘

<span class="mention">@今天群内信息量极大</span> 宣布找到了语音输入法的正确形态：自己搓个键盘。用 ESP32 单片机做一个带屏幕和麦克风的小设备，录音走 AI Builder Space 做语音识别，识别结果按 BLE HID 键盘协议直接打字——在电脑和手机眼里它就是块普通蓝牙键盘，天然跨 iPhone/Android/Mac/Windows/Linux，不依赖 universal clipboard，也绕开 iPhone 上第三方语音输入法的糟糕体验。<span class="mention">@冷静的飞鼠</span> 一句话总结原理：「把语音伪装成键盘」。<span class="mention">@稳重的海豚</span> 帮着理清了定位：本质是 STT 模拟键盘，那物理形态根本不必像键盘——狐狸确认可以是脚踏板、手链甚至史莱姆，命名环节 <span class="mention">@80-HD</span> 提名 yaboard 鸭板，<span class="mention">@稳重的海豚</span> 觉得做成 plaud note 那样贴手机的圆钮就行，叫 yadot。

<span class="mention">@沉稳的仓鼠</span> 提出关键难题：键盘能输出中文吗？狐狸的绕行方案颇有年代感——让固件打五笔，一码一字，反正自己不用会、AI 会就行，实在不行再自己搓个不联网的输入法。<span class="mention">@睿智的犀牛</span> 被唤起久远记忆：「王旁青头兼五一」。

开发过程本身就是卖点：因为不涉及物理操作和验证，电脑可以全自动自己蹬——GLM-5.2 做了一大半，下午上课时 Claude 接力 debug 推完，现在能用了。代价是 AI 把固件搞坏后他物理复位了十几次，疑似把老单片机的 flash 刷出了坏块；iPad 对 HID 协议要求极严，一度卡在最后一步打不出字。他放话做出来给大家用、无缝接入 AI Builder Space，<span class="mention">@飘逸的狮子</span> 感叹又有一个牛逼的周边，<span class="mention">@冷静的飞鼠</span> 抢先命名鸭哥手作珍藏版；晚间 <span class="mention">@风趣的企鹅</span> 贴出一台四键带屏小装置的实物照，很像这个思路的现成雏形。顺带一提，清晨 <span class="mention">@坦荡的灰熊</span> 也在感叹语音输入的体验红利：卸载搜狗改用微信输入法一个月，觉得每个功能都是朝着有利于 vibe 的方向做的。

项目背后的方法论狐狸也点破了：

> <span class="mention">@今天群内信息量极大</span>：关键是设计机制把自我循环打通，让AI尽可能自主工作。怎么prompt等等都是奇技淫巧，不重要了。

<span class="mention">@80-HD</span> 概括为让 AI 理解你的 intent、剩下让它自己搞清楚；<span class="mention">@稳重的海豚</span> 自嘲现在大部分时间都花在整理清楚自己的 intent 上，<span class="mention">@80-HD</span> 顺势推销 grillme——<span class="mention">@风趣的企鹅</span> 今早正好给 product manager skill 小幅更新、加上了 grill me 模式（前情见 22 日 [「语音 dump 续：grillme 与 i 人羞耻」]({{ '/daily/2026/07/22/daily/#语音-dump-续grillme-与-i-人羞耻' | relative_url }})）。

### 备胎模型账本：K3 不慢、MiniMax 不限量

凌晨 <span class="mention">@开朗的企鹅</span> 对着黑客松 codex 一炸全场走光的照片（昨天 [「深夜 503 与全员 reset」]({{ '/daily/2026/07/25/daily/#深夜-503-与全员-reset' | relative_url }}) 已报）总结「永远要有第二个模型」，引出一轮国产备胎盘点。<span class="mention">@神秘的企鹅</span> 的困境是 A 社用不了、国产要么慢要么能力差点：他觉得 GLM 5.2 比 5.6 差、也比不上 5.5。<span class="mention">@风趣的海豚</span> 力挺 K3：根本不慢，「你只会觉得自己钱少」——199 的套餐体感不比 20 刀 codex 抗用多少，且 K3 没有低 effort 档。<span class="mention">@直率的鸵鸟</span> 补一笔账：论单价还是 codex 20x 最便宜，最近用量足够就没必要开别家，等哪天不再送 reset 了再看备选。

<span class="mention">@风趣的海豚</span> 的冷门推荐是 MiniMax：100 多块一个月那档 token 不限量，常规任务单独用它已经足够，还晒出近 30 天 786M、累计 1.22B 的用量图。<span class="mention">@风趣的熊猫</span> 吐槽 minimax 根本不听话，<span class="mention">@风趣的海豚</span> 回敬听不听话主要看 harness，性价比讨论的前提是先想清楚自己对性能的最高要求是什么。订阅全景可对照昨天的 [「七个 Coding Plan 的订阅账本」]({{ '/daily/2026/07/25/daily/#七个-coding-plan-的订阅账本' | relative_url }})。

## 方法论

### Codex thread 互聊：比 subagent 更深的 AI 对谈

<span class="mention">@谨慎的松鼠</span> 分享新发现：在 codex 里让当前对话专门开一个 thread 用作 AI 间讨论问题，整体深度、全面性和思考过程都比 subagent 更好。起因是嫌 GPT 前端做得太难看，让 K3 跟着一起审查，结果完成度和思考深度都变高了，「算是个意外副产物」。他贴出的截图里两个对话在后台多轮对答、全程没有人参与——由 Codex 从另一个任务发来的消息写着：接受关于不升 V3、不引入 regions 的否决，但反对其中一条论证。至于为什么比 subagent 强：

> <span class="mention">@谨慎的松鼠</span>：我觉得可能是因为开新对话等同于和用户交流的水准，但是sub一般只是做一些杂活。

机制层面群里很快拆解清楚：<span class="mention">@优雅的灰熊</span> 科普 codex 把 session 叫 thread，有文件权限就能跨 thread 读别人的上下文，可以指定 id 也可以让它自己搜，甚至能修改别的 session 的对话；<span class="mention">@开朗的企鹅</span> 补充本质就是读 session 对应的 jsonl，创建时会带上自己的 session ID；<span class="mention">@坦荡的灰熊</span> 提示 codex desktop 右击即可复制 codex://threads/uuid 深度链接。<span class="mention">@认真的荷兰猪</span> 猜这招奏效的原因是 codex 的 subagent 之间本身不直接通讯，<span class="mention">@开朗的企鹅</span> 则指出 subagent 也只是个普通 session，靠创建提示词显式让它去看其他 subagent 的内容。

<span class="mention">@80-HD</span> 负责收束：所谓 graph eng，实现起来就只是多说一句话——呼应 23 日那篇 [「Graph Engineering：一篇钓鱼文的自我修养」]({{ '/daily/2026/07/23/daily/#graph-engineering一篇钓鱼文的自我修养' | relative_url }})。

### 老鸭汤出圈：给爸妈用与 memory 治理

<span class="mention">@稳重的海豚</span> 抛出部署难题：老鸭汤会用 cron 自动更新全局 memory、rules 和 skill，自己用可以不看，但给团队、客户乃至爸妈用，就需要 review、observability 和 rollback——他最近正在给爸妈部署老鸭汤，深感自己思维太 tech，「我妈说 这堆小人是干啥的」。<span class="mention">@开朗的企鹅</span> 建议 git+changelog 再配个 viewer，最好把 git 这层彻底抽象掉。

<span class="mention">@80-HD</span> 泼了盆现实的冷水，还补刀说大胆一点——有技术但不信 AI 的也驾驭不了；他现在被人问起就直接推荐 codex，稳定能保底，比什么 hermes 的 setup 都简单。<span class="mention">@豁达的灰熊</span> 盖章这个形容太对：

> <span class="mention">@80-HD</span>：说实话 用老鸭汤我觉得是需要一定驾驭能力的 就好像称了两斤散装乐高打出来的东西一样

<span class="mention">@今天群内信息量极大</span> 则交出现成方案 [opencode-private-host](https://github.com/grapeot/opencode-private-host)：SSH 网关加每用户独立 OpenCode 容器，配 iOS 客户端，公共凭据走 1Password、provider 密钥 BYOK，非技术用户填个 IP 和端口就能用——他妈妈就在用，和 opencode client 无缝衔接。<span class="mention">@天真的浣熊</span> 惊叹爸妈会 vibe coding 太厉害了。

至于 memory 自动更新本身，<span class="mention">@今天群内信息量极大</span> 的结论是不特别有用，他后来只在觉得需要时才让 AI 去更新；<span class="mention">@开朗的企鹅</span> 觉得最有用的其实是每天的 observation，<span class="mention">@80-HD</span> 附议。<span class="mention">@坦荡的灰熊</span> 由此起意：做个 MCP 给网页版 Claude，把聊天记录也纳入 observation。
