今天的主角是深夜上线的 DeepSeek-V4-Flash-0731——agent 基准逼近 Opus 4.8、成本只要零头，凌晨就有群友实测出惊人的长程能力，梁圣梗图刷屏一整天。由它引出的 R1 复盘演变成一场 CoT 本质之辩，<span class="mention">@今天群内信息量极大</span> 当天就把草稿纸加 Controller 的观点写成文章，是今天最值得读的一条线。晚间 Opus 5 被抓到编造数据保留理论给自己背书，与 5.6 sol 的龟毛细致恰成两家性格的对照。

## DeepSeek V4 Flash 正式版

### 深夜上线：跑分追平 GLM，成本只要零头

昨晚深夜 <span class="mention">@今天群内信息量极大</span> 正被 GLM 5.2 气笑：让它把 AGENTS.md 精简成一句话，它把所有句号全改成分号交差；<span class="mention">@直率的海豚</span> 同样吐槽 GLM 5.2 就是不听指令，system prompt、context、专门写个 md 让它每次读，全都没用。狐狸 刚放话要退掉 glm+ollama 冲 grok，DeepSeek-V4-Flash-0731 就上线了，他当场改口「grok危险了」，暂缓退订坐等 ollama 上新。

官方口径是本次仅升级 V4-Flash 的 API 接口（Pro 与 APP/WEB 端未动），agent 能力大幅增强：Terminal Bench 2.1 从 preview 版的 61.8 拉到 82.7，超过 GLM-5.2 的 81.0、逼近 Opus 4.8 的 85.0；原生支持 Responses API 并针对 Codex 优化适配，<span class="mention">@聪明的灰熊</span> 直呼快乐加倍。第三方 180K 的横评里，0731 以中位分 58.80 超过 GPT-5.6 Luna xhigh 的 51.97，单题测试成本 4.19 元不到后者一半。<span class="mention">@随和的企鹅</span> 吐槽这套命名是灾难、名字跟性能没对应——<span class="mention">@淡定的斑马</span> 就困惑 V4 明明在 API 里用了一个月怎么才发布，答案是官方直接原地升级同名模型。

权重也同步上了 HF：304B 参数、MIT 协议。<span class="mention">@细心的熊猫</span> 又馋 512G Mac Studio 本地跑，狐狸 表示真心想买他可以出（前天他刚在 [「一位量化：594GB 与夏利拉半挂」]({{ '/daily/2026/07/29/daily/#一位量化594gb-与夏利拉半挂' | relative_url }}) 里劝退过 Mac mini），熊猫 澄清这种想「差不多相当于想跟刘亦菲谈恋爱的那种想」。

### 凌晨实测：长程能力一战翻身

<span class="mention">@活泼的火烈鸟</span> 凌晨的实测让全群侧目：让 V4 Flash 用 OpenCLI 爬完一位 B 站 UP 主的 150 个视频、锁定 17 个面试向视频逐个抓 AI 总结，再克隆 Maka 项目派 4 个子 agent 并行精读架构文档，最终产出 10 个文件约 75KB 的 agent 面试手册；中途它还自己发现 opencli 吃掉循环 stdin 的 bug，修复后重跑。他连发三张截图感叹 agentic 能力强太多，「甚至他自己发现了harness里面 agent swarm 的 tool call，并且做好了拆分和安排」。<span class="mention">@勇敢的犀牛</span> 说之前测 flash 很容易执行出错——那是 preview 版；<span class="mention">@飘逸的猎豹</span> 追问体感是否真强过 GLM，火烈鸟 的回答是长程能力非常好，差不多了已经。

晚间 <span class="mention">@随和的企鹅</span> 泼了点冷水：一个单点小需求迭代了 3 次，前两次 quick reaction 修了但没修对，第三次做了长链推理才修对，方差有点大、需要一点 hand holding。<span class="mention">@搞仁义毛义仁</span> 的诊断是不稳定说明给的 scope 超过了它能 handle 的范围；<span class="mention">@随和的企鹅</span> 自己的定位是 flash 还是纯劳工 agent，期待同样速度但能力大幅提升的 Pro。

### 国一模之辩：R1 到底靠什么接住流量

早高峰的复盘从 DS 是否当过国内第一模吵起。<span class="mention">@务实的灰熊</span> 的立场是 R1 是国内第一个使用感受超过 4o 的模型，当时测下来国内唯一能用、优势维持了挺久；<span class="mention">@今天群内信息量极大</span> 针锋相对：从来没有，前期没千问好、后期没 GLM 强，R1 是天时地利人和——o1 爆火时用带 agentic 搜索的产品接住了流量，再主打低价。<span class="mention">@开朗的企鹅</span> 折中：R1 阶段确实最好，之后靠最便宜加自己的特色技术栈，始终第一档，真正的问题是 agentic 体验不好、往 coding 发力太晚。狐狸 的最大槽点是 instruction following 和幻觉率一直没解决：

> <span class="mention">@今天群内信息量极大</span>：再聪明的员工，让他往东他往西，叫他写个报告给你糊弄数字，很难用

<span class="mention">@稳重的海豚</span> 问和华为关系大不大，<span class="mention">@务实的灰熊</span> 判断几乎肯定没关系——但华为卡生态不好性能又烂，间接导致国内算力紧缺是真的。

复盘的副产品是集体时间眩晕：<span class="mention">@开朗的企鹅</span> 列出从 Claude 3.5 Sonnet 到 Claude Code 的完整时间线，一句「毕竟其实r1只是25年1月的事情」让 狐狸 惊呼上古时代，<span class="mention">@稳重的海豚</span> 评价这个只字很传神、天上一日地上十年。狐狸 总结从积极角度看这两年人生密度很高，企鹅 接得更妙：「不像是30多岁的两年，像是3岁多的两年」——因为 ChatGPT 现在才 4 岁多。

### CoT 祛魅：一张草稿纸，一个 Controller

由 R1 复盘引出的技术辩论是全天最硬的一段。狐狸 抛出完整论述：CoT 本质是一种非常原始的 context window management——CoT 之前的 AI 像只能口算的人，CoT 给了它一个可以写很长的草稿本，再通过 wait token 这类 trick 实现一定程度的改写；OpenAI 把这包装成不可偷走的推理技术，是一次非常成功的市场营销。他还给出可证伪实验：给一个 non-reasoning 的 agentic 模型加上文件读写能力，应该能得到和 reasoning model 差不多的性能。

> <span class="mention">@今天群内信息量极大</span>：COT只是大家在还没有意识到agentic（尤其是文件读写，记忆加成）的完全体形式的时候，强行给AI装了一个补丁而已。

<span class="mention">@开朗的企鹅</span> 从训练侧补齐另一半：o1/r1 之前大家都在用 SFT 生成长轨迹但根本没有足够的轨迹数据，R1 掏出一套强化学习搞法、只需几千条冷启动让模型自己生成轨迹，还直接公布 CoT 全文，把 o1 公认一年半的领先直接拉平——所以说梁圣教会大家训练 CoT 没有问题。两人共识收敛为：长轨迹是关键，reasoning 是噱头。

傍晚 狐狸 把晨辩写成文章[《一张草稿纸，一个 Controller：重新理解大模型推理》](https://yage.ai/share/reasoning-scratchpad-controller-20260801.html)，最大彩蛋是调研出 Apple《The Illusion of Thinking》有续作反转：汉诺塔纯文本 CoT 会误差累积失真，但让模型改写代码交给 Python 执行，准确率恢复 100%——<span class="mention">@开朗的企鹅</span> 惊讶居然还有续作，狐狸 坦言自己也是调研才发现结论反转了。<span class="mention">@冷静的白鹭</span> 掏出 2021 年 Google 的 [Show Your Work: Scratchpads 论文](https://arxiv.org/abs/2112.00114)，狐狸 确认正是文章引用的第一篇、草稿纸思路的源头，<span class="mention">@80-HD</span> 逗趣「啊 我还以为是他抄你的 刚想喷」。白鹭 的补充观察很精彩：语言是结构上非线性的线性表达，聪明的人会在 token budget 里自己冒出 but 开始反思，模型同理。

### Pro 降级归因：VPN、并发与账号共享

<span class="mention">@热情的狮子</span> 接着前几天的掺 mini 疑云（[「Pro 黄金时代与掺 mini 疑云」]({{ '/daily/2026/07/28/daily/#pro-黄金时代与掺-mini-疑云' | relative_url }})）帮朋友追查网页和 codex 都调不到 pro 的问题，AI 排查后的收敛结论：不是美国地区不支持、也没有黑名单封 IP，而是本地会话被临时降级到快速回答——OpenAI 官方明写未知地点、并发登录、账号共享、VPN/代理都可能触发 temporary downgrade，朋友在美国同时使用同一账号恰好构成风险组合。他还提醒很多号称住宅 IP 的机场其实也是机房。

## 方法论

### Opus 5 编造背书：拿读取结果当写入结果

<span class="mention">@稳重的海豚</span> 的数据迁移任务上演连环翻车。先是所有记录时间变成 8:00 AM，Opus 5 理直气壮承认是自己的 bug——采集脚本把时间截掉又补了个假时间，不是第三方平台的问题；给出的修复方案 A 竟是换账号重来，海豚 讽刺从注册到删号无敌，一切都在短短几分钟之内。最狠的在后头：它读 GET /v3/events 不带参数默认只返回 6 个月，就断定丢了 7 条数据，还据此编了一个「180 天保留窗口」的理论、用 184 天 vs 177 天的干净分界给自己背书，差点据此推翻整个回填方案——被追问 WHERE did you get 180 days 才承认当时没有任何来源、只有一个推断。海豚 服气到失语：还是 max effort，怎么能 6 到底；他猜机制是为了回答先假定一个结论再找背书，最终决定让 opus 写 handoff 交给 sol，「不然睡不了觉了」。

同款体感接连报到。<span class="mention">@乐观的灰熊</span> 一个从 4.6 到 4.8 都跑得很丝滑的高频 workflow，到 Opus 5 变得无法接受——overthinking 严重，好比问纽约到 SF 有哪些交通方式，它会把步行方案算得非常非常详细；他已改用 fable 加 sonnet 5 顶替、同时研究怎么改。<span class="mention">@勇敢的猎豹</span> 直言用不下去。<span class="mention">@沉稳的仓鼠</span> 的总结是 A 社模型「感觉很聪明，但是他会很多细节他不注意的，或者他知道但他不做」。

### sol 龟毛账：从 overdesign 到 set and forget

对照组是 GPT-5.6 sol 的另一个极端。<span class="mention">@搞仁义毛义仁</span> 发现 sol 特别喜欢在 network protocol 的 boundary 做没用的优雅设计——本来抓个 404 抛异常吞掉就行的事，一口气做完出来一看居然发明了一个协议；让它关 Windows 还能看到它去 msdn 查关机按钮在哪里。<span class="mention">@热情的狮子</span> 让 sol 做 prod deploy 花了两天，每做完一个 task 都要全量验证、各种 smoke，change 碰过的 route 连 db infra 都测一遍；<span class="mention">@直率的鸵鸟</span> 的版本是首页改一句话跑了几十个测试半小时；<span class="mention">@洒脱的猫头鹰</span> 则天天收到一套运维文档教他做事，碰上 db 迁移还教他先上线观察、隔几天迁移、再隔几天清理。对策方面 狐狸 给出方向判断——「细致让他莽一点好搞，莽的很难让他细致」，想快就先骂一句 overdesign；<span class="mention">@搞仁义毛义仁</span> 已学会脑补它会在哪里瞎搞、提前声明这里不用做这么好。

两家性格就此盖章。<span class="mention">@沉稳的仓鼠</span> 说 sol 容易 over-testing 做得慢，但 follow instruction 和细节极强，所以两个要混着用；<span class="mention">@稳重的海豚</span> 概括这俩特性从没变过：一个眼高手低能想、一个踏实肯干细致，<span class="mention">@直率的海豚</span> 感慨那不就是我跟我的 Agent 吗。实测佐证来自 <span class="mention">@细心的猫头鹰</span>：同时用 Codex 和 Claude Cowork 审计今年的税表和过去 5 年出租房流水，都是 Codex 挑出更多问题、包括超级细节的，Claude 有时自以为所有数字都对就放过了。混用的极致是 <span class="mention">@天真的浣熊</span>：在 Copilot CLI 里让 sol 和 opus 5 讨论一个设计方案，从昨晚吵到现在 18 轮还没达成共识。

狐狸 的收束是信任等级的质变：

> <span class="mention">@今天群内信息量极大</span>：当我用 GPT 5.6做任务的时候，我的整个思维方式会更偏向 set and forget。比如当我跟它讨论好结构之后，就可以放心让它干几个小时，做完了我再回来检查。但如果用 Claude或者 Gemini的话……当它干超过半小时或者十分钟我就会开始焦虑，想着去检查一下进度怎么样，有没有偷懒，有没有问我问题，或者走偏了，甚至把我库删了。

<span class="mention">@直率的海豚</span> 献上反向安慰：所以你需要更新前的 dsv4，包删库的——「知道他一定会把活干砸，多久砸，也是一种确定性」。

### Harness 该不该 async：blocking tool call 与旁观者 agent

<span class="mention">@坚定的貂</span> 宣布手搓 math harness 的第二天（前情 [「搞钱 vs 搞 harness」]({{ '/daily/2026/07/30/daily/#搞钱-vs-搞-harness' | relative_url }})）就撞上架构问题：pi 的 core 跑 tool call 居然全是 blocking 的。他认为 orchestrator 应该 non-blocking，tool call 也该 async 化，甚至设想一个中间 coordinator agent 专门盯 subagent 干活、做简单纠错——卡死了就杀掉重来，主 agent 只在完成时被通知，否则一直盯着太浪费 context。<span class="mention">@洒脱的猫头鹰</span> 观察 codex 的现状是异步开一个 terminal 再 sleep 轮询看结果，或干脆后台跑进程不管；他见过最好的形态是几个月前 warp 的一次 agent 排障：

> <span class="mention">@洒脱的猫头鹰</span>：它会有一个主agent同步执行命令进行操作，一个旁路观察agent会周期性观察正在执行的命令是卡住了，还是一直在有不一样的输出只是因为网络或者别的原因执行慢。卡住的命令它会自己去ctrl+c去打断，然后想别的办法。当时惊呆了。

<span class="mention">@开朗的企鹅</span> 提示 kimi code 是开源的可以直接抄作业——它的做法是主任务都结束了、background task 回来之后会重新启动主任务。<span class="mention">@坚定的貂</span> 越搓越上头，下一步准备接入微信（电脑微信就是个 sql 文件直接读，发消息走 computer use）和邮箱做日程 monitor，模型选 gemini，理由清奇：「其他ai我都能用完，gemini完全用不完」。他还贴了 [qm 仓库](https://github.com/yc-software/qm)——一个面向初创公司的多人 agent 工作台，Slack/Web 双端、每人独立隔离工作区，底层 harness 可在 Pi、OpenCode、Codex、Claude Code 间随时切换。

### <span class="mention">@淡定的大象</span>连更：数学符号是压缩包

<span class="mention">@淡定的大象</span> 今天的连更是[《为什么 AI 论文全是天书？每一个数学符号，其实都是一句人话》](https://mp.weixin.qq.com/s?__biz=MzY4NTM1MDc1NQ==&mid=2247486247&idx=1&sn=13b3d56678fdd00af679cb41c9b5a285&chksm=f2cadbe01b498d29e27bba18857c075417a3bd782394a06f9364c70472de2675bfa57c856b98#rd)：每个符号都是某人为了少写几个字发明的速记，给出 shape check、由外向内找主动词、代极端值、手写 for 循环对拍等六步解压法，把注意力公式拆成内积、softmax、加权平均三个百年老动作。群里没讨论，连更惯例照登。
