### 问你是谁测不出蒸馏

<span class="mention">@睿智的犀牛</span> 带来消息：有说法称 Anthropic 指 Kimi K3 蒸馏了其未开放的大模型，<span class="mention">@淡定的喜鹊</span> 觉得这更像个梗，并补充传这事的博主本就是 X 上以反华立场出名的账号。<span class="mention">@今天群内信息量极大</span> 顺手贴出 [Travis Kalanick 的推文](https://x.com/travisk/status/2078500472437043337)（中国模型蒸美国模型告不了、蒸中国模型算偷美国公司，政策该怎么办），指出所谓证据不过是问 K3 是什么模型它有时答 Claude——「2026年了… 还在用这种方法测蒸馏」。

他给出了完整的两层拆解。第一层是训练：identity 一般不会训进模型，因为在 K3 基础上 continue train 出 K3.1 时脑子会被搞混，正确做法是 serve 时用 system prompt 规范；没规范时模型只是在瞎猜一个 reasonable 的答案，乱答才是正常。第二层是蒸馏：厂商完全能控制蒸什么数据，没有人会专门花钱去蒸「你是谁」这种问答。

> <span class="mention">@今天群内信息量极大</span>：所以用这种方法来判断模型有没有蒸馏，就说明他既不懂模型是怎么训练的，又不懂模型是怎么蒸馏的。水平很低。

他还叠了两层甲：各大主流模型不论开源闭源都有 identity 混乱，如果这样的指控多了，未来厂商为了 PR 可能真会把身份训进去；至于中转站卖数据的渗透说，连 A 家自己都说是厂商主导有组织蒸馏、没提中转站，且清理这类数据 trivial。<span class="mention">@沉稳的仓鼠</span> 的补充解释赢下全场：「也可能发现了说我是claude 客户打分更高」，属于 AGI 了已经。

### Anthropic 迁移剧本：两周百万行 Zig 转 Rust

<span class="mention">@热情的狮子</span> 转发 Anthropic 官方博客 [How Anthropic runs large-scale code migrations with Claude Code](https://claude.com/blog/ai-code-migration)：Bun 联合创始人在不到两周内把 Bun 从 Zig 整体移植到 Rust、产出百万行代码，消耗约 59 亿未缓存输入 token，按 API 计价约 16.5 万美元——对比传统迁移动辄三四百万美元、耗时四年；另一案例是 Mike Krieger 一个周末把 16.5 万行 Python 迁到 TypeScript，用了数百个 agent、八阶段门控、三轮对抗性审查。

## 方法论

### 语音 dump 的乱序之痛与 quiz 复述

<span class="mention">@稳重的海豚</span> 自我剖析了 prompt 的老毛病：写完 task 和 criteria 又想到新的事，一句 btw 这几个也要做，Fable 和 5.6 Sol 都容易迷糊；一次给十几二十个指令还前后冲突，后面推翻前面。他的两个对策：开工前 quiz 一下让模型复述任务，效果好很多；以及倾向让 agent 自己定义 acceptance criteria、根据交互历史补全模糊部分——和 <span class="mention">@今天群内信息量极大</span> 的做法正好反着来。他还想起有研究说 ADHD 用 AI 的效率不如一般人，<span class="mention">@豁达的灰熊</span> 泪目：「adhd还要付token税吗」。

<span class="mention">@豁达的灰熊</span> 的经验是不用治：他语音 dump 四五分钟、中途反复绕回，frontier model 遇到矛盾点会主动来问他拍板，连 Typeless 这类整理工具都不需要了，代价是现实生活中的语言表达能力反而在退化——

> <span class="mention">@豁达的灰熊</span>：毕竟 AI 可以通读全文，人才是真正线性注意力

他由此想到费曼说手稿不是记录而是工作本身：现在思考发生在语音输入里，只是换了外部存储装置。<span class="mention">@80-HD</span> 的痛点更物理：说着说着手机自己锁屏，白说五分钟，现在只能说一会停一下。

### 先画像后翻译：两阶段猛蹬

<span class="mention">@搞仁义毛义仁</span> 是反方：他脑子里没有语言，觉得一边说话一边思考完全不 work，不如先把画像画好，再一次性翻译成 agent 能听懂的自然语言；过程中用 bullet point 记关键字，十几个单词最后 expand 成几十行 prompt——他项目里几百行的 todo 全靠关键字激发远古回忆。<span class="mention">@天真的浣熊</span> 问敲字敲到中间忘了前面的点怎么办，主张先嘴炮 dump 再慢慢整理；<span class="mention">@搞仁义毛义仁</span> 的回答很硬核：只要是自己思考的结论都能重新回忆起来。

> <span class="mention">@搞仁义毛义仁</span>：因为sol智力的提高，现在已经可以分两阶段做了，一开始先把这些指令先丢给他做analysis，然后自己稍微看一看，align双方的利益关系，后面生成一个三位数actionable items的plan，来个新session猛蹬睡觉

至于语音识别精度，他认为凑合就好：就算 Windows 把口音识别错超过 50%，GPT 在带 repo 知识的前提下自己纠错，成功率高到基本不会失败。<span class="mention">@稳重的海豚</span> 补充边界条件：大部分错误能纠回来，但核心问题纠错不对会把内容带跑偏；<span class="mention">@务实的考拉</span> 的数据是 AI 直出比例最近从 100% 回落到 70%，复杂任务的 prompt 要手动修改很多。

### 数学家的 agent 工作流：单 prompt 跑几十小时

<span class="mention">@坚定的貂</span> 在 Emléktábla Workshop 发现大多数数学家还在古法用 AI——<span class="mention">@开朗的企鹅</span> 精准还原：就是在 ChatGPT 里直接问能不能帮着想个解决方案——于是写了[《AI agents for the working mathematician》](https://chaoxu.prof/posts/2026-07-18-ai-agents-for-the-working-mathematician.html)。核心是一个编排器 prompt 并行管最多 6 个子 agent 持续攻坚：问题和判定标准固化在 STATEMENT.md、绝不自降证据等级收工，REGISTRY.md 记路线、FAILED.md 记已关闭路线的精确障碍、PROVED.md 记经受住验证的引理；每条声明走候选、自审、敌意审计加全新 agent 独立重建证明的标签体系，他自己用 Sol ultra 搜证明、Fable 5 做最终验证。

战果与成本都惊人：十天尝试 10 个开放问题成功 3 个（含他本人投入过的难题），最长单次会话跨百小时、只发约 30 条几乎不涉数学的引导指令，代价是几天烧掉六周 token 配额——上周 [「46 分钟攻破 open problem」]({{ '/daily/2026/07/11/daily/#46-分钟攻破-open-problem' | relative_url }}) 的思路至此已成体系。<span class="mention">@坚定的貂</span> 总结现在的姿势：「对 现在要控制一个agent控制其他agent干活」。

### DSL 小世界与信息茧房

<span class="mention">@天真的浣熊</span> 读了 <span class="mention">@今天群内信息量极大</span> 今天的[《为 LLM 建立更小的可执行世界》](https://yage.ai/share/llm-smaller-executable-world-20260718.html)很受启发，追问有没有项目真做成了 DSL、解析器是否可以封成 skill 供日后调用。文章的核心判断：AI 把设计语言、写解释器的成本打了下来，DSL ≈ 领域 API + 组合规则 + 可保存的程序表示，parser 和 validator 能在产生副作用之前先做检查，比给模型写更长的说明更接近可靠工程。

<span class="mention">@稳重的海豚</span> 提出了一个反向忧虑：建 domain knowledge 和 context infrastructure 的过程中，系统会逐渐被自己影响，越来越像我、也越来越不灵活，「有点像自己给自己造了一个信息茧房」。

### 问题规模匹配模型智力

模型选档今天又攒了一批体感。<span class="mention">@神秘的企鹅</span> 报告 5.6 Terra + medium 落后于 5.5 + high——同一个任务前者没解决后者解决了；<span class="mention">@随和的猫头鹰</span> 做 PPT 也要退回 5.5；<span class="mention">@80-HD</span> 则被 Sol 自作主张多干了不少活，只能打回重做。<span class="mention">@搞仁义毛义仁</span> 一句话定调：「问题规模需要匹配模型智力」，5.5 能做好的让 Sol 做不一定更好。

但 Sol 的长板也很清楚：<span class="mention">@搞仁义毛义仁</span> 认为它 debugging 找 root cause 的能力比过去所有模型都强，多了一个自己不断做实验 narrow down observation 的过程、不用人 drive——5.5 时代这些还得手动；昨晚他从 TCP socket 蹬出来的 http protocol 也经受住了 Chrome、http.sys 和 WinHttp 的三重考验。<span class="mention">@淡定的喜鹊</span> 的流水线是让 Sol 先写 plan、丢给 Fable 切磋几轮再交回 Sol 执行：Sol 干活一板一眼，聪明和全局观还是 Fable 好些，「我现在越来越喜欢多模型互掐之后的输出结果了」。
