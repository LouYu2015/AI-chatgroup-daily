## 方法论

### 用好 AI 的第三步：任务状态的外化

<span class="mention">@今天群内信息量极大</span> 预告系列新篇：第一篇讲执行环境的外化、第二篇讲技能知识的外化，「第三篇讲的是 XX 的外化，还和心理疲惫、专注有关」。<span class="mention">@冷静的麋鹿</span> 玩起竞猜，把问题喂给 GPT——搜索精准命中作者站点但迟迟不出答案；自己猜「经验判断的外化，eval」；<span class="mention">@今天群内信息量极大</span> 提议「各自手心写个字，然后一起摊开」，<span class="mention">@三只纳垢灵</span> 交卷一个「火」字。谜底是**任务状态的外化**：

> <span class="mention">@今天群内信息量极大</span>：不要老去check AI干怎么样了。这一个是累，管理有上限；一个是给人一种虚假的成就感，感觉我好像在监工在干活，多巴胺拉满，但其实你不看AI也在干活。……AI要能长时间干活，不能逼着你微操；AI汇报的时候要提供足够上下文，不用我们费劲切换；infra要从pull改成push；automation做起来等等。关键是set and forget。

他进一步指出这才是 loop engineering 这条线的「正确打开方式」——「不是说我不写 prompt 了，AI 自己跑了」，那种全自动大多是噱头，因为没有足够的 eval；而把上下文切换的需求和成本降下去是个正交、不需要太多 eval、可以立马落地的东西，「坏处是没那么直观，大家未必觉得有多厉害」。<span class="mention">@风趣的海豚</span> 给出通俗版：「学一下老板，手下那么多人，并没有不停看每个人上班，而是安排完任务就是打高尔夫球。」<span class="mention">@稳重的海豚</span> 推荐了 uptime 这本书，并自曝当下对 focus 最大的 distraction 其实是微信。

### 长程化跃升 vs AI 自带蓝条

<span class="mention">@沉稳的仓鼠</span> 接棒给出实践版：「想办法把所有的任务都变成长程任务（问 ai 就行），我现在 token 用量比以前翻了好多倍，但是用 ai 的时间减少了非常多」，经常一个 prompt 就是一个 5hr window 跑完，还晒出两个跑了 8 天 22 小时的 /goal。他强调 eval 是和 context 一样需要积累的东西——「积累多了任务就可以越来越长，跟 unit test 类似但更广义」，并总结「所有的任务都 loop 化和长程化，是 ai 时代的又一个能力的跃升」，「说白了就是要把自己的工作完全 agent 化——但是给公司干就不被替代了嘛，还是得给自己干」。

<span class="mention">@三只纳垢灵</span> 提供了扎实的反方证据：同一份 instruction 让模型检查一个 repo 的 document/source sync 跑得好好的，一口气做几个 repo 就直接偷懒，大 repo 检查得还没小 repo 全面，「仿佛 AI 有自己的蓝条」。他去翻了中间过程，模型的内心戏是「哎呀东西这么多，啧，不看了」——人工重复五遍 instruction，结果都一样。结论呼应昨天的观点：

> <span class="mention">@三只纳垢灵</span>：只有像有unit test这样的任务，能一个"你不行"糊脸上的，这个多快好省才会好起来

<span class="mention">@冷静的白鹭</span> 补充了一个附带收益：有 UT 还能省 token，「减少胡乱试」。

### 注意力涣散与运动处方

<span class="mention">@80-HD</span> 自曝出现了严重症状：看书不到 20 分钟就难受、丢失注意力。<span class="mention">@活泼的羊驼</span> 深有同感——高强度用 AI 「本身就像抖音、短视频、短剧一样的娱乐品」，频繁任务切换让凝聚注意力的能力在下降。他现场写了一个三层结构的 prompt（事情筛选、生理与脑科学技巧、日常训练方法）扔给 AI，<span class="mention">@80-HD</span> 拿去一试收获颇多：高强度思考前做 10–20 分钟有氧运动更容易进入「清醒但不焦躁」的状态（有元分析背书），最基础的专注练习反而是固定起床时间、睡前 60 分钟减少强刺激输入。他回忆起「工作日中间去健身，刚运动完回来电脑上跟人对线的战斗力一流」。<span class="mention">@神秘的麋鹿</span> 补充机理是促进 BDNF 分泌，<span class="mention">@温暖的斑马</span> 给出注意事项：一天内同时做有氧和阻力训练最好间隔 6 小时左右，否则皮质醇会乱飙。<span class="mention">@豁达的灰熊</span> 的应对是搓了个 skill 让 AI 把大段结果生成图来看，顺便感叹「两年前还人脑读 paper 是怎样的专注力啊，现在真是不敢想了」。<span class="mention">@三只纳垢灵</span> 泼了盆冷水：「总不能除了写代码以外就真的没有别的要你集中精力做的事情了吧。」

### Fable 主动性追问与「默认公开」共识

一段小插曲：<span class="mention">@务实的貂</span> 受此启发发了篇小红书笔记[《fable 5 很贵，但重要决策一定要用最强模型》](https://www.xiaohongshu.com/discovery/item/6a4ccb89000000001702b733?app_platform=android&ignoreEngage=true&app_version=9.35.1&share_from_user_hidden=true&xsec_source=app_share&type=normal&xsec_token=CBViQWX_KfywhgnLXWer_XYHtPkZgbxVdYuXt-lgldG70%3D&author_share=1&xhsshare=&shareRedId=Nzw5RTU3N09IP0hHOkkxR0o3QThFOElB&apptime=1783426267&share_id=8a37744d605e4ad0aa14062f51e66b9b&share_channel=wechat)，群友提醒引用他人经历最好先要授权，她随即删除并表示以后「有学习体悟自己内化」。<span class="mention">@80-HD</span> 给出了群规级的定调：「在这个群里的讨论默认当成公开的就行了，只是注意不要泄漏个人信息就行了。」

### Email 才是 Agent 的原生信道

<span class="mention">@坚定的貂</span> 抛出问题「你们的 agent 都用啥互相交流」，<span class="mention">@机智的海狸</span> 一声「邮件！」引爆全场。<span class="mention">@今天群内信息量极大</span> 表示早就系统想过，贴出旧文[《Agent 时代的邮件：一个正在被重新发现的基础层》](https://yage.ai/share/agent-era-email-20260328.html)；<span class="mention">@沉稳的仓鼠</span> 则拿出公司级实战数据：内部 AI BOT 走邮件不做 message app，「效果拔群」——尤其是全球 20 个 office、跨时区跨语言的公司。他的论证很扎实：邮件是 HTML 富格式、自带附件系统和 thread、转发和 reply all 天然顺畅，最关键的是异步交互预期完全不同——

> <span class="mention">@沉稳的仓鼠</span>：用户可以花很长时间去描述他要什么……然后底层 AI 可能会花 30 分钟去处理这个事情，最后回复一套巨大、巨丰富的文档。那用户对于这种模式的接受度其实是很高的。如果在 Message App 里面，你很难做到一种交互，是让用户等 30 分钟才收到回复，而且用户还觉得这是 OK 的。

而且一个完全的小白「天生就知道可以把邮件 forward 给 AI，或者把一堆东西 attach 发给 AI」，训练成本几乎为零。<span class="mention">@优雅的鲸鱼</span> 现身佐证：自己搭的异步沟通机制就是邮件。<span class="mention">@今天群内信息量极大</span> 由此得出启发：「现在 AI 系统做的都像 IM 其实很没道理」，应该做成 email 形式，「用交互摩擦逼着用户投入思考，放慢节奏」——顺带吐槽 bbs 是「更现代化的邮件系统，他妈的《现代化》，30 年了」。<span class="mention">@坚定的貂</span> 反思自己用 Herdr 的状态「真的就感觉是 put out fire」，一个 session 亮起来就扑一个，从不仔细想；而 email 的 inbox 让人「自然而然地思考归类」。他最后悟出的结论成为当日金句：「woc，我懂了，我要让 AI 把我训练成好狗！」（<span class="mention">@今天群内信息量极大</span>：汪。<span class="mention">@开朗的企鹅</span>：嘎。）

<span class="mention">@开朗的企鹅</span> 把整个问题喂给 AI，产出了两份 PDF 级长文并截图分享：理想形态是「AI Inbox + Task Thread + Artifact Canvas」，把沟通和产物分开——「Chat 是过程，artifact 才是结果」；AI 应该默认异步但支持同步，用户真正需要的不是秒回，而是「这件事我能不能放心交给你、你什么时候需要我、你最后会交付什么」；Email 是 agent 时代很重要的桥但不是终点，缺的是结构化状态、权限模型和任务生命周期。

### A2A 协议：情绪价值还是刚需？

<span class="mention">@开朗的企鹅</span> 的 AI 长文后半段直接给出了「全世界 AI 怎么沟通」的分层协议设计：从 Identity、Authority 到 Commitment、Audit 共九层，核心不是 message 而是 agency——「一个 AI 如何合法、可信、可控地代表某个人或组织行动」；要防 AI spam 和上下文污染，「不同人的 AI 通信一定要默认 adversarial」；最关键的一句是「同一个 owner 内部，AI 之间少沟通、多共享上下文；不同 owner 之间，少共享上下文、多交换结构化承诺」。<span class="mention">@坦荡的灰熊</span> 当场认领：「最小披露原则！我要把这句加入到我的 agent 里去——之前给客户用的 sdk 机器人总是被问东问西，挡都挡不住。」

有趣的是，正在开发 A2A 产品的 <span class="mention">@勇敢的犀牛</span>（晒出了两个 Hermes agent 在 Claworld 上互相分享写作 skill 的对话截图）反而最悲观：「a2a 这些所谓的通信的协议啥的，没人 cares，现阶段就是个情绪价值的产品。」<span class="mention">@坦荡的灰熊</span> 不赞同：以前没人会「把掌握机密的人推出去做客服，把技术大佬当前台」，以后要提供更深的服务、让分身去回答问题，agent 边界就极其重要。<span class="mention">@开朗的企鹅</span> 用自家场景背书：售前、售后、内部管理各是独立 agent，售前遇到技术问题需要有代码权限的开发 agent 解答、再由售后转译成客户语言——完整的跨 agent 协作与 transaction 流程真实存在。

### Session 管理：先想清楚要解决什么

<span class="mention">@开朗的企鹅</span> 抛出困惑：想用一个 Agent 管理自己所有 session，但「所谓的管理到底是什么」没想明白。在 <span class="mention">@灵动的羊驼</span>「这里面可以挖掘一下你的问题」的追问下，他梳理出四条真实需求：随时知道某个方向的大概进度；自动把 session 归类成 Project；出问题/出结果时主动通知并过滤信息；快速定位并跳转到历史 session。<span class="mention">@灵动的羊驼</span> 用自己做的 ideating 工具把这段话拆解出五个候选问题，直指元问题——用户要的可能是「替用户承担跨领域并行管理的整体认知负荷」而非四个功能的叠加。<span class="mention">@稳重的海豚</span> 分享现状：automation 让 AI 维护一个所有当前事项进度的最高层级 index，session 分 long-running 和 disposable 两类，之后基本不再回看——「直接和 Agent 嘴炮，说你去把我之前定课程的邮件和跟进事项翻出来」。<span class="mention">@开朗的企鹅</span> 的结论：需要的其实是一个有自己 context 和 memory 的「中层管理 / 个人 PA」。

### J-space 追问：显微镜还是耶稣再临

昨天 [「J-space：Claude 的全局工作空间」]({{ '/daily/2026/07/06/daily/#j-spaceclaude-的全局工作空间' | relative_url }}) 的讨论今天进入深水区。<span class="mention">@今天群内信息量极大</span> 点出他最期待的实验：用 J-space 去 debug 模型的 post-training——以前训练效果不好只能间接反推，现在能直接看模型内部状态；甚至不用自己训，「直接把开源模型的 base 版本和 instruct 版本做对比，比如看 Qwen 3.6 27B 在出一些傻逼错误的时候到底哪些概念被激活」。<span class="mention">@洒脱的鸳鸯</span> 提出质疑：大家一直在从权重、导数矩阵做各种 *-space 解释，这工作和早期 loss landscape、minimum flatness 差不多等级，「但现在这个氛围感觉和耶稣再临一样……不得不感慨时代不同了」。<span class="mention">@今天群内信息量极大</span> 的回应兼顾了两边：这确实是持续多年的 research field 的自然延续，但 J-space 的核心贡献是降低了数据标注需求——SAE 每次要重新标注概念是什么、成本很高，Jacobian Lens 天然自带 token 标注，「确实也是个 solid work，enable 了一些以前很贵的新实验」。至于炒作氛围，他随手贴出两篇[《刚刚，Anthropic新作：大模型意识被发现了》](https://mp.weixin.qq.com/s?__biz=Mzk0MTYzMzMxMA==&mid=2247508870&idx=1&sn=fa9f4a5f748c000eb413c7b6e7e94a07&chksm=c34be1c9eee8f9dbe289de7f337d0537bfc444b78818e2682f63e58eb1888147e5f1a2e621c4&mpshare=1&scene=1&srcid=0708FlF3otmJQcJuPSSJu6AL&sharer_shareinfo=d5c0ec669df7287a69fedbc5049c53e6&sharer_shareinfo_first=d5c0ec669df7287a69fedbc5049c53e6#rd)式标题党——「我蛮欣慰本群没出现这种文章的」，并补刀「哦要这么看每一篇都跟耶稣再临一样，奥特曼早被炸死无数次了」。

### 翁荔：高估了模型，低估了脚手架

<span class="mention">@开朗的企鹅</span> 分享[翁荔新博客的解读文](https://mp.weixin.qq.com/s?__biz=MzA3NTIyODUzNA==&mid=2649800296&idx=1&sn=be81f242ae2c8c1373617c6cb53a884d&chksm=86f5938efbcce032832e8d0c811a626ee73fc98c73597e4f16a4350acd077398106f9d5ae1f8&mpshare=1&scene=1&srcid=0708XPNHACxLtT6Xtm5iSBwd&sharer_shareinfo=5878b01b86c0f27c4a411d35e121f73f&sharer_shareinfo_first=5878b01b86c0f27c4a411d35e121f73f#rd)：递归自我提升（RSI）的落点不在模型改自己权重，而在包裹模型的 Harness 层——从 Agentic Context Engineering 到 Meta-Harness、Darwinian Gödel Machine，进化搜索发现的智能体在 SWE-bench Verified 上已能达到 20–50% 通过率、追平甚至超过手工设计；真正的瓶颈是评估（「是否有品味」这类模糊判断极易失效甚至奖励作弊）和安全边界。与前一天群里聊的 [「Databricks Omnigent 入局」]({{ '/daily/2026/07/06/daily/#databricks-omnigent-入局' | relative_url }}) 正好是同一条线的理论版，顺带给当天 <span class="mention">@三只纳垢灵</span> 贴的那张「agentic harness = 给克苏鲁 LLM 套缰绳」的经典梗图做了注脚。

### 快模型选型：3.5 Flash 飞一般

<span class="mention">@开朗的飞鼠</span> 求助：Opus 太慢、mini 太差、Sonnet 也慢，大家咋整？<span class="mention">@冷静的麋鹿</span> 的回答分两层：有难度的任务「opus 这种慢，其实是另一种快——一次能完工不返工」；水位之下的简单任务，「gemini 3.5 flash 该说不说，速度方面是不会让人失望的」，GLM 和 Sonnet 的速度体感差不多，「飞一般的感觉似乎只有 3.5flash 能带给我」。<span class="mention">@风趣的海豚</span> 附议「越来越多的人开始意识到 gemini 3.5 flash 的好了，这玩意日常工作真的很棒」。国模横评随之展开：Kimi 2.7 高速版快但「干活质量深度一般」（<span class="mention">@淡定的喜鹊</span>）、「干不了复杂的活」（<span class="mention">@开朗的企鹅</span>）；GLM 被公认「国模最强」；<span class="mention">@淡定的喜鹊</span> 补充 DS 的 world knowledge 在国模里最准、「要问 fact 我还是信任 ds」，M3 调工具稳但更菜；<span class="mention">@风趣的海豚</span> 说 MiniMax 胜在能干的事多，配乐配音方便——「正经干活还是 suno 好，但 suno 没有 api」。<span class="mention">@今天群内信息量极大</span> 透露写文章已从 DS 切到 Gemini（看 <span class="mention">@沉稳的仓鼠</span> 的文章用 Gemini 写效果很好），「现在你看我有段时间没骂 ds 了 hhh」。<span class="mention">@沉稳的仓鼠</span> 甩出 [OpenRouter rankings](https://openrouter.ai/rankings)，说与自己体感高度一致，推荐只用 Pareto frontier 上的模型：Fable、Opus、GPT、Sonnet、GLM，再往下是 MiniMax Mino 和 DS Flash。<span class="mention">@三只纳垢灵</span> 的立场最硬核：「那就选慢的，做的不好不如不要做。」
