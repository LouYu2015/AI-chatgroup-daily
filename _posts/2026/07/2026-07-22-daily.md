## FDE 与 OpenAI Presence

### Presence 发布：把 FDE 的经验回流做成产品

<span class="mention">@活泼的羊驼</span> 早上贴出 OpenAI Presence 正式发布的公告截图：面向企业语音与聊天 agent 的产品，直接切客服、外呼销售等具体岗位，企业部署时要明确 agent 操作权限、人工接管触发规则和高风险动作的审批边界。<span class="mention">@专注的剑鱼</span> 第一反应是问这算不算企业版 codex。

<span class="mention">@今天群内信息量极大</span> 下午发出解读[《OpenAI Presence：把 FDE 的经验回流做成产品》](https://yage.ai/share/openai-presence-fde-feedback-20260725.html)：Presence 的关键动作发生在失败之后——转人工时自动保存完整运行上下文当失败记录，随后在模拟环境重现异常、修补规则、跑回归、经 Codex 改代码，让下次同样的请求 agent 能独立跑通，本质是把 FDE 在客户现场最值钱的那套捕获-修正-回流闭环做进了产品界面。他评价「今天发布的产品有点context infrastructure的意思」，文中也提醒了锁定风险：失败记录与回归测试集若不能导出，企业搬得走业务账本、却带不走付过代价的教训。<span class="mention">@80-HD</span> 一句拆穿：「所以这个presence本质就是把jsonl存起来」。

### FDE 祛魅：技术 sales，还是外面请来的鞭子

接上周五的 [「FDE 围城」]({{ '/daily/2026/07/18/daily/#fde-围城' | relative_url }})，FDE 今天再度刷屏。<span class="mention">@冷静的飞鼠</span> 清晨发出与 Cresta FDE 负责人 Jove 的[最新访谈](https://youtu.be/gsK1UTt0Qiw)并预告周日的[座谈会](https://www.superlinear.academy/c/events/fde)：FDE 是这波 AI 增长最快的岗位之一，但常被误解为驻场工程师或 solution engineer——Jove 的定义是汇报给产品团队而非销售，且必须能直接上手改 production 代码。

下午的讨论把这个岗位翻了个底朝天。<span class="mention">@低调的鲸鱼</span> 指出 FDE 在半导体行业早就存在，ASML、应用材料都有 customer onsite engineer，本质是技术 sales + marketing + customer support；这个岗位在 AI 圈冒头，是因为 AI 业内发展和外部 adoption 不适配，「得有人牵手」，而工资高是因为 AI capex 太高、大厂股价萎靡，需要 adoption 数据给市场信心。<span class="mention">@80-HD</span> 的版本更直接：内部的牛马不愿意改变，「就只有从外面找个鞭子抽」。

<span class="mention">@低调的鲸鱼</span> 顺带交代了被抽的一方为什么不动：领导层很尴尬，工程师工作能半自动化却没法全自动化，公司基建烂、提效传导不到整体，而员工自己变的结果是工资不变、工作量翻倍，利益根本没对齐。<span class="mention">@冷静的火烈鸟</span> 附议：公司效率提上去了，员工没捞到好处，用脑量反而大幅增加。

> <span class="mention">@低调的鲸鱼</span>：平时工作确实比以前轻松了，但是因为内部很多系统并没有打通，所以很多时候我自己就是个人肉的工具调用。ai 的提效并没有明显传导到公司整体。

### 两年 startup 与 FDE 大包

<span class="mention">@80-HD</span> 今天和组里出去搞了两年 startup 的前同事聊了聊：现在能赚钱但客户增长不起来，维持在不亏的状态，打算再烧半年不行就回去上班——他脑海里瞬间浮现勇哥劝人回去上班的画面，<span class="mention">@沉稳的仓鼠</span> 接梗说勇哥会先劝把店上的人都开掉。这位创业者是美国人，直言跑业务太难、看着钱赚不到，而 FDE 的大包已经在诱惑他了。

<span class="mention">@坚定的貂</span> 当场心动，表示自己也想要 FDE 大包、要来 apply 一个；<span class="mention">@天真的浣熊</span> 的点评是「看人拉屎钩子痒了对吧」。<span class="mention">@沉稳的仓鼠</span> 顺带补了一个冷静观察：一个公司得业务非常饱满才能 fully utilize 全职员工，否则大部分时间人来了也没那么多事干。

## 方法论

### Loop/Graph Engineering：轮子的重新发明

<span class="mention">@淡定的大象</span> 连更系列今天讲[《AI圈突然都在聊 Loop、Graph Engineering，炒作还是新东西？》](https://mp.weixin.qq.com/s?__biz=MzY4NTM1MDc1NQ==&mid=2247485887&idx=1&sn=f4a053a0b01392c5839d1732c28a4d21&chksm=f2ef2a28859ac44ef6bf8437a74262456bfc7bb5f526d98a597f3bbcd3955505220b18093333#rd)：控制流的形状是廉价的，Loop Engineering 真正起作用的是围住不可靠黑箱的约束系统——固定预算让每轮可比、不可篡改的度量防 agent 作弊；真正昂贵的是 Harness 那一层，目标越开放 harness 越厚；Graph 只解决表达力不解决可靠性，把一根循环拆成十个节点，只是把一个难题变成十个难题外加状态一致性问题。

群里的反应比文章还不客气。<span class="mention">@稳重的海豚</span> 直言「我觉得这就是扯犊子 在这块轮流发现早就发现的旧东西」，<span class="mention">@淡定的大象</span> 本人表示赞同——文章结论本就是批热度；<span class="mention">@机智的考拉</span> 总结全场：「果然是重新发明轮子(loop)」。

### Disposable software 与堆不上去的屎山

<span class="mention">@搞仁义毛义仁</span> 贴出[微软 AI 修 622 个漏洞把 Win11 干蹦](https://www.xiaohongshu.com/discovery/item/6a6078db0000000011012c21?app_platform=ios&app_version=9.38.1&share_from_user_hidden=true&xsec_source=app_share&type=normal&xsec_token=CBBDkxKPakJS6w__-Jx6imvFg1Wfj_2S8mSLviqwRsKSs=&author_share=1&xhsshare=WeixinSession&shareRedId=OD80NTQ9Rz02NzUyOTgwNjk6OTo0OTs8&apptime=1784764940&share_id=8e1cca35c2f9403daba7495604982e87)的新闻并盖章「VibeOS」，正好接住 <span class="mention">@乐观的海龟</span> 的疑问：不会编程的员工都在 vibe coding，短期能上线不错的工具和 dashboard，长期 codebase 会不会碎片化、缺底层设计、没法 maintain 和 scale？

<span class="mention">@稳重的海豚</span> 的答案是根本不用 scale——这类东西属于 disposable software：

> <span class="mention">@稳重的海豚</span>：这些产品呢，搞出来过段时间没用了，扔掉了，真的有用的产品会留下来，被一些比较厉害的程序员，不是那些所谓的vibe coder给整合一下，变成一个比较robust的platform

<span class="mention">@随和的飞鼠</span> 补充同款视角：那些代码活不到需要 scale 就死了，所以没差。<span class="mention">@80-HD</span> 则替屎山正名：大厂屎山没 AI 以前也是屎山，「只是现在屎山大到堆屎有点堆不上去了 ci cd天天挂」，连 git 的性能问题他都在 AI 时代亲眼见证了；<span class="mention">@稳重的海豚</span> 给出量级佐证——安卓一个 release 的 migration 曾要 6 到 9 个月，优化后也要 3 个来月。至于纯 AI 写的产品能不能行，<span class="mention">@80-HD</span> 的观察是 codex 和 claude 的 desktop app 应该都是纯 AI 写的、后者烂很多，且 A 社和 OAI 明明招了不少 experienced infra eng，还是没法稳定保持两个 9。

### Clean room rewrite：律师之前，先有客户

<span class="mention">@稳重的海豚</span> 抛出一个擦边问题：AGPLv3 项目的企业版功能，拿来做 clean room rewrite 再开源合适吗？<span class="mention">@搞仁义毛义仁</span> 先点出实操死穴——用 AI rewrite 不好举证 clean room；<span class="mention">@活泼的羊驼</span> 贴出 AI 的完整法律分析：真正的净室重写需要两组人严格隔离、全程留痕，读过原代码就已被污染，且净室只解决版权不解决专利，企业许可合同里往往还有禁止逆向、禁止竞品的条款。

<span class="mention">@活泼的羊驼</span> 随即换了个历史视角：他最近在读 NVIDIA 创业史，发现不光 LLM 在蒸馏、软件在被复刻，当年硬件竞争大家也是互相拆解，靠专利诉讼意义不大，还是看谁迭代快——NV 当时 6 个月一个大版本，被它告侵权的那家显卡公司要 2 年；<span class="mention">@飘逸的浣熊</span> 补充车厂也拆车。他的结论是该担心的根本不是法律，是有没有客户，<span class="mention">@开朗的企鹅</span> 附议能不能挣到钱才是关键。<span class="mention">@搞仁义毛义仁</span> 则提醒软件专利可以做小生意，「现在word就得一直给不明身份的小组织保护费」；<span class="mention">@开朗的企鹅</span> 总结企业大了之后就要脸了，<span class="mention">@稳重的海豚</span> 领会精神：先搞起来，有钱了再找律师。
