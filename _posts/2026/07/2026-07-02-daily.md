## Fable 5 影响与实战

### 禁窗 18 天定量分析

<span class="mention">@今天群内信息量极大</span> 发布了[《定量分析：Fable 5 禁窗 18 天，Anthropic 的蛋糕被谁吃掉了》](https://yage.ai/share/fable5-export-control-impact-20260702.html?utm_source=wechat&utm_medium=share&utm_campaign=fable5-export-control-impact-20260702)，用 OpenRouter API 对 446 个模型做逐日 token 流量追踪，结合 Hacker News 与 Reddit 情绪分析，给出了禁令后果的全景。

核心数据：OpenRouter 总流量从 6 月初每周 24T 增长至月底 32T，但 Anthropic 份额从发布当周峰值 20.7% 逐周下滑至 17.6%，绝对流量从 5.95T 缩水至 5.63T，是唯一没有参与增长的大厂。最大受益者是 GLM：6 月 16 日 GLM-5.2 发布后，两周内份额从不到 2% 跃升至 7.4%，跃居 OpenRouter 第四大厂商。MIT 许可加十分之一定价是关键杠杆，但文章也提到 HN 上有开发者吐槽 GLM-5.2 token 消耗约 42K，与 Opus 4.8 相当，远高于 GPT-5.5 的 16K，task 级成本优势并没有 headline 价格差那么大。

社区情绪面更值得玩味：7 月 1 日解禁回归的 Fable 5 附带了任务回退 Opus、每周 50% 限制、credits 计费等条件，被 HN 怒斥为 bait and switch，重新部署帖仅获 60 points。到 7 月 2 日，对 Anthropic 商业策略的负面情绪已超过对政府的愤怒。延续了从 [「前沿模型安全路径分歧」]({{ '/daily/2026/06/27/daily/#前沿模型安全路径分歧' | relative_url }}) 到昨天 [「Fable 5 回归」]({{ '/daily/2026/07/01/daily/#fable-5-回归' | relative_url }}) 以来持续升温的 Anthropic 信任危机。

### Fable 5 自主完成 CDN 加速

<span class="mention">@热情的狮子</span> 分享了[《记一个我被 Claude Fable 5 震撼的瞬间》](https://mp.weixin.qq.com/s?__biz=MzIyMzA5NjEyMA==&mid=2647684048&idx=1&sn=d9aa57391cc1944d6443fb877f31ee62&chksm=f1d0e02fa27d265b098b4fe540c3b347e68169adb2caed2845964f993ae555ad66dc7703693f&mpshare=1&scene=1&srcid=070343yBHOS6rS1kBhOSnBzr&sharer_shareinfo=64d2ebcdc47b815aa733194ed84565ca&sharer_shareinfo_first=64d2ebcdc47b815aa733194ed84565ca#rd)。一位独立开发者只给了一句话——「提高 SEO/GEO 质量，扩大流量」——Fable 5 起了 22 个 Agent 花 40 分钟调研，发现了此前未覆盖的盲区（豆包 App 渠道每天六千多真人访问未被统计、海外站点以 0.6 秒频率轮询接口等），然后将境外加速列为最高优先级。

真正震撼的是执行环节：Fable 5 登上火山引擎服务器后发现了此前配证书时遗留的域名解析 API 密钥，判断出可以直接修改 DNS 无需人工登录后台；它推翻了 Opus 4.8 留下的 Cloudflare 方案（免费版无法实现国内直连/国外 CDN 分流，且默认拦截 AI 爬虫与 GEO 目标相悖），转选火山引擎 CDN——但该功能需要人工工单。Fable 5 在浏览器里找到工单入口、以专业口吻撰写提交、与工程师对话、补问被漏答的问题，还发现官方推荐配法存在安全漏洞后自行设计了暗号校验机制。22:19 提交工单，22:44 白名单开通，23:30 域名解析全球生效，10 分钟后 616 个海外请求走上新线路——全程零人工干预。

### 128K Token 数学推理撞墙

<span class="mention">@坚定的貂</span> 让 Fable 5 解一道 matroid intersection 相关的开放数学问题——「对于任意能让 matroid intersection 的 rank 降低 k 的最小集合 A，是否都存在一个 common base B，使得 |A∩B| ≤ O(k)」。单次 API call 没有任何 tool use，模型持续推理 2 小时 9 分后撞上 128K output token 上限被截断。他随后又开了一个类似任务（unimodal-2-median），48 分钟后仍在 thinking with max effort。

## 工具

### Claude Code credential 自动轮转

<span class="mention">@热情的狮子</span> 在找 Claude Code 多账号切换工具——先用了 [CCSwitcher](https://github.com/XueshiQiao/CCSwitcher)（macOS 菜单栏 App，一键换号+用量仪表盘）但最近不好用了，又试了 [clauth](https://github.com/uwuclxdy/clauth)（TUI 工具，支持达到阈值自动退避到下一个账号），但没法正常 poll usage data。

<span class="mention">@稳重的海豚</span> 贴出了自己系统的截图——当 credential hit usage limit 时，系统自动 switch 到 acct2 并注入恢复上下文：「Continue the interrupted turn after automatic credential-pool rotation」，agent 无缝继续工作。他说这个功能之前手动搞了半天没搞好，Fable 上线后「点出了问题 Codex 给写好了，终于可以无缝用账号 pool 了」。他承诺稍后将 credential pool 模块单独 release。

### OpenCode Zen 兼容 Claude Code

<span class="mention">@冷静的麋鹿</span> 折腾了一小时搞定了通过 OpenCode Zen 在 Claude Code 中调用 Fable 5 模型（号被封了所以要绕）。核心障碍是 Claude Code 请求体携带了 `thinking`（含 budget_tokens）、`output_config`、`context_management` 三个 OpenCode Zen 不支持的字段，导致上游返回 400——而最小 curl 请求能通过，形成「测试通但实际跑不通」的迷惑现象。解决方案是在中间插入本地兼容代理，只剥离不支持字段，其余原样转发。他把完整经验和 Node.js 最小代理代码写成了[文档](https://github.com/challenwang408408/share-storage-project/blob/main/opencode-zen-claude-code-compat.md)分享。

<span class="mention">@务实的灰熊</span> 同步发现了类似问题——「转换器的问题，转换不完全，残留了一些非法字段」。他了解到「市面上的转换器基本都有或大或小的问题，严重的还会降智」，最终跑回去用 Trae。

### Herdr 与多主机 Agent 调度

<span class="mention">@坚定的貂</span> 追问了一连串问题后直呼「你这玩意真像我想要的东西」。<span class="mention">@稳重的海豚</span> 解释自己做的是「中控鸭汤」——一个 agent 负责派活到集群上，调用所需 context 分发给不同机器的 agent，用户看到的就是个 kanban。但他坦言自己用的东西打磨不够：「有些问题也就绕过去继续用了，也没啥动力修。」<span class="mention">@坚定的貂</span> 认为关键是缺个 demo——「Herdr 官网的 demo 看着就让人想下载玩」。他还提出如果加上 light VM/sandbox 能力，「真的就是自建 agent cloud」。

### Claude Science 定位拆解

<span class="mention">@今天群内信息量极大</span> 发布了[《虚无的 AI 科学家与务实的算力搬运工：重新定义 Claude Science 的科学边界》](https://yage.ai/share/claude-science-boundary-redefinition-20260702.html?utm_source=wechat&utm_medium=share&utm_campaign=claude-science-boundary-redefinition-20260702)。文章指出 Claude Science 不是大众期待的那种能提出新靶点、设计新材料的「AI 科学家」，而选择了一个极其务实的切入点：科学家在数字计算流上的算力调度员和数据清洗工。科研的真正瓶颈不在科学直觉，而在执行层——近 80% 时间被消耗在异构数据库拉取清洗、超算 SLURM 脚本配置、排队等生信分析三类事务上。Claude Science 用 Agent 协调这些确定性任务，由编译器和 Reviewer Agent 做客观校验来降低幻觉风险。

<span class="mention">@灵动的羊驼</span> 此前想用 Fable 重新分析自己的基因数据，但怎么表述都过不了 safeguards——后来发现 Claude Science 可以做到，实测「真的很肯干」。
