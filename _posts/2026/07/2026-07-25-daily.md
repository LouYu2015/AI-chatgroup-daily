今天是 Opus 5 实测次日：第三方测评发现它靠饱和式自测换交付质量、综合成本反而可能反超 Fable，官方也首次劝用户别把 effort 拉满，是最值得细读的一组材料。凌晨 OpenAI 一场大宕机，白天换来全员 reset，群里有人痛失重置卡、有人懒人有懒福。方法论侧，读不进 AI 输出的困扰接上前两天的认知带宽讨论，还引出一篇认知科学论文。

## Opus 5 实测次日

### 第三方测评：饱和式自测，综合成本反超 Fable

接昨天 [「同等智能半价：上线即进 Copilot」]({{ '/daily/2026/07/24/daily/#同等智能半价上线即进-copilot' | relative_url }})，昨晚 <span class="mention">@热情的狮子</span> 连发两篇实测。[《Claude Opus 5 测评》](https://mp.weixin.qq.com/s?__biz=Mzk3NTI3ODI4MA==&mid=2247484715&idx=1&sn=12b76759e28cb758b50dd0eea81c5f5b&chksm=c5112d5ad78574f780110f663385378cee381d4558e5bce81b1627ed6386a7a7d1fc1ff27927#rd)的结论是基本功比 4.8 明显扎实：推理档同类问题 token 消耗只有前代六成，长文幻觉测试史上首次满分，3D 建模好于 K3。最大的行为变化是饱和式自测——前端对照需求逐个功能截图确认、后端能写超过 1000 个测试用例，大面上的交付问题几乎消失；代价是时间和 token 消耗极大，复杂场景综合成本可能反超 Fable，而关掉自测直出的代码 bug 率并不低于前代——A 社的策略显然是用长程细致 debug 替代一次写对。

另一篇[《实测Claude Opus5，系统提示语删了80%，半价还能逼近Fable5》](https://mp.weixin.qq.com/s?__biz=Mzg3MTk3NzYzNw==&mid=2247508794&idx=1&sn=12d7cfa252e99d6e57f1d9d126227a59&chksm=cf26b711f58ed53cf9859d2865a3722a8435bf6fe3fb9445d08cad730b35e2d782a977f44a0a#rd)聚焦提示词瘦身：A 社把 Claude Code 约 80% 的系统提示删了，删的是过量示例、硬性禁令和模型已能自主判断的部分，与 OpenAI 此前简化 system prompt 后评分升 10–15%、token 降 41–66% 的对照实验互相印证；文章还给出一套用 /doctor 把 skills 分成高频常驻、中频项目化、低频归档三档的实操方法。今天 <span class="mention">@稳重的海豚</span> 贴出系统提示的 diff 对照（红色是删掉的、绿色是 Opus 5 新加的），盖章 opus5 可以打。

群内体感同样正面：<span class="mention">@坦荡的灰熊</span> 对着 benchmark 全表感叹新模型好强，<span class="mention">@细心的熊猫</span> 说 opus 5 丝滑得很，「蹬起来感觉比fable还舒服」。

### 青春版还是去皮 Fable：router 猜想续集

昨天 [「榜单玄机：Mythos 混装列与 53.4 > 53.5」]({{ '/daily/2026/07/24/daily/#榜单玄机mythos-混装列与-534--535' | relative_url }}) 的 router 玩笑昨晚继续发酵。<span class="mention">@淡定的喜鹊</span> 发问：所以 opus5 是折扣版 fable？<span class="mention">@天真的浣熊</span> 给出两个版本——青春版，「或者也可能是去掉包皮的fable 5」，给自己一个台阶。

<span class="mention">@细心的熊猫</span> 的技术版猜想更认真：大模型降推理成本的路子太多、每个月都有新玩法，把 Fable 在推理上做点手脚直接当 Opus 5 发出来也不是不可能。至于隔壁的反应，<span class="mention">@随和的企鹅</span> 问「伪人公司也破防了么」，<span class="mention">@聪明的灰熊</span> 复读经典：「I smell fear」，这个梗永不过时。

### Effort 不是越高越好：官方劝你重扫一遍

<span class="mention">@专注的剑鱼</span> 注意到一个细节：这可能是 Anthropic 第一次在 model card 里把 effort 不用拉最高拿出来说——FrontierBench 的最佳值出现在 xhigh 而非 max，官方建议迁移时别机械复用 4.8 的配置、重新做一轮 effort sweep，优化目标应是任务成功率乘可验证质量再除以全链路成本，而不是最高档的 benchmark 分数。<span class="mention">@随和的企鹅</span> 现身佐证：sol 的 max 也不总比 xhigh 强，「想多了还想错了」。

他顺带抛出另一个疑惑：都这个程度了，codex status bar 里 sol 还是 256K context；<span class="mention">@天真的浣熊</span> 对照 Copilot 那边已经全是 1M，两边体验的差距暂时无解。

## 方法论

### 读不进 AI 输出与记忆悖论

<span class="mention">@博学的穿山甲</span> 坦承自己的困扰：agent 每次写一大堆，完全读不进也读不懂，让它写简单点又到处模模糊糊，不知道是阅读能力太差还是 agent 没调教好。他做 research，必须理解实现细节是否合理、对自己的研究负责，而 AI 的行文结构还很奇怪，经常冒出一段不知目的的解释。这正是 [「认知带宽：产出是库存，理解才是交付」]({{ '/daily/2026/07/24/daily/#认知带宽产出是库存理解才是交付' | relative_url }}) 的一线样本。

支招各有路数：<span class="mention">@敏锐的海狸</span> 说需要 <span class="mention">@今天群内信息量极大</span> 的 communication.md；<span class="mention">@沉稳的兔子</span> 提醒也看模型，4.8 这方面挺差劲，讨论和读单篇建议用网页版、写作水平高非常多；<span class="mention">@搞仁义毛义仁</span> 的立场最激进——不读就好了，文字没什么好看的，AI 用的英语也「自成一统」，问它只是为了 trigger 一下继续干活。

<span class="mention">@搞仁义毛义仁</span> 随后贴出一篇正中话题的论文《The Memory Paradox: Why Our Brains Need Knowledge in an Age of AI》（Barbara Oakley 与 Sejnowski 等合著）：外部辅助越强、内部记忆系统越可能萎缩，过早依赖 AI 会抑制程序化掌握与直觉形成，有效的人机协作反而依赖强大的内部 schema。他自己的感想是「居然有人去研究了我之前群里灌的水」，<span class="mention">@沉稳的兔子</span> 总结：你的问题也是别人的问题。
