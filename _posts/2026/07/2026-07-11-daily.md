今天是 GPT-5.6 上手第三天，最重磅的一条来自 <span class="mention">@坚定的貂</span>：他 2024 年论文里的 open problem 被 gpt-5.6-sol ultra 用 46 分钟解决，Fable 复核「说是对的」——「5.4 时代才第一次解决我们觉得有点重要的问题，但 5.6 是把我彻底碾压了」。另一条主线是 OpenCode 里冒出来的 Sol Pro：从「真 Pro 还是套壳」的全群侦探戏，到 <span class="mention">@今天群内信息量极大</span> 抓包实测揭晓 Pro 根本不是模型 ID、而是 reasoning.mode 的一个取值，并连夜写成解密文章；配套的 token 账本同样精彩——5.6 悄悄对 cache writes 收费被小红书实锤「变相涨价」，<span class="mention">@热情的狮子</span> 的「两天 190 亿 token」之谜最终归因于 98% 的 cache read，goal 蹬进 43% 赤字的玩法也有了完整攻略。

行业侧有推特爆料称 Anthropic 内部会议紧张、正推动把 Fable 5 永久留在订阅里，群友顺势展开「模型即 commodity」的补贴经济学讨论；工具侧 <span class="mention">@今天群内信息量极大</span> 把 Anthropic 官方认证考试破解成模拟题库，<span class="mention">@三只纳垢灵</span> 和 <span class="mention">@冷静的麋鹿</span> 双双 13/18 过线。花絮区则由 0 糖王老吉考据和「张雨绮征婚要求会 harness」承包。

## Sol Pro 与烧钱账本

### 真假 Pro：OpenCode 里的意外羊毛

昨天 [「OpenCode 解锁 GPT-5.6 Sol Pro」]({{ '/daily/2026/07/10/daily/#opencode-解锁-gpt-56-sol-pro' | relative_url }}) 的发现今天全面发酵。<span class="mention">@冷静的麋鹿</span> 一早定性：「感觉这是个漏洞，应该很快会封住。因为 codex 都不允许用的东西，居然允许第三方调用，这个感觉不太合理」——他从来没敢用 API 调过 GPT Pro 干活，「贵的实在是有点离谱」，如果是真 Pro 那就是「一波大羊毛」。<span class="mention">@80-HD</span> 的反应最直接：「抓紧用了」，让它点评自己几个项目「赶紧薅一把」。

真假之辩随即展开。<span class="mention">@风趣的海豚</span> 实测发现选「GPT-5.6 Pro」会报错 not supported，但「GPT-5.6 Sol Pro」畅通无阻，模型列表里 Luna Pro、Terra Pro 一字排开——「pro 太多了」「我已经有点无法理解 gpt 的产品逻辑了」。支持真 Pro 的证据有两条：一是慢，<span class="mention">@冷静的麋鹿</span> 说它「比 5.6 sol 的任何模式都慢出一个数量级」，<span class="mention">@80-HD</span> 一个任务跑了 40 分钟还没结束；二是文风，<span class="mention">@冷静的麋鹿</span> 判断「gpt 其他模型系列，写不出这种 ai 味道比较少的文字」。<span class="mention">@开朗的企鹅</span> 则反向发现 ChatGPT app 里 chat 的 Pro「特别特别快」、和浏览器里完全不一样，怀疑那个才是假 Pro。至于大家最关心的「占不占额度」——答案是占：<span class="mention">@开朗的企鹅</span> 确认走的是 codex plan 的 token，<span class="mention">@风趣的海豚</span> 拿它跑长任务 20 分钟用掉 5 小时额度的 15%，结论是「确实是蹬出火星」。

### Pro 只是 reasoning.mode：三维度实测

解密由 <span class="mention">@今天群内信息量极大</span> 完成。他先断言「effort 是 effort，pro 是 model id 里面带 pro」，随即「我验证了一下，自我打脸」——实测抓包显示 OpenCode 里的 Pro 和 Fast 根本不是新模型 ID：Sol Pro 实际请求是 `model: gpt-5.6-sol` + `reasoning.mode: "pro"`，Fast 则是 `service_tier: "priority"`，而且 mode、effort、service_tier 三个维度可以自由组合，一次请求可以同时开 pro + xhigh + priority。<span class="mention">@飘逸的浣熊</span> 补充官网口径：GPT Pro 是 parallel test time compute，「感觉就跟 gemini 的 deep think 差不多，同时进行多次尝试然后合并结果」。实测还发现开 Pro 后同一句简单问候的 input tokens 从 12 变成 1,527，<span class="mention">@今天群内信息量极大</span> 淡定总结「也就贵了 100 多倍吧」。

他当晚把整套调研写成[《GPT-5.6 Sol Pro Max Fast：这个玩笑为什么成立了》](https://yage.ai/share/gpt-5-6-sol-pro-max-fast-20260713.html?utm_source=wechat&utm_medium=share&utm_campaign=gpt-5-6-sol-pro-max-fast-20260713)：这个 model ID 并不存在，但每个后缀都对应一个独立可组合的控制维度，Ultra 则是产品层的多智能体编排、API 开不了。<span class="mention">@三只纳垢灵</span> 摘出文中一句「如果发现输出的逻辑质量不佳，应当提高推理投入度或调整推理模式，而不是在提示词中拼命塞语气词」，<span class="mention">@今天群内信息量极大</span> 自己都懵：「怎么感觉中枪了」，并坦白进化路线——「我现在已经超越了辱骂 AI 的层次，来到让他辱骂自己了」。

### Sol Pro 版最后一封信

<span class="mention">@冷静的麋鹿</span> 用 Sol Pro 重玩了 7 月 9 日 [「让 AI 读完全部仓库写一封信」]({{ '/daily/2026/07/09/daily/#让-ai-读完全部仓库写一封信' | relative_url }}) 的游戏，并把结果发成[博客](https://challenwang.com/essays/gpt56-sol-pro-letter-20260711.html)。对比很鲜明：Fable 写的最后一封信是工程师视角——劝他赶紧补几个漏洞、把有风险的 key 挪个位置；5.6 Pro 的信则直指结构性问题——他太擅长把一切变成系统，连生活也可能变成一套需要持续维护的系统，最后压成一句「不要让你建立的系统占满它原本要替你守护的人生」。他的评价是「这封信写的比之前 fable 写的有人情味儿多了」，而且从文风上「几乎可以百分百确定这是 pro 模型」。

### 写作从换语言进化到真分析

### 5.6 的多疑：非要自己跑一遍测试

<span class="mention">@三只纳垢灵</span> 把自己的编译器项目 VlppParser2 喂给 5.6：「感觉 5.6 能经受住考验了，5.5 反正是一点都没法做」——让它 scan 出算法 report、分析距离实现 C++26 还有多少 gap，终于算出了答案，代价是一小时烧掉 140% 左右的 5hr rate limit，结论是「这还是一个不舍得给钱就 vibe 不了的项目，依然有古法的空间」（<span class="mention">@天真的浣熊</span> 确认他全程只用 ultra，感叹「上班用不了 ultra」，得到的建议是「没事 xhigh 猛蹬」）。

另一个观察是 5.6 多疑到近乎失礼：他告诉模型 test case 已经覆盖了所有实现的 feature，5.6 依然「吭哧吭哧地对比 C++ 的标准文档」，觉得他说的话不够 promising，「一定要自己跑一遍 test case 确定我没有骗他」。<span class="mention">@冷静的麋鹿</span> 认出这个行为模式——他的 AI 在多次被错误指令带偏后，自己总结出了「基于事实而非基于用户指令，因为指令可能是主观的」这条规则，除非明确叫停否则一律自行验证。<span class="mention">@三只纳垢灵</span> 确认自己并没有下过这样的指令，是 5.6 天生如此。

### Cache writes 收费：额度不耐用的真相

<span class="mention">@睿智的北极熊</span> 转发小红书帖[《终于知道codex5.6额度不耐用的原因了》](https://www.xiaohongshu.com/discovery/item/6a51a8200000000008003aec?app_platform=harmony&app_version=9.36.0&author_share=1&share_from_user_hidden=true&type=normal&xsec_source=app_share&xsec_token=CBr7MpKoWZUIU-CKZ3GZvDKoD3U2fKEh4iHrQT4DZaNeE=&xhsshare=WeixinSession&xstag=1)并贴出官方 pricing 表：GPT-5.6 基础价没涨（Sol 仍是 $5/$30），但新增了 5.5 时代免费的 cache writes 收费项（短上下文 $6.25/M、长上下文 $12.5/M），Codex 长任务成本可能达到 5.5 的 2 倍以上——「学坏一出溜」。<span class="mention">@天真的浣熊</span> 表示早发现了，并顺手拉了个平：「Claude write cache 一直是收费的，也没见大家有怨言。」

### 190 亿 token 之谜：98% 是 cache read

<span class="mention">@热情的狮子</span> 深夜惊呼「我 chovy，两天怎么烧了 190 亿 token」，起初怀疑是自己写的统计 CLI 没适配新模型，结果 AI 审计报告显示计数没错：真实用量 10.1B/天，其中 98.2% 是 cache_read（9.92B），fresh input 只有 141M、output 28M——机制是 gpt-5.6-sol 的长 loop 每次 API 调用都要重读整个会话上下文，平均 ~156k cached tokens/次 × 当天 63,611 次调用 ≈ 9.9B。按 cache read 只有 fresh input 约 1/10 的等价计价，当日成本视角是 $1,829。<span class="mention">@三只纳垢灵</span> 的诊断只有四个字：「高血脂了。」

后续还有个反转：codex app 官方统计当日只有 2.5B，<span class="mention">@热情的狮子</span> 排查发现是 tokscale 在 collab/swarm 模式下重复计数——每个 subagent 文件里镜像记录了 main loop 的 token count。他顺手安利了自己的账本方案：tokscale 每台机器独立统计（「挺准的，和 codexapp 报的差不多」），再用 turso db 聚合，「turso 这个 free tier 非常 generous」（100 个库、5GB、月读 5 亿行），对比结论是「supabase 太贵了」。

### 超 5h 蹬进赤字与 reset 卡的坑

昨晚 [「午夜第三次 reset：蹬车社会学」]({{ '/daily/2026/07/10/daily/#午夜第三次-reset蹬车社会学' | relative_url }}) 之后，今天进入善后与攻略阶段。<span class="mention">@活泼的树懒</span> 确认「周末有两次 reset，这波已经结束了」，并猜测频繁 reset 可能是在给自家额度计算 bug 找个体面的名义——<span class="mention">@豁达的灰熊</span> 正好撞上额度计算异常，「准备 report 一下，看看能不能再给我张卡」。<span class="mention">@神秘的麋鹿</span> 则提出另一种阴谋论：这是标记重度用户行为的方式，「然后就可以出一些细分套餐」。也有人被 reset 伤到：<span class="mention">@稳重的海豚</span> 的 weekly 被清零但 5h session 不重置，「Quota 没用完太难受了」「还不如给 reset 卡」。

goal 的「赤字蹬法」今天被摸清了全貌，接上前天 [「到量不断线：Codex 的好习惯」]({{ '/daily/2026/07/10/daily/#到量不断线codex-的好习惯' | relative_url }})：<span class="mention">@三只纳垢灵</span> 发现现在超过 5h 额度会继续消耗 weekly，<span class="mention">@热情的狮子</span> 大赞这个设计——「Claude 直接给你停了，这个可以一直对着 goal 猛干」，并估算 20x 套餐的 weekly 上限约 2-3B token。<span class="mention">@沉稳的仓鼠</span> 贴出面板实况：session 剩 0%，weekly 43% left / 43% in deficit，「amazing！我的 session 显示没有了但是 /goal 还在跑！」<span class="mention">@专注的剑鱼</span> 补充规则细节：通常多消耗 10% 之后 goal 会自动停止，得等 5h 刷新——但客户端可以反复按 goal 的启动按钮，「我老婆亲测是按 10 几次，就有概率可以让他接着蹬」。<span class="mention">@三只纳垢灵</span> 的反应从「？」到「机魂大悦！」再到「我的打印机没墨了，怎么还在往外印刷.jpg」。

<span class="mention">@专注的剑鱼</span> 还同步了一个昂贵的坑：Codex 重置卡显示的截止日期（比如 7 月 12 日）其实是当日 0 点，「等于说得在 7 月 11 日 23 点 59 分就用掉」。<span class="mention">@沉稳的仓鼠</span> 给本月定调：「Codex 这个月有点发疯，感觉已经快 100X 补贴了。」

### SK 海力士：内存即服务

## 方法论

### 哥布林与三明治：DND 规则引擎

<span class="mention">@稳重的海豚</span> 兑现了 7 月 8 日 [「模拟经营界面养 agent」]({{ '/daily/2026/07/08/daily/#模拟经营界面养-agent' | relative_url }}) 里的游戏瘾，贴出与 ChatGPT 深聊的 LLM DND 设计：玩家输入「我脱掉鞋，踩着桌子冲过去，用三明治砸哥布林的眼睛」，系统不能只当一个动作处理——先拆成 Intent + 五步 Atomic Actions + 相关 Checks，再生成标准化 JSON 动作对象（intent: blind_target、tool: ham_sandwich_04、difficulty: 14），最后交给规则引擎跑 d20 判定，大成功是「三明治黏在脸上，Blinded 2 回合，士气下降」，大失败是「三明治散开，引来附近的狗或怪物」。核心思路是 AI 负责理解与规划、canonical state 负责事实、validated delta 负责改变世界——ChatGPT 还翻出 2026 年一篇 LLM 世界模拟研究佐证这套 Plan → Diff → Validate → Apply 架构，<span class="mention">@稳重的海豚</span> 哭笑不得：「这就布置了一个阅读任务…」

更野的是 Mint Skill 系统：玩家先发明行为，系统观察成熟后铸造成技能，用 Creative Contribution Score（原创时间权重 × 行为独特性 × 跨场景复用 × 反刷分系数）防止「脱左鞋、脱右鞋、赤脚踩草」灌水，首创者获得 Founder Variant、名字永久写进世界历史。Knowledge 层则把世界真实与角色认知分开——三明治确实沾了哥布林口水，但玩家不知道、哥布林知道，「这会产生鉴定、欺骗、调查、谣言、秘密和误判」。他自问「这会有人想玩吗[Doge]」，看到 turso 免费额度后自答：「这游戏可以搞起来了。最近觉得，搞好玩的。」
