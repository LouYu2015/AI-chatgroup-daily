今天群里被 Grok 刷屏：从 300 刀的 SuperGrok Heavy 到 Twitter Premium+ 白送的订阅，再到有损音频碾压 GPT Realtime 的语音链路，一天凑齐了入伙 token plan 全家桶的全部理由。行业侧 OpenAI 把 GPT-5.6 Luna 降价八成、给 Sol 上了 Fast mode，翁荔裸辞 48 小时闪电回归领 RSI 团队也值得一读。最有嚼头的是晚间那场搞钱 vs 搞 harness 的辩论——铲子做得再精美，不如旁边上手直接薅。

## Grok 订阅全家桶

### SuperGrok Heavy 300 刀：深不见底的额度

<span class="mention">@沉稳的仓鼠</span> 宣布 Grok 也开出 300 刀 plan，正式进入 token plan 全家桶时代，并晒出 codexbar 里的八家图标：Codex、Claude、Cursor、Antigravity、z.ai、Kimi、Ollama、Grok。他顺带感慨 codexbar 是龙虾哥的项目、想必是「AI Slop 集大成」，而 OpenAI 也不去 sue 一下——对比 Anthropic 就会 sue Clawdbot，<span class="mention">@80-HD</span> 总结都是自家人。<span class="mention">@热情的狮子</span> 补上价格页：SuperGrok Heavy 前三个月 67% off、99 刀一个月，之后恢复 300 刀。

实测数据惊人：<span class="mention">@沉稳的仓鼠</span> 从昨晚开始用 Grok CLI，一晚（7 月 29 日 21:59 到 30 日 05:59）就蹬掉 3.23 亿 token，weekly 额度条却还显示 99% left。他的体感是这个 plan 的 token「深不见底」，可能在 20 到 30 个 billion 级别，等测出一个月到底能用多少再来分享；<span class="mention">@稳重的海豚</span> 支招测个 5% 消耗就能外推。连带效应是他打算取消 kimi coding plan——同样 200 刀级别差得太多。

彩蛋是内容审查：<span class="mention">@沉稳的仓鼠</span> 才发现 Grok 可以随意生成 18 禁内容，<span class="mention">@80-HD</span> 补充推上有人只是 prompt 了亚洲美女就出了 nsfw 图，<span class="mention">@热情的狮子</span> 评价这分类像古早网站。

### Premium+ 白送与 30 刀账本

<span class="mention">@今天群内信息量极大</span> 中午的大发现：Twitter Premium+ 自动附带 Grok plan，还能接 opencode——他和 <span class="mention">@稳重的海豚</span> 都开着 Premium+ 却从没用过 Grok，齐呼「亏大了」。他最近在 Cursor 上大量用 Grok 4.5 感觉相当可以，还让 Grok 自己找配额 API：它开了 Playwright、找到一个 gRPC call、解码 protobuf，最终给 [ai_usage_dashboard 交出 PR](https://github.com/grapeot/ai_usage_dashboard/pull/30)，任务并不 trivial 但很靠谱——代价是一周配额直接蹬没三分之一。

账本随即算清：30 刀档一周约 80M token，按官方价折算 42.56 刀，一个月约 170 刀 token 量，对比订阅费是 reasonable 的；坑在没有 5 小时限额、只有周限额，他 5 小时就蹬满了整周。对照之下 <span class="mention">@沉稳的仓鼠</span> 一晚 3 亿多 token 相当于蹬了 285 刀，<span class="mention">@今天群内信息量极大</span> 判断要么 Grok 补贴巨大、要么 CLI 计费有别的口径。API 直接付费则根本不敢用：input 2 刀 output 6 刀每百万，稍一蹬四五十就没了，<span class="mention">@沉稳的仓鼠</span> 总结没有 coding plan 早就破产了，还是要 Coding plan maxxing。

横向对比也有人泼冷水：<span class="mention">@冷静的麋鹿</span> 说 Claude 20 刀的 pro 蹬满一个月能到 400 左右，<span class="mention">@直率的鸵鸟</span> 觉得算下来还是 OpenAI 最划算——<span class="mention">@今天群内信息量极大</span> 自己的账印证：20 刀的 Cursor 上月蹬了 400，codex 上周蹬了 2400。斩杀线的前情见昨天 [「Cursor 倒贴 20 刀与斩杀线名单」]({{ '/daily/2026/07/29/daily/#cursor-倒贴-20-刀与斩杀线名单' | relative_url }})。插曲是「蹬」这个词本身：<span class="mention">@热情的大象</span> 感叹不知道谁发明的、太形象了，<span class="mention">@谨慎的松鼠</span> 说要站起来蹬，<span class="mention">@洒脱的猫头鹰</span> 补上前半句「扶我起来」。

### Grok Voice 续评：口音、有损音频与 3.3 秒

昨天 [「Grok 彩蛋：能爬 X，STT 又便宜又快」]({{ '/daily/2026/07/29/daily/#grok-彩蛋能爬-xstt-又便宜又快' | relative_url }}) 之后，<span class="mention">@今天群内信息量极大</span> 今天给出更完整的技术评估。最戳他的是口音处理：GPT Realtime 老把他说的 skill 识别成 scale，Grok 坚持认定他是标准英语，说什么出来都是对的，「情绪价值拉满」；准确率虽略差 GPT，但便宜 10 倍，还带 diarization 和时间戳。

速度差距则是架构性的：Grok 支持有损音频格式，一段五分钟的音频连传输在内 end-to-end 3.3 秒搞定；GPT Realtime 只能吃 24kHz 无压缩 PCM，光传音频就要十几二十秒，后端再快也没用，之前攒的各种奇技淫巧都不需要了。他已把 Grok 接入 AI Builder Space，配套的 [VoiceFlow Kit](https://github.com/grapeot/voiceflow/tree/master) 是个 skill，扔给 AI 就能给任意 iOS/Android app 内置实时语音识别，Grok 后端的 PR 还在等 merge，<span class="mention">@80-HD</span> 已经排队开蒸。

本地派也有支线：<span class="mention">@神秘的麋鹿</span> 电脑上一直用本地 ASR 模型，<span class="mention">@开朗的企鹅</span> 推荐 qwen 3.7 asr，他在 6G 显存的 3060 笔记本上日常跑，还顺手贴了 HF 的 Speech To Speech 开源 pipeline（VAD→STT→LLM→TTS，全组件可换）。

### 中文写作横评：Gemini 仍是最强

<span class="mention">@热情的狮子</span> 追问 Grok 写中文小说怎么样，<span class="mention">@今天群内信息量极大</span> 还没试过，但顺势给出一版写作排位：Gemini 还是最强，比 GPT-5.6 Sol 好太多，Opus 4.6 挺好，GPT 蛮差，GLM 一般般、Kimi 未测；<span class="mention">@随和的老虎</span> 附议 GPT 写作确实不太行。

讽刺的是 coding 侧正相反：<span class="mention">@沉稳的仓鼠</span> 说现在就等 Gemini 能像个人样、搞一个斩杀线以上的 model，<span class="mention">@热情的狮子</span> 补刀 Gemini 还是非人类——写作之王进不了 coding 斩杀线名单。

<span class="mention">@豁达的灰熊</span> 转来[《别再用 TUI 的 Claude Code 了》](https://mp.weixin.qq.com/s?__biz=MzA4NzgzMjA4MQ==&mid=2453486768&idx=1&sn=a2427ca6f03829d3e4b0d9aaafa2c609&chksm=86a0b95a42ab65e0a338b13968e4fcc528174bc4cedfe866e77fa2ee5ec48c979fd89d31dbf1#rd)深表同感：查看子 agent、切模型、管理分组 session，桌面端体验全面超过 TUI。他自嘲之前坚持 CLI 纯粹是看厉害的人都用 CLI，连同当年用 vim、买 hhkb 一起「也都有点叶公好龙」；现在的真实状态是——

### Paseo、orca 与 harness 壁垒

晚间客户端选型继续：<span class="mention">@豁达的考拉</span> 更喜欢 Claude Code 桌面版但它不支持服务器，于是通过 Paseo 用网页版 Claude Code，主流 agent 加手机都支持；他试过一些类似 agent，对他 llm-wiki 格式的 memory 支持都不好、老要返工，最后还是回到 Claude Code。<span class="mention">@开朗的企鹅</span> 坦白自己不是在用 Paseo 而是在抄：它的 GUI 模式挺好（比如把输出分成重点/全部/消息/工具四档过滤），但非要自己搞 harness 没必要，应该直接接 codex 或 Claude Code，和它们正面竞争看不到好处。<span class="mention">@坚定的貂</span> 则看上了 orca——GUI 版 herdr，顺带吐槽 TUI 有时只想看回复、不想看 tool calling 都做不到。

由此引出壁垒之辩：<span class="mention">@神秘的企鹅</span> 认为 harness 没壁垒——不是技术壁垒，是用户转换没壁垒，和大模型一样；<span class="mention">@洒脱的猫头鹰</span> 觉得还是有一点，他最近 codex 用爽了、切回 Cursor 就很不习惯；<span class="mention">@豁达的考拉</span> 给出最实在的锚点：最重要的是 memory 要能带走。

### Codex voice：语音指挥的雏形

<span class="mention">@洒脱的猫头鹰</span> 发现 codex 的语音可以直接给某个 session 发消息，实测能切对话、切模型，就是有点慢不如手动；<span class="mention">@开朗的企鹅</span> 点破本质——用语音发消息其实就是让 codex 的一个 session 去操作 codex。他已把键盘快捷键改成一键启动 voice 模式，愿景更远：

> <span class="mention">@开朗的企鹅</span>：我是希望不用拿手机出来，通过蓝牙耳机就可以完全帮我做opencode_ios_client里面的各种事情（更进一步就可以用AR眼镜来操作了）"Hi，鸭鸭，XXX的session你让他别问我了，继续干活""开一个新的session，把那个XXX的项目给做了"

<span class="mention">@80-HD</span> 判断这就是 <span class="mention">@今天群内信息量极大</span> 几个月前说的语音操作一切：开一个聊天 session 当入口、干活让它自己开新 session 不污染上下文，目前缺点是没法一脚触发；他还建议弄个电话号码让 AI 做完打电话确认，<span class="mention">@稳重的海豚</span> 表示已经做了——目的是让 AI 以他的名义给别人打电话，还因此第一次撞见 sip trunk 这种问题。落地限制也很真实：<span class="mention">@稳重的海豚</span> 发现在家里语音干扰太多，<span class="mention">@80-HD</span> 确认只有一个人在家才好用。

横向对比一句定调：<span class="mention">@今天群内信息量极大</span> 说 Codex 的语音识别是所有流行 harness 里唯一能用的，Claude Code、Antigravity 和 Cursor 做的都是一坨屎；<span class="mention">@天真的浣熊</span> 替 Copilot CLI 喊冤——玩屎也不拉上我。彩蛋是 <span class="mention">@洒脱的猫头鹰</span> 的桌面小宠物（前情见 7 月 25 日 [「AI 京剧与 Codex 桌面宠物」]({{ '/daily/2026/07/25/daily/#ai-京剧与-codex-桌面宠物' | relative_url }})）现在可以点语音了，<span class="mention">@80-HD</span> 挑剔就差个热键 mute/unmute。

### DIY 语音输入模仿者与 unicode 键盘之谜

昨晚 <span class="mention">@坚定的貂</span> 转来视频：有人看到 <span class="mention">@今天群内信息量极大</span> 的鸭板后也做了一个，用 whisper 加 Android 模拟蓝牙键盘，还准备把 ASR 换成豆包。<span class="mention">@风趣的企鹅</span> 紧急劝阻：他们之前做 OneOneTalk 被豆包坑惨了，ASR 还是科大讯飞。<span class="mention">@今天群内信息量极大</span> 的点评切中场景本质：对着安卓手机讲话给电脑打字，技术难度低但意义存疑——电脑上限制很小，为什么不直接对着电脑说话？他做硬件的原因恰恰是 iOS 输入法禁联网禁麦克风，只剩蓝牙键盘这条通路（前情见昨天 [「鸭板换板：M5Stack 到货即语音输入法」]({{ '/daily/2026/07/29/daily/#鸭板换板m5stack-到货即语音输入法' | relative_url }})）。

中文输入的死结也被掰开了：<span class="mention">@开朗的企鹅</span> 问能不能做个含全部中文的 unicode 键盘，<span class="mention">@今天群内信息量极大</span> 调研过——蓝牙键盘 HID 协议只能发键位不能发字符串，还贴出一张几百键的圆形巨型键盘图，盛赞它「像扬琴一样给你两把锤子」。深夜 <span class="mention">@开朗的企鹅</span> 贴出 AI 给的完整方案：第一版工程验证走自定义 BLE GATT 发 UTF-8、配套 iOS App 塞剪贴板、再模拟 Cmd+V，正式方案则是 iOS Custom Keyboard Extension 用 textDocumentProxy 插入整串文本——但第三方键盘有激活和银行 App 封禁问题。<span class="mention">@天真的浣熊</span> 顺带解惑：微信语音输入根本不是键盘，只是在自家输入框里实现了 mic。

### ClaudeSkills 升级四旗舰

### 把 UI 渲染成缩进文本给 agent

### 跨模型横评怎么做

## 方法论

### Library ownership：scope 变大后的新麻烦

聪明的老<span class="mention">@随和的老虎</span> 报告一个新问题：自从 5.6 sol 拿到更大的 scope，判断每个 library 的 ownership 变成了显著难题。他要 deliver 的 library 不可能让模型瞎搞，更不能 demo app 跑通就算完；以前模型不够牛逼、scope 从没跨越过边界，每个 library 负责什么都由他决定，现在尝试让模型根据 knowledge base 自己判断归属，效果不行——「革命尚未成功，同志仍需努力」。这与前天 [「太聪明的边界感：从路径指引到验收边界」]({{ '/daily/2026/07/28/daily/#太聪明的边界感从路径指引到验收边界' | relative_url }}) 是同一枚硬币：能力放开后，边界要重新发明。

### 搞钱 vs 搞 harness

<span class="mention">@坚定的貂</span> 一句想写自己的 harness，引爆了全天最热的辩论。<span class="mention">@稳重的海豚</span> 血泪劝退千万别搞，<span class="mention">@80-HD</span> 建议实在想就去折腾 pi；<span class="mention">@沉稳的仓鼠</span> 则直接掀桌：/goal make 1mm，大家别忘了搞钱，搞到钱了再去搞什么 harness。<span class="mention">@洒脱的猫头鹰</span> 道出技术人的窘境——harness 怎么搞大概知道，钱怎么搞几乎一无所知，<span class="mention">@沉稳的仓鼠</span> 的回应意外地励志：

> <span class="mention">@沉稳的仓鼠</span>：这个世界上有几亿人都在搞钱所以搞钱肯定是一个显性的东西但是搞 Harness 一共才多少人……所以一无所知并不重要，重要的是只要开始研究，就一定会有答案

<span class="mention">@沉稳的兔子</span> 表示那我打算翻开刑法。反方证据也很扎实：<span class="mention">@80-HD</span> 给出判词「把铲子做得无比精美，但是不如旁边直接上手薅的快」，今天还有朋友问他要不要做管理系统，他让对方先找到愿意付钱的客户再说；<span class="mention">@洒脱的猫头鹰</span> 现身说法——工作上搞了两年 terminal、最近折腾了个 terminal 玩具，出门一看满世界 agent 写的 terminal，好多推广帖连一个回复都没有；<span class="mention">@灵动的北极熊</span> 总结不要给程序员做工具，这是红海。

结局充满戏剧性：<span class="mention">@坚定的貂</span> 晚间宣布「决定了 手搓math harness」——他的理由是数学 harness 和 coding harness 不一样，<span class="mention">@洒脱的猫头鹰</span> 也认可这种垂直场景适合数学加技术的 1+1>2。

### 人有人的用处：成本病与反向订阅

<span class="mention">@安静的树懒</span> 贴出 CCCF 上郭毅可的《人有人的用处》：维纳 1950 年写下的不是安慰而是进攻性命题——人与机器是共同进化的物种，机器越强人就必须越深刻，当机器接管所有可计算的劳动，剩下的专属领地是人文，过去人文是选择、现在人文是答案。<span class="mention">@活泼的羊驼</span> 认可文章，但对文中养孩子式训练模型的路径存疑：AI 需要海量数据，只靠一个人喂远远不够。

他顺势展开了两段经济学注脚：科斯之问——公司之所以存在，是因为使用市场本身有交易成本，当摩擦成本超过内部管理成本，你就会雇佣而不是外购；以及 Baumol 成本病——1826 年演一首贝多芬弦乐四重奏要 4 个人 40 分钟，1966 年还是 4 个人 40 分钟，生产率停滞部门的相对价格只涨不降。<span class="mention">@80-HD</span> 的接茬把两者焊在了 AI 时代：「公司就是反向的subscription plan，老板站起来蹬就能多压榨出usage」。

支线是一场观点勘误：<span class="mention">@80-HD</span> 引 <span class="mention">@沉稳的仓鼠</span> 之前不要给公司多干活的说法，<span class="mention">@活泼的羊驼</span> 纠正他领悟错了——原意是副业只能做可长期积累、可脱手的那种，认真做好本职工作才是真正的 alpha 或 beta。<span class="mention">@稳重的海豚</span> 自嘲主业是 beta 副业也是 beta，自封 beta 之王。

### <span class="mention">@淡定的大象</span>连更：排列组合与组合泛化

<span class="mention">@淡定的大象</span> 今天的连更是[《高中背到头秃的排列组合，其实解释了大模型为什么不可能靠背、只能靠学》](https://mp.weixin.qq.com/s?__biz=MzY4NTM1MDc1NQ==&mid=2247486085&idx=1&sn=2bb0c5e796a67aec99ff420fbda6e5e7&chksm=f2091045731389e801598b96516aa835db6465bc49d139f696ae05c5b93aad9f2814e2ea35d2#rd)：20 个词的短句在 5 万词表下有 50000^20 种排列——一个 94 位数，超过可观测宇宙的原子总数，所以模型只能习得部件与组合规则做组合式泛化，生成时再用贪心或 Beam Search 把 V^L 的不可能拆成 L 次 V 选一。群里没讨论，连更惯例照登。
