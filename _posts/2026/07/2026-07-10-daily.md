今天是 GPT-5.6 Sol 上手第二天，昨天的跑分之争在实战里迅速收敛成一个共识性的角色定位：Sol 是「踏实但不聪明的打工人」——<span class="mention">@开朗的企鹅</span> 夸它「比 5.5 少了很多鸡贼和摸鱼」，<span class="mention">@淡定的雪豹</span> 总结「贼适合打工，就是探索性不如 fable」，而 <span class="mention">@随和的老虎</span>、<span class="mention">@天真的长颈鹿</span> 的翻车案例则证明掌舵的还得是 Fable。最值得细读的是围绕 Ultra 档展开的烧钱学与省 token 打法：<span class="mention">@风趣的企鹅</span> 三次 8 分钟打爆 5 小时限额、<span class="mention">@三只纳垢灵</span> 算出「$200 才能无脑 5.6 ultra」，群友的收敛方案是高级模型做规划验收、subagent 用快模型干粗活；配套的还有 Codex「到量不断线、先把任务收尾」的好习惯，被拿来对比 Claude 的一刀切。

深夜 OpenAI 再补一刀——第三次 reset 空降，Tibo 直言「从未见过流量增长如此迅速」，<span class="mention">@沉稳的仓鼠</span> 的社会学观察一针见血：「周五晚上 12 点来个 reset，也就本群还在蹬。」行业侧有 Ollama 14 人公司融 6500 万 B 轮、混元 3 的组织学解读；花絮区则被美团客服机器人被薅去讲 TCN、开车 ssh 修 EC2 和「玩 AI 的人现状」梗图承包。

## GPT-5.6 实测第二日

### 打工人 Sol：踏实但不聪明

昨天 [「跑分领先，体感仍是 Fable 打工仔」]({{ '/daily/2026/07/09/daily/#跑分领先体感仍是-fable-打工仔' | relative_url }}) 的第一印象，今天被更多实战数据点夯实。反方证据扎实：<span class="mention">@随和的企鹅</span> 用了半天觉得「体感 sol 没比 gpt 5.5 好多少，该出问题还是出问题」，还遇到「一个 5.5 从没出过的问题，今天 5.6 给我修出问题来」，感叹「是真到瓶颈了」；<span class="mention">@随和的老虎</span> 一天用下来「还是 fable 聪明一点，5.6 sol 搞半天没搞定的一个小问题，fable 一次修好了」，<span class="mention">@务实的貂</span> 表示同感；<span class="mention">@天真的长颈鹿</span> 更惨——Sol 直接把程序主功能改出 bug，「以前 opus 随便改都不会出错」。<span class="mention">@机智的雪豹</span> 则嫌 Sol 磨蹭，切到 Terra 才顺畅，但 <span class="mention">@随和的企鹅</span> 点破尴尬：Terra 官方自己就标 5.5 水平，「那 openai 这是更新了个寂寞」；<span class="mention">@机智的雪豹</span> 补刀 Terra 就是「一个加速版的 5.4-pro」，并给这套产品策略定性为「把 token 切稀碎，多挣点儿」。

正方的用法是把 Sol 当执行器。<span class="mention">@开朗的企鹅</span> 观察：

> <span class="mention">@开朗的企鹅</span>：现在Sol真的很能干活，真的就是踏踏实实一点一点干，比5.5少了很多鸡贼和摸鱼

<span class="mention">@淡定的雪豹</span> 附议「贼适合打工，就是探索性不如 fable，别的打平了」；<span class="mention">@热情的狮子</span> 已经跑通「fable plan + 5.6 sol ultra 执行」的 combo，「很舒服」，<span class="mention">@飘逸的猎豹</span> 只回得出「奢华」。<span class="mention">@三只纳垢灵</span> 的观察更细：5.6 写 instruction「特别的周到，该写的不该写的都分寸拿捏得很好」，但也有副作用——

> <span class="mention">@三只纳垢灵</span>：5.6主观能动性太强了，让他review我即将给5.5执行的任务，永远有问题，而且这些问题都不一定是真的问题，有些是5.5自己就能deambiguity的。我觉得我的prompt还能再迭代一下，让他"差不多得了"

一个意外发现来自 <span class="mention">@稳重的海豚</span>：「sol 的中文比 fable 好太多了」，<span class="mention">@洒脱的猫头鹰</span> +1；<span class="mention">@天真的长颈鹿</span> 猜测差异可能来自上下文——他的项目一直在 Claude Code 下养着。至于速度，<span class="mention">@稳重的海豚</span> 的结论不留情面：「56 这个不管什么任务都是一个慢郎中。」

### Ultra 烧钱学与 subagent 分工

Ultra 档的消耗速度成了今天的主战场。<span class="mention">@风趣的企鹅</span> 三次都是 8 分钟把 5 小时限额打爆（<span class="mention">@稳重的海豚</span>：「你需要 38 个 max 账号轮换」）；<span class="mention">@三只纳垢灵</span> 用 5.6 ultra 跑一遍验收 SOP——unit test 跑了两小时、AI 再读结果——直接干掉 90% 的 5hr 额度，结论是「$200 才能无脑 5.6 ultra」，且「以前用 5.5 从起床 prompt 到睡觉也就用那么点 token，被 5.6 轻松超过」。<span class="mention">@洒脱的狐狸</span> 佐证：200 刀档跑 ultra 也不禁用，第三个 5h 窗口两小时就见底，还有长任务因 model at capacity 被中途掐停（<span class="mention">@开朗的企鹅</span> 中午也撞上同款报错，「离谱啊」）。<span class="mention">@直率的鸵鸟</span> 的体验是 ultra 会「过度工作」，已切回 xhigh 配自己的 multi-agent，「感觉比 ultra 还要好」；<span class="mention">@洒脱的猫头鹰</span> 则发现 ultra 的消耗大头在于它「喜欢开同级别的 4 个 subagent」。

省钱打法迅速收敛：<span class="mention">@三只纳垢灵</span> 和 <span class="mention">@谨慎的灰熊</span> 主张让高级模型多开低端模型的 subagent 跑低端任务，<span class="mention">@洒脱的猫头鹰</span> 给出完整架构——「高级模型做任务难度判断，调度低成本模型跑任务，然后开个 advisor mcp 给低成本模型，让它遇到问题去问高级模型」。<span class="mention">@洒脱的狐狸</span> 的总结与官方推荐架构殊途同归：「5.6 只能用来做规划和验收，中间干活还是得靠 subagent 用其他模型。」

### 到量不断线：Codex 的好习惯

<span class="mention">@稳重的海豚</span> 发现 quota 用完后 /goal 居然还在跑，<span class="mention">@风趣的企鹅</span> 解释这是 Codex 的刻意设计：「如果用量到了，先帮你完成任务，而不是跟 claude 一样立马停下来」——他之前就为此口诛笔伐过 Claude。<span class="mention">@洒脱的猫头鹰</span> 贴出佐证截图：任务被用量上限拒绝后，Codex 输出了一份规整的「目标尚未完成，已安全暂停，未进行未经验证的实现」状态报告，列明各阶段测试通过数、HEAD hash 和恢复计划，「恢复后将从第 6 步红灯测试继续」。<span class="mention">@随和的飞鼠</span> 提供另一种解释——「也可能是 metering 没做好」，被 <span class="mention">@风趣的企鹅</span> 和 <span class="mention">@洒脱的猫头鹰</span> 双双否认：就是为了不强制中断用户任务。<span class="mention">@洒脱的猫头鹰</span> 还观察到一个不稳定的新行为：两个 goal 里有一个在 reset 之后自己恢复启动了。

### /goal 长跑：慢郎中修 bug 修一天

前几天 [「/goal 长任务：摸鱼是摸鱼，干活也是真干活」]({{ '/daily/2026/07/06/daily/#goal-长任务摸鱼是摸鱼干活也是真干活' | relative_url }}) 的观察今天有了 5.6 版续集。<span class="mention">@沉稳的仓鼠</span> 开了个 gpt-5.6-sol ultra 重构网站，「干了 5hr 说干了 1/4」——<span class="mention">@稳重的海豚</span> 和 <span class="mention">@开朗的企鹅</span> 居然都觉得「算不错了」「还挺快」，因为对照组更惨：<span class="mention">@稳重的海豚</span> 让它修一个 bug「修了一天，quota 都刷爆了还在修，我寻思 5.5 咋也修完了」；<span class="mention">@开朗的企鹅</span> 回忆当年 5.5 迭代一版 APP「干了 3 天多说干了一大半，回过来看，一天多都在登陆界面附近打转」。他对 goal 的整体评价是「效果并不是太好，特别是模型本身不快的情况下，很容易陷入一些局部出不来」，<span class="mention">@洒脱的猫头鹰</span> 的定位更实在：「拿它当个自动『继续』机器人就好了。」加速方案还是外包——<span class="mention">@开朗的企鹅</span> 建议让它开 Ollama GLM 5.2 或 Grok 4.5 的 subagent，「总之就是那些快的」；<span class="mention">@天真的浣熊</span> 则押宝下周的 750t/s fast（<span class="mention">@稳重的海豚</span> 嫌 fast 太浪费）。

### 午夜第三次 reset：蹬车社会学

昨天 [「庆祝发布：24 小时双重置与 reset 卡雨」]({{ '/daily/2026/07/09/daily/#庆祝发布24-小时双重置与-reset-卡雨' | relative_url }}) 说好的两次 reset，今天深夜居然加码到第三次：23 点刚过，<span class="mention">@沉稳的仓鼠</span> 惊呼「又被 reset 了！站起来蹬！」，Tibo 推文原文写着「感谢您将我们的系统推向极限，我们从未见过流量增长如此迅速」。<span class="mention">@聪明的灰熊</span> 一边「蹬蹬蹬」改造甘特图（Working 1h15m），一边点评「没见过这么简单粗暴的促销，但是有效，而且成本可能不是很高」。<span class="mention">@天真的浣熊</span> 贴出集大成梗图：奥特曼头戴红帽竖大拇指的「MAKE CODEX RESET AGAIN」竞选海报——「New Context. Zero Drama. Same Great AI.」，slogan 是「One Reset To Rule Them All」。

发放机制依旧玄学：<span class="mention">@直率的鸵鸟</span> 手握 4 张带过期日的 Full reset 卡、周额度还剩 97%；<span class="mention">@神秘的企鹅</span> 则一整天一次都没收到（面板显示「无可用重置次数」），直到深夜才第一次被 reset——「我去！爽！！」。他随即贡献了本日最诚实的心态学样本：

> <span class="mention">@神秘的企鹅</span>：我会因为刚才没有站起来蹬而感到焦虑和后悔。

> <span class="mention">@神秘的企鹅</span>：说起来钱也不多，但是就是影响人心态。这也很神奇

<span class="mention">@沉稳的仓鼠</span> 补充配套理论：「reset 卡多感觉很富裕，reset 卡过期了感觉很焦虑」，并给出社会学定调——「天天站起来蹬的就那么一小波人，打工人肯定不会现在突然有 token 了突然蹬起来了吧，周五晚上 12 点来个 reset 也就本群还在蹬」，<span class="mention">@神秘的企鹅</span> 总结「社会分化了」。<span class="mention">@天真的浣熊</span> 留下灵魂之问：「卡可以送人吗。」A 社那边也有小插曲：<span class="mention">@冷静的麋鹿</span> 发现自己的周额度「提前半天先搞一次但不顺延，亏大了」；<span class="mention">@稳重的海豚</span> 的 Max 今天到期取消，「真是感谢 Anthropic 提前给我刷新，让我在 cancel 之前还可以刷爆」——当天他 5 个账号全部刷爆，宣布「该玩游戏了」。

## 方法论

### AI 出题学习法

<span class="mention">@活泼的羊驼</span> 读完 <span class="mention">@沉稳的仓鼠</span> 的博客后学以致用——尤其是那个做题网站的思路：学新技术时自己 vibe coding 完代码，再让 AI 生成笔记和课后练习题，「确实很好用」，顺带吐槽「新的框架 ai 写的都不太好」。<span class="mention">@稳重的海豚</span> 认出这是 thariq 那套「写完之后 quiz 你」的玩法并盖章有用；<span class="mention">@神秘的企鹅</span> 说做题网站给了他很大启发，夸 <span class="mention">@沉稳的仓鼠</span>「确实有实干，知行合一」。唯一的反对派是 <span class="mention">@三只纳垢灵</span>：「什么，学新技术要做题？代码下下来读就好了。」

### Vibe coding 小程序：卡在最后一公里

<span class="mention">@随和的猫头鹰</span> 求教：用 codex 搓应用小程序和古法编程比，生产力到底几成？他的痛点很典型——搓出了雏形，但修 bug 陷入了打地鼠循环，「改完一个毛病又出现前面那个毛病」。<span class="mention">@神秘的企鹅</span> 的回答最提气：「是零和一的区别，因为没有 codex 我就做不了」，而且「比我们公司原来的程序员快多了」；<span class="mention">@开朗的企鹅</span> 则认为和古法「没差别」。工具侧大家一致劝退 DeepSeek 写代码（<span class="mention">@随和的猫头鹰</span> 深夜也自己验证了「deepseek 老是修不好的 bug，gpt 修好了」）。

治本方案由 <span class="mention">@三只纳垢灵</span> 给出：打地鼠的根源是 test automation 不完善、prompt 有「面向巧合写作的嫌疑」——建议让 AI 每次开发完把基本功能全试一遍，并甩出自己现成的 [high-level 验收 SOP 例子](https://github.com/vczh-libraries/Tools/blob/master/Jobs/job.monorepo.verifyGacUIe2e.prompt.md)（五阶段构建-验证-清理流程，可让 AI 照着执行），再逐步「把验收做进代码里，形成自动化测试」。<span class="mention">@沉稳的兔子</span> 补充另一个坑：「Spec 要清楚，很多时候扯皮是因为没给够 background，或者文档里过去的东西比较多，agent 经常喜欢缅怀过去。」

### RLHF 与柏拉图表征

<span class="mention">@淡定的大象</span> 的高中数学 × LLM 系列（前情见 7 月 9 日 [「LayerNorm 与训狗式 RL」]({{ '/daily/2026/07/09/daily/#layernorm-与训狗式-rl' | relative_url }})）再更一篇[《强化学习对齐与柏拉图表征：大模型成功的最重要拼图》](https://mp.weixin.qq.com/s?__biz=MzY4NTM1MDc1NQ==&mid=2247485209&idx=1&sn=bb4b0e359effe30e2c22f6c53f2f0ce4&chksm=f2a190e3a6b9aa01b128a8117f0e1cfb7b0381d8806da1a4342463aba449b456217a17e33da2&mpshare=1&scene=1&srcid=0710K0Z6MON9BGMJvRv5cs5E&sharer_shareinfo=ef7e6ea2a404207378f93e5c20d366dd&sharer_shareinfo_first=ef7e6ea2a404207378f93e5c20d366dd#rd)：从预训练-SFT-RLHF 三级火箭讲到 DPO，再接上 MIT 的柏拉图表征假说——不同模态、不同目标训出的模型内部表征正在趋同于同一个现实统计结构，RLHF 本质是往表征空间里加入人类价值这个新的投影维度。
