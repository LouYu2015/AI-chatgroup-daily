今天 K3 开源进入算账阶段——从美国律所自建硬件的临界点传闻，到 unsloth 的一位量化和被当场掐灭的 Mac mini 本地梦，最值得读的是这本私有化经济账。行业侧 OpenAI 宣布给十万科研人员免费开放前沿模型，羊毛党已经批量入场。工具侧 <span class="mention">@今天群内信息量极大</span> 的 M5Stack 板子到货，当晚就把语音输入法跑通，还顺手把 skill 上架给全群蒸。

## K3 余波：算账与量化

### 律所自建账本：月烧两万刀是临界点

<span class="mention">@天真的浣熊</span> 转来推上的说法：受 K3 冲击，A 社估值被砍的传闻四起，已有投行开始研究部署 K3。更具体的是[袋鼠帝转的案例](https://x.com/aikangarooking/status/2082291965006315735?s=46&t=_GBL8weBZa8putBqbpom3A)：一家美国律所每月在 Claude API 上烧近 3 万美元，正拿 K3 跑内部基准，达标就买 8 卡 AMD MI355X 服务器（约 2.3TB 显存、40 万美元），5 年融资月供约 1 万，加电费托管每月总成本 1.8 万——比 API 账单省 20–30%，数据不出门，新税法还允许硬件购置当年 100% 税前抵扣。帖子给出的临界点是：月 API 支出一旦超过 2 万美元，自建就开始划算。

<span class="mention">@热情的狮子</span> 直呼「谁编的段子」，律所哪里会折腾这个劲；<span class="mention">@敏锐的海狸</span> 也认为部署 K3 动辄几千万成本、继续利好数据中心。<span class="mention">@天真的浣熊</span> 补充 X 上的另一派算法：不用 N 卡，8 张 MI300X 就能部署满血版，硬件 50 万刀左右，加每月约 2 万的电力运维。昨天 [「全都开：权重之外，报告与 Infra 一并放出」]({{ '/daily/2026/07/28/daily/#全都开权重之外报告与-infra-一并放出' | relative_url }}) 里的私服账本，今天已经从群友集资进化成企业选型题。

### 一位量化：594GB 与夏利拉半挂

<span class="mention">@风趣的企鹅</span> 贴出 unsloth 的战报：K3 动态 1-bit 量化 594GB（比 1.56TB 全精度小 62%）还能保住约 78.9% 的 top-1 一致性，2-bit 861GB 到 90%，Mac Studio 或 DGX Station 接 128G 内存设备就能跑，他顺势喊大家端出 512G 的 Mac mini。本地梦被 <span class="mention">@今天群内信息量极大</span> 当场掐灭：这机器千万别买——算力一坨屎，装得下的模型只有几 token/s，速度跑得动的模型 64G 版本就装得下，「夏利发动机拉半挂，你就说能不能装吧」。<span class="mention">@坚定的貂</span> 退而求其次说内存大总是好的、可以多开点 Chrome 窗口，狐狸 想起 Linus 搞过 2T 内存的服务器开 Chrome，还是被 Chrome 干翻了。

### 星火燎原：闭源不再理所当然

<span class="mention">@风趣的企鹅</span> 发布[《Kimi K3：中国时间以及星火燎原》](https://mp.weixin.qq.com/s?__biz=MzcwNDE5NzI3Ng==&mid=2247484318&idx=1&sn=40ae121e2c2db5623317ffa058459518&chksm=f59fbe4bd66cb281cff9478c203d884b803284bd360d27e064990b9934c6ee06b742675d7b20#rd)：官方报告坦承 K3 整体仍落后 Fable 5 与 GPT-5.6 Sol，但它是第一个 3T 级的开放权重模型，在多项编程与 agent 评测登顶，Kimi Code Bench 上以 Fable 5 约 38% 的成本只落后 4 分——闭源卖答案，开放权重交出的是可检查、可私有部署、可持续再加工的生产资料。

> <span class="mention">@风趣的企鹅</span>：K3 没有打败闭源。它只是让"闭源永远定义前沿"这件事，第一次显得没那么理所当然。这，才是 K3 的意义。

生态侧的注脚：<span class="mention">@幽默的犀牛</span> 发现 ollama 上疑似已有 K3；开放模型价格战也在同步打响——<span class="mention">@直率的海豚</span> 贴出 OpenRouter 上 GLM 5.2 打 52% off、已处理 3.74T tokens，<span class="mention">@沉稳的兔子</span> 对着 3T 直呼牛逼。

## 方法论

### 四个 AI 号进钉钉群：入口、隔离与心理满足

<span class="mention">@安静的海豚</span> 分享公司玩法：拉个钉钉群配 4 个 AI 号——产品、设计、研发、内容生成，每天的工作就是 @ 对应的号让它们直接干活。<span class="mention">@聪明的蜂鸟</span> 泼了盆技术冷水：这是很早的拉 AI 建群做法，他担心 token 消耗，一般用一个 master agent 按需起 sub session，多个机器人之间走 IM 效率不高；而且要么只看单条消息丢掉群聊价值，要么一堆 AI 互相制造上下文、隔离全无。<span class="mention">@活泼的海龟</span> 解读走 IM 的真实目的是让人类可见、符合员工工作习惯，但他在飞书上搭机器人的教训是私聊比群聊好：

> <span class="mention">@活泼的海龟</span>：群聊的价值在于大家能够相互看到别人怎么使用 AI，但是因为 AI 给的上下文实在是他妈的太多了，这个群很快就会乱七八糟，根本没人愿意看。

<span class="mention">@80-HD</span> 的方案是只配一个 AI 号当入口、每个活单独起实例，就像 Slack 里的 @Claude；且只让 AI 读单独的 thread，强行塞进 channel 群聊不可取。<span class="mention">@谨慎的树懒</span> 提议话题群天然隔离，<span class="mention">@搞仁义毛义仁</span> 说 Teams 能开 thread 正好解决；<span class="mention">@稳重的海豚</span> 则认为每个 agent 一个独立 workspace、工作区和交流区分开就好，顺势再推自家 herd。

至于堆 persona，<span class="mention">@80-HD</span> 认定除了给人类心理满足没啥用；<span class="mention">@稳重的海豚</span> 反驳心理满足很大用——这就是电影里一句「来人」那人就来了；仓鼠 想想也是，天天叫马一龙乔布斯干活确实挺爽。

### 老鸭汤瘦身：30k 砍到 10k

<span class="mention">@80-HD</span> 把 A 社那篇 [Claude 5 代上下文工程新规](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models)扔给 AI 让它全文背诵、出方案优化老鸭汤，重点清理每个 session 都会自动 load 的 context：前几天清完自己的、昨天清了公司的，token 从 30k 降到 10k，整体减到原来的 1/3，「就是不知道会不会变难用」。他坦言不少清掉的东西跟文章关系不大，纯粹是太久没管长出来的冗余。<span class="mention">@冷静的麋鹿</span> 印证方向：Opus 5 出来后 A 社这篇讲的就是别约束太多，和群里的结果确定性大于过程确定性一个道理——文章解读见昨天 [「Skill 是责任状：给强模型写责任」]({{ '/daily/2026/07/28/daily/#skill-是责任状给强模型写责任' | relative_url }})。

### 档位接龙：medium 党再添一票

凌晨 <span class="mention">@沉稳的兔子</span> 夸 GPT 5.6 的写作真不错，网页版开 High，自称最不尊贵的 plus 用户。白天 <span class="mention">@随和的企鹅</span> 求平衡速度与准确度的 sol/terra 组合——sol xhigh 有点太慢；<span class="mention">@80-HD</span> 给出 sol medium + fast，理由还是那条：xhigh 和 ultra 老多干活很烦（前情见 25 日 [「Effort 不是越高越好：官方劝你重扫一遍」]({{ '/daily/2026/07/25/daily/#effort-不是越高越好官方劝你重扫一遍' | relative_url }})）。<span class="mention">@活泼的老虎</span> 投出新一票：High 一方面慢、一方面做事太细致，大部分简单活很浪费时间，默认改 medium 也不觉得质量差；<span class="mention">@沉稳的兔子</span> 依然坚守 xhigh，慢点就慢点了。

### Don't build：刚好能做出来的最危险

<span class="mention">@冷静的飞鼠</span> 分享 Superlinear 的 [Don't build：最危险的 AI 项目，可能是你刚好能做出来的那个](https://www.superlinear.academy/c/ai-resources/dont-build)：AI 极度压缩了第一版的开发速度，让更多人更快走到 demo 与生产系统的鸿沟边上——demo 只需要在展示的瞬间是对的，产品要在现实不断变化时始终是对的，90-90 规则并没有被 AI 改变，自建系统每周从你这里拿走的注意力才是最贵的成本。<span class="mention">@认真的灰熊</span> 深有共鸣：领导看到 prototype 隔天就想上线，总觉得怎么干得那么慢；<span class="mention">@稳重的海豚</span> 支招——prototype 当然可以上线，我第二天就给你上线，想要 production 你就等着；<span class="mention">@开朗的企鹅</span> 说这篇就是 AI 跟他说的话。

中午 <span class="mention">@温暖的斑马</span> 延伸出创业视角：0 到 1 阶段验证 MVP，拿块砖头画几个功能按键、问身边一二十个人就够了；第二个陷阱是指望 freemium——他见过很多公司烧钱速度跑不赢营收，还没到盈利下一轮融资断掉就完蛋了。

### 长鑫股份 5% 的男朋友
