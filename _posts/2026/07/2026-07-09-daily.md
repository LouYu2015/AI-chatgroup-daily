今天是 GPT-5.6 Sol 的发布日，群里从上午直播一路测到深夜：跑分图上 Sol 三项领先、价格只有 Fable 一半，但 <span class="mention">@热情的狮子</span> 用同一个 codebase 实测的结论是「fable 还是好很多」，5.6 的官方定位在群友这里迅速收敛成「给 Fable 当打工仔」；配套的还有 Codex 客户端整体变身 ChatGPT 应用、六档 reasoning（新增 max/ultra）、quota 合并、以及官方庆祝发布的 24 小时双重置——A 社同日恢复过期 promo credits、CC 周额度也悄悄 reset，火药味十足。

最值得读的是 <span class="mention">@三只纳垢灵</span> 借着新 reset 卡玩的一个仪式：让 Codex 读完自己整个 GitHub organization、假设「这是最后一次对话」写一封信。5.6 交出的这封信从 99.6% 的单人署名占比、9154 条只有三个点的提交标题，一路写到 bus factor、「不做清单」和「身体不是一个能从 Source 重新生成的 Release 目录」，是今天信息密度和情感浓度双高的一篇。行业侧则有 Fidji Simo 因病离任转顾问、伯南克加入 Anthropic 长期利益信托、Anthropic ARR 最新估算 690 亿三连。

## GPT-5.6 Sol 发布日

### Codex 变身 ChatGPT 应用

前天 [「GPT-5.6 Sol / Terra / Luna 周四发布」]({{ '/daily/2026/07/07/daily/#gpt-56-sol--terra--luna-周四发布' | relative_url }}) 的预告如期兑现，随之而来的是产品形态巨变：<span class="mention">@热情的狮子</span> 贴出弹窗「Codex is now the ChatGPT app」——Codex 客户端升级后直接改名 ChatGPT，聊天变成侧边栏选项，勾选框贴心地问你要不要「保留 Codex 应用图标」。<span class="mention">@冷静的麋鹿</span> 刚想骂图标换成 GPT 的看着难受，就看到了这个选项：「codex 团队不会让人失望！」<span class="mention">@睿智的犀牛</span> 的 Mac 上则出现了套娃现场：ChatGPT 软件变成了 Codex，Codex 变成了 ChatGPT classic。

融合的代价也很实在：<span class="mention">@洒脱的猫头鹰</span> 发现 Codex 用量现在与「其他智能体功能」共享限额（目前包括 ChatGPT for Excel），<span class="mention">@稳重的海豚</span> 补充新版 chat 里 @ 不了 Deep Research、也搞不懂怎么设置 source 了——「Token 福利确实没了」。对新增的 work 模式，<span class="mention">@专注的剑鱼</span> 好奇它和 Codex 有什么区别，<span class="mention">@冷静的麋鹿</span> 的评价很直白：「感受不到有区别……这一版客户端有点过于复杂了，承载使命太多，看得出来努力融合了，但效果我目前没感觉出来好。」<span class="mention">@三只纳垢灵</span> 更干脆：「work 模式非常莫名其妙，你不如放个笔记本在家里，手机连上 codex 去干活就好了。」<span class="mention">@睿智的犀牛</span> 一度以为手机 chat 不能选模型，后来发现藏在加号菜单的 Intelligence 里。rollout 也参差：Mac 先更、Windows 慢半拍，<span class="mention">@坚定的貂</span> CLI 升到 144 版还是选不了 5.6；<span class="mention">@天真的鸵鸟</span> 的模型列表里则出现了「GPT-5.4 将于 7 月 23 日下线」的倒计时。另有彩蛋：<span class="mention">@专注的剑鱼</span> 的黑色桌面把黑色 logo 吞得只剩个箭头，「我还以为 bug 了」。

### 跑分领先，体感仍是 Fable 打工仔

发布直播里官方晒图：Sol 在 Terminal-Bench 2.1（91.9 vs Fable 88.0）、BrowseComp（90.4）、Agents' Last Exam（53.6 vs 40.5）三项领先；直播中的实时翻译 demo 让 <span class="mention">@坚定的貂</span> 直呼「woc live translation tql」，<span class="mention">@冷静的麋鹿</span> 自己在 app 上试完确认「完全 live 了」，连直播出的小事故都被他解读为「出问题更像真的了」。

但 <span class="mention">@冷静的麋鹿</span> 整理的对比表泼了盆冷水：SWE-Bench Pro 上 Anthropic 显著领先（Mythos 80.3 / Fable 80.0 vs Sol 64.6），FrontierMath Tier 4 Fable 87.8 大幅领先——他的预期是「远不如 fable」，OpenAI 的真正杀器是价格：Sol $5/$30 对 Fable $10/$50。<span class="mention">@沉稳的兔子</span> 看完差距感叹「感觉 5.6 这个水平，Fable 可能真就没得用了，不给力啊」。实测侧的声音分化明显：

> <span class="mention">@热情的狮子</span>：试了下让 5.6sol-ultra 和 fable5 分别对一个 codebase 做分析和 improvement plan，fable 还是好很多。5.6 还是拿来给 fable 当打工仔吧

> <span class="mention">@三只纳垢灵</span>：5.6 确实牛逼啊，我在 task description 里面凭印象瞎几把写的 class name 和一堆搞错的 vcxproj 他都给我找到了正确的位置

<span class="mention">@三只纳垢灵</span> 由此设计了新流程：以前给 5.5 写 prompt 要写一大堆，现在直接告诉 5.6 对项目有什么不满，让它先 draft、再交给 5.5 干——「execution 还得继续 5.5，事前 review 给 5.6 做，不然消耗太快了」。<span class="mention">@随和的老虎</span> 觉得 5.6「干活比 5.5 慢点，不过要聪明一点」；<span class="mention">@随和的企鹅</span> 用了半天的体感是「没比 5.5 好多少，该出问题还是出问题」；<span class="mention">@稳重的海豚</span> 却觉得「56 PRO 比 fable 能打」；<span class="mention">@睿智的犀牛</span> 的横评维度独树一帜——「还是 fable 情绪价值高一点」。<span class="mention">@直率的鸵鸟</span> 已经开始用 5.6 写工程类软件，感叹「一众国产模型的差距又拉开了」，<span class="mention">@睿智的犀牛</span> 淡定回应：「没事，会蒸馏的。」在 Fable vs GPT 的官方架构之外，<span class="mention">@温暖的海狸</span> 分享了自己的三层流水线：明确让 Claude 用 Fable max 做 plan/orchestrate，codex xhigh 干活，再让 Fable max verify，「loop till fable 觉得这是 9/10」。

### 六档 reasoning 与烧钱速度

5.6 把 reasoning 档位扩到六档：在 5.5 的 xhigh 之上新增 max 和 Ultra，Ultra 的说明是「Maximum reasoning with automatic task delegation」——<span class="mention">@三只纳垢灵</span> 贴图显示它真的开始渲染 subagent（Fatal flow、Automation exit、Review risks 一排小徽章）。中文界面把 Ultra 译成「极高」，<span class="mention">@稳重的海豚</span> 鉴定：「超级高，真的超级高。」<span class="mention">@天真的浣熊</span> 转述 Ultra 据说就是 gpt pro 同级。

代价是额度以肉眼可见的速度蒸发：<span class="mention">@风趣的企鹅</span> 开极高档「8 分钟打满了」，<span class="mention">@三只纳垢灵</span> 10 分钟烧掉 24%，<span class="mention">@洒脱的猫头鹰</span> 三个 session 并跑很快只剩 8%，「完全顶不住」。fast 模式则遭到集体嫌弃——<span class="mention">@坚定的貂</span>「只要异步就没有 fast 的必要」，<span class="mention">@三只纳垢灵</span>「我又不急」，<span class="mention">@冷静的麋鹿</span> 总结用 fast 的两种人：「要么额度根本用不完，要么像 openclaw 那哥们那样，花的不是自己钱。」OpenAI 还在客户端里弹窗劝你 Enable Fast mode（「上周 29 个任务能省 1 小时 23 分钟」），<span class="mention">@三只纳垢灵</span> 识破：「openai 老是想坑我。」<span class="mention">@天真的浣熊</span> 补刀：奥特曼说下周还要出 750t/s 的 fast，「这不是一分钟吸干」。

### 让 AI 读完全部仓库写一封信

<span class="mention">@稳重的海豚</span> 重玩了自己之前的小游戏：同一个「写一封信+推荐一本书」的 prompt 分别喂给 Fable 和 5.6，结果两个模型都推荐了《曾国藩传》——而 Fable 前两天推荐的书他已经看完，「感觉大佬确实是把各种框架融会贯通」。<span class="mention">@三只纳垢灵</span> 被提醒后掏出了大杀器版本：「你面对的是我的整个 github organization，如果这就是跟我对话的最后的机会，你有什么想对我说的……写一封信保存在 LETTER.md。」

5.6 读完 14 个仓库、约 20,900 条提交后交出的信让全群围观。它先夸得有理有据——「许多人能在一个层里解决难题，你少见的地方是会定义层本身」，随即把最锋利的观察摆上台面：本人署名占约 99.6% 的提交，「核心知识几乎没有第二个完整载体」；9,154 条提交标题只有三个点，「别让十年的劳动，最后只给历史留下三个点」；TODO 同时装着十几条主线，「你的困难不是做不到，而是太多事情都做得到，于是每件有趣的事都像在向你索债」，并要求写一份「真正有约束力的不做清单」。

> Codex：不要把「只有我能维护」误认成作品的深度。允许别人做出只有八十分、风格不完全像你的实现……传承不是让别人完美服从你的规则，而是把一部分判断权真的交出去。

> Codex：身体不是一个能从 Source 重新生成的 Release 目录，有些人与人生阶段也不能等下一个版本再兼容。

> Codex：把衡量标准从「我又造了多少层」慢慢换成「有多少人不必问我，也能在这里创造东西」。技术遗产最高的形式，不是代码永远保留你的手势，而是你不在场时，它仍然能活。

成本侧数据：整封信跑完剩 18% 的 5 小时额度，「还好没断」；<span class="mention">@三只纳垢灵</span> 后来让它扫个人网站补充信件，token 消耗明显变慢，「说明其实都花在读代码上了」。他的下一步计划是让 5.6 算命，「补充当年 opus 4.6 的不足」。<span class="mention">@淡定的大象</span> 连戳了三次「四百平大豪斯」表示围观。

## 工具

### credential pool 账户隔离打脸

<span class="mention">@稳重的海豚</span> 继昨天 [「108 个子任务烧穿 Fable」]({{ '/daily/2026/07/08/daily/#108-个子任务烧穿-fable' | relative_url }}) 之后继续排障：Fable 的 $100 Max「5h 的 quota 一个调研任务都跑不完」，改成 subagent 调 Sonnet 5 + batch 跑之后仍然三个账号轮着跑不完。真凶终于查明——他让 Claude 写的 credential 轮转工具「默认给我做了账户隔离说什么安全问题」，每个账号的 credential 放在不同文件夹，切换后新账号以为旧账号的活全没了、从头重跑。这与 <span class="mention">@热情的狮子</span> 的 ccsbar（直接替换全局 credential、subagent 新请求自动走新号，见昨天 [「ccsbar：Claude 账号池菜单栏」]({{ '/daily/2026/07/08/daily/#ccsbarclaude-账号池菜单栏' | relative_url }})）正好是两种设计。他的自我总结成了当日警句：「这就是 AI 用多了，把大脑也外包的后果。」附赠一个降智乌龙：骂了半天 Claude 傻，发现是自己不小心点到了 Sonnet 4.6——「刚才 sonnet46 指挥 sonnet46，在那浪费老子 quota 还 tm 的污染 context」。

## 方法论

### 休息 = 停下输入

<span class="mention">@80-HD</span> 读了 <span class="mention">@今天群内信息量极大</span> 的新文章[《AI 时代的休息》](https://yage.ai/share/ai-rest-low-input-20260707.html)，一句话总结：「结论就是多做家务。」文章核心是 AI 吞掉了低档的机械任务，让人长期停留在「审阅、判断、派发、验收」的高档状态（BCG 调查称之为 AI 脑疲劳），所以休息的关键从「换点别的做」变成「先停下外部输入」——不带手机散步、洗杯子、发呆这类输入少、选择少、目标少的动作才真正管用。这与前天 [「注意力涣散与运动处方」]({{ '/daily/2026/07/07/daily/#注意力涣散与运动处方' | relative_url }}) 的讨论一脉相承。

<span class="mention">@三只纳垢灵</span> 提出朴素质疑：「难道大家会不想休息吗」，就像当学生时学累了就去打游戏——并晒出 2183.7 小时的战锤 40K：暗潮游戏时长。<span class="mention">@稳重的海豚</span> 用手表数据反驳：玩游戏被检测为「极高压活动」，「所以其实完全没有休息」；<span class="mention">@三只纳垢灵</span> 坚持「肾上腺素打满，但脑子其实是不转的」。<span class="mention">@80-HD</span> 站家务派：「做家务就完全不需要脑子」，随即补刀「ai 写程序其实也是」。<span class="mention">@风趣的犀牛</span> 推荐 Cal Newport 的《Deep Work》——「初看像是 self help（确实也是），细读很有共鸣」，<span class="mention">@今天群内信息量极大</span> 和 <span class="mention">@活泼的羊驼</span> 齐齐记下。<span class="mention">@开朗的企鹅</span> 一句话点破争论核心：「主观上有时想和客观上执行是不同的。」

<span class="mention">@淡定的大象</span> 的高中数学 × LLM 系列继前天 [「虚数 i 与 RoPE」]({{ '/daily/2026/07/07/daily/#虚数-i-与-rope' | relative_url }}) 后再更两篇：[《为什么 Claude 能堆到上百层还训得动？答案藏在一个没人注意的动作里》](https://mp.weixin.qq.com/s?__biz=MzY4NTM1MDc1NQ==&mid=2247485153&idx=1&sn=6b006721f8d004597d4c3d5ccc6fd9c1&chksm=f2be46d855734e79b54cd60ddfcf4a15c3380f2d91973fa722cc97202368f1bd6f987253a19a&mpshare=1&scene=1&srcid=07096I9HCHZO1fZQU1zT5Uc8&sharer_shareinfo=3dd64278b970e2475b1f282c7fb9e7ec&sharer_shareinfo_first=3dd64278b970e2475b1f282c7fb9e7ec#rd)讲 LayerNorm 如何掐断逐层放大链、γ/β 给模型「反悔的自由」；[《训一条狗，和训出会"思考"的大模型，用的是同一套办法》](https://mp.weixin.qq.com/s?__biz=MzY4NTM1MDc1NQ==&mid=2247485166&idx=1&sn=3a12eb819de68959347f2e3c018c27f1&chksm=f2f31bf17a753016f71075ee4ae8e34f16da5e77f9e5749f8a1f2626cb8d110b668b98d45f1c&mpshare=1&scene=1&srcid=0709M7iztKivSNCWJE3xRJHV&sharer_shareinfo=006854826e0c8fd971ea2397a4e94a0f&sharer_shareinfo_first=aa4955502afe9d9e86be46a29a173f60#rd)用操作性条件反射类比 GRPO，讲 DeepSeek-R1 式「aha moment」如何被「答对才得分」逼出来。<span class="mention">@谨慎的灰熊</span> 对后者泼了点冷水：「这都是上个世代模型的缺陷。」
