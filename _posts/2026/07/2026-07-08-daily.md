### GPT-Live 全双工语音上线

上午 <span class="mention">@天真的浣熊</span> 贴出 OpenAI「Listen up. Livestream at 10am.」预告，晚间靴子落地：<span class="mention">@热情的狮子</span> 分享了[《OpenAI深夜放出GPT-Live，ChatGPT终于像真人一样说话》](https://mp.weixin.qq.com/s?__biz=MzA3MzI4MjgzMw==&mid=2651043227&idx=1&sn=a1924ecbfde2a696194a41c536f6992a&chksm=85a19d5fa215e961982931aea08792cc56d1972b6d0f111012ab753cbc525854e5c4018ecb3f&mpshare=1&scene=1&srcid=0709QRhPCUphTEYDlx7ZvFr5&sharer_shareinfo=9c42f7c89e3961196957ed5f3ab8570b&sharer_shareinfo_first=9c42f7c89e3961196957ed5f3ab8570b#rd)——新一代语音模型 GPT-Live 抛弃轮次式架构改为全双工，能边听边说、自然插话打断，深层任务委派给 GPT-5.5 后台处理、自己维持对话不断线；GPT-Live-1 是付费用户 Voice 默认模型，mini 版给免费用户。<span class="mention">@天真的浣熊</span> 总结最大卖点是「全双工是吧，还有延迟速度」，看好实时翻译和听写体验。

这条新闻正好接住了凌晨的需求讨论：<span class="mention">@稳重的海豚</span> 说最近特别需要给 agent 配邮箱和电话，让它以「我秘书的名义」发邮件打电话做确认——他现在已经可以打电话给 agent 布置任务，「有种当老板的感觉」；<span class="mention">@开朗的企鹅</span> 感叹一个好的语音 Agent 是真刚需，重点不是跟自己说话，而是替自己给别人发消息打电话。<span class="mention">@坚定的貂</span> 的要求更高：要 AI 即时用他自己收集语音训练出来的某人声线说话，为此得配 5090——GPT-Live 出来后他确认愿望落空，「就是不能用我想要的声音了」，只好「学会对方架构自建一个」。<span class="mention">@天真的浣熊</span> 补刀：「老哥你这需求为啥听起来和园区的需求很像」，并猜官方不开放自定义声音「估计也是怕电诈」。

### Moshi + hcom + herdr 三件套

<span class="mention">@热情的狮子</span> 试完 AgentHub、Herd、Omnigent 一圈后（前情见 7 月 6 日 [「Herd 新版与 10k star 预言」]({{ '/daily/2026/07/06/daily/#herd-新版与-10k-star-预言' | relative_url }})），宣布收束到新组合：[Moshi](https://getmoshi.app/)（专为手机重构的 agent 终端，支持 mosh、Tailscale、语音输入、审批推送、灵动岛）+ [hcom](https://github.com/aannoo/hcom)（Rust 单二进制的 agent 互发消息总线，hook 注入 + 本地 SQLite）+ herdr（agent-aware 终端复用器）。<span class="mention">@坚定的貂</span> 连呼「太厉害了」，但 <span class="mention">@热情的狮子</span> 让 Fable 出具的调研意见反而建议跳过 hcom：与 herdr 的 socket API 撞车、和 moshi-hook 抢 Stop hook 有语义冲突、「三件套全网没有任何人写过实跑经验——它是群聊拼贴，不是被验证的 stack」，跨机 relay 安全模型也薄。<span class="mention">@开朗的企鹅</span> 补了份对照分析：这套 combo 厉害在「站在终端原生层解决问题」，是高手的轻装工作流；AgentHub-OSS 则是可部署、可审计的自托管控制平面。

任务管理选型顺势展开：<span class="mention">@坚定的貂</span> 代码在自建 Gitea 上、不想用 GitHub，觉得 issue 也不该只是代码 issue（「remind 我买牛奶」也算），考虑 Linear（免费版有 200 issue 上限）；<span class="mention">@80-HD</span> 力挺 md 文件——「不用 API call，快又好。最大的难点还是推进，我 backlog 里面一大堆，agent 天天催我干活」。<span class="mention">@坚定的貂</span> 的真正牢骚在生态本身：

> <span class="mention">@坚定的貂</span>：就是这样东西一直挂，不是使用者，天天在修东西……所有的产品都是95%的状态，过几天要fix个东西

<span class="mention">@80-HD</span> 给出两条路：像他一样拿 <span class="mention">@今天群内信息量极大</span> 的框架让 AI 一个个抄过来满足自己需求，「或者你就像 <span class="mention">@沉稳的仓鼠</span> 一样，彻底放弃折腾这些，claude 和 codex 有什么用什么，专注问题就行了」。<span class="mention">@热情的狮子</span> 表态折腾本身有价值——「加深了自己对 agent system 的理解」。<span class="mention">@沉稳的兔子</span> 的用法最朴素：「我的 herdr 就全当作 tmux 用了」，agent 功能从来没识别上。

## 方法论

### 聊天框的幻觉：邮件流成文

<span class="mention">@今天群内信息量极大</span> 把前晚 [「Email 才是 Agent 的原生信道」]({{ '/daily/2026/07/07/daily/#email-才是-agent-的原生信道' | relative_url }}) 的讨论连夜写成文章[《聊天框的幻觉：为什么我们一直在给 AI Agent 做错误的界面？》](https://yage.ai/share/chat-box-illusion-agent-interface-20260710.html?utm_source=wechat&utm_medium=share&utm_campaign=chat-box-illusion-agent-interface-20260710)：聊天框对用户和开发者施加双重规训——输入框尺寸和永远亮着的发送键诱导人只丢一句模糊指令，即时对话的节奏又逼开发者让 agent 遇分支就停下发问；真正把 AI 用成放大器的人都在「用写邮件的思路强行使用聊天框」；工程落地方案是把信息流和控制平面拆成「邮局与办公桌」，任务只有 Working、Ready to Review、Archived 三态。<span class="mention">@随和的飞鼠</span> 表示昨天看讨论有启发、今天看文章更有体会，并贡献了全场最扎心的自白：

> <span class="mention">@随和的飞鼠</span>：不但如此，我还变成了自己最讨厌的deadline boy，天天问你这个做了吗那个弄了没，为啥无视了我哪句话，这个你说写了结果不work

<span class="mention">@灵动的考拉</span> 说自己现在用 GitHub issue 和 code agent 交流，「基本和邮件类似」；<span class="mention">@务实的长颈鹿</span> 和 <span class="mention">@灵动的羊驼</span> 则用可交互 HTML 做非代码规划工作，「阅读、修改和生成其他媒体形式分享很舒适」。<span class="mention">@沉稳的仓鼠</span> 泼了盆现实的冷水：「邮件主要的问题是国内不用邮件，不太能想象邮件是个什么工作流」，并补充文化视角（先说反随即自我纠正）——英文工作环境是低语境、万事显式写清，天然适配邮件，也更适配与 AI 的交互方式；<span class="mention">@灵动的考拉</span> 顺势推论「这么说现在模式最适合中国呀，就是聊天」，<span class="mention">@务实的长颈鹿</span> 替某协作软件抢答：「Feishu：我又赢了。」

### 模拟经营界面养 agent

<span class="mention">@务实的长颈鹿</span> 提出想用模拟经营游戏界面跟 agent 交互——理想形态是异星工厂那种「半引导半交互」的任务设计。<span class="mention">@稳重的海豚</span> 掏出存货：他做过一个叫 Hammurabi 的 RPG 界面，agent 是地图上的像素小人，可以走过去直接对话、看每个员工的 quest 列表和 token 开销——结论是「真要玩还行，干事情纯纯浪费时间」。<span class="mention">@飘逸的狮子</span> 也认领同款黑历史：「我也做过，用魔兽世界打副本的 UI 😂」。<span class="mention">@热情的狮子</span> 警告异星工厂式界面是「时间黑洞」，<span class="mention">@务实的长颈鹿</span> 表示同意（「我自己觉得比文明还厉害」），但留下了当日最认真的一句判断：「人类和 Agent 最好的 UI/UX 可能确实还未出现。」

### 一个 merged PR 平均 $22

<span class="mention">@80-HD</span> 读 <span class="mention">@今天群内信息量极大</span> 的[《AI token 降本》一文](https://yage.ai/share/ai-token-cost-saving-20260707.html)深有体会：公司风向从「看谁 AI 用得多」突然变成「找便宜模型省开支」，两头都没找到重点——应该先归因再优化，拿 PR 数量当 metrics 没意义。他顺手统计了自己近两个月的数据：平均一个 merged PR 花 $22（API 计费），而组里干活最猛的同事也是 20 出头——关键是他 90% 用 Opus、对方 90% 用 Sonnet。结论：「可以主观上说 sonnet 不会省钱」，而且体验上两人都经常骂降智，对方骂得可能更多。<span class="mention">@开朗的企鹅</span> 点出症结：「主要是 sonnet 没有更快，否则还可以忍。」

### A2A 续辩：协议即 harness

昨天 [「A2A 协议：情绪价值还是刚需？」]({{ '/daily/2026/07/07/daily/#a2a-协议情绪价值还是刚需' | relative_url }}) 的争论深夜再起。<span class="mention">@勇敢的犀牛</span> 把「情绪价值」立场展开成完整论证：竞品都在强化严格的 transaction 流程，但「人们并不会因为你的 transaction 流程很鲁棒就愿意用 A2A，这是一个必要不充分条件」——协议再棒不等于产品有价值，情绪价值反而是更好的切入点。他还补了一层更根本的担忧：

> <span class="mention">@勇敢的犀牛</span>：这些协议，本质上都是harness，一套为社交或者交易设计的harness，只要是harness就需要面对一个问题是当模型更强大之后怎么解绑的问题，约束太死了反而有负作用

<span class="mention">@飘逸的浣熊</span> 换了个定性：与其说是 A2A 系统，不如说是权限系统——agent 对通信格式没什么要求，用邮件都行，关键是身份验证、授权、支付这些问题。
